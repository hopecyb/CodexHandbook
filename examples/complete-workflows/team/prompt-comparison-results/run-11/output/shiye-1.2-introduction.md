# 拾页 1.2：从散落的笔记中，找到文章的出处

> 合成资料说明：拾页是虚构产品，本文依据三份 CC0 1.0 教学材料撰写，不代表实际软件评测。下文的“小林”也是虚构角色，其经历不能视为真实用户证言。

写文章时，想起自己记过某个观点，却找不到它放在哪份笔记里，是一个具体的整理需求。拾页 1.2 的设定正围绕这一步展开：整理指定本地文件夹中的 Markdown 和纯文本笔记，生成主题索引，以及带源文件路径的摘要。对个人作者而言，可以把它放在查找材料的环节，沿着索引和路径回到原笔记，再决定哪些内容适合写进文章。[P1–P2、I1]

它能接收的文件范围很明确：只有 `.md` 和 `.txt`。PDF、网页抓取和图片识别均不在 1.2 的支持范围内。如果你的材料主要是扫描书页或 PDF，这份产品说明并未提供直接整理它们的能力。[P1]

这次版本变化中，与查找出处直接相关的是摘要新增了源文件路径；版本摘要还记载，1.2 修复了重新扫描时重复索引同一文件的问题。[C1] 路径让作者有线索回查，但摘要仍然需要核对。它是对原文的概括，不能直接当成原文引用，产品说明也没有承诺摘要完全准确。[P2]

合成访谈给出了一个具体情境：虚构受访者小林试用了十二份 Markdown 笔记，借助索引回到源文件；其中一次摘要把两个相似项目当成了同一件事，小林对照原文后进行了修正。[I2] 这个教学例子提示作者，在采用摘要中的判断之前，要确认它是否把不同对象或不同语境混在一起。访谈没有计时，也没有固定评估样本，因此不能据此推算整体准确率或节省的时间。[I3]

网络设置还有一处不能略过的疑点。9 月 10 日的产品说明写着“诊断上传默认关闭”，9 月 12 日的版本摘要却写着“新安装的 1.2 默认开启诊断上传”。两份材料都指向 1.2，维护者尚未给出修正说明，较晚的日期也不足以消除冲突。因此，目前无法确定诊断上传的默认状态，需要维护者确认适用版本和安装情境，并补充上传字段及网络行为说明。[P3、C2–C3]

资料能够确认的是文件索引在本机完成；这不足以推断所有功能都离线运行。[P3–P4] 对个人作者来说，依据这些材料可以形成一个使用思路：把支持格式的笔记交给工具整理，借主题索引和摘要找到线索，再回到源文件核实、选择和引用。至于处理速度、准确率、付费方案和跨设备同步，现有资料都没有给出承诺，本文也不作推断。[P4]
