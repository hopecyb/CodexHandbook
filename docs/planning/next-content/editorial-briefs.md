共同约束：以下是待制作内容，不是已经完成的案例。不得编造真实使用对话、执行耗时、模型结果或运行截图。预估时间是编辑目标，发布时用实跑记录修订。

## A. 从销售 CSV 到可核对的周报

**目标读者**：会打开文件，但不要求会编程的办公用户。目标练习时间 30—45 分钟，需实测。

**升级位置**：`src/content/docs/cases/analyze-a-spreadsheet.md`。

**读完能够**：明确销售指标口径，用 Codex 汇总合成数据，检查总额、分组和异常，交付附计算依据的周报。

### 材料与数据契约

建议目录：`examples/complete-workflows/creator/sales-weekly-report/`。

| 文件 | 内容 |
|---|---|
| `README.md` | 环境、运行/跟做步骤、许可、预期产物 |
| `brief.md` | 使用场景、允许范围、成功条件 |
| `starter/sales.csv` | 合成销售数据，标明不存在真实客户信息 |
| `starter/data-dictionary.md` | 字段类型、币种、退款/缺失/重复的处理定义 |
| `prompts/01-inspect.md` | 先确认字段、日期范围、数据问题 |
| `prompts/02-report.md` | 按已确认口径生成报告和汇总表 |
| `prompts/03-verify.md` | 独立重算与差异解释 |
| `solution/summary.md` | 参考周报，逐项标注计算依据 |
| `solution/region-summary.csv` | 地区汇总与总额 |
| `validation/check.py` | 用标准库重算已定义指标，非依赖模型判断 |
| `validation/record.md` | 环境、输出差异、人工复核及限制 |

完整数据集建议 30—60 行，包含两个连续周和正常/退款/重复 ID/缺失日期样本。使用 `order_id,date,region,product,net_sales`；金额以人民币元计、允许退款负值。重复订单、缺日期的处理在字典明确，不让作者或 Agent 随意猜测。环比以同口径两个完整周计算，上期为零时显示不可计算。

原型仅有 6 行简化样本用于展示交互，不包含上述异常与环比条件。正式案例不能拿原型样本冒充完整验收。

### 正文结构

先展示最终周报预览与本次要检查的三个数字。随后下载材料、确认环境、识别字段、生成报告、独立核对、修正一次口径错误、保存可复用提示词。

错误演示建议：把退款忽略导致销售额虚高。若是人工设计的反例，标为「设计反例」；实际 Agent 没犯这个错误时，不编造发生过的对话。

### 验收

- 所有引用文件存在；CSV 可正确读取中文；字典与计算脚本同口径。
- 正常/退款/重复/缺日期/上期为零均有预期结果。
- 原始输入哈希不变；报告每个关键数字可追溯。
- 人工不靠模型自己声称正确，至少复核总额、一个分组与一项异常。
- 给出找不到文件、字段误读、环比基数不足的恢复入口。

## B. 从三份资料到带来源的文章

**目标读者**：创作者、产品与技术写作者。目标练习时间 45—60 分钟，需实测。

**升级位置**：`src/content/docs/cases/write-an-article.md`。

**读完能够**：区分原始事实、自己的推断与待确认问题；围绕受众写出可复核初稿。

### 材料

建议目录：`examples/complete-workflows/creator/source-backed-article/`。

提供三份作者自制、允许再分发的资料：一页产品说明、一份明确标为合成的访谈记录、一份版本更新摘要。设定同一个虚构工具，避免将合成事实误读为真实产品宣传。

目录包含 `brief.md`、`sources/01-product.md`、`02-interview.md`、`03-changelog.md`、`sources/index.csv`、`prompts/`、`solution/outline.md`、`article.md`、`claim-map.csv`、`validation.md`。

事实映射表字段：`claim_id,article_section,claim,source_id,locator,evidence_type,confidence_note`。`evidence_type` 区分原文支持、作者推断、未确认。版本冲突不强行拼成一个结论。

### 工作流程

1. 阅读资料，列事实和冲突；先不写正文。
2. 明确受众、主问题、文章边界，确认一次大纲。
3. 在明确范围内连续写稿，无需逐段默认等待。
4. 对照事实表审查引用、数字、版本与夸大结论。
5. 编辑语气，保留必要的不确定性，输出终稿及待核验清单。

对照实验：第一版只有「帮我写文章」，第二版增加受众、事实表和禁止推断项。固定输入，记录输出差异；不能声称某提示保证无幻觉。

### 验收

- 关键事实在 claim-map 中逐项可定位，无不存在的引用。
- 至少一个冲突信息明确说明未决状态。
- 合成访谈未包装为真实用户证言；所有素材许可清楚。
- 终稿与初稿有可读 diff，复盘指出一项事实修正与一项表达修正。
- 不自动发布文章；交付停在本地稿件与核验材料。

## C. 从文章到 8 页可编辑演示稿

**目标读者**：需要汇报的创作者与业务人员。目标练习时间 60—90 分钟，需实测。

**升级位置**：`src/content/docs/cases/create-a-slide-deck.md`。依赖 B 的稳定终稿，也允许单独下载输入完成此案例。

**读完能够**：将长文压缩为一条汇报主线，制作可编辑 PPTX，核对版式与来源。

### 材料与页面结构

建议目录：`examples/complete-workflows/creator/article-to-slides/`，包含输入文章、受众简报、大纲、提示词、参考 PPTX、8 页预览、逐页说明、验证记录与字体/素材许可。

八页：主题与结论、受众问题、资料证据、方法、示例、限制、下一步、来源。每页只有一个主要结论；不得为凑图表编造数字。

### 工作流程

读文章 → 确认汇报目标和八页叙事 → 做两页样张定版式 → 完成其余页 → 检查原生可编辑对象、溢出和来源 → 修正 → 导出。

记录使用的客户端、可用演示工具/插件、输出程序及版本；不能承诺所有入口都能原生生成同样的 PPTX。工具不可用时解释替代产物的差异。

### 验收

- PPTX 可打开，关键文字为可编辑文本对象；不能把八张整页截图包装为可编辑成果。
- 全部八页渲染检查，无中文缺字、文字溢出、遮挡或不合理断行。
- 数字与文章/来源表一致；每张外来图片保留来源与许可。
- 至少在一种声明的演示软件与字体环境中打开验证。
- 记录一次实际修订；若演示设计反例，明确标注。
- 下载包、网页预览、实际文件版本一致。
