# 拾页 1.2：从散落的笔记里，找回写作需要的原文

> 本文依据三份合成教学资料撰写。拾页是虚构产品，“小林”是虚构受访者；本文不构成真实软件推荐或真实用户证言。三份资料均标注 CC0 1.0。

对个人作者来说，积累笔记之后，还要解决一个问题：写到某个主题时，怎样找到相关的原笔记，再判断哪些内容值得放进文章？拾页 1.2 的设定正是帮助个人整理指定本地文件夹中的笔记，生成主题索引和带源文件路径的摘要。它接受的格式只有 `.md` 和 `.txt`，不支持 PDF、网页抓取或图片识别。[P1–P2]

## 找到线索，再回到原文

在这套产品设定中，主题索引可以作为查找材料的入口，摘要则提供阅读线索。对写作者而言，可以先找到相关笔记，再沿源文件路径回看上下文，自己决定如何引用和组织材料。摘要不是原文，产品说明也没有承诺它完全准确，因此不能把摘要直接当作已经核实的写作依据。[P2]

合成访谈提供了一个具体情境：虚构受访者小林试用了十二份 Markdown 笔记，认为索引能帮助自己回到源文件；但有一次，摘要把两个相似项目当成了同一件事，小林对照原文后才改正。这个教学案例说明了为什么需要核对原文，不能用来推算产品的整体准确率或节省时间。访谈没有计时，也没有固定评估样本。[I1–I3]

## 1.2 更新了什么

版本摘要列出的变化有两项：摘要新增源文件路径，以及修复重新扫描时重复索引同一文件的问题。对作者而言，前者提供了回查材料的入口，后者针对重复索引的问题；资料没有给出量化效果，也没有说这次更新扩展了文件格式支持。[C1]

## 诊断上传的默认状态仍待确认

关于网络行为，资料中有一个不能略过的冲突：

- 9 月 10 日的产品说明称，1.2 的“诊断上传默认关闭”。[P3]
- 9 月 12 日的版本摘要称，“新安装的 1.2 默认开启诊断上传”。它没有说明这一条仅针对测试版还是正式版。[C2]

维护者尚未给出修正说明，不能仅凭版本摘要发布日期较晚，就认定产品说明已经失效。因此，目前无法从这些资料确定诊断上传的默认状态。需要请维护者确认：新安装的 1.2 究竟默认开启还是关闭诊断上传，相关描述适用于哪些版本，以及具体上传哪些字段。[C2–C3]

产品说明明确的是文件索引在本机完成。它没有提供诊断字段列表，也不足以证明全部功能都离线运行；开启诊断后的发送内容与网络行为，还需要查阅相应设置说明。[P3–P4]

如果你是一位用 Markdown 或纯文本积累素材的作者，这个虚构产品展示了一种整理思路：用索引定位材料，用源文件路径核对摘要，再由自己完成写作判断。至于处理速度、能省多少时间、准确率、付费方案和跨设备同步，现有资料都没有提供依据。[P1–P4]
