# 中文整站审查与下一阶段内容建议

审查日期：2026-09-18。范围：简体中文源站的结构、内容资产、导航组件与线上重点页面。

后续交付：[深化审查、执行规划与交互设计](next-content/README.md)。该目录包含 281 页结构盘点、24 项工作清单、首批作者 brief、三种首页方向与五视图原型。

## 结论

网站已经有较完整的知识覆盖，下一阶段应提高读者完成任务的成功率。优先补齐可跟做的项目、带验证的资源包与故障恢复实例，再考虑增加一级栏目。

现有强项是四模块主线、权限与验证意识、扩展机制的区分，以及带 starter、solution 和验证说明的 Bug 修复练习。主要短板是部分案例和 Skill 示例仍是骨架，学习路径尚未兑现完整练习，核验标记没有充分区分事实核对与实际运行。

## 审查范围与证据边界

- 盘点全部 281 个简体中文 Markdown/MDX 源页面：指南 178、提示词 19、Skills 29、案例 37、AI 路线图 13、宠物 3、主题 1、首页 1。独立 Astro 页面另计。
- 审阅重点模块入口、学习路径、代表性指南、模板、案例、Skill 示例、路线图和资源页，并检查 examples 目录及导航实现。
- 在线抽查首页、指南、表格案例、价格页；确认当前页面文本、重复标题和上下篇关系。视觉观察使用浏览器默认视口，未完成所有尺寸的响应式验收。
- 中文搜索“表格”返回 13 项结果，前列包括表格指南与分析表格案例；抽查可用。结果计数、复制按钮等局部界面仍出现英语，可列入中文体验优化。搜索摘要也收录了重复标题和装饰图文字，建议排除无检索价值的装饰内容。
- 运行现有链接检查：通过，覆盖 2,844 个源文件、10,407 个内部链接与图片引用。这个数字包含翻译和仓库文档，不是中文页面数量。检查不证明外部链接、锚点及产品事实全部正确。
- 本轮是全站结构审查与重点内容深读，不是逐句重新核验 281 页全部产品事实；没有进行完整构建、无障碍审计或性能基准测试。
- 本文记录建议；未修改公开正文、部署网站或提交 Git commit。

## 按优先级排列的问题

### 1. P1：价格页将演示估算与实际报价放在同一套排行中

证据：`src/data/chatgptPricing.ts:53` 起，只有 Plus 月付标记 `source: true`；Go、Pro、年付、Credits 使用固定 factor。`public/scripts/chatgpt-pricing.js:117` 以地区 Plus 基准价乘 factor 生成金额。页面确实提示“其他套餐按比例生成，用于交互展示”，但主标题、套餐标签、最低价、最高价和排名仍呈现为价格对比。

影响：读者可能将估算结果用于购买判断。切换套餐时原价字段仍沿用基准地区记录，也需一并修正。

建议：未核验套餐显示“暂无核验数据”，或移到明确命名的估算演示区；真实价格记录增加来源链接、采集日期、渠道、币种与税费口径。不能仅通过更新日期来表示完成核验。本次不判定任何具体金额的现行正确性。

### 2. P1：实战案例缺少完整练习材料

证据：`cases/analyze-a-spreadsheet.md:25` 使用 `@data/sales-q1.csv`，但 examples 中没有对应数据集。幻灯片案例提供主题占位符和两项检查，没有示例输入、交付文件或失败修正。写文章案例也主要展示提示流程。

对照：`examples/complete-workflows/developer/verified-bug-fix/` 已有 brief、starter、solution、三段提示词和验证说明。这是可复制到其他案例的成熟结构。

建议：优先升级现有表格、文章、幻灯片案例，每个案例增加真实或明确标注的合成输入、完整操作步骤、参考产物、一次纠偏、验收证据。未实际执行的内容标为“示例流程”，避免当作真实任务复盘。

### 3. P1：三条角色路径仍是未完成概览

证据：创作者、开发者、团队路径开头均有 MVP/后续补齐说明；首页把三条路径作为主要入口。

影响：读者能获得阅读清单，但难以知道每一步做什么、交付什么，以及是否已经学会。

建议：每条路径补 3—5 个里程碑，写明输入、操作、预期产物和完成条件。路径仍链接权威正文，不复制教程。先补创作者路径，串联“资料整理→文章→幻灯片”；开发者复用现有 Bug 修复练习；团队先完成一个小规模试点流程。

### 4. P1：verified 无法表达不同类型的验证

统计：281 页中，258 页含文末 verified，199 页核验日期为 2026-07-26。日期较早不等于内容已失效，但需要按主题波动性复核。

证据：写作/研究 Skill 明确是骨架，案例页面的依据常是“官方支持这类用途”。这能支持能力层描述，不能证明该示例实际运行成功或所有客户端都适用。

建议：将“内容状态”和“验证方式”分开记录：事实核对、示例实跑、编辑审阅；为实跑页记录客户端版本、系统、环境和验证日志。把结果摘要放在页首，详细来源保留在页尾。避免一律附四客户端适用标签。

### 5. P2：页面标题重复，通用装饰挤占正文空间

证据：`PageTitle.astro` 输出一级标题；61 个中文源页面正文另含一级标题。线上指南与表格案例均确认出现两个 H1，主题插图中还重复一次标题。

影响：用户在开始阅读前反复看到同一标题；目录和辅助阅读的层次也变得冗余。

建议：每页保留一个主标题；通用封面缩小或仅用于模块页。教程优先放真实界面、操作标注、输入输出对照和解释流程的图，不把装饰图当作教学证据。

### 6. P2：上下篇顺序没有始终服务学习路径

证据：线上 `/guide/` 页尾显示“上一页：故障排查”“下一页：提示词”，与本页正文推荐“从这里开始”的学习顺序不一致。配置使用目录自动生成导航。

建议：入口页明确指定下一步，模块首页必要时禁用跨模块上下篇；学习路径采用明确的步骤顺序。参考资料可以按检索需要组织，不要求所有页面都变成线性课程。

### 7. P2：Skill 示例尚未形成可交付资源库

证据：示例目录有写作、审查、研究、自动化四类，其中写作和研究页主要是一段 SKILL.md 骨架；examples 当前未形成对应的完整 Skill 包集合。

建议：先将现有四类各做成一个完整示例包，包含 README、SKILL.md、输入样本、预期输出、触发/不触发示例、失败测试、依赖和安装验证。不要只扩大清单数量。

### 8. P2：排障入口齐全，但操作深度不足

证据：桌面排障页已有症状表，错误参考也已覆盖认证、权限、网络、MCP 等分类。多数解决方式仍是“检查权限、重新登录、收窄范围”等方向。

建议：扩写现有页面，增加“现象→需要的证据→只改一个变量→预期结果→失败后下一步”，优先覆盖找不到文件、Skill 未触发、MCP 连接失败、任务等待审批、上下文跑偏。无需再新增一个重复的通用 FAQ。

### 9. P2：路线图需要解释时间节点的口径

证据：AI 路线图按月份串联 Prompt、RAG、MCP、Skills 等；Skills 详情采用某一厂商公开文章的日期作为节点。

建议：明确这是“本站选取的代表事件”，区分技术起源、厂商发布与本站收录日期；趋势判断标为作者判断。每个节点加“何时用、不必何时用、对应站内练习”。本次不将这些日期判定为历史事实错误，需另做来源核验。

### 10. P2：资源内容与主线之间缺少回流

证据：首页强调四模块，顶部另有路线图和资源；宠物、主题、价格页承担不同目的。独立价格页沿用单独导航。首页“最近更新”硬编码为 2026-08-01，而仓库已有 8 月 26 日的内容核验记录。

建议：保持“从入门到完成任务”的主线，把趣味资源放入资源区，并链接到实际制作案例。日期明确区分“本页更新”和“全站更新”。保留现有联系与 GitHub 贡献入口，新增能带当前页面 URL 的纠错入口和面向读者的更新记录。

## 实施顺序

第一批：修复报价呈现、重复标题、入口页上下篇与验证标识；交付表格周报完整练习。此批直接提高可信度和首次使用成功率。

第二批：交付文章、演示稿两个案例，将三者串成创作者路径；用现有 Bug 修复练习串起开发者路径。首页展示真实成果和三个任务入口。

第三批：把已有 Skill 骨架升级成可用包；补提示词对照实验、恢复实例和评估表。根据真实反馈决定继续增加哪些主题。

第四批：补团队试点、更新记录和环境兼容性维护。资源库积累到确有筛选困难时，再做按任务、难度、客户端、产物和验证状态的筛选界面。

首轮不建议投入每日新闻、泛 AI 工具排行榜或大量新的概念页。路线图、宠物和主题可以保留，但新增投入优先服务站点的实战教学承诺。

## 建议跟踪的结果

- 新读者能否从首页在两次点击内进入一个明确的实践任务。
- 新案例是否同时拥有输入、步骤、产物、验证和恢复说明。
- 读者能否依据参考输出判断自己是否完成，而不必请作者解释。
- 高波动事实是否有可追溯来源和核验日期。
- 反馈中“找不到入口”“照做失败”“版本不同”的问题是否减少。

这些是后续可测的目标；本次没有访问站点流量或行为分析，不能据此声称现有跳出率、完成率或转化率有问题。
