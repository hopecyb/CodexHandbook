# 内容扩展规划

日期：2026-08-01

## 1. 结论

本站下一阶段不应扩展成泛 AI 导航站，也不应停留在单纯的 Codex 产品说明书。更可行的方向是：

> 以 Codex 为主轴的 AI Agent 实战手册，帮助个人、创作者、开发者和团队把一次成功的 AI 协作沉淀成可复用、可验证、可交接的方法。

新增内容应服务这个定位。Skill 合集、高质量提示词、示例、工具使用文档、作品展、平台对比、教程和创作笔记都可以纳入，但必须先归入稳定内容体系，再决定是否独立成栏目。

## 2. 扩展原则

1. 先强化现有四模块，不急于增加一级导航。
2. 先做可长期复用的内容资产，再做容易过时的榜单和资讯。
3. 产品事实、方法论、模板、案例和个人笔记要分层存放。
4. 每个新增页面必须说明适用场景、边界、验证方式和维护责任。
5. 排行榜类内容优先改写为工具选型指南，减少主观排序和维护压力。

## 3. 内容归位

| 待扩展内容 | 建议归属 | 处理方式 |
|---|---|---|
| Skill 合集 | `Skills` | 作为核心资产库，按场景、难度和可复用程度分类 |
| 高质量提示词 | `提示词` | 做成模板库、任务库和反例库 |
| 高质量示例 | `实战案例` 与 `examples/` | 文档讲过程，`examples/` 放可复制材料 |
| AI 工具正确使用文档 | `Codex 指南`，后续可拆为工具指南 | 先讲能力边界和选型方法 |
| AI 作品展 | 后续 `showcase` | 等案例和作品数量足够后再独立 |
| AI 平台排行榜 | 后续工具选型专题 | 不作为 MVP 核心栏目 |
| 教程 | `Codex 指南` 与学习路径 | 承担新手上手和能力递进 |
| AI 创作笔记 | 先并入 `实战案例` 或维护者日志 | 内容稳定后再考虑独立为 `notes` |

## 4. 目标信息架构

第一阶段继续采用公开网站四模块：

```text
Codex 指南
提示词
Skills
实战案例
```

第二阶段在内容规模足够后，再评估是否增加：

```text
AI 工具指南
AI 创作笔记
AI 作品展
```

不建议在第二阶段以前新增“AI 平台排行榜”一级栏目。若需要榜单，应放入工具指南下，以“选型矩阵”“使用场景对比”“更新日期”形式呈现。

## 5. 四模块扩展方向

### 5.1 Codex 指南

目标：让读者理解 Codex 和 AI Agent 的能力边界，并能安全完成任务。

优先补充：

- AI Agent 能力地图
- Codex 适合做什么，不适合做什么
- App、CLI、IDE、Cloud 的选择方法
- 工具调用边界：终端、浏览器、Web、图片、文件、自动化
- 验收、撤销、恢复和人工确认
- 敏感数据、权限和团队治理

### 5.2 提示词

目标：把“怎么跟 AI 说清楚任务”变成可复制、可检查、可调试的方法。

优先补充：

- 高质量任务提示词结构
- 写作、研究、代码、设计、自动化、复盘模板
- 长任务提示词
- 让 Codex 先计划再执行的提示方式
- 常见失败提示词与改写示例
- 提示词调试清单

### 5.3 Skills

目标：把稳定工作流封装成可复用能力，形成本站的差异化资产。

优先补充：

- Skill 合集首页
- Skill 难度分级
- 内容创作 Skill
- 代码评审 Skill
- 研究总结 Skill
- 文档处理 Skill
- 自动化 Skill
- 团队协作 Skill
- Skill 安全边界与测试方法

### 5.4 实战案例

目标：通过真实任务展示从目标、提示、执行、纠偏到验收的完整链路。

优先补充：

- 第一次安全任务
- 修复 Bug 并补测试
- 写一篇文章
- 做一个网页或原型
- 生成一份演示文稿
- 研究并输出带来源的总结
- 自动化日报
- 多 Agent 协作案例

## 7. MVP 内容清单

下一阶段建议先完成以下内容，使网站从“结构完整”进入“可持续生产内容”的状态。

### P0：定位与入口

- 调整首页文案：从 Codex 指南手册升级为 Codex / AI Agent 实战手册
- 在首页强化四模块职责
- 在每个模块首页加入“推荐阅读顺序”和“可拿走的资产”

### P1：四个关键页面

- `guide/ai-agent-capability-map.md`
- `prompts/templates/index.md` 的模板库化改造
- `skills/examples/index.md` 的 Skill 合集化改造
- `cases/case-study-template.md` 的案例模板化改造

### P2：首批内容资产

- 10 条高质量提示词模板
- 5 个 Skill 示例
- 5 个完整案例
- 1 篇 AI 工具选型总览

### P3：增长内容

- AI 创作笔记试运行
- AI 作品展信息架构
- 工具选型矩阵
- 多语言同步策略更新

## 8. 里程碑

### 里程碑 1：内容扩展基础

目标：明确站点定位和新增内容边界。

交付：

- 本规划文档
- 首页和模块首页文案调整方案
- Prompt、Skill、案例、工具选型四类模板

### 里程碑 2：资产库成型

目标：让读者能直接复制、改造和实践。

交付：

- Prompt Library 首批模板
- Skill Library 首批示例
- Case Library 首批案例
- 每类内容的质量检查清单

### 里程碑 3：工具生态扩展

目标：在不稀释 Codex 主线的前提下覆盖更广 AI 工具。

交付：

- AI 工具选型总览
- 编程、写作、图片、演示、自动化工具专题
- 工具页面核验日期和更新机制

### 里程碑 4：展示与传播

目标：通过作品和创作笔记提升传播性。

交付：

- AI 作品展入口
- 创作笔记栏目
- 典型作品复盘
- 可分享的案例合集页

## 9. 质量门槛

新增内容上线前必须满足：

- 页面目的明确，不能只是资料堆砌。
- 至少链接到一个相关模块或案例。
- 易过时事实必须标注最近核验日期。
- 模板和案例必须包含验证方式。
- 涉及工具、权限、联网、文件写入或凭据时，必须说明风险边界。
- 不提交真实密钥、私人数据或无法复核的宣传性结论。

## 10. 暂缓内容

以下内容不进入下一阶段 MVP：

- AI 平台总排行榜
- 每日 AI 新闻
- 泛工具导航目录
- 没有复盘的作品截图集合
- 缺少使用边界的“万能提示词”
- 未经验证的工具推荐

这些内容可以作为素材池保留，但不应成为公开主导航。
