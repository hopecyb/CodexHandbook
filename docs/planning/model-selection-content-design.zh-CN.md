# 模型选择与套餐内容设计

日期：2026-10-24。状态：第一版已实现于工作区，尚未部署。交互筛选与模型实测留待后续版本。

## 目标与现状

让读者从具体任务出发，得到可尝试的模型、思考档位和升级条件，再判断是否需要付费。延续网站“完成任务、核对结果、积累可复用方法”的定位。

仓库已有四个互补入口：

| 现有页面 | 当前职责 | 本次建议 |
|---|---|---|
| `/guide/foundations/models-and-reasoning/` | 模型与思考强度的稳定概念 | 保留原理，增加最新选型指南入口 |
| `/guide/quality/usage-time-and-model-choice/` | 额度、API费用、等待与人工返工记录 | 承接性价比验证，不重复维护型号价格表 |
| `/guide/getting-started/account-plans-and-access/` | 账号与访问权限 | 增加“买哪个套餐”“看不到推荐模型”入口 |
| `/chatgpt-pricing/` | 2026-09-18 美国 App Store 公开内购清单快照 | 保留历史证据，增加独立的套餐选择区和官网来源区 |

当前价格页不是全球实时价格表。不得给 App Store 原始记录补推测的月付/年付周期，也不得用官网月费覆盖原始快照。现有部分外语导航仍称 Global Prices，后续应同步纠正名称与实际范围。

## 信息架构

新增 `/guide/reference/model-selection/`，标题“ChatGPT 与 Codex 模型怎么选”。使用 Starlight 文档布局，保证站内搜索、侧栏、目录、深浅主题与既有教程一致。

不增加一级导航。中文现有“查问题”入口已经适合承载选型；价格页保留现有 URL 和导航，页内增加“模型怎么选”的明显链接。

入口安排：

- 首页“找到下一步操作”新增“选模型、看套餐”卡片，链接选型指南。
- 参考目录加入“模型选择”；通过实际 sidebar 配置验证可见性与顺序。
- 模型基础、账号访问、用量记录三页各补一个语境明确的交叉链接。
- 选型指南链接价格页与三组现有实战案例；价格页反向链接选型指南。

## 选型页结构与文案

```text
面包屑：Codex 指南 / 参考 / 模型选择
ChatGPT 与 Codex 模型怎么选
按任务选择起点，再用结果决定是否提高档位。
适用入口 · 来源核对日期 · 查看更新依据

[ 普通聊天 Chat ] [ Work / Codex ]

你准备做什么？
[ 翻译与改写 ] [ 写文章 ] [ 分析表格 ] [ 写代码 ] [ 深入研究 ]
你更看重什么？ [ 节省用量 ] [ 综合平衡 ] [ 结果质量 ]

推荐起点：模型 / 档位
推荐理由：任务为何适合这个起点
何时提高：具体失败信号
当前不可用：替代路线 / 账号访问说明
[跟做相关案例] [记录一次实际用量]

模型对照：擅长任务 / 代价 / 不适用情形 / 可用入口
思考档位：何时提高，何时降低
套餐建议：简短摘要 → 查看完整价格来源
如何验证是否划算 → 现有记录模板
常见问题 / 官方来源 / 更新记录
```

第一屏给出建议，详细比较放在后面。默认 Work / Codex，与手册主轴一致；通过 `?surface=chat` 可以直达普通聊天。切换入口时只显示该入口已核对的模型和档位，不把 6.1 Sol 的 Work/Codex 可用性推广到 Chat。

首版可以先用静态分节与场景表，不依赖交互完成主要阅读。第二步加入筛选，增强后仍保留可搜索的正文。

### 场景建议示例

以下是待接入最新可用性数据的编辑建议，不是模型实测排名：

| 任务 | Work / Codex 推荐起点 | 提高档位的信号 | 关联现有材料 |
|---|---|---|---|
| 提取信息、转换格式 | Luna，客户端支持的适当档位 | 漏字段或不能处理明确边界；先检查输入 | 用量记录模板 |
| 根据多份资料写文章 | 6.1 Sol，默认档位 | 来源冲突处理不清、反复遗漏要求 | `/cases/write-an-article/` |
| 分析销售数据 | 6.1 Sol，默认档位 | 退款、去重、环比口径仍无法核对 | `/cases/analyze-a-spreadsheet/` |
| 修复代码缺陷 | 6.1 Sol，默认档位 | 跨文件依赖难以定位，修复反复失败 | `/cases/use-cases/software-development/fix-a-bug-with-verification/` |
| 多来源复杂研究 | 6.1 Sol；要求严格时考虑 Astra | 无法整合相互矛盾证据或保持任务约束 | 来源核对与质量章节 |

Chat 分支使用 Instant、Medium、High、Extra High、Pro 等当前界面选项，并按套餐和来源过滤；不套用 Work/Codex 的推理枚举。

推荐卡只使用“建议起点”“可尝试”措辞，不给虚构的准确率、速度星级或综合得分。没有模型可用性证据时，显示“请核对客户端可选项”，不保证用户一定拥有该模型。

## 价格页增量设计

保留 `/chatgpt-pricing/`，建议页面标题改为“ChatGPT 套餐选择与价格来源”，首屏提供锚点：套餐怎么选 / 官网价格 / 渠道快照 / 核验说明。

1. **套餐怎么选**：Free、Go、Plus、Pro 用紧凑对照表展示适合人群与升级触发条件。Plus 可标注“经常使用时可优先考虑”，避免无条件的“最划算”。Pro 子档位单独列明，避免只写一个 Pro 价格。
2. **官网价格记录**：使用独立来源记录，包含币种、周期、地区适用范围、税费是否已知、核对日期和官网链接。未知字段明确标记未知。
3. **渠道历史快照**：完整保留现有 App Store 数据，标题明确“2026-09-18 美国 App Store 历史快照”。
4. **购买前核对**：账号实际结账信息与可用模型为准。套餐月费、额外积分、API按量费率分开呈现。

模型页只放套餐决策摘要，不维护第二份月费表。价格页不重复整份模型能力说明。

## 视觉与交互

- 选型页使用现有文档字体、宽度、主题变量与提示块；不要引入新的整站视觉体系。
- 推荐结果用一张重点卡片，模型比较使用表格；避免多个等权卡片让读者重新做一遍选择。
- 桌面保留文档右侧目录；移动端筛选项换行，长对照表置于有名称的横向滚动区域。
- 入口切换使用语义化按钮或原生表单控件，支持键盘与清晰焦点；结果区域使用适当的 live 提示。
- 推荐理由用文字表达，颜色只作辅助。可复制当前选择链接，不需要用户登录。
- 不做虚构成本计算器。可展示同口径费率比，但明确它不等于完整任务成本比。

## 数据与维护

建议新增 `src/data/modelSelection.ts`，分开维护模型、入口可用性、思考档位和编辑推荐。不要把这些字段继续塞进主要存储价格页翻译的 `chatgptPricing.ts`。

记录至少包含：稳定 ID、产品入口、显示名称、套餐范围、已核对档位、来源 URL、来源核对日期、可用性说明、维护状态。推荐规则额外保存任务类型、偏好、理由、提高条件、替代路线。

价格可另建 `src/data/chatgptPlanQuotes.json`，与原有 `chatgptPriceQuotes.json` 的渠道快照分离。模型积分费率与 API 美元费率用不同计费类型，禁止跨类型直接比较。

沿用现有 `verification` 机制：官方产品事实标记 `source-checked`；网站场景建议注明编辑判断；只有保存模型标签、档位、输入与运行证据的实验才标记 `run-tested`。已有提示词对照实验实际模型未知，不能拿它给模型排名。

每次型号、入口、价格或套餐变化都需单独核对来源并更新记录。来源冲突保留范围与不确定性；不要仅刷新日期制造“最新”。定期人工检查是维护建议，本设计不创建自动化。

初版支持简体中文、英文，繁体按现有生成流程处理。其他语言只在有正文后接入本地化入口；遵守现有路由回退方式，不制造译文已完成的印象。

## 实施顺序与验收

### 第一批：完成内容闭环

- 新增选型指南的静态页面、场景表、来源与版本说明。
- 补齐首页、参考目录和三篇现有指南的入口。
- 价格页增加套餐建议、官网记录区域，保留旧快照。
- 更新相应简体、英文与繁体入口；验证其他语言回退。

验收：读者能找到“用哪个”“不可用怎么办”“是否值得付费”“怎么验证效果”四个答案；所有价格有周期与来源状态；Chat 和 Work/Codex 不混用。

### 第二批：交互推荐

- 用同一数据源增加入口、任务与偏好筛选。
- 加入可分享选择 URL 和明确的无匹配状态。
- 只对可用性过滤、规则优先级、URL恢复和缺失数据回退做必要测试。

验收：键盘可操作；手机不出现整页横向溢出；关闭 JavaScript 仍能读核心表格；不显示跨入口或不支持的推理组合。

### 第三批：真实案例验证

复用现有周报、文章、Bug 修复材料，用明确记录的模型与档位做对照。控制输入与工具条件，保留失败、重试、人工核对和费用证据。只有完成实验后，才新增“本站实测”内容。

实现后的仓库检查：`pnpm check:links`、`pnpm check:i18n`、`pnpm build`，并检查桌面/移动端、深浅主题与关键跳转。设计文档阶段不需要运行生产构建。
