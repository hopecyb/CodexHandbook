## 总体判断

网站已经具备手册的知识广度。下一阶段应优先完成可跟做的课程、可下载的示例包和可追溯的技术核验。新增内容的标准应是读者能完成一项工作，而不是再增加一个概念标题。

当前最好的内容基准是销售周报、带来源文章，以及已有的 Bug 修复练习：输入、步骤、参考产物、核对方法能互相对应。建议把这种结构推广到其他案例。

## 优先修正的问题

### P1：SDK 页的执行模型不清晰

证据：`src/content/docs/guide/developer-platform/sdk-overview.md:13` 使用“创建任务、轮询状态、拉取结果”，第 64—68 行混合 OAuth 委派、HTTP 错误码和 artifact URL，第 81 行直接写“SDK 触发 Cloud”。没有对应接口示例或具体引用。

官方当前将 Codex SDK 描述为控制本地 Agent，并提供本地线程启动、继续与恢复示例；定制客户端的认证、会话和审批交互另指向 App Server。现文容易让读者误以为 SDK 自带托管云任务接口。

修正：明确本地执行环境，把自建队列/远程 runner 标为架构方案，补固定版本的最小调用和实际输出。来源：[官方 Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)。

### P1：Issue 分流示例无法作为可执行自动化教程

证据：`src/content/docs/cases/use-cases/team-automation/issue-triage-suggestions.md:42` 将含 `bool` 的对象称为 JSON Schema。它既不是合法 JSON，也没有类型、枚举或必填字段约束。第 46 行只用 3 个 fixture、一致率大于 80% 作为上线门槛；按整条样本计，实际只有全部命中才能超过门槛，也无法覆盖注入、未知标签与缺失输入。

修正：提供真正的 Schema、允许标签列表、正常与恶意输入样本、校验器及 dry-run 输出；分开记录结构通过与分类质量。上线条件还需覆盖错误处理、去重、重试和人工接管，不以这 3 个样本推断整体可靠性。

### P1：角色路径仍未兑现实操承诺

证据：创作者、开发者、团队三个 `guide/learning-paths/*/index.md` 仍明确标注 MVP/后续补齐，正文主要是阅读清单，而首页已把它们作为主要入口。

修正：每条路径补 3—5 个里程碑，逐步明确输入、动作、产物、完成条件和下一步。先连接已有材料，避免另写一套重复教程。

### P1：演示稿资源尚未接入读者路径

证据：`cases/create-a-slide-deck.md` 仍是主题占位符与两项检查。工作区已有 `examples/complete-workflows/creator/article-to-slides/` 文件，但公开案例未提供其下载和预览，案例库仍标为“制作中”。

修正：完成产物验收后，接入 PPTX、PDF、八页预览、输入文章、备注和验证说明。仓库内有文件不等于读者已经能完成练习。

### P2：Skill 示例与排障内容深度不足

四类 Skill 示例仍主要是一段骨架；审查示例同时出现默认比较 main 与“审查未提交改动”，但未明确暂存、未暂存及分支差异。失败恢复页有流程，却缺一份可复现的失败现场。

修正：每类 Skill 配输入、参考输出、触发/不触发用例和失败样本；排障补脱敏日志、单变量修复与恢复结果。未观察到的输出应标为设计示例。

### P2：产品机制与资源页需要版本化证据

上下文优先级页将“当前提示词最优先”“项目安全禁令始终遵守”和“后一句未必覆盖”放在一起，缺少适用层级与例子。应分别解释指令来源、项目文件作用域和不可被普通提示改变的执行限制。[官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明了文件发现与合并顺序；这不等于所有指令来源的完整优先级。

路线图应分别标出代表事件日期、技术起源与作者趋势判断。宠物/主题页应提供测试版本、来源版本、恢复记录，尤其避免把第三方项目声明写成跨版本保证。本轮未判定这些资源的实际兼容性。

### P2：中文体验和内容命名存在小断点

- 浏览器实见搜索保留 `Clear`、`13 results for 表格`、`Load more results`，文章代码块保留 `Copy to clipboard`，标题锚点辅助名称仍是英语。
- 页脚仍称“ChatGPT全球价格”，而当前价格页仅覆盖美国 App Store 来源快照。应统一名称，避免导航承诺超出数据范围。
- 首页还有模块、资产、角色、能力地图等多组入口。建议依据读者测试压缩重复说明，保留任务入口优先；这是编辑建议，不是已证实的转化率问题。

## 最值得增加或升级的内容

| 优先顺序 | 内容 | 放在哪里 | 最小交付标准 |
|---|---|---|---|
| 1 | 文章到 8 页可编辑演示稿 | 升级现有幻灯片案例 | 输入、大纲、PPTX、预览、备注、软件渲染与编辑验证 |
| 2 | 三条角色实操路径 | 升级现有学习路径 | 每步有产物和验收；创作者连接资料→文章→演示，开发者连接读代码→修复→测试→审查 |
| 3 | 四个可安装 Skill 包 | 扩展现有 Skill 示例 | README、SKILL.md、样本、输出、触发反例、依赖、测试记录 |
| 4 | 同一任务的提示词对照实验 | 提示词模块 | 固定输入、两版提示、输出差异、评分依据；设计反例和真实运行分开 |
| 5 | 五个故障恢复练习 | 扩写现有排障/恢复页 | 文件找不到、Skill 未触发、MCP 连接失败、审批等待、上下文跑偏；各有证据和最小修正 |
| 6 | 可运行的团队自动化 | 扩写 Issue 分流/定时检查案例 | 合法 Schema、fixtures、dry-run、失败处理、停止和去重机制 |
| 7 | 用量与任务成本 | 指南新增专题 | 区分订阅用量与 API 计费，记录耗时/返工，说明选择与停止条件，易变事实附来源日期 |
| 8 | 工作流评估 | Skills 新增评估页 | 固定任务集、触发正反例、结构/事实/人工返工评价表；脚本通过不冒充整体成功率 |
| 9 | 团队两周试点 | 团队路径 | 范围、角色、样本任务、抽检、退出和推广条件 |
| 10 | 更新与纠错机制 | 维护专题及页内入口 | 更新影响、迁移动作、版本依据、带当前页面信息的纠错链接 |

以上多数应原位升级，不必增加一级导航。第一批建议交付“机制纠错 + 演示稿接入 + 创作者路径”；第二批交付 Skill 包、提示词对照与恢复练习；第三批交付评估、用量和团队试点。

首批验收指标：读者两次点击内找到材料；解压后能独立跟做；每项产物都有可检查的完成条件；能区分实际运行、作者自检、设计示例与待核验内容。本轮未读取行为分析，不能声称完成率或留存率已改善。
