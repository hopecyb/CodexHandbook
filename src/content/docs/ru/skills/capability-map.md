Механизмы расширения легко перепутать: они часто участвуют в одном рабочем процессе, но решают разные задачи.

Сначала построим общую схему системы. Промпт и `AGENTS.md` задают задачу и правила, Skill — многократно используемый процесс, MCP — внешние инструменты, Hook защищает точки жизненного цикла, Plugin объединяет и распространяет возможности, а Scheduled task запускает их по времени. Эти механизмы можно сочетать; единой обязательной «последовательности повышения уровня» не существует.

## Архитектура системы

![Архитектура многократно используемой рабочей системы Codex](/illustrations/arch-work-system.webp)

При чтении схемы обратите внимание на три момента:

- **Входные данные задачи** определяют, что нужно сделать сейчас, а правила проекта — что обязательно соблюдать каждый раз.
- **Исполнительные возможности** расширяют охват, но сами по себе не доказывают правильность результата; MCP, дочерние Agent и скрипты также должны подчиняться ограничениям разрешений и критериям приёмки.
- **Распространение и запуск** — не сам рабочий процесс. Plugin объединяет возможности, а Scheduled task в заданное время инициирует отдельный запуск.

## Восемь видов ответственности

| Ответственность | Механизм | Лучше всего решает | За что не отвечает |
|---|---|---|---|
| Текущая задача | Промпт | Что сделать сейчас, границы и критерии приёмки | Долгосрочные правила проекта |
| Постоянные правила | `AGENTS.md` | Команды репозитория, соглашения и границы каталогов | Полный порядок выполнения определённого вида задач |
| Многократно используемый процесс | Skill | Устойчивые шаги, справочные материалы, шаблоны и вспомогательные скрипты | Получение доступа к внешним системам из ниоткуда |
| Внешние инструменты | MCP / Connector | Доступ Codex к данным и операциям за пределами репозитория | Определение правильности бизнес-цели |
| Защита жизненного цикла | Hook | Регистрация, проверка, добавление контекста или блокировка до и после сеанса либо вызова инструмента | Замена тестов и проверки человеком |
| Объединение и распространение | Plugin | Упаковка Skills, коннекторов, MCP, Hooks и шаблонов задач | Автоматическое превращение всех возможностей в доверенные |
| Запуск по времени | Scheduled task | Запуск проверенной задачи по расписанию или с заданной периодичностью | Замена ясного промпта и условий завершения |
| Параллельное разделение работы | Дочерний Agent | Передача независимых исследований, тестов или Review | Автоматическое устранение конфликтов записи и затрат на координацию |

## Как сочетать возможности в одной задаче

Предположим, команда еженедельно проверяет риски зависимостей:

1. `AGENTS.md` задаёт допустимый менеджер пакетов, команды тестирования и каталоги, которые запрещено изменять.
2. Skill `dependency-audit` закрепляет шаги сбора зависимостей, сверки бюллетеней, классификации и проверки.
3. MCP для GitHub или реестра пакетов предоставляет внешние сведения; предпочтителен доступ только для чтения.
4. Hook может блокировать вывод с настоящими секретами или протоколировать вызовы внешних инструментов.
5. Plugin распространяет среди команды Skill, конфигурацию MCP и Hook единым пакетом.
6. Scheduled task запускается раз в неделю и создаёт только отчёт или черновик Issue; перед публикацией результат проверяет человек.

Отсутствие одного из уровней не делает решение «менее продвинутым». Для разовой локальной проверки зависимостей может быть достаточно ясного промпта и имеющихся команд терминала.

## Типичные соответствия

| Потребность | Рекомендуемый выбор |
|---|---|
| Унифицировать стиль кода и команды тестирования | AGENTS.md |
| Стандартизировать процесс Review PR | Skill |
| Читать задачи Jira/Linear | MCP |
| Установить один набор интеграций всей команде | Plugin |
| Сканировать секреты перед каждым коммитом | Hooks |
| Автоматически создавать черновик еженедельного отчёта по понедельникам | Automations (+ публикация человеком) |

## От разового успеха к командному активу

Чтобы решить, стоит ли дальше закреплять процесс, используйте следующую последовательность:

| Этап | Форма | Когда подходит |
|---|---|---|
| Разовый промпт | Описание задачи в текущем диалоге | Задача выполняется один раз либо подход ещё исследуется |
| Шаблон | Постоянный каркас «цель, контекст, ограничения, приёмка» | Задачи этого типа повторяются, но шаги ещё меняются |
| Skill | `SKILL.md` с шаблонами, справочными материалами или скриптами | Процесс устойчив, критерии успеха ясны |
| Plugin | Пакет из Skills, коннекторов, MCP, Hooks и шаблонов | Требуется единая установка, обновление и управление |
| Scheduled task | Сохранённая задача, правила времени и история запусков | Процесс уже проверен вручную и оправдывает периодический запуск |

MCP, Hook и дочерний Agent не являются обязательными ступенями этой последовательности. Добавляйте их лишь тогда, когда задаче действительно нужны внешние инструменты, защита жизненного цикла или параллельное разделение работы.

Подробную логику выбора см. в разделе [«Как выбрать способ расширения»](/ru/skills/choosing-an-extension-method/).

## Текущие границы продуктов

- Codex Skills определяются каталогами с `SKILL.md`, к которым можно добавлять скрипты, справочные материалы и ресурсы; полные инструкции Codex загружает по мере необходимости.
- Настольное App, Codex CLI и расширение IDE используют общую конфигурацию MCP в рамках одного хоста Codex.
- Сейчас Plugins доступны в поддерживаемых точках входа ChatGPT, настольном Codex и Codex CLI; расширение IDE не поддерживает просмотр и использование Plugin.
- Scheduled task создаются и управляются из ChatGPT Web или настольного App. В CLI и IDE можно предварительно проверить промпт, Skill или скрипт, но интерфейса управления Scheduled там нет.
- Дочерний Agent удобен для независимого исследования, тестирования и Review в режиме чтения; параллельная запись в одни и те же файлы увеличивает цену конфликтов.

Точки входа продуктов продолжат меняться. Перед конкретной настройкой сверьтесь с [таблицей возможностей](/ru/guide/reference/feature-comparison/) и официальными источниками ниже.
