**Skill** — это каталог с файлом `SKILL.md` (при необходимости также со скриптами и справочными материалами), который упаковывает устойчивый рабочий процесс в возможность, доступную Codex для **автоматического или явного вызова**.

Skill подходит для методов работы, которые уже повторялись и будут использоваться снова.

![Иллюстрация: успешный рабочий процесс складывают в набор инструментов, затем копируют и передают нескольким Agent для повторного использования](/illustrations/skills-toolkit.webp)

## Основные понятия

### Отличия от slash-команд

| | Slash-команда | Skill |
|---|---|---|
| Запуск | Вы вводите `/xxx` | Вы можете вызвать `$name`, либо модель подберёт Skill по описанию |
| Контекст | Обычно разворачивается сразу | **Прогрессивное раскрытие**: по умолчанию занимает только имя и описание, а полный текст читается лишь после выбора |
| Лучше всего подходит | Для фиксированных частых точек входа, которые легко запомнить | Для длинных процессов, требующих документации, и случаев, когда модель должна сама определить момент применения |

### Прогрессивное раскрытие

При запуске Codex видит только **name, description и путь** каждого Skill; полный `SKILL.md` загружается лишь после решения использовать Skill. Поэтому в основной текст можно включать подробные контрольные списки, не опасаясь переполнить контекст.

Учтите: для начального списка Skill действует **ограничение по числу символов** — он занимает лишь небольшую часть контекста. Основные сценарии запуска помещайте в самое **начало** `description`, иначе после усечения описание может перестать совпадать с задачей.

## Структура каталога Skill

```text
my-skill/
├── SKILL.md          # обязательно
├── scripts/          # необязательно: детерминированные шаги
└── references/       # необязательно: объёмная справочная документация
```

Минимальный пример `SKILL.md`:

```md
---
name: pr-review
description: Проверьте diff текущей ветки относительно main, отметьте риски и пробелы в тестах. Используйте, когда пользователь просит выполнить review, проверить PR или провести проверку перед слиянием.
---

## Шаги
1. Получите diff относительно main
2. Разделите замечания по файлам и категориям: логические ошибки, безопасность, производительность, тесты
3. Выведите список по уровням: блокирует / рекомендуется / nit
4. Не выполняйте push или слияние автоматически
```

## Где хранить

| Тип | Типичное расположение | Пояснение |
|---|---|---|
| Проектный Skill | `.agents/skills/<name>/` | Хранится в репозитории и используется всей командой |
| Пользовательский Skill | Пользовательский каталог skills (см. официальную документацию) | Доступен пользователю в разных проектах |
| Официальная подборка | Устанавливается через установщик | Путём управляет установщик; не путайте его с каталогами, созданными вручную |

**Не копируйте** ошибочные пути из устаревших руководств и не придумывайте поле `trigger:`. Ориентируйтесь на [официальную документацию по Skills](https://developers.openai.com/codex/skills).

## Способы запуска

1. **Явный**: в поддерживаемой среде вызовите `$skill-name` (имя должно совпадать с `name` во frontmatter)
2. **Неявный**: модель определяет применимость к текущей задаче по смыслу `description`

Как составить хорошее `description`:

- Укажите, когда Skill следует и когда не следует использовать
- Включите слова, которые может употребить пользователь (review, выпуск, changelog)
- Избегайте расплывчатых формулировок вроде «помогайте пользователю писать код»

## Рекомендуемый рабочий процесс

1. Заметьте, что один и тот же процесс уже повторялся несколько раз
2. Подготовьте `SKILL.md`, начав с текстового описания шагов
3. Испытайте `$name` и неявное сопоставление на небольшой задаче
4. Добавляйте `scripts/` только там, где нужна детерминированность
5. Отправьте изменения в `.agents/skills/` и откройте PR для команды

Практическое задание: [создайте первый Skill](/ru/skills/create-your-first-skill/).

## Частые вопросы

### 1. Чем Skill отличается от промпта?

- **Промпт** — временные указания для текущей задачи
- **Skill** — рабочий процесс, который можно снова применять к похожим задачам

### 2. Нужно ли сразу учиться писать Skill?

Нет. Сначала научитесь ясно формулировать обычные задачи. Превращайте процесс в Skill, когда он начнёт регулярно повторяться.

### 3. Skill и slash-команда — это одно и то же?

Не совсем. Slash-команда скорее служит быстрым входом, а Skill представляет собой рабочий пакет с полными инструкциями и процессом.

Skill не требуется для начала работы. Он полезнее для упорядочивания уже повторяющихся процессов.

## Границы безопасности

- Скрипты и вызовы MCP внутри Skill наследуют текущую политику подтверждений
- Не встраивайте секреты в Skill; используйте переменные окружения или аутентификацию MCP
- Команда должна проверять сторонние Skill так же, как зависимости

## Распространённые ошибки

- Слишком длинное или общее `description`, из-за которого Skill никогда не запускается либо запускается не к месту
- Один Skill объединяет десять не связанных друг с другом процессов
- Скрипты заменяют шаги, которые можно было ясно описать текстом, и усложняют сопровождение
