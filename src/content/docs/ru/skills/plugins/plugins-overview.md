ChatGPT и Codex используют общий публичный каталог Plugin. Plugin объединяет связанные возможности в доступный для обнаружения и установки рабочий процесс, а не вводит новый протокол вызова инструментов.

![Иллюстрация: перевязанные лентой пакеты расширений едут по конвейеру к нескольким рабочим станциям; на одной пакет распаковывают, с другой аккуратно удаляют](/illustrations/plugins-overview.webp)

## Что может входить в Plugin

| Компонент | Назначение | Что должен проверить установщик |
|---|---|---|
| Skills | Многократно используемые шаги, справочные материалы и скрипты | Подходят ли инструкции для текущей задачи, можно ли доверять скриптам |
| Connectors | Подключение к GitHub, Slack, Google Drive и другим инструментам | Области доступа OAuth, операции чтения и записи, охват внешних данных |
| MCP servers | Определение инструментов и аутентификации, возврат структурированных данных | Источник сервера, список инструментов, журналы и разрешения |
| Browser extensions | Возможности браузера для определённого рабочего процесса | Область доступа к браузеру и обоснованность такого доступа |
| Hooks | Запуск команды или инструмента MCP в точке жизненного цикла | Перед включением проверить точное определение и признать его доверенным |
| Scheduled task templates | Многократно используемая отправная точка в средах с поддержкой задач по расписанию | Частота, разрешения, условия завершения и проверка человеком |

## Отличия от Skill и MCP

| Механизм | Основной вопрос | Пример в наборе для Review PR |
|---|---|---|
| Skill | По каким шагам выполнять работу | Прочитать diff, проверить доказательства, упорядочить замечания по риску |
| MCP / Connector | Какие внешние инструменты доступны | Прочитать GitHub PR и комментарии |
| Hook | В какой точке жизненного цикла выполнять проверку | Запустить сканирование секретов после записи файла |
| Plugin | Как установить и распространять эти возможности вместе | Командный «пакет Review PR» |

Plugin — уровень распространения, а не последний шаг цепочки выполнения. Схему связей см. на [карте возможностей расширения](/ru/skills/capability-map/).

## Установка и первая проверка

### ChatGPT Web / настольное App

1. Откройте вкладку Plugins.
2. Проверьте издателя, описание и входящие возможности.
3. Установите Plugin; если требуется подключение к внешнему сервису, отдельно проверьте область разрешений.
4. Выполните низкорисковую проверку в новой задаче Chat, Work или Codex.

### Codex CLI

1. Введите `/plugins`, чтобы открыть каталог Plugin.
2. Установите пакет из настроенного каталога.
3. **Откройте новый сеанс**, а затем проверьте установленный в составе пакета Skill или инструмент.

Сейчас расширение IDE не поддерживает Plugin. Не составляйте инструкции по диагностике «в IDE не видно точки входа»: управляйте Plugin через настольное App ChatGPT или Codex CLI.

## Промпт для низкорисковой проверки

```text
Только проверь установленный <plugin-name>, не выполняй операции записи:
1. Перечисли связанные с ним Skills и инструменты, доступные в этой задаче.
2. Укажи, какие инструменты работают только на чтение, а какие могут вызвать внешние побочные эффекты.
3. Выполни один минимальный вызов на тестовых данных или с запросом только для чтения.
4. Сообщи, какой компонент фактически использован, и перечисли разрешения, которые ещё должен подтвердить человек.
```

Если Plugin требует внешнего подключения, при первой проверке не отправляйте сообщения, не изменяйте состояния, не удаляйте данные и не выполняйте массовую запись файлов.

## Процесс внедрения в команде

1. **Инвентаризация компонентов**: перечислите Skills, коннекторы, MCP, расширения браузера, Hooks и шаблоны.
2. **Проверка источника**: подтвердите каталог, репозиторий, издателя и правила обновления.
3. **Минимальные разрешения**: выполните пробный запуск с тестовым аккаунтом и областью доступа только для чтения.
4. **Изолированный пилот**: сначала используйте Plugin в непроизводственном проекте или небольшой команде.
5. **Review Hook**: через `/hooks` проверьте хеш и поведение Hook, входящего в Plugin.
6. **Описание выхода**: документируйте отключение, удаление, откат и отзыв OAuth.

## Важные границы

- Успешная установка не означает, что компоненты безопасны или подходят для текущих данных.
- Plugin может предложить подключить внешний сервис; предоставление разрешений — отдельный высокорисковый шаг.
- Hook из Plugin выполняется вместе со всеми совпадающими Hook из других источников и не заменяет старый Hook автоматически.
- Администратор Workspace может определять доступные Plugin и инструменты; каталог, видимый отдельному пользователю, не равен разрешённому для организации набору.
- Mobile подходит для использования Plugin, уже связанных с аккаунтом; не предполагайте наличия полного интерфейса управления.

## Когда Plugin не нужен

- Есть только один простой `SKILL.md`, а задачи объединения или распространения отсутствуют
- Разовый личный скрипт всё ещё быстро меняется
- Правила разрешений и обновления ещё нестабильны
- Целевые пользователи работают только в расширении IDE

Обычно проще сначала стабилизировать отдельный процесс Skill или MCP, а затем объединять и распространять его: такой пакет легче проверять.

## Контрольный список приёмки

- [ ] Целевая среда поддерживает Plugin
- [ ] Издатель и источник прослеживаются
- [ ] Внешние подключения и области доступа OAuth проверены
- [ ] Hook из Plugin проверен и признан доверенным
- [ ] Минимальная задача только для чтения выполнена успешно
- [ ] В новом сеансе доступен ожидаемый Skill или инструмент
- [ ] У команды есть инструкции по отключению, откату и отзыву разрешений
