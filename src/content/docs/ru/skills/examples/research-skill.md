Недоступный источник, отсутствие сведений и противоречие между двумя материалами требуют разных действий. Этот Skill сохраняет различия, чтобы читатель видел, какие выводы можно проверить, а для каких ещё нужны доказательства.

## Фиксированный вопрос и материалы

Пакет продолжает пример с вымышленным инструментом «拾页» из [упражнения со статьёй](/ru/cases/write-an-article/) и исследует входные форматы, настройки диагностики по умолчанию и поля отправляемых данных. В пакет входят три оригинальных синтетических источника; четвёртый источник из списка — пояснение сопровождающего — намеренно отсутствует. Не ищите настоящие веб-страницы вымышленного продукта и не придумывайте ответы.

| Состояние доказательства | Пример в пакете | Как представить результат |
|---|---|---|
| supported: подтверждено материалом | P1 перечисляет только Markdown и обычный текст | Указать поддерживаемый диапазон и место в источнике, не утверждая, что продукт протестирован |
| conflict: противоречие | В P3 настройка по умолчанию отключена, в C2 — включена | Представить обе версии, сохранив пробелы в данных о версии и условиях |
| unknown: неизвестно | Поля диагностической отправки не перечислены | Указать, чего не хватает, не угадывать отправляемое содержимое |
| unavailable: источник недоступен | Локальный файл для M не предоставлен | Сохранить недоступный источник и его влияние, не выдавать его за прочитанный |

## Установка и вызов

Поместите весь каталог в `.agents/skills/evidence-research/` учебного проекта, убедитесь, что точкой входа служит `SKILL.md`, и не перезаписывайте существующий пользовательский Skill с таким именем. Проверьте доступность Skill в клиенте по разделу [«Использование Skill»](/ru/skills/use-a-skill/), затем вызовите его:

```text
$evidence-research на основе документов из sources/catalog.json этого пакета
определи, можно ли подтвердить входные форматы «拾页» 1.2, настройки диагностики по умолчанию и поля отправляемых данных.
Создай my-output/report.md и evidence.csv, явно отметь противоречия и недоступные источники.
Сохрани синтетическую идентичность материалов и не ищи реальные веб-страницы вымышленного продукта.
```

Положительные и отрицательные примеры запуска находятся в `fixtures/trigger-cases.json`: процесс подходит для сравнения источников и проверки доказательств, но не нужен для творческого стихотворения или простого подсчёта файлов. Это проектные ожидания; автоматический запуск ещё не измерялся.

## Проверка источников и отчёта

Для необязательной проверки нужен Python 3.10+ без сторонних зависимостей. Выполните в распакованном каталоге:

```sh
# Вывести фактическое состояние каждого источника
python3 scripts/check_evidence.py --inspect-only
# Проверить эталонный отчёт
python3 scripts/check_evidence.py
# Проверить отчёт в формате пакета
python3 scripts/check_evidence.py --output my-output
# Выполнить регрессионные проверки во временной копии
python3 validation/test_checks.py
```

Для эталонного результата P/I/C имеют состояние `available`, M — `missing`, а структура четырёх доказательств проходит проверку. Код завершения 0 означает, что проверка выполнена и структура соблюдена, но не подтверждает доступность всех источников. Особенно при проверке только источников читайте каждое состояние отдельно.

Проверяющий скрипт обнаруживает изменение хеша содержимого, отсутствие или нечитаемость файла, а также отсутствие ожидаемого хеша. Недоступный источник нельзя использовать как прочитанное доказательство или молча исключать из отчёта. Скрипт обрабатывает только локальные файлы и не проверяет состояние HTTP или доступность веб-страниц.

## Восстановление после сбоя

- **Файл отсутствует**: проверьте путь; если материал действительно не предоставлен, сохраните состояние недоступности и представьте остальные обоснованные выводы.
- **Содержимое изменилось**: сравните версии и diff, заново проверьте ссылки; не обновляйте хеш лишь ради успешной проверки.
- **Доказательства противоречат друг другу**: проверьте версию, условия установки и применимость; если противоречие не разрешается, оставьте его открытым, не выбирайте ответ только по дате.
- **Факта не хватает**: перечислите поля или пояснения, которые должен предоставить сопровождающий; не выдавайте рекомендацию за подтверждённый факт.

В этом примере не требуется решать вопросы, ответа на которые нет в фиксированных входных данных. Если в реальном исследовании разрешено искать альтернативные источники, запишите основания замены и фактический результат доступа.

## Условия завершения и ограничения

Отчёт должен охватывать исследовательские вопросы, прочитанные и недоступные источники, основания по каждому пункту и дальнейшие шаги для получения доказательств. Автор сверил эталонный отчёт с фиксированными материалами, но независимый читатель или второй рецензент его не проверял.

Восемь тестов скрипта также демонстрируют слепую зону: ложное утверждение «поддерживает все форматы с абсолютной точностью» всё равно проходит структурную проверку при допустимой ссылке. Поэтому скрипт не способен доказать смысловую поддержку или определить настоящее противоречие между фрагментами. Перед выдачей результата по-прежнему необходимо прочитать каждый источник.

Затем с помощью [Skill для написания текстов](/ru/skills/examples/writing-skill/) можно превратить проверенные выводы в статью, сохранив состояния противоречия и неизвестности.
