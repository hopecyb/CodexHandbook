Этот Skill превращает предоставленные материалы в статью, сведения в которой можно сверить с источниками, и сохраняет требования к стилю, фактические основания и неподтверждённые вопросы. Он подходит для написания по источникам и фактологического Review; ради исправления одной опечатки запускать весь процесс не нужно.

Материалы используют вымышленный инструмент «拾页» из [упражнения по написанию статьи с источниками](/ru/cases/write-an-article/). Сначала можно выполнить упражнение со статьёй, а затем сохранить этот метод работы с помощью Skill.

## Установка и первый вызов

Поместите весь каталог в `.agents/skills/source-backed-writer/` учебного проекта и убедитесь, что `SKILL.md` находится на первом уровне. Если Skill с таким именем уже существует, сначала сравните их и не перезаписывайте его. Механизм обнаружения установленного Skill описан в разделе [«Использование Skill»](/ru/skills/use-a-skill/). После того как Skill станет доступен в клиенте, вызовите его явно:

```text
$source-backed-writer прочитай три документа из sources/ в этом учебном пакете,
напиши по references/style.md обзор для независимого автора и сохрани его в my-output/.
Подготовь article.md, claim-map.csv и unresolved.md.
Сохрани синтетическую идентичность материалов и ничего не публикуй.
```

Для чтения и написания Python не требуется. Необязательная проверка структуры использует только стандартную библиотеку Python 3.10+. Выполните в распакованном каталоге Skill:

```sh
# Проверить приложенный эталонный текст
python3 scripts/check_article.py
# Проверить текст, созданный в формате этого пакета
python3 scripts/check_article.py --output my-output
# Воспроизвести восемь проверок во временной копии
python3 validation/test_checks.py
```

На этой странице действительно запускались скрипты; автоматическое обнаружение и вызов моделью в конкретном клиенте не проверялись. Если в реальной задаче используется собственный формат результата, проверяйте его по своим соглашениям, не подгоняя под формат учебного пакета.

## Как стиль влияет на статью

[Образец стиля](/downloads/skills/source-backed-writer/references/style.md) содержит пару для сравнения:

> Неудачный вариант: «拾页» — универсальный чудо-инструмент, который легко обрабатывает любой формат и удваивает вашу продуктивность.

Исправленный вариант: «В документации перечислены только Markdown и обычный текст. Сначала попробуйте скопировать небольшой фрагмент заметок, затем сверьте указанный в сводке исходный текст». Первое предложение основано на материалах, второе представляет рекомендацию автора; в таблице фактов их нужно различать. Если пользователь отдельно задал тон или структуру, приоритет имеют требования реальной задачи.

## Как обрабатывать противоречия и пробелы

В описании продукта P3 сказано, что отправка диагностических данных по умолчанию отключена, а в сводке версии C2 — что для новых установок она включена. Финальный текст должен представить обе версии как противоречие, не объявляя более поздний документ автоматически верным. Поля отправляемых данных не указаны, поэтому вопрос остаётся в [списке открытых вопросов](/downloads/skills/source-backed-writer/solution/unresolved.md).

В синтетическом интервью нет измерения времени и фиксированной выборки для оценки, поэтому нельзя утверждать «продуктивность удваивается» или рассчитывать точность. Для восстановления удалите необоснованные числа, верните ограничения и обновите таблицу фактов — искать правдоподобный ответ для вымышленного продукта не нужно.

## Приёмка и ограничения проверки

После завершения проверьте каждый пункт:

- У ключевых фактов есть место в источнике, которое можно найти; факты, рекомендации и неизвестные сведения разделены.
- В основном тексте сохранены синтетическая идентичность, ограничения входных данных и неразрешённые противоречия.
- Правка стиля не удалила необходимые оговорки и не изменила структуру, которую запросил пользователь.
- После успешной проверки формата цитат каждое предложение сверено с материалами; одного наличия номера недостаточно.

Скрипт обнаруживает изменение хеша источника и ошибки структуры цитат, но не определяет, действительно ли источник подтверждает смысл. В пакет намеренно включено тестовое ложное обещание возможности: оно проходит структурную проверку, если сохранить допустимый номер ссылки. Это доказывает необходимость фактологического Review человеком.

## Когда Skill запускать не следует

Исправление опечатки, Review Git-патча и разработка новой функции не должны автоматически превращаться в полноценную задачу написания статьи. Завершение статьи также не предоставляет разрешение на публикацию. [Сценарии запуска](/downloads/skills/source-backed-writer/fixtures/trigger-cases.json) выражают проектные ожидания, а не отчёт об успешности маршрутизации.

После завершения вернитесь к [пути автора](/ru/guide/learning-paths/creator/) и внесите использованные стиль и критерии приёмки в собственную многократно используемую инструкцию.
