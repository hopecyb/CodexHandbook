Повторный запуск проверки не означает, что уведомление нужно отправлять каждый раз. Этот Skill развивает [пример проверки ссылок](/ru/cases/use-cases/team-automation/scheduled-link-check/): регистрирует изменения, восстановление и ошибки выполнения, а при неизменном результате ничего не сообщает.

## Установка и ручная проверка

Поместите весь каталог в `.agents/skills/quiet-link-monitor/` учебного проекта и не перезаписывайте существующий Skill с таким именем. Убедитесь в доступности Skill по разделу [«Использование Skill»](/ru/skills/use-a-skill/), затем вызовите его:

```text
$quiet-link-monitor на примерах из пакета воспроизведи сбой, повторную проверку и восстановление.
Работай во временной копии, сохраняй отдельное состояние, в конце сообщи об изменениях событий и не отправляй уведомлений.
```

Сначала скрипт можно запустить отдельно — модель и аккаунт не требуются. Нужна только стандартная библиотека Python 3.10+:

```sh
python3 validation/test_monitor.py
```

Для ручного запуска скопируйте `fixtures/broken` в собственный каталог `work-site`. Затем дважды выполните в каталоге Skill:

```sh
python3 scripts/run_once.py --site work-site --state run-state.json
python3 scripts/run_once.py --site work-site --state run-state.json
```

Первый запуск завершается с кодом 1 и регистрирует событие сбоя. Второй снова возвращает 1, но `new_event` имеет значение null. Исправьте тот же каталог по образцу `fixtures/fixed` и запустите скрипт ещё раз: код завершения станет 0, а результат — `recovered`. Не заменяйте каталог сайта другим путём, чтобы имитировать восстановление: состояние отклонит изменение области.

[Сводка трёх фактических запусков CLI](/downloads/skills/quiet-link-monitor/validation/manual-run.json)

## Что регистрируется и когда процесс останавливается

Файл состояния должен находиться за пределами проверяемого каталога. В нём сохраняются результаты каждого запуска, число последовательных сбоев и постоянные события. Скрипт записывает этот файл и соседний файл блокировки, поэтому операция не является полностью доступной только для чтения. Содержимое сайта не изменяется.

| Ситуация | Поведение |
|---|---|
| Первый успешный результат | Создаётся базовое состояние, нового события нет |
| Первый сбой или изменение обнаруженной проблемы | Сохраняется событие изменения |
| Тот же результат повторяется | Новое событие не создаётся |
| Сбой исправлен | Сохраняется событие восстановления |
| Проверка три раза подряд завершается внутренней ошибкой | Сохраняется событие остановки, процесс переходит на паузу |
| Состояние повреждено, файл блокировки конфликтует или сайт не совпадает | Немедленная остановка без перезаписи исходного состояния |

Обнаруженная битая ссылка считается допустимым результатом проверки, а не внутренней ошибкой выполнения. После перехода на паузу обычный вызов не продолжает проверку. Установите и устраните причину, затем явно возобновите работу:

```sh
python3 scripts/run_once.py --site work-site --state run-state.json --resume
```

Не удаляйте файл блокировки или состояние автоматически ради обхода сбоя. После аварийного завершения процесса файл блокировки может остаться; сначала убедитесь, что активных процессов нет. В [описании состояния и восстановления](/downloads/skills/quiet-link-monitor/references/operations.md) перечислены коды завершения, правила хранения и границы параллельного выполнения.

## Кандидат на уведомление не означает отправленное уведомление

Скрипт только записывает локальные события; значение всех полей `delivery` равно `not-sent`. Он не создаёт расписание и не отправляет сообщения. У события есть стабильный для этой записи идентификатор; повторение результата не создаёт новое событие того же состояния.

После подключения разрешённого средства отправки прочитайте постоянные недоставленные события, удалите дубликаты по идентификатору и сохраните подтверждение доставки. Если читать только `new_event` последнего запуска, событие может потеряться при прерывании процесса. Пакет не содержит средство отправки и не гарантирует доставку «ровно один раз» между системами.

## От ручного к периодическому запуску

Сначала убедитесь в успешной сборке, затем проверяйте самый свежий результат. Если сборка не удалась, остановитесь и не проверяйте старый каталог. При каждом запуске планировщик должен использовать один и тот же сайт и файл состояния, не допуская параллельной перезаписи. Сначала запустите процесс вручную в целевой среде и проверьте журнал и поведение остановки, а затем задайте периодичность. Канал, получатели и область настоящего уведомления должны следовать из уже выданных разрешений.

Настоящее расписание и доставка сообщений здесь не проверялись. Внешние ссылки по-прежнему имеют состояние `unchecked`, поэтому локальный успешный результат нельзя описывать как «все ссылки на сайте работают».

## Область применения и приёмка

Пакет подходит для повторяющегося аудита ссылок в документации, но не для обычного ежедневного отчёта о продажах, творческого письма или автоматической установки задач в производственную среду. Сценарии запуска отражают проектные ожидания; маршрутизация модели не измерялась.

После упражнения должны остаться записи о первом сбое, тихом повторе, исправлении и восстановлении, а также свидетельства паузы и явного возобновления. Восемь тестов пакета подтверждают это локальное поведение состояния, но не доказывают правильность решений модели, доступность сети или надёжность в настоящей производственной среде.
