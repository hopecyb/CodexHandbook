Перед Review точно определите, что сравнивается. Этот Skill не путает «текущие незакоммиченные изменения» с «коммитами относительно main» и не пропускает ошибку в index только потому, что рабочее дерево выглядит нормально.

[Загрузить полный scoped-review v1.0.0](/downloads/skills/scoped-review/scoped-review-1.0.0.zip) · [Открыть SKILL.md](/downloads/skills/scoped-review/SKILL.md) · [Инструкция по установке и использованию](/downloads/skills/scoped-review/README.md)

## Возможности

| Запрос пользователя | Область сбора | Что не входит |
|---|---|---|
| Review только staged | HEAD → index | Unstaged-содержимое |
| Review только unstaged | Index → рабочее дерево | Staged-патч |
| Review текущих незакоммиченных изменений | Два указанных патча сохраняются отдельно; новые файлы перечисляются | Содержимое новых файлов нужно прочитать отдельно |
| Review коммитов относительно указанной ветки | Единственный merge-base → HEAD | Локальные незакоммиченные изменения |

Skill не угадывает main по умолчанию. Если базовая версия не существует, он сообщает об ошибке, а не незаметно меняет область. Сборщик предоставляет только доказательства; для поиска дефектов всё равно нужно учитывать связанный код и тесты.

## Установка и первый вызов

Нужны Python 3.10+, Git и локальный учебный репозиторий хотя бы с одним коммитом. Поместите распакованный `scoped-review/` в `.agents/skills/` целевого проекта и убедитесь, что точка входа находится в `.agents/skills/scoped-review/SKILL.md`. Если Skill с таким именем уже существует, сначала сравните их и не перезаписывайте его.

Обнаружение локальных Skills и доступные точки входа определяются [официальной документацией](https://learn.chatgpt.com/docs/build-skills). После установки убедитесь, что Skill доступен, и вызовите его явно:

```text
$scoped-review проведи Review текущих незакоммиченных изменений кода в этом учебном репозитории.
Не изменяй файлы: сначала перечисли замечания, затем опиши охват staged, unstaged и новых файлов.
```

Этот учебный пакет не устанавливается в личную конфигурацию автоматически. Если вы пока не хотите его устанавливать, запустите приложенный скрипт напрямую и изучите собранную область.

## Воспроизведение сценария, который легко пропустить

Синтетические входные данные находятся в `fixtures/scenario.json`:

1. Формула скидки в базовой версии верна.
2. Ошибочная формула добавлена в staged: `amount * (1 - percent)`.
3. В рабочем дереве снова восстановлена правильная формула `amount * (1 - percent / 100)`, но изменение не добавлено в staged.

В таком состоянии `git diff HEAD` может не показывать изменений, однако коммит из index всё равно внесёт ошибку. При `amount=40, percent=10` staged-версия возвращает -360 вместо правильного значения 36.

Правильный Review должен отдельно отметить, что staged-версия содержит ошибку, а unstaged-патч исправляет её. Полный [эталон автора](/downloads/skills/scoped-review/fixtures/expected-review.md) также объясняет, почему режим ветки не должен включать эту локальную проблему; это не фактический результат модели.

## Запуск проверок из пакета

Выполните в распакованном каталоге Skill:

```sh
python3 validation/test_scopes.py
```

Семь тестов во временном Git-репозитории проверяют область, регрессию пропущенного Review, отклонение неверной базовой версии, список новых файлов и отсутствие изменений в проверяемом репозитории. При успехе код завершения равен 0. Тесты не записывают данные в ваш настоящий проект.

Использование сборщика в реальной задаче:

```sh
python3 scripts/collect_diff.py --repo /path/to/your/repo --mode working-tree
```

Замените путь репозиторием, Review которого разрешён. Для режима ветки обязательно дополнительно указать `--base`. Выходной JSON может содержать закрытый код и не загружается автоматически; полная команда приведена в [описании областей](/downloads/skills/scoped-review/references/scopes.md).

## Когда Skill запускать не следует

Редактирование статьи и разработка новой функции не относятся к этому Skill. Для расплывчатой просьбы «сделай review» сначала определите область по контексту и задайте вопрос, только если она всё ещё неясна. В [сценариях запуска](/downloads/skills/scoped-review/fixtures/trigger-cases.json) из пакета записано семь ожидаемых запросов; фактическая автоматическая маршрутизация ещё не измерялась.

## Условия завершения и ограничения

- В отчёте указаны фактически проверенный снимок, базовая версия и область файлов.
- Findings содержат место, условие запуска, влияние и доказательства; предпочтение по стилю не выдаётся за блокирующую проблему.
- Содержимое связанных неотслеживаемых файлов проверено либо явно отмечено как непроверенное; бинарные и игнорируемые файлы, а также подмодули не выдаются за охваченные.
- Указано, какие проверки выполнены, а какие нет; отсутствие замечаний не гарантирует отсутствия дефектов.
- Review завершается отчётом и не изменяет файлы, не выполняет commit или push.

Затем сохраните результат с помощью шаблонов Review и передачи задачи из [пути разработчика](/ru/guide/learning-paths/developer/). Короткий исходный каркас `pr-review` по-прежнему подходит для изучения структуры; этот пакет использует другое имя, чтобы не перезаписать уже существующую личную версию.
