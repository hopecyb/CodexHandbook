Каталог `templates/` нужен не только для экономии времени на форматировании. Его практическая задача — стабилизировать результат Skill, чтобы не придумывать структуру заново при каждом запуске.

Если `references/` определяет, «на что опираться во входных данных», то `templates/` — «как должен выглядеть результат». Здесь стоит хранить структуры для результатов, которые должны быть единообразными и удобными для проверки.


В `templates/` находятся многократно используемые форматы результата Skill: отчёты Review, каркасы changelog, сравнительные таблицы исследований.

## Пример

```text
review-skill/
├── SKILL.md
└── templates/
    └── review-report.md
```

Укажите в `SKILL.md`: «Выведите результаты Review по структуре templates/review-report.md».

## Как распределяется ответственность

- `SKILL.md` отвечает за процесс
- `templates/` определяет форму результата

Можно представить это ещё проще:

- Skill определяет, «как действовать»
- Шаблон определяет, «как представить результат»

Это устраняет две распространённые проблемы:

- Структура результата меняется при каждом запуске
- Все сведения присутствуют, но их неудобно читать, сравнивать и проверять

## Когда стоит использовать `templates/`

Если результаты определённого типа каждый раз должны выглядеть примерно одинаково, подготовьте шаблон. Например:

- Отчёт Review
- changelog
- Сравнительная таблица исследования
- Контрольный список перед выпуском

Для первого Skill каталог `templates/` не обязателен.
Но если вам приходится постоянно повторять «выведи результат по этой структуре», её стоит вынести в отдельный файл.

## Распространённые заблуждения

### 1. Шаблон лишь делает результат красивее

Он не только улучшает оформление, но и повышает стабильность, упрощает сравнение и последующую проверку.

### 2. При наличии шаблона требования к результату в Skill можно не описывать

Нельзя.

В `SKILL.md` всё равно следует указать, когда применять шаблон и какие поля обязательны.

### 3. Шаблон нужен для любого результата

Необязательно.

Если результат этого типа почти не повторяется или его структура каждый раз сильно различается, жёсткий шаблон лишь создаст ограничения.

## Когда создавать отдельный `templates/`

Если вы два или три раза подряд повторили «выведи по этой структуре», пора добавить `templates/`.

Главная ценность `templates/` — стабильная структура результата, удобная для дальнейшего повторного использования.
