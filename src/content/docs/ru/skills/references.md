В `references/` удобно хранить объёмные материалы, которые не нужно разворачивать при каждом запуске, чтобы основной процесс оставался кратким и упорядоченным.

Смысл не просто в том, чтобы «положить рядом ещё несколько документов». Отдельно храните материалы, которые **не требуется читать сразу каждый раз, но которые действительно нужны на определённом шаге**, и открывайте их по мере необходимости.


Если основной текст `SKILL.md` стал слишком длинным, перенесите подробные стандарты, описание API и контрольные списки в `references/`, а в шагах ссылайтесь на них по мере необходимости.

## Пример

```text
my-skill/
├── SKILL.md
└── references/
    ├── style-guide.md
    └── api-contracts.md
```

Укажите в `SKILL.md`:

```md
При Review стиля кода прочитайте references/style-guide.md и выполните проверку по изложенным в нём правилам.
```

## Как распределяется ответственность

- `SKILL.md` задаёт основной процесс
- `references/` хранит материалы, открываемые по мере необходимости

Можно представить это ещё проще:

- `SKILL.md` — инструкция по работе
- `references/` — справочный шкаф

Благодаря этому при чтении Skill не приходится сначала продираться через длинные фоновые пояснения, но необходимые подробности всегда доступны.

## Когда стоит выделить `references/`
Рассмотрите разделение, если в `SKILL.md` появилось что-то из следующего:

- Большой блок стандартов каждый раз занимает место
- Смешаны справочные материалы по нескольким разным темам
- Фоновые материалы прерывают основной процесс, и при первом чтении его трудно проследить

Для первого Skill каталог `references/` не обязателен.  
Обычный порядок — **сначала добиться работы, а разделить содержимое лишь после реального роста**.
## Распространённые заблуждения

### 1. `references/` — не просто место, куда копируют часть содержимого

Его главная задача — сохранить основной процесс кратким и ясным, чтобы его можно было сразу выполнить.

### 2. Больше справочных материалов — не всегда лучше

Если складывать в `references/` всё подряд, беспорядок просто переместится из одного файла в несколько.

### 3. При наличии `references/` файл `SKILL.md` можно сократить до минимума

Основной процесс всё равно должен оставаться в `SKILL.md`, иначе при первом чтении будет непонятно, как действовать.

## Принципы

- Оставляйте основной процесс в `SKILL.md`, а справочные материалы загружайте по мере необходимости
- Посвящайте каждый файл одной теме, чтобы упростить сопровождение
- Не повторяйте в references шаги, уже описанные в SKILL.md
