Skill — не просто ещё один шаблон промпта.

Он влияет на способ работы Codex и иногда включает скрипты или дополнительные ресурсы.

Поэтому при ненадёжном источнике, непроверенном содержимом или дрейфе версий риск может быть почти таким же высоким, как у MCP. На этой странице описано, как команде **выбирать, устанавливать, обновлять и проверять** Skill.

## Почему это важно знать обычному пользователю

Если вы выполняете хотя бы одно из следующих действий:

- Устанавливаете Skill, которым поделился другой человек
- Подключаете командный Skill в проекте
- Обновляете установленный Skill
- Рекомендуете Skill коллегам

то вы уже участвуете в цепочке распространения риска.

Безопасность Skill не может зависеть только от централизованного управления: каждому пользователю нужна базовая способность оценивать риски.

## Упрощённая модель угроз

| Риск | Проявление |
|---|---|
| Вредоносный Skill | Склоняет раскрыть секреты или выполнить разрушительную shell-команду |
| Избыточные разрешения | Читает или изменяет пути, которых не должен касаться |
| Цепочка поставок | Зависит от скомпрометированного стороннего репозитория Skill |
| Устаревший Skill | Несовместим с новой версией CLI и ведёт себя неверно |

## Что проверить перед установкой

При оценке Skill ответьте на три вопроса:

1. Откуда он получен?
2. Какие дополнительные действия он поручит Codex?
3. Понимаю ли я его `SKILL.md` и приложенные скрипты?

Если на два из трёх вопросов нет ответа, не устанавливайте Skill сразу в рабочий проект.

## Принципы установки

1. **Источник**: предпочитайте официальный каталог или внутренний Git компании; осторожно относитесь к анонимным gist
2. **Чтение**: перед установкой откройте `SKILL.md` и приложенные скрипты, проверьте подозрительные запросы разрешений
3. **Изоляция**: храните Skill клиентских проектов отдельно от личных экспериментов
4. **Минимальность**: если задачу решает один Skill, не устанавливайте десять

## Распространённые заблуждения

### 1. Skill — лишь текстовая инструкция и не несёт реального риска

Поскольку Skill влияет на рабочий процесс, выбор инструментов и способ запуска скриптов, риск не ограничивается «изменением стиля текста».

### 2. Популярный Skill можно сразу использовать в рабочем проекте

То, что Skill подходит другим, не означает его совместимость с вашим репозиторием, границами разрешений и правилами команды.

### 3. Обновить Skill — примерно то же, что обновить документ

Для команды обновление Skill меняет автоматизированное поведение, поэтому к нему нужно относиться так же серьёзно, как к обновлению зависимости.

## Версии и обновления

| Практика | Пояснение |
|---|---|
| Фиксация версии | Записывайте в командной документации имя Skill и commit/tag |
| Review изменений | Обновляйте Skill через PR, как зависимости |
| changelog | Ведите примечания к выпускам командного набора Skill |
| Откат | Храните копию предыдущей версии, чтобы быстро переключиться при проблемах |

Plugin позволяет упаковывать и централизованно распространять Skill: [обзор Plugins](/ru/skills/plugins/plugins-overview/).

## Командные практики

Если Skill долго используется несколькими людьми, не оставляйте его на уровне «кто-то прислал путь в личном сообщении».  
Более надёжный подход:

- Постоянный источник
- История версий
- Описание обновлений
- Способ отката

## Вызов через `$skill`

При явном вызове `$name` намерение пользователя ясно. Когда **модель выбирает Skill автоматически**, ограничьте список и сценарии применения в `AGENTS.md`.

## Контрольный список командного управления

- [ ] Белый список допустимых источников установки Skill
- [ ] Для новых сотрудников в рамках адаптации устанавливается только «базовый пакет»
- [ ] Раз в квартал пересматривается необходимость установленных Skill
- [ ] Настройки согласованы с [правилами разрешения и запрета](/ru/guide/customization/rules/allow-and-deny-patterns/)

## Распространённые ошибки

- Установка «универсального Skill в один клик» по ссылке из чата
- Ссылка на Skill из личного пути в AGENTS.md рабочего репозитория
- Отсутствие smoke-теста после обновления
- Полное доверие к поведению Skill без чтения `SKILL.md`
