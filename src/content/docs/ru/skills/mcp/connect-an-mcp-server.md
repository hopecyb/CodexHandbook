В этой главе с помощью актуальных официальных интерфейсов выполняется минимальный полный цикл: **добавить сервер -> просмотреть конфигурацию -> подтвердить инструменты в сеансе -> выполнить один вызов только для чтения**.

![Иллюстрация: маленький помощник вставляет коннектор в сервер; после авторизации загорается зелёный сигнал, тестовый запрос отправляется по кабелю в базу данных и получает ответ](/illustrations/mcp-connect.webp)

## Перед началом

- Прочитайте [обзор MCP](/ru/skills/mcp/mcp-overview/)
- Убедитесь, что локально выполняется `codex mcp --help`
- Для первого подключения выберите доверенный источник и сценарий только для чтения
- Не записывайте настоящий токен в историю команд, промпт или репозиторий

## Способ A: добавьте сервер STDIO через CLI

В официальном примере используется сервер документации Context7:

```bash
codex mcp add context7 -- npx -y @upstash/context7-mcp
codex mcp list
```

Команда записывает сервер в конфигурацию Codex. После `--` указана команда запуска сервера STDIO. При первом запуске может потребоваться загрузить npm-пакет, поэтому заранее проверьте его имя и источник.

## Способ B: измените config.toml напрямую

Пользовательская конфигурация по умолчанию находится в `~/.codex/config.toml`. Доверенный проект также может использовать проектный `.codex/config.toml`.

Пример STDIO:

```toml
[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp"]
startup_timeout_sec = 10
tool_timeout_sec = 60
```

Пример удалённого Streamable HTTP:

```toml
[mcp_servers.internal_docs]
url = "https://mcp.example.com"
bearer_token_env_var = "INTERNAL_DOCS_TOKEN"
enabled_tools = ["search_docs", "get_doc"]
```

`internal_docs`, адрес и имена инструментов служат только примером структуры; замените их настоящими значениями из документации вашего сервера. В `bearer_token_env_var` хранится имя переменной окружения, а не сам токен.

## Сервер OAuth

После настройки сервера с поддержкой OAuth выполните:

```bash
codex mcp login <server-name>
```

В списках MCP настольного App и IDE сервер, которому требуется OAuth, также будет отмечен; для него доступно действие Authenticate.

## Где просматривать в трёх клиентах

| Среда | Точка настройки или просмотра |
|---|---|
| Настольное App ChatGPT | Settings -> MCP servers; после сохранения — Restart; для просмотра подключения введите `/mcp` |
| Codex CLI | `codex mcp add/list/login`; в TUI введите `/mcp` |
| Расширение IDE | Меню с шестерёнкой -> MCP servers; после сохранения — Restart extension |

Все три клиента используют общую конфигурацию в рамках одного хоста Codex; поддерживать три отдельных файла не нужно. ChatGPT Web локальную конфигурацию не читает.

## Промпт для проверки

```text
Выполни следующую проверку только через подключённый сейчас сервер MCP:
1. Перечисли имена доступных инструментов для поиска в документации разработчика.
2. Выбери один инструмент только для чтения и найди основы использования Node.js test runner.
3. Укажи, какой инструмент был фактически вызван.
4. Не выполняй операции записи и не подключай другие сервисы.
```

Свидетельства приёмки: сервер присутствует в `codex mcp list` или `/mcp`, инструмент только для чтения успешно вернул структурированный результат и не запросил лишних разрешений.

## Настройки минимальных разрешений

- `enabled_tools`: разрешает только перечисленные инструменты
- `disabled_tools`: дополнительно исключает инструменты после применения списка разрешённых инструментов
- `enabled = false`: сохраняет конфигурацию, но временно отключает сервер
- `required = true`: прерывает запуск при сбое инициализации сервера; подходит для действительно обязательной зависимости

## При сбое

Не изменяйте несколько полей одновременно наугад. Сохраните точный текст ошибки и следуйте разделу [«Диагностика подключения MCP»](/ru/skills/mcp/debugging-mcp/), по очереди проверяя чтение конфигурации, процесс или сеть, аутентификацию и отдельный инструмент.
