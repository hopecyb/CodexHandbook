MCP превращает намерение модели использовать внешнюю возможность в структурированный вызов инструмента. Протокол подходит для подключения сторонней документации, браузера, Figma, систем управления задачами и внутренних сервисов.

![Иллюстрация: маленький помощник подключён к единому коммутационному центру, от которого стандартные кабели ведут к базе данных, календарю, доске задач и облачному диску](/illustrations/mcp-overview.webp)

## Цепочка одного вызова

```text
Codex в задаче
  -> клиент MCP (предоставляется хостом Codex)
  -> сервер MCP (локальный процесс или удалённый сервис)
  -> внешняя система (документация, дизайн, задачи, внутренний API)
  -> структурированный результат возвращается в задачу
```

| Компонент | Ответственность | За что не отвечает |
|---|---|---|
| Хост Codex | Читает конфигурацию, подключается к серверу и предоставляет инструменты Agent | Не определяет бизнес-разрешения вместо сервера |
| Сервер MCP | Определяет инструменты, аутентификацию, параметры и структурированные результаты | Не гарантирует автоматически безопасность инструментов |
| Skill | Задаёт, когда и по каким шагам использовать инструменты | Не устанавливает сетевое соединение |
| Plugin | Объединяет и распространяет Skills, коннекторы, MCP и другие возможности | Не является ещё одним протоколом инструментов |

## Поддерживаемые способы подключения серверов

### STDIO

Codex запускает локальный процесс и обменивается с ним данными через стандартный ввод-вывод. Этот способ подходит для локальных средств разработки и сервисов, работающих только на текущем компьютере.

Основной риск: процесс наследует локальную среду выполнения; необходимо проверить команду, источник зависимостей и передаваемые переменные окружения.

### Streamable HTTP

Codex подключается к удалённому адресу. Согласно текущей официальной документации, поддерживаются Bearer-токен, OAuth и аутентификация сеанса ChatGPT для доверенных серверов первой стороны.

Основной риск: удалённый сервис получает аргументы инструментов; необходимо проверить TLS, идентификацию, ведение журналов, хранение данных и разрешения инструментов.

## Как сочетаются MCP, Skill и Plugin

Рассмотрим еженедельную проверку задач с высоким приоритетом:

| Уровень | Содержимое |
|---|---|
| MCP | Предоставляет инструменты `search_issues`, `get_issue` и аналогичные |
| Skill | Определяет условия отбора, требования к доказательствам и формат отчёта |
| Plugin | Упаковывает Skill, коннектор и определение MCP для установки командой |
| Scheduled task | Запускает проверенную задачу в заданное время |

У этих механизмов независимые обязанности; они не образуют лестницу повышения уровня. Полную схему см. на [карте возможностей расширения](/ru/skills/capability-map/).

## Когда стоит подключать MCP

| Стоит | Пока не стоит |
|---|---|
| Один и тот же внешний сервис опрашивается многократно | Разовый поиск по публичной веб-странице |
| Нужны структурированные параметры и результаты инструмента | Достаточно операций с файлами в репозитории |
| Требуется OAuth или детальный контроль инструментов | Доступен только интерфейс записи с высокими разрешениями, тестовой среды нет |
| Команде нужно единообразно использовать подключение | Источник сервера нельзя проверить |

## Уровни безопасности

1. **Пробный режим только для чтения**: публичная документация или тестовый арендатор, включены только инструменты запросов.
2. **Командная проверка**: ограничены проект, роль и список разрешённых инструментов, регистрируются сбои и длительность.
3. **Ограниченная запись**: небольшие обратимые операции записи с подтверждением человеком.
4. **Управляемая эксплуатация**: разрешения можно отозвать, конфигурацию — проверить, журналы обезличиваются, среды изолированы.

Не помещайте токен в промпт, Git или статический HTTP-заголовок. Предпочитайте OAuth, `bearer_token_env_var` или передачу переменных окружения.

## Контрольный список перед подключением

- [ ] Можно проверить источник сервера, версию и команду запуска
- [ ] В списке инструментов отмечены операции чтения и записи
- [ ] Используется тестовый арендатор или аккаунт с минимальными разрешениями
- [ ] Понятно, какие параметры и результаты попадут в удалённые журналы
- [ ] Для записи предусмотрены подтверждение, откат и аудит
- [ ] Команда знает, как отключить сервер и отозвать разрешения
