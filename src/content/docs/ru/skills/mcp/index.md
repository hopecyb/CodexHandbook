MCP (Model Context Protocol) отвечает на вопрос «как Agent вызывает инструменты и данные за пределами репозитория», а не «как описать рабочий процесс».

## Для кого подходит

- Для разработчиков, которым нужно, чтобы Codex обращался к документации, макетам, задачам или внутренним инструментам
- Для команд, которым требуется единая конфигурация внешних инструментов, OAuth и минимальных разрешений
- Для сопровождающих, разбирающихся, почему «сервер настроен, но инструменты не видны или вызов завершается ошибкой»

Если задача ограничивается чтением и записью в текущем репозитории, сначала используйте встроенные возможности работы с файлами и терминалом. Подключайте MCP лишь при реальной необходимости во внешнем контексте или операциях.

## Порядок чтения

1. [Обзор MCP](/ru/skills/mcp/mcp-overview/): разграничьте ответственность MCP, Skill и Plugin
2. [Подключение сервера MCP](/ru/skills/mcp/connect-an-mcp-server/): добавьте первый сервер через CLI или `config.toml`
3. [Диагностика подключения MCP](/ru/skills/mcp/debugging-mcp/): последовательно проверьте четыре уровня — конфигурацию, запуск, аутентификацию и инструмент

## Текущие границы поддержки

- Настольное App ChatGPT, Codex CLI и расширение IDE используют общую конфигурацию MCP в рамках одного хоста Codex.
- Локальные клиенты Codex поддерживают серверы STDIO и Streamable HTTP.
- ChatGPT Web не читает локальный `~/.codex/config.toml`; удалённые инструменты MCP предоставляются ему установленным Plugin.

## Запомните три правила

1. MCP предоставляет инструменты, но не определяет надёжный процесс вместо вас; устойчивый процесс всё равно следует описывать в Skill или `AGENTS.md`.
2. Возможности сервера зависят от предоставляемых им инструментов и области учётных данных, стоящих за ними.
3. Первое подключение начинайте с режима только для чтения, тестового арендатора и небольшого числа инструментов; не проводите пробный запуск с токеном администратора производственной среды.
