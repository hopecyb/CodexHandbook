Сбои MCP часто сводят к фразе «инструмент не работает». Быстрее сначала определить уровень ошибки, а затем менять только одну переменную.

![Иллюстрация: прозрачный разрез из четырёх уровней — конфигурации, транспорта, аутентификации и инструмента; маленький помощник с фонариком последовательно проверяет их и ремонтирует разорванную трубу на одном из уровней](/illustrations/mcp-debugging.webp)

## Сначала сохраните четыре свидетельства

```bash
codex mcp list
codex mcp --help
node --version   # только если сервер STDIO использует Node.js
python3 --version # только если сервер STDIO использует Python
```

Также запишите имя сервера, транспорт STDIO или Streamable HTTP, точный текст ошибки и среду, в которой она возникла: настольное App, CLI или IDE. Не сохраняйте полный токен.

## Диагностика по четырём уровням

| Уровень | Типичный признак | Первая проверка |
|---|---|---|
| Конфигурация | Сервера нет в списке | Путь к файлу, синтаксис TOML, имя сервера, `enabled` |
| Запуск / подключение | Тайм-аут инициализации | Команда STDIO и PATH либо URL HTTP, TLS и прокси |
| Аутентификация | 401/403, требование войти | Состояние OAuth, переменная окружения токена, область доступа |
| Инструмент | Сервер доступен, но вызов завершается ошибкой | Имя инструмента, аргументы, список разрешённых инструментов, тайм-аут инструмента |

## 1. Убедитесь, что конфигурация прочитана

- Пользовательский файл находится в `~/.codex/config.toml`.
- Проектный файл находится в `.codex/config.toml` и загружается только для доверенного проекта.
- Настольное App, CLI и IDE используют общую конфигурацию в рамках одного хоста Codex; не создавайте для них расходящиеся копии.
- Проверяйте фактическое состояние через `codex mcp list` или `/mcp` в сеансе, а не по одному лишь наличию файла.

## 2. Сервер STDIO не запускается

Проверьте, доступна ли `command` через PATH, соответствует ли версия среды выполнения требованиям сервера, существует ли `cwd` и можно ли доверять источнику пакетов зависимостей.

Прямой запуск команды доказывает только способность исполняемого файла запуститься. Если сервер MCP ожидает протокольный ввод и не завершается, это может быть нормальным поведением; такой запуск не является полноценным тестом вызова инструмента.

Повышайте `startup_timeout_sec` только при действительно медленной инициализации. Значение по умолчанию — 10 секунд; необоснованно большой тайм-аут лишь скроет ошибочную команду.

## 3. Не удаётся подключиться через Streamable HTTP

Проверяйте по порядку:

1. URL и сертификат TLS
2. Корпоративный прокси или VPN
3. Существует ли переменная окружения, на которую ссылается `bearer_token_env_var`
4. Нужно ли повторно выполнить `codex mcp login <server-name>` для OAuth
5. Получил ли журнал сервера запрос инициализации

Не подставляйте токен как статическое значение `http_headers` «для временной диагностики»: он легко попадёт в файл конфигурации и снимки экрана.

## 4. Сервер доступен, но инструмент не работает

| Признак | Что проверить |
|---|---|
| Инструмент вообще не отображается | `enabled_tools` / `disabled_tools`, список инструментов от сервера |
| Tool not found | Версию сервера, переименование инструмента, не хранит ли сеанс старый список |
| Ошибка проверки аргументов | Сверьтесь со схемой инструмента, не угадывайте поля по старому промпту |
| Тайм-аут вызова | Сузьте запрос, затем проверьте `tool_timeout_sec`; значение по умолчанию — 60 секунд |
| Пустой результат | Проверьте диапазон данных и фильтры в исходной системе под тем же аккаунтом |

## Промпт для минимального воспроизведения

```text
Проверь только сервер MCP <server-name>:
1. Сообщи имена инструментов, которые сейчас видны для него.
2. Вызови <readonly-tool>, используя только <minimal-arguments>.
3. Сохрани без изменений тип ошибки и сообщение сервера, но скрой учётные данные.
4. Не вызывай другие серверы и не выполняй операции записи.
```

## Критерии завершения диагностики

- [ ] Состояние в `codex mcp list` соответствует ожиданиям
- [ ] Один инструмент только для чтения успешно вызван с минимальными аргументами
- [ ] Корневая причина отнесена к конкретному уровню, а не описана как «после перезапуска заработало»
- [ ] Временный токен, отладочные журналы и широкие разрешения удалены
- [ ] Командная конфигурация и описание исправления обновлены
