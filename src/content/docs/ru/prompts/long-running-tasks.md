Длительные задачи часто проваливаются по следующим причинам:

- Слишком много работы выполняется за один раз
- По ходу работы нет контрольных точек
- По мере удлинения ветки диалога ограничения из разных сообщений начинают противоречить друг другу

Главное в длительной задаче — не написать более длинный промпт, а разбить работу на небольшие этапы с контрольными точками.

Разделите длительную задачу на этапы и задайте для каждого критерии приёмки:

```text
Этап 1: только изучить вопрос и перечислить варианты решения (код не изменять)
Этап 2: реализовать минимальное изменение
Этап 3: добавить тесты и запустить …
После каждого этапа остановись и дождись моего подтверждения.
```

## Почему длительные задачи особенно легко отклоняются от курса

Обычно они одновременно включают несколько видов работы:

- Понять проблему
- Спроектировать решение
- Внести изменения
- Выполнить проверки
- Подготовить описание для передачи работы

Если объединить всё это в одно поручение «сделать до конца», риск заметно возрастёт.

## Распространённые заблуждения

### 1. Длительная задача — это не просто более подробное описание короткой задачи

Длительные задачи требуют прежде всего **поэтапного управления**; одного дополнительного контекста недостаточно.

### 2. Недостаточно просто перечислить этапы

Для каждого этапа желательно указать чёткую точку выхода, например:

- Только предложить варианты, не изменяя код
- Выполнить лишь минимальную реализацию
- Только добавить тесты и провести проверку

### 3. Не всегда лучше доводить всё до конца в одной ветке диалога

Если задача слишком длинная, зачастую понятнее передать работу, подвести итог и продолжить в новой ветке диалога.

## Достаточная схема разбиения

Длительную задачу можно сначала разделить на 4 этапа:

1. Исследование: понять проблему, ничего не изменяя
2. План: перечислить шаги, риски и способы проверки
3. Выполнение: внести минимальные изменения
4. Проверка: запустить проверки, записать выводы и подготовить передачу работы

## Более практичная формулировка

```text
Этап 1: сначала изучи вопрос и перечисли варианты решения, не изменяя код; дождись моего подтверждения
Этап 2: внеси только минимальные изменения, затем сообщи, на что они влияют
Этап 3: добавь недостающие проверки и запусти их
Этап 4: подведи итог изменений, рисков и дальнейших рекомендаций
```

Лучше предусмотреть возможность остановиться и проверить результат каждого этапа, чем выполнять всё без перерыва.
