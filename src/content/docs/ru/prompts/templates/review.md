В задачах проверки проще всего отклониться от цели, если с самого начала незаметно перейти к исправлениям.

Надёжнее сначала найти проблемы, а затем решить, нужно ли что-либо менять.

## Шаблон

```text
Проверь текущий diff относительно 【main/целевой ветки】, но пока не изменяй код.
Критерии:
1. Не выходят ли изменения за рамки 【issue/спецификации】
2. Логические ошибки, граничные случаи, обработка ошибок
3. Безопасность: секреты, инъекции, разрешения
4. Соответствуют ли тесты и документация изменениям
Результат — список по уровням: 🔴 Блокер / 🟡 Рекомендация / 🟢 Пройдено; для каждого пункта укажи файл и номер строки.
```

## Когда подходит этот шаблон

- Для проверки PR.
- Для проверки diff.
- Для оценки рисков в очередном наборе изменений документации или конфигурации.

## Распространённые ошибки

### 1. Проверка означает попросить высказать мнение

Точнее, это просьба системно найти проблемы по заданным критериям.

### 2. Если явных ошибок нет, проверка пройдена

Следует также выяснить:

- не вышли ли изменения за рамки задачи;
- обновлены ли тесты и документация;
- нет ли проблем с безопасностью и границами.

Смысл шаблона проверки — последовательно выявить риски по фиксированным критериям, а не дать общую оценку качества.
