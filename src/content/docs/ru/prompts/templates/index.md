Слово «шаблон» часто вызывает одну из двух реакций:

- Шаблон кажется слишком жёстким, и его не хочется использовать.
- Шаблон копируют буквально, даже не разобравшись, какие фрагменты нужно заменить.

Главная задача шаблона — помочь не упустить важные разделы, а не думать за вас.

Страницы с шаблонами сохраняют структуру задачи, а не выдают единственный правильный ответ.

## Как использовать шаблон

Рекомендуемый порядок:

1. Выберите тип шаблона, наиболее близкий к вашей задаче.
2. Замените содержимое заполнителей `【】` реальными данными своей задачи.
3. Удалите неактуальные разделы.
4. Добавьте ограничения и критерии приёмки, характерные именно для этой задачи.

Шаблон больше похож на строительные леса, чем на эталонный ответ.

| Шаблон | Когда применять |
|---|---|
| [Изучение](/ru/prompts/templates/understand/) | Разобраться в кодовой базе, документации или материалах и сформировать общее представление |
| [Создание](/ru/prompts/templates/create/) | Создать функцию, текст или другой результат с нуля |
| [Изменение](/ru/prompts/templates/change/) | Итеративно доработать существующее решение |
| [Диагностика](/ru/prompts/templates/diagnose/) | Найти первопричину проблемы, пока не изменяя код |
| [Проверка](/ru/prompts/templates/review/) | Проверить изменения в diff, PR или документации |
| [Исследование](/ru/prompts/templates/research/) | Провести исследование или сравнение со ссылками на источники |
| [Автоматизация](/ru/prompts/templates/automate/) | Автоматизировать повторяющиеся задачи, скрипты и процессы без постоянного наблюдения |

## От шаблона к рабочему процессу

Некоторые промпты достаточно использовать один раз, а регулярно повторяющиеся стоит развивать дальше.

| Повторяющаяся задача | Сначала оформить как | После стабилизации можно развить до |
|---|---|---|
| Подготовка PR | Шаблон проверки/изменения | Skill с фиксированным контрольным списком |
| Создание документации API | Шаблон создания/изменения | Skill + скрипт документации |
| Расширение тестового покрытия | Шаблон изменения | Skill + соглашение о командах тестирования |
| Поиск причин проблем с производительностью | Шаблон диагностики | Отдельный Agent или специализированный Skill |
| Проверка форматирования при каждом сохранении файла | Одного шаблона недостаточно | Hook |
| Изучение внешней заявки перед изменением кода | Шаблон исследования | MCP + Skill |

Шаблон подходит для процесса, который запускает человек. Skill — для однотипных задач, которые регулярно выполняются по фиксированной процедуре. Hook — для обязательной автоматической проверки в определённой точке процесса. MCP — для подключения к внешней системе.

## Как быстро выбрать формат для задачи

Сначала ответьте на 4 вопроса:

1. Задача выполняется только один раз?
2. При повторном выполнении шаги останутся в основном прежними?
3. Есть ли фиксированный контрольный список или формат результата?
4. Нужны ли внешняя система, скрипт или автоматическая блокировка?

| Вывод | Рекомендуемый формат |
|---|---|
| Однократная задача, которую ещё нужно обсудить | Полный промпт без шаблона |
| Часто повторяется, но процесс ещё меняется | Шаблон |
| Процесс стабилен, формат результата фиксирован | Skill |
| Нужен отдельный независимый исполнитель для глубокого анализа | Отдельный Agent |
| Необходимо читать внешнюю систему | MCP, по возможности сначала в режиме только чтения |
| Проверка обязательна на каждом определённом этапе | Hook |
| Решение нужно передать всей команде в едином виде | Plugin |

Длинный промпт не обязательно лучше. Переиспользовать стоит задачи, которые уже неоднократно проверены, имеют чёткие границы и однозначные критерии приёмки.

## Распространённые ошибки

### 1. Шаблон нужно копировать без изменений

Если не заменить заполнители и не удалить неактуальные разделы, шаблон, наоборот, сделает задачу бессодержательной.

### 2. Само использование шаблона делает промпт профессиональным

Шаблон помогает сохранить структуру, но не решает за вас:

- какова реальная цель;
- где провести границы;
- как сформулировать критерии приёмки.

### 3. Чем полнее шаблон, тем лучше

Новичку достаточно шаблона, в котором есть всё необходимое, но нет лишней громоздкости.

Сначала выберите правильный тип шаблона, затем адаптируйте его к своей задаче. Не используйте сам шаблон как готовую задачу.

Принципы составления описаны в разделах [Основы промптов](/ru/prompts/basics/) и [Структура задачи](/ru/prompts/task-anatomy/).
