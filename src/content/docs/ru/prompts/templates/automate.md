В задачах автоматизации часто думают только о том, можно ли запустить процесс автоматически, не ответив сначала на другие вопросы:

- Что произойдёт при сбое?
- Кто увидит результат?
- Можно ли безопасно остановить процесс при ошибке?

Главное в шаблоне автоматизации — сохранить контроль над задачей даже при возникновении проблем.

## Шаблон

```text
Цель: автоматизировать 【повторяющуюся задачу】 с помощью 【скрипта/Skill/задачи по расписанию】.
Запуск: 【вручную / по расписанию / в CI】
Входные данные: 【источник данных, файл конфигурации】
Ограничения:
- При сбое выдавать понятный код завершения и указывать расположение журнала
- Не встраивать секреты в код; использовать переменные среды
- Предусмотреть режим dry-run
Приёмка:
- Для 【примера входных данных】 получен ожидаемый результат
- В документации объяснено, как запускать процесс и устранять неполадки
```

## Когда подходит этот шаблон

- Для повторяющихся задач с чёткими правилами.
- Для процессов, которые нужно оформить в виде скрипта или запускать по расписанию.
- Когда вы хотите заранее предусмотреть такие защитные меры, как dry-run, журналы и коды завершения.

## Распространённые ошибки

### 1. Автоматизация полностью исключает участие человека

Многие процессы проще автоматизировать частично: например, автоматически выполнять проверку, собирать сводку или создавать черновик.

### 2. Если задача один раз выполнилась успешно, её уже можно автоматизировать

Чтобы процесс мог надёжно работать длительное время, дополнительно нужны:

- журналы;
- коды завершения;
- dry-run;
- инструкции по устранению неполадок.

Ценность шаблона автоматизации в том, что он помогает процессу работать безопасно и долго.
