Когда задача одного типа — проверка публикации, синхронизация документации или сканирование безопасности — выполняется **в третий раз** копированием промпта, стоит задуматься о [Skill](/ru/skills/overview/). Эта страница связывает [методы организации работы](/ru/cases/workflows/) с системой расширений.

## Какие вопросы решает этот подход

- Когда превратить шаблон промпта в Skill
- Какие части должен включать Skill: инструкции, ресурсы и скрипты
- Как предоставить Skill команде и версионировать его

## Признаки того, что процесс стоит закрепить

- Фиксированные шаги + фиксированный контрольный список приёмки
- Необходимость использовать шаблоны или скрипты из репозитория
- Потребность нескольких людей в единообразном поведении
- Желание, чтобы модель **сама вспоминала** этот процесс при подходящей задаче

Не нужно закреплять разовое исследование или небольшое исправление, сильно зависящее от сегодняшнего контекста.

## Минимальный рабочий вариант

1. **Ясно напишите SKILL.md:** когда запускать, какие входные и выходные данные использовать, что запрещено.
2. **Добавьте `references/`:** контрольный список и пример diff.
3. **При необходимости добавьте `scripts/`:** повторяемые проверочные команды, согласованные с [правилами команд](/ru/guide/customization/rules/command-rules/).
4. **Упомяните имя Skill** в README репозитория или AGENTS.md.
5. **Проведите 2–3 пробных запуска** и лишь затем установите отметку `verified`.

Для начала: [Создание первого Skill](/ru/skills/create-your-first-skill/)

## Рекомендуемый процесс

```text
Извлечь промпт и критерии приёмки из успешного примера
    → сократить до текста Skill — удалить разговорные фразы, сохранить ограничения
    → добавить описание условий запуска — «перед объединением», «перед публикацией»
    → провести командный Review PR
    → сохранить в каталоге examples/, принятом в репозитории, в командном Plugin или внутренней библиотеке Skills
```

Сравните с [автоматизацией процесса](/ru/skills/automations/scheduled-tasks/): Skill предназначен преимущественно для **интерактивного руководства**, а автоматизация — для работы **по расписанию или без постоянного наблюдения**.

## Распространённые ошибки

- Skill получился настолько длинным, что читать его труднее, чем `AGENTS.md`.
- Checklist приёмки отсутствует, поэтому качество выполнения нестабильно.
- Скрипту нужен локальный секрет, но инструкции SECURITY нет.
- Процесс дублирует правила Hook и противоречит им.

## Границы безопасности

- См. [Безопасность и версии Skill](/ru/skills/security/).
- Командный Skill должен входить в список разрешённых расширений; см. [Риски Plugin и MCP](/ru/guide/team-enterprise/security/plugin-and-mcp-risk/).

## Checklist приёмки

- [ ] Новый сотрудник может выполнить одну задачу, руководствуясь только Skill.
- [ ] Условия запуска ясны, частые ложные срабатывания отсутствуют.
- [ ] Для командного Skill есть версия или CHANGELOG.
- [ ] Есть перекрёстная ссылка на исходное описание рабочего процесса.
