**Review перед объединением** встраивает [качество и проверку](/ru/guide/quality/) в процесс Git: до merge PR Codex проверяет согласованность diff, тестов, безопасности и спецификации. Автоматический комментарий сам по себе не должен означать автоматическое объединение.

## Главное на этой странице

- Разделение обязанностей между локальным Review и Review в Cloud или CI
- Какие измерения должен охватывать промпт для Review
- Когда обязательно окончательное ручное одобрение

## Минимальный рабочий вариант

**Локально — самопроверка автора**

```text
Сравни diff текущей ветки с main, пока не изменяя код:
1. Есть ли изменения за рамками issue
2. Есть ли очевидные риски безопасности: секреты, инъекции, права доступа
3. Не хватает ли тестов или документации
Выведи контрольный список и пометь пункты P0/P1.
```

**CI — командный шлюз**

- Зафиксированная версия промпта + токен с правами только для чтения
- Результат сохраняется как PR comment или check run
- См. [Автоматизация Review кода](/ru/guide/developer-platform/ci-cd/code-review-automation/)

## Рекомендуемые измерения Review

| Измерение | На что обратить внимание |
|---|---|
| Корректность | Логика, граничные случаи, обработка ошибок |
| Тесты | Покрыто ли новое поведение |
| Безопасность | Признаки секретов, инъекций и уязвимостей зависимостей |
| Сопровождаемость | Именование, дублирование, публичный API |
| Спецификация | Соответствие issue и документу спецификации |

Подход можно сочетать с [Review diff](/ru/guide/quality/review-diffs/); для пунктов высокого риска используйте [схемы ручного подтверждения](/ru/cases/workflows/human-approval-patterns/).

## Распространённые ошибки

- Модель отвечает только LGTM, не приводя конкретных оснований.
- Полное описание PR без очистки вставляется в промпт CI, создавая риск инъекции.
- Review пройден, но тесты CI не запускались.
- Автоматический бот для merge включён без защиты ветки.

## Границы безопасности

- Для Review используйте права только для чтения; исправление должно запускаться человеком в **новом commit**.
- Не записывайте пользовательские PII или секреты в журнал Review.

## Checklist приёмки

- [ ] Вывод Review отслеживается до конкретного файла или строки.
- [ ] Проблемы P0 блокируют объединение либо уже исправлены.
- [ ] Результат согласован с командным контрольным списком Review.
- [ ] Окончательное решение по спорным пунктам принимает сопровождающий проекта.
