В **исследовании со ссылками на источники** каждый ключевой вывод должен вести к конкретному материалу — например, официальной документации, научной статье или файлу репозитория, — а не быть необоснованным утверждением. Подход подходит для выбора технологий, сравнения конкурентов, обзоров литературы и анализа политик.

## Главное на этой странице

- Когда использовать [веб-поиск](/ru/guide/tools/web-search/), а когда ограничиться чтением репозитория
- Как задать формат ссылок и обозначение неопределённости
- Как связать работу с этапом [проверки источников](/ru/guide/quality/validate-sources/)

## Минимальный рабочий вариант

```text
Исследуй пригодность Rust и Go для сценария этого репозитория.
1. Сначала перечисли измерения оценки: производительность, экосистема, знакомство команды с технологией.
2. Для каждого вывода приведи URL источника или путь @ к файлу репозитория.
3. Всё, что невозможно проверить, пометь как «требует подтверждения».
4. В конце дай рекомендацию и перечисли открытые вопросы.
Не изменяй код.
```

## Рекомендуемый процесс

```text
Определить вопрос и исключения
    → собрать источники — поиск / чтение документации / MCP
    → подготовить сравнительную таблицу с преимуществами и недостатками
    → отметить уверенность и противоречащие источники
    → принять решение вручную или перейти к этапу спецификации
```

Большое исследование разбивайте на несколько циклов, как описано в разделе [Управление длительными задачами](/ru/cases/workflows/long-running-task-management/).

## Распространённые ошибки

- URL не запрошены, поэтому результат невозможно проверить.
- Устаревшие блоги смешаны с официальной документацией без пояснения.
- Исследовательский вывод сразу превращён в инструкцию по реализации, а спецификация пропущена.
- Файл с конфиденциальными данными загружен во внешний инструмент без соответствующего разрешения.

## Границы безопасности

- Непубличные внутренние материалы нельзя передавать наружу через неконтролируемый MCP.
- Для изменчивых фактов — цен, версий и региональной доступности — нужно указывать [дату проверки](/ru/guide/start-here/handbook-version-policy/).

## Checklist приёмки

- [ ] У каждого ключевого вывода есть как минимум один кликабельный или отслеживаемый источник.
- [ ] Противоречащие сведения представлены рядом.
- [ ] Неопределённые пункты перечислены и не выданы за факты.
- [ ] Конфиденциальные данные не попали в промпт или журналы.
