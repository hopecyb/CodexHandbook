Подход **«сначала результат»** предполагает, что вы сначала ясно задаёте форму и расположение итоговых материалов, а затем просите Codex определить необходимые шаги в обратном порядке. Он подходит для задач с однозначными результатами: документов Markdown, описаний OpenAPI, скриптов миграции и структур презентаций. Его также можно сочетать с [разработкой на основе спецификации](/ru/cases/workflows/specification-driven-work/).

## Главное на этой странице

- Как описывать структуру результата, а не детали процесса
- Как проверять согласованность результатов из нескольких файлов
- Как согласовать процесс с возможностями из раздела [Файлы и результаты](/ru/guide/files-and-artifacts/)

## Минимальный рабочий вариант

```text
Требуемые результаты:
- docs/api/auth.md с 3 разделами: обзор, конечные точки, коды ошибок
- стиль должен соответствовать @docs/api/users.md

Сначала выведи структуру и ключевые тезисы каждого раздела, не пиши полный текст.
После моего подтверждения создай документ и самостоятельно проверь внутренние ссылки.
```

## Рекомендуемый процесс

```text
Определить список результатов — путь + формат + ссылка на пример
    → создать структуру или каркасные файлы
    → получить подтверждение человека
    → заполнить содержимое и перекрёстные ссылки
    → проверить — lint, ссылки, предварительный просмотр
```

Для визуальных результатов можно потребовать снимок экрана или описание предварительного просмотра; подробнее см. в разделе [Проверка результатов](/ru/guide/quality/verify-artifacts/).

## Распространённые ошибки

- Путь результата не соответствует правилам репозитория, поэтому файл оказывается не в том каталоге.
- Создан только один файл, а навигация и index не обновлены.
- Результат не сопоставлен с примером, и стиль выбивается из проекта.
- Для бинарного результата — pptx или docx — не описан способ ручной приёмки после открытия.

## Границы безопасности

- Если результат содержит сторонние материалы, защищённые авторским правом, человек должен проверить соблюдение требований.
- Не перезаписывайте пути production-конфигурации; сначала создайте результат в ветке или в каталоге `draft/`.

## Checklist приёмки

- [ ] Все заявленные файлы существуют и открываются.
- [ ] Формат соответствует указанному примеру.
- [ ] Ссылки, каталоги и Frontmatter корректны.
- [ ] Соблюдены [критерии завершения](/ru/prompts/define-done/).
