Несколько Agent хорошо справляются с параллельными, слабо связанными подзадачами, но не должны одновременно изменять один файл без координации.

## Когда разделять задачу

| Подходит | Не подходит |
|---|---|
| Параллельно исследовать стили frontend и контракт backend API | Два исполнителя изменяют одну функцию |
| Один запускает тесты, другой пишет документацию | Общая изменяемая память без блокировки |
| Исследовать несколько вариантов реализации | Сильные последовательные зависимости ещё не выяснены |

Возможности продукта описаны в разделах [Параллельные Agent](/ru/guide/desktop-app/parallel-agents/) и [Дочерние Agent](/ru/guide/agent-work/subagents/).

## Схемы совместной работы

### Схема A — параллельное исследование и ручной выбор решения

```text
Agent 1: преимущества, недостатки и объём работы для варианта A
Agent 2: преимущества, недостатки и объём работы для варианта B
Вы: выбираете один вариант, затем поручаете выполнение одному Agent
```

### Схема B — конвейер

```text
Agent исследования → выводит план → Agent выполнения в новой ветке диалога с краткой сводкой плана
```

Передавайте структурированную сводку с помощью подхода из раздела [Передача и возобновление работы](/ru/guide/agent-work/handoff-and-resume/), а не копируйте весь диалог.

### Схема C — изоляция рабочих деревьев

Разные Agent изменяют разные ветки в отдельных [git worktree](/ru/guide/desktop-app/worktrees/), после чего результаты объединяются вручную.

## Правила координации — рекомендуем добавить в AGENTS.md

- Задайте каждому Agent чёткие границы каталогов.
- Запретите параллельный `git push`.
- Перед объединением запустите единый набор проверок CI.
- Конфликты разрешает человек; Agent не должен угадывать.

## Приёмка

- [ ] Для каждого дочернего Agent задано отдельное определение завершения.
- [ ] После объединения проходит полный набор тестов.
- [ ] Каждый diff можно связать с описанием соответствующей подзадачи.

## Распространённые ошибки

- Три Agent параллельно изменяют `package.json`.
- Этап объединения выводов отсутствует, поэтому непонятно, чьему заключению доверять.
