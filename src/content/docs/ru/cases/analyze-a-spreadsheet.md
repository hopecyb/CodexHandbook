В этом упражнении вы подготовите еженедельный отчёт о продажах, а также сводку по регионам, рейтинг товаров и построчный журнал очистки данных. В качестве входных данных используется созданный для сайта синтетический набор, поэтому реальные сведения о клиентах не потребуются.

Сложность: начальная. Расчётное время — 30–45 минут. Это редакционная оценка, пока не подтверждённая замерами читателей. Требование: уметь передавать Codex локальные файлы. Для просмотра эталонного результата навыки программирования не нужны; для запуска проверки требуется Python 3.10+.

Текущая неделя — 2026-09-07—09-13, предыдущая — 2026-08-31—09-06. Изменение между двумя полными календарными неделями составляет 87.04%. Это лишь результат для синтетического набора, а не объяснение причин в реальном бизнесе.

## 1. Сначала проверьте файлы и правила расчёта

Передайте Codex следующую задачу. Способ предоставления файлов зависит от клиента; прежде чем продолжать, убедитесь, что Codex действительно прочитал их.

```text
Прочитай brief.md, starter/data-dictionary.md и starter/sales.csv.
Убедись, что файлы существуют; перечисли поля, диапазон дат, количество записей и номера строк, требующих особой обработки.
Не изменяй исходную таблицу и не открывай solution. Различай полные дубликаты, отсутствующие даты, отрицательные значения и настоящие нули.
Опиши правила отнесения данных к двум неделям согласно словарю. Если есть противоречия, перечисли их; если противоречий нет, продолжай.
```

В 46 строках исходной таблицы есть два возврата, один полный дубликат и одна запись без даты. У полного дубликата оставьте только первую строку; если строки с одинаковым ID различаются, проверку нужно остановить. Не придумывайте отсутствующую дату; нулевая сумма считается допустимой. После обработки в расчёт должны войти 44 строки.

## 2. Сформируйте отчёт и расчётные журналы

Продолжите работу с файлом `prompts/02-report.md` из комплекта и потребуйте сохранить результаты в `my-output/`:

| Файл | Что в нём должно быть |
|---|---|
| `summary.md` | Общая сумма, изменение к предыдущей неделе, регионы, три товара-лидера за текущую неделю, качество данных и основания расчёта |
| `region-summary.csv` | Чистая выручка каждого региона за обе недели, абсолютное и относительное изменение; общая сумма должна сходиться с суммой регионов |
| `top-products.csv` | Товары по убыванию чистой выручки за текущую неделю с учётом возвратов |
| `row-ledger.csv` | Номер каждой строки исходных данных, решение о включении, неделя и сумма |

Входные данные, solution и validation должны остаться без изменений. Имена полей и порядок таблиц должны соответствовать словарю данных, чтобы независимая проверка могла сопоставить каждый элемент. В предыдущую неделю выручка Юго-Западного Китая равна нулю, поэтому для относительного изменения укажите N/A; это нельзя считать ни 0%, ни бесконечным ростом.

## 3. Проведите независимую проверку — вопроса «всё верно?» недостаточно

Выполните следующую команду в распакованной папке упражнения:

```sh
python3 validation/check.py --output my-output
```

Если все четыре результата присутствуют и соответствуют согласованным правилам, скрипт выведет `result: PASS`. Изменение хеша входных данных, пропущенный возврат, ошибка группировки или несоответствие журнала приведут к ошибке. Если проверка не проходит, исправляйте только свои результаты — не подгоняйте проверочный скрипт под ошибочный ответ.

Если Python запустить невозможно, как минимум проверьте вручную:

1. Семь положительных значений Восточного Китая за текущую неделю дают 1,401.75 юаня; с возвратом -120.50 из строки 44 получается 1,281.25.
2. Сумма трёх регионов за текущую неделю: 1,281.25 + 2,101.75 + 1,261.75 = 4,644.75.
3. В строке 47 запись O046 на 199.99 юаня не имеет даты и не входит ни в одну из двух недель; строка 46 с O001 — дубликат.

Автоматическая проверка не оценивает все выводы на естественном языке. Еженедельный отчёт всё равно нужно прочитать и удалить из него любые объяснения роста или бизнес-выводы, не подтверждённые источниками.

## 4. Отработайте исправление ошибки: пропущенный возврат

**Специально смоделированная ошибка**: если при расчёте сводки отфильтровать все отрицательные значения, итог за текущую неделю составит 4,765.25 юаня — на 120.50 больше верного результата. При проверке эталона автор действительно изменил временный результат и подтвердил, что проверочный скрипт отклоняет неверную сумму; это не выдуманный диалог с моделью.

```text
Проверь допустимые записи, где net_sales меньше нуля, и объясни, должны ли они учитываться.
Сохрани исходный знак возвратов, заново рассчитай сводки по регионам и товарам за обе недели; перечисли разницу до и после исправления.
Не устраняй ошибку изменением исходного CSV или проверочного скрипта.
```

## 5. Восстановитесь при возникновении проблемы

| Симптом | Что проверить сначала | Следующий шаг |
|---|---|---|
| Файл не найден | Есть ли в текущей папке starter/sales.csv | Откройте распакованную папку и снова укажите файл; не позволяйте Agent воссоздавать отсутствующие данные |
| Китайский текст отображается некорректно или все данные попали в один столбец | Используется ли UTF-8 и запятая ли выбрана разделителем | Повторно импортируйте исходный CSV, не меняя суммы вручную |
| Расхождение равно 120.50 | Не пропущен ли возврат R043 | Сохраните отрицательное значение согласно словарю и пересчитайте обе недели |
| При сравнении недель возникает деление на ноль | Действительно ли показатель Юго-Западного Китая за предыдущую неделю равен нулю | Укажите N/A и поясните, что база равна нулю |
| Проверочный скрипт сообщает об отсутствующем файле | Созданы ли все четыре результата | Дополните набор согласно словарю и запустите проверку снова; отсутствие файла не означает ошибку в сумме |

## Условия завершения и дальнейшие шаги

- Хеш исходной таблицы не изменился, все четыре результата созданы.
- Общая сумма, показатель Восточного Китая и сумма записей без даты проверены независимо.
- В еженедельном отчёте сохранены аномалии, нулевая база и правила расчёта; причины не выдуманы.
