| Текущая ситуация | С чего начать |

| Известно лишь, что «результат неверен», но стабильного воспроизведения ещё нет | [Сначала диагностика, затем исправление](/ru/cases/workflows/diagnose-before-fixing/) |

## Минимальный замкнутый цикл

Независимо от языка и фреймворка сохраните следующую цепочку доказательств:

1. Стабильно воспроизведите исходную проблему одной явно указанной командой.
2. Сохраните упавшее утверждение, сообщение об ошибке и входные условия.
3. Сначала объясните первопричину, затем внесите минимальное исправление.
4. Добейтесь прохождения исходного падающего теста и новых тестов граничных случаев.
5. Запустите более широкий набор регрессионных проверок.
6. Вручную прочитайте diff и убедитесь, что в нём нет посторонних изменений.

Наличие шага 4 без шага 1 не доказывает, что тест действительно покрывает исходную проблему. Зелёный полный набор тестов без проверки diff также не подтверждает, что область изменений выбрана правильно.

## Упражнение, которое можно запустить сразу

В репозитории есть пример расчёта скидки в корзине на JavaScript, не требующий сторонних пакетов:

```bash
# Исходный код: ожидается падение 1 теста
node --test examples/complete-workflows/developer/verified-bug-fix/starter/cart.test.js

# Эталонное исправление: ожидается прохождение всех 3 тестов
node --test examples/complete-workflows/developer/verified-bug-fix/solution/cart.test.js
```

Полный комплект находится в каталоге [`examples/complete-workflows/developer/verified-bug-fix/`](https://github.com/hopecyb/CodexHandbook/tree/main/examples/complete-workflows/developer/verified-bug-fix).
