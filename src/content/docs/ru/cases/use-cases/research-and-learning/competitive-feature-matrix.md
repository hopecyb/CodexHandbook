## Общая информация

| Поле | Значение |
|---|---|
| Для кого | Специалисты по продукту, операционной работе и исследованиям |
| Клиент | App или CLI |
| Расчётное время | 45 минут |
| Дата проверки | 2026-07-25 |

## 1. Цель и контекст

**Цель:** подготовить таблицу сравнения 3–5 конкурирующих продуктов — функции, сведения о ценах и подходящие сценарии — со ссылкой на источник для каждого вывода.

**Критерии успеха:**

- Таблица Markdown и явные отметки «требует подтверждения».
- Цены и номера версий не выдуманы.
- Внешний документ не содержит внутренних конфиденциальных сведений.

## 2. Подготовка

- Заранее определите измерения для сравнения в промпте или в `@brief.md`.
- Включите [веб-поиск](/ru/guide/tools/web-search/), если продукт его поддерживает.

## 3. Рабочий процесс

Следуйте схеме [Исследование со ссылками на источники](/ru/cases/workflows/research-with-sources/):

```text
Сравни функции «командной работы» у продуктов A, B и C.
Для каждого измерения дай пояснение в 1–2 предложениях и URL источника.
Отдавай предпочтение официальной документации перед блогами.
Если цену проверить невозможно, отметь её как «требует подтверждения».
Выведи таблицу Markdown и не изменяй другие файлы репозитория.
```

**Проверка:** вручную откройте три URL; проверьте даты и [политику проверки](/ru/guide/start-here/handbook-version-policy/).

## 4. Сбои и восстановление

- Источники противоречат друг другу: приведите обе версии, не пытаясь искусственно согласовать их.
- Контекст слишком велик: сначала сравните A и B, затем добавьте C.

## 5. Закрепление опыта

- Сохраните шаблон таблицы сравнения в согласованном командой каталоге шаблонов или базе знаний.
- Процесс можно превратить в Skill `source-backed-research`.
