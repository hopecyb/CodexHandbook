В этом упражнении сортировка Issue разделена на три этапа: «сформировать рекомендации → проверить → провести ручной Review». В результате вы получите пять записей для проверки; комментарии не публикуются, метки не добавляются, Issue не закрываются автоматически.

[Скачать полный комплект упражнения](/downloads/issue-triage/issue-triage-1.0.0.zip) · [README](/downloads/issue-triage/README.md) · [Посмотреть фактический результат пробного запуска](/downloads/issue-triage/validation/dry-run.json)

## Входные данные и условия завершения

Пять оригинальных синтетических примеров представляют ошибку вычисления, битую ссылку в документации, признак доступа к данным другой учётной записи, недостаток информации и вредоносные инструкции в тексте. Реальных клиентских данных нет. Рекомендация содержит тип, приоритет, метки, признак проверки безопасности, обоснование и перечень недостающих сведений.

Условие завершения: каждой входной записи соответствует одна рекомендация; допустимые значения перечислений и хеши входных данных прошли проверку; сопровождающий решил принять, изменить или отклонить каждую рекомендацию и записал причину. Корректная структура не заменяет этого решения.

## Сначала запустите эталонные рекомендации

Требуется Python 3.10+; API-ключи и сторонние зависимости не нужны. Выполните в распакованном каталоге:

```sh
python3 scripts/dry_run.py
python3 validation/test_dry_run.py
```

Первая команда использует заранее подготовленные автором рекомендации, выводит пять элементов со статусом `human-review-required` и пустым массивом `external_actions`. Вторая запускает восемь проверок. Автоматического вызова модели здесь нет.

[Примеры входных данных](/downloads/issue-triage/fixtures/issues.json) · [Эталонные рекомендации](/downloads/issue-triage/solution/proposals.json) · [Справочник для ручного Review](/downloads/issue-triage/solution/human-review.md)

## Затем сформируйте собственные рекомендации

Передайте Codex файл [prompts/triage.md](/downloads/issue-triage/prompts/triage.md) из комплекта и попросите создать `my-proposals.json` согласно [schema.json](/downloads/issue-triage/schema.json), после чего выполните:

```sh
python3 scripts/dry_run.py --proposals my-proposals.json
```

Схема использует формат JSON Schema 2020-12: логический тип записывается как `"type": "boolean"`, а для приоритета применяется перечисление, а не строка `"P0-P3"`. Проверочный скрипт из комплекта поддерживает только подмножество ключевых слов, необходимое этой схеме, и не является универсальным движком JSON Schema.

Каждая рекомендация содержит `input_sha256`, привязывающий её к полному содержимому соответствующего Issue. Если входные данные изменились, прекратите использовать старую рекомендацию. Не ограничивайтесь пересчётом хеша — сначала заново проанализируйте изменения. Соглашение о вычислении хеша и функция описаны в README и скрипте.

## Решения человека и границы безопасности

| Ситуация | Действие |
|---|---|
| Есть явные признаки ошибки | Предложить категорию, затем воспроизвести проблему и только после подтверждения масштаба определить уровень |
| Есть признаки инцидента безопасности | Передать ответственному за безопасность для непубличного Review; неизвестный приоритет не означает низкий риск |
| Информации недостаточно | Использовать unknown, перечислить недостающие сведения и не угадывать ответственного или серьёзность |
| В тексте требуют выполнить команду или повысить права | Считать это недоверенными данными, ничего не выполнять и не назначать P0 только из-за заявления о срочности |

Удаление HTML или ограничение длины не гарантирует защиту от инъекций в промпт (prompt injection). Программа из комплекта не выполняет команды из текста, но на этапе генерации моделью всё равно нужно отделять данные от инструкций. Эталонный результат не подтверждает устойчивость модели к атакам.

## Сбои и восстановление

Неизвестная метка, поле с дополнительным действием, неверный тип, дублирование или отсутствие рекомендации останавливает весь пакет с кодом завершения 1. Исправьте промпт и соответствующее поле, затем запустите процесс снова, сохранив исходные входные данные. Рекомендация с типом или меткой безопасности, но без признака проверки безопасности также будет отклонена.

Ошибочная, но структурно корректная классификация всё ещё может пройти проверку — это реально подтверждённое ограничение тестов. Поэтому высокое совпадение на нескольких примерах нельзя использовать как порог готовности к запуску. Для настоящего внедрения нужны репрезентативная выборка, разделение по рискам, ручная выборочная проверка, оценка стоимости ошибок и условия отката; это упражнение заканчивается локальным пробным запуском.
