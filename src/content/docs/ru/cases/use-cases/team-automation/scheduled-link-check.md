Прежде чем запускать проверку по расписанию, убедитесь, что скрипт действительно находит проблемы и ясно сообщает, что именно он проверил. Упражнение начинается с двух намеренно созданных битых ссылок: изменяйте по одному целевому значению и наблюдайте за результатом проверки.

[Скачать полный комплект упражнения](/downloads/docs-link-audit/docs-link-audit-1.0.0.zip) · [README](/downloads/docs-link-audit/README.md) · [Фактический журнал восстановления](/downloads/docs-link-audit/validation/recovery.json)

## Сначала запустите ошибочный пример

Требуется Python 3.10+; сторонние зависимости, API-ключи и доступ к сети не нужны. Выполните в распакованном каталоге:

```sh
python3 scripts/check_links.py fixtures/site
```

Ожидаемый код завершения — 1. Отчёт содержит файл, номер строки, URL и причину: для `/missing/` в строке 4 файла index.html нет соответствующей страницы, а якорь `#old-anchor` из строки 5 отсутствует на целевой странице. Ещё одна внешняя ссылка попадает в список `unchecked` и не засчитывается молча как прошедшая проверку.

## Исправляйте по одной проблеме

Скопируйте `fixtures/site` в собственный каталог `work/`, сохранив исходные входные данные. Сначала замените `/missing/` на `/guide/` и выполните:

```sh
python3 scripts/check_links.py work
```

Команда по-прежнему завершается с кодом 1, но остаётся только проблема с якорем. Затем замените `#old-anchor` на `#install` и запустите проверку снова — теперь код завершения равен 0. Сравните результат с `solution/site` и [справочником для ручного Review](/downloads/docs-link-audit/solution/review.md), чтобы убедиться в отсутствии попутных изменений.

При самопроверке автор последовательно получил 2, 1 и 0 ошибок; хеш исходного примера не изменился. [JSON до исправления](/downloads/docs-link-audit/validation/stage-0.json) · [JSON после исправления](/downloads/docs-link-audit/validation/stage-2.json)

## Интерпретируйте результаты и границы проверки

| Результат | Значение | Следующий шаг |
|---|---|---|
| Код 0 | Локальные ссылки прошли проверку | Прочитать unchecked; этот результат не подтверждает доступность внешних ссылок |
| Код 1 | Найдена отсутствующая страница, якорь или путь за разрешёнными границами | Уточнить назначение каждой ссылки и исправить её |
| Код 2 | Проверку невозможно завершить | Проверить каталог, результат сборки, ошибки чтения и неподдерживаемый тег base |

Скрипт читает собранный HTML и поддерживает каталоги с `index.html`, относительные и корневые пути, а также HTML-якоря. Он не разбирает динамическую маршрутизацию JavaScript, URL в CSS, srcset и пользовательские правила перенаправления фреймворка. При встрече с `base href` скрипт останавливается, чтобы не интерпретировать относительные пути ошибочно. Внешние URL и другие протоколы явно помечаются как непроверенные.

Запустите семь проверок из комплекта:

```sh
python3 validation/test_links.py
```

Для настоящего проекта сначала выполните сборку по его инструкциям, а затем передайте скрипту выходной каталог. На этом сайте уже есть специализированный проверочный инструмент для внутренних ссылок; учебный комплект не заменяет все проверки конкретного фреймворка.

## Подключите периодический процесс

Поручите существующему планировщику последовательность «сборка проекта → проверка ссылок → сохранение кода завершения и JSON», зафиксировав рабочий каталог и среду зависимостей. Если сборка завершилась ошибкой, остановитесь и не читайте старый результат. Не допускайте одновременной записи в один и тот же журнал.

Сначала выполните процесс вручную, затем вручную запустите его в целевой среде планировщика и лишь после этого настройте расписание. Сравнивайте текущий результат с предыдущим: если ничего не изменилось, не создавайте лишних уведомлений; при новых ошибках, сбое проверки или восстановлении подготовьте сводку изменений. Фактическая отправка всё равно должна оставаться в пределах выданных полномочий.

Комплект не создавал задачу по расписанию, не отправлял уведомления, не изменял настоящий сайт и не запускал CI. Описанные шаги — руководство по интеграции, а не доказательство реального запуска планировщика. Далее можно обратиться к [руководству по задачам по расписанию](/ru/skills/automations/scheduled-tasks/).

## Работа с внешними ссылками

Для внешних ссылок отдельно задайте разрешённую область и частоту проверки. Коды 404, ограничения аутентификации, тайм-ауты и временные ошибки службы имеют разный смысл; один неудачный запрос не является достаточным основанием для удаления ссылки. В этом комплекте настоящие внешние ссылки не проверялись, а смоделированный ответ не выдавался за реальный сетевой сбой.

При объединении с [упражнением по сортировке Issue](/ru/cases/use-cases/team-automation/issue-triage-suggestions/) сначала сформируйте локальный отчёт и результаты ручного Review, а затем решите, нужно ли создавать задачу.
