Этот пример демонстрирует задачу **контентной инженерии**: Markdown в нескольких файлах, конфигурация боковой панели и проверка сборки. Технологический стек похож на стек этого руководства, но подход применим к любому статическому сайту.

## Общая информация

| Поле | Значение |
|---|---|
| Область | Создание контента / инженерия документации |
| Точка входа | CLI или IDE |
| Риск | Средний — множество ссылок и элементов навигации |
| Продолжительность | 1–3 часа в зависимости от масштаба |

Описание структуры: [Шаблон примера](/ru/cases/use-cases/case-study-template/)

## Контекст

После добавления нового раздела на сайт документации требуется:

1. Обновить slug боковой панели в `astro.config`.
2. Исправить относительные ссылки в тексте.
3. Добиться выполнения `npm run build` без ошибок.

Человек легко может пропустить slug, поэтому задача подходит Agent: **выполнить пункты контрольного списка и подтвердить результат сборкой**.

## Подготовка

- [ ] Чистая ветка git
- [ ] `npm run build` успешно выполняется локально
- [ ] Перечислены пути новых страниц и их целевое положение в sidebar

## Пример промпта для задачи

```text
Цель: добавь environment-variables.md в 12-reference и подключи страницу к боковой панели и ссылкам index.
Ограничения: изменяй только src/content/docs и astro.config.mjs; не обновляй зависимости.
Приёмка: npm run build завершается успешно; битых ссылок нет.
Порядок: сначала измени config, затем создай md и в конце обнови 12-reference/index.md.
```

## Важное при выполнении

- **Сначала config, затем контент:** так сборка не завершится ошибкой missing slug.
- Фиксируйте каждые 3–5 файлов отдельным commit, чтобы упростить Review.
- Следуйте схеме [Исследование — планирование — выполнение — проверка](/ru/cases/workflows/explore-plan-execute-verify/).

## Проверка

- [ ] Каждому slug в боковой панели соответствует файл.
- [ ] Внутренние ссылки оформлены по правилам относительных путей.
- [ ] В журнале сборки нет предупреждений Starlight, если команда требует нулевого количества предупреждений.

## Восстановление после сбоя

| Проблема | Решение |
|---|---|
| Ошибка в slug боковой панели | Свериться с документацией Astro, исправить slug или добавить md |
| Битая ссылка | Найти целевой путь с помощью `grep`; исправить ссылку или добавить страницу |
| Сборке не хватает памяти | Вносить изменения пакетами; локально увеличить объём памяти, доступной Node.js |

## Ретроспектива

- После третьего повторения процесса «новый раздел + боковая панель» его стоит оформить как Skill.
- Отмечайте выполненные пункты в ROADMAP, чтобы документация не расходилась с планом.
