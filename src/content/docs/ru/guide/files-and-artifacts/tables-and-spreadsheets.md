Табличная задача — типичный пример незаметной ошибки: неверный разделитель, кодировка, заголовок, формула или формат даты могут полностью нарушить последующую обработку.

## Содержание страницы

- Как безопасно поручить Codex чтение и запись CSV / Excel
- Как структурировать промпт для анализа данных
- Как проверить числа и количество строк

## Выбор формата

| Формат | Преимущества | На что обратить внимание |
|---|---|---|
| CSV | Текстовый diff, широкая совместимость | Кодировка (UTF-8 BOM), разделитель, экранирование кавычек |
| TSV | Меньше конфликтов с запятыми | То же, что для CSV |
| XLSX | Несколько листов, формулы | Двоичный формат, сложный diff; читайте и записывайте библиотекой |
| Google Sheets | Совместная работа | Обычно через MCP или экспорт CSV |

Для небольшого набора данных, который нужно хранить в Git, **предпочтительны CSV/TSV**. Для сложного отчёта используйте **исходные данные CSV и скрипт генерации XLSX**.

Учитывайте три правила:

- Если важны diff, отслеживаемость и воспроизводимость, выбирайте CSV / TSV
- Если результат предназначен людям, привыкшим к Excel, затем экспортируйте XLSX
- Не смешивайте «формат окончательного просмотра» и «исходный формат, наиболее удобный для автоматической обработки»

## Чтение и анализ

Рекомендуемая структура промпта:

```text
Файл: data/sales_2025.csv
Кодировка: UTF-8
Задача: сгруппировать revenue по region и записать результат в summary.csv
Ограничения: не изменять исходный файл; пустые значения считать равными 0; сохранять два знака после запятой
Приёмка: вывести первые 5 строк + общее количество строк
```

Подробнее о контексте: [Контекст файлов и каталогов](/ru/guide/context/file-and-folder-context/)

## Почему в таблицах особенно легко ошибиться незаметно

Проблемы обычно возникают в следующих местах:

- Считать ли значение даты текстом или датой
- Приравнять ли пустое значение к 0, пропустить его или вернуть ошибку
- Какой столбец является уникальным идентификатором
- Нужно ли округлять дроби и суммы
- Разрешено ли изменять исходный файл

Если правила не заданы, результат Codex может выглядеть завершённым, оставаясь ненадёжным.

## Запись и очистка

- Явно задайте **имена, порядок и типы столбцов**; для дат используйте ISO 8601
- Обрабатывайте большие таблицы пакетами, чтобы не исчерпать память одновременной загрузкой
- Укажите в задаче правила удаления дублей и ключи объединения; не заставляйте Agent угадывать первичный ключ

## Распространённые заблуждения

### 1. Если файл открывается, значит он обработан правильно

Нет.

В табличных задачах «файл открывается» и «данные не повреждены» — разные утверждения.

### 2. Если в Excel всё выглядит правильно, ошибок нет

Некоторые ошибки обнаруживаются только при последующем чтении другой системой. Например:

- Неверная кодировка
- Изменённый порядок столбцов
- Изменившийся тип числа
- Формула, заменённая фиксированным результатом

### 3. Можно поручить Agent самостоятельно определить правила для пустых значений, дат и первичного ключа

Обычно это нежелательно.

Чем яснее заданы эти правила, тем надёжнее результат.

## Что уточнить в табличной задаче

Сформулируйте требования в пяти пунктах:

1. Какой файл является входным
2. Как должен называться выходной файл
3. Какие столбцы нужно сохранить, агрегировать или очистить
4. Как обрабатывать пустые значения, даты и дубли
5. Как проверить результат

Это значительно надёжнее просьбы «Приведи в порядок этот Excel».

Для Python используйте `pandas`; для Node — `csv-parse`, `xlsx` и подобные библиотеки. Стандартную библиотеку проекта зафиксируйте в `AGENTS.md`.

## Проверка

- Сопоставьте количество строк и итоговые суммы с исходными данными
- Откройте Excel и убедитесь, что даты не отображаются числами
- Выполните [проверку артефакта](/ru/guide/quality/verify-artifacts/) на выборочных данных

В табличной задаче особенно важно ясно указать столбцы, типы, правила и способ приёмки.

## Распространённые ошибки

- Нечитаемый китайский текст при открытии CSV в Excel из-за отсутствия BOM или неверной кодировки
- Неописанная ошибка суммы с плавающей точкой и отсутствие округления
- Изменение формулы в Excel без сохранения воспроизводимого скрипта

## Контрольный список приёмки

- [ ] Имена и типы столбцов соответствуют договорённостям следующего потребителя
- [ ] Итоги и выборка совпадают с ручной проверкой или SQL
- [ ] Исходный файл не был случайно перезаписан либо изменение видно в diff
