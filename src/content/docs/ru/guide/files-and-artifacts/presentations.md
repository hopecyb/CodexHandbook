В презентациях — PPT, Keynote, Google Slides, Marp, Reveal и других — особенно важны **структура повествования** и **визуальная согласованность**. Agent хорошо составляет план и первый черновик, но шаблон и фирменные стандарты по-прежнему должен контролировать человек.

Главная польза Codex при подготовке презентации — возможность сначала выстроить структуру, порядок слайдов и логику рассказа. Окончательную версию всё равно следует довести самостоятельно.

## Содержание страницы

- Рекомендуемый процесс подготовки слайдов в Codex
- Компромиссы между `.pptx` и слайдами Markdown
- Как избежать разрозненного стиля от слайда к слайду

## Сначала определите формат результата

| Формат | Подходит для |
|---|---|
| Marp / Slidev / reveal.md | Разработчиков и удобного управления версиями |
| `.pptx` | Деловых докладов и обмена с клиентами |
| Google Slides | Совместной работы в реальном времени — обычно через экспорт или MCP |
| Экспорт PDF | Распространения только для чтения |

Зафиксируйте формат в начале задачи, чтобы Agent не смешивал несколько цепочек инструментов.

Выбирайте по получателю окончательного материала:

- Если клиент, руководитель или коллега должен сразу открыть и изменить файл, обычно выбирают `.pptx`
- Если презентация должна храниться в системе версий вместе с кодом, обычно выбирают слайды Markdown
- Если требуется только версия для чтения, в конце обычно экспортируют PDF

## Рекомендуемый процесс

```text
1. План: аудитория, продолжительность, 3–5 основных тезисов
2. Заголовок каждого слайда + 3 пункта, основные мысли в заметках докладчика
3. Выбор инструмента и создание первого черновика
4. Ручная корректировка шаблона, диаграмм и источников данных
5. Экспорт PDF и репетиция с замером времени
```

Это соответствует процессу [Исследование — планирование — выполнение — проверка](/ru/cases/workflows/explore-plan-execute-verify/): сначала примите план и только затем заполняйте подробности.

## Почему в презентации сначала нужно согласовать структуру

Если не определить структуру заранее, Codex легко создаст множество слайдов, в которых:

- Нарушен порядок
- Не контролируется объём
- Каждый слайд выглядит отдельным плакатом, а не частью единого доклада

Надёжнее двигаться по трём уровням:

1. Сначала определить, какую мысль должна донести презентация в целом
2. Затем назначить каждому слайду один ключевой тезис
3. И лишь после этого поручить Agent текст, пояснения к графикам и заметки докладчика

## Распространённые заблуждения

### 1. Чем эффектнее PPT, тем убедительнее сообщение?

Для понимания часто важнее другое:

- Выражает ли заголовок главную мысль одним предложением
- Развивается ли аргумент от слайда к слайду
- Указаны ли источники данных

### 2. Если Agent создал полный черновик, ручная проверка не нужна?

Нужна. Обязательно проверьте вручную:

- Фирменный стиль и шаблон компании
- Ключевые выводы
- Числа и диаграммы
- Версию для внешней отправки

### 3. Чем больше содержимого на слайде, тем он информативнее?

Обычно его лишь труднее представить.  
Если на одном слайде слишком много пунктов, изображений и выводов, аудитории сложно сразу выделить главное.

## Практический порядок создания

Если вы хотите поручить Codex презентацию прямо сейчас, сформулируйте требования в такой последовательности:

1. Укажите аудиторию
2. Сообщите продолжительность выступления
3. Перечислите три мысли, которые слушатели должны запомнить
4. Сначала запросите план
5. После подтверждения плана попросите раскрыть каждый слайд
6. В конце добавьте заметки докладчика, визуальные требования и формат экспорта

Так проще удержать процесс в границах: сначала структура, затем текст, в конце стиль.

## Что указать в промпте

- **Аудитория**: технические специалисты или руководство — от этого зависит глубина терминологии
- **Ограничение числа слайдов**: не допускайте 80 страниц лишнего текста
- **Фирменный стиль**: основной цвет, путь к logo, запрет clipart при наличии корпоративных правил
- **Графики данных**: укажите исходный файл и требуйте обновляемый график, а не выдуманный снимок экрана

Можно сформулировать запрос так:

> «Сначала составь план не более чем из 10 слайдов для нетехнического руководства. На каждом слайде оставь только один ключевой вывод, а в конце добавь заметки докладчика».

Такое требование обычно даёт гораздо более пригодный для дальнейшей работы результат, чем просьба «Сделай эффектный PPT».

Требования к изображениям см. в разделе [Изображения и снимки экрана](/ru/guide/files-and-artifacts/images-and-screenshots/), а создание новых изображений — в разделе [Генерация изображений](/ru/guide/tools/image-generation/).

## Приёмка

- Размер шрифта читается при проекционном разрешении
- Анимация умеренна: избыточную анимацию трудно сопровождать
- Числа согласуются с [проверенными источниками](/ru/guide/quality/validate-sources/)
- Заметок докладчика достаточно, если они требуются

## Что лучше поручить Codex, а что оставить человеку

| Лучше поручить Codex | Лучше проверить вручную |
|---|---|
| Разбивку плана на слайды | Формулировку окончательного вывода |
| Черновые заголовки | Соответствие фирменному стилю |
| Черновик заметок докладчика | Конфиденциальные данные |
| Пояснения к графикам | Версию для внешней публикации |

Такое разделение обычно экономит время и помогает сохранить качество окончательного результата.

## Распространённые ошибки

- Сразу попросить «сделать квартальный отчёт PPT» без плана
- Многократно вручную менять двоичный `.pptx`, не сохраняя исходный Markdown
- Использовать на графиках данные, не совпадающие с CSV репозитория
- Одновременно поручить Agent выбор структуры, дизайна, выводов и методики расчёта данных

## Контрольный список приёмки

- [ ] Полный текст создан только после ручного подтверждения плана
- [ ] В целевой среде показа файл открывается без проблем со шрифтами
- [ ] Ключевые данные прослеживаются до исходного файла
