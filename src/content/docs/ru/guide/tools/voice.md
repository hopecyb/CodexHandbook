Некоторые клиенты Codex поддерживают **голосовое взаимодействие**: вы можете продиктовать задачу или прослушать краткий ответ. Это удобно, когда руки заняты или нужно быстро сформулировать идею, но **не** подходит для произнесения ключей и не заменяет письменные материалы приёмки.

Голос лучше использовать для описания общего направления, дополнения контекста и быстрого отслеживания хода работы. Точные, доступные для поиска и последующей проверки детали следует фиксировать текстом.

## Содержание страницы

- Для каких задач подходит голос
- Как сочетать его с текстовым промптом
- Что учитывать для конфиденциальности и точности

## Сценарии использования

| Подходит | Не подходит |
|---|---|
| Диктовка общей цели, мозговой штурм | Инструкции по коду с точными именами переменных |
| Короткое уточнение с мобильного устройства | Произнесение ключа API или пароля |
| Потребности accessibility | Спецификация, которую нужно искать и сравнивать через diff |

После диктовки попросите Codex **повторить, как он понял задачу**, или составить текстовый план, а затем подтвердите его. См. [Запрос плана](/ru/prompts/ask-for-a-plan/).

## Для чего подходит голос

Его основные преимущества:

- Скорость
- Возможность не использовать руки
- Удобство для первоначального изложения мыслей

Распространённые проблемы:

- Пропущенные слова
- Ошибки распознавания
- Непригодность для точных путей, имён переменных и параметров командной строки

Обычно сначала диктуют общее направление, а затем подтверждают его текстом.

## Рекомендации

1. Говорите короткими предложениями в тихой обстановке и отдельно формулируйте «цель / ограничения / критерии завершения»
2. Для путей к файлам и имён веток **переходите к набору текста** либо просите Agent повторить написание по буквам
3. Для конфиденциального проекта отключите облачную обработку голоса, если продукт поддерживает локальный режим или отключение
4. Сохраняйте важные решения текстом в Issue или PR

## Распространённые заблуждения

### 1. Может ли голос полностью заменить набор текста?

Нет.  
Следующие сведения лучше вводить с клавиатуры:

- Пути к файлам
- Имена веток
- Команды
- Параметры
- Критерии приёмки

### 2. Чем длиннее и подробнее диктовка, тем меньше вероятность ошибки

Длинная речь без структуры, наоборот, легче теряет главное.

### 3. Может ли голосовой ответ заменить проверку результата?

Нет.  
Голосовая сводка помогает быстро понять общий смысл, но для проверки изменений, файлов, diff и результатов тестов нужно вернуться к тексту и самим артефактам.

## Удобный порядок формулировки

Если вы ставите задачу голосом, говорите в такой последовательности:

1. Что я хочу сделать
2. Чего делать не следует
3. Как проверить результат

Затем попросите Codex оформить задачу текстом для подтверждения.

## Конфиденциальность

- Голос может расшифровываться в облаке; не произносите персональные данные клиентов и учётные сведения
- В общественном месте учитывайте, что разговор могут услышать посторонние
- Политика команды может запрещать обработку кодовых имён конфиденциальных проектов функциями записи звука

## Связь с мультимодальностью

- **Изображение на входе**: макет или снимок экрана → [промпты с изображениями](/ru/prompts/prompting-with-images/)
- **Голос на входе**: текущая страница
- **Результат**: прежде всего код, файлы и текстовый diff; голосовая сводка не заменяет проверку

## Распространённые ошибки

- Диктовать длинный неструктурированный текст, из-за чего Agent пропускает ограничения
- Голосом принять большой пакет изменений кода, не посмотрев diff
- Описывать голосом необезличенные подробности производственного инцидента

Голос удобен для начала работы и коротких уточнений, но не заменяет точные инструкции, безопасную обработку конфиденциальных сведений и окончательную приёмку.
