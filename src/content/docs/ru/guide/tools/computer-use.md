**Computer Use** позволяет Agent, подобно человеку, видеть экран, перемещать указатель и вводить текст, не ограничиваясь браузером или терминалом. Это самый мощный вариант, поэтому **риски и требования к подтверждениям здесь также максимальны**.

Computer Use действует на уровне экрана, мыши и клавиатуры. Это другой класс возможностей по сравнению с браузерным инструментом и терминалом, а значит, включать его следует особенно осторожно.

## Содержание страницы

- Разделение задач между Computer Use, браузером и терминалом
- Задачи, для которых оправдано включение этой возможности
- Меры защиты для отдельных пользователей и команд

## Границы возможностей

| Уровень | Типичные возможности |
|---|---|
| Терминал | Shell, скрипты, программы CLI |
| Браузер | DOM веб-страницы, ограниченное взаимодействие |
| Computer Use | Настольные приложения, системные диалоги, процессы с несколькими окнами |

## Чем Computer Use отличается от других инструментов

Его особенности:

- Работа по всему рабочему столу
- Переключение между несколькими окнами
- Нажатие реальных кнопок и взаимодействие с системными диалогами

Поэтому область доступных интерфейсов и информации обычно гораздо шире.

Подходит:

- Для демонстрации повторяющихся действий в программе без API — под вашим наблюдением
- Для копирования данных между приложениями — при соблюдении требований
- Для проверки поведения самого настольного App

Не подходит:

- Для повседневной разработки кода — IDE и терминал эффективнее
- Для производственных операций без наблюдения
- Для обхода защитного программного обеспечения или DRM

## Распространённые заблуждения

### 1. Если инструмент мощнее, нужно ли выбирать его первым?

Его преимущества становятся заметны только при выполнении обоих условий:

- Задача действительно связана с GUI рабочего стола
- Нет более лёгкого и безопасного инструмента

### 2. Если я наблюдаю за экраном, риск исчезает?

Наблюдение повышает безопасность, но всё равно возможны:

- Случайное подтверждение диалога
- Открытие лишнего окна
- Попадание конфиденциальных сведений с экрана в рабочий процесс

### 3. Может ли Computer Use заменить любую автоматизацию GUI?

Он лучше подходит для разовой помощи, проверки процесса и действий в GUI без API, чем для стабильной, долговременной и автономной производственной автоматизации.

## Модель рисков

Computer Use почти равносилен тому, чтобы **передать Agent клавиатуру и мышь**:

- Он может открыть почту, чат или файловый менеджер
- Может случайно подтвердить диалог
- В уведомлениях на экране могут находиться конфиденциальные сведения

Обязательно прочитайте: [Разрешения и подтверждения](/ru/guide/foundations/permissions-and-approvals/) и [Песочница и сеть](/ru/guide/foundations/sandbox-and-network/)

## Как понять, нужен ли Computer Use

Обычно не стоит начинать с Computer Use, если требуется только:

- Изменить код
- Запустить тесты
- Посмотреть веб-страницу
- Найти информацию

Большинство таких задач решается более лёгкими инструментами.

Рассматривайте Computer Use, только если:

- Необходимо управлять настольным приложением
- Нужно работать в нескольких окнах GUI
- Требуется взаимодействовать с интерфейсом, недоступным браузеру и терминалу

## Рекомендуемый способ использования

1. **Отдельная среда**: виртуальная машина или вторичная учётная запись без личных окон на экране
2. **Минимальная задача**: «Проверь формулу в Calculator», а не «Разбери всю мою почту»
3. **Человек в контуре**: держите процесс на виду и будьте готовы немедленно прервать его
4. **Запись экрана и журналы**: для командного разбора — с учётом того, что запись тоже содержит конфиденциальные сведения
5. **Проверка после завершения**: файловая система, буфер обмена и открытые приложения

В корпоративной среде функция может быть отключена по умолчанию; ориентируйтесь на управляемые политики.

## Выбор между Computer Use и браузером

```text
Нужно только посмотреть веб-страницу?       → Инструмент браузера
Нужно управлять приложением вне IDE?        → Computer Use (с повышенной осторожностью)
Нужно только изменить код и запустить тест? → Терминал + файловые инструменты
```

См. [Выбор инструментов](/ru/guide/tools/tool-selection/)

## Готовая формулировка

Можно написать так:

```text
Разрешено управлять только Calculator и локальным тестовым приложением. Не открывай почту, чаты, файловый менеджер и производственные панели.
Если появится системный диалог подтверждения, остановись и сначала объясни ситуацию.
```

## Распространённые ошибки

- Использовать Computer Use для ненадёжного проекта на основном рабочем столе
- Продолжать задачу, когда на экране видны коды 2FA, банковские данные или сведения клиентов
- Считать автоматизацию GUI полноценной стратегией тестирования

## Контрольный список приёмки

- [ ] Возможность включена только в изолированной среде
- [ ] В промпте перечислены разрешённые приложения и запреты
- [ ] После задачи проверено отсутствие неожиданных файлов и сетевых подключений
- [ ] Политика организации разрешает эту возможность
