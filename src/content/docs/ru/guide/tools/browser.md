**Инструмент браузера** позволяет Agent посещать реальные веб-страницы в контролируемой среде: читать DOM, делать снимки экрана, а иногда и выполнять простые действия. Он подходит для приёмки клиентской части, проверки ссылок в документации и сравнения с макетом, но не заменяет аудит безопасности и не должен без ограничений использоваться для операций в производственной панели администратора.

Поиск и браузер — два разных типа инструментов. Поиск находит сведения о веб-страницах, а браузер действительно открывает их.

## Какие задачи он решает

Браузер часто используют, чтобы ответить на вопросы:

- Как страница выглядит сейчас
- Что произойдёт после нажатия кнопки
- Не ломается ли макет при фактической ширине экрана

Одного чтения кода или текстового описания для таких вопросов обычно недостаточно — страницу нужно открыть.

## Содержание страницы

- Что браузерный инструмент может и чего не может
- Чем он отличается от веб-поиска и Computer Use
- Как безопасно предоставить доступ и задать ограничения

## Обзор возможностей

| Подходит | Не подходит |
|---|---|
| Открыть страницу локального dev server и проверить макет | Массово собирать данные с сайтов, чьи ToS это запрещают |
| Проверить общедоступную ссылку на ошибку 404 | Автоматически входить в системы без разрешения |
| Сопоставить статическую страницу с реализацией | Заменять полноценную систему E2E-тестов |
| Прочитать видимый текст страницы для диагностики | Работать с сайтами, требующими сложной проверки пользователя |

Подробнее о выборе: [Выбор инструментов](/ru/guide/tools/tool-selection/)

## Сравнение с другими инструментами

| Инструмент | Входные данные | Результат |
|---|---|---|
| Веб-поиск | Поисковый запрос | Сводка и ссылки |
| Браузер | URL / локальный адрес | Структура страницы, снимки экрана, результат взаимодействия |
| Computer Use | Весь GUI экрана | Управление любыми приложениями — более тяжёлое и чувствительное |

## Распространённые заблуждения

### 1. Браузерный инструмент не заменяет автоматизированное тестирование

С его помощью можно осмотреть страницу, сделать снимок экрана и проверить некоторые действия, но он не заменяет полноценную систему тестов.

### 2. Если страница открывается, это ещё не значит, что с ней всё в порядке

Открытие доказывает лишь существование страницы. Макет, текст, взаимодействия и ссылки нужно проверять отдельно.

### 3. Когда его использовать?

Наиболее распространённые сценарии:

- Проверить локальную страницу на проблемы макета
- Убедиться, что ссылка не возвращает 404
- Сопоставить общее направление страницы с макетом
- Проверить, что правильный на вид код действительно даёт нужный результат в браузере

## Критерий выбора

Браузерный инструмент обычно лучше чисто текстового анализа, если вопрос звучит так:

- «Как выглядит фактический результат рендеринга?»
- «Что именно видно на странице?»
- «Как страница отреагирует после этого действия?»

## Рекомендуемый процесс

1. **Локальная клиентская часть**: сначала выполните `npm run dev`, затем передайте адрес `http://localhost:PORT/path`
2. **Конкретная задача**: «Проверь, не выходит ли форма входа за границы экрана шириной 375px» вместо «Посмотри сайт»
3. **Ясные границы**: запретите доступ во внешнюю сеть и отправку форм в производственную среду
4. **Приёмка**: сопоставьте результат с разделом [Проверка артефактов](/ru/guide/quality/verify-artifacts/) и снимками экрана

## Готовая формулировка

Можно написать так:

```text
Посети только http://localhost:4321/guide/foundations/local-vs-cloud/ и проверь макет первого экрана и внешний вид главной иллюстрации.
Не обращайся во внешнюю сеть и не отправляй формы.
Если обнаружишь проблему, приложи подтверждающий снимок экрана и предложи исправление.
```

## Границы безопасности

- По умолчанию считайте, что браузер может обратиться **ко всему, что доступно вашему компьютеру или среде**, включая внутреннюю панель admin
- В задаче укажите `только localhost` или белый список разрешённых доменов
- Не запускайте задачи из ненадёжных репозиториев в профиле браузера, где выполнен вход в личные учётные записи
- Политика браузера в Cloud определяется [средой Cloud](/ru/guide/web-and-cloud/cloud-environments/) и сетевыми правилами

Подробнее о подтверждениях: [Разрешения и подтверждения](/ru/guide/foundations/permissions-and-approvals/)

## Распространённые ошибки

- Указать производственный URL и не ограничить операции режимом только для чтения
- Принять снимок экрана за доказательство прохождения тестов и не запустить автоматизированные проверки
- Смешивать браузер с веб-поиском: поиск не заменяет проверку фактического рендеринга

## Контрольный список приёмки

- [ ] Область доступа жёстко задана в промпте
- [ ] Ключевые визуальные проблемы подтверждены снимками экрана или текстовым описанием
- [ ] Выводы согласуются с модульными и E2E-тестами либо известные различия зафиксированы
