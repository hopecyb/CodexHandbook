Codex SDK позволяет программе управлять локальным Codex Agent. «Локальный» означает находящийся на машине, где запущены SDK и Agent: это может быть ваш компьютер или управляемый вами исполнитель CI. Не считайте SDK размещённой HTTP-службой, которая создаёт облачные задачи, опрашивает их состояние и загружает артефакты. См. [официальную документацию SDK](https://learn.chatgpt.com/docs/codex-sdk).

## Выберите точку входа под задачу интеграции

| Цель | С чего начать | Что по-прежнему остаётся под вашим управлением |
|---|---|---|
| Выполнить одну задачу в скрипте | [`codex exec`](/ru/guide/developer-platform/non-interactive/codex-exec/) | Рабочий каталог, входные данные, статус завершения и хранение артефактов |
| Запускать и продолжать задачи из программы | Codex SDK | Жизненный цикл программы, окружение, обработка сбоев и проверка результата |
| Создать клиент с сеансами, подтверждениями и потоковыми событиями | App Server | Взаимодействие с клиентом, соединения, работа с идентификацией и развёртывание |
| Предоставить многопользовательскую платформу удалённых задач | Собственная архитектура службы | Очереди, изоляция арендаторов, учётные данные, хранилище, отмена и обратные вызовы |

Последняя строка описывает ваше инженерное решение, а не возможность размещённой платформы, входящую в SDK. В официальных рекомендациях SDK предназначен для автоматизации и CI, а App Server — для более глубокой клиентской интеграции. App Server обменивается запросами и событиями по двунаправленному JSON-RPC. См. [документацию App Server](https://learn.chatgpt.com/docs/app-server).

## Минимальный вызов TypeScript SDK

Официальный пакет TypeScript называется `@openai/codex-sdk` и требует Node.js 18 или новее. В следующем примере синтаксис модулей JavaScript демонстрирует базовый интерфейс того же пакета. Это не готовая производственная служба.

Установите зависимость в отдельном учебном каталоге, сохранив разрешённую версию и lock-файл:

```sh
npm init -y
npm install --save-exact @openai/codex-sdk
npm ls @openai/codex-sdk
```

Подготовьте `README.md` без конфиденциальных данных, затем сохраните следующий код в `example.mjs`:

```js
import { Codex } from '@openai/codex-sdk';

const agent = new Codex();
const session = agent.startThread();
const answer = await session.run(
  'Прочитай только README.md в текущем каталоге и опиши его назначение по-русски тремя пунктами. Не изменяй файлы и не выполняй внешние действия.'
);
console.log(answer.finalResponse);
```

После этого выполните `node example.mjs`. Пройдите аутентификацию для выбранного окружения и перед запуском проверьте фактические настройки песочницы и подтверждений. Фраза «Read only» в промпте — ограничение задачи, а не замена ограничениям среды выполнения. Вызов модели может расходовать квоту вашей учётной записи; эта страница не устанавливала пакет и не выполняла вызов за вас.

Названия методов и поле ответа сверены с [официальным примером](https://learn.chatgpt.com/docs/codex-sdk). В рамках этого руководства проверен только синтаксис JavaScript: конкретная версия SDK не фиксировалась и не тестировалась, а успешный вывод не выдумывался. Воспроизводя пример, запишите версию пакета, CLI или среды выполнения, операционную систему, способ аутентификации (без учётных данных) и результат.

## Продолжение и возобновление задач

Чтобы продолжить задачу, снова вызовите `run()` для того же объекта потока. Для возобновления можно передать существующий идентификатор потока в `resumeThread()`. Возможность возобновить поток зависит от места хранения его состояния. Не воспринимайте идентификатор как облачный URL, доступный для запроса с любой машины. В официальной документации также описан интерфейс Python; проверяйте его собственные имена методов и зависимости, не смешивая код на двух языках. См. [вызовы потоков и языковые интерфейсы](https://learn.chatgpt.com/docs/codex-sdk).

После возобновления проверьте, соответствуют ли текущие файлы истории. См. [передачу работы и возобновление](/ru/guide/agent-work/handoff-and-resume/).

## Что проверить после успешного вызова

1. **Место выполнения:** запишите рабочий каталог и фактически прочитанные или изменённые файлы, а не только промпт.
2. **Результат задачи:** изучите ответ, diff файлов и тесты. Наличие `finalResponse` не означает, что критерии приёмки выполнены.
3. **Категория сбоя:** различайте сбои локальных зависимостей или процесса, ошибки аутентификации, ошибки службы модели и неудачную проверку задачи. Не сводите любое исключение к 400 или 429.
4. **Последствия повтора:** перед повторной попыткой проверьте, не появились ли уже файлы или внешние эффекты; не отправляйте тот же запрос вслепую.
5. **Разрешения:** средой выполнения и доступными инструментами управляете вы. Само название SDK не предоставляет доступ к Cloud, администрированию организации или изоляции арендаторов.

Это интеграционные проверки из руководства, а не перечень полей ответа SDK. Фактические поля смотрите в типах установленной версии и официальной документации.

## Обратные вызовы, очереди и удалённое выполнение

Ваш исполнитель может запускать SDK, после чего ваша служба отправит уведомление о завершении. В такой схеме состояние очереди, HTTP-обратные вызовы, форматы подписей и политика повторов относятся к протоколу вашей системы. Потоковые события App Server нельзя напрямую использовать как адрес вебхука.

Далее изучите [границы вебхуков и событий задач](/ru/guide/developer-platform/webhooks/overview/) и [скрипты и конвейеры](/ru/guide/developer-platform/non-interactive/scripts-and-pipelines/). Эта страница не обещает, что вызов SDK автоматически создаст задачу Codex Cloud, сформирует URL артефакта или предоставит делегирование OAuth.
