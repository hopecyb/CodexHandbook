**Платформа для разработчиков** предназначена для тех, кто хочет встроить Codex в рабочие процессы и превратить его в часть продукта: пользовательские приложения, пакетную проверку кода, контрольные этапы выпуска и внутренние порталы разработчиков. Если вам нужно просто «написать промпт и исправить ошибку», начните с раздела [«Начало работы»](/ru/guide/getting-started/).

Эта глава посвящена не повседневной работе с Codex, а его подключению к собственным системам.

Она рассчитана на такие сценарии:

- автоматический запуск задач в CI;
- интеграция Codex с бэкендом или внутренними инструментами;
- включение Codex в командные процессы.

## О чём эта глава

- Граница между платформой для разработчиков и документацией пользовательских продуктов
- Типовая архитектура интеграции

## Типовая архитектура (концептуально)

```text
Ваша система (CI / внутренняя платформа / SaaS)
        ↓ Локальный SDK / CLI или клиент App Server
Контролируемая среда выполнения (вызовы модели + инструменты + политики)
        ↓
Git-провайдер / трекер задач / хранилище артефактов
```

## Принципы проектирования

Codex SDK запускает локальный Agent. Удалённый исполнитель, очередь и HTTP-обратные вызовы, которые вы создаёте, — архитектурные решения вашей интеграционной системы. Не следует делать из схемы вывод о существовании единого размещённого API для облачных задач. Основания и минимальный пример вызова приведены в [обзоре SDK](/ru/guide/developer-platform/sdk-overview/).

1. **Идемпотентность и возможность повтора:** повторная проверка одного PR должна давать сопоставимые результаты.
2. **Минимальные привилегии:** токены CI должны предоставлять только чтение либо доступ к конкретным репозиториям.
3. **Наблюдаемость:** сохраняйте версию промпта, модель и артефакты diff.
4. **Участие человека:** автоматический комментарий ≠ автоматическое слияние.

## Распространённые заблуждения

### 1. Нужно ли изучить эту главу, чтобы по-настоящему пользоваться Codex?

Если ваша основная цель — сначала освоить Codex, вернуться к этой главе можно позже.

### 2. Как это связано с CLI / App / IDE?

Удобно разделять их так:

- **App / CLI / IDE** — точки входа, через которые вы или ваша команда напрямую работаете с Codex;
- **платформа для разработчиков** — встраивание Codex в другие системы и процессы.

### 3. Что в этой главе полезнее всего прочитать сначала?

Если вам нужен только концептуальный обзор, начните с [обзора SDK](/ru/guide/developer-platform/sdk-overview/) и его связи с [неинтерактивным режимом](/ru/guide/cli/non-interactive-mode/).

Глава о платформе для разработчиков объясняет, как подключать Codex к системам. Для первого практического знакомства с Codex сначала прочитайте материалы по началу работы.
