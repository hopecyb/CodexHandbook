Многие задачи становятся всё запутаннее по мере обсуждения, потому что контекст теряет фокус.

Сохранить фокус контекста — значит работать за один раз над одной ясной целью и не смешивать старые вопросы с новыми.

## Почему диалог становится всё запутаннее

Подход «лучше добавить побольше сведений для надёжности» обычно не работает: контекст нельзя наращивать бесконечно.

Если в одной задаче для Codex одновременно смешаны:

- Исходная проблема
- Новый вопрос, добавленный заодно
- Идея, возникшая по ходу работы
- Уже обсуждённые, но теперь несущественные подробности

главное неизбежно размывается.

## Почему задача постепенно отклоняется от цели

Типичные причины:

- В одном диалоге смешано несколько целей
- Ограничения, заданные в начале, позднее забываются даже вами
- Уже решённый вопрос продолжает занимать внимание
- По ходу работы добавлено новое требование, но границы не сформулированы заново

Вам может казаться, что вы уточняете информацию, тогда как для Codex задача становится всё менее сфокусированной.

## Основные приёмы

- Одна задача — одна цель
- Регулярно подводите итог: «завершено / осталось / действующие ограничения»
- Для длительных задач используйте этапы с контрольными точками
- Между сеансами используйте [передачу и возобновление работы](/ru/guide/agent-work/handoff-and-resume/)

## Признаки того, что пора подвести итог

Подведите промежуточный итог, если:

- Даже вам приходится перечитывать диалог, чтобы понять текущее состояние
- В рамках одной задачи уже обсуждается второй вопрос
- Просьб «заодно сделать ещё кое-что» становится всё больше
- Codex начинает ссылаться на старые выводы, которые больше не важны

## Какие проблемы решают эти приёмы

### Одна задача — одна цель

Не просите в рамках одной задачи одновременно:

- Исправить Bug
- Отредактировать текст
- Заодно провести рефакторинг
- Исследовать ещё одну новую проблему

После разделения область становится яснее, а результат проще проверить.

### Регулярный итог: «завершено / осталось / действующие ограничения»

Так вы калибруете задачу по ходу работы. В длительной задаче это помогает обеим сторонам не потерять текущее состояние.

### Этапы с контрольными точками для длительных задач

Контрольная точка означает: завершить небольшой этап, проверить, что работа не отклонилась от цели, и лишь затем переходить к следующему.

Например, сначала «только найти проблему», потом «только предложить решение» и, наконец, «внести изменения».

### Передача работы между сеансами

Если задачу невозможно завершить за один сеанс, сохраните ключевое состояние в кратком сообщении для передачи работы.

## Готовая формулировка для подведения промежуточного итога

Можно написать так:

```text
Подведём промежуточный итог.
Завершено: A.
Осталось: B.
Действующие ограничения: изменять только клиентскую часть, не менять API; не устанавливать новые зависимости.
Следующий шаг — только C.
```

## Распространённые ошибки

### 1. Попытка сразу перечислить все требования без разделения главного и второстепенного

Большой объём информации не делает её ясной. Если не отделить основную задачу от необязательных дополнений, Codex легче запутаться.

### 2. Задача изменилась, но работа продолжается в старом диалоге

Если направление уже стало другим, новый тред иногда оказывается гораздо чище, чем попытка продолжить прежний.

### 3. Слишком много изменений без проверки этапов

Чем больше изменений внесено разом, тем труднее понять, на каком шаге работа начала отклоняться от цели.

Сохранить фокус контекста — не значит говорить меньше. Нужно оставлять актуальную информацию и вовремя убирать то, что уже не важно. Если контекст запутан, последующая работа легко отклоняется от цели.
