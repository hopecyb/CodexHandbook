Сочетания клавиш зависят от платформы, клиента и пользовательских настроек. Здесь перечислены только явно документированные на текущий момент сочетания; полный список смотрите в разделе **Keyboard Shortcuts** внутри App.

## Desktop App

| Действие | macOS | Windows |
|---|---|---|
| Открыть Settings | `Cmd + ,` | `Ctrl + ,` |
| Открыть или закрыть Activity | `Cmd + Option + U` | `Ctrl + Alt + U` |
| Открыть встроенный терминал | `Ctrl` + обратная кавычка | `Ctrl` + обратная кавычка |
| Открыть палитру команд App | `Cmd + K` | См. Keyboard Shortcuts |
| Очистить экран терминала | `Ctrl + L` | `Ctrl + L` |

`Cmd + K` открывает палитру команд App, а не очищает терминал.

В разделе Keyboard Shortcuts настроек можно искать по команде или клавише, менять привязки и восстанавливать значения по умолчанию. После настройки локальная привязка важнее справочной карточки в интернете.

## IDE

В редакторах семейства VS Code параметр `chatgpt.composerEnterBehavior` определяет, как Enter и `Cmd/Ctrl + Enter` отправляют многострочные промпты. Не предполагайте, что на каждом компьютере используется одна и та же клавиша отправки.

Во время работы Codex параметр `chatgpt.followUpQueueMode` определяет, ставится ли новое сообщение в очередь или немедленно меняет направление. Нажмите `Cmd/Ctrl + Shift + Enter`, чтобы однократная отправка использовала противоположный текущему режим.

Если боковая панель Codex отсутствует, выполните из Command Palette редактора:

```text
Codex: Open Codex Sidebar
```

## CLI

Используйте `/help` текущего TUI CLI и подсказки на экране. На этой странице не угадываются `y`, `n` и другие клавиши подтверждения, поскольку взаимодействие зависит от терминала, режима и версии.

Общий сигнал терминала `Ctrl + C` может прервать команду или сеанс. Сначала проверьте текущее состояние и не считайте его клавишей Back без побочных эффектов.

## Порядок изучения

Сначала научитесь открывать Settings и Activity, запускать терминал и отправлять многострочные промпты. Остальные часто используемые действия ищите внутри App. В командной документации лучше указывать названия действий, а не навязывать всем одинаковые пользовательские привязки.
