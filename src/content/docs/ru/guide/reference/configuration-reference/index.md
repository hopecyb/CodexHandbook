Справочник конфигурации может подавлять количеством ключей, уровней и переопределений. Начните с одного вопроса:

> **Что должно быть конфигурацией, а что — нет?**

Файлы конфигурации часто объединяют поведение **модели, песочницы, подтверждений и MCP**. Эта страница — **концептуальный индекс**; пути к файлам и ключи TOML/YAML должны соответствовать [документации OpenAI Codex](https://developers.openai.com/codex) и установленной версии.

## Принцип принятия решения

В конфигурации хранятся параметры, которые **должны влиять на поведение длительное время**. Обычно туда не относятся:

- секреты;
- полный текст командных правил;
- инструкции разовой задачи.

Три категории:

- **Долгосрочные предпочтения поведения** → конфигурация
- **Требования конкретной задачи** → промпт / `AGENTS.md` / Skill
- **Секреты** → переменные окружения или хранилище секретов

Если сомневаетесь, спросите: вы меняете долгосрочные привычки Codex или описываете текущую задачу?

- Долгосрочные привычки → конфигурация
- Текущая задача → промпт, `AGENTS.md` или описание задачи

## Уровни конфигурации

| Уровень | Расположение (концептуально) | Типичное содержимое |
|---|---|---|
| Пользователь | `~/.codex/` и аналогичные пути | Модель по умолчанию, личные привычки подтверждения |
| Проект | Конфигурация в репозитории | Командная песочница, список MCP |
| Переменные окружения | Передача через shell / CI | Ключи, временные переключатели |
| Управляемый | Предоставляется организацией | Обязательная политика без возможности переопределения |

## Чем управляет каждый уровень

- **Пользовательский:** ваши личные настройки по умолчанию
- **Проектный:** общие настройки этого репозитория
- **Переменные окружения:** значения, переданные во время выполнения
- **Управляемая политика:** границы, закреплённые организацией и недоступные для локального переопределения

В первый день не нужно помнить приоритеты. Достаточно знать назначение уровней:

- пользовательский — «как лично мне удобно работать»;
- проектный — «как этот репозиторий требует работать от всех»;
- окружение — «значения для этого запуска»;
- управляемый — «организация уже приняла решение».

## Области конфигурации (концептуально)

### Модель и рассуждение

| Намерение | Примечание |
|---|---|
| Модель по умолчанию | Идентификатор модели для новых сеансов |
| Глубина рассуждения | Уровень сложности, если поддерживается |
| Сэмплирование (temperature и т. п.) | Обычно оставляют по умолчанию; фиксируйте для скриптов |

Контекст: [модели и рассуждение](/ru/guide/foundations/models-and-reasoning/)

### Песочница и сеть

| Намерение | Примечание |
|---|---|
| Область файловой системы | Пути для записи, запись за пределами проекта |
| Доступ к сети | Запретить / ограничить / разрешить |
| Домены исходящего трафика | Список разрешённых, если поддерживается |

Контекст: [песочница и сеть](/ru/guide/foundations/sandbox-and-network/)

### Политика подтверждений

| Намерение | Примечание |
|---|---|
| Перед shell | Всегда спрашивать / список доверия / автоматически (высокий риск) |
| Перед записью файла | Аналогично |
| Вызовы инструментов MCP | На уровне сервера или отдельного инструмента |

Контекст: [разрешения и подтверждения](/ru/guide/foundations/permissions-and-approvals/) · Матрица: [матрица разрешений](/ru/guide/reference/permission-matrix/)

### Рабочая область и CLI

| Намерение | Примечание |
|---|---|
| `cwd` по умолчанию | Начальный каталог |
| Настройки неинтерактивного режима по умолчанию | Подтверждение и песочница exec |
| Уровень журналирования | Повышайте для диагностики |

### Серверы MCP

| Намерение | Примечание |
|---|---|
| Список серверов | Команда, URL, транспорт |
| Передача окружения | Привязана к процессу MCP, а не хранится в Git |

[Подключение MCP](/ru/skills/mcp/connect-an-mcp-server/)

### Расширение IDE / App

Некоторые настройки существуют только в интерфейсе расширения и могут использовать с CLI общее хранилище пользовательской конфигурации — проверяйте документацию продукта.

## Распространённые заблуждения

### 1. Не всё должно находиться в конфигурации

Часто лучше выбрать:

- `AGENTS.md`;
- переменные окружения;
- Skill;
- описание текущей задачи.

Конфигурация — не ящик для всего подряд.

### 2. В первый день не нужны все ключи

Большинство начинает с четырёх областей:

- модель;
- песочница;
- подтверждение;
- MCP.

Они охватывают большинство первых вопросов.

### 3. Проектная конфигурация заменяет командную документацию?

Конфигурация задаёт системные значения по умолчанию, но не объясняет «почему» и «когда не следует».

### 4. Официальных ключей много — сначала изучите четыре

- Модель по умолчанию
- Область песочницы
- Политика подтверждений
- Подключения MCP

## Сравнение с переменными окружения

| Тип | Где хранить |
|---|---|
| API-ключ, токен | Переменная окружения или диспетчер секретов |
| Неконфиденциальные переключатели | Переменная окружения или конфигурация |
| Соглашения о коде | `AGENTS.md`, не конфигурация |

## Следует ли поместить это в конфигурацию?

Четыре вопроса:

1. Должно ли значение применяться долгое время по умолчанию?
2. Оно конфиденциально?
3. Это личная привычка или общее правило проекта?
4. Оно настраивает поведение системы или описывает текущую задачу?

## При настройке поведения

1. Это долгосрочное значение по умолчанию или разовая задача?
2. Это конфиденциальное или обычное значение?
3. Оно личное или общее?

После этого выберите конфигурацию, окружение, `AGENTS.md`, Skill или текущий промпт.

## Распространённые сценарии

| Цель | Обычное место |
|---|---|
| Надолго зафиксировать модель | Пользовательская или проектная конфигурация |
| Команда хочет запускать тесты до правок | `AGENTS.md` |
| Только для этой задачи: каталог `docs/` | Текущий промпт |
| API-ключ / токен | Окружение или Secret |
| Подключить MCP | Проектная конфигурация + окружение |

Это проще, чем всматриваться в списки ключей.

Секреты Cloud: [секреты и переменные окружения](/ru/guide/web-and-cloud/secrets-and-variables/)

## Дисциплина изменений

1. Меняйте один класс конфигурации за раз и наблюдайте неделю.
2. Проектные изменения проводите через PR Review.
3. После обновления CLI читайте официальные примечания по миграции.
4. Никогда не добавляйте секреты в файлы конфигурации репозитория.

Конфигурация предназначена для долгосрочных значений по умолчанию, а не для секретов, текста задачи и эссе о командных правилах.

## Распространённые ошибки

- Имена ключей в документации не соответствуют старой версии CLI.
- Нестрогая личная песочница используется в репозитории клиента.
- Конфигурация противоречит `AGENTS.md`: конфигурация разрешает, а документ запрещает.
