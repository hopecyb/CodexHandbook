Справочник команд помогает выбрать точку входа, а не запомнить каждый флаг:

> **Запустить интерактивный сеанс или выполнить разовую команду?**

На этой странице собраны текущие стабильные точки входа **Codex CLI** для поиска и сравнения. Продолжайте использовать `codex --help` и `--help` каждой подкоманды; полные сведения о зрелости и параметрах приведены в [Developer commands](https://learn.chatgpt.com/docs/developer-commands).

## Когда использовать эту страницу

- Выбор между интерактивной и разовой командой
- Выбор между задачей в стиле чата и скрипта
- Вы уже выбрали CLI, но не знаете нужную точку входа

## Выбор точки входа

- Диалог в процессе работы: `codex`
- Одна задача с результатом после завершения: `codex exec`

Для новых пользователей CLI этого различия достаточно в большинстве случаев.

## Обзор стабильных команд

| Точка входа | Назначение | Подробнее |
|---|---|---|
| `codex` | Интерактивный сеанс TUI | [Интерактивный режим](/ru/guide/cli/interactive-mode/) |
| `codex exec` / `codex e` | Одна неинтерактивная задача или шаг конвейера | [Неинтерактивный режим](/ru/guide/cli/non-interactive-mode/) |
| `codex doctor` | Создать диагностический отчёт об установке, конфигурации, аутентификации, среде выполнения, Git и терминале | [Диагностика CLI](/ru/guide/cli/troubleshooting/) |
| `codex login` / `codex logout` | Управление аутентификацией | [Вход и аутентификация](/ru/guide/getting-started/sign-in-and-authentication/) |
| `codex resume` / `codex fork` | Продолжить или ответвить сохранённый сеанс | [Передача работы и возобновление](/ru/guide/agent-work/handoff-and-resume/) |
| `codex mcp` | Управление серверами MCP | [Подключение сервера MCP](/ru/skills/mcp/connect-an-mcp-server/) |
| `codex plugin` | Установка, просмотр и удаление Plugin | [Plugin](/ru/skills/plugins/) |

:::caution[Разные уровни зрелости]
Официальный справочник также содержит экспериментальные, бета- и устаревшие команды. Этот базовый справочник не смешивает их со стабильным списком; перед использованием уточните зрелость и риски.
:::

## Распространённые заблуждения

### 1. Не нужно запоминать всё

Запомните класс точки входа для задачи, а флаги ищите по мере необходимости.

### 2. `codex exec` — не просто «продвинутый `codex`»

Он предназначен для скриптов и CI без наблюдения, а не для более мощного режима чата.

### 3. Наличие флага ≠ необходимость использовать его сейчас

Многие флаги зависят от версии, окружения и политики безопасности. Сначала поймите назначение.

### 4. Справочник команд ≠ учебник

Это:

- карта точек входа;
- индекс параметров;
- указатель на подробные страницы.

## Интерактивный режим (концептуально)

```bash
# Запустить интерактивный сеанс в корне репозитория (пример)
codex

# Типичные действия в сеансе (зависят от TUI)
# - Ввести описание задачи
# - Слеш-команды / → см. страницу о слеш-командах
# - Подтвердить запросы на shell и запись файлов
```

Слеш-команды: [справочник слеш-команд](/ru/guide/reference/slash-commands/)

## Как выбрать точку входа

1. Выполните `codex --help`.
2. Выберите интерактивный режим или `exec`.
3. Для подкоманды прочитайте её `--help`.

В первый день не нужно погружаться в полную таблицу флагов.

## Быстрый старт

1. `codex --help`
2. Диалог в процессе работы → `codex`
3. CI или скрипты → изучите `codex exec`

## Неинтерактивный exec (концептуально)

```bash
# Рабочий каталог и разовый промпт
codex exec --cd /path/to/repo "Your complete task description"

# Распространённые текущие флаги
# --cd, -C       рабочий каталог
# --model        зафиксировать модель
# --sandbox      политика песочницы
# --ask-for-approval, -a  политика подтверждения
# stdin pipe     прочитать промпт из файла или предыдущей команды
```

Безопасность: [схемы подтверждения человеком](/ru/cases/workflows/human-approval-patterns/)

## Коды завершения и автоматизация

В неинтерактивном режиме CI обычно использует **коды завершения**:

- `0`: выполнение завершено по соглашению;
- ненулевой код: сбой или требуется человек — проверьте stderr и журналы.

Используйте справочник, чтобы выбрать точку входа и понять её назначение; запоминать параметры не нужно.

Не игнорируйте stderr в CI и сохраняйте журналы для процесса [«Диагностировать до исправления»](/ru/cases/workflows/diagnose-before-fixing/).
