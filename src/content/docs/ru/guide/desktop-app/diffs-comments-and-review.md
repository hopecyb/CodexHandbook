Сводка в чате — это объяснение Codex о проделанной работе, а diff Git — фактические изменения файлов. В панели Review настольного приложения можно просматривать diff, добавлять построчные комментарии и решать, какие изменения индексировать, отменять, включать в коммит или отправлять через push.

Для полноценной работы панели Review и команды `/review` проект должен находиться в репозитории Git.

## Два уровня проверки

Сначала самостоятельно проверьте область изменений, затем вызовите независимый reviewer для поиска проблем в реализации:

1. Откройте панель Review и прежде всего проверьте количество файлов и их пути;
2. Выберите **Last turn**, чтобы увидеть изменения именно последнего хода;
3. Переключайтесь между **Unstaged**, **Staged**, **Commit** и **Branch**, чтобы задать область проверки;
4. Выполните `/review` в поле ввода;
5. Выберите сравнение с базовой веткой, проверку незакоммиченных изменений, конкретный коммит или собственные критерии;
6. Изучите замечания, отсортированные по приоритету, и решите, что исправить.

По умолчанию reviewer команды `/review` работает только на чтение и не меняет рабочее дерево. Если затем попросить Codex исправить замечания, продолжат действовать исходные правила песочницы и одобрений.

## Многоразовый набор критериев Review

```text
Проверь текущие незакоммиченные изменения. Обрати особое внимание:
- не вышли ли изменения за рамки задачи;
- нет ли регрессий поведения, пропущенных граничных случаев или проблем безопасности;
- покрывают ли тесты сценарии ошибок;
- соответствуют ли друг другу документация и реализация.

Сначала перечисли проблемы по убыванию серьёзности. Для каждой укажи файл, место, доказательство и минимальное исправление.
Если проблем не найдено, скажи об этом прямо и перечисли риски, которые всё ещё не покрыты тестами.
```

## Уменьшайте неоднозначность построчными комментариями

Наведите указатель на подозрительную строку, нажмите появившийся значок **+** и запишите конкретное замечание. Когда все комментарии готовы, отправьте однозначную инструкцию:

```text
Обработай оставленные мной построчные комментарии. Сведи изменения к минимуму, затем снова запусти соответствующие тесты и покажи новый diff.
```

Полезный комментарий описывает риск или условие приёмки — например: «Что вернёт этот код для пустого массива?». Фразы «здесь неправильно» обычно недостаточно.

## Индексирование и отмена

В панели Review можно индексировать, убирать из индекса или отменять весь diff, отдельный файл или отдельный hunk. Отмена удаляет изменения: сначала убедитесь, что они не были внесены пользователем ещё до начала задачи.

Рекомендуемый порядок приёмки: область → поведение → тесты → безопасность → сопровождаемость. Дополнительные приёмы см. в разделе [Проверка diff](/ru/guide/quality/review-diffs/).
