Основная единица параллельной работы — чат с независимыми контекстом, сообщениями, результатом и целью. Задачу стоит распараллеливать не потому, что в ней много шагов, а когда **её части независимы, границы файлов ясны, а результаты можно принять по отдельности**.

![Схема оркестрации: основной поток распределяет независимые задачи между несколькими дочерними Agent, а затем объединяет доказательства и сведения о конфликтах](/illustrations/flow-subagents.webp)

## Сначала определите, возможна ли параллельная работа

| Можно выполнять параллельно | Следует выполнять последовательно |
|---|---|
| Два исследования только для чтения | Вторая задача зависит от вывода первой |
| Каталоги кода и документации не пересекаются | Обе задачи меняют один ключевой файл |
| Независимые прототипы двух решений | Требования всё ещё часто меняются |
| У каждой задачи отдельные тесты | Правильность можно определить только после общей интеграции |

Официальная рекомендация — не позволять двум чатам записывать один источник данных. Для параллельной разработки используйте разные Git worktree.

## От простого к сложному

### 1. Начните с параллельных задач только для чтения

```text
Задача: только проанализировать последний сбой модуля аутентификации, не изменяя файлы.
Область: src/auth/** и соответствующие тесты.
Результат: гипотезы о первопричине, пути к доказательствам, оставшиеся неопределённости и рекомендуемые команды проверки.
```

Задачи только для чтения не создают конфликтов слияния и лучше всего подходят для первого опыта.

### 2. Затем распараллельте задачи с записью

Для каждого чата явно задайте цель, владение файлами, запретные области и критерии приёмки:

```text
Цель: дополнить документацию кодов ошибок аутентификации.
Владение: только docs/auth/**.
Запрещено: изменять src/**, lock-файлы и общую конфигурацию.
Приёмка: выполнить pnpm check:links и сообщить результат.
```

Чаты, которые пишут код, размещайте в отдельных [Worktree](/ru/guide/desktop-app/worktrees/). Общую конфигурацию должен изменять основной чат или один явно назначенный владелец.

### 3. В конце соберите результаты

Не объединяйте результаты механически. Основной чат должен проверить:

1. Соблюдены ли границы каждой задачи
2. Воспроизводимы ли доказательства и тесты
3. Не противоречат ли выводы друг другу
4. Нужно ли повторно запустить интеграционные тесты после слияния

## Длительные задачи и режим Goal

Введите `/goal` в Desktop App, CLI или IDE, чтобы запустить режим Goal. Цель должна описывать результат, ограничения и критерии проверки. У каждого чата собственная цель; параллельная работа не расширяет песочницу или разрешения, поэтому операция, требующая решения пользователя, всё равно будет приостановлена.

Более подробная оркестрация на уровне инструментов описана в разделе [Дочерние Agent](/ru/guide/agent-work/subagents/).
