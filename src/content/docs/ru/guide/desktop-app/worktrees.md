Worktree позволяет одному репозиторию Git иметь несколько независимых каталогов checkout. У каждого каталога собственные файлы и состояние ветки, но метаданные Git у них общие. Это удобно, когда несколько чатов с кодом работают параллельно и не должны перезаписывать файлы друг друга.

## Предварительные условия

- Проект должен находиться в репозитории Git;
- Границы задачи должны независимо описываться и проверяться;
- Параллельные задачи не должны менять один и тот же набор ключевых файлов.

Если вы только начинаете работать с Codex, сначала выполняйте задачи последовательно в режиме Local. Переходите к Worktree, когда ожидание или конфликты файлов действительно становятся проблемой.

## Создание в App

1. Под полем ввода нового чата выберите **Worktree**;
2. Выберите начальную ветку: основную, функциональную или текущую с неиндексированными изменениями;
3. Отправьте промпт — приложение создаст Git worktree;
4. Выполните проверку, тестирование и Review в отдельном чате;
5. Когда будете готовы вернуться к локальному checkout, используйте **Handoff**.

По умолчанию Worktree создаётся в состоянии detached HEAD. Это не мешает Codex работать, но до сохранения или публикации коммитов явно определите целевую ветку и способ слияния.

## Пример двух параллельных направлений

| Чат | Задача Worktree | Владение файлами | Приёмка |
|---|---|---|---|
| A | Исправить ошибку входа | `src/auth/**` | Тесты аутентификации проходят |
| B | Дополнить документацию аутентификации | `docs/auth/**` | Проверка ссылок проходит |

Не позволяйте A и B одновременно менять общий lock-файл или один файл конфигурации. Если это необходимо, заранее назначьте один чат владельцем изменения, а второй пусть предоставит только результаты анализа.

## Проверка перед передачей

```bash
git status --short
git diff --check
git diff --stat
```

Затем запустите тесты для конкретной задачи. Выполняйте Handoff, коммит или слияние только после того, как точно установили происхождение каждого изменения, целевую ветку и результат проверки.

## Связь с плановыми задачами и Remote

- Плановые задачи в репозитории Git могут использовать отдельный фоновый Worktree, чтобы не конфликтовать с текущей работой;
- Через Remote можно с мобильного устройства управлять чатами Worktree на подключённом компьютере; репозиторий и команды по-прежнему остаются на этом компьютере или в его удалённой среде разработки;
- В проектах без Git изоляции Worktree нет, поэтому плановые задачи работают непосредственно в каталоге проекта.
