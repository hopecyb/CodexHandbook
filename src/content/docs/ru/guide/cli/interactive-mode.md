В «интерактивном режиме» вы ведёте диалог с Codex непосредственно в терминале. Он объясняет и выполняет действия, а при необходимости ждёт вашего подтверждения.

Это один из основных способов работы с CLI.

После запуска интерактивного сеанса:

1. Запускайте его из каталога проекта или задайте рабочий каталог согласно документации
2. Формулируйте промпты так же тщательно, как в App
3. Одобряйте или отклоняйте вызовы инструментов, когда появляется запрос
4. Управляйте сеансом командами вида `/`, если они доступны; ориентируйтесь на справку текущей версии CLI

Рекомендации по формулировке задач остаются теми же: [Промпты](/ru/prompts/)

## Для каких задач подходит интерактивный режим

Он лучше всего работает там, где решения принимаются по ходу выполнения:

| Состояние задачи | Почему подходит интерактивный режим |
|---|---|
| Требования ещё не полностью определены | Их можно уточнять в процессе |
| Следующий шаг зависит от просмотра diff | Можно одобрять действия поэтапно или сужать область задачи |
| Процесс впервые пробуется в этом проекте | Проще следить, что было прочитано и изменено |
| Нужны разрешения, внешние инструменты или запись файлов | Пользователь контролирует ключевые этапы |

Если процесс уже стабилен и не требует промежуточных уточнений, рассмотрите [неинтерактивный режим](/ru/guide/cli/non-interactive-mode/) или автоматизацию.

## Распространённые заблуждения

### 1. Раз работа идёт в терминале, можно писать менее точные промпты?

Нет.

Изменилась только точка входа; качество постановки задачи не стало менее важным.
Чем яснее цель, ограничения и критерии завершения, тем надёжнее результат.

### 2. Почему важно запускать CLI из каталога проекта?

CLI должен понимать, в каком проекте он работает.
Неверный каталог может привести к тому, что он:

- не увидит нужные файлы;
- изменит не тот каталог;
- не прочитает правила проекта.

### 3. Запрос одобрения в терминале означает ошибку?

Обычно наоборот: это значит, что CLI соблюдает заданные границы разрешений.

## Простой сценарий для первого запуска

Начните с небольшой задачи:

- запустите CLI в корне проекта;
- разрешите менять только один файл;
- после завершения попросите перечислить внесённые изменения.

Интерактивный режим CLI — это диалоговый процесс выполнения задачи в терминале. Запускайте его в правильном каталоге и формулируйте промпт достаточно чётко.
