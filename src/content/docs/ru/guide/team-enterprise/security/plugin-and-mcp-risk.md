**Plugin** и **серверы MCP** подключают Codex к внешним системам: трекерам задач, базам данных и внутренним API. Чем больше возможностей, тем шире поверхность [модели угроз](/ru/guide/team-enterprise/security/threat-model/) для утечки данных и выхода за разрешённые границы. Читайте вместе с [обзором MCP](/ru/skills/mcp/mcp-overview/) и [обзором Plugin](/ru/skills/plugins/plugins-overview/).

В первый день не обязательно знать идеальные определения. Главное: внешнее подключение Codex увеличивает и возможности, и риски.

Независимо от названия — Plugin или MCP — задайте вопросы:

- Что он может читать
- Что он может записывать
- Кто его одобряет
- Как расследуются инциденты

## О чём эта страница

- Категории рисков расширений
- Списки одобрения и фиксация версий
- Изоляция при диагностике и инцидентах

## Категории рисков

| Тип | Пример | Мера контроля |
|---|---|---|
| Чтение данных | MCP читает базу данных клиентов | Учётная запись только для чтения, разрешения на уровне строк |
| Запись данных | Автоматическое закрытие тикетов, изменение конфигурации | Подтверждение человеком, двойное подтверждение |
| Сеть | Произвольные исходящие подключения | Список разрешённых направлений исходящего трафика |
| Учётные данные | Токен OAuth на диске | Управление секретами, короткоживущие токены |
| Цепочка поставок | Подмена обновления стороннего сервера | Фиксация версии и хеша |

## Процесс командного одобрения (рекомендуется)

```text
Запрос (цель, класс данных, разрешения) → проверка безопасности и архитектуры
    → внесение в репозиторий «утверждённого списка» или внутренний каталог
    → фиксация версии и владельца
    → повторная проверка раз в квартал или при крупном обновлении
```

Экспериментальный личный MCP **не должен** использовать токены производственного репозитория.

## Минимальные практики

1. **По умолчанию запрещайте** установку удалённых MCP, отсутствующих в списке.
2. **Локальный MCP** всё равно может читать весь диск — используйте отдельного пользователя ОС или контейнер.
3. **Журналы:** имя инструмента и сводка параметров с удалёнными секретами; см. [аудит Hook](/ru/skills/hooks/hooks-examples/).
4. **Skill и MCP:** Skill описывает процесс, а MCP выполняет внешние вызовы. Оценивайте их совокупные разрешения и применяйте наиболее строгую политику.

## Распространённые ошибки

- Считать, что «официальный магазин» автоматически означает «прошло проверку безопасности»
- Использовать одно приложение MCP OAuth для разработки и производственной среды
- Включать `DEBUG=*` и тем самым выводить токены в журналы CI

## Распространённые заблуждения

### 1. Пока неясна разница между Plugin и MCP — важно ли это вначале?

На первом этапе — не слишком.

Оба подключают Codex к внешним системам, поэтому требования к разрешениям и рискам применимы в обоих случаях.

### 2. Почему сначала только чтение?

Режим только для чтения обычно означает:

- более простой пилотный запуск;
- более простое доказательство ценности;
- меньший масштаб последствий ошибки.

### 3. Можно установить и забыть?

Даже для удобной функции нужно выяснить:

- к каким данным она получает доступ;
- записывает ли данные обратно;
- как управляются учётные данные.

Для внешних расширений сначала определите разрешения и границы и лишь затем оценивайте мощность функций.
