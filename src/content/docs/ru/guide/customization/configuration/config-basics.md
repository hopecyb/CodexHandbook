Файл конфигурации позволяет **унифицировать поведение Codex** на вашем компьютере или в проекте, чтобы не задавать модель, уровень подтверждений и политику песочницы в каждом сеансе.

## Содержание страницы

- Где хранится конфигурация и как сочетаются проектный и пользовательский уровни
- Какие настройки меняют чаще всего: модель, подтверждения, песочница и рабочий каталог по умолчанию
- Граница с `AGENTS.md`: конфигурация управляет возможностями, а AGENTS — способом работы с кодом проекта

## Чем управляет конфигурация

Конфигурация ближе всего к **рабочим привычкам Codex по умолчанию**.

Например:

- Какую модель использовать по умолчанию
- Насколько строгими должны быть границы безопасности по умолчанию
- В каком каталоге начинать работу по умолчанию

Она задаёт не временные требования одной задачи, а обычное начальное состояние для большинства случаев.

## Уровни конфигурации

| Уровень | Типичное расположение | Содержимое |
|---|---|---|
| Пользовательский | Конфигурация в `~/.codex/` — точное имя файла см. в официальной документации | Модель по умолчанию, личные привычки подтверждения |
| Проектный | Фрагмент конфигурации или связанный с `codex` проектный файл в репозитории | Общая политика песочницы и инструментов команды |
| Управляемый | Назначается организацией | Обязательные параметры, которые пользователь не может переопределить |

Для **изменчивых сведений** — путей, имён полей и TOML-ключей — сверяйтесь с [документацией OpenAI Codex](https://developers.openai.com/codex). Здесь рассматриваются понятия и способ принятия решений.

## Распространённые заблуждения

### Большой объём конфигурации не означает профессионализм

При первом знакомстве с файлом конфигурации хочется задать каждый доступный параметр.

Но новичку обычно достаточно закрепить несколько часто используемых настроек:

- Модель по умолчанию
- Политику подтверждений и песочницы по умолчанию
- Рабочий каталог по умолчанию

Сначала стабилизируйте их, а не пытайтесь сразу изучить все поля.

### Конфигурация не равна правилам проекта

Если требование должны соблюдать все участники, его обычно следует записать в `AGENTS.md` или документацию проекта, а не только в локальную конфигурацию.

Например:

- Какие проверки выполнять перед коммитом
- Какие каталоги нельзя изменять
- Для каких задач запрещён автоматический push

Эти правила не должны зависеть только от личной конфигурации.

## Часто настраиваемые аспекты

### Модель и рассуждения

- Повседневная разработка: баланс скорости и качества
- Сложный рефакторинг: более мощная модель рассуждений, если поддерживается тарифом
- Скрипты и CI: фиксированная модель для воспроизводимости

Основные понятия: [Модели и рассуждения](/ru/guide/foundations/models-and-reasoning/)

### Подтверждения и песочница

| Намерение | Направление конфигурации |
|---|---|
| Новичок или недоверенный репозиторий | Более строгие подтверждения, ограничение сети и области записи |
| Доверенный личный проект | При безопасных условиях можно сократить число остановок |
| Корпоративный репозиторий | Следовать управляемой политике и не ослаблять её самостоятельно |

Основные понятия: [Разрешения и подтверждения](/ru/guide/foundations/permissions-and-approvals/) и [Песочница и сеть](/ru/guide/foundations/sandbox-and-network/)

### Согласованность CLI и App

Для одной учётной записи в CLI и настольном App следует сохранять **одинаковый базовый уровень безопасности**, а не использовать полные разрешения в CLI и строгие ограничения в App.

## Минимально полезный подход

1. Прочитайте официальный раздел Configuration и уточните пути файлов для текущей версии
2. Измените только один параметр — например, режим песочницы по умолчанию — и понаблюдайте неделю
3. Общие настройки команды запишите в документацию репозитория, а личные предпочтения оставьте локально
4. В `AGENTS.md` объясните, как рекомендуется использовать Codex с проектом, не копируя всю конфигурацию

## Как выбрать место для настройки

Если вы не уверены, использовать ли конфигурацию, `AGENTS.md` или промпт задачи, ответьте на вопросы:

1. Это привычное значение по умолчанию для большинства задач?
2. Это личное предпочтение, важное только для меня?
3. Это правило, которое должен соблюдать весь проект?

В большинстве случаев:

- Значение по умолчанию хранится в конфигурации
- Личное предпочтение остаётся на личном уровне
- Общая договорённость команды хранится в репозитории

## Распространённые ошибки

- Отключить все подтверждения ради удобства, а затем открыть проект в каталоге с производственными данными
- Записать ключ API в файл конфигурации и добавить его в Git
- Использовать в документации ключ конфигурации, не соответствующий установленной версии — например, не проверить его после обновления CLI

## Границы безопасности

Файл конфигурации может содержать **белые списки путей, сетевую политику и список серверов MCP**. Перед изменением подумайте, сможет ли вредоносный промпт воспользоваться новой настройкой. В корпоративной среде конфигурацию должен назначать администратор; пользователю не следует обходить управляемую политику.

В конфигурации лучше хранить значения по умолчанию, которые вы выбираете почти каждый раз, а не помещать туда все существующие правила.
