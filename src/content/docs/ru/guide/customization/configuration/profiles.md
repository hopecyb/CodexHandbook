В текущем Codex CLI параметр `--profile <name>` накладывает `$CODEX_HOME/<name>.config.toml` на базовую пользовательскую конфигурацию. Он предназначен прежде всего для CLI и не должен описываться как универсальный «режим в одно нажатие» настольного приложения.

## Минимальный пример

В базовой конфигурации сохраните общие значения по умолчанию:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "medium"
```

Profile для Review только в режиме чтения:

```toml
# ~/.codex/review.config.toml
sandbox_mode = "read-only"
approval_policy = "never"
```

Запуск:

```bash
codex --profile review
# Сокращённая форма
codex -p review
```

Проверьте семантику локальной версии:

```bash
codex --help
```

В текущей справке должны быть описаны путь к файлу Profile и правила наложения. Для другой версии ориентируйтесь на локальный вывод и официальный справочник конфигурации.

## Для чего подходит Profile

| Profile | Назначение | Пример границ |
|---|---|---|
| `review` | Проверка только для чтения | read-only, без операций записи |
| `workspace` | Повседневные изменения проекта | Запись только в рабочей области, подтверждения по необходимости |
| `ci` | Неинтерактивная проверка | Фиксированный вывод, без push |

Profile сохраняет только исходный набор настроек. Он не отменяет requirements организации и не делает промпт автоматически безопасным. В частности, не создавайте часто используемый Profile по умолчанию с `danger-full-access`.

## Не путайте с Permission Profile

- **Конфигурационный Profile**: `--profile name` выбирает `<name>.config.toml`, который может накладывать различные настройки Codex;
- **Permission Profile (Beta)**: `default_permissions` и `[permissions.<name>]` определяют границы файловой системы и сети.

Оба механизма называются Profile, но имеют разное назначение и структуру конфигурации. Текущий Permission Profile также не сочетается со старым `sandbox_mode`: выберите одну систему разрешений.

## Границы командного использования

Конфигурационный Profile расположен в пользовательском Codex home и в текущей версии не является проектной конфигурацией, которую можно естественным образом добавить в репозиторий. Команда может предоставить в документации проверенный пример файла, чтобы участники установили и сверили его явно. Не предполагайте, что личный Profile автоматически включится после clone репозитория.

## Приёмка

1. Выполните `codex --help` и убедитесь, что текущая версия поддерживает `-p/--profile`;
2. Проверьте `review` на задаче только для чтения;
3. Запросите чтение файла вне рабочей области или запись и убедитесь, что граница блокирует действие ожидаемым образом;
4. Проверьте фактически действующую конфигурацию, а не только имя файла.
