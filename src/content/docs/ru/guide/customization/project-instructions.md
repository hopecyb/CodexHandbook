«Инструкции проекта» — это **статический контекст**, помогающий Codex понять репозиторий. Он не ограничен одним форматом файла.

## Содержание

- Где хранить информацию уровня проекта помимо `AGENTS.md`
- Как распределить роли между README, docs и скриптами
- Какие сведения должны находиться в репозитории, а какие — только в текущем диалоге

## Из чего состоит контекст проекта

| Источник | Назначение |
|---|---|
| `AGENTS.md` | Правила совместной работы и команды — авторитетное описание приведено в серии AGENTS этой главы |
| `README.md` | Что представляет собой проект и как его запустить |
| `docs/` | Архитектура, ADR и Runbook |
| Зависимости и скрипты | Исполняемый источник истины: `package.json`, `Makefile` и другие файлы |

Codex читает эти материалы с помощью инструментов. Важно сохранить **единый источник истины**: команда запуска из README должна действительно работать.

## Основной подход

1. Убедитесь, что корневой `README.md` содержит четыре раздела: назначение, установка, разработка и тестирование
2. Перенесите в `AGENTS.md` **инструкции, которые постоянно повторяете Codex**
3. В задаче ссылайтесь через `@` на конкретные файлы, а не вставляйте их целиком:

```text
Исправь обращение к null в @src/auth/login.ts, соблюдая требования к тестам из @AGENTS.md.
Связанный дизайн описан в @docs/auth-flow.md
```

## Почему это важно

Распространённая ситуация:

- README описывает один способ
- docs — другой
- Рабочая команда спрятана в `package.json`

Это запутает не только человека, но и Codex. Старайтесь сделать «истину проекта» в репозитории как можно более централизованной и согласованной.

## Разделение ролей с контекстом диалога

- **Инструкции проекта**: относительно стабильны в течение нескольких месяцев
- **Контекст диалога**: текущая цель, ограничения и промежуточные выводы

Если одно правило многократно всплывает в длительной задаче, **запишите его обратно** в `AGENTS.md` или `docs/`, а не копируйте в десять тредов. См. [Сохранение фокуса контекста](/ru/guide/context/keep-context-focused/).

## Распространённые ошибки

- Устаревший README заставляет Codex выполнять неверную команду
- Вся документация собрана в огромном `CONTEXT.md`, который никто не сопровождает
- Конфиденциальные сведения записаны в инструкциях публичного репозитория

## Распространённые заблуждения

### 1. Если я всё объясню в диалоге, беспорядок в документации репозитория не важен

В краткосрочной перспективе это может сработать, но со временем хаос будет расти.

В следующий раз всё придётся объяснять заново, а другие участники не увидят текущих договорённостей.

### 2. `AGENTS.md` решает все проблемы с инструкциями проекта

Нет.

`AGENTS.md` лучше подходит для правил и ограничений совместной работы. Он не должен заменять описание проекта, архитектурный контекст и полное руководство по запуску.

### 3. Чем больше документации, тем лучше

Важнее другое:

- Ясное распределение ролей
- Согласованное содержимое
- Рабочие ключевые команды

## Рекомендуемое распределение

- `README.md`: что представляет собой проект, как его запустить и протестировать
- `AGENTS.md`: правила совместной работы, запретные области и критерии завершения
- `docs/`: более подробный контекст, архитектура и описание процессов
- Скрипты и файлы конфигурации: исполняемый источник истины

Главная задача инструкций проекта — помочь Codex и людям найти один и тот же «источник истины репозитория». Количество документов само по себе не является целью.

## Контрольный список приёмки

- [ ] Человек или Codex после нового clone может запустить тесты, следуя README и AGENTS.md
- [ ] Промпт задачи в основном использует ссылки @, не повторяя большой объём контекста
