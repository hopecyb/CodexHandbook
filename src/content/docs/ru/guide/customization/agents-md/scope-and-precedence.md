В начале каждого запуска Codex строит цепочку инструкций. Важно не придумывать общую таблицу приоритетов для политик организации, конфигурации и промптов, а прежде всего правильно понимать порядок обнаружения самого `AGENTS.md`.

## Официальный порядок обнаружения

1. **Глобальный уровень**: сначала в Codex home — по умолчанию `~/.codex` — ищется `AGENTS.override.md`, а при его отсутствии читается `AGENTS.md`. На этом уровне используется только первый непустой файл.
2. **Уровень проекта**: Codex проходит от корня проекта — обычно корня Git — до текущего рабочего каталога. В каждом каталоге по порядку проверяются `AGENTS.override.md`, `AGENTS.md` и настроенные fallback-имена; для каждого уровня выбирается не более одного файла.
3. **Объединение**: файлы объединяются от корня к текущему каталогу. Более близкие к текущему каталогу инструкции добавляются позднее и поэтому могут переопределять более ранние.

Codex пропускает пустые файлы и прекращает объединение, когда размер содержимого достигает `project_doc_max_bytes`. Ограничение по умолчанию — 32 KiB.

## Пример Monorepo

```text
repo/
├── AGENTS.md
├── apps/
│   └── web/
│       └── AGENTS.md
└── services/
    └── payments/
        ├── AGENTS.md
        └── AGENTS.override.md
```

При запуске из `services/payments` сначала загружается корневой `AGENTS.md`. Поскольку в текущем каталоге существует `AGENTS.override.md`, расположенный рядом `AGENTS.md` игнорируется.

В корневом файле задавайте правила для всего репозитория: менеджер пакетов, общие тесты и запретные области безопасности. Во вложенном файле указывайте только дополнительные правила конкретного сервиса. Не копируйте 80 % одинакового содержимого.

## Как сочетать с промптом задачи

`AGENTS.md` хранит долговременные, версионируемые соглашения проекта, а промпт описывает цель, область и приёмку текущей задачи. Например:

```text
Соблюдай все применимые AGENTS.md. В этой задаче изменяй только services/payments/retry.ts и тесты.
Не выполняй замену ключей. Запусти make test-payments и сообщи фактический результат.
```

Промпт не может превратить непреодолимые системные, организационные, песочничные или разрешительные границы в доступные возможности. При конфликте попросите Codex перечислить связанные источники инструкций и их области, отделив изменяемые значения проекта по умолчанию от фактических ограничений выполнения. Если область ясна, разрешение уже предоставлено и конфликта более высокого уровня нет, работа должна продолжаться. Если действительно не хватает сведений или разрешения, следует указать конкретную блокирующую причину. Полное сопоставление см. в разделе [Приоритеты контекста](/ru/guide/context/context-priority/).

## Проверка фактически загруженных инструкций

Начните новый сеанс из целевого каталога и спросите:

```text
До начала работы перечисли порядок источников AGENTS.md / AGENTS.override.md, загруженных в этом сеансе,
и кратко опиши дополнительные ограничения каждого файла. Не изменяй файлы.
```

`AGENTS.md` читается при запуске. После изменения откройте новый запуск или сеанс для проверки и не предполагайте, что текущий сеанс обновился автоматически.

## Fallback и ограничение размера

Если в проекте уже есть `TEAM_GUIDE.md`, его можно настроить:

```toml
project_doc_fallback_filenames = ["TEAM_GUIDE.md", ".agents.md"]
project_doc_max_bytes = 65536
```

Fallback действует только при отсутствии в том же каталоге файла с более высоким приоритетом. Прежде чем увеличивать ограничение, удалите повторы и несущественный фон, чтобы важные правила не вытеснялись из контекста.
