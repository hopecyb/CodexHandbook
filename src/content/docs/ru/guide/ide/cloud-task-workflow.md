Быстрые итерации из IDE можно выполнять локально, а более длительные задачи — делегировать в Cloud через подключение к Codex web. Точка входа остаётся в редакторе, но среда выполнения, состояние репозитория и сетевые границы уже становятся облачными.

## Когда делегировать задачу

| Оставить локально | Делегировать в Cloud |
|---|---|
| Нужны быстрые итерации с текущим выделением | В задаче много шагов и она долго выполняется |
| Задача зависит от незакоммиченного локального состояния | Входные данные уже находятся в удалённом репозитории или их можно загрузить |
| Нужны инструменты, доступные только на вашем компьютере | Зависимости и проверки можно воспроизвести в облачной среде |
| Вам нужно управлять процессом в реальном времени | Вы хотите продолжить другую работу локально |

Cloud не получает автоматически незакоммиченные локальные файлы, учётные данные или запущенные процессы. Перед делегированием явно укажите репозиторий, ветку и коммит, с которых начинается задача.

## Контрольный список перед делегированием

- [ ] Выполнен вход с учётной записью ChatGPT; Codex Cloud не поддерживает вход по API key
- [ ] Подключён GitHub или используется доступная сейчас Beta-интеграция с GitLab
- [ ] В облачной среде можно выполнить скрипты установки и проверки
- [ ] Необходимые переменные и secrets настроены в среде, а не записаны в промпте
- [ ] Незакоммиченные локальные изменения обработаны или явно исключены из задачи
- [ ] Чётко заданы цель, разрешённые пути, запретные области и команды приёмки

## Сквозной пример

```text
Цель: исправить ошибку, из-за которой модуль повторных попыток после достижения лимита всё равно ожидает ещё один раз.
Начальная точка: репозиторий acme/retry-service, ветка fix/retry-limit.
Область: изменять только src/retry.ts и соответствующие тесты.
Ограничения: не обновлять зависимости, не менять публичный API, не выполнять push в main.
Приёмка: выполнить pnpm test -- retry и pnpm typecheck; показать diff и результаты команд.
```

Рекомендуемый процесс:

1. В IDE приложите нужные файлы или выделение и сначала подтвердите границы проблемы;
2. Выберите Cloud для продолжения более длительной работы;
3. Следите в Cloud за планом, прогрессом и результатами проверок;
4. Вернитесь в IDE или Web и изучите результат, готовый для Review;
5. Получите изменения, загрузив ветку или через PR;
6. Перед слиянием повторно протестируйте код в доверенной локальной среде и проведите ручной Review.

Статус «завершено» в Cloud означает только окончание удалённого выполнения, а не готовность кода к слиянию. Зависимости, операционная система или учётные данные в удалённой среде могут отличаться от локальных и CI, поэтому расхождения среды всё ещё возможны.

## Конфликты и безопасность

- После делегирования не позволяйте локальной и облачной задачам одновременно менять один файл;
- Не вставляйте производственные ключи в промпт — используйте secrets среды;
- Не считайте сетевой доступ Cloud возможностью по умолчанию; настройте allowlist среды;
- Push, создание PR и слияние — разные действия; для слияния должен сохраняться контроль человеком или CI.
