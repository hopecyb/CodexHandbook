IDE удобно использовать, чтобы быстро прочитать сводку и сосредоточиться на diff рядом с исходным кодом. Но появление изменения в редакторе ещё не означает, что оно прошло приёмку. Сначала проверьте diff, затем запустите тесты и только после этого решайте, что сохранить.

## Выполните локальный Review

1. Прочитайте сводку результата, но не подменяйте ею diff;
2. Разверните changed lines и проверьте каждый затронутый файл;
3. Сохраните нужные правки, а для вышедших за границы потребуйте последующего исправления;
4. Выполните `/review` в поле ввода;
5. Выберите сравнение с базовой веткой или проверку незакоммиченных изменений;
6. Выполните тесты проекта и статические проверки в терминале IDE;
7. В конце снова проверьте состояние средствами Git.

Команда `/review` появляется, только если открытый проект находится в репозитории Git. Она сообщает о проблемах по приоритету и не изменяет Worktree. В IDE доступны варианты:

- **Review against a base branch**: сравнить текущую ветку с выбранной базовой;
- **Review uncommitted changes**: проверить изменения в текущем Worktree.

По умолчанию результат отображается в текущем чате. Задайте для `chatgpt.reviewDelivery` значение `detached`, чтобы открыть отдельный чат Review.

## Пример: явные критерии для reviewer

```text
Проверь текущие незакоммиченные изменения. В первую очередь найди дефекты, которые могут привести к неверному поведению, повреждению данных или проблемам безопасности.
Игнорируй чисто стилистические предпочтения. Для каждого замечания укажи точное место в файле, условие воспроизведения и проверяемое последствие.
Если проблем нет, перечисли оставшиеся пробелы в тестировании.
```

## Контрольный список приёмки

- [ ] Изменённые файлы соответствуют разрешённой области задачи
- [ ] Нет непреднамеренных удалений, форматирования целых файлов или чувствительных файлов
- [ ] Покрыты сценарии ошибок и граничные случаи
- [ ] Тесты, lint и проверка типов проходят согласно требованиям проекта
- [ ] Замечания reviewer с высоким приоритетом исправлены или риск явно принят
- [ ] Результаты `git diff --check` и `git status --short` не содержат проблем
