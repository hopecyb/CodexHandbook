В IDE Codex читает не только ваш промпт, но и автоматически получает **состояние редактора**. Это главное преимущество IDE перед CLI. Понимание источников контекста помогает избежать ситуации «файл открыт, но Codex его не увидел».

Codex в IDE учитывает не только текст вашего запроса, но и то, что вы сейчас просматриваете в редакторе.

## На этой странице

- Какой контекст IDE прикладывает автоматически
- Как он сочетается с файлами через `@`, выделением и `AGENTS.md`
- Как уменьшить шум и повысить точность результата

## Рекомендуемый процесс

1. **Откройте репозиторий от корня рабочей области**, а не только подпапку; исключения для monorepo ищите в документации команды
2. Перед локальным изменением **выделите нужный код**, затем опишите задачу → [Выделенный код и открытые файлы](/ru/guide/ide/selected-code-and-open-files/)
3. Для межмодульной задачи явно укажите ключевые файлы через `@`, а не рассчитывайте, что Codex найдёт их сам
4. В длительном сеансе периодически [сжимайте контекст](/ru/guide/context/compaction/) или открывайте новый поток

## Отличия от CLI

| | Расширение IDE | CLI |
|---|---|---|
| Осведомлённость о файлах | Высокая: открытый файл сразу становится частью контекста | Нужны `--cd` / `-C` и чтение с диска инструментами |
| Выделение | Поддерживается напрямую | Нужно вставить текст или указать путь |
| Лучше всего подходит для | Изменений на уровне строк, объяснения кода | Скриптов, CI, сред без GUI |

## Частые вопросы

### 1. Почему открытый файл всё равно изменён не так, как я хотел?

Открытый файл ещё не означает, что приоритетный фрагмент достаточно ясно обозначен.

Если область задачи остаётся расплывчатой, Codex может изучать другие связанные места или не определить самый важный для вас участок.

### 2. Чем больше открытых файлов, тем лучше?

Слишком много посторонних файлов создают шум и размывают главное.

### 3. Если IDE автоматически передаёт контекст, можно не уточнять задачу?

Автоматический контекст помогает, но не заменяет описание задачи.
Цель, ограничения и критерии завершения всё равно должны быть сформулированы явно.

Контекст IDE помогает, но не угадывает ваши намерения. Чем точнее область файлов, тем надёжнее результат.

## Чувствительная информация

Не оставляйте `.env` с ключами надолго открытым в редакторе; см. [Чувствительный контекст](/ru/guide/context/sensitive-context/).

Перед вставкой журналов или клиентских данных удаляйте чувствительные сведения: IDE не определяет соответствие требованиям за вас.

## Частые ошибки

- Ожидать, что `AGENTS.md` будет прочитан в режиме одного файла без рабочей области
- Открыть десятки крупных посторонних файлов и занять ими окно контекста
- Сказать только «эта функция», не выделив код и не указав файл через `@`

## Контрольный список

- [ ] Открыт правильный корень рабочей области
- [ ] Открыты или указаны через `@` 1–3 файла, относящиеся к задаче
- [ ] Команды тестирования из `AGENTS.md` совпадают с командами терминала IDE
