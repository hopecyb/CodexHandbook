Локальная задача в IDE следует замкнутому циклу «**открыть → выделить → описать → проверить → протестировать**» и хорошо подходит для частых небольших изменений. Ниже приведён самый типичный процесс; подробнее о контексте см. [Выделенный код и открытые файлы](/ru/guide/ide/selected-code-and-open-files/).

## Рекомендуемый процесс

1. **Откройте корень рабочей области** — весь репозиторий, а не отдельный файл
2. Откройте нужные файлы; при необходимости [выделите фрагмент кода](/ru/guide/ide/selected-code-and-open-files/)
3. На панели Codex явно укажите цель, ограничения и [критерии завершения](/ru/prompts/define-done/)
4. Для сложной задачи сначала [запросите план](/ru/prompts/ask-for-a-plan/), затем переходите к выполнению
5. [Проверьте изменения](/ru/guide/ide/reviewing-changes/) в представлении diff или inline
6. Выполните команды тестирования проекта в терминале IDE
7. Самостоятельно выполните `git commit`, если только команда явно не разрешила Agent создавать коммиты

## Пример промпта

```text
Изменяй только src/auth/login.ts и соответствующие тесты.
Цель: исправить ошибку 500 при отправке пустого адреса электронной почты, возвращая вместо неё 400 и сообщение об ошибке.
Запрещено: изменять package-lock, выполнять git push.
Завершение: выполни npm test -- auth и перечисли изменения.
```

## Когда выбрать другую точку входа

| Ситуация | Рекомендация |
|---|---|
| Несколько параллельных задач, Worktree | [Desktop App](/ru/guide/desktop-app/) |
| Скрипт или CI | [Неинтерактивный режим CLI](/ru/guide/cli/non-interactive-mode/) |
| Стандартизированная удалённая среда, создание PR | [Облачная задача из IDE](/ru/guide/ide/cloud-task-workflow/) |

## Частые ошибки

- Не открыть рабочую область, из-за чего `AGENTS.md` недоступен
- Принять все предложения inline одним нажатием
- Создать коммит без запуска тестов

## Частые вопросы

### 1. Почему так важно открыть корень рабочей области?

Значительная часть контекста расширения IDE зависит от того, открыт ли целый проект, а не одиночный файл.

### 2. Если в IDE так удобно вносить изменения, можно проверять их менее тщательно?

Нет.

Чем проще принять изменение, тем выше риск сделать это автоматически. Поэтому привычка к проверке становится ещё важнее.

### 3. Какая задача подходит для первого запуска?

Выберите задачу, которая:

- меняет только 1–2 файла;
- даёт очевидный результат;
- легко проверяется тестом или предпросмотром.

Локальные задачи в IDE удобны для быстрых небольших шагов, но удобство не отменяет Review и проверку.
