После завершения задачи Cloud предоставляет сводку и diff. Вы можете задать дополнительные вопросы, запросить изменения или создать PR. Завершение задачи не означает одобрения слияния: результат по-прежнему должен пройти CI проекта, защиту веток и оценку человеком.

## Два вида Review

| Тип | Что проверяется | Результат |
|---|---|---|
| Review результата Cloud | Сводка задачи, журналы и diff | Решение о продолжении работы или создании PR |
| GitHub Codex review | Diff PR подключённого репозитория и правила `AGENTS.md` | Публикация GitHub code review |

Оставьте в PR GitHub комментарий:

```text
@codex review
```

Codex опубликует замечания как обычный GitHub review. Согласно текущей официальной документации, комментарии в GitHub сосредоточены на проблемах высокого приоритета P0/P1; если проблем нет, может остаться только реакция. Небольшое число комментариев не отменяет ручной Review.

## Порядок проверки

1. **Область**: соответствуют ли задаче файлы, каталоги, зависимости и сгенерированные материалы;
2. **Поведение**: выполняются ли требования в штатных, ошибочных и граничных сценариях;
3. **Безопасность**: аутентификация, разрешения, обработка входных данных, учётные данные и исходящий сетевой трафик;
4. **Доказательства**: какие тесты действительно запускались и раскрыты ли сведения об ошибках;
5. **Возможность отката**: можно ли отменить изменение локально и не смешан ли с ним посторонний рефакторинг.

Пример промпта:

```text
Проверь этот PR и сообщай только о проблемах, которые приводят к неверному поведению, повреждению данных, уязвимостям или регрессии совместимости.
Для каждого замечания укажи серьёзность, точное место, условие воспроизведения и последствие.
Не считай стилистические предпочтения дефектами.
```

## Правила конкретного репозитория

Добавьте в применимый `AGENTS.md`:

```md
## Правила Code Review

### Границы аутентификации

- Отмечай любой путь, который записывает access token в журнал или отправляет его на хост вне allowlist.
  Безопасный путь: хранить token в поставщике учётных данных и удалять его из диагностического вывода.
```

Правила в корне применяются ко всему репозиторию, а вложенный `AGENTS.md` может добавлять более конкретные проверки для сервиса. Начните с двух-трёх устойчивых правил, описывающих безопасный путь, вместо длинного списка быстро устаревающих имён функций.

## Границы автоматического Review

Пользователь с необходимым разрешением GitHub push или admin может включить автоматические reviews репозитория в Codex Settings. Автоматический Review дополняет контроль, но не должен иметь разрешения на автоматическое слияние. Для репозиториев высокого риска по-прежнему нужны required reviewers, CI и защита веток.

## Контрольный список приёмки

- [ ] Человек прочитал основной логический diff
- [ ] Замечания P0/P1 исправлены или риск письменно принят
- [ ] CI пройден, повторные запуски после ошибок объяснимы
- [ ] Нет Secret, неожиданных сгенерированных материалов или постороннего обновления lock-файла
- [ ] Описание задачи, описание PR и фактические изменения соответствуют друг другу
