У переменных среды и Secrets в Cloud разные жизненные циклы. Это различие определяет, для чего их безопасно использовать, а не только то, скрывается ли значение в интерфейсе.

| Тип | Когда доступен | Подходящее содержимое |
|---|---|---|
| Переменная среды | На протяжении setup и Agent | Несекретная конфигурация: режим выполнения, публичный базовый адрес API |
| Secret | Только в setup script | Token частного пакета, учётные данные для установки зависимостей |

Secret дополнительно хранится в зашифрованном виде, расшифровывается только при выполнении задачи и удаляется до начала этапа Agent. Это не универсальный канал передачи Agent учётных данных для вызова production API во время выполнения.

## Правильный пример: установка частного пакета

Создайте в настройках среды Secret `NPM_TOKEN`. Setup script использует его для временной конфигурации аутентификации и установки зависимостей:

```bash
set -euo pipefail
printf '//registry.npmjs.org/:_authToken=%s\n' "$NPM_TOKEN" > ~/.npmrc
pnpm install --frozen-lockfile
rm -f ~/.npmrc
```

На этапе Agent token уже не нужен: используются установленные зависимости. В журнале setup запрещено выполнять `echo` для Secret.

## Неправильный пример

```text
Настроить производственный API_KEY как обычную переменную среды,
а затем попросить Agent проверить реальные заказы через curl к внешнему API.
```

В этом случае чувствительное значение доступно на всём этапе Agent и при открытой сети возникает риск утечки или ошибочной операции. Вместо этого используйте тестовые данные, mock, временные тестовые учётные данные с минимальными правами или ограничьте требующую аутентификации подготовку этапом setup.

## Проверка конфигурации

1. Перечислите значения, которые действительно нужны отдельно этапам setup и Agent;
2. Для чувствительных данных, используемых только при установке, применяйте Secret;
3. Для несекретных настроек, необходимых Agent, применяйте переменные среды;
4. Не записывайте значения в промпт, issue, PR, репозиторий или `AGENTS.md`;
5. Запустите secret scanner и проверьте журналы setup;
6. Регулярно заменяйте и удаляйте неиспользуемые учётные данные.

Setup выполняется в отдельном сеансе Bash, поэтому обычный `export` не переносится автоматически на этап Agent. Несекретное значение, которое должно быть доступно в течение всего чата, задавайте непосредственно как переменную среды, а не через временное состояние shell.

## Связь с CI

GitHub Actions Secrets и Codex Cloud Secrets — разные хранилища, которые не синхронизируются автоматически. Для удобства документации им можно дать одинаковые **имена**, но не следует копировать один производственный token с полномочиями шире, чем нужно задаче.

## Действия после утечки

Немедленно отзовите или замените учётные данные, затем удалите раскрытые значения из журналов, чатов, issue и истории Git. Одного удаления из текущего файла недостаточно, чтобы отозвать уже распространённый Secret.
