Среда Cloud определяет, что Codex устанавливает и запускает для конкретного репозитория. Она не наследует конфигурацию вашего ноутбука. Если локально всё работает, а в Cloud — нет, сначала сравните среду выполнения, зависимости, переменные и сеть.

## Порядок выполнения каждого чата

1. Создаётся контейнер и выполняется checkout выбранной ветки или commit SHA;
2. Запускается setup script; при повторном использовании кеша также может запускаться maintenance script;
3. Применяется политика доступа к интернету;
4. Agent в цикле выполняет команды, редактирование и проверки, читая применимые файлы `AGENTS.md`;
5. Возвращаются ответ и diff, после чего можно задать дополнительный вопрос или создать PR.

Образ `universal` по умолчанию содержит распространённые языки, пакеты и инструменты. В настройках среды можно зафиксировать версии Python, Node.js и других сред выполнения, а дополнительные зависимости установить через setup script.

## Минимальная воспроизводимая конфигурация

Для проекта pnpm сначала зафиксируйте в среде ту же версию Node.js, что используется в CI, затем добавьте:

```bash
corepack enable
pnpm install --frozen-lockfile
```

В корневом `AGENTS.md` репозитория укажите:

```md
## Проверка

- После изменения кода выполни `pnpm test`.
- Перед сообщением о завершении выполни `pnpm typecheck`.
- Не обновляй lock-файл, если изменение зависимостей не запрошено явно.
```

Этапы setup и Agent выполняются в разных сеансах Bash, поэтому временный `export` из setup автоматически не сохраняется. Несекретные значения следует задавать в настройках среды или сохранять в конфигурации shell согласно официальным рекомендациям.

## Кеш и maintenance

Cloud может кешировать состояние контейнера до 12 часов, ускоряя новые чаты и продолжение работы. После восстановления кеша выполняется checkout ветки, указанной для чата, и при необходимости запускается maintenance script для обновления зависимостей.

Изменение setup, maintenance, переменных среды или secrets автоматически сбрасывает кеш. Если он стал несовместим из-за изменений репозитория, вручную выберите **Reset cache**. В средах Business и Enterprise кеш может быть общим для пользователей с доступом к среде, поэтому сброс затронет и других участников рабочей области.

## Переменные среды и Secret

- Переменные среды доступны на этапах setup и Agent;
- Secret расшифровывается только на этапе setup и удаляется до запуска Agent;
- На этапе setup доступен интернет;
- На этапе Agent сеть по умолчанию отключена и включается отдельно для каждой среды.

Эти границы часто путают. Подробнее см. в следующей главе: [Secrets и переменные среды](/ru/guide/web-and-cloud/secrets-and-variables/).

## Контрольный список согласования среды

| Проверка | Цель |
|---|---|
| Начальная ветка/commit | Соответствует описанию задачи |
| Версия среды выполнения | Соответствует ограничениям CI или production |
| Lock-файл | Используется установка с зафиксированными версиями |
| Setup | Воспроизводим, неинтерактивен и останавливается при ошибке |
| Команды проверки | Записаны в `AGENTS.md` |
| Сеть | Для Agent открыты только необходимые домены и методы |
