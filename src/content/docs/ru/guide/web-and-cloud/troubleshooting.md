Повторный запуск в Cloud снова расходует время, но не добавляет автоматически недостающие разрешения, зависимости или сетевую конфигурацию. Сначала определите этап сбоя.

## Диагностика по пяти уровням

| Этап | Типичные симптомы | Первая точка проверки |
|---|---|---|
| Подключение репозитория | Репозитория нет в списке, 403, ветка не существует | Область авторизации GitHub, политика организации, начальная ветка |
| Контейнер/setup | `command not found`, ошибка установки зависимости | Зафиксированная среда выполнения, setup script, Secret |
| Сеть Agent | Setup загружает данные, но `curl` в Agent завершается ошибкой | Agent access по умолчанию Off, allowlist, методы HTTP |
| Выполнение Agent | Изменения ушли в сторону, команда теста не существует | Границы промпта, `AGENTS.md`, рабочий журнал |
| Доставка | Неполный diff, невозможно создать PR | Состояние ветки, разрешение на запись, правила защиты |

## Сначала сохраните доказательства

Запишите репозиторий, начальный commit, имя среды, этап сбоя, первую значимую ошибку и полную команду. Не ограничивайтесь последней строкой `exit 1`.

```text
Среда: api-node22
Начальная точка: main@abc123
Этап: setup
Команда: pnpm install --frozen-lockfile
Первая ошибка: ERR_PNPM_FETCH_401 ...
Локальное отличие: локально использовался ~/.npmrc, а в Cloud не настроен NPM_TOKEN
```

Такая запись сразу указывает на исправление, вместо того чтобы заставлять следующий запуск снова угадывать причину.

## Частые проблемы

### Secret доступен в setup, но пуст в Agent

Это предусмотренное поведение: Secret удаляется до этапа Agent. Перенесите использующую учётные данные установку в setup; не превращайте Secret в обычную переменную среды ради обхода защиты.

### Setup имеет доступ к сети, а Agent — нет

Это также поведение по умолчанию. Если сети требует сама задача Agent, включите её в среде, ограничьте домены и методы HTTP, а затем проверьте журнал.

### Из-за кеша используются старые зависимости

Изменение setup, maintenance, переменных или secrets автоматически сбрасывает кеш. Если он стал несовместим из-за изменений самого репозитория, выберите Reset cache на странице среды. Для общей командной среды сначала оцените влияние на других пользователей.

### Локально тесты проходят, в Cloud — нет

Сравните версии Node/Python, lock-файл, системные зависимости, скрытую локальную конфигурацию, сервисы VPN/localhost и пути с учётом регистра. Превратите различия в явный setup и правила репозитория.

### PR review не запускается

Убедитесь, что Cloud настроен для репозитория, Code review включён, комментарий имеет вид `@codex review`, а у интеграции GitHub есть нужные разрешения. Автоматические reviews включаются отдельно.

## Когда вернуться к локальной среде

Если проблема зависит от локального сервиса или два запуска подряд исправляют среду, а не прикладной код, сначала создайте минимальное локальное воспроизведение. Запишите рабочие команды, версии и тесты в `AGENTS.md`/setup, после чего снова делегируйте задачу в Cloud.

## Проверка после исправления

- [ ] Та же среда воспроизводимо запускается с чистой начальной точки
- [ ] Проблема не скрыта расширенными разрешениями репозитория или сетью unrestricted
- [ ] Журнал не раскрывает Secret
- [ ] Diff результата и тесты всё ещё проверены человеком
