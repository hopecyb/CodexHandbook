Codex Cloud выполняет задачи разработки в изолированной облачной среде. Он подходит для длительной фоновой работы, параллельных экспериментов и задач, запущенных из GitHub, GitLab (Beta), Linear или Slack. Это не «удалённое управление вашим компьютером», и локальные неотправленные файлы автоматически ему недоступны.

![Иллюстрация: репозиторий в браузере соединён с изолированным облачным контейнером, где выполняется задача; результат возвращается в виде карточки Pull Request с зелёной галочкой](/illustrations/web-and-cloud.webp)

## Этапы задачи Cloud

```text
Вход в ChatGPT
  → Подключение GitHub / GitLab
  → Создание среды репозитория
  → Checkout указанной ветки или commit
  → Установка зависимостей через setup script
  → Изменение и проверка Agent в рамках сетевой политики
  → Просмотр сводки, журналов и diff
  → Follow-up с изменениями или создание PR
  → Слияние после ручного Review и CI
```

Ценность Cloud заключается в изоляции, воспроизводимости и параллельной работе, а не в отмене Review.

## Локально или в Cloud

| Выбрать локальную среду | Выбрать Cloud |
|---|---|
| Задача зависит от незакоммиченных файлов или локальных сервисов | Входные данные уже находятся в удалённом репозитории |
| Нужно взаимодействовать с процессом в реальном времени | Задача может независимо выполняться в фоне |
| Быстрое небольшое изменение | Многоэтапная сборка, тестирование или параллельные эксперименты |
| Инструмент есть только на текущей машине | Среду можно воспроизвести скриптами |

Сначала прочитайте раздел [Локальная среда и Cloud](/ru/guide/foundations/local-vs-cloud/), чтобы понять границы выполнения.

## Рекомендуемый порядок изучения

1. [Подключение GitHub](/ru/guide/web-and-cloud/connect-github/): предоставьте доступ только к нужным репозиториям;
2. [Среды Cloud](/ru/guide/web-and-cloud/cloud-environments/): зафиксируйте инструменты, версии и setup;
3. [Secrets и переменные среды](/ru/guide/web-and-cloud/secrets-and-variables/): различайте Secret этапа установки и переменные времени выполнения;
4. [Доступ к интернету](/ru/guide/web-and-cloud/internet-access/): сеть для Agent по умолчанию отключена; открывайте только необходимые домены и методы;
5. [Делегирование и follow-up](/ru/guide/web-and-cloud/delegate-and-follow-up/): задавайте цель, ограничения и критерии приёмки;
6. [Создание Pull Request](/ru/guide/web-and-cloud/create-pull-requests/) и [Review кода](/ru/guide/web-and-cloud/code-review/): превращайте результат в материал, готовый к слиянию;
7. [Диагностика Cloud](/ru/guide/web-and-cloud/troubleshooting/): ищите проблему по уровням репозитория, setup, сети и задачи.

Если задача запускается из настольного приложения или IDE, см. соответственно [Локальные и облачные задачи](/ru/guide/desktop-app/local-and-cloud-tasks/) и [Облачные задачи из IDE](/ru/guide/ide/cloud-task-workflow/).

## Первое упражнение

Выберите тестовый репозиторий без производственных учётных данных и поручите Codex только исправить ссылки в документации и выполнить их проверку. Критерии успеха: среда запустилась, diff содержит только ожидаемые файлы, вывод команды доступен, а из результата можно создать PR. Не считайте один лишь статус «завершено» достаточной приёмкой.
