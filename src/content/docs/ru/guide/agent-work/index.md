Работа с Agent посвящена тому, как довести задачу **до завершённого состояния, которое можно проверить**. Когда сначала нужен план, когда стоит выделить подзадачи, как скорректировать курс по ходу работы и когда передавать или возобновлять задачу — всё это рассматривается в данной главе.

Речь здесь идёт о способе взаимодействия, а не об отдельной функции.

Сложность многих задач не в том, чтобы сформулировать требование, а в том, чтобы довести его до состояния «действительно завершено и поддаётся проверке».

## О чём эта глава

- Как свести сложную задачу к плану
- Как небольшими шагами скорректировать курс во время выполнения
- Какие части задачи имеет смысл поручать дочерним Agent
- Как передать и возобновить длительную прерванную задачу

## Полезная схема

Работу с Agent можно представить как четыре последовательных действия:

```text
Сначала понять → затем спланировать → корректировать курс при выполнении → передать работу или завершить её
```

Если пропустить один из этапов, обычно возникают такие последствия:

- Нет понимания: изменения направлены не туда
- Нет плана: потеря контроля над областью обнаруживается лишь в середине работы
- Нет корректировки: каждое следующее исправление ещё сильнее уводит от цели
- Нет передачи: после перерыва в длительной задаче никто не знает, на чём остановились

## Распространённые заблуждения

### 1. Работа с Agent сводится к более длинному промпту

Этого недостаточно.

На качество задачи влияют и другие факторы:

- Есть ли план
- Корректируется ли курс по ходу работы
- Выделены ли сложные части в отдельные подзадачи
- Сохранено ли состояние, с которого можно продолжить

### 2. Смена направления по ходу работы означает, что всё сделанное раньше было напрасно

Часто уточнять границы во время выполнения совершенно нормально. Необязательно делать вид, будто с первой попытки можно безошибочно сформулировать всё.

### 3. Чем больше дочерних Agent, тем выше эффективность

Не всегда.

Если границы не определены, рост числа подзадач лишь сильнее запутает основной тред.

## Начните с минимального процесса

Если вам достаточно базового процесса выполнения задачи, используйте четыре шага:

1. Чётко сформулируйте задачу
2. Для сложной задачи сначала запросите план
3. По ходу выполнения корректируйте курс небольшими шагами на основании результатов
4. Перед завершением потребуйте проверяемые доказательства результата

Освоив эти четыре шага, вам будет проще перейти к дочерним Agent и передаче работы.

В работе с Agent важнее всего, продолжает ли задача двигаться в нужном направлении на этапах планирования, выполнения, корректировки и завершения.

## Распространённые ошибки

- Использовать Agent как строку поиска и давать лишь расплывчатую цель
- Считать, что корректировка по ходу работы обязательно означает полный перезапуск
- Не оставлять никаких материалов для передачи длительной задачи
- Выделять подзадачи без границ, ещё сильнее запутывая основной тред
