**Codex Handbook** — сайт документации, который поддерживает сообщество. Мы приветствуем исправления, новые страницы, воспроизводимые кейсы и примеры промптов в каталоге [`examples/`](https://github.com/hopecyb/CodexHandbook/tree/main/examples).

## О чём эта страница

- Виды вклада и точки входа
- Стандарты написания и проверки
- Ожидания от PR и выпусков

## Что помогает больше всего

Если вы заметили:

- раздел, которому новичок не может следовать;
- пункт навигации с поверхностным содержанием;
- устаревшие команды, снимки экрана или объяснения,

— это уже важный сигнал для улучшения.

Не нужно сначала становиться экспертом в предметной области. Многие полезные правки появляются, когда читатель впервые замечает: «Здесь предполагается, что я уже знаю X».

## Виды вклада

| Вид | Описание | Руководство |
|---|---|---|
| Исправление / небольшая правка | Опечатка, ссылка, одно устаревшее предложение | Сразу откройте PR |
| Новая страница руководства | Содержимое главы в `src/content/docs/` | [Написать страницу руководства](/ru/guide/contributing/write-a-guide/) |
| Кейс | `src/content/docs/cases/` | [Шаблон кейса](/ru/cases/use-cases/case-study-template/) |
| Пример промпта | `examples/prompts/` | [Добавить пример промпта](/ru/guide/contributing/add-a-prompt-example/) |
| Техническая проверка | Установить `verified`, обновить даты | [Проверить техническое содержимое](/ru/guide/contributing/verify-technical-content/) |
| Перевод | `en/`, `zh-tw/` и другие локали | Этап M6 плана; сначала стабилизируйте источник |

## Распространённые заблуждения

### Участие в проекте ≠ написание целой главы

Полезным вкладом может быть:

- абзац, который помогает новичкам;
- исправление вводящей в заблуждение формулировки;
- недостающий пункт навигации;
- понижение статуса или датирование устаревшей команды.

### «Я не эксперт» ≠ «мой отзыв бесполезен»

Если среди аудитории есть новички, место, где вы застряли, — ценный сигнал. Сделайте его конкретным и улучшите текст, а не ограничивайтесь словом «непонятно».

## Основные принципы

1. **Корневые файлы на упрощённом китайском — источник**, если явно не указано обратное.
2. **Не копируйте** внешние руководства дословно; см. [план интеграции внешних источников](https://github.com/hopecyb/CodexHandbook/blob/main/docs/planning/external-source-integration.md).
3. Для **изменчивых фактов** нужны даты `Last verified`.
4. У новых страниц должны быть корректные frontmatter, пути к файлам и перекрёстные ссылки.
5. Боковые панели четырёх основных модулей формируются по каталогам. После добавления файла запустите сборку и проверьте порядок и точки входа.

## Путь первого вклада

1. Выберите реальную проблему, на которой вы застряли.
2. Определите тип изменения: правка текста, новая страница, пример или проверка устаревшей информации.
3. Измените один небольшой фрагмент и объясните контекст читателя.
4. Запустите сборку, чтобы структура сайта оставалась корректной.

Небольшие сфокусированные PR проверяются быстрее, чем переписывание целой главы.

## Локальная разработка

```bash
source ~/.nvm/nvm.sh && nvm use 22
pnpm install
pnpm dev
```

Перед слиянием:

```bash
pnpm build
```

## Кодекс поведения

- Уважайте работу других; обсуждайте идеи, а не людей.
- Не добавляйте реальные ключи и данные клиентов.
- Перед крупным рефакторингом создайте issue или RFC.

Первый вклад не обязан быть большим: достаточно прояснить одну реальную трудность новичка и успешно пройти сборку.
