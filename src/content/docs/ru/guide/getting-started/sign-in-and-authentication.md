Для использования моделей OpenAI в Codex предусмотрены два индивидуальных способа входа:

- **Вход через ChatGPT**: используется лимит подписки, а также наследуются разрешения рабочей области ChatGPT и политики данных.
- **Вход с API key**: оплата начисляется по объёму использования API, а политики данных и управления наследуются от API organization.

Локальная работа в настольном приложении ChatGPT, Codex CLI и интеграции с IDE поддерживает оба способа. **Codex Cloud требует входа через ChatGPT.**

## Вход через ChatGPT

Локальный клиент открывает браузер для авторизации, а затем возвращает учётные данные клиенту:

- Настольное приложение: на странице выхода выберите продолжение входа.
- CLI: выполните `codex login`.
- IDE: на странице выхода выберите вход через ChatGPT.

После входа проверьте активную учётную запись и рабочую область, особенно если у вас одновременно есть личное пространство и корпоративная рабочая область.

## Вход с API key

Создав key в OpenAI Platform, не записывайте его напрямую в историю команд. Для CLI используйте стандартный ввод:

```bash
printenv OPENAI_API_KEY | codex login --with-api-key
```

В настольном приложении выберите вход другим способом, а в IDE — «Use API Key». API key подходит для локальной работы и доверенного CI, но не предоставляет функции, зависящие от рабочей области ChatGPT или Cloud.

## Проверка учётной записи и выход из CLI

```bash
codex login status
codex logout
```

CLI и IDE совместно используют кешированные сведения о входе. После выхода в одном из них при следующем запуске другого тоже может потребоваться повторный вход.

## Безопасность учётных данных

- Не добавляйте `~/.codex/auth.json` в репозиторий и не вставляйте его содержимое в тикеты, чаты или журналы.
- По возможности используйте хранилище учётных данных операционной системы; token в файловом хранилище следует защищать как пароль.
- Для CI используйте отдельные отзываемые учётные данные, а не долговременный личный key.
- Codex Cloud напрямую обращается к репозиторию кода, поэтому включите MFA для учётной записи; при SSO администратор организации должен принудительно требовать MFA.
- Не переходите на личный key ради обхода ограничений организации; сначала проверьте рабочую область и управляемые политики.

## Вход выполнен, но продукт всё равно недоступен

Проверяйте в следующем порядке:

1. Правильно ли выбрана учётная запись или API organization.
2. Открыта ли нужная рабочая область ChatGPT.
3. Требует ли целевая функция входа через ChatGPT вместо API key.
4. Ограничивают ли доступ план, лицензия, роль или политика администратора.
5. Только после этого проверяйте кеш клиента, сеть и версию.

Для входа через CLI предусмотрены специальные журналы, которые могут понадобиться официальной поддержке или при устранении неполадок. Перед передачей журналы всё равно нужно проверить на конфиденциальные данные.

Границы планов описаны в разделе [Учётные записи, планы и доступ](/ru/guide/getting-started/account-plans-and-access/), а полные подробности — на [официальной странице Authentication](https://learn.chatgpt.com/docs/auth).
