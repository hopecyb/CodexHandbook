# Codex Pet 설치하기

Codex Pet 설치의 본질은 클라이언트가 읽을 수 있는 리소스 패키지를 약속된 폴더에 두는 것입니다. 클라이언트가 시작되거나 설정을 새로고침할 때 이 폴더를 읽고, 메타데이터를 찾은 뒤 해당 애니메이션 애셋을 로드합니다.

<PetScienceFigure variant="install" locale="ko" />

Pet은 보통 최소 두 파일을 가진 로컬 폴더입니다.

```text
~/.codex/pets/<pet-id>/
  pet.json
  spritesheet.webp
```

`pet.json`은 펫 이름, 설명, spritesheet 경로를 설명합니다. `spritesheet.webp`는 애니메이션 프레임을 저장합니다. 두 파일은 보통 같은 펫 폴더에 있으며, `pet.json`의 `spritesheetPath`는 실제 파일을 가리켜야 합니다.

## 설치 흐름의 논리

1. 패키지 받기: 최소한 `pet.json`과 spritesheet가 포함되어 있는지 확인합니다.
2. Pets 폴더에 넣기: 일반적인 위치는 `~/.codex/pets/<pet-id>/`입니다.
3. 클라이언트가 다시 읽게 하기: Codex를 재시작하거나 Pets 설정을 새로고침합니다.
4. UI에서 선택하기: 보통 Settings -> Appearance -> Pets에 있습니다.

Windows에서는 보통 사용자 디렉터리 아래 `.codex\pets\<pet-id>\`를 사용합니다. `CODEX_HOME`을 설정했다면 현재 클라이언트가 표시하는 Pets 폴더를 기준으로 하세요.

## 설치가 자주 실패하는 이유

설치 후 보이지 않으면 다음을 확인합니다.

- 폴더 이름과 `pet.json`의 `id`가 일치하는지.
- `spritesheetPath`가 `spritesheet.webp` 같은 상대 경로인지.
- spritesheet가 실제로 같은 폴더에 있는지.
- Codex를 재시작했거나 Pets 설정을 새로고침했는지.
- Windows, WSL, 사용자 지정 `CODEX_HOME`이 다른 디렉터리를 가리키지 않는지.

대부분의 실패는 펫 자체가 망가진 것이 아니라 클라이언트가 예상 위치에서 완전한 리소스 묶음을 찾지 못한 경우입니다.

## 업데이트와 삭제

업데이트 전에는 기존 폴더를 백업하세요. 새 패키지가 동작하는 것을 확인한 뒤 `pet.json`과 spritesheet를 교체합니다.

삭제할 때는 `~/.codex/pets/<pet-id>/` 폴더를 지운 뒤 Codex를 재시작하거나 Pets 설정을 새로고침합니다.

## 안전 주의

출처가 불분명한 원격 shell 명령을 바로 실행하지 마세요. 설치 스크립트는 로컬 파일을 쓰거나 추가 명령을 실행할 수 있습니다. 더 안전한 방식은 패키지를 내려받고, `pet.json`을 확인하고, 소재 출처와 라이선스를 검토한 뒤 수동으로 Pets 폴더에 복사하는 것입니다.

설치를 “로컬 리소스 패키지 복사”로 이해하면 경계가 분명해집니다. 리소스 파일은 확인할 수 있고, 스크립트 동작은 검토해야 하며, 출처와 라이선스는 보존해야 합니다.
