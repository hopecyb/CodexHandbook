# Codex Pet 만들기

Codex Pet을 만드는 목표는 단순히 예쁜 이미지를 얻는 것이 아닙니다. Codex가 식별하고, 로드하고, 재생하고, 상태를 전환할 수 있는 리소스 패키지를 만드는 것입니다. “메타데이터 + 애니메이션 아틀라스 + 출처와 라이선스 설명”의 조합으로 생각하면 됩니다.

<PetScienceFigure variant="spritesheet" locale="ko" />

최소 구조는 보통 다음과 같습니다.

```text
<pet-id>/
  pet.json
  spritesheet.webp
```

## spritesheet란 무엇인가

Spritesheet는 여러 애니메이션 프레임을 하나의 큰 이미지로 합치는 방식입니다. 클라이언트는 수십 개의 작은 파일을 로드하지 않고, 큰 이미지에서 행과 열 좌표로 각 프레임을 잘라 순서대로 재생합니다.

많은 Codex Pet 리소스는 다음 atlas 규약을 사용합니다.

- 8열 x 9행
- 프레임당 192 x 208 px
- 전체 이미지 1536 x 1872 px
- 72프레임
- WebP 또는 출처 도구가 명시적으로 지원하는 이미지 형식

이 값들은 일반적인 규약일 뿐 영구적인 규칙은 아닙니다. 만들기 전에 현재 Codex 클라이언트, 생성 도구, 리소스 출처가 사용하는 실제 계약을 확인하세요.

## 애셋 준비

좋은 소재는 보통 다음 조건을 만족합니다.

- 캐릭터 윤곽이 뚜렷하고 배경을 깨끗하게 제거할 수 있습니다.
- 각 동작의 비율, 시점, 기준선이 일관됩니다.
- 투명 배경에 색 번짐, 잔상, 불필요한 픽셀이 없습니다.
- 재생 중 잘리지 않도록 가장자리에 붙지 않습니다.
- 작업, 대기, 완료, 실패, 이동, 유휴 상태 등에 대응할 수 있습니다.

소재가 팬 창작, 게임, 애니메이션, 브랜드, 타인 작품에서 왔다면 먼저 출처와 라이선스를 확인하세요. 허가받지 않은 소재를 상업적으로 사용할 수 있는 리소스로 설명하지 마세요.

## `pet.json`의 역할

`pet.json`은 최소한 펫의 ID와 spritesheet 경로를 설명해야 합니다. 최소 예시는 다음과 같습니다.

```json
{
  "id": "my-pet",
  "displayName": "My Pet",
  "description": "A focused companion for Codex sessions.",
  "spritesheetPath": "spritesheet.webp"
}
```

권장 사항:

- `id`는 소문자, 숫자, 하이픈을 사용합니다.
- 폴더 이름과 `id`를 일치시킵니다.
- `spritesheetPath`는 상대 경로를 사용합니다.
- `description`에는 펫이 무엇인지 분명히 씁니다.
- 추가 메타데이터에 작성자, 버전, 출처, 라이선스를 남깁니다.

`pet.json`은 애니메이션 자체를 저장하지 않습니다. 클라이언트에게 “이 패키지가 누구인지, 소재가 어디 있는지, 어떻게 해석해야 하는지” 알려줍니다.

## 로컬 점검

공개하거나 공유하기 전에 최소한 다음을 확인합니다.

- `pet.json`이 유효한 JSON입니다.
- `spritesheetPath`가 존재하는 파일을 가리킵니다.
- spritesheet 크기와 프레임 그리드가 현재 계약에 맞습니다.
- 각 행의 애니메이션이 크게 튀거나 밀리거나 잘리지 않습니다.
- 투명 배경이 깨끗합니다.
- 패키지에 임시 파일, 원본 이미지, 공개하면 안 되는 소재가 없습니다.

## 라이선스와 출처

펫 소재는 팬 창작, 스크린샷, AI 생성 이미지, 공개 이미지 라이브러리, 타인 작품에서 올 수 있습니다. 만들 때는 다음을 구분하세요.

- 개인적으로 사용할 수 있는지.
- 공개적으로 공유할 수 있는지.
- 다른 사람의 재배포를 허용할 수 있는지.
- 출처 표시나 링크 보존이 필요한지.

원본 작업 파일과 출처 기록을 보관하면 이후 테두리 수정, 동작 변경, 크기 조정, 라이선스 설명 보완이 쉬워집니다.
