CI는 **프로세스 종료 코드**로 단계 성패를 판단합니다. 이 장은 [codex exec](/guide/developer-platform/non-interactive/codex-exec/)의 흔한 의미, 재시도 전략, 멱등 설계를 설명합니다.

## 이 페이지 내용

- 종료 코드와 업무상 「리뷰 미통과」의 차이
- 429/네트워크류 오류를 재시도할지
- 중복 실행의 부작용을 피하는 방법

## 종료 코드가 알려 주는 것

이런 내용을 처음 본다면, “종료 코드”를 작업이 끝난 뒤 프로그램이 스크립트와 CI에 남기는 짧은 결과로 이해하면 됩니다.

보통 길게 설명하지 않고, 파이프라인에 이것만 알립니다.

- 이번은 성공
- 아니면 실패

“재시도”는 다른 질문에 답합니다. 이번 실패를 즉시 멈출지, 한 번 더 기회를 줄지입니다.

:::note
구체 종료 코드 표는 공식 CLI 문서를 기준으로 합니다. 아래 표는 통합 시의 **설계 원칙**입니다.
:::

## 흔한 오해

### 실패는 한 종류가 아닙니다

많은 초보자가 모든 비 `0`을 같은 실패로 이해합니다.

실제로는 최소한 다음을 구분해야 합니다.

- 작업 자체가 깨짐
- 정책이나 샌드박스가 막음
- 외부 서비스가 일시적으로 불안정함
- 실행은 성공했지만 리뷰 결론이 “미통과”

처리 방식이 다르므로, 전부 재시도로 다루면 안 됩니다.

### “자동 재시도”가 곧 더 안정적인 것은 아닙니다

실패 원인이 재시도로 사라지지 않는다면——권한 부족, 규칙 차단, 프롬프트 문제 등——재시도는 시간과 쿼터만 반복 낭비합니다.

## 권장 의미(개념)

| 상황 | 권장 처리 |
|---|---|
| `0` | 작업 완료 + 프롬프트의 성공 기준 충족 |
| 비 `0`이고 로그에 policy/sandbox 거부 | **맹목 재시도하지 말고** 설정이나 프롬프트를 고침 |
| 비 `0`이고 API 429/5xx | 제한된 횟수의 지수 백오프 재시도 |
| P0 문제를 찾았지만 실행은 성공 | [구조화 출력](/guide/developer-platform/non-interactive/structured-output/)의 `pass: false` + 스크립트 `exit 1` |

「보안 문제를 발견했다」는 크래시성 예외에 의존하지 말고, JSON에 `pass: false`를 **명시**하고 래퍼 스크립트가 종료 코드를 결정하게 하세요.

## 재시도 템플릿(bash)

```bash
max=3
delay=10
for i in $(seq 1 $max); do
  if codex exec --cwd . "$(cat "$PROMPT")"; then
    exit 0
  fi
  code=$?
  if [ "$code" -eq 2 ]; then
    echo "Policy error, not retrying" >&2
    exit "$code"
  fi
  sleep $((delay * i))
done
exit 1
```

「재시도 불가」 코드를 공식 문서와 맞춘 뒤 `case` 분기에 넣으세요.

## 멱등과 부작용

| 위험 | 완화 |
|---|---|
| 중복 PR 댓글 | check run id 또는 「이미 bot 댓글이 있으면 갱신」 |
| 중복 파일 쓰기 | exec 기본은 읽기 전용 리뷰；쓰기는 별도 job + 사람 게이트 |
| 중복 알림 | 알림 webhook에 dedupe key |

## 헷갈릴 때 판단하는 법

어떤 실패를 재시도할지 모르겠다면, 먼저 스스로에게 물어보세요.

1. 이 오류가 일시적인 외부 흔들림처럼 보이는가
2. 다시 돌려도 중복 댓글·중복 쓰기·중복 알림이 날 수 있는가
3. 실패 원인이 사실 사람이 설정·프롬프트·권한을 고쳐야 하는가

1번에 가까우면 제한된 재시도가 맞고, 2·3번에 가까우면 멈춰서 근본 원인을 처리하는 편이 맞습니다.

## 흔한 실수

- 종료 코드를 무시하고 CI가 항상 green
- 정책 오류를 무한 재시도해 쿼터를 태움
- 재시도 시 프롬프트/git sha를 고정하지 않아 결과를 비교할 수 없음

“일시 장애인가, 재시도해도 나아지지 않는가”를 먼저 가른 뒤 재시도 여부를 정하세요. 모든 실패를 다시 돌릴 가치는 없습니다.

## 검수 체크리스트

- [ ] CI가 비 0 종료 코드에서 실패
- [ ] 재시도 횟수와 백오프에 상한이 있음
- [ ] 리뷰 「미통과」와 「실행 크래시」를 구분할 수 있음
- [ ] 로그에 충분한 장애 분석 정보가 남음
