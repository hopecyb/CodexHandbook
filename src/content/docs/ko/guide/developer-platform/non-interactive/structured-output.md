처음 자동화할 때 Codex가 “그럴듯한 문장”을 쓰게 두는 경우가 많습니다. 사람이 읽기에는 괜찮지만, 스크립트에는 불친절합니다.

구조화 출력이 푸는 문제는 단순합니다. Codex가 정해 둔 형식으로 결과를 돌려주게 하는 것입니다.

비대화형 작업이 자유 텍스트만 내면, 다운스트림이 “통과인가 실패인가”, “문제가 몇 개인가”, “심각도는 무엇인가”를 자동으로 판단하기 어렵습니다. 구조화 출력은 결과를 기계가 이어 처리하기 쉽게 만듭니다.

## 이 페이지 내용

- JSON / Markdown 표 / 고정 필드를 언제 요구할지
- 프롬프트에서 schema를 어떻게 정의할지
- 파싱 실패 시 폴백 전략

## 흔한 오해

### 구조화 출력은 다음 단계가 받을 수 있게 하려는 것입니다

JSON, schema 같은 말을 엔지니어링 강박으로 이해하기 쉽습니다.

더 현실적인 이유는, 다음 단계가 스크립트로 성패를 판단하고, 봇이 댓글을 달고, 대시보드가 결과를 보여야 한다면, 안정된 형식이 필요하고 프로그램이 매번 의미를 추측하게 두면 안 되기 때문입니다.

### 형식이 안정하다고 결론이 신뢰할 만한 것은 아닙니다

구조화 출력은 “요구한 모양처럼 보이게”만 보장합니다. 작업을 올바르게 이해했는지는 자동으로 보장하지 않습니다.

출력 인터페이스 문제를 푸는 데 맞으며, 작업 정의와 결과 검증을 대체하지 않습니다.

## 직접적인 구분

- 자유 텍스트：사람이 읽기에 적합
- 구조화 출력：프로그램이 읽기에 적합

다음 단계가 `jq`, 스크립트, 대시보드, 게이트 규칙, 자동 댓글 봇이라면, 자유로운 자연어에만 의존하면 안 됩니다.

## 최소 사용법

프롬프트 끝에 형식 요구를 고정하세요.

```text
…(작업 본문)…

출력 요구：
- JSON 객체 하나만 출력하고, markdown 코드 펜스는 쓰지 마세요
- 필드：{"pass": boolean, "findings": [{"severity":"P0|P1|P2", "file":"", "message":""}]}
- 문제가 없으면 findings는 빈 배열
```

Shell 파싱(예시):

```bash
result=$(codex exec --cwd . "$(cat prompts/structured-review.md)")
echo "$result" | jq -e '.pass == true'
```

## 흔한 함정

### 1. “JSON을 출력하라”만 말하고 “JSON만 출력하라”고는 안 함

모델이 앞에 설명을 붙인 뒤 JSON을 주면 파싱이 깨집니다.

### 2. 오늘 필드명, 내일 다른 필드명

스크립트가 특정 필드에 의존하면 schema를 인터페이스처럼 유지해야 합니다. 마음대로 바꾸면 안 됩니다.

### 3. 구조화 출력이 모든 모호함을 해결하길 기대함

풀 수 있는 것은 “형식 안정”입니다. 작업 자체가 불명확하면 JSON도 안정적으로 애매한 결과만 냅니다.

## 권장 워크플로

```text
schema 정의(버전 v1)
    → 프롬프트가 schema 파일 @schemas/review-output.json 참조
    → exec 실행
    → jq / 커스텀 validator 검증
    → 통과하지 않으면 exit 1
```

큰 출력은 파일 경로 필드를 요구하고, Agent가 `artifacts/`에 쓰게 한 뒤 CI가 artifact를 업로드하게 할 수 있습니다.

## 어떻게 판단할까

결과가 “다음 프로그램”에 소비되어야 하면 되도록 구조화하세요.  
주로 사람이 읽고 토론한다면 자유 텍스트가 보통 더 자연스럽습니다.

결과가 프로그램에 이어져야 한다면, Codex가 약속한 필드로 안정적으로 돌려주게 하세요.

## 흔한 실수

- 모델 출력에 설명 문장이 섞여 JSON 파싱 실패——프롬프트에서 「JSON만」을 강조
- Schema 변경 후 버전을 올리지 않아 옛 CI가 잘못 파싱
- 키를 JSON 필드에 넣어 로그로 되돌림
- 파싱 실패에 대한 명확한 종료 동작이 없음

## 검수 체크리스트

- [ ] schema 파일 또는 문서화된 필드가 있음
- [ ] CI가 파싱 실패를 명시적으로 실패 처리
- [ ] 샘플 출력을 `fixtures/`에 두어 회귀용으로 사용
- [ ] [종료 코드](/guide/developer-platform/non-interactive/exit-codes-and-retries/) 전략과 일치
