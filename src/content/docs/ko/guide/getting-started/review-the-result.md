작업을 마친 뒤 많은 초보자가 이 단계를 건너뜁니다.

Codex를 더 안정적으로 쓰려면 **결과를 확인**할 줄 알아야 합니다.

「완료했다」는 말만 보지 말고, 무엇을 바꿨는지, 결과가 원하는 것인지 보세요.

## 확인 체크리스트

1. **diff 보기**: 허용한 파일만 고쳤는지?
2. **산출물 열기**: 내용이 수락 기준에 맞는지?
3. **이어서 수정**: 조금만 모자라면 정밀한 피드백을 이어 줌
4. **결정**: 수락 / 수동 수정 / [실행 취소](/guide/getting-started/undo-and-recover/)

더 많은 방법: [diff 검토](/guide/quality/review-diffs/).

## 흔한 놓침

### 1. 요약만 보고 실제 변경은 안 봄

Codex가 요약을 매끄럽게 써도, 진짜로 중요한 것은:

- 잘못된 파일을 고치지 않았는지
- 승인하지 않은 곳을 슬쩍 고치지 않았는지
- 결과가 수락 조건을 정말 충족하는지

### 2. 「대충 비슷」하면 바로 수락

「대충 비슷」은 뒤에 작은 함정을 남기기 쉽습니다.  
조금만 모자라면 정밀한 피드백 한 줄을 더하는 편이 낫고, 혼자 참고 넘기지 마세요.

### 3. 틀렸는데 어떻게 말할지 모름

이런 문장으로 이어가면 됩니다.

```text
거의 맞았습니다. 다만 두 가지가 남았습니다. 1)…… 2)…… 이 두 가지만 고치고, 다른 곳은 건드리지 마세요.
```

## 확인 순서

첫 연습에서는 이 순서로:

1. **범위**: 어떤 파일을 고쳤는지
2. **결과**: 페이지·문서·코드 출력이 요구에 맞는지
3. **부작용**: 여분 변경이나 새 오류를 넣지 않았는지

수락할 때는, 이번 결과를 안심하고 받을 수 있는지가 핵심입니다.
