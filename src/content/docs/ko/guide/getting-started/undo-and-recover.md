Codex를 처음 쓸 때 많은 사람이 가장 걱정하는 것은: 잘못 고치면 돌아갈 수 있는가?

대부분의 경우 가능하지만, 안전한 방법으로 되돌리는 편이 좋습니다.

결과가 범위를 넘거나 품질이 안 되면:

1. 클라이언트가 제공하는 실행 취소 / 변경 복원 기능을 씁니다(현재 UI 기준)
2. 프로젝트가 Git 아래라면: 익숙한 방식으로 작업 공간 변경을 버립니다(초보자는 먼저 Git 없이 연습 디렉터리에 의존해도 됩니다)
3. 새 스레드를 열고, 제약을 조인 뒤 다시 시도합니다

많은 경우, 범위를 미리 좁혀 두면 더 수월합니다. 예: 파일 소수만, 금지 항목을 분명히, 계획을 본 뒤 실행.

## 「실행 취소」와 「복구」 구분

- **실행 취소**: 방금의 마음에 안 드는 변경을 되돌림
- **복구**: 프로젝트를 안전하다고 확인한 상태로 되돌림

작은 파일 하나 연습이면 실행 취소는 보통 어렵지 않습니다. 더 까다로운 경우는:

- 파일을 둘 이상 고침
- 당신이 나중에 수동으로도 고침
- 어디가 누가 고쳤는지 기억나지 않음

먼저 추가 수정을 멈추고, 영향 범위를 좁히세요.

## 처음에 잘못했을 때의 처리 순서

1. 먼저 추가 수정을 멈추고, 당황한 채 더 고치게 하지 마세요
2. 어떤 파일을 고쳤는지 먼저 확인
3. 제품의 실행 취소를 쓸 수 있으면 우선 사용
4. 원래 Git 아래라면, 익숙한 Git 방법으로 되돌림
5. 안전 상태로 돌아간 뒤, 더 분명한 지시를 다시 냄

## Git에 익숙하지 않다면

많은 초보자가 「복구」라는 말에 겁을 먹고, Git 명령을 많이 알아야 한다고 생각합니다. 처음에는 그럴 필요 없습니다.

이렇게 하세요.

- 연습 디렉터리에서 연습
- 한 번에 작은 파일 하나만 고치게
- 결과가 마음에 안 들면 바로 실행 취소

정식 프로젝트를 다룰 때 Git 되돌리기를 체계적으로 배우면 됩니다.

## 예방이 보완보다 중요합니다

아래를 하면 「고친 뒤 수습하기 어렵다」는 확률이 분명히 줄어듭니다.

- 「어느 파일만」을 분명히 씀
- 먼저 계획을 받고 나서 실행
- 한 단계마다 확인하고, 변경을 쌓아 두지 않음
- 고위험 작업 전에 확인

틀린 것 자체는 무섭지 않습니다. 변경 범위를 보지 않고 계속 고치는 일이 더 번거롭습니다.
