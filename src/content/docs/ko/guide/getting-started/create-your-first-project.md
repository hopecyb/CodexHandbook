첫 연습 프로젝트를 만들 때, 손에 있는 정식 프로젝트로 바로 시험하고 싶어지기 쉽습니다. 편해 보이지만 위험도 더 큽니다.


## 권장 방법

1. 폴더를 새로 만듭니다. 예: `codex-practice/`
2. 민감 정보가 없는 텍스트 파일 1–2개를 넣습니다. 예: `hello.md`
3. Codex에서 해당 폴더를 열거나 프로젝트로 추가합니다
4. 프로덕션 키·고객 데이터·버릴 수 없는 이력이 있는 저장소는 **쓰지 마세요**

## 왜 연습 프로젝트를 먼저 만드나

첫 작업의 목표는 흐름을 익히는 것이지, 비즈니스를 인도하는 것이 아닙니다. 격리하면 오수정 비용이 훨씬 낮아집니다.

첫 연습에서 더 중요한 것은 이 동작을 익히는 일입니다.

- 작업을 어떻게 이해하는지
- 언제 권한을 요청하는지
- 결과를 어떻게 확인하는지
- 잘못했을 때 어떻게 철회하는지

처음부터 정식 프로젝트에서 연습하면, 저위험으로 배워야 할 단계에 실제 대가가 붙습니다.

## 흔한 오해

### 1. 연습 프로젝트는 실제 프로덕션과 닮을수록 좋다

처음에는 안전·버릴 수 있음·확인하기 쉬움이 더 중요합니다. 「완전 실제」를 쫓을 필요는 없습니다.

### 2. 조심만 하면 정식 저장소를 써도 된다

처음에 더 흔한 문제는:

- 작업 경계를 분명히 말하지 않음
- diff를 놓침
- 이해하지 못한 작업을 승인함

### 3. 연습 프로젝트가 너무 단순하면 배울 것이 없다

첫 작업이 작을수록, 비즈니스 복잡도보다 흐름 자체에 주의를 두기 쉽습니다.

## 연습 프로젝트를 고르는 법

지금 바로 만든다면 적어도 이 4가지를 만족하세요.

1. 버릴 수 있음
2. 민감 데이터 없음
3. 파일이 적고 구조가 단순함
4. 변경을 한눈에 이해할 수 있음

첫 연습 프로젝트는 프로덕션과 닮을 필요가 없습니다. 안전하고 단순하며, 잘못해도 되돌리기 쉬우면 됩니다.
