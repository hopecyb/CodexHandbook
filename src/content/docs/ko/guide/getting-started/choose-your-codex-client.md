처음 `App / CLI / IDE / Cloud`를 보면 흔한 질문은 「도대체 무엇을 쓸까」입니다.

첫 선택을 너무 무겁게 생각할 필요는 없습니다. 시작하기 쉬운 입구부터 쓰고, 나중에 나머지를 보완하면 됩니다.

## 바로 고르기

지금 강한 선호가 없다면:

- **처음 사용**: 데스크톱 App
- **원래 터미널을 매일 씀**: CLI
- **주로 VS Code / JetBrains에서 코드를 씀**: IDE 확장
- **GitHub 클라우드 저장소 연결이나 장기 작업이 이미 분명함**: Cloud를 보세요

## 각 입구가 무엇인가

| 입구 | 바로 이렇게 이해하면 |
|---|---|
| 데스크톱 App | 그래픽 콘솔. 작업·diff·승인 누르기에 적합 |
| CLI | 터미널 안의 Codex. 커맨드라인 사용자에게 적합 |
| IDE 확장 | 편집기에 끼워 넣은 조수. 코드를 보며 고치기에 적합 |
| Cloud | 원격으로 작업을 돌리는 방식. 저장소 협업·장기 작업에 적합 |

## 현재 상황에 맞춰 고르기

| 당신이… | 고르기 |
|---|---|
| 처음이고, diff와 검토를 분명히 보고 싶음 | **데스크톱 App** |
| 터미널이 익숙하고 스크립트를 씀 | **CLI** |
| 주로 편집기에서 코드를 고침 | **IDE 확장** |
| GitHub 클라우드 환경 / 장기 작업이 필요 | **Cloud**(먼저 개요를 읽으세요) |

## 데스크톱 App이 흔한 시작점인 이유

초보자에게 데스크톱 App의 분명한 이점:

- 무엇을 했는지 보기 쉽습니다
- 언제 권한을 요청하는지 한눈에 보입니다
- diff·작업·프로젝트 개념이 더 직관적입니다
- 오류가 나도 멈춰 확인하기 쉽습니다

터미널을 분명히 선호하지 않는다면, 데스크톱 App이 더 수월한 경우가 많습니다.

## 흔한 오해

### 1. 네 입구는 완전히 다른 네 제품이다

같은 능력 세트를 쓰며, 차이는 주로 조작 방식과 적합 장면입니다.

### 2. 처음 한 번에 맞게 고르지 않으면 나중에 아주 번거롭다

첫 선택은 시작점일 뿐, 평생 결정이 아닙니다.

### 3. 이후에는 입구 하나만 고정해야 한다

많은 사람이 나중에 이렇게 조합합니다.

- 평소에는 데스크톱 App으로 작업과 변경 검토
- 일괄 작업이 필요하면 CLI
- 주로 코드를 쓸 때는 IDE 확장

## 시작 순서

1. 먼저 [데스크톱 App](/guide/getting-started/install-desktop-app/)을 설치합니다
2. [첫 작업](/guide/getting-started/run-your-first-task/)을 한 번 돌립니다
3. 익숙해진 뒤 CLI나 IDE를 고려합니다

전체 대조: [기능 비교](/guide/reference/feature-comparison/). 여러 클라이언트를 설치해도 됩니다. **연습 프로젝트는 같은 디렉터리를 유지**하면 경험을 대조하기 쉽습니다.

처음에는 「어느 쪽이 더 전문적인가」를 급히 비교하지 마세요. 과정과 결과를 가장 이해하기 쉬운 입구부터 고르면 됩니다.
