막 설치했고 첫날 어떻게 시작할지 모르겠다면, 이 경로를 따르세요.

처음 30분의 목표는 첫 루프를 끝까지 도는 것입니다.

| 시간 | 할 일 |
|---|---|
| 0–5분 | [안전 체크리스트](/guide/getting-started/beginner-safety-checklist/) 읽기 |
| 5–10분 | [데스크톱 App 설치](/guide/getting-started/install-desktop-app/) 및 [로그인](/guide/getting-started/sign-in-and-authentication/) |
| 10–15분 | [연습 프로젝트 만들기](/guide/getting-started/create-your-first-project/) |
| 15–25분 | [첫 작업 실행](/guide/getting-started/run-your-first-task/) 및 확인 |
| 25–30분 | [Codex와 대화하기](/guide/learning-paths/beginner/01-talk-to-codex/)를 열어 초보자 경로로 |

## 이 30분에서 끝낼 것

반 시간에 모든 기능을 배울 필요는 없습니다. 이 체인만 통하면 됩니다.

- 제품에 들어갈 수 있음
- Codex가 실제 디렉터리에 대해 일할 수 있음
- 결과를 볼 수 있음
- 결과를 수락할 가치가 있는지 판단할 수 있음

이 체인이 통하면 CLI·IDE·Cloud·Skill·자동화를 배우기가 수월해집니다.

## 각 구간에서 끝낼 것

### 0에서 5분

개념을 외울 필요 없이 이것만 알면 됩니다.

- 프로덕션 저장소로 바로 연습하지 않기
- 철회 가능한 실험 환경 준비
- 결과는 스스로 확인

### 5에서 10분

설정을 많이 파지 말고, 제품에 정상 진입하고 로그인부터 하세요.

### 10에서 15분

완전한 프로젝트를 급히 만들지 말고, 변경을 관찰하기 쉬운 작은 디렉터리부터 준비하세요.

### 15에서 25분

여기서 확인할 것:

- 작업을 실제로 실행했는지
- 결과를 이해할 수 있는지
- 이어서 묻거나·수정하거나·철회할 곳을 아는지

### 25에서 30분

「첫 성공」을 이후 학습 경로에 이어, 한 번만 쓰고 멈추지 않게 합니다.

## 흔한 오해와 막힘

### 1. 첫 작업을 너무 크게 고름

처음에는 아주 작은 일이 좋습니다. 예를 들어:

- 문장 일부 수정
- 작은 페이지 하나 추가
- 위치를 이미 아는 작은 문제 수정

처음부터 「프로젝트 전체 리팩터」를 시키지 마세요.

### 2. 개념 연구에만 시간을 쓰고 실제로 손을 안 댐

이해도 중요하지만, 초보자에게는 「정말 써 봤다」는 경험이 더 중요합니다.

### 3. 결과를 보고 바로 끝내고 재확인을 안 함

처음 30분에 더 들일 습관은, 작업이 아무리 작아도 결과를 한 번 확인하는 것입니다.

## 완료 표시

30분 뒤 아래 4가지를 했다면 이번 라운드는 완료입니다.

1. 어느 디렉터리에서 작업했는지 앎
2. 실제 작업을 적어도 하나 돌림
3. 답변만이 아니라 결과를 봄
4. 다음에 어느 페이지를 이어서 배울지 앎

## 막히면

먼저 [문제 해결 색인](/guide/reference/troubleshooting/)으로 가세요. 개념만 안 들렸다면 [시작 전에 필요한 것](/guide/start-here/prerequisites/)과 [로컬과 클라우드](/guide/foundations/local-vs-cloud/)로 돌아가도 됩니다.

처음 30분에 「작업 내기·결과 보기·스스로 판단」루프를 한 번 손으로 끝내면 이미 충분히 가치 있습니다.
