표 작업은 silently 틀리기 쉬운 전형입니다. 구분자, 인코딩, 헤더, 수식, 날짜 형식 중 하나만 틀려도 하류가 전부 무너집니다.

## 이 페이지 내용

- Codex가 CSV / Excel을 안전하게 읽고 쓰게 하는 법
- 데이터 분석형 작업의 prompt 구조
- 숫자와 행 수를 어떻게 검증할지

## 형식 선택

| 형식 | 장점 | 주의 |
|---|---|---|
| CSV | 텍스트 diff 가능, 범용 | 인코딩(UTF-8 BOM), 구분자, 따옴표 이스케이프 |
| TSV | 쉼표 충돌이 적음 | CSV와 동일 |
| XLSX | 다중 시트, 수식 | 바이너리라 diff 어려움; 라이브러리로 읽기/쓰기 |
| Google Sheets | 협업 | 보통 MCP 또는 CSV보내기 |

작은 데이터·Git에 넣음: **CSV/TSV 우선**. 복잡한 보고서: **원천 CSV + XLSX 생성 스크립트**.

먼저 이 셋을 보세요.

- diff·추적·재현이 필요: CSV / TSV 우선
- Excel에 익숙한 사람에게 납품: 이어서 XLSX보내기
- “최종 보기 형식”과 “자동 처리에 가장 맞는 원천 형식”을 한 일로 섞지 않음

## 읽기와 분석

권장 prompt 구조:

```text
파일: data/sales_2025.csv
인코딩: UTF-8
작업: region별로 revenue를 집계해 summary.csv 출력
제약: 원본 수정 금지; 빈 값은 0; 소수 둘째 자리 유지
검증: 앞 5행 출력 + 총 행 수
```

컨텍스트: [파일과 폴더 컨텍스트](/guide/context/file-and-folder-context/)

## 왜 표 작업이 특히 몰래 틀리기 쉬운가

진짜 문제가 나기 쉬운 곳은 보통:

- 날짜가 텍스트인지 날짜인지
- 빈 값을 0으로 칠지, 건너뛸지, 오류로 할지
- 어느 열이 유일한 식별자인지
- 소수·금액 반올림 여부
- 원본을 고쳐도 되는지

이것을 분명히 말하지 않으면 Codex도 “끝난 것처럼” 보이지만 결과는 신뢰할 수 없습니다.

## 쓰기와 정제

- **열 이름·순서·타입**을 명시(날짜는 ISO 8601)
- 큰 표는 배치 처리해 한 번에 메모리 폭발을 피함
- 중복 제거·병합 키를 작업 설명에 쓰고, Agent가 「기본 키」를 추측하게 두지 않음

## 흔한 오해

### 1. 파일이 열리면 처리가 맞은 것?

아닙니다.

표형 작업에서 “열림”과 “데이터가 망가지지 않음”은 다른 일입니다.

### 2. Excel에서 괜찮아 보이면 문제없다?

어떤 오류는 하류 시스템이 소비할 때만 드러납니다. 예:

- 인코딩이 틀림
- 열 순서가 바뀜
- 숫자 타입이 바뀜
- 수식이 결과로 고정됨

### 3. 빈 값·날짜·기본 키를 Agent가 알아서 판단해도 되나?

보통 권장하지 않습니다.

이런 규칙이 분명할수록 결과가 안정적입니다.

## 표 작업을 넘길 때 분명히 할 것

요구를 이 5가지로 말하세요.

1. 입력 파일이 무엇인지
2. 출력 파일 이름이 무엇인지
3. 어떤 열을 유지·집계·정제할지
4. 빈 값·날짜·중복을 어떻게 처리할지
5. 결과를 어떻게 검증할지

“이 Excel 정리해 줘”보다 훨씬 안정적입니다.

Python이면 `pandas`로 읽고 쓰고, Node면 `csv-parse` / `xlsx` 등 — `AGENTS.md`에 프로젝트 표준 라이브러리를 약속하세요.

## 검증과의 관계

- 행 수·합계가 원천 데이터와 교차 검증되는지
- Excel을 열어 날짜가 숫자로 취급되지 않았는지
- [산출물 검증](/guide/quality/verify-artifacts/): 표본 대조

표 작업에서는 열·타입·규칙·검증을 분명히 말하는 것이 더 중요합니다.

## 흔한 실수

- Excel이 CSV 한글을 깨뜨림(BOM 없음 또는 잘못된 인코딩)
- 부동소수 합계 오차를 반올림 설명 없이 둠
- Excel에서 수식만 고치고 재현 가능한 스크립트로 남기지 않음

## 검증 체크리스트

- [ ] 열 이름·타입이 하류 소비 측 약속에 맞음
- [ ] 합계/표본이 사람 또는 SQL 대조와 일치
- [ ] 원본이 우연히 덮이지 않음(또는 변경이 diff에 보임)
