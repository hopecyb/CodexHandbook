이미지는 Agent가 인터페이스 문제, 디자인 의도, 화이트보드 스케치를 **보게** 합니다. 이 페이지는 입력(당신이 준 이미지)과 저장소 안 이미지 파일 관리를 다룹니다. 새 이미지 생성은 [이미지 생성](/guide/tools/image-generation/)을 보세요.

스크린샷으로 작업을 줄 때는, 어디를 보고 싶은지, 왜 그곳이 문제인지 알려 주는 편이 좋습니다.

## 이 페이지 내용

- 스크린샷을 어떻게 붙이면 가장 효과적인지
- 디자인 시안 / Figma보내기를 어떻게 쓰는지
- 이미지가 저장소·컨텍스트에서 차지하는 용량 문제

## 입력 이미지 장면

| 장면 | 실천 |
|---|---|
| UI bug | 스크린샷 + 이상 영역을 글로 표시 |
| 디자인 재현 | PNG보내기 + 브레이크포인트·컴포넌트 라이브러리 명시 |
| 아키텍처 화이트보드 | 선명한 사진 또는보내기 그림 + 범례 |
| 오류 팝업 | 오류 전문 포함, 한쪽만 자르지 않음 |

심화: [이미지 프롬프트](/prompts/prompting-with-images/)

## 이미지가 진짜 보완하는 것

이미지의 가장 큰 가치는, 글만으로는 설명하기 어려운 정보를 바로 보여 주는 데 있습니다. 예:

- 레이아웃이 어떻게 틀어졌는지
- 버튼이 어디로 밀렸는지
- 팝업에 무엇이 쓰였는지

하지만 이미지 자체가 Codex에게 자동으로 말해 주지는 않습니다.

- 당신이 가장 신경 쓰는 블록
- 어떻게 고치길 기대하는지
- “현재 상황”인지 “목표 효과”인지

그래서 이미지에는 보통 직접 설명을 한 줄 더 붙입니다.

## 품질 요구

- **해상도**: 글자가 읽히고, 흐린 썸네일 피함
- **크롭**: 무관한 데스크톱·알림바 민감 정보 제거
- **표시**: 화살표/원 표시는 가능하되, 핵심은 글로 다시 말함
- **여러 장**: 「현재 / 기대」로 짝지어 업로드

## 흔한 오해

### 1. 스크린샷을 보냈다고 문제를 자동으로 이해하나?

스크린샷은 시각 증거를 주지만, 다음을 더하는 편이 좋습니다.

- 문제가 어디인지
- 무엇으로 바꾸고 싶은지
- 어느 장이 현재이고 어느 장이 목표인지

### 2. 이미지가 클수록 더 선명해서 좋다?

너무 큰 원본은 두 문제를 낳습니다.

- 무관 정보가 너무 많음
- 저장소나 컨텍스트 용량이 무거워짐

### 3. 디자인 그림만내면 정보가 충분하다?

“그림대로 구현”이면 다음도 보완하세요.

- 브레이크포인트 요구
- 컴포넌트 제약
- 어디서 자유롭게 해도 되고, 어디서 안 되는지

## 저장소 안의 이미지

| 실천 | 이유 |
|---|---|
| `assets/` 또는 `docs/images/` 통일 디렉터리 | 유지보수 용이 |
| WebP/압축 | clone 용량 통제 |
| 의미 있는 파일명 | `login-form-mobile.png` — `image1.png` 아님 |
| alt 텍스트(문서 안) | 접근성 |

## 바로 쓸 수 있는 쓰기

이렇게 쓰세요.

```text
첫 장은 현재 페이지, 둘째 장은 기대 효과입니다.
첫 화면 제목 영역과 버튼 간격에 집중해 주세요.
스크린샷으로 비즈니스 로직을 추측하지 말고, 시각·레이아웃만 처리하세요.
```

## 프라이버시와 보안

- 스크린샷에 고객 데이터, 내부 URL, token이 있을 수 있음 — 먼저 마스킹
- 키가 보이는 설정 UI를 신뢰하지 않는 작업에 보내지 않음
- [민감 컨텍스트](/guide/context/sensitive-context/)

## 검증

「그림대로 구현」형 작업:

1. 구현과 참고 그림을 나란히 비교(또는 [브라우저 도구](/guide/tools/browser/)로 페이지 열기)
2. 반응형·다크 모드 점검(요구가 있으면)
3. [산출물 검증](/guide/quality/verify-artifacts/)

## 흔한 실수

- 디자인 시안만 주고 인터랙션 설명이 없음
- 4K 원본을 바로 commit
- Figma 링크를 모델이 읽을 수 있다고 가정하고보내기하지 않음

좋은 스크린샷은 “이미지가 있음”만이 아닙니다. 그림이 선명하고, 초점이 분명하고, 기대도 분명해야 작업을 맞추기 쉽습니다.
