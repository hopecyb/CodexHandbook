계획은 확인하고 조정할 수 있는 실행 경로입니다. 범위, 의존성, 완료 기준의 빈틈을 미리 찾는 데 도움이 되지만, 작업이 크다는 이유로 확인을 반복해서 기다릴 필요는 없습니다.

먼저 [작업 분류](/ko/prompts/ask-for-a-plan/)에 따라 바로 완료할지, 계획 후 이미 받은 권한 안에서 실행할지, 이번에는 방안만 제시할지 정하세요. “먼저 방안을 제시하고 파일은 수정하지 말라”는 명시적 요청은 읽기 전용으로 유지해야 합니다. 구현을 요청받았다면 계획만 내고 끝내면 안 됩니다.

## 충분한 계획의 구성 요소

| 요소 | 구체화할 내용 |
|---|---|
| 목표 | 완료 후 관찰할 수 있는 동작 |
| 범위 | 관련 파일, 입력, 제외 항목 |
| 순서 | 실제 의존성. 모든 도구 호출을 단계로 만들지 않음 |
| 검증 | 완료를 입증할 출력이나 확인 방법 |
| 선택 | 결과에 영향을 주는 미해결 결정만 |

기존 보고서에 데이터 그룹을 추가한다면 “정의 확인→집계와 표시 변경→샘플로 합계와 그룹 대조”라고 계획할 수 있습니다. 파일 읽기, 편집, 테스트마다 별도로 승인을 요청할 필요는 없습니다.

## 서로 다른 두 가지 계획 요청

**해결 방법이 아직 정해지지 않은 경우:**

```text
이번에는 읽기 전용으로 두 가지 내보내기 방안의 의존성, 호환성, 유지보수 비용을 비교하세요.
추천안과 내가 결정해야 할 선택을 제시하고 구현은 수정하지 마세요.
```

**범위가 정해졌고 구현이 필요한 경우:**

```text
기존 요구 사항에 맞춰 CSV 내보내기를 완료하세요. 먼저 저장소를 확인하고 짧은 계획을 설명한 뒤,
합의된 범위 안에서 구현과 검증을 연속해서 진행하세요. 매 단계마다 기다릴 필요는 없습니다.
새 서비스, 공개 인터페이스 변경, 데이터 접근 확대가 필요하면 먼저 구체적인 이유를 설명하세요.
```

두 문장은 이 사이트가 만든 예시입니다. 제품 승인 창이 뜰지는 실제 도구, 정책, 권한에 따라 달라집니다.

## 실행 중 계획 조정하기

- 일반적인 구현 세부 사항을 발견하면 계획을 갱신하고 승인된 범위에서 계속합니다.
- 원래 전제가 틀렸다면 근거와 영향을 설명하고 범위 안의 대안을 제시합니다.
- 사용자가 결정해야 할 선택이 있다면 구체적으로 묻고, 답과 무관한 작업은 계속합니다.
- 승인되지 않은 외부 작업이 필요하다면 검토 가능한 결과를 준비하고 실행 전에 권한을 요청합니다.

“문제가 생길 수도 있다”는 이유로 멈추지 말고, 실제로 범위가 바뀌었는데 계획만 따르느라 무시하지도 마세요.

## 계획에 의견 주기

```text
1, 2단계는 유지하고 리팩터링은 빼세요.
이번에는 로컬 미리보기만 만들고 게시하지 마세요.
기존 파일 형식도 정상적으로 읽을 수 있는지 완료 기준에 추가하세요.
```

의견은 명시한 내용만 바꿉니다. 철회하지 않은 제약과 완료 기준은 계속 유효합니다. 작업이 중단되면 현재 파일, 완료한 검증, 다음 단계를 [인계 기록](/ko/guide/agent-work/handoff-and-resume/)에 남기세요.

## 끝날 때 증거 확인하기

단계를 모두 체크했는지만 보지 말고 목표가 실제로 달성됐는지 확인하세요. 실행하지 않은 테스트, 확인하지 않은 미리보기, 검증하지 않은 사실을 명시하세요. 전체 흐름은 [탐색→계획→실행→검증](/ko/cases/workflows/explore-plan-execute-verify/)을 참고하세요.
