# 권한과 샌드박스

Codex는 동의 없이 고위험 작업을 실행해서는 안 됩니다. **승인**은 사람·Agent 협업의 핵심 게이트이며, **샌드박스**는 Agent가 닿을 수 있는 파일 시스템과 일부 시스템 능력을 제한합니다.

## 이 페이지의 내용

「권한」「승인」「샌드박스」「네트워크 접근」을 처음 보면, 비슷해서 전부 보안 설정처럼 느껴질 수 있습니다.

가장 위험한 것은 바로 이 혼동입니다. 「계속 실행만 허용」한다고 생각했는데, 실제로는 파일 쓰기·명령 실행·외부망 접근 경계를 함께 연 것일 수 있습니다.

이 페이지는 개념을 나누어, 매번 확인이 무엇을 풀어 주는지 판단하도록 돕습니다.

## 먼저 이 개념들을 구분하세요

이렇게 나누면 됩니다.

- **승인**: 먼저 한 번 물을지
- **샌드박스**: 하려 해도 어디까지 닿을 수 있는지
- **네트워크 접근**: 정보를 밖으로 내보내거나 밖에서 끌어올 수 있는지

함께 결과에 영향을 주지만, 같은 것은 아닙니다.

## 보통 신경 쓸 것

- 현재 프로젝트 밖 경로 읽기·쓰기를 허용할지
- 네트워크를 허용할지
- 특정 shell 명령 실행을 허용할지
- 팀이 강제 정책(관리형 설정)을 배포했는지

## 샌드박스와 네트워크

**샌드박스**는 오조작 면을 줄입니다. **네트워크 접근**은 또 다른 위험 층입니다. 프롬프트의 민감 정보가 유출되거나, 신뢰할 수 없는 데이터를 가져올 수 있습니다.

처음에는 보통 이렇게 다루면 됩니다.

1. 첫 연습에서는 불필요한 네트워크를 끄거나, 분명히 필요한 접근만 허용합니다
2. 프로덕션 비밀키를 연습 프로젝트에 넣지 마세요
3. 「외부망 / 민감 경로 쓰기」요청이 보이면, 이해하고 나서 승인하세요

## 흔한 오해

### 팝업이 뜬다고 해서 반드시 위험한 것은 아닙니다

정상 작업도 승인을 트리거하는 경우가 많습니다. 예를 들어:

- 의존성 설치
- 프로젝트 밖 디렉터리 쓰기
- 브라우저나 시스템 앱 열기
- 외부 사이트나 API 접근

진짜로 판단할 것은 **이 단계가 현재 작업에 원래 필요한지**입니다. 팝업 유무만 보지 마세요.

### 팝업이 없다고 해서 위험이 전혀 없는 것도 아닙니다

현재 샌드박스가 이미 어떤 작업을 허용했거나, 이전에 규칙을 넓혀 두었다면 Codex가 다시 묻지 않을 수 있습니다.

그래서 「안내 창이 있는지」만으로 위험을 판단하지 말고, 현재 환경 설정 자체도 보세요.

## 권한 요청을 볼 때 판단하는 단계

권한 관련 요청이 보일 때마다 세 가지를 스스로에게 물으세요.

1. 이 단계가 현재 작업을 끝내는 데 필수인가
2. 닿으려는 데이터·경로가 원래 기대를 넘는가
3. 잘못 실행되어도 철회·보완 방법을 아는가

세 중 둘에 답이 없으면 승인하지 말고, 먼저 왜 이 단계가 필요한지 설명하게 하세요.
