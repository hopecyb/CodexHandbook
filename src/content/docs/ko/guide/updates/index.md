## 2026-09-18: 사례 필터와 학습 경로 탐색

[사례 목록](/ko/cases/)은 작업 유형과 키워드 필터, 공유할 수 있는 필터 URL을 제공합니다. 카드의 결과물과 검증 상태는 각 사례의 메타데이터에서 읽습니다. 중국어 간체와 번체에서는 학습 경로의 사이드바에 현재 경로, 단계, 관련 도움말만 표시합니다. 초보자 개요를 맨 위에 두고 다섯 단계에 순서를 매겼습니다. 결과가 없으면 필터를 초기화할 수 있으며 스크립트를 쓰지 않아도 모든 사례를 읽을 수 있습니다.

## 2026-09-18: 프롬프트 비교 실측 12회

[세 가지 프롬프트 비교](/ko/prompts/comparison-lab/)에는 주간 매출 보고서, 출처 기반 글, 버그 수정 각각에서 A/B를 두 번씩 실행한 실제 결과물, 소요 시간, 항목별 점수가 추가되었습니다. [결과 패키지](/downloads/prompt-comparison-results/prompt-comparison-results-1.0.0.zip)는 도구 오류, 로그 누락, 경로를 비식별화한 해시를 보존합니다. 주 Agent의 평가는 눈가림 방식이 아니었고 실제 모델 표시는 알 수 없으며, 일반적인 성공률이나 시간 절감을 입증하지 않습니다.

## 2026-09-18: 완전한 웹사이트 연습

[웹사이트 만들기](/ko/cases/build-a-website/) 사례에 고정 요구사항, HTML 시작 페이지, 참고 완성본, 인수 양식, 버튼 앵커 오류를 추가했습니다. 참고 페이지는 데스크톱과 너비 375px 화면에서 확인했으며 실제 수정과 링크 로그를 보존했습니다. 배포, 가입자 확보, 모델 효과를 주장하지 않습니다.

## 2026-09-18: 중국어 시작 화면 정리

홈은 작업하기, 역할별 경로, 문제 찾기, 재사용 자료를 중심으로 구성하고 반복되는 소개와 기능 설명을 덜어냈습니다. 간체와 번체 중국어 주 메뉴는 작업, 학습 경로, 참고 자료를 강조합니다. 로드맵은 자료 메뉴로 옮겼고 모바일도 같은 입구를 사용합니다.

## 2026-09-18: 초보자 고정 자료와 복구 연습

[초보자 다섯 단계 경로](/ko/guide/learning-paths/beginner/)는 하나의 합성 행사 자료, 참고 공지, 네 가지 오류 샘플, 검토와 인계 양식을 사용합니다. 읽기 전용, 단일 파일 수정에서 실제 복사본 복구까지 진행합니다. [작성자의 스크립트 기록](/downloads/first-project/validation/record.json)은 파일 작업 흐름만 증명하며 독립적인 모델 평가나 독자의 완주 결과는 없습니다.

## 2026-09-18: 로드맵 날짜와 실습 입구

[AI 애플리케이션 로드맵](/ko/ai-roadmap/)은 이제 논문, 제품 출시, 엔지니어링 글, 최초 발표일 순으로 정렬하지 않은 프로젝트 주제를 구분합니다. 각 주제에 구체적인 출처와 연습 입구가 있습니다. 글 한 편의 날짜로 업계 전체의 확산 시기를 표현하지 않고, Skill 패키지 구조 검사도 클라이언트 호출 실측으로 제시하지 않습니다. 기존 URL은 유지하며 옛 연월은 현재 사건의 날짜가 아닙니다. 출처와 검증 범위는 각 주제 페이지 상단에 있습니다.

## 2026-09-18: 오해를 줄이는 설명 수정

- 가격 메뉴 이름을 “가격 참고”로 바꿨습니다. 출처 있는 원래 통화의 스냅샷과 알 수 없는 정보를 분리하고 추정치로 전 세계 가격 순위를 매기지 않습니다. 구매 전에는 판매 채널에 실제 표시되는 가격을 확인하세요.
- 페이지 상단에서 편집 상태, 출처 확인, 예제 실행, 과거 설명을 구분합니다. “실행됨”은 나열한 스크립트와 환경에만 해당하며 모델 출력의 신뢰성 비율이 아닙니다.
- [지침 우선순위](/ko/guide/context/context-priority/)는 메시지 역할, 프로젝트 지침 발견 규칙, 실행 권한을 구별하고 “더 새롭거나 엄격하면 항상 우선”이라고 일반화하지 않습니다.
- [SDK](/ko/guide/developer-platform/sdk-overview/)와 [Webhook](/ko/guide/developer-platform/webhooks/overview/)는 로컬 실행, 자체 운영 서비스, 콜백 설계를 나누며 설계 인터페이스를 공식 계약처럼 쓰지 않습니다.
- [작업 수준](/ko/prompts/ask-for-a-plan/)은 직접 실행, 선계획, 행동 승인을 구분해 모든 단계에서 무차별적으로 중단하지 않습니다.

이런 기능의 출처와 검증 범위는 해당 페이지 상단을 확인하세요. 이 업데이트 요약을 완전한 API 문서로 취급하지 마세요.

## 페이지 문제를 발견하면

각 중국어 본문 아래에는 “이 페이지 문제 신고(GitHub 초안)” 링크가 있습니다. 페이지 제목, 사이트 경로, 기록된 검증 날짜를 넣은 제출 전 Issue 초안을 엽니다. 내용을 확인한 뒤 직접 제출해야 하며 GitHub 계정이 필요합니다.

구체적인 문단, 기대와 실제의 차이, 필요한 환경, 공개 근거를 적으세요. 비식별화한 정보만 공유하고 API 키, 계정, 개인 디렉터리, 고객 데이터, 전체 원본 로그는 붙여 넣지 마세요. 초안이 작업 기록을 자동 수집하거나 페이지 쿼리 매개변수를 포함하지는 않습니다.

GitHub 계정이 없다면 페이지 경로와 문제 설명을 로컬 메모로 저장한 뒤 권한 있는 동료에게 제출을 부탁할 수 있습니다. 처리 기한은 보장하지 않으며 메시지도 자동으로 보내지지 않습니다.

## 관리자의 처리 방법

문제를 재현하거나 출처를 확인한 뒤 접수, 수정, 아직 확인 불가의 이유를 기록합니다. 제품 사실을 바꿀 때는 해당 증거를 갱신하되 다른 페이지의 검증 날짜를 일괄 변경하지 않습니다. 연습을 바꿀 때는 원본 자료, 다운로드 패키지, 본문을 함께 맞춥니다. 이전 결론이 더는 유효하지 않다면 단순히 “내용 개선”이라고 쓰지 말고 옛 방법의 영향과 이전 절차를 설명합니다.

이 페이지를 고칠 때는 구체적인 페이지와 검증 기록을 연결하고 아직 시험하지 않은 범위를 남깁니다. 이는 커뮤니티 안내서의 변경 기록이지 OpenAI의 공식 제품 출시 기록이 아닙니다.
