먼저 무엇을 기록하는지 분명히 하세요. 계정의 남은 한도, API 호출 비용, 대기 시간, 사람이 검토하고 다시 작업한 시간은 단위가 다르므로 서로 대신할 수 없습니다.

[기록 양식 다운로드](/downloads/usage-log/usage-log-1.0.0.zip) · [작성 안내](/downloads/usage-log/README.md)

## 네 가지 항목을 따로 기록하기

| 지표 | 기록 근거 | 흔한 오해 |
|---|---|---|
| 구독 한도 | 현재 화면에 표시된 기간, 남은 비율, 초기화 시간 | 남은 비율을 달러나 고정된 작업 횟수로 바로 환산 |
| API 비용 | 실제 호출 사용량, 모델, 적용 가격 및 청구서 | 구독 가격을 API 요금으로 대체하거나 추정치를 실제 청구액으로 간주 |
| 대기 시간 | 같은 작업의 시작, 종료, 대기열, 재시도 | 마지막 성공 실행만 기록하고 실패에 걸린 시간을 누락 |
| 사람의 노력 | 검토와 재작업 시간을 따로 측정 | 모델을 기다린 시간 전체를 절약한 인력 투입 시간로 계산 |

[공식 가격 설명](https://learn.chatgpt.com/docs/pricing)에 따르면 작업 사용량은 모델, 컨텍스트, 추론, 도구, 캐시에 영향을 받습니다. 메시지 수 추정치는 고정된 상한이 아닙니다. 현재 한도는 사용량 화면에서 확인하고, CLI 세션에서는 `/status`를 사용할 수 있습니다. API 키 사용에는 API 요금이 적용됩니다.

한도 스냅샷에는 다른 작업의 사용량이나 기간 초기화가 섞일 수 있습니다. 전후로 5% 줄었다는 이유만으로 이 작업이 항상 5%를 소비한다고 단정하거나 앞으로 몇 번 더 실행할 수 있다고 약속하지 마세요.

## API 비용 추정 전에 과금 기준 확인하기

모델, 입력·캐시·출력 범주, 서비스 조건에 맞는 가격을 찾고 실제 사용량으로 계산하세요. 다른 과금 항목은 별도로 더합니다. 이 안내서는 별도의 고정 모델 가격표를 유지하지 않습니다. [API 가격](https://developers.openai.com/api/docs/pricing)을 확인하세요.

추론 token은 출력 token으로 과금됩니다. 사용량 필드에 추론 부분이 이미 포함되었는지 확인해 중복 합산을 피하세요. 선택 가능한 추론 단계도 모델 지원 여부를 [추론 모델 설명](https://developers.openai.com/api/docs/guides/reasoning)에서 확인하세요.

교육용 계산: 입력 10,000 token, 출력 2,000 token을 사용하고 캐시나 추가 비용이 없다고 가정합니다. 입력 100만 token당 2달러, 출력 100만 token당 10달러라는 **가상의** 요금을 적용하면 추정 비용은 0.04달러입니다. 단위 환산을 보여 주는 예시일 뿐 실제 모델 가격이나 청구액이 아닙니다.

## 같은 작업 묶음으로 설정 비교하기

명확한 완료 조건이 있는 작업을 골라 현재 사용 가능한 설정으로 기준선을 만드세요. 입력, 도구 권한, 프로젝트 지침, 평가 방법은 동일하게 유지하고 모델 또는 추론 설정의 주요 요인 하나만 한 번에 바꾸세요.

정확성, 경계 준수, 증거, 재작업을 항목별로 비교하세요. 응답 속도만 비교해서는 안 됩니다. 가벼운 설정이 완료 조건을 안정적으로 만족하지 못한다면 자료 부족, 범위 불명확, 추론 부족 중 무엇이 원인인지 확인한 뒤 설정을 높일지 결정하세요. 높은 설정도 출처 확인과 테스트를 대신하지 못합니다.

이는 안내서의 평가 권고이지 어떤 모델이 항상 우세하다는 실측 결론이 아닙니다. [세 가지 프롬프트 비교](/ko/prompts/comparison-lab/)와 [워크플로 평가 샘플](/ko/guide/quality/workflow-evaluation/)로 직접 관찰한 내용을 기록할 수 있습니다.

## 표본 조건 기록하기

[실행 기록표](/downloads/usage-log/runs.csv)는 입력 해시, 실제 모델 표시, 클라이언트, 추론 설정, 과금 경로, 시간, 재시도, 결과, 비용 증거를 기록합니다. [한도 스냅샷 표](/downloads/usage-log/allowance-snapshots.csv)는 기간과 초기화 시간을 별도로 기록합니다.

실패와 중단도 남기세요. 사람의 검토와 재작업 시간을 따로 기록하세요. 알 수 없는 필드는 비워 두고 이유를 설명해야 하며, 사용량이 없었던 것처럼 0을 쓰지 마세요. 계정 별칭을 사용하고 공개 자료에 키, 계정 정보, 개인 로그를 넣지 마세요.

현재 다운로드용 표에는 실측 실행 행이 없습니다. 비교 가능한 사람의 기준 작업이 없으면 절감률을 계산하지 말고, 반복 표본이 없으면 안정적인 속도 우위를 주장하지 마세요. 모델 대기가 짧아져도 재작업이 늘면 채택할 가치가 없을 수 있습니다.

## 한도에 가까워졌을 때

현재 결과, 미해결 항목, 재개 방법을 저장하세요. 작업이 반복 재시도에 빠졌거나 관련 없는 자료를 읽고 있지 않은지 살피세요. 목표에 따라 불필요한 범위를 줄이되 품질과 안전 완료 조건은 유지하세요. 한도가 끝나기 전에 마치려고 핵심 확인을 생략하지 마세요.

계속 실행해야 한다면 현재 한도와 과금 경로를 확인한 뒤 선택하세요. 이 글은 자동으로 API 과금으로 전환하거나 크레딧을 구매하거나 계정 설정을 바꾸지 않습니다. 팀은 [2주 시험 경로](/ko/guide/learning-paths/team/)로 선택 이유와 되돌릴 조건을 기록할 수 있습니다.

현재 모델, 제품별 차이, 작업별 추천을 확인하세요: [모델 선택: 작업에 맞는 시작점](/ko/guide/reference/model-selection/).
