이 장은 ChatGPT 데스크톱 앱을 처음 여는 독자를 위한 것입니다. 모든 버튼을 외우기보다 **검토하고 검증할 수 있는 작은 작업 하나**를 끝내는 것이 목표입니다.

설치와 로그인 방법은 [데스크톱 앱 설치](/ko/guide/getting-started/install-desktop-app/)를 참고하세요. 현재 공식적으로 macOS, Windows, Linux 버전이 제공됩니다. 로그인한 뒤 새 채팅이나 프로젝트를 만들거나 로컬 폴더를 열 수 있습니다.

## 먼저 세 가지 대상을 알아두기

| 대상 | 역할 | 처음 해 볼 일 |
|---|---|---|
| 프로젝트 또는 폴더 | 채팅에 파일과 작업 디렉터리를 제공 | 운영 환경의 디렉터리 대신 연습용 저장소를 열기 |
| 채팅 | 목표, 맥락, 진행 상황, 결과를 보관 | 명확한 목표 하나당 채팅 하나 사용하기 |
| Codex | 프로젝트 내용을 읽고 수정하고 검증 | 위험이 낮고 확인하기 쉬운 작은 변경부터 시작하기 |

앱의 화면은 계속 바뀌지만, 이 세 대상은 특정 버튼의 위치보다 안정적인 개념입니다.

## 첫 실제 작업 완료하기

기존 Git 저장소를 준비하고, 보존해야 하지만 아직 기록하지 않은 변경 사항이 없는지 먼저 확인합니다. 그런 다음 앱에서 해당 폴더를 열고 새 Codex 채팅을 만듭니다.

다음과 같이 입력합니다.

```text
먼저 README.md를 읽고 그중 "로컬 실행" 절만 수정해 주세요.
1. 더 이상 작동하지 않는 시작 명령을 고치세요.
2. 다른 절은 그대로 두세요.
3. 수정 후 diff를 보여 주고, 문서에 있는 실행 가능한 검증 명령을 실행하세요.
4. 검증할 수 없다면 이유를 명확히 설명하고 완료했다고 주장하지 마세요.
```

작업이 끝나면 채팅 요약만 읽지 말고 다음도 확인합니다.

1. 검토 창에 예상한 파일만 나타나는지
2. 삭제된 내용이 타당한지
3. 터미널 출력이 실제로 “검증 통과”라는 결론을 뒷받침하는지
4. `git diff`가 작업 범위와 일치하는지

## Chat, Work, Codex 중 무엇을 선택할까

- 지식을 묻거나 아이디어를 논의할 때는 **Chat**을 사용합니다.
- 여러 파일과 도구에 걸친 일반 작업에는 **Work**를 사용합니다.
- 저장소를 이해하고 수정하고 테스트해야 할 때는 **Codex**를 사용합니다.

장기 맥락이 필요 없는 일회성 질문이라면 Quick chat을 사용할 수 있습니다. 계속 추적해야 하는 작업은 일반 채팅이나 프로젝트에 남겨 두세요.

## 실패하면 먼저 확인할 것

- **파일이 보이지 않음**: 올바른 폴더를 열었고 작업 권한이 거부되지 않았는지 확인합니다.
- **명령을 실행할 수 없음**: 의존성이 설치되었는지 확인한 다음 터미널의 첫 번째 실제 오류를 봅니다.
- **이전 변경 사항이 섞임**: `git status`로 작업 전부터 있던 변경과 이번 변경을 구분합니다.
- **앱 화면이 이 글과 다름**: 스크린샷의 고정된 위치가 아니라 “프로젝트/폴더, 채팅, 검토, 터미널”이라는 대상에 따라 찾습니다.
