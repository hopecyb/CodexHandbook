**작업 트리(worktree)**는 격리된 디렉터리에서 변경을 시험해 메인 작업 영역에 대한 간섭을 줄입니다.

같은 저장소에 “평행 시험 구역”을 여는 것으로 보면 됩니다. 모든 시도를 현재 작업 영역에 몰아넣지 않아도 됩니다.

## 언제 쓰나요

- 두 가지 구현을 병렬로 시도하고 싶을 때
- 실험적 리팩터가 메인 브랜치 작업 영역을 오염시킬까 걱정될 때

## 언제 쓰지 않나요

- 연습 프로젝트 자체가 이미 충분히 격리된 경우
- Git에 아직 익숙하지 않은 경우: 연습 디렉터리에서 직렬로 작업을 먼저 끝내세요

## 흔한 오해

### 1. 그냥 새 폴더를 만드는 것 아닌가요?

겉보기에는 비슷하지만, 목적은 “디렉터리를 하나 더”가 아니라 같은 저장소의 다른 시도에 격리 공간을 주는 것입니다.

### 2. 처음부터 배워야 하나요?

아닙니다.

기본 작업 흐름을 익히는 중이라면 worktree를 건드리지 않는 편이 보통 더 쉽습니다.

### 3. 언제 배우면 좋을까요?

다음 상황에 부딪히면 배울 가치가 있습니다.

- 두 가지 구현을 시도하고 싶을 때
- 실험 변경을 현재 작업 영역에 섞고 싶지 않을 때
- 팀에서 여러 병렬 작업을 동시에 열 때

worktree는 고급 격리 도구이며, Codex를 처음 쓸 때 필수 항목은 아닙니다.
