작업 트리(worktree)를 사용하면 하나의 Git 저장소에 여러 독립적인 체크아웃 디렉터리를 둘 수 있습니다. 각 디렉터리는 자체 파일과 브랜치 상태를 갖지만 저장소의 Git 메타데이터는 공유합니다. 따라서 여러 코딩 채팅을 동시에 진행하면서 서로의 파일을 덮어쓰지 않도록 할 수 있습니다.

## 사용 전제 조건

- 프로젝트가 Git 저장소에 있어야 합니다.
- 각 작업의 경계를 독립적으로 설명하고 검증할 수 있어야 합니다.
- 병렬 작업이 같은 핵심 파일 집합을 수정해서는 안 됩니다.

Codex를 처음 연습하는 단계라면 먼저 Local 모드에서 작업을 순서대로 완료하세요. 대기 시간이나 파일 충돌이 실제 문제가 되었을 때 작업 트리를 사용하면 됩니다.

## 앱에서 만들기

1. 새 채팅 입력창 아래에서 **Worktree**를 선택합니다.
2. 시작 브랜치를 선택합니다. 기본 브랜치, 기능 브랜치 또는 스테이징되지 않은 변경이 있는 현재 브랜치를 선택할 수 있습니다.
3. 프롬프트를 제출하면 앱이 Git worktree를 만듭니다.
4. 독립된 채팅에서 변경을 확인하고 테스트하고 검토합니다.
5. 로컬 체크아웃으로 돌아갈 준비가 되면 **Handoff**를 사용합니다.

기본적으로 만들어지는 작업 트리는 detached HEAD 상태입니다. 이 상태에서도 Codex는 작업할 수 있지만, 커밋을 보관하거나 공유하기 전에는 대상 브랜치와 병합 방법을 명확히 정해야 합니다.

## 두 작업을 병렬로 진행하는 예시

| 채팅 | 작업 트리의 작업 | 파일 소유 범위 | 완료 기준 |
|---|---|---|---|
| A | 로그인 오류 수정 | `src/auth/**` | 인증 테스트 통과 |
| B | 인증 문서 보강 | `docs/auth/**` | 링크 검사 통과 |

A와 B가 같은 잠금 파일이나 설정 파일을 동시에 수정하게 하지 마세요. 꼭 수정해야 한다면 한 채팅만 해당 파일을 담당하고, 다른 채팅은 분석 결과만 제공하도록 먼저 정하세요.

## 전달 전 확인

```bash
git status --short
git diff --check
git diff --stat
```

그다음 작업에 맞는 테스트를 실행합니다. 각 변경이 어느 채팅에서 나왔는지, 대상 브랜치가 무엇인지, 검증이 통과했는지 명확히 확인한 후에만 Handoff, 커밋 또는 병합을 진행하세요.

## 예약 작업 및 Remote와의 관계

- Git 저장소의 예약 작업은 전용 백그라운드 작업 트리를 사용해 현재 작업과의 충돌을 피할 수 있습니다.
- Remote를 사용하면 모바일 기기에서 연결된 컴퓨터의 작업 트리 채팅을 제어할 수 있습니다. 저장소와 명령은 그 컴퓨터 또는 해당 컴퓨터의 원격 개발 환경에 그대로 남습니다.
- Git이 아닌 프로젝트에는 작업 트리 격리가 없으며, 예약 작업은 프로젝트 디렉터리를 직접 사용합니다.
