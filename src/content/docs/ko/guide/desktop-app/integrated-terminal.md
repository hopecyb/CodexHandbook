ChatGPT 데스크톱 앱의 각 대화에는 현재 프로젝트 또는 작업 트리를 범위로 하는 터미널이 있습니다. 이 터미널은 로그를 보는 곳일 뿐 아니라 Codex의 결론을 확인할 근거를 얻는 곳이기도 합니다.

앱 오른쪽 위의 터미널 아이콘을 누르거나 `Ctrl`과 백틱 키를 함께 눌러 열 수 있습니다. ChatGPT가 현재 터미널 출력을 읽을 수 있으므로 실패한 빌드나 실행 중인 개발 서버의 출력을 분석해 달라고 요청할 수도 있습니다.

## 최소 검증 절차

JavaScript 프로젝트에서는 다음 명령을 순서대로 실행할 수 있습니다.

```bash
git status --short
pnpm test
pnpm run lint
```

명령은 프로젝트마다 다릅니다. 먼저 `README.md`, `package.json`, 프로젝트 규칙을 확인하세요. 확인한 명령을 요청에 명시합니다.

```text
변경 후 pnpm test와 pnpm run lint를 실행하세요.
각 명령의 종료 상태를 보고하고, 하나라도 실패하면 작업이 완료되었다고 말하지 마세요.
```

검수할 때는 최소한 실행한 명령, 성공 여부, 실패 시 첫 번째 유효한 오류, 실행하지 못한 검사를 기록합니다.

## 오래 실행되는 프로세스 처리

개발 서버는 계속 실행됩니다. 이는 명령이 멈췄다는 뜻이 아닙니다. 시작한 뒤 다음을 확인하세요.

- 출력에 로컬 주소가 표시되는지
- 브라우저에서 페이지가 열리는지
- 이후 터미널에 런타임 오류가 나타나는지

멈춰야 할 때 중단 신호를 보냅니다. 잠시 새 출력이 없다는 이유만으로 서버를 여러 개 다시 시작하지 마세요.

## 재사용 가능한 Action

같은 명령을 자주 실행한다면 로컬 환경에 Action을 정의할 수 있습니다. 데스크톱 앱의 바로 가기 작업으로 표시되며 통합 터미널에서 실행됩니다. `test`, `lint`, `build` 같은 위험이 낮은 검증 명령에 적합합니다. 운영 배포나 데이터베이스 정리 작업을 숨겨서 실행하는 용도로 사용하지 마세요.

## 안전 경계

- 운영 환경의 비밀 키를 대화나 터미널 기록에 붙여 넣지 않습니다.
- 이해하지 못하는 명령은 목적, 영향 범위, 되돌리는 방법을 먼저 설명해 달라고 요청합니다.
- 운영 환경에서 삭제, 마이그레이션, 배포 명령을 무작정 다시 실행하지 않습니다.
- 터미널에서 실행할 수 있다는 사실이 업무상 실행 승인을 뜻하지는 않습니다.

공식 문서에는 `git status`, `git pull --rebase`, 테스트, lint 등이 일반적인 명령으로 제시됩니다. 실제 프로젝트에서 사용할 명령은 해당 프로젝트 문서를 기준으로 삼으세요.
