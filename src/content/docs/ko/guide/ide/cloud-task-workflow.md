IDE에서는 빠른 반복 작업을 로컬에서 진행할 수도 있고, Codex web에 연결해 시간이 더 걸리는 작업을 Cloud에 위임할 수도 있습니다. 시작점은 편집기 안에 그대로 있지만 실행 환경, 저장소 상태, 네트워크 경계는 클라우드로 바뀝니다.

## 위임할 시점

| 로컬에서 계속하기 | Cloud에 위임하기 |
|---|---|
| 현재 선택 영역을 보며 빠르게 여러 번 수정해야 함 | 작업 단계가 많고 실행 시간이 김 |
| 커밋하지 않은 로컬 상태에 의존함 | 입력이 원격 저장소에 있거나 업로드 가능함 |
| 내 컴퓨터의 전용 도구에 접근해야 함 | 클라우드 환경에서 의존성과 검증 절차를 재구성할 수 있음 |
| 실행 중인 프로세스를 실시간으로 조작해야 함 | 로컬에서 다른 일을 계속하고 싶음 |

Cloud는 내 컴퓨터에서 아직 커밋하지 않은 파일, 자격 증명, 실행 중인 프로세스를 자동으로 갖고 있지 않습니다. 위임하기 전에 어느 저장소, 브랜치, 커밋에서 작업을 시작할지 명확히 하세요.

## 위임 전 체크리스트

- [ ] ChatGPT 계정으로 로그인했습니다. Codex Cloud는 API key 로그인을 받지 않습니다.
- [ ] GitHub를 연결했거나 현재 지원되는 GitLab Beta 통합을 사용 중입니다.
- [ ] 클라우드 환경에서 설치 및 검증 스크립트를 실행할 수 있습니다.
- [ ] 필요한 변수와 secrets를 환경에 설정했으며 프롬프트에 적지 않았습니다.
- [ ] 로컬의 커밋하지 않은 변경 사항을 처리했거나 작업에 포함하지 않는다고 명시했습니다.
- [ ] 목표, 허용 경로, 금지 영역, 검수 명령을 분명히 적었습니다.

## 처음부터 끝까지의 예시

```text
목표: 재시도 모듈이 상한에 도달한 뒤에도 한 번 더 기다리는 문제를 수정합니다.
시작점: acme/retry-service 저장소, fix/retry-limit 브랜치.
범위: src/retry.ts와 해당 테스트만 수정합니다.
제약: 의존성을 업그레이드하거나 공개 API를 수정하거나 main에 푸시하지 않습니다.
검수: pnpm test -- retry와 pnpm typecheck를 실행하고 diff와 명령 결과를 보여 줍니다.
```

권장 흐름:

1. IDE에서 관련 파일이나 선택 영역을 첨부해 문제의 경계를 먼저 확인합니다.
2. 더 긴 작업은 Cloud에서 계속하도록 선택합니다.
3. Cloud에서 계획, 진행 상황, 검증 결과를 확인합니다.
4. IDE나 Web으로 돌아와 검토할 수 있는 결과를 확인합니다.
5. 브랜치를 가져오거나 PR을 통해 변경 사항을 받습니다.
6. 신뢰할 수 있는 로컬 환경에서 다시 테스트하고 사람이 검토한 뒤 병합합니다.

Cloud에서 “완료”라고 표시되는 것은 원격 실행이 끝났다는 뜻일 뿐, 코드가 곧바로 병합에 적합하다는 뜻은 아닙니다. 원격의 의존성, 운영체제 또는 자격 증명이 로컬이나 CI와 달라 환경 차이가 드러날 수 있습니다.

## 충돌과 보안

- 위임한 뒤 로컬과 Cloud가 동시에 같은 파일을 수정하지 않도록 합니다.
- 프로덕션 키를 프롬프트에 붙여 넣지 말고 환경 secrets를 사용합니다.
- Cloud의 네트워크 접근을 기본 기능으로 가정하지 말고 환경의 허용 목록에 맞게 설정합니다.
- 푸시, PR 생성, 병합은 서로 다른 작업입니다. 병합에는 사람 또는 CI의 승인 단계를 남겨야 합니다.

이어서 [클라우드 환경](/ko/guide/web-and-cloud/cloud-environments/)과 [Pull Request 만들기](/ko/guide/web-and-cloud/create-pull-requests/)를 읽어 보세요.
