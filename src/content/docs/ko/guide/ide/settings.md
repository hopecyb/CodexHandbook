IDE 확장 설정은 **개인 선호**와 **프로젝트 규칙**을 잇습니다. 모델 등급, 승인 엄격도, 열린 파일 자동 첨부 여부 등입니다. 전역 [구성 기초](/guide/customization/configuration/config-basics/)와 일치하며, 이 페이지는 에디터 안의 흔한 옵션에 초점을 둡니다.

## 이 페이지의 내용

- IDE 설정 vs 사용자 구성 vs `AGENTS.md`의 역할
- 개발자가 가장 자주 바꾸는 항목
- 팀이 기본값을 맞추는 방법

## 이 설정이 다루는 것

IDE 설정은 다음에 가깝습니다. **Codex가 에디터에서 당신과 협업할 때의 기본 습관**.

다루는 문제는 예를 들면 다음과 같습니다.

- 기본 모델은 무엇으로 할지
- 승인을 얼마나 조일지
- 현재 파일·선택 영역을 자동으로 넣을지

프로젝트 규칙 자체를 정의하지는 않습니다. 에디터에서 쓰기 편하고 안정적인지를 정합니다.

## 구성 계층(복습)

| 계층 | 예시 | 우선순위 |
|---|---|---|
| 조직 관리형 정책 | 샌드박스 완화 금지 | 최고 |
| 프로젝트 `AGENTS.md` / 프로젝트 구성 | 테스트 명령, 디렉터리 규약 | 높음 |
| IDE 확장 설정 UI | 기본 모델, 패널 레이아웃 | 중간 |
| 단일 작업 prompt | 「이번엔 네트워크 쓰지 말 것」 | 작업급 |

참고: [범위와 우선순위](/guide/customization/agents-md/scope-and-precedence/)

## 흔한 오해

### IDE 설정은 프로젝트 규약이 아닙니다

“내 에디터 기본값”을 “이 프로젝트가 그래야 한다”로 오해하기 쉽습니다.

더 명확한 구분:

- 에디터 설정은 개인 사용 경험에 가깝습니다
- `AGENTS.md`와 프로젝트 구성은 팀 합의에 가깝습니다

관련은 있지만 같은 것은 아닙니다.

### 자동 컨텍스트는 많을수록 좋지 않습니다

현재 파일·선택 영역·열린 탭을 자동으로 넣는 것은 편리합니다. 너무 많이 넣으면 작업 초점이 희석됩니다.

실용 기준은 충분하면 됩니다. “많이 열수록 강하다”를 추구할 필요는 없습니다.

## 자주 바꾸는 설정(개념)

### 모델과 추론

응답 속도와 복잡 작업 품질에 영향을 줍니다. 팀 프로젝트는 README에 「권장 모델 등급」을 적어, 사람마다 기본값이 달라 재현이 어려워지지 않게 하세요.

### 승인과 샌드박스

[권한과 승인](/guide/foundations/permissions-and-approvals/)에 대응합니다.

- 초보자: 기본값 유지 또는 더 엄격
- 신뢰 저장소: 신중히 완화, 프로덕션 secrets 디렉터리와 섞지 않음

CLI와 IDE는 **같은 보안 기준선**을 써야 합니다. CLI는 [CLI 구성](/guide/cli/configuration/)을 보세요.

### 컨텍스트 동작

일부 확장은 다음을 구성할 수 있습니다.

- 현재 파일 / 선택 영역 자동 포함 여부
- `AGENTS.md` 읽기 여부
- 컨텍스트 창 관련 옵션(버전 기준)

자동 컨텍스트가 과도하면 노이즈가 늘어납니다. [컨텍스트 초점 유지](/guide/context/keep-context-focused/)를 보세요.

### 로그인과 계정

[로그인과 인증](/guide/getting-started/sign-in-and-authentication/)과 공유합니다. 계정을 바꾼 뒤 확장 세션을 다시 시작하세요.

## 팀 정렬

1. **반드시 같아야 할** 항목은 저장소에 둡니다(`AGENTS.md` + 선택적 프로젝트 구성)
2. **개인 습관**은 IDE 설정에 두고 Git에 넣지 않습니다
3. 신규 멤버 onboarding: [IDE 설치](/guide/ide/installation/)와 대조해 확장 버전을 확인합니다

## 처음 볼 항목

IDE 확장을 처음 구성할 때는 세 종류만 보세요.

1. 모델과 추론 등급
2. 승인/보안 관련
3. 자동 컨텍스트 관련

이 세 가지를 맞추면 대부분 실제 사용 문제를 덮을 수 있습니다.

## 문제 해결

| 현상 | 점검 |
|---|---|
| 설정이 반영되지 않음 | 조직 정책 덮어쓰기 여부; 창 다시 로드 필요 여부 |
| CLI와 동작이 다름 | [구성 참고](/guide/reference/configuration-reference/)와 비교 |
| 확장 무응답 | [IDE 문제 해결](/guide/ide/troubleshooting/) |

IDE 설정은 “에디터에서 Codex와 어떻게 맞출지”에 가깝습니다. 프로젝트 규칙을 어떻게 쓸지는 다른 층이니 섞지 마세요.
