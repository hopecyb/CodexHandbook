일부 Codex 클라이언트는 **기억(Memory)**을 지원합니다. 여러 턴 대화에서 확인한 선호나 사실을 이후 세션까지 남깁니다. `AGENTS.md`·프로젝트 설정과 보완 관계이지만, 버전 관리되는 팀 규범을 **대체할 수 없습니다**.

## 내용

- 기억에 무엇을 두고, 무엇을 두지 않는지
- AGENTS.md, Memories 기능, 프로젝트 지침과의 우선순위
- 개인과 팀이 기억 내용을 어떻게 관리하는지

## 기억이 잘 맞는 용도

기억을 이렇게 이해하면 됩니다. **매번 다시 말하기엔 귀찮지만, 자꾸 반복해서 말하게 되는 것을 Codex가 대신 기억해 주는 층**입니다.

예:

- 설명을 한국어로 하는 습관
- 결론 먼저, 세부 나중
- 어떤 프로젝트에서 “백엔드”가 기본으로 가리키는 디렉터리

“개인 장기 선호와 소량의 안정적 사실”에 가깝고, 프로젝트 설명서도, 비밀 금고도 아닙니다.

## 기억에 두기 좋은 것

| 적합 | 부적합 |
|---|---|
| 개인 코딩 선호(주석 언어, 들여쓰기 습관) | 프로덕션 키, token |
| 반복 설명하는 프로젝트 별칭(「백엔드는 `services/api`」) | 바뀌는 sprint 작업 상태 |
| 「기억해 줘」라고 명시했고 비민감한 사실 | Git에 넣어야 할 팀 규범 |

팀급 규범은 **`AGENTS.md` 또는 프로젝트 설정**에 두어 review와 신규 onboarding이 가능하게 하세요. [범위와 우선순위](/guide/customization/agents-md/scope-and-precedence/)를 참고하세요.

## 흔한 오해

### 기억은 “뭐든 영원히 기억”하지 않습니다

한 번만 말하면 Codex가 이후에도 완전하고 안정적으로 기억한다고 착각하기 쉽습니다.

더 정확한 이해는, 기억이 반복 설명을 줄이는 보조 층이며, 문서와 저장소의 공식 정보를 대체하지 않는다는 점입니다.

### 기억은 팀 합의를 싣기에 맞지 않습니다

규칙이 당신 계정의 기억에만 있으면 다른 사람은 보지 못하고 review도 할 수 없습니다.

이런 내용은 다음으로 돌려보내세요.

- `AGENTS.md`
- 프로젝트 문서
- 설정 파일

### 기억은 민감 정보를 두는 곳이 아닙니다

클라이언트가 기억을 지원해도 다음을 장기 보관에 맡기지 마세요.

- token
- 고객 데이터
- 내부 계정
- 미공개 비즈니스 정보

## 관련 메커니즘 비교

| 메커니즘 | 누가 보나 | 변경 방식 |
|---|---|---|
| 단발 prompt | 현재 작업 | 직접 입력 |
| 기억 | 보통 당신 계정/워크스페이스만 | 대화에서 확인하거나 설정 페이지에서 관리 |
| `AGENTS.md` | 저장소 전체 협업자 | Git PR |
| 프로젝트 설정 | 설정 계층에 따름 | 파일 + 호스팅 정책 |

## 권장 사용법

1. **먼저 저장소에 쓰기**: 테스트 명령, 디렉터리 구조, push 금지 — 기억에만 두지 않음
2. **기억에는 개인 선호**: 예 「설명은 한국어」, 「diff 코멘트는 영어」
3. **정기 정리**: 프로젝트 아키텍처가 크게 바뀌면 낡은 기억 삭제
4. **민감 프로젝트**: 기억을 끄거나 제한해 프로젝트 간 컨텍스트 유출을 막음

## 기억에 둘지 판단하기

기억에 넣을지 모르겠으면 먼저 스스로에게 물어보세요.

1. 내가 자주 반복해서 말하는 개인 선호인가
2. 단기적으로 비교적 안정적인 사실인가
3. 다른 사람이 못 봐도 팀 협업에 영향이 없는가

세 가지가 모두 “예”에 가까울 때만 기억에 두기 좋습니다.

## 보안 경계

- 기억이 `AGENTS.md` 금지 항목을 우회하는 **비밀 통로**가 되게 두지 마세요
- 기억에 고객 데이터, 자격 증명, 미공개 재무 정보를 저장하지 마세요
- 기업 환경에서는 기억 기능이 비활성화될 수 있습니다 — 호스팅 정책을 따르세요

## 흔한 실수

- 「이번 주 완료할 epic 목록」을 기억에만 두어 협업자가 못 봄
- 기억과 `AGENTS.md`가 충돌하는데 어느 쪽도 갱신하지 않음
- 기억이 「모델이 저장소 전체를 영원히 기억한다」와 같다고 착각

기억은 “자꾸 반복하는 개인 선호와 소량의 안정적 사실”에 가장 잘 맞으며, 저장소 문서·팀 규칙·민감 정보 관리를 대체하기엔 맞지 않습니다.
