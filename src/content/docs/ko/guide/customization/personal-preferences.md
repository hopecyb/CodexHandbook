**개인 선호**는 로컬에서 프로젝트 전반에 적용되는 설정입니다. 기본 모델, 테마, 승인 습관, 개인 Skill 경로 등입니다. 저장소 안 `AGENTS.md`와 달리, 개인 선호는 동료가 **같다고 가정하면 안 됩니다**.

## 내용

- 무엇을 개인 계층에, 무엇을 프로젝트 계층에 둘지
- [Profile](/guide/customization/configuration/profiles/)과 어떻게 맞춰 장면을 전환할지
- 개인이 느슨한 설정이 팀 저장소로 새지 않게 하기

우선순위 개요: [개인화 설정](/guide/customization/) · [범위와 우선순위](/guide/customization/agents-md/scope-and-precedence/)

## 왜 이 계층을 구분하나

많은 사람이 다음을 먼저 섞습니다.

- 내가 개인적으로 어떻게 쓰고 싶은지
- 이 저장소가 어떻게 요구하는지
- 회사·팀이 강제로 어떻게 하는지

이 셋을 나누지 않으면 나중에 이런 일이 납니다.

- 내 로컬은 편한데 동료는 전혀 재현하지 못함
- 규칙이 이미 먹혔다고 착각하지만, 사실 내 로컬만 받쳐 줌
- 느슨한 설정을 더 엄격한 프로젝트에 가져감

## 개인 선호에 두기 좋은 내용

| 내용 | 예시 |
|---|---|
| 기본 모델과 추론 등급 | 개인 기기 성능과 요금제 |
| UI 테마, 글꼴, 알림 | 데스크톱 App [설정](/guide/desktop-app/settings/) |
| 개인 MCP(사설 도구) | 로컬 DB 읽기 전용(권한 신중) |
| 개인 Skill 라이브러리 경로 | 팀 Plugin과 충돌하지 않게 |
| 터미널 별칭, `codex` 시작 디렉터리 습관 | [CLI 설정](/guide/cli/configuration/) 참고 |

## 개인 계층에만 두면 안 되는 팀 내용

- 코드 스타일, 테스트 명령, 디렉터리 구조 → **프로젝트 `AGENTS.md`**
- 강제 샌드박스 정책 → **프로젝트 설정 또는 조직 호스팅**
- 고객 저장소 컴플라이언스 → **문서 + CI**, 개인 기억에 의존하지 않음

## 권장 실천

1. **업무 / 개인 Profile 분리**: 고객 프로젝트는 엄격 Profile, 연습 프로젝트는 느슨해도 됨
2. **새 저장소에 들어가면 프로젝트 규칙을 먼저 읽고**, 개인 기본값을 임시로 덮을지 결정
3. **개인 MCP와 Skill을 정기 정리**하고, 쓰지 않는 서드파티 소스를 제거
4. 기기 교체·재설치 시 설정 목록을 내보내기(키 값 제외)

## 흔한 오해

### 1. 평소 좋아하는 방식이 곧바로 전역 기본값이 되어도 되나?

기본 습관이 느슨하면 고객·팀 프로젝트에는 맞지 않을 수 있습니다.

### 2. 개인 선호와 프로젝트 규칙은 비슷하지 않나?

많이 다릅니다.  
개인 선호는 “나는 이렇게 한다”, 프로젝트 규칙은 “이 저장소에서는 다들 되도록 이렇게 한다”입니다.

### 3. 로컬만 괜찮으면 설정이 합리적이라고 볼 수 있나?

더 나은 기준은 다음과 같습니다.

- 저장소를 오염하지 않음
- 나만이 아는 기본값에 의존하지 않음
- 엄격한 프로젝트로 전환할 때 오해를 만들지 않음

## 개인 계층에 둘지 판단하기

설정이 개인 계층에 맞는지 헷갈리면 스스로에게 물어보세요.

1. 나만이 신경 쓰는 습관인가?
2. 다른 사람의 결과 재현에 영향을 주는가?
3. 모든 프로젝트에 가져가도 되나?

2번이나 3번이 위험 쪽으로 기울면 전역 기본값으로 쉽게 두지 마세요.

개인 선호는 당신이 더 손에 맞게 쓰기 위한 것이지, 팀 규칙을 대신 받쳐 주는 것도, 느슨한 설정을 모든 프로젝트에 한꺼번에 넣는 것도 아닙니다.

## 기억 기능과의 관계

제품이 「기억」이나 지속 선호를 제공하면 [기억과 지속 컨텍스트](/guide/customization/memories-and-persistent-context/)를 보세요. 기억은 안정적 습관에 맞고, **프로젝트 고유 제약은 여전히 저장소 파일이 기준**입니다.

## 흔한 실수

- 개인 설정에 회사 API key를 하드코딩
- 개인 전역에서 shell 자동 승인 후 고객 코드 처리
- 동료가 clone 후 「규칙이 안 먹혀」라고 함 — 규칙이 커밋된 적이 없음

## 검증 체크리스트

- [ ] 개인 vs 프로젝트 vs 조직 세 계층 사례를 각각 하나씩 말할 수 있음
- [ ] 고객 프로젝트 하나 이상에 엄격 Profile을 둠
- [ ] 저장소 안에 개인 키가 없음
