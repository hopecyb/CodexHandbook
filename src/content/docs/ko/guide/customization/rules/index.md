규칙 그룹은 초보자가 “Codex에 알림을 더 쓴다”로 오해하기 쉽습니다.

더 정확한 이해는, 규칙이 “어떤 동작은 기본 허용, 어떤 동작은 막고, 어떤 동작은 팀 기준으로 통일할지”를 푼다는 점입니다.

## 권장 순서

1. [허용과 거부 패턴](/ko/guide/customization/rules/allow-and-deny-patterns/)
2. [명령 규칙](/ko/guide/customization/rules/command-rules/)
3. [팀 규칙](/ko/guide/customization/rules/team-rules/)

## 이 그룹이 돕는 것

- 어떤 동작을 바로 막아야 하는지
- 어떤 제한을 구두 알림이 아니라 명확한 규칙으로 써야 하는지
- 팀이 같은 유형의 위험에 같은 경계를 갖게 하는 방법

규칙은 경계를 분명히 말해, 시스템이 경계대로 실행하게 합니다.

---

**상태:** verified  
**적용 제품:** App / CLI / Cloud  
**검증 근거:** 본 저장소의 현재 rules 하위 구조와 진입 링크를 교차 확인했습니다. 이 페이지는 “allow/deny, 명령 규칙, 팀 규칙으로 묶어 탐색”하는 역할만 하며, 구체 규칙 구현이나 기본 차단 동작을 단독으로 선언하지 않습니다.
