`AGENTS.md`는 저장소(또는 하위 디렉터리)에 두는 **Markdown 프로젝트 지침**입니다. Codex가 해당 프로젝트에 들어갈 때 읽어, 코딩 스타일·테스트 요구·커밋 규범·금지구역을 맞춥니다.

`AGENTS.md`를 “이 프로젝트에서 Codex가 어떻게 협력하길 바라는지”의 설명서로 이해하면 됩니다.

고급 아키텍처 문서도, 인간 신입용 완전한 핸드북도 아니며, Codex를 위한 프로젝트 협업 규칙입니다.

## 핵심 개념 하나

**신입 onboarding 핸드북의 압축판**으로 보세요. 「이 저장소에서 어떻게 일하는가」만 쓰고, 회사 연혁은 쓰지 않습니다.

| AGENTS.md에 쓰기 좋음 | 쓰기 나쁨 |
|---|---|
| 테스트·lint·빌드 실행 방법 | 완전한 API 문서(정식 문서로 링크) |
| 디렉터리 규약, 네이밍 스타일 | 수천 줄의 역사적 설계 결정 |
| 금지 사항(예: `main` 수정 금지, 키 커밋 금지) | 작업마다 다른 임시 요구 |
| 커밋 메시지, PR 체크리스트 | 코드와 무관한 개인 선호 |

## 최소 가용 실천

저장소 루트에 `AGENTS.md`를 만듭니다.

```md
# 프로젝트 지침

## 빌드와 테스트
- 설치: `pnpm install`
- 테스트: `pnpm test`(로직 변경 후 필수)
- 타입 검사: `pnpm typecheck`

## 코드 스타일
- TypeScript strict 모드 사용
- 새 컴포넌트는 `src/components/`에, 파일명은 PascalCase

## 금지
- 의존성 변경이 아니면 `pnpm-lock.yaml`을 수정하지 않음
- `.env` 또는 API 키를 커밋하지 않음
- 확인 없이 `git push` 하지 않음

## 완료 정의
- 관련 테스트 통과
- 신규 lint 오류 없음
- PR 설명에 검증 단계를 적음
```

저장 후에는 새 작업에 **이번 차이**만 쓰면 됩니다. 예: 「Safari에서 로그인 페이지 레이아웃 문제를 AGENTS.md 기준으로 고쳐 주세요.」

## 흔한 오해

### 1. 이 규칙을 매번 손으로 다시 말해야 하나?

보통은 아닙니다.  
`AGENTS.md`의 의미 중 하나가 바로 이것입니다.  
**안정적으로 변하지 않는 프로젝트 규칙**을 넣어, 새 작업을 열 때마다 반복 설명을 줄입니다.

### 2. “썼으니 Codex가 100% 그대로 한다”와 같나?

`AGENTS.md`는 중요하지만, 다음과도 함께 동작합니다.

- 이번 작업의 명시적 요구
- 제품의 권한·승인 메커니즘
- 샌드박스, 네트워크, 팀 정책

더 정확히 말하면 정렬을 돕는 것이지, 만능 강제기가 아닙니다.

### 3. 프로그래머가 아니면 이 파일을 신경 쓸 필요 없나?

기본 개념은 알아 두는 편이 좋습니다.  
직접 코드를 쓰지 않더라도, Codex가 한 프로젝트를 계속 다루게 한다면 `AGENTS.md`가 반복 설명과 이탈을 줄여 줍니다.

## 어디에 두나

| 위치 | 범위 |
|---|---|
| 저장소 루트 `AGENTS.md` | 전체 프로젝트 기본 적용 |
| 하위 디렉터리 `AGENTS.md` | 해당 디렉터리와 하위 경로(monorepo에 흔함) |
| 사용자급 설명 | 개인 설정 또는 전역 선호 — 프로젝트 지침과 혼동하지 않음 |

범위와 충돌 처리는 [범위와 우선순위](/guide/customization/agents-md/scope-and-precedence/)를 보세요.

## Skill·슬래시 명령과의 차이

| 메커니즘 | 본질 | 전형적 용도 |
|---|---|---|
| AGENTS.md | 지속·수동적 프로젝트 규칙 | 스타일, 테스트, 금지구역 |
| Skill | 재사용 가능한 워크플로 패키지(`SKILL.md`) | 릴리스 체크리스트, 전문 심사 흐름 |
| 슬래시 명령 | 당신이 능동적으로 트리거하는 단축 진입점 | `/review`, 일회성 워크플로 |

프로젝트 규칙은 `AGENTS.md`에 두고, **반복·공유 가능한 한 세트 단계**는 [Skill](/skills/overview/)로 만드는 편이 맞습니다.

## 어디에 쓸지 판단하기

문장을 어디에 둘지 모르겠으면 이 규칙을 쓰세요.

- **장기적으로 항상 성립**: `AGENTS.md`에 적합
- **이번 작업만의 특수 요구**: 현재 작업 프롬프트에
- **반복 재사용 가능한 단계 세트**: Skill 고려

예:

- “이 저장소는 `pnpm test`로 검증” → `AGENTS.md`
- “이번엔 로그인 페이지만, 회원가입은 건드리지 마” → 현재 작업
- “배포 전마다 같은 점검 흐름” → Skill이 더 적합

## 흔한 실수

- 파일이 너무 길어 모델이 앞부분만 읽음 — **하드 제약은 앞 30줄에**
- 「영원히 자동 push」 같은 고위험 지침을 써 [권한과 승인](/guide/foundations/permissions-and-approvals/)과 충돌
- 팀이 유지하지 않아 문서와 실제 스크립트 명령이 불일치

## 보안 경계

`AGENTS.md`는 샌드박스와 승인을 **대체하지 않습니다**. 「명령을 마음대로 실행해도 됨」이라고 써도 제품이 확인을 요구할 수 있고, 팀 호스팅 정책이 더 조일 수 있습니다.

`AGENTS.md`는 Codex에게 “이 프로젝트에서 평소 어떻게 일하는지”를 알려 주는 것이지, 이번 구체 작업을 대신 서술해 주는 것이 아닙니다.
