더 완전한 항목은 [용어집](/ko/guide/reference/glossary/)을 보세요. 여기에서는 가장 흔하고, 읽기에 가장 영향을 주는 말만 먼저 둡니다.

Codex 핸드북을 처음 볼 때 막히는 지점은 종종 명사가 너무 빽빽한 것입니다. 단어 하나씩은 알지만, 이어 붙이면 헷갈리기 쉽습니다.

흔한 경우는 두 가지입니다.

- 글자는 읽히지만, 실제 조작에서 무엇을 가리키는지 모름
- 지금 꼭 알아야 할 말과 나중에 알아도 되는 말을 구분하지 못함

용어 시험처럼 대하지 마세요. 대략 무엇을 말하는지 알고, 본문에서 자주 멈추지 않으면 됩니다.

## 먼저 알아 둘 말

목표가 첫 작업을 끝까지 돌리는 것이라면, 아래 6개부터 이해하세요.

| 용어 | 왜 먼저 |
|---|---|
| **프롬프트** | 작업을 어떻게 분명히 말하는지 |
| **컨텍스트** | Codex가 지금 볼 수 있는 정보 |
| **Agent** | 왜 한 단락 답변만이 아닌지 |
| **승인** | 왜 가끔 멈추고 묻는지 |
| **차이(diff)** | 무엇을 바꿨는지 어떻게 확인하는지 |
| **작업** | 한 번의 완전한 일의 기본 단위 |

| 용어 | 짧은 설명 |
|---|---|
| **프롬프트(prompt)** | Codex에 주는 목표·배경·요구 |
| **컨텍스트(context)** | 모델이 지금 볼 수 있는 프로젝트·파일·대화 정보 |
| **Agent** | 목표를 중심으로 도구를 호출하며 반복 추진하는 실행 방식 |
| **도구(tool)** | 파일 읽기·명령 실행·검색 등 호출 가능한 능력 |
| **샌드박스(sandbox)** | 파일 시스템·네트워크 영향 범위를 제한하는 실행 환경 |
| **승인(approval)** | 어떤 작업은 당신이 분명히 동의한 뒤에만 계속됨 |
| **차이(diff)** | 변경 전후 비교. 검토용 |
| **스레드 / 세션** | 이어진 대화와 누적 컨텍스트 |
| **작업** | 목표가 있는 일의 단위(여러 도구 호출에 걸칠 수 있음) |
| **Skill** | 재사용 가능한 전문 작업 설명·리소스 묶음(고급) |
| **MCP** | 외부 도구·데이터 소스를 연결하는 프로토콜(고급) |
| **Cloud 작업** | 클라우드 환경에서 실행하는 작업. 로컬 샌드박스가 아님 |

## 더 직설적으로

- **프롬프트**: 일을 맡길 때 하는 말
- **컨텍스트**: 지금 손에 쥔 자료
- **Agent**: 한 단락만 답하지 않고, 실제로 작업을 앞으로 밀어 감
- **승인**: 어떤 일은 혼자 못 하고, 당신의 동의가 필요함
- **diff**: 바꾸기 전과 후의 비교
- **Skill**: 고정된 방법을 묶어 재사용

## 쓰는 방법

다른 페이지에서 이 말들을 만나도 매번 정의를 찾을 필요는 없습니다.

- 대략 알면 계속 읽습니다
- 반복해서 보아도 흐리면 여기로 돌아옵니다
- 흐름 이해에 지장을 주면 해당 주제 페이지로 갑니다

## 묶어서 보기

한 번에 너무 많이 외우기 싫다면:

- 당신이 말하는 것: 프롬프트
- 그것이 보는 것: 컨텍스트
- 그것이 하는 방식: Agent, 도구
- 할 수 있는지: 승인, 샌드박스
- 당신이 확인하는 방식: diff, 작업 결과

## 나중에 봐도 되는 말

아래는 대개 고급이며, 처음에는 급히 파고들 필요가 없습니다.

- Skill
- MCP
- Hook
- Plugin
- Cloud 환경 세부

[첫 작업](/ko/guide/getting-started/run-your-first-task/)을 마친 뒤 다시 보면 이해가 더 수월한 경우가 많습니다.

모르는 말이 나오면 여기로 돌아와 확인한 뒤 계속 읽으면 됩니다.

핸드북을 처음 읽을 때는 이 말들을 힌트로만 두세요. 대략 무엇을 가리키는지 아는 편이, 처음부터 전부 외우는 것보다 현실적입니다.
