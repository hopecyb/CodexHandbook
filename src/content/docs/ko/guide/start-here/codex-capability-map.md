핸드북의 모듈이 많아 처음에는 흩어져 보이기 쉽습니다. 이 페이지는 주요 능력을 한 장에 모아 구조를 빠르게 맞춥니다.

흔한 막힘은 두 가지입니다.

- 여기저기 페이지를 보다가, 결국 무엇을 먼저 보완할지 모름
- 처음부터 MCP·자동화·확장에 뛰어들어, 기초가 정리되지 않음

큰 틀을 먼저 잡으면, 이후 구체 주제를 찾을 때 훨씬 수월합니다.

Codex는 채팅창만이 아니며, 뒤에 몇 겹의 능력이 있습니다.

```text
목표와 프롬프트
  → 컨텍스트(프로젝트 / 파일 / 대화)
    → 도구(파일, 터미널, 검색, 브라우저…)
      → Agent 작업(계획, 실행, 유도, 인수인계)
        → 품질 검증과 사람 승인
      → 확장과 자동화(Skills / MCP / Hooks…, 고급)
            → 팀 거버넌스(이후 마일스톤)
```

## 전체 구조

Codex를 세 층으로 볼 수 있습니다.

- 첫째 층: 어떻게 말해, 무엇을 원하는지 알리기
- 둘째 층: 어떤 컨텍스트와 도구로 일을 해내기
- 셋째 층: 이 협업 방식을 쌓아 두고 나중에 반복하기

처음에는 앞 두 층이 더 중요합니다. 작업을 분명히 말하고 결과를 안정적으로 낸 뒤, 고급 확장을 보세요.

## 흔한 오해

### 능력이 고급일수록 먼저 배워야 하는 것은 아닙니다

Skills, MCP, Hooks, 자동화는 강력하지만, 효율 확대와 규모 있는 재사용에 가깝고, 처음 막히는 지점을 푸는 핵심은 아닙니다.

프롬프트·컨텍스트·도구 선택 같은 기초가 정리되지 않으면, 확장도 잘못 쓰기 쉽습니다.

### 이 그림을 읽기 순서로도 쓸 수 있습니다

사이트 목차를 페이지마다 다 읽을 필요는 없습니다. 이 순서로 가도 됩니다.

1. Codex가 어떻게 작동하는지 이해합니다
2. 작업을 주고 방법·컨텍스트를 주는 방법·결과를 검증하는 방법을 배웁니다
3. 익숙해진 뒤 설정·확장·자동화를 고려합니다
