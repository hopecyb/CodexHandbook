## 지속 업데이트

이 핸드북은 단일 Codex 버전 번호에 오래 고정되지 않습니다. 제품이 바뀌므로, 페이지는 상태와 검증 날짜로 현재 신뢰도를 표시합니다.

## 내용

- 왜 이 핸드북이 영원히 변하지 않는다고 가정할 수 없는지
- 본문 끝의 상태와 검증 날짜를 어떻게 읽는지
- 공식과 충돌할 때 무엇을 믿어야 하는지

## 페이지 상태

| 상태 | 의미 |
|---|---|
| planned | 계획됨. 아직 작성 전 |
| draft | 작성 중 |
| review | 내용 완료. 재검토 대기 |
| verified | 표시된 근거로 검증됨 |
| outdated | 제품 변경 후 업데이트 필요 |
| archived | 역사 보존. 주 내비게이션에 넣지 않음 |

## 페이지 상태를 읽는 법

- `planned`: 아직 쓰지 않음
- `draft`: 쓰는 중이나 아직 불안정
- `review`: 본문은 갖춰졌으나 가장 강한 확인 단계는 아님
- `verified`: 표시된 근거로 이미 검증됨
- `outdated`: 예전에는 맞았을 수 있으나 지금은 시효에 주의
- `archived`: 참고용으로 남김. 현재 주선 콘텐츠로 쓰지 않음

## 본문 끝 세 줄

MVP 단계에서는 매 페이지 끝에 **상태 / 적용 제품 / 최근 검증**을 표시합니다. 쉽게 시효가 되는 내용(설치·계정·권한·모델)에는 공식 링크를 붙입니다.

## 공식 근거

제품 동작은 OpenAI 문서를 기준으로 합니다: [https://developers.openai.com/codex](https://developers.openai.com/codex). 이 저장소는 커뮤니티 가이드이며, 공식과 충돌하면 공식을 따르고 issue로 알려 주시면 좋습니다.

## 흔한 오해

### 1. 핸드북에 쓰였다고 해서 오래 변하지 않는 것은 아닙니다

특히 아래가 자주 바뀝니다.

- 설치 방식
- 로그인·계정 흐름
- 권한·모델·설정 항목
- Cloud와 제품 입구 동작

### 2. `review`는 「보면 안 된다」가 아닙니다

`review`는 본문이 이미 있으나 가장 강한 확인 단계는 아니라는 뜻이며, 참고 자체가 금지된 것은 아닙니다.

### 3. 커뮤니티 핸드북과 공식 문서가 충돌하면 반반 믿을 수 없습니다

이렇게 나누면 됩니다.

- 이해와 경로 설명은 핸드북
- 최신 동작·파라미터 표기는 공식

## 한 페이지가 믿을 만한지 판단하는 법

시효가 걱정되면 세 가지를 보세요.

1. 본문 끝 상태가 `review`, `verified`, `outdated` 중 무엇인지
2. 최근 검증 날짜가 지금과 얼마나 먼지
3. 개념인지, 설치·설정·권한처럼 쉽게 바뀌는 내용인지

최신 동작·파라미터·규칙은 최종적으로 공식 현재 문서를 기준으로 합니다.
