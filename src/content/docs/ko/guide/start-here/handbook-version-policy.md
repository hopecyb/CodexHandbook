## 지속 업데이트

이 핸드북은 하나의 Codex 버전에 장기간 고정되지 않습니다. 제품이 바뀌므로 각 페이지는 상태, 검증 날짜, 구체적인 근거로 확인한 범위를 설명합니다. 날짜만으로 신뢰도를 평가할 수는 없습니다.

## 내용

- 왜 이 핸드북이 영원히 변하지 않는다고 가정할 수 없는지
- 페이지 맨 위의 상태와 검증 날짜를 읽는 방법
- 공식과 충돌할 때 무엇을 믿어야 하는지

## 페이지 상태

| 상태 | 의미 |
|---|---|
| planned | 계획됨. 아직 작성 전 |
| draft | 작성 중 |
| review | 내용 완료. 재검토 대기 |
| verified | 표시된 근거로 검증됨 |
| outdated | 제품 변경 후 업데이트 필요 |
| archived | 역사 보존. 주 내비게이션에 넣지 않음 |

## 페이지 상태를 읽는 법

- `planned`: 아직 쓰지 않음
- `draft`: 쓰는 중이나 아직 불안정
- `review`: 본문은 갖춰졌으나 가장 강한 확인 단계는 아님
- `verified`: 표시된 근거로 이미 검증됨
- `outdated`: 예전에는 맞았을 수 있으나 지금은 시효에 주의
- `archived`: 참고용으로 남김. 현재 주선 콘텐츠로 쓰지 않음

## 검증 기록과 콘텐츠 업데이트

페이지 맨 위에는 편집 상태, 검증 방법, 검증 날짜, 적용되는 근거가 각각 표시됩니다. `editorial`은 편집 검토, `source-checked`는 출처 대조, `run-tested`는 기록된 환경에서 예제를 실제 실행했다는 뜻입니다. 이 방법들은 서로를 대신하지 못합니다. 과거 기록은 따로 보존되며 현재의 실행 테스트 근거로 자동 승격되지 않습니다.

[콘텐츠 업데이트와 정정](/ko/guide/updates/)은 구체적인 변경 사항과 영향을 설명합니다. 중국어 본문 페이지의 맨 아래에서는 현재 페이지 정보가 담긴 GitHub 정정 초안을 열 수 있습니다. 제출 전 내용을 확인하고 민감한 정보를 제거해야 합니다.

## 공식 근거

제품 동작은 OpenAI 문서를 기준으로 합니다: [https://developers.openai.com/codex](https://developers.openai.com/codex). 이 저장소는 커뮤니티 가이드이며, 공식과 충돌하면 공식을 따르고 issue로 알려 주시면 좋습니다.

## 흔한 오해

### 1. 핸드북에 쓰였다고 해서 오래 변하지 않는 것은 아닙니다

특히 아래가 자주 바뀝니다.

- 설치 방식
- 로그인·계정 흐름
- 권한·모델·설정 항목
- Cloud와 제품 입구 동작

### 2. `review`는 「보면 안 된다」가 아닙니다

`review`는 본문이 이미 있으나 가장 강한 확인 단계는 아니라는 뜻이며, 참고 자체가 금지된 것은 아닙니다.

### 3. 커뮤니티 핸드북과 공식 문서가 충돌하면 반반 믿을 수 없습니다

이렇게 나누면 됩니다.

- 이해와 경로 설명은 핸드북
- 최신 동작·파라미터 표기는 공식

## 한 페이지가 믿을 만한지 판단하는 법

시효가 걱정되면 세 가지를 보세요.

1. 페이지 맨 위의 편집 상태가 `review`, `verified`, `outdated` 중 무엇인지
2. 최근 검증 날짜가 지금과 얼마나 먼지
3. 개념인지, 설치·설정·권한처럼 쉽게 바뀌는 내용인지

최신 동작·파라미터·규칙은 최종적으로 공식 현재 문서를 기준으로 합니다.
