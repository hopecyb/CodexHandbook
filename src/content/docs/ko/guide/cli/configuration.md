CLI 구성은 **기본 모델, 작업 디렉터리, 승인 엄격도, MCP 서버** 등을 정합니다. [구성 기초](/ko/guide/customization/configuration/config-basics/) 개념과 일치하며, 이 페이지는 터미널 사용자가 자주 바꾸는 항목에 초점을 둡니다.

## 이 페이지의 내용

많은 사람이 CLI 구성을 처음 접하면 “고급 설정 패널”로 생각합니다. 그러면 두 가지 오해가 생기기 쉽습니다.

- 안 해도 된다고 생각해, 시작할 때마다 같은 설정을 수동으로 반복
- 구성이 많을수록 전문적이라 생각해, 개인 선호·팀 규칙·임시 실험을 한곳에 몰아 넣고 나중에 점검이 어려움

여기서는 **오래 고정할 설정과, 임시로만 바꿀 설정**을 구분합니다.

## CLI 구성이 다루는 것

CLI 구성은 “Codex의 터미널 기본 작업 습관”으로 이해하면 됩니다.

- 모델 구성: 기본적으로 누구에게 일을 맡길지
- 샌드박스와 승인: 기본적으로 어디까지 할 수 있고, 어디서 고개를 끄덕여야 하는지
- 작업 디렉터리: 기본적으로 어느 프로젝트에서 일하는지
- MCP와 확장: 기본적으로 어떤 외부 능력을 빌릴 수 있는지

아무것도 구성하지 않아도 Codex는 동작합니다. 다만 같은 선택을 더 자주 반복하게 됩니다.

## 구성을 어디에 두나요

| 계층 | 용도 |
|---|---|
| 사용자급 | 개인 기본값, 프로젝트 간 공유 |
| 프로젝트급 | 팀 공유 전략(커밋 전 검토 필요) |
| 환경 변수 | CI에 키와 스위치 주입 |

**경로와 파일명**은 CLI 버전에 따라 달라지므로 [공식 문서](https://developers.openai.com/codex)를 기준으로 하세요. 흔히는 사용자 디렉터리의 `config.toml` 또는 동등 파일입니다.

## 흔한 오해

### 모든 구성을 프로젝트에 넣어야 하는 것은 아닙니다

많은 초보자가 “내가 좋아하는 기본 모델”“본기 경로”“팀이 지켜야 할 승인 전략”을 섞습니다.

더 명확한 구분:

- 개인 장기 선호 → 사용자급
- 이 저장소에서 모두 같아야 할 것 → 프로젝트급
- CI·스크립트·특정 실행에만 임시 주입 → 환경 변수

### 구성이 곧 권한이 즉시 열린다는 뜻은 아닙니다

어떤 전략을 구성에 썼다고 해서 이후 모든 동작이 무조건 통과되지는 않습니다. 실제 동작은 제품 입구·실행 환경·관리형 정책·작업 내용의 영향도 받습니다.

구성은 기본 경향에 가깝고, 영구 특권이 아닙니다.

## 자주 바꾸는 항목

### 기본 모델과 추론 강도

속도·비용·복잡 작업 성공률에 영향을 줍니다. 스크립트 장면에서는 **모델을 고정**해 로그 비교가 쉽도록 하세요.

### 샌드박스와 네트워크

| 설정 의도 | 설명 |
|---|---|
| 엄격 | 신뢰할 수 없는 저장소에 적합 |
| 표준 | 일상 개발 |
| 완화 | 개인 신뢰 환경만, 회사 정책에 부합할 때 |

개념: [샌드박스와 네트워크](/ko/guide/foundations/sandbox-and-network/)

### 승인 전략

CLI는 shell 실행·디스크 쓰기·네트워크 전에 물을 수 있습니다. 팀은 `AGENTS.md`에 어떤 명령을 예상 자동 통과로 둘지 명시해야 하며, 제품 실제 동작과 일치할 때만 유효합니다.

### MCP 서버 목록

[MCP 서버 연결](/ko/skills/mcp/connect-an-mcp-server/)과 구성을 공유합니다. 변경 후 세션을 다시 시작하세요.

## 충분한 구성 순서

처음에는 모든 필드를 파고들 필요가 없습니다. 이 순서가 훨씬 편합니다.

1. 가장 자주 쓰는 모델을 먼저 고정
2. 기본 작업 디렉터리가 현재 프로젝트인지 확인
3. 승인·샌드박스를 보수적으로 할지 완화할지 결정
4. 마지막에 MCP·자동화·고급 확장을 추가

앞 두 항목은 일상에 가깝고, 뒤 두 항목은 위험 제어에 가깝기 때문입니다.

## 프로젝트와 CLI 정렬

「App에서는 되고 CI에서는 실패」를 피하세요.

1. README에 권장 CLI 최소 버전을 명시
2. 프로젝트급 구성에는 **팀 합의** 항목만
3. 키는 절대 저장소에 넣지 않음

## 문제 해결

| 현상 | 점검 |
|---|---|
| 구성이 반영되지 않음 | 계층을 잘못 바꿨는지; 재시작 필요 여부 |
| MCP가 로드되지 않음 | JSON/TOML 문법, 경로 |
| 승인이 너무 잦음 | 샌드박스 모드와 allowlist |

더 보기: [CLI 문제 해결](/ko/guide/cli/troubleshooting/)

CLI 구성을 “기본 작업 습관”으로 보고, **거의 매번 반복해 고르는** 것만 고정하세요. 고급 능력은 나중에 보완해도 됩니다.
