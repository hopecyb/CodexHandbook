“대화형 모드”는 터미널에서 Codex와 한 왕복씩 대화하는 방식입니다. 설명하고 실행하며, 필요할 때 확인을 기다립니다.

CLI의 흔한 사용법 중 하나입니다.

대화형 세션을 시작한 뒤:

1. 프로젝트 디렉터리에서 시작합니다(또는 문서에 지정된 작업 디렉터리)
2. App과 같은 품질의 프롬프트를 입력합니다
3. 요청이 오면 도구 호출을 승인/거부합니다
4. `/` 계열 단축 명령(있는 경우)으로 세션을 관리합니다—현행 CLI 도움말 기준

프롬프트 방법은 그대로 적용됩니다: [프롬프트](/prompts/)

## 흔한 오해

### 1. 터미널에서 쓰니 프롬프트를 대충 해도 되나요?

안 됩니다.

입구가 터미널로 바뀌어도 작업 설명 품질은 똑같이 중요합니다.  
목표·범위 제한·완료 기준은 여전히 분명할수록 안정적입니다.

### 2. 왜 “프로젝트 디렉터리에서 시작”을 강조하나요?

CLI가 어느 프로젝트에서 일하는지 알아야 하기 때문입니다.  
디렉터리가 틀리면 다음이 생기기 쉽습니다.

- 봐야 할 파일을 못 봄
- 잘못된 디렉터리를 수정
- 프로젝트 규칙을 못 읽음

### 3. 터미널에서 승인 여부를 물으면 오류인가요?

많은 경우 권한 경계에 따라 동작하는 것이며, 비정상 실행이 아닙니다.

## 처음 쓸 때 간단한 장면

처음에는 이런 작은 작업을 하세요.

- 프로젝트 루트에서 시작
- 파일 하나만 수정
- 끝난 뒤 무엇을 바꿨는지 설명하게 함

CLI 대화형 모드는 터미널에서 대화식 작업 흐름을 돌리는 것입니다. 디렉터리가 맞아야 하고, 프롬프트도 분명해야 합니다.
