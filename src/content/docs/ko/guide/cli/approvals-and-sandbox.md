CLI에서 Agent는 **파일을 읽고, 쓰고, shell을 실행하고, 네트워크에 연결할 수** 있습니다. 승인과 샌드박스는 당신과 자동화 사이의 안전 밸브입니다. 구성이 잘못되면 대화형에서 팝업이 잦아지거나, CI 무인 운전에서 위험이 커집니다.

## 이 페이지의 내용

- 승인 팝업이 묻는 것과 고르는 법
- 샌드박스 등급이 파일과 네트워크에 미치는 영향
- 팀이 CLI와 `AGENTS.md` 사이에서 전략을 맞추는 법

## 승인과 샌드박스가 각각 다루는 것

이렇게 기억하세요.

- **승인**은 “이 단계를 계속해도 되나?”를 묻습니다
- **샌드박스**는 “계속해도, 어디까지 닿을 수 있나?”를 제한합니다

둘이 함께 작동하며, CLI 사용이 보수적인지 경계가 너무 열린지를 좌우합니다.

개념 기초: [권한과 승인](/guide/foundations/permissions-and-approvals/) · [샌드박스와 네트워크](/guide/foundations/sandbox-and-network/)

## 승인이 일어나는 때

전형적 트리거(제품 기준):

| 조작 유형 | 위험 | 기본 경향 |
|---|---|---|
| 프로젝트 안 파일 쓰기 | 중 | 자주 확인 필요 |
| 프로젝트 밖 경로 쓰기 | 고 | 거부하거나 엄격히 확인 |
| shell 실행 | 고 | 명령 내용 확인 |
| 네트워크 / curl | 고 | 대상과 데이터 확인 |
| MCP 도구 호출 | 서버에 따라 | 도구 단위로 |

대화형에서는 **한 번 허용 / 세션 허용 / 거부** 등의 옵션이 있습니다(이름은 버전에 따라 다름). **이해하지 못한 명령에 「항상 허용」을 누르지 마세요.**

## 샌드박스 등급(개념)

| 등급 의도 | 적합 |
|---|---|
| 엄격 / 읽기 전용 | 신뢰할 수 없는 코드 검토, CI 읽기 전용 검토 |
| 표준 | 일상 개발 저장소 |
| 완화 | 개인 신뢰 환경, 회사 정책에 부합할 때 |

샌드박스가 제한할 수 있는 것:

- 쓰기 가능 디렉터리 범위
- `$HOME`의 다른 프로젝트 접근 여부
- 하위 프로세스와 네트워크 능력

구성 입구: [CLI 구성](/guide/cli/configuration/) · 매트릭스: [권한 매트릭스](/guide/reference/permission-matrix/)

## 대화형 vs 비대화형

| 모드 | 승인 특징 |
|---|---|
| 대화형 `codex` | 사람이 있어 건별로 판단 가능 |
| 비대화형 `exec` | 당신이 없으므로 샌드박스를 미리 조이고 프롬프트를 고정해야 함 |

CI 필독: [비대화형 모드](/guide/cli/non-interactive-mode/) · [사람 승인 패턴](/cases/workflows/human-approval-patterns/)

권장 CI 원칙:

- 읽기 전용이거나 쓰기 경로를 한정
- 임의 `curl`로 저장소 내용 업로드 금지
- 실패 시 비영 종료, 로그 보존

## allow/deny 규칙과의 관계

프로젝트는 [허용과 거부 규칙](/guide/customization/rules/allow-and-deny-patterns/)에서 「예상 가능 명령」을 선언할 수 있습니다. **규칙은 실제 제품 동작과 일치해야** 하며, 그렇지 않으면 Agent가 여전히 막히거나 오히려 과도하게 열립니다.

## 흔한 실수

- 본기 전역 「모든 shell 자동 승인」 후 고객 저장소 처리
- `sudo`·DB 삭제·`~/.ssh` 변경 류 명령을 잘못 통과
- CI에 개발기 완화 설정을 그대로 사용
- 샌드박스가 코드 검토를 대체한다고 가정—오조작을 막을 뿐, 악성 프롬프트 주입을 막지 않음

## 흔한 오해

### 팝업이 많다고 설정이 잘못된 것은 아닙니다

CLI를 막 배우기 시작하면 승인이 많은 편이 오히려 안전합니다. 각 단계가 무엇을 하는지 보게 만들기.

진짜 경계해야 할 것은, 내용을 보지 않고 통과를 누르기 시작한 경우이지, 질문이 많은 경우가 아닙니다.

### 한 번 완화했다고 이후가 모두 안전한 것은 아닙니다

어떤 사람은 편의를 위해 규칙을 크게 완화한 뒤, 다른 저장소·다른 작업에도 같은 설정을 이어 씁니다.

안전 경계는 작업 위험을 따라야 하며, 지난번이 편했다는 이유만으로 이번도 문제없다고 기본값으로 두면 안 됩니다.

## 검수 체크리스트
