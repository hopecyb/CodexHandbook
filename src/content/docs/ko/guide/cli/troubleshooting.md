CLI에 문제가 생기면 오류가 모두 터미널 오류처럼 보이지만, 이면 원인이 같지는 않습니다.

CLI 문제 해결 시, 문제가 “설치 미완 / 미로그인 / 권한 없음 / 잘못된 디렉터리” 중 어디에 속하는지 먼저 판단하세요.

| 증상 | 먼저 시도 |
|---|---|
| command not found | 설치와 PATH 확인 |
| 인증 실패 | 다시 로그인; 조직 정책 확인 |
| 권한 거부 | 승인 모드와 샌드박스 설정 확인 |
| 잘못된 디렉터리에서 파일 수정 | 현재 작업 디렉터리 확인 |

## 먼저 4가지로 나눕니다

- **명령 자체를 못 찾음**: 대개 설치 또는 `PATH`
- **명령은 되지만 들어가지 못함**: 대개 인증
- **들어가지만 일을 못 함**: 대개 권한 또는 샌드박스
- **일은 했지만 잘못함**: 대개 디렉터리 또는 컨텍스트가 틀림

## 흔한 오해

### 1. 모든 CLI 오류를 같은 로그에서 파야 하나요

먼저 큰 범주로 나누는 편이, 처음부터 오류 세부만 파는 것보다 보통 더 빠릅니다.

### 2. 권한 거부는 프로그램이 망가진 건가요

많은 경우 망가진 게 아니라, 승인·샌드박스·정책이 정상 동작하는 것입니다.

### 3. 명령이 실행되면 디렉터리는 문제없나요

아닙니다.

CLI의 많은 문제는 명령이 안 도는 게 아니라, 잘못된 저장소나 잘못된 작업 디렉터리에서 도는 것입니다.

## 점검 순서

1. 명령이 존재하는지 먼저 확인
2. 로그인 상태를 확인
3. 현재 권한 모드와 샌드박스 제한을 확인
4. 마지막으로 현재 작업 디렉터리가 생각한 프로젝트인지 확인

CLI 문제 해결은 설치·로그인·권한·디렉터리 중 어디인지 먼저 나누면 점검이 수월해집니다.
