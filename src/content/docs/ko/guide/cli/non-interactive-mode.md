비대화형 모드는 Codex가 **TTY 대화 없이** 작업을 마치게 하며, 개발자가 Agent를 스크립트와 CI에 연결하는 입구입니다.

간단히 말해, 비대화형 모드는 주고 채팅이 아니라 작업을 한 번에 넘겨 실행하는 방식입니다.

명령형 호출에 더 가깝습니다.

## 이 페이지의 내용

- 비대화형을 `codex` 대화형 세션 대신 쓸 때
- 무인 운전 시 보안·승인의 추가 요구
- [구성](/guide/cli/configuration/)과의 관계

## 적용 장면

| 적합 | 부적합 |
|---|---|
| CI에서 고정 검토 프롬프트 실행 | 다라운드 요구 명확화가 필요 |
| nightly 문서 링크 점검 | 탐색적 리팩터 |
| 사전 정의 템플릿의 코드 생성 | 모호한 제품 의사결정 |

## 핵심 개념

비대화형 실행은 보통:

1. 매개변수 또는 stdin으로 **완전한 작업 설명**을 받음
2. 지정 작업 디렉터리에서 실행
3. 종료 코드로 성공/실패를 표시
4. 로그 또는 구조화 결과를 출력해 하류가 소비

**명령 이름과 매개변수는 공식 CLI 문서를 기준**으로 합니다(흔히 `codex exec` 또는 동등 하위 명령). CLI 업그레이드 후 `--help`를 다시 확인하세요.

## 최소 사용 예시(예시)

```bash
# 저장소 루트에서 읽기 전용 검토(예시, 매개변수는 공식 기준)
codex exec --cwd . "main 대비 diff의 보안 위험을 나열하고, 파일은 수정하지 말 것"
```

실무 제안:

- shell 스크립트에서 먼저 깨끗한 작업 복사본으로 `cd`
- 작업 문자열은 heredoc 또는 버전 관리되는 `prompts/` 파일에 둠
- 종료 코드를 캡처하고, 실패 시 CI를 빨갛게

## 보안 설계

무인 운전 = **거부를 눌러 줄 당신이 없음**:

| 원칙 | 방법 |
|---|---|
| 최소 권한 | 읽기 전용 token, 제한된 샌드박스 |
| push 없음 | CI는 PR만 열거나 artifact만 업로드 |
| 고정 프롬프트 | PR 설명에서 소독되지 않은 텍스트를 바로 이어 붙이지 않음(주입 위험) |
| 감사 | 로그와 diff artifact 보존 |

참고: [사람 승인 패턴](/cases/workflows/human-approval-patterns/)와 로드맵 `08-developer-platform/non-interactive/`.

## 대화형 모드와 비교

| | 대화형 모드 | 비대화형 모드 |
|---|---|---|
| 입구 | `codex` TUI | `exec` / 파이프 |
| 사람 개입 | 강함 | 약함, 사전 설계 필요 |
| 학습에 적합 | 예 | 아니오 |
| CI에 적합 | 아니오 | 예 |

대화형 사용법: [CLI 대화형 모드](/guide/cli/interactive-mode/)

## 흔한 오해

### 1. 비대화형이 더 효율이니 먼저 배워야 하나요?

권하지 않습니다.

처음 쓰는 사람에게 비대화형은 보통 너무 빠르고 딱딱하며, 중간에 명확화할 여지가 적습니다.

### 2. 대화형과의 가장 큰 차이는?

핵심 차이를 이렇게 보면 됩니다.

- **대화형 모드**: 중간에 묻고, 고치고, 승인할 수 있음
- **비대화형 모드**: 한 번 실행에 가깝고, 미리 정의된 흐름에 적합

### 3. 당분간 건드리지 말아야 할 때는?

다음 단계라면 잠시 미루세요.

- 프롬프트 쓰는 법에 아직 익숙하지 않음
- 결과를 검수하는 법을 모름
- 승인·샌드박스·권한에 대한 기본 판단이 없음

비대화형은 자동화에 맞고, 첫 탐색에는 잘 맞지 않습니다. 대화형을 익힌 뒤 스크립트에 연결하세요.

## 흔한 실수

- 대화형 세션의 긴 대화 이력을 그대로 단일 exec에 넣음
- CI에 프로덕션 자격 증명과 쓰기 권한을 사용
- CLI 버전을 고정하지 않아 파이프라인 동작이 갑자기 바뀜
