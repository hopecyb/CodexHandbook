터미널 효율은 세 덩어리에서 옵니다. **시작 방식**, **세션 내 단축 조작**, **스크립트/에디터와의 맞춤**. 이 페이지는 사용법과 습관을 다룹니다. 매개변수 표는 [CLI 명령 참고](/guide/reference/commands/)와 [키보드 단축](/guide/reference/keyboard-shortcuts/)을 보세요.

## 이 페이지의 내용

- `codex`와 `codex exec`를 언제 쓰는지
- 대화형 세션의 흔한 조작 유형
- 반복 조작을 별칭이나 스크립트로 굳히는 법

## 먼저 구분할 것

많은 초보자가 CLI를 처음 보면 “명령과 단축”을 문법·매개변수 암기로 생각합니다.

더 실질적인 것은 세 가지를 먼저 구분하는 일입니다.

- 지금 **대화하며 하는** 중인지
- **한 번에 작업을 끝내게** 할지
- 자주 반복하는 동작을 조금 **짧게** 만들고 싶은지

이걸 나누면 많은 명령 선택이 훨씬 분명해집니다.

## 명령 입구 한눈에

| 하려는 일 | 입구 | 상세 |
|---|---|---|
| 대화하며 코드 수정 | `codex` 대화형 TUI | [대화형 모드](/guide/cli/interactive-mode/) |
| CI / 파이프 단일 작업 | `codex exec`(또는 동등) | [비대화형 모드](/guide/cli/non-interactive-mode/) |
| 기본 동작 변경 | 구성 파일 | [CLI 구성](/guide/cli/configuration/) |

:::note
하위 명령 이름은 버전에 따라 달라지므로 `codex --help`를 기준으로 하세요.
:::

## 흔한 오해

### `codex`와 `codex exec`는 초급·고급이 아닙니다

많은 사람이 이렇게 이해합니다.

- 하나는 간단한 모드
- 하나는 전문 모드

더 실용적인 구분:

- `codex`는 당신이 있어 보며 유도할 때
- `codex exec`는 작업을 미리 분명히 말해 한 번 흐름으로 실행할 때

### 단축이 많을수록 좋은 것은 아닙니다

처음에는 모든 단축키와 `/` 명령을 외울 필요가 없습니다.

먼저 익히세요.

- 세션을 시작하는 법
- 현재 환경이 지원하는 `/` 명령을 확인하는 법
- 종료·다시 열기·디렉터리 바꾸기

이 정도면 충분합니다.

## 대화형 세션의 「단축」

버전마다 구체 키와 `/` 명령은 다르지만, 범주는 안정적입니다.

### 입력과 이력

- 여러 줄 입력: 제품 설명에 따른 줄바꿈 조합(흔히 `Shift+Enter` 또는 에디터 모드)
- 이전 작업 되돌아보기: 터미널 이력 또는 세션 내 이력(있는 경우)

### 슬래시 명령

프롬프트에 `/`를 입력하면 내장 흐름(검토, 컨텍스트 압축 등)이 트리거됩니다. **목록을 외우지 마세요**—현재 환경의 `/` 완성을 기준으로 하세요. 학습용 분류는 [슬래시 명령 빠른 참조](/guide/reference/slash-commands/)를 보세요.

### 승인 관련

Agent가 shell 실행이나 파일 쓰기를 요청하면 대화형 UI가 승인/거부/항상 허용(제공 시)을 묻습니다. 무인 운전 전에 반드시 [승인과 샌드박스](/guide/cli/approvals-and-sandbox/)를 읽으세요.

## Shell 층 단축(권장)

「프로젝트 진입 + Codex 시작」을 함수로 써 디렉터리 오류를 줄이세요.

```bash
# ~/.zshrc 예시(필요에 맞게 수정)
cx() {
  cd "$1" || return 1
  codex
}
```

비대화형 검토는 스크립트로 감싸고, prompt는 `prompts/review.md`에 두면 버전 관리가 쉽습니다.

## 이렇게 익히세요

CLI를 처음 쓸 때는 이 순서로:

1. 올바른 디렉터리에서 `codex`를 먼저 시작
2. 언제 `codex exec`를 쓸지 판단
3. 마지막에 고빈도 동작을 alias·함수·스크립트로 정리

도구를 익히기도 전에 한 겹 더 감싸는 상황을 피하기 쉽습니다.

## IDE / App과의 역할

| | CLI | IDE 확장 |
|---|---|---|
| 컨텍스트 | `--cwd`, @ 파일(버전에 따라) | 열린 파일, 선택한 코드 |
| 적합 | 스크립트, SSH 원격, 순수 터미널 | 고치면서 diff 보기 |
| 단축 | 터미널 키 + `/` | 에디터 명령 팔레트 |

IDE: [로컬 작업 워크플로](/guide/ide/local-task-workflow/)

## 흔한 실수

- 잘못된 디렉터리에서 시작해 옆 프로젝트를 수정
- 앱 내 `/review`를 터미널 하위 명령처럼 외부 shell에서 실행
- 대화형 세션에 검토하지 않은 제3자 「만능 prompt」를 붙여넣기

모든 명령과 단축키를 외울 필요는 없습니다. “지금 대화하며 할지, 한 번에 끝낼지”만 먼저 나누면 명령 선택이 훨씬 단순해집니다.

## 검수 체크리스트

- [ ] 최소 `codex exec` 읽기 전용 작업을 쓸 수 있음(환경이 제공하면)
