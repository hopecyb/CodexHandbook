> MVP 상태：이 페이지는 개요입니다. 완전한 다섯 단계(리서치, 글쓰기, 이미지와 데모, 웹 프로토타입, 재사용 가능한 워크플로)는 이후 마일스톤에서 보완합니다.

Codex로 주로 콘텐츠를 만들고, 코드를 고치는 용도가 아니라면, 이 경로부터 시작하세요.

## 맞는 경우

- 글, 설명문, 스크립트 콘텐츠를 쓰는 사람
- 이미지·텍스트, 데크, 페이지 프로토타입을 만드는 사람
- “창작 요구를 분명히 + 결과 검수를 분명히”하는 방법을 익히고 싶은 사람

- [산출물 검증](/guide/quality/verify-artifacts/)：원고와 페이지 검사
- [데스크톱 App](/guide/desktop-app/)：터미널을 쓰지 않는 사용자의 주 입구

## 흔한 오해

### 1. 크리에이터 경로는 “대신 써 주게 하는 것”이다

그것만으로는 부족합니다.

더 중요한 것은 다음과 같습니다.

- 목표, 독자, 스타일을 어떻게 분명히 말할까
- 생성된 콘텐츠를 쓸 수 있는지 어떻게 판단할까
- 여러 라운드 창작이 점점 빗나가지 않게 하려면

### 2. 프로그래머가 아니니 검증은 안 봐도 된다

콘텐츠 작업도 예외가 아닙니다.

콘텐츠도 검증이 필요합니다. 다만 초점이 구조, 톤, 사실, 형식, 전달 효과처럼 다를 뿐입니다.

## 계획 중인 단계(개요)

리서치와 주제 → 글쓰기와 편집 → 이미지와 데모 → 웹과 프로토타입 → 재사용 가능한 콘텐츠 워크플로
