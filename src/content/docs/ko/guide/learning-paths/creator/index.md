한 묶음의 자료로 글을 쓰고 편집 가능한 발표 자료로 만든 다음, 다음에도 쓸 작업 지시를 저장한다. 단계마다 파일이 남으므로 그것으로 완료 여부를 확인할 수 있다.

Codex에서 로컬 폴더를 열 수 있어야 한다. 발표 자료 제작에는 PPTX를 만들 수 있는 도구와 파일을 열 수 있는 발표 프로그램도 필요하다. 구체적인 환경은 사례를 참고하며, 모든 클라이언트에 같은 도구가 있다고 가정하지 않는다. 파일 작업이 익숙하지 않다면 먼저 [파일 다루기](/ko/guide/learning-paths/beginner/02-work-with-files/)를 마친다.

## 경로와 자료

| 단계 | 필요한 입력 | 이번 단계 결과물 | 다음 단계 |
|---|---|---|---|
| 1. 근거 정리 | 합성 자료 세 개와 출처 색인 | 사실표, 충돌·누락 목록 | 글 쓰기 |
| 2. 작성과 수정 | 사실표, 독자, 개요 | 글, 주장 대응표, 수정 설명 | 발표 자료 만들기 |
| 3. 발표 자료 만들기 | 글, 주장 대응표, 발표 목적 | 8장 PPTX, 미리보기 8장, 노트와 확인 기록 | 재사용 지시 저장 |
| 4. 재사용 지시 저장 | 앞의 세 단계 결과와 경험 | 작업 템플릿, 완료 기준 체크리스트, 한 번의 전환 기록 | 새 자료로 다시 시도 |

[글 실습 패키지 내려받기](/downloads/source-backed-article/source-backed-article-1.0.0.zip) · [발표 자료 실습 패키지 내려받기](/downloads/article-to-slides/article-to-slides-1.0.0.zip)

두 패키지는 각각 독립적으로 사용할 수 있다. 전체 경로를 따르면 3단계에서는 자신이 완성한 글을 우선 사용한다. 발표 자료 패키지의 `input/`은 글을 아직 완성하지 못했거나 비교가 필요할 때 쓰는 참고 입력이다. 제품, 인물, 인터뷰는 모두 합성 교육 자료다.

## 1. 근거를 정리하고 충돌을 남기기

글 패키지를 풀고 `brief.md`, `sources/index.csv`, 거기에 나열된 자료 세 개를 읽는다. [글 작성 사례의 첫 단계](/ko/cases/write-an-article/#1-먼저-사실과-충돌-정리하기)에 따라 정리하며, 본문 작성부터 서두르지 않는다.

결과물은 글 패키지의 `my-output/`에 두고 원본 출처를 보존한다. 사실표에는 자료 ID, 절, 뒷받침되는 주장, 증거 유형을 적는다. 자료로 해결되지 않는 문제는 `unresolved.md`에 따로 쓴다.

P3와 C2의 진단 기본 설정 충돌을 찾아내되 한쪽을 임의로 최종 답으로 택하지 않아야 완료다. 합성 인터뷰는 계속 합성으로 표시하고, 출처에 없는 정확도나 시간 절약 수치를 만들지 않는다.

출처가 열리지 않거나 번호가 맞지 않으면 파일과 색인을 먼저 복원한다. 파일명으로 내용을 추측하지 않는다. 확인한 뒤 다음 단계로 간다.

## 2. 글을 쓰고 출처와 대조해 수정하기

앞 단계의 사실과 미해결 목록을 사용한다. [글 작성 사례](/ko/cases/write-an-article/)에 따라 독자를 정하고 개요를 만든 다음 정해진 범위에서 이어서 쓰고, 사실과 표현을 검토한다.

`article.md`, `claim-map.csv`, `unresolved.md`, 수정 설명을 제출한다. 사실 수정 하나와 표현 수정 하나를 최소한 지적한다. 참고 패키지에는 의도적으로 설계한 초안과 실제 텍스트 diff가 있다. 설계된 반례를 모델의 실제 실패로 제시하지 않는다.

주요 사실의 위치를 찾을 수 있고 작성자 조언과 자료가 뒷받침하는 사실이 분리되어 있으며 진단 충돌이 남아 있으면 완료다. Python을 실행할 수 있다면 사례의 구조 검사를 진행할 수 있다. 통과해도 문장마다 출처가 결론을 뒷받침하는지 판단해야 한다.

이 파일을 다음 단계의 입력으로 보관한다. 글은 참고 초안과 달라도 되지만 핵심 제한을 잃어서는 안 된다.

## 3. 글을 8장 발표 자료로 만들기

완성한 글과 사실표를 준비한다. [발표 자료 사례](/ko/cases/create-a-slide-deck/)에 따라 독자, 약 5분짜리 목표, 8장 흐름을 정한다. 표지와 제한 사항 슬라이드로 서식을 먼저 확인한 후 나머지를 완성한다.

글과 사실표를 발표 작업의 입력 폴더에 복사하고 자신의 버전임을 밝힌다. 자신의 글을 인용하면서 참고 초안의 결론을 전부 그대로 적용한다고 가정하지 않는다.

8장 PPTX, 미리보기 8장, 장별 설명과 검증 기록을 제출한다. 기록한 발표 프로그램에서 열 수 있고 주요 문구를 편집할 수 있어야 한다. 각 장의 중국어와 페이지 경계를 검사하고, 축약 후에도 출처 충돌이 명확해야 완료다.

PPTX 도구가 없다면 개요를 저장하고 부족한 기능을 기록한다. 이 단계는 미완료로 남기고 도구가 있는 환경에서 이어 한다. 완료되면 재사용 단계로 간다.

## 4. 다음에도 쓸 작업 지시 저장하기

검토를 끝낸 글과 발표 자료를 준비한다. 아래 템플릿으로 실제 사용한 방법을 `workflow.md`에 적는다. 마지막에 쓴 “계속” 프롬프트만 저장하지 않는다.

```md
# 자료에서 발표까지

## 이번 작업
- 독자와 목적:
- 입력 폴더, 출처 색인, 변경 금지 원본 파일:
- 출력 폴더와 필요한 파일 형식:

## 순서
1. 본문 전에 사실, 추론, 충돌, 누락을 나열한다.
2. 독자와 구성을 정한 뒤 이어서 쓰고 출처와 대조해 수정한다.
3. 글을 8장으로 압축하고 표지와 제한 사항 슬라이드를 먼저 확인한다.
4. 편집 가능한 텍스트, 중국어 글꼴, 모든 미리보기와 노트를 검사한다.

## 완료 기준
- 주요 사실을 원문에서 찾을 수 있고 미해결 사항이 계속 보인다.
- 작성자 조언과 제품 사실을 구분하고 합성 자료를 실제 증언처럼 제시하지 않는다.
- PPTX를 열고 편집할 수 있다. 장마다 확인하며 프로그램과 글꼴 환경을 기록한다.
- 실제로 한 검사와 하지 않은 검사를 밝히고 결과물은 로컬에만 둔다.

## 이번 경험
- 겪은 문제, 변경 사항, 복원을 확인한 방법:
- 다음에도 유지할 단계:
- 다음에 다시 확인할 사실과 환경:
```

작은 범위의 전환도 해 보자. 독자를 “처음 써 보는 개인 작성자”에서 “자료 검토를 준비하는 동료”로 바꾸고 같은 출처를 유지한 채 개요만 다시 만든다. `reuse-check.md`에 제목, 강조점, 순서가 어떻게 달라졌는지와 그대로인 사실상의 경계를 적는다. 이 연습은 템플릿이 새 작업에 적응하는지 확인할 뿐, 새 사실 조사를 마쳤다고 주장하지 않는다.

다른 사람이 `workflow.md`에서 입력과 출력을 찾고 완료 시점을 알 수 있으면 완료다. 전환 기록에는 구체적인 차이가 있어야 하며 옛 독자에게 쓸 글을 계속 작성해서는 안 된다. 순서가 안정되면 [작업 흐름을 Skill로 만들기](/ko/cases/workflows/turn-a-workflow-into-a-skill/)를 읽는다. [글쓰기 Skill 예시](/ko/skills/examples/writing-skill/)는 스타일 예시, 사실표, 충돌 처리 방법을 재사용할 수 있는 전체 패키지를 제공한다. 구조 검사는 사람의 사실 검토를 대신하지 않는다.

## 선택: 수치가 분명한 작업부터 시작하기

사무 분석을 선호한다면 [주간 매출 보고서](/ko/cases/analyze-a-spreadsheet/)를 먼저 해 볼 수 있다. CSV, 환불과 중복 행, 참고 요약과 독립 확인 스크립트가 있다. 완료 후 “주요 수치를 독립적으로 계산하고 이상 값의 기준을 명시하기”를 완료 기준 체크리스트에 추가할 수 있다. 가상 제품 글에 억지로 합칠 필요는 없다.

전체 경로를 마치면 출처 자료, 글과 사실표, 편집 가능한 발표 자료, 검증 기록, 재사용 지시가 남아야 한다. 링크를 읽거나 참고 답안을 내려받기만 해서는 실습을 끝낸 것이 아니다.
