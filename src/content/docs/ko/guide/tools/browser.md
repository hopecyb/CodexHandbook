**브라우저 도구**는 Agent가 통제된 환경에서 실제 웹페이지에 접근하게 합니다. DOM 읽기, 스크린샷, 때로는 단순 상호작용. 프론트엔드 검증, 문서 링크 점검, 디자인 대조에 맞고, 보안 감사를 대체하거나 프로덕션 백오피스를 함부로 조작하기엔 맞지 않습니다.

검색과는 다른 도구입니다. 검색은 웹 정보를 찾고, 브라우저 도구는 페이지를 실제로 엽니다.

## 어떤 문제를 푸나

흔히 다음 질문에 씁니다.

- 이 페이지가 지금 어떻게 보이는지
- 이 버튼을 누르면 무엇이 일어나는지
- 이 레이아웃이 실제 너비에서 깨지는지

코드만 읽거나 글 설명만으로는 부족하고, 페이지를 실제로 열어야 합니다.

## 이 페이지 내용

- 브라우저 도구가 무엇을 할 수 있고 못 하는지
- Web 검색, Computer Use와의 차이
- 권한을 안전하게 주고 제약하는 법

## 능력 개요

| 적합 | 부적합 |
|---|---|
| 로컬 dev server 페이지를 열어 레이아웃 보기 | ToS로 제한된 사이트 대량 크롤 |
| 공개 문서 링크 404 검증 | 미승인 시스템에 자동 로그인 |
| 정적 페이지와 구현 대조 | 완전한 E2E 테스트 프레임워크 대체 |
| 페이지 가시 텍스트를 읽어 디버그 보조 | 복잡한 사람 검증이 필요한 사이트 |

선택 배경: [도구 선택](/guide/tools/tool-selection/)

## 다른 도구와 비교

| 도구 | 입력 | 출력 |
|---|---|---|
| Web 검색 | 질의어 | 요약과 링크 |
| 브라우저 | URL / 로컬 주소 | 페이지 구조, 스크린샷, 상호작용 결과 |
| Computer Use | 전체 화면 GUI | 임의 앱 조작(더 무겁고 민감) |

## 흔한 오해

### 1. 브라우저 도구는 자동화 테스트 대체품이 아님

페이지 점검·스크린샷·일부 상호작용은 돕지만, 완전한 테스트 체계를 대체하지 않습니다.

### 2. 페이지가 열린다고 문제가 없다?

열림은 “페이지가 존재한다”만 말하고, 레이아웃·문안·상호작용·링크가 맞는지는 계속 봐야 합니다.

### 3. 언제 쓰나?

가장 흔한 장면:

- 로컬 페이지 레이아웃 문제 보기
- 링크 404 점검
- 페이지와 디자인 시안의 큰 방향 일치 여부
- “코드는 맞아 보이는데 실제 페이지도 맞는지” 확인

## 판단 기준

질문이 다음이라면:

- “실제 렌더가 어떤 모습인가”
- “페이지에서 무엇을 보는가”
- “이 상호작용을 누른 뒤 피드백이 무엇인가”

브라우저 도구가 순수 텍스트 분석보다 보통 더 맞습니다.

## 권장 워크플로

1. **로컬 프론트**: 먼저 `npm run dev`, 이어서 `http://localhost:PORT/path`
2. **작업을 분명히**: 「로그인 폼이 375px 너비에서 넘치는지」 — 「웹 좀 봐」가 아님
3. **경계를 씀**: 외부망 금지, 프로덕션에 폼 제출 금지
4. **검증**: [산출물 검증](/guide/quality/verify-artifacts/)과 스크린샷 대조

## 바로 쓸 수 있는 쓰기

이렇게 요청하세요.

```text
http://localhost:4321/guide/foundations/local-vs-cloud/ 만 방문하고, 첫 화면 레이아웃과 표지 느낌을 점검하세요.
외부망에 가지 말고, 어떤 폼도 제출하지 마세요.
문제가 있으면 스크린샷 근거와 수정 제안을 주세요.
```

## 보안 경계

- 기본적으로 브라우저는 **당신 기기·환경이 접근할 수 있는 모든 것**에 닿을 수 있다고 가정 — 사내 admin 포함
- 작업에 선언: `localhost만` 또는 허용 도메인 화이트리스트
- 이미 개인 계정으로 로그인한 브라우저 설정에서 신뢰하지 않는 저장소 작업을 돌리지 않음
- Cloud 환경 브라우저 정책은 [Cloud 환경](/guide/web-and-cloud/cloud-environments/)과 네트워크 정책에 따름

승인 개념: [권한과 승인](/guide/foundations/permissions-and-approvals/)

## 흔한 실수

- 프로덕션 URL을 주고 읽기 전용을 제한하지 않음
- 브라우저 스크린샷을 「테스트 통과」로 두고 자동화 테스트를 돌리지 않음
- Web 검색과 혼용: 검색이 실제 렌더 점검을 대체하지 않음

## 검증 체크리스트

- [ ] 접근 범위가 prompt에 고정됨
- [ ] 핵심 시각 문제에 스크린샷 또는 글 설명이 있음
- [ ] 단위/E2E 테스트 결론과 일치하거나, 알려진 차이를 기록함
