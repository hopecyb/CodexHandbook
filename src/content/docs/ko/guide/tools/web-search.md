Web 검색은 사실을 보완하기에 맞고, 최종 결론을 대신 내리기엔 맞지 않습니다.

적합: 공개 문서, 오류 코드, 버전 설명 조회. 부적합: 검색 결과를 최종 법률/의료 결론으로 둠.

출처를 붙이게 하고, 사람이 열어 대조하세요. [출처 검증](/guide/quality/validate-sources/)과 함께 쓰세요.

## 검색이 잘 맞는 일

검색은 주로 다음을 찾는 데 돕습니다.

- 어디에 볼지
- 어떤 정보가 더 대조할 가치가 있는지
- 더 권위 있는 출처가 있는지

역할은 자료를 먼저 찾아 두고, 나중에 원문으로 돌아가는 것입니다.

## 흔한 오해

### 1. 결과가 나오면 답이 신뢰할 만한가?

그렇게 보면 안 됩니다. 찾았다 ≠ 신뢰할 만함. 요약이 매끄럽다 ≠ 정확함.

### 2. 언제 검색을 쓰나?

흔한 장면:

- 공식 문서 조회
- 오류 메시지 조회
- 버전 변화 조회
- 공개 웹의 사실 조회

### 3. 검색 결과 요약을 바로 인용해도 되나?

바로 인용하지 마세요. 이렇게:

1. 검색 결과에 어떤 출처가 있는지 봄
2. 원 페이지를 염
3. 자신의 말로 요약

### 4. 언제 검색만으로 부족한가?

문제가 다음일 때:

- 고위험 법률/의료/재무 판단
- 실제 페이지 동작을 확인해야 함
- 공망 자료가 아니라 프로젝트 로컬 파일을 대조해야 함

이때는 다른 도구나 사람 검증을 함께 씁니다.

## 검색 순서

이 순서로:

1. 문제에 가장 가까운 키워드로 먼저 검색
2. 공식 문서나 1차 출처를 우선
3. 원문을 열어 세부 확인
4. 결론을 결과에 넣을지 결정

## 바로 쓸 수 있는 프롬프트

한 줄을 더하세요.

```text
먼저 검색하고 공식 출처를 우선하세요. 결론에는 클릭 가능한 출처 링크를 붙이고, 검색 요약만 주지 마세요.
```

검색은 단서와 출처를 주고, 마지막에는 원문으로 돌아가 대조해야 합니다.
