일부 Codex 클라이언트는 **음성**을 지원합니다. 작업을 말하거나, 답변 요약을 듣습니다. 손이 바쁘거나 생각을 빠르게 구술할 때 맞고, 키를 읽기에 **맞지 않으며**, 서면 검증 기록을 대체하지도 않습니다.

음성은 방향 표현, 배경 보완, 빠른 후속에 맞고, 정밀·검색·재검토가 필요한 세부는 다시 글로 돌아가야 합니다.

## 이 페이지 내용

- 음성이 맞는 작업 형태
- 문자 프롬프트와 어떻게 맞출지
- 프라이버시와 정확도 주의

## 적용 장면

| 적합 | 부적합 |
|---|---|
| 상위 목표 구술, 브레인스토밍 | 변수명까지 정밀한 코드 지시 |
| 모바일에서 짧은 후속 | API key·비밀번호 낭독 |
| accessibility 요구 | 검색·diff 가능한 규범 문서 |

구술 뒤에는 Codex가 **이해를 되풀이**하거나 문자 계획을 만들게 한 뒤 확인하세요. [계획 요청](/prompts/ask-for-a-plan/)을 참고하세요.

## 음성이 잘 맞는 일

음성의 주요 장점:

- 빠름
- 손을 아낌
- 머릿속 생각을 먼저 쏟아내기에 맞음

흔한 문제:

- 글자를 빠뜨리기 쉬움
- 잘못 듣기 쉬움
- 정밀 경로·변수명·CLI 인자를 싣기에 맞지 않음

흔한 실천은 방향을 먼저 구술하고, 글로 보완해 확인하는 것입니다.

## 사용 제안

1. 조용한 환경, 짧은 문장으로 「목표 / 제약 / 완료 기준」을 구간별로
2. 파일 경로·브랜치 이름은 **타이핑**하거나 Agent가 철자를 되풀이하게
3. 민감 프로젝트에서는 음성 클라우드 처리를 끔(제품이 로컬/비활성 옵션을 주면)
4. 중요 결정은 issue나 PR에 문자로 남김

## 흔한 오해

### 1. 음성이 타이핑을 완전히 대체하나?

아닙니다.  
다음은 타이핑이 낫습니다.

- 파일 경로
- 브랜치 이름
- 명령
- 인자
- 검증 기준

### 2. 길게 자세히 말할수록 덜 틀리나?

구조 없는 긴 구술은 초점을 흩뜨리기 쉽습니다.

### 3. 음성 답변이 결과 심사를 대체하나?

아닙니다.  
음성 요약은 대의를 빠르게 파악하는 데 돕지만, 변경·파일·diff·테스트 결과를 확인할 때는 글과 산출물로 돌아가야 합니다.

## 자주 쓰는 말하기 순서

음성으로 작업을 먼저 줄 때:

1. 무엇을 할지
2. 무엇을 하지 말지
3. 끝나면 어떻게 검증할지

말한 뒤 문자 버전으로 정리해 확인하게 하세요.

## 프라이버시

- 음성이 클라우드 전사를 거칠 수 있음 — 고객 PII·자격 증명을 읽지 않음
- 공공장소에서 옆사람 청취에 주의
- 팀 정책이 녹음류 기능으로 기밀 코드명을 처리하는 것을 금지할 수 있음

## 멀티모달과의 관계

- **이미지 입력**: 디자인 시안, 스크린샷 → [이미지 프롬프트](/prompts/prompting-with-images/)
- **음성 입력**: 이 페이지
- **출력**: 여전히 코드·파일·문자 diff가 중심; 음성 요약이 심사를 대체하지 않음

## 흔한 실수

- 구조 없는 긴 구술로 Agent가 제약을 놓침
- 음성으로 대량 코드 변경을 수락하고 diff를 보지 않음
- 음성으로 미마스킹 프로덕션 사고 세부를 설명

음성은 시작과 후속에 맞고, 정밀 지시·민감 정보 처리·최종 검증을 대체하기엔 맞지 않습니다.
