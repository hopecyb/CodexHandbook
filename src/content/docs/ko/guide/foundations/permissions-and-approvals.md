Codex는 동의 없이 고위험 작업을 실행해서는 안 됩니다. **승인**은 사람·Agent 협업의 게이트입니다.

어떤 파일이든 읽고, 마음대로 네트워크에 연결하고, 마음대로 명령을 실행할 수 있다면, 작업을 잘못 이해했을 때 대가가 큽니다.

## 신경 쓸 것

- 현재 프로젝트 밖 경로 읽기·쓰기를 허용할지
- 네트워크를 허용할지
- 특정 shell 명령 실행을 허용할지
- 팀이 강제 정책(관리형 설정)을 배포했는지

## 무엇을 관리하는가

승인을 「위험 단계 전의 확인 창」으로 보면 됩니다.

예를 들어 이런 경우 멈춰서 물어야 합니다.

- 파일 쓰기
- 시스템을 바꿀 수 있는 명령 실행
- 프로젝트 밖 경로 접근
- 네트워크로 내용을 읽거나 보내기

팝업이나 확인 요청이 보인다고 해서 Codex가 고장 난 것은 아닙니다. 많은 경우 안전 경계에 따라 일하는 중입니다.

## 흔한 오해

### 1. 왜 어떤 때는 바로 하고, 어떤 때는 묻나?

작업마다 위험이 다르기 때문입니다.

- 일반 파일 읽기는 위험이 낮음
- 많은 파일 수정·네트워크·명령 실행은 위험이 더 큼

### 2. 계속 「허용」만 눌러도 되나?

적어도 세 가지를 보세요.

1. 무엇을 하려는지
2. 어디에 영향을 주는지
3. 원래 시키고자 한 일인지

### 3. 「거부」하면 작업 전체가 망가지나?

보통은 아닙니다. 거부한 뒤 더 안전한 방식으로 이어가게 하면 됩니다.

## 사용할 때의 간단한 원칙

- 이해가 안 되면 먼저 승인하지 마세요
- 현재 프로젝트 범위를 넘으면 특히 조심하세요
- 네트워크·명령 실행·일괄 파일 수정은 한 번 더 보세요
- 확신이 없으면 「왜 이 권한이 필요한지」를 먼저 설명하게 하세요

승인의 역할은 「할 수 있는지」를 항상 당신이 결정하게 하는 것입니다.
