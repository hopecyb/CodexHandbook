어떤 작업은 금방 잘 돌아가고, 어떤 작업은 대화할수록 빗나갑니다. 차이는 모델이 갑자기 똑똑해지거나 둔해져서가 아니라, 작업을 분명히 나눴는지에 있습니다.

가장 짧은 버전은: 목표는 「결국 무엇을」, 컨텍스트는 「무엇에 기반해」, 행동은 「어떻게 해도 되는지」, 수락은 「어느 정도면 끝인지」를 말합니다.

비교적 안정적인 Codex 상호작용은 보통 네 덩어리를 포함합니다.

1. **목표**: 최종으로 무엇을 인도할지
2. **컨텍스트**: 관련 배경·파일·제약
3. **행동**: Codex가 취해도 되는 단계(읽기·수정·실행)
4. **수락**: 완료 기준과 확인 방법

프롬프트 교육은 이 네 덩어리를 안정 프레임으로 펼칩니다. [좋은 작업의 구조](/prompts/task-anatomy/)를 보세요.

## 네 덩어리가 각각 맡는 것

실행 조수에게 일을 맡긴다고 보면:

- **목표**: 결국 무엇을 넘기게 할지
- **컨텍스트**: 판단 전에 반드시 알아야 할 전제
- **행동**: 파일 읽기·수정·명령 실행·네트워크 조사가 가능한지
- **수락**: 끝난 뒤 「된다」고 말할 기준

어느 한 쪽이 빠지면 문제가 나기 쉽습니다.

- 목표 없음: 바쁘지만 핵심에 안 맞을 수 있음
- 컨텍스트 없음: 추측함
- 행동 경계 없음: 너무 많이 하거나, 아예 못 할 수 있음
- 수락 없음: 「완료」에 대한 이해가 어긋남

## 흔한 오해

### 1. 목표만 분명히 하면 충분하다

충분하지 않습니다.

예를 들어 「홈페이지 좀 고쳐 줘」는 방향일 뿐, 안정 실행에는 모자랍니다. 더 알아야 합니다.

- 어느 파일을 고칠지
- 무엇을 남길지
- 무엇을 건드리지 말지
- 최종 모습이 어떤지

### 2. 컨텍스트는 많을수록 좋다

너무 적으면 추측하고, 너무 많으면 핵심이 묻힙니다. 핵심은 **관련 컨텍스트**이지, 모든 정보를 쏟아붓는 것이 아닙니다.

### 3. 행동은 말하지 않고 스스로 판단하게 해도 된다

가끔은 가능하지만, 초보자에게는 불안정합니다.

분명히 쓰면:

- 편집 가능한 파일
- 의존성 설치 금지
- 설정 변경 금지
- 먼저 방안을 주고 나서 손대기

결과가 훨씬 안정됩니다.

## 어떻게 쓸지 모를 때 이 순서로

작업을 어떻게 조직할지 모르겠다면 이 네 문장으로:

1. 최종으로 무엇을 끝내 달라고 하는가
2. 어떤 배경과 제약에 기반해야 하는가
3. 무엇을 해도 되고, 무엇을 하면 안 되는가
4. 끝났는지 어떤 기준으로 확인할 것인가

「이 문제 좀 처리해 줘」한 줄보다 훨씬 분명합니다.

## 작은 예

> 목표: `notes.md`의 제목 계층을 정리한다.  
> 컨텍스트: 이 파일만 수정. 기존 단락 순서는 유지.  
> 행동: 해당 파일 편집 가능. 의존성 설치 금지.  
> 수락: 파일을 열면 제목이 H1부터 H3까지 연속이며 건너뛰지 않음.

비교적 안정적인 작업은 적어도 목표·컨텍스트·행동 경계·수락 방식을 분명히 넘겨야 합니다.
