「로컬」「클라우드」는 기술 용어처럼 들리지만, 간단히 말하면 로컬은 자기 컴퓨터에서, 클라우드는 원격 기계에서 일하는 것입니다.

Codex를 먼저 쓰기만 원한다면, 보통 **로컬**이 더 수월합니다.

| | 로컬 작업 | Cloud 작업 |
|---|---|---|
| 실행 위치 | 당신 기기 / 로컬 환경 | 클라우드 환경 |
| 적합 | 빠른 반복, 로컬 파일, 로컬 키가 필요한 디버깅 | 원격 저장소 연결, 장기 작업, 표준 환경 |
| 주의 | 로컬 권한과 오수정 위험 | 환경 설정, 키 주입, 네트워크 정책 |

## 사용 체감

대략 이렇게입니다.

- **로컬 작업**: 자기 컴퓨터 앞에서 Codex와 함께 현재 프로젝트를 고치는 느낌
- **Cloud 작업**: 원격 작업기에 일을 맡기고 거기서 계속 돌리는 느낌

차이는 「위치」만이 아닙니다.

- 어떤 파일에 접근할 수 있는지
- 로컬에 이미 있는 소프트웨어·환경을 바로 쓸 수 있는지
- 작업을 얼마나 오래 돌릴 수 있는지
- 팀이 환경을 통일해야 하는지

## 많은 초보자가 로컬부터 시작하는 이유

로컬이 이해하기 쉽고 확인하기도 쉽기 때문입니다.

- 파일이 자기 컴퓨터에 있음을 압니다
- 프로젝트를 열고 결과를 보고 수동으로 고치기 쉽습니다
- 오류 시 철회 경로가 더 분명합니다

처음에는 작업 루프를 끝까지 돌리는 일이, 처음부터 클라우드에 올리는 것보다 중요합니다.

## 흔한 오해

### 1. 클라우드가 반드시 더 고급이거나 정식 업무에 더 맞지는 않습니다

로컬 프로젝트를 고치고, 로컬 파일을 보고, 빠르게 몇 번 시도하는 일이라면 로컬이 더 직접적입니다.

### 2. 로컬은 「비전문」인가?

많은 실제 개발 일은 원래 로컬에서 끝납니다. 클라우드 여부는 작업 유형에 따르며, 「고급감」으로 판단할 필요가 없습니다.

### 3. 어떻게 고르나

이렇게 판단하세요.

- **컴퓨터에 있는 기존 프로젝트를 고침**: 로컬
- **작업이 길고, 걸어 두고 싶고, 원격 저장소 환경에 붙이고 싶음**: 클라우드를 고려

## 확신이 없을 때

아직 구분이 안 되면: 로컬에서 끝낼 수 있으면 클라우드로 급히 가지 마세요.

아래가 필요할 때 Cloud로 전환하세요.

- 작업 시간이 김
- 환경 통일이 필요함
- 원격 저장소·원격 자원에 연결해야 함
- 로컬을 점유하고 싶지 않음

많은 초보자는 **로컬 + 데스크톱 App**부터 시작합니다. Cloud 세부는 [Web과 Cloud 개요](/guide/web-and-cloud/)를 보세요. App에서 전환은 [로컬과 클라우드 작업](/guide/desktop-app/local-and-cloud-tasks/)을 보세요.

로컬은 흐름을 이해하고 작은 것을 고치는 데 더 맞습니다. 클라우드는 더 길고·더 표준화되고·원격 협업이 많은 작업에 더 맞습니다.
