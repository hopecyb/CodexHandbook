처음 `App / CLI / IDE / Cloud`를 보면 많은 사람이 「도대체 무엇을 설치해야 하지」에서 멈춥니다.

첫 선택이 자신에게 가장 맞지 않아도 길이 막히지는 않습니다. 손에 익는 것부터 쓰고, 나중에 나머지를 보완하면 됩니다.

## 바로 쓰는 고르는 법

지금 강한 선호가 없다면 이렇게 고르세요.

- **처음 사용**: 데스크톱 App
- **원래 터미널을 매일 씀**: CLI
- **주로 VS Code / JetBrains에서 코드를 씀**: IDE 확장
- **GitHub 클라우드 저장소 연결이나 장기 작업이 이미 분명함**: Cloud를 보세요

## 각 입구가 무엇인가

| 입구 | 이렇게 이해하면 |
|---|---|
| 데스크톱 App | 그래픽 콘솔. 작업·diff·승인 누르기에 적합 |
| CLI | 터미널 안의 Codex. 커맨드라인 사용자에게 적합 |
| IDE 확장 | 편집기에 끼워 넣은 조수. 코드를 보며 고치기에 적합 |
| Cloud | 원격으로 작업을 돌리는 방식. 저장소 협업·장기 작업에 적합 |

| 당신이… | 고르기 |
|---|---|
| 처음이고, diff와 검토를 분명히 보고 싶음 | **데스크톱 App**(권장 기본값) |
| 터미널이 익숙하고 스크립트를 씀 | **CLI** |
| 주로 편집기에서 코드를 고침 | **IDE 확장** |
| GitHub 클라우드 환경 / 장기 작업이 필요 | **Cloud**(먼저 개요를 읽으세요) |

## 흔한 오해

### 1. 클라이언트 선택은 너무 기술적이라 건너뛰어도 된다

이 단계는 실용적입니다. 첫 경험이 매끄러운지를 바로 가릅니다.

### 2. 가장 전문적으로 보이는 것을 먼저 써야 한다

처음에는 「과정과 결과를 가장 이해하기 쉬운」 입구가 더 맞습니다. 가장 하드코어한 것을 쫓을 필요는 없습니다.

## 왜 데스크톱 App을 먼저 권하나

초보자에게 데스크톱 App이 친절한 이유는:

- 무엇을 했는지 보기 쉽습니다
- 언제 권한을 요청하는지 한눈에 보입니다
- diff·작업·프로젝트 개념이 더 직관적입니다
- 오류가 나도 멈춰 확인하기 쉽습니다

터미널을 분명히 선호하지 않는다면, 데스크톱 App이 더 맞는 경우가 많습니다.

## 나중에 여러 입구를 함께 써도 됩니다

넷 중 하나를 영원히 고르는 관계가 아닙니다.

많은 사람이 나중에 이렇게 조합합니다.

- 평소에는 데스크톱 App으로 작업과 변경 검토
- 일괄 작업이 필요하면 CLI
- 주로 코드를 쓸 때는 IDE 확장

첫 선택은 시작점일 뿐입니다.

## 덜 헤매려면

1. 먼저 [데스크톱 App](/guide/getting-started/install-desktop-app/)을 설치합니다
2. [첫 작업](/guide/getting-started/run-your-first-task/)을 한 번 돌립니다
3. 익숙해진 뒤 CLI나 IDE를 고려합니다

전체 대조는 [기능 비교](/guide/reference/feature-comparison/)를 보세요. 여러 클라이언트를 설치해도 됩니다. **연습 프로젝트는 같은 디렉터리를 유지**하면 오가며 비교하기 쉽습니다.
