## 30초 안에 선택하기

| 작업이 주로 이루어지는 곳 | 우선 선택 | 가장 적합한 상호작용 |
|---|---|---|
| 로컬의 여러 프로젝트와 병렬 작업 | **데스크톱 App** | 작업 확인, diff 검토, 승인 처리, 장시간 작업 관리 |
| 터미널, 스크립트, 기존 명령줄 흐름 | **CLI** | 작업 지시, 명령 실행, 스크립트와 자동화 조합 |
| VS Code, 호환 편집기, Xcode, JetBrains | **IDE 통합** | 편집기 컨텍스트로 질문, 제자리 수정과 검토 |
| 연결된 원격 저장소와 격리 환경 | **Cloud** | 클라우드에 작업 위임, 병렬 처리, 나중에 결과 검토 |

특별한 선호가 없다면 **데스크톱 App**이 가장 직관적인 시작점입니다. 터미널이나 VS Code를 오래 사용했다면 익숙한 작업 화면에 머무는 편이 전환 비용을 줄입니다.

## 네 진입점이 해결하는 문제

### 데스크톱 App: 로컬 작업 콘솔

데스크톱 App은 작업 상태, 파일 변경, 승인 과정을 명확하게 확인해야 하는 작업에 적합합니다. 특히 다음 상황에 잘 맞습니다.

- 여러 작업이나 프로젝트를 동시에 추적
- worktree로 병렬 변경 격리
- diff를 검토한 뒤 후속 질문이나 수정 요청
- 로컬 프로젝트에서 계속 실행해야 하는 작업 관리

예: 한 작업에는 로그인 회귀 수정을 맡기고 다른 작업에는 성능 병목을 읽기 전용으로 분석하게 한 뒤, 결과를 각각 검토합니다.

### CLI: 터미널 워크플로에 Codex 넣기

CLI는 이미 명령줄로 프로젝트를 관리하는 사람에게 적합합니다. 테스트 명령, Git, 스크립트와 가깝고 같은 작업을 팀 문서에 기록하기 쉽습니다.

```bash
codex
```

예: 저장소 루트에서 Codex를 시작하고, 실패 테스트 실행, 근본 원인 찾기, 최소 수정, 같은 테스트 명령으로 재검증하는 순서를 요청합니다.

### IDE 통합: 현재 코드를 중심으로 작업하기

IDE 통합은 문제가 “현재 보고 있는 파일, 선택 영역 또는 diff”와 밀접할 때 적합합니다. 현재 지원 방식은 두 종류입니다. VS Code, Cursor, Windsurf 등 호환 편집기에서는 Codex 확장을 사용하고, Xcode와 JetBrains IDE에서는 각각의 Codex 통합 진입점을 사용합니다.

예: 이해하기 어려운 함수를 선택해 Codex에게 입력, 출력, 예외 경로를 설명하게 한 다음 경계 조건 테스트를 추가하도록 요청합니다.

### Cloud: 격리된 원격 환경에 위임하기

Cloud는 원격 저장소가 연결되어 있고 작업을 로컬 컴퓨터와 독립적으로 실행하려는 경우에 적합합니다. 클라우드 작업은 격리 환경에서 실행되므로 병렬 탐색, 장시간 작업, 완료 후 집중 검토에 알맞습니다.

예: 서로 독립된 저장소 문제 세 개를 별도 클라우드 작업에 맡기고, 변경과 검증 증거가 돌아오면 하나씩 검토합니다.

## 네 가지 중 하나만 고를 필요는 없습니다

하나의 워크플로를 여러 진입점에서 이어갈 수 있습니다.

1. IDE에서 현재 파일과 관련된 문제를 명확히 합니다.
2. 긴 탐색이 필요한 작업은 데스크톱 App이나 Cloud에 맡깁니다.
3. CLI에서 팀이 정한 검사 명령을 실행합니다.
4. 데스크톱 App이나 코드 검토 화면에서 최종 diff를 확인합니다.

“어느 것이 가장 강한가”가 아니라 **어느 것이 현재 컨텍스트에 가장 가깝고 결과를 가장 쉽게 확인할 수 있는가**를 기준으로 선택합니다.

## 자주 만나는 두 가지 상황

### 상황 1: 실제 프로젝트에서 처음 bug 수정하기

데스크톱 App부터 사용하세요. 작업 대화, 변경, 권한 요청을 한곳에서 볼 수 있습니다. 전체 폐루프를 한 번 완료한 뒤 CLI나 IDE를 시도합니다.

### 상황 2: 팀에 고정 명령과 CI 규칙이 있는 경우

CLI를 우선 사용하고 설치, 테스트, 포맷 명령을 `AGENTS.md`에 기록합니다. 그러면 Codex가 모든 작업에서 같은 프로젝트 규칙을 따를 수 있습니다.

## 선택한 뒤 즉시 검증하기

클라이언트가 “열린다”는 사실만 확인하지 마세요. 연습용 저장소에서 다음 폐루프를 완료합니다.

1. Codex가 파일 하나를 읽고 설명하게 합니다.
2. 되돌릴 수 있는 작은 수정을 요청합니다.
3. 최종 답변뿐 아니라 diff를 확인합니다.
4. 검증 명령을 실행합니다.
5. 권한 요청을 거부하거나 범위를 줄이는 방법을 아는지 확인합니다.

전체 비교는 [기능 비교](/ko/guide/reference/feature-comparison/), 안전 경계는 [권한과 샌드박스](/ko/guide/permissions-and-sandbox/)를 참고하세요.
