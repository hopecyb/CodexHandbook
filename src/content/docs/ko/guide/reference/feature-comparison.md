이 표는 학습과 선정 참고에 가깝습니다. 구체 능력은 현재 제품을 기준으로 합니다.

입구마다 어떤 쓰임에 더 가까운지 보는 데 도움이 됩니다.

| 능력 | 데스크톱 App | CLI | IDE | Cloud |
|---|---|---|---|---|
| 초보자 시각적 검토에 적합 | 강 | 중 | 중 | 중 |
| 터미널/스크립트 통합 | 중 | 강 | 중 | 중 |
| 에디터 인라인 컨텍스트 | 중 | 약 | 강 | 중 |
| 원격 표준화 환경 | 통합에 따라 | 쓰임에 따라 | 쓰임에 따라 | 강 |
| 병렬 작업 / 작업 트리 | 흔함 | 워크플로에 따라 | 워크플로에 따라 | 제품에 따라 |
| Skills / MCP / Plugin | 흔함 | 흔함 | 버전에 따라 | 제품에 따라 |
| 이동 중 승인·후속 | 알림/원격에 따라 | 약 | 약 | 제품에 따라 |

선택 제안：[Codex 클라이언트 선택](/guide/getting-started/choose-your-codex-client/)

## 흔한 오해

### 1. 기능이 많다고 먼저 쓰기 더 좋은 것은 아니다

지금 가장 필요한 사용 방식을 보세요. 기능 개수만 계속 보지 마세요.

### 2. 처음부터 네 입구를 다 배울 필요 없다

먼저 쓸 수 있는 입구 하나만 고르면 됩니다.

### 3. 지금 일하는 방식에 맞춰 고르세요

평소 습관대로 고르세요.

- 가장 직관적이고 검토하기 좋음 -> 데스크톱 App
- 이미 터미널에 익숙함 -> CLI
- 평소 에디터에서만 일함 -> IDE
- 원격 저장소, 장시간 작업에 가깝음 -> Cloud

### 4. 입구를 잘못 골라도 나중에 바꿀 수 있다

너무 무겁게 생각하지 마세요.  
먼저 시작할 수 있는 입구를 고르고, 나중에 바꿔도 됩니다.

## 고르기 어려울 때

잠깐 헷갈리면 이것부터 보세요.

1. 어디서 가장 자주 일하나：데스크톱, 터미널, 에디터, 브라우저
2. 지금 가장 중요한 것이 잘 보이는 것인지, 스크립트·코드·원격 환경 연결인지
3. 먼저 쓰는 법을 배울 것인지, 이미 지속 워크플로에 들어갈 것인지

많은 사람이 이렇게 갑니다.

- 먼저 데스크톱 App으로 기본 리듬을 익힘
- 습관에 따라 CLI나 IDE를 보완
- 원격 장시간 작업이 필요할 때 Cloud를 추가

## 빠른 선택 표

| 현재 요구 | 먼저 쓰기 더 맞는 것 |
|---|---|
| 무엇을 하는지 먼저 보고 싶음 | 데스크톱 App |
| 이미 커맨드라인과 스크립트에 익숙함 | CLI |
| 주로 코드를 씀 | IDE |
| 작업을 원격에서 돌리고 더 표준화하고 싶음 | Cloud |

사용 시나리오로 고르는 편이, 기능 개수만 보는 것보다 보통 더 믿을 만합니다.
