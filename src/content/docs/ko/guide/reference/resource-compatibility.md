호환성은 구체적인 버전 조합을 기준으로 판단해야 합니다. 패키지 구조가 올바르고 이미지 크기가 맞으며 화면이 열린다는 사실만으로 애니메이션 상태나 제거 후 복구가 정상이라고 증명할 수는 없습니다.

## 현재 확보한 증거

2026-09-18에 로컬 앱의 `Info.plist`를 읽기 전용으로 확인했습니다. 클라이언트 식별자는 `com.openai.codex`, 버전은 `26.911.61220`, 빌드는 `9647`이었습니다. 이 확인에서는 펫이나 테마를 로드하지 않았고 클라이언트 설정도 바꾸지 않았습니다. **설치, 재생, 전환, 복구 테스트를 모두 완료한 버전 조합은 아직 없습니다.**

[펫 설치](/ko/pets/install/), [펫 제작](/ko/pets/create/), [테마](/ko/theme/)의 절차는 해당 리소스와 클라이언트 버전을 확인한 뒤 사용하세요. 제삼자 프로젝트의 주장은 출처에 귀속하고, 이 사이트의 실측 결과로 바꾸어 적지 마세요.

## 펫 확인

먼저 JSON과 리소스 경로를 검증합니다. 그런 다음 클라이언트에서 선택, 로딩, 투명 배경, 동작 전환, 창 크기 변경을 확인합니다. 아틀라스에 버전 필드가 있다면 행과 열의 형식 규약에 맞는지 확인하세요. 이미지가 열린다고 해서 클라이언트가 올바른 형식 버전으로 해석했다는 뜻은 아닙니다.

펫을 비활성화할 때는 먼저 기본 리소스로 전환하거나 펫을 끕니다. 사용자 지정 패키지를 스캔 디렉터리 밖의 백업 위치로 옮긴 뒤 새로고침하거나 재시작해 더 이상 나타나지 않는지 확인합니다. 복구할 때는 같은 패키지를 다시 넣고 로딩을 확인합니다. 스캔 디렉터리 안에서 이름만 바꾸는 것으로는 부족하며 설정 디렉터리 전체를 삭제해서는 안 됩니다.

## 테마 확인

테마를 켜기 전후에 동일한 화면의 외형과 상호작용을 기록합니다. 최소한 홈, 작업, 입력창, 검색, 오류 메시지, 접근 가능한 승인 화면을 포함하세요. 열 수 없는 화면은 미테스트로 표시하고 버튼 확인만을 위해 실제 고위험 동작을 실행하지 마세요.

복구 후 일반 클라이언트를 다시 열어 외형과 조작이 정상인지, 테마가 자동으로 다시 시작되거나 재주입되지 않는지 확인합니다. 화면 복구와 디버깅 연결 종료는 각각 확인하세요. 둘 중 하나라도 확인하지 못했다면 미해결 항목으로 남겨 둡니다.

## 재검증이 필요한 때

클라이언트, 운영체제, 테마 엔진, 펫 형식 또는 리소스 패키지가 바뀌면 같은 절차로 다시 검증합니다. 이전 기록을 보존하고 새 버전 조합을 추가해야 하며 검증 날짜만 갱신해서는 안 됩니다. 실패하면 먼저 정상 동작이 확인된 설정을 복구한 뒤 새 변경 사항을 별도로 조사하세요.
