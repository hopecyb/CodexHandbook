Codex Dream Skin은 타사 데스크톱 테마 프로젝트입니다. 프로젝트 문서에 따르면 공식 설치 패키지를 바꾸지 않고 로컬 CDP 연결로 외관을 주입합니다. 이는 프로젝트 측의 설명이며, 이 핸드북은 모든 버전의 파일·네트워크 동작과 화면 호환성을 확인하지 않았습니다.

![테마 외관 예시](/theme/codex-dream-skin/article/codex-dream-skin-home.jpg)

여기에 있는 외관 이미지는 이번 버전 검증의 증거가 아닙니다. 입력창, 승인 버튼, 모든 작업 화면이 정상 작동함을 증명하지도 않습니다.

## 버전과 검증 상태

| 항목 | 이번 확인 결과 |
|---|---|
| 출처 | [프로젝트 저장소](https://github.com/Fei-Away/Codex-Dream-Skin)와 [릴리스](https://github.com/Fei-Away/Codex-Dream-Skin/releases) |
| 확인한 릴리스 | 2026-09-18 확인한 [v1.5.18](https://github.com/Fei-Away/Codex-Dream-Skin/releases/tag/v1.5.18), 커밋 `34335d27d54300eccb325cc652f6c93fef428b84`; 설치하지 않음 |
| 로컬 클라이언트 정보 | Info.plist를 읽기 전용으로 확인: 26.911.61220, build 9647, 식별자 com.openai.codex |
| 시험한 테마/클라이언트 조합 | 없음. 설치, 상호작용, 제거 모두 미시험 |
| Windows 호환성 | 이 핸드북에서 미시험 |
| 복구 결과 | 미시험. 아래는 절차와 확인 방법 |

릴리스 노트는 일부 화면 수정 사항을 상위 macOS Codex 26.901.41123에서 확인했다고 합니다. 여기서 기록한 26.911.61220과 다르므로 해당 조합의 호환성 근거가 되지 않습니다. 이 페이지의 macOS 설치 링크는 v1.5.18에 고정됐습니다. 다른 버전은 해당 태그를 확인하세요.

클라이언트 버전 읽기는 환경 정보일 뿐 테마 호환성 근거가 아닙니다. 직접 시험한 결과는 [리소스 호환성과 복구 기록](/ko/guide/reference/resource-compatibility/)에 남기세요.

## 설치 전 준비

1. 릴리스에서 버전을 명확히 선택하고 패키지 이름, 다운로드 주소, SHA-256을 기록하세요. 게시자가 체크섬 파일을 제공하면 내려받은 파일과 비교하세요. 해시 일치는 파일이 같다는 뜻일 뿐 프로그램 안전의 증거는 아닙니다.
2. 현재 클라이언트와 OS 버전, 테마 설정, 사용 권한이 있는 사용자 이미지의 사본을 보관하고 백업 위치를 기록하세요.
3. 원래 화면의 홈, 작업, 입력, 스크롤, 검색, 승인 UI를 먼저 확인해 기준으로 삼으세요.
4. 선택한 릴리스의 설치, 업데이트, 제거 지침을 읽으세요. main 브랜치 문서는 설치 패키지보다 최신일 수 있습니다.

macOS에서는 [프로젝트 설치 안내](https://github.com/Fei-Away/Codex-Dream-Skin/blob/v1.5.18/docs/install-macos.md), Windows에서는 [Windows 안내](https://github.com/Fei-Away/Codex-Dream-Skin/blob/main/docs/install-windows.md)를 읽으세요. '손상됨' 경고나 시스템 차단을 서명 부족 탓으로 단정하지 마세요. 출처, 패키지 무결성, 구체적 오류를 확인한 뒤 계속할지 결정하세요.

## 이미지 교체 후 확인할 것

프로젝트는 배경 이미지와 테마 관리 기능을 제공합니다. 메뉴 이름은 버전에 따라 다릅니다. 사용 권리가 있는 이미지를 쓰고 라이트·다크 모드, 창 크기 조절, 실제 작업 화면을 확인하세요.

- 입력창, 버튼, 승인 정보를 여전히 읽고 클릭하고 포커스할 수 있는가?
- 배경이 검색 결과, 긴 출력, 코드 diff, 오류를 가리지 않는가?
- 페이지 전환과 재시작 뒤에도 표시된 테마가 선택과 일치하는가?
- 테마를 끄면 원래 화면이 돌아오며 문제가 계속 재현되는가?

내용이 가려지거나 조작할 수 없다면 테마 사용을 멈추고 복구하세요. 스타일을 더 쌓아 문제를 가리지 마세요.

## 제거와 복구

프로젝트의 macOS 문서는 테마 앱을 삭제하기 전에 메뉴 막대에서 '원상 복구 후 제거'를 실행하라고 합니다. 사용자 테마와 이미지는 별도로 보관하거나 삭제할 수 있습니다. 먼저 사용자 자료를 백업하세요. Windows에서는 macOS 경로를 적용하지 말고 해당 버전 문서를 따르세요.

아래는 이 핸드북이 권장하는 복구 확인 방법이며 이미 완료한 시험 기록이 아닙니다.

1. 클라이언트의 작업을 저장하고 현재 테마와 보존할 파일을 기록하세요.
2. 테마 도구의 복구 절차를 사용하고 완료, 실패, 미확인 상태 메시지를 남기세요.
3. 정상적인 진입점에서 Codex를 다시 열어 배경, 글자, 입력, 작업 탐색을 확인하세요.
4. 테마 도구가 자동 시작하거나 다시 주입하지 않는지 확인하세요. 기술 점검이 필요하면 비슷한 이름의 프로세스를 무턱대고 종료하지 말고 프로세스와 디버그 연결을 조사하세요.
5. 확인이 끝난 뒤 앱을 제거하세요. 사용자 이미지는 별도로 불필요하다고 판단할 때까지 보관하세요.

백업 존재, 제거 프로그램 종료, 테마 창 닫힘만으로 복구 성공이 증명되지는 않습니다. 결과가 불분명하면 로그를 저장하고 프로젝트 Issue를 확인하되 '복구됨'이라고 쓰지 마세요. 테마 제거를 위해 Codex 설정 디렉터리 전체를 삭제하지 마세요.

## 적용 범위

CDP는 페이지 내용을 바꿀 수 있으므로 '공식 패키지를 수정하지 않는다'가 사용에 영향이 없다는 뜻은 아닙니다. 화면 구조가 업데이트되면 다시 검증하세요. 로컬 처리, 네트워크 접근, 복구 방법에 대한 프로젝트 설명도 버전별로 검토해야 합니다. 이 핸드북은 자료가 절대 업로드되지 않음, 모든 버전의 원클릭 복구, 덮어쓰기 업데이트의 무손실을 보장하지 않습니다.
