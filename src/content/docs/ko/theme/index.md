# Codex 테마 스킨

Codex의 스킨을 바꾸는 일은 단순히 더 예쁘게 꾸미는 것처럼 보입니다. 하지만 Codex Dream Skin은 데스크톱 테마를 위한 하나의 완성된 방식입니다. Codex의 기본 상호작용은 유지하고, 공식 설치 패키지는 수정하지 않으며, 외부 주입 방식으로 배경, 색상, 분위기를 실제 인터페이스에 더합니다.

## Codex Dream Skin이란?

Codex Dream Skin은 Codex 데스크톱 앱에 테마를 적용하는 오픈소스 프로젝트입니다. Codex 뒤에 16:9 배경 이미지를 깔고, 라이트/다크 모드, 포커스 위치, 색상 팔레트에 맞춰 자동으로 조정합니다. 사이드바, 제안 카드, 프로젝트 선택, 입력창은 그대로 네이티브 상호작용 컨트롤입니다.

![Codex Dream Skin이 Codex 홈 화면에 16:9 배경을 적용한 모습](/theme/codex-dream-skin/article/codex-dream-skin-home.jpg)

_실제 Codex 데스크톱 앱에 테마를 적용한 홈 화면. 사이드바, 제안 카드, 입력창은 여전히 네이티브 컨트롤입니다._

예전처럼 바이너리를 수정해 스킨을 바꾸는 방식과는 다릅니다.

| 방식 | 공식 파일 수정 | 서명 훼손 | 네이티브 컨트롤 사용 | 이미지 자유도 |
| --- | --- | --- | --- | --- |
| CDP 주입(Dream Skin) | 아니요 | 아니요 | 가능 | 높음 |
| `app.asar` 수정 | 예 | 예 | 일부 | 중간 |
| 공식 라이트/다크 전환 | 아니요 | 아니요 | 가능 | 없음 |

`app.asar`를 수정하는 방식은 Codex 리소스 패키지를 풀고 CSS와 이미지를 바꾼 뒤 다시 패킹하는 방식이었습니다. 문제는 서명이 즉시 깨지고, Codex가 업데이트될 때마다 반복해야 하며, 보안 소프트웨어가 차단할 수도 있다는 점입니다.

CDP 주입은 공식 바이너리 파일을 수정하지 않습니다. Codex 외부에서 디버그 포트를 통해 스타일과 스크립트를 주입하며, `.app`, `app.asar`, 코드 서명에는 손대지 않습니다.

할 수 있는 일: 스킨 변경, 배경 변경, 여러 테마 저장, 공식 외관으로 한 번에 복원.

하지 않는 일:

- 설치 스크립트가 제3자 API Key나 Base URL을 몰래 쓰지 않습니다. 스킨과 릴레이 설정은 분리됩니다.
- 공식 설치 디렉터리와 서명을 수정하지 않습니다.
- CDP는 `127.0.0.1`에만 바인딩됩니다. 그래도 테마 실행 중에는 출처 불명의 로컬 프로그램을 피해야 합니다.

프로젝트는 OpenAI 공식 제품이 아니라고 밝힙니다. 복원 후 제거를 선택하면 Codex는 공식 외관으로 돌아가고 CDP 연결도 끊깁니다.

## 설치와 시작

설치 전 Codex를 한 번 열어 데스크톱 앱이 정상적으로 실행, 로그인, 종료되는지 확인합니다. 그래야 테마 도구가 올바른 로컬 Codex 환경을 찾을 수 있습니다.

### macOS

macOS에서는 보통 프로젝트 Releases에서 `.dmg` 설치 파일을 받습니다. 설치 후 `Codex Dream Skin.app`을 Applications로 드래그하고, 메뉴 막대에서 테마 관리, 배경 변경, 공식 외관 복원을 수행합니다.

시스템이 앱이 "손상됨" 또는 열 수 없다고 표시하면, 대개 Gatekeeper가 서명되지 않은 앱을 차단한 것입니다. 설치 파일 출처를 신뢰할 수 있을 때만 시스템 설정 > 개인정보 보호 및 보안에서 열기를 허용하세요.

### Windows

Windows에서는 보통 Releases에서 설치 파일을 받거나 프로젝트 문서의 PowerShell 절차를 따릅니다. 설치 후 시스템 트레이에서 테마 도구를 열어 테마와 배경을 관리합니다.

SmartScreen의 파란 경고가 뜨면 설치 파일에 코드 서명 인증서가 없는 경우가 많습니다. 출처를 신뢰할 수 있을 때만 계속하세요.

### 자주 발생하는 문제

| 현상 | 원인 | 해결 |
| --- | --- | --- |
| macOS가 "손상됨"이라고 표시 | 서명되지 않은 앱을 Gatekeeper가 차단 | 시스템 설정 -> 개인정보 보호 및 보안 -> 그래도 열기 |
| Windows SmartScreen 파란 경고 | 코드 서명 인증서 없음 | 추가 정보 -> 실행 |
| 설치 후 효과 없음 | Codex를 먼저 한 번 실행하지 않음 | Codex를 열고 로그인 후 종료한 다음 Dream Skin 설치 |
| Codex 업데이트 후 테마 실패 | 업데이트로 내부 경로가 바뀌었을 수 있음 | 최신 설치 파일을 내려받아 덮어 설치 |

덮어 설치해도 저장된 테마와 이미지는 삭제되지 않습니다.

## 배경과 테마 관리

설치 후 macOS 메뉴 막대 또는 Windows 시스템 트레이에서 "배경 변경"을 클릭하고 이미지를 선택합니다.

![Codex Dream Skin 테마 미리보기와 전환 화면](/theme/codex-dream-skin/article/codex-dream-skin-gallery.jpg)

_이미지를 바꾼 뒤에는 홈, 사이드바, 입력창, 작업 페이지를 함께 확인해 실제 사용 중에도 명확하고 읽기 쉬운지 확인해야 합니다._

이미지를 선택하면 엔진은 밝기, 주요 색상, 포커스 위치, 좌우 중 정보량이 적은 쪽을 로컬에서 분석하고 그 이미지에 맞는 테마 변수를 만듭니다. 테마는 저장, 이름 지정, 한 번의 전환이 가능합니다.

Gothic Void Crusade는 공개 설치 파일의 기본 테마이며 커뮤니티 작성자가 기여했습니다. 원하는 16:9 순수 배경 이미지도 가져올 수 있습니다.

이미지 기준:

- 권장 크기는 `2560 x 1440` 16:9이며, 창, 사이드바, 텍스트, 로고가 들어가지 않은 순수 배경입니다.
- 주 피사체를 Codex 입력창, 사이드바, 제안 카드 영역에 두지 마세요.
- 너무 밝거나 복잡하거나 대비가 강한 배경은 가독성을 해칠 수 있습니다.
- 공개 공유나 상업적 사용 전에는 배경, 인물, 상표, 글꼴, IP 권리를 확인하세요.

구도 기준을 만족하지 않는 이미지도 쓸 수 있지만, 네이티브 콘텐츠가 피사체를 가리거나 글자가 잘 안 보일 수 있습니다.

## 작동 방식

### CDP 주입 원리

CDP(Chrome DevTools Protocol)는 Chromium 기반 브라우저의 원격 디버깅 프로토콜입니다. Chrome 개발자 도구가 모바일 페이지를 원격 디버깅할 때도 CDP가 사용됩니다. 브라우저가 로컬 디버그 포트를 열고, 외부 도구가 연결해 CSS와 JavaScript를 주입할 수 있습니다.

Codex 데스크톱 앱은 Electron 기반이며 내부도 Chromium입니다. Dream Skin의 흐름은 다음처럼 단순화할 수 있습니다.

![문서의 CDP 주입 흐름도](/theme/codex-dream-skin/article/cdp-injection-flow.png)

```text
테마 도구 시작
  -> 로컬 CDP 엔드포인트가 있는 Codex 데스크톱 열기
  -> Codex의 Chromium 렌더러 프로세스에 연결
  -> 테마 CSS와 장식 DOM 주입
  -> Codex는 계속 정상 동작하고 외관은 테마 레이어가 담당
```

주입기를 중지할 때는 PID, 실행 파일 경로, 시작 시간을 함께 확인해 다른 프로세스를 잘못 종료하지 않도록 합니다.

주입된 CSS는 사이드바, 입력창, 제안 카드의 네이티브 상호작용을 유지합니다. 배경은 네이티브 컨트롤 아래에 깔리고, 반투명 그라데이션 레이어가 글자 가독성을 보장합니다.

### 적응형 색상: 로컬 계산, 업로드 없음

이미지를 바꾸면 Dream Skin은 Canvas에서 이미지를 로컬로 다운샘플링하고 주요 색상, 밝기, 포커스 위치를 추출합니다. 그런 다음 HSL 색 공간에서 강조색, 보조색, 하이라이트색 등 CSS 변수를 계산합니다.

다크 모드에서는 어두운 주요 색상에서 시작하고, 라이트 모드에서는 밝은 중성 회색에서 시작합니다. 이미지가 바뀌면 전체 팔레트가 자동으로 다시 계산됩니다.

라우트 인식 측면에서 홈은 전체 배경과 그라데이션을 유지하고, 작업 페이지로 이동하면 배경이 낮은 간섭의 환경 레이어로 바뀌어 콘텐츠가 우선됩니다.

## 마무리

CDP 주입 방식은 공식 바이너리를 수정하지 않고 앱 외부에서 스타일을 주입하는 방식입니다. 이 아이디어는 Codex에만 한정되지 않습니다. CDP 디버그 포트를 지원하는 Electron 앱이라면 이론적으로 같은 방식의 테마 커스터마이징이 가능합니다.

개인화된 개발 환경에 대한 수요는 실제로 있습니다. 좋은 테마 스킨은 단지 "더 멋진" 것이 아니라 네이티브 상호작용을 유지하고, 복원 가능하며, 검사 가능하고, 시각적 개선과 모델 설정을 섞지 않아야 합니다.
