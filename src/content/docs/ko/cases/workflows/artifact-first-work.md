**산출물 우선**은 인도물의 형태와 위치를 먼저 밝힌 뒤, Codex가 단계를 역산하게 하는 방식입니다. Markdown 문서, OpenAPI, 마이그레이션 스크립트, 슬라이드 개요처럼 출력이 명확한 작업에 적합하며, [스펙 주도](/cases/workflows/specification-driven-work/)와 함께 쓸 수도 있습니다.

## 이 페이지의 초점

- 과정 세부보다 산출물 구조를 어떻게 설명할지
- 여러 파일 산출물의 일관성 검사
- [파일과 산출물](/guide/files-and-artifacts/) 기능과의 정렬

## 최소 실행 방법

```text
목표 산출물:
- docs/api/auth.md(개요, 엔드포인트, 오류 코드 세 절 포함)
- 스타일은 @docs/api/users.md 와 일치

먼저 목차 개요와 각 절 요점을 출력하고, 전문은 쓰지 마세요.
내가 확인한 뒤 생성하고, 내부 링크가 유효한지 자체 검사하세요.
```

## 권장 워크플로

```text
산출물 목록 정의(경로 + 형식 + 샘플 참조)
    → 개요 또는 골격 파일
    → 사람 확인
    → 내용 채우기 + 교차 링크
    → 검증(lint, 링크 검사, 미리보기)
```

시각 산출물은 스크린샷 또는 미리보기 설명을 요구할 수 있습니다. [산출물 검증](/guide/quality/verify-artifacts/)을 참고하세요.

## 흔한 실수

- 산출물 경로가 저장소 약속과 맞지 않음(잘못된 디렉터리)
- 단일 파일만 생성하고 내비게이션·index 업데이트를 무시
- 샘플을 대조하지 않아 스타일이 어긋남
- 바이너리 산출물(pptx/docx)을 사람이 어떻게 열어 인수할지 설명하지 않음

## 보안 경계

- 생성물에 제3자 저작권 내용이 있으면 사람이 컴플라이언스 검사해야 합니다
- 프로덕션 설정 경로를 덮어쓰지 말고, 먼저 브랜치 또는 `draft/` 아래에 산출하세요

## 인수 체크리스트

- [ ] 선언한 모든 파일이 존재하고 열 수 있음
- [ ] 형식과 참조 샘플이 일치
- [ ] 링크/목차/Frontmatter가 유효
- [ ] [완료 정의](/prompts/define-done/)를 충족
