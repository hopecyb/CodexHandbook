## 1. 목표와 배경

**목표:** 경쟁 제품 3–5개의 비교표(기능, 가격 단서, 적합 시나리오)를 만들고, 각 결론에 출처를 붙입니다.

**성공 기준:**

- Markdown 표 + 「확인 필요」표시
- 가격과 버전 번호를 날조하지 않음
- 내부 기밀을 대외 문서에 쓰지 않음

## 2. 준비

- 비교 차원을 명확히(미리 프롬프트 또는 `@brief.md`에 작성)
- [웹 검색](/guide/tools/web-search/) 활성화(제품이 지원하는 경우)

## 3. 워크플로

[출처가 있는 리서치](/cases/workflows/research-with-sources/)를 따릅니다:

```text
A/B/C 세 곳의 「팀 협업」기능을 비교하세요:
각 차원에 1–2문장 설명 + 출처 URL을 주세요.
공식 문서를 블로그보다 우선하세요.
가격을 검증할 수 없으면 「확인 필요」로 표시하세요.
markdown 표를 출력하고, 저장소의 다른 파일은 수정하지 마세요.
```

**검증:** 사람이 URL 3개를 열어 보고, 날짜와 [검증 정책](/guide/start-here/handbook-version-policy/)을 확인합니다.

## 4. 실패와 복구

- 출처 충돌: 두 설을 나란히 제시하고 억지로 통일하지 않음
- 컨텍스트가 너무 김: 「먼저 A vs B, 이어서 C 추가」로 쪼갬

## 5. 정착

- 비교표 템플릿을 팀 약속 템플릿 디렉터리 또는 지식 베이스에 정착
- Skill로 전환 가능: `source-backed-research`
