이번 연습에서는 판매 주간 보고서, 지역별 요약, 제품 순위, 행별 데이터 정리 장부를 만듭니다. 입력은 이 사이트에서 만든 합성 데이터이며 실제 고객 정보는 필요하지 않습니다.

난이도: 입문. 예상 30~45분은 편집상의 추정치로 독자를 대상으로 시간을 재보지 않았습니다. Codex에 로컬 파일을 제공할 수 있어야 합니다. 참고 결과를 읽는 데는 프로그래밍이 필요 없지만 검증을 실행하려면 Python 3.10 이상이 필요합니다.

[전체 연습 자료 v1.0.0(ZIP) 다운로드](/downloads/sales-weekly-report/sales-weekly-report-1.0.0.zip) · [판매 CSV만 다운로드](/downloads/sales-weekly-report/sales.csv)

## 먼저 제출할 결과 확인

| 지표 | 참고 값 | 확인할 점 |
|---|---:|---|
| 이번 주 순매출 | 4,644.75위안 | 환불 포함 |
| 화둥(중국 동부) 이번 주 순액 | 1,281.25위안 | 1,401.75 − 120.50 |
| 날짜 없는 금액 | 199.99위안 | 주를 추측하지 말고 격리 |

이번 기간은 2026-09-07~09-13, 이전 기간은 2026-08-31~09-06입니다. 두 개의 완전한 달력 주를 비교한 전주 대비 변화율은 87.04%입니다. 이는 합성 표본의 결과일 뿐 실제 사업상 원인을 설명하지 않습니다.

[참고 주간 보고서 보기](/downloads/sales-weekly-report/summary.md). 먼저 직접 연습한 뒤 답안과 비교하세요.

## 자료 내려받기

전체 패키지에는 작업 안내, 데이터 사전, 프롬프트 세 개, 46행 CSV, 참고 보고서, 요약·장부 CSV 세 개, 참고 구현, 독립 검증 스크립트, 검증 기록이 포함됩니다. 모두 CC0 1.0으로 공개되어 수정과 재배포가 가능합니다.

압축을 풀고 `sales-weekly-report` 폴더를 여세요. CSV만 내려받으면 다른 참조 파일이 자동으로 생기지 않습니다.

## 1. 파일과 계산 기준 확인

다음 작업을 Codex에 맡깁니다. 파일을 제공하는 방법은 클라이언트마다 다를 수 있으니 실제로 읽었는지 먼저 확인하세요.

```text
brief.md, starter/data-dictionary.md, starter/sales.csv를 읽으세요.
파일 존재 여부를 확인하고 필드, 날짜 범위, 기록 수, 별도 처리가 필요한
행 번호를 나열하세요. 원본 표는 수정하지 말고 solution은 보지 마세요.
완전 중복, 날짜 누락, 음수, 실제 0을 구분하세요.
사전에 따라 두 주의 계산 기준을 설명하고 충돌이 있으면 나열하세요.
충돌이 없으면 계속 진행하세요.
```

원본 46행에는 환불 두 건, 완전 중복 한 건, 날짜 누락 한 건이 있습니다. 완전 중복은 첫 행만 남깁니다. 같은 ID의 내용이 다르면 검증을 중단합니다. 빠진 날짜를 지어내지 말고 금액 0은 유효하게 처리합니다. 처리 후 포함되는 행은 44개여야 합니다.

## 2. 주간 보고서와 계산 장부 만들기

이어서 패키지의 `prompts/02-report.md`를 사용하고 결과물을 `my-output/`에 작성합니다.

| 파일 | 포함할 내용 |
|---|---|
| `summary.md` | 총액, 전주 대비 변화, 지역, 이번 주 상위 제품 3개, 데이터 품질, 계산 근거 |
| `region-summary.csv` | 두 주의 지역별 순액, 차액, 변화율 및 지역 합계와 대조 가능한 전체 합계 |
| `top-products.csv` | 환불을 포함해 이번 주 제품별 순액을 내림차순으로 정렬 |
| `row-ledger.csv` | 원본 각 행의 행 번호, 포함 여부, 해당 주, 금액 |

입력, `solution`, `validation`은 변경하지 마세요. 독립 검증에서 항목별로 비교할 수 있도록 필드 이름과 표 순서는 데이터 사전을 따릅니다. 남서부의 이전 주 값은 0이므로 변화율은 N/A로 쓰고 0%나 무한 성장으로 표현하지 마세요.

## 3. “맞나요?”라고 묻는 데 그치지 말고 독립 검증

압축을 푼 연습 폴더에서 실행합니다.

```sh
python3 validation/check.py --output my-output
```

결과물 네 개가 모두 있고 합의한 계산 기준과 일치하면 `result: PASS`가 출력됩니다. 입력 해시 변경, 환불 누락, 그룹화 오류, 장부 불일치는 오류가 납니다. 실패하면 자신의 결과물만 고치고, 통과시키려고 검증기를 수정하지 마세요.

Python을 실행할 수 없다면 최소한 다음을 수동으로 확인하세요.

1. 화둥(중국 동부)의 양수 일곱 건 합계는 1,401.75위안입니다. 44행 환불 −120.50을 더하면 1,281.25입니다.
2. 이번 주 세 지역의 합계는 1,281.25 + 2,101.75 + 1,261.75 = 4,644.75입니다.
3. 47행 O046에는 날짜가 없으며 199.99위안은 어느 주에도 포함되지 않습니다. 46행 O001은 중복입니다.

자동 검증으로 자연어 결론을 모두 검토할 수는 없습니다. 보고서를 읽고 근거 없는 성장 원인이나 사업 판단을 삭제하세요.

## 4. 오류 수정 연습: 환불 누락

**설계된 반례**: 음수를 모두 걸러내면 이번 주 합계는 4,765.25위안으로 120.50위안 많아집니다. 참고 검증에서는 임시 결과를 실제로 바꾸어 검증기가 잘못된 금액을 거부하는지 확인했습니다. 모델 대화를 꾸며낸 것이 아닙니다.

```text
net_sales가 0보다 작은 유효 기록을 확인하고 포함해야 하는지 설명하세요.
환불의 음수 부호를 유지하며 두 기간의 지역별·제품별 요약을 다시 계산하고
수정 전후 차이를 나열하세요. 실패를 없애려고 원본 CSV나 검증기를
수정하지 마세요.
```

## 5. 문제 발생 시 복구

| 현상 | 먼저 확인 | 다음 단계 |
|---|---|---|
| 파일을 찾지 못함 | 현재 폴더에 `starter/sales.csv`가 있는가? | 압축을 푼 폴더를 열고 파일을 참조. 에이전트가 누락 데이터를 새로 만들지 않게 함 |
| 중국어가 깨지거나 열 하나만 보임 | UTF-8 인코딩과 쉼표 구분자인가? | 원본 CSV를 다시 가져오고 금액을 손으로 바꾸지 않음 |
| 금액이 120.50 차이 남 | 환불 R043을 빠뜨렸는가? | 사전에 따라 음수를 유지하고 두 기간을 다시 계산 |
| 전주 대비 계산 중 0으로 나누기 | 남서부의 이전 주 값이 실제로 0인가? | N/A로 쓰고 기준 값이 0임을 설명 |
| 검증기가 파일 누락을 보고 | 결과물 네 개를 모두 만들었는가? | 사전에 따라 보완하고 다시 실행. 파일 누락이 금액 오류를 뜻하지는 않음 |

## 완료 조건과 다음 단계

- 원본 표의 해시가 바뀌지 않았고 결과물 네 개가 모두 있다.
- 총액, 화둥(중국 동부) 금액, 날짜 누락 금액을 독립적으로 재확인했다.
- 보고서에 이상값, 0 기준, 계산 방식을 남기고 원인을 지어내지 않았다.
- 실제로 실행한 검사와 사람의 검토가 남은 부분을 명확히 구분했다.

자신의 프롬프트와 수정 기록을 보관하세요. 다음에 데이터를 바꾸기 전에 필드와 계산 기준을 다시 확인하세요. 이 연습의 고정 검증기는 임의의 기업 데이터에 적용되지 않습니다.
