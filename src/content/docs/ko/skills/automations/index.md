`Automations`는 반복 작업을 어떻게 자동으로 돌릴지를 다루며, 「Codex를 더 똑똑하게」 만드는 논의가 아닙니다.

이 그룹이 더 관심 두는 것은 다음과 같습니다.

- 어떤 작업을 자동으로 돌릴 가치가 있는지
- 자동 실행을 어디까지 하고 사람을 기다려야 하는지
- 실패·알림·롤백을 어떻게 설계할지

## 판단 초점

자동화를 처음 접할 때, 처음부터 모든 반복 일을 맡기지 마세요.

다음 순서로 판단하세요.

1. 먼저 그 일이 **반복되고, 규칙이 분명하며, 결과를 수락하기 쉬운지** 판단
2. 그다음 읽기 전용·제안만·초안 PR만 가능한지 판단
3. 그다음 완전 무인 운용을 고려

## 이 그룹 입구

- [예약과 백그라운드 작업](/skills/automations/scheduled-tasks/): 자동화 작업의 의미, 트리거 방식, 종료 조건, 사람 재검토 지점

## 흔한 오해

### 1. 반복되면 반드시 자동화해야 한다

작업이 반복되어도 판단 기준이 사람에게 크게 의존하면, 너무 이른 자동화가 오히려 문제를 키울 수 있습니다.

### 2. 자동화는 사람 확인을 없애야 한다

많은 자동화는 다음만으로도 이미 가치가 있습니다.

- 자동 검사
- 자동 요약
- 자동으로 issue / 초안 PR 열기

결과를 바로 메인 브랜치에 올리지 마세요.

자동화는 「반복되고, 규칙이 분명하며, 결과를 검사하기 쉬운」 작업에 더 적합합니다. 판단에 의존하는 일에는 절차에 사람 재검토를 남겨 두는 편이 보통 더 안정적입니다.
