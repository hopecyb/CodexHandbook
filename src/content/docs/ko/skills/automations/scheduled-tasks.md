**Automations**는 Codex가 **일정표, 저장소 이벤트, 외부 트리거**에서 작업을 자동 실행하게 합니다. 예: 의존성 업데이트 검사, 문서 동기화, 주기적 헬스 스캔.

## 이 페이지 내용

- 언제 자동화할 가치가 있고, 언제 사람을 루프에 남겨야 하는지
- 트리거·실행·알림·실패 네 가지 설계 지점
- Cloud 작업, 로컬 CLI 스크립트와의 관계

## 수동 작업과 비교

| | 수동 작업 | Automation |
|---|---|---|
| 시작 | 당신이 시작 | 스케줄/이벤트 |
| 감독 | 언제든 중단 가능 | 알림과 로그 필요 |
| 위험 | 그 자리에서 판단 | 오류가 대량 확산될 수 있음 |
| 적합 | 탐색, 리팩터 | 반복, 규칙이 분명함 |

## 안전한 자동화 설계

### 1. 트리거 조건이 분명해야 함

```text
좋음: 매주 월요일 09:00, docs/ 디렉터리 죽은 링크 검사
나쁨: 지속적으로 감시하며 코드를 자동 수정
```

### 2. 권한 최소화

- 읽기 전용 스캔이 자동 커밋보다 나음
- 자동으로 PR을 열면 전용 bot 계정과 브랜치 보호 사용

### 3. 종료 조건

- 연속 실패 N회 시 일시 중지
- diff가 행수 임계를 넘으면 사람에게 넘김
- `AGENTS.md` 금지 디렉터리에 닿으면 중단

### 4. 알림

- Slack/메일/모바일: 완료, 실패, 승인 필요
- 감사용 로그 보관

### 5. 사람 재검토 지점

| 완전 자동 가능 | 사람 필요 |
|---|---|
| 초안 PR 생성 | main에 병합 |
| 낡은 의존성 나열 | major 버전 업그레이드 |
| 공개 문서 동기화 | 대외 공지 게시 |

## 전형적 패턴

### 주기적 유지보수

- 의존성 취약점 보고 → issue 열기, lockfile을 직접 수정하지 않음
- 번역 파일과 원문 카피 diff 알림

### 이벤트 구동

- 새 PR 열림 → review Skill 실행(댓글 제안, push하지 않음)
- Issue 라벨 `bug` → 재현 단계 초안 생성

### 장시간 작업

여러 Automation 구간 + [인수인계와 재개](/guide/agent-work/handoff-and-resume/)로 나누어, 한 번 컨텍스트가 고갈되지 않게 하세요.

## Cloud / CLI와의 관계

- **Cloud**: GitHub와 깊게 통합된 원격 자동화에 적합
- **CLI + cron/CI**: 사내망, 커스텀 파이프라인에 적합
- 선택은 [로컬과 클라우드](/guide/foundations/local-vs-cloud/)와 [Web과 Cloud](/guide/web-and-cloud/) 참고

## 흔한 실수

- 자동화가 메인 브랜치에 직접 `git push`
- 실패 알림이 없어 저장소가 조용히 부패
- 탐색성 작업을 예약으로 설정—할당량만 낭비하고 수락이 어려움

## 수락 체크리스트

- [ ] 트리거 조건, 권한, 알림, 종료 조건이 문서화됨
- [ ] fork 또는 테스트 저장소에서 전체 주기를 한 번 연습함
- [ ] 팀이 bot 계정과 승인 규칙을 알고 있음
