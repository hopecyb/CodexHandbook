## 비교표

| | 누가 트리거 | 지속성 | 외부 시스템 연결 | 팀 배포 |
|---|---|---|---|---|
| AGENTS.md | 자동 로드 | 높음(Git) | 쉬움 |
| 프롬프트 | 당신 | 낮음 | 어려움 |
| 슬래시 명령 | 당신 | 중간 | 제품에 따름 |
| Skill | 당신 또는 모델 매칭 | 높음 | 쉬움(디렉터리/Git) |
| MCP | 모델이 도구 호출 | 설정 수준 | 거버넌스 필요 |
| Plugin | 설치 후 종합 적용 | 높음 | 공식/팀 채널 |
| Hooks | 시스템 이벤트 | 설정 수준 | 기업에서 흔함 |
| Automations | 시간/이벤트 | 설정 수준 | 승인 흐름 필요 |

## 흔한 대응 관계

| 요구 | 권장 선택 |
|---|---|
| 코드 스타일·테스트 명령 통일 | AGENTS.md |
| 「PR 검토」 절차 표준화 | Skill |
| Jira/Linear 티켓 읽기 | MCP |
| 팀 전체에 통합 세트 설치 | Plugin |
| 커밋마다 비밀 스캔 | Hooks |
| 매주 월요일 주간 보고 초안 자동 생성 | Automations(+ 사람 게시) |

## 하나의 작업에서 팀 능력 패키지까지

아래 흐름으로 워크플로를 어디까지 다듬을지 판단할 수 있습니다.

| 단계 | 형태 | 어울리는 상황 |
|---|---|---|
| 일회성 프롬프트 | 현재 대화 안의 작업 지시 | 한 번만 쓰거나 아직 탐색 중 |
| 템플릿 | 목표, 맥락, 제약, 검수 기준의 고정 구조 | 비슷한 작업은 반복되지만 절차는 아직 바뀜 |
| Skill | `SKILL.md`와 템플릿, 참고 자료, 스크립트 | 절차가 안정되고 성공 기준이 분명함 |
| 서브에이전트 | 분리된 맥락의 전문 역할 | 검토, 테스트, 디버깅, 조사처럼 범위가 뚜렷한 작업 |
| MCP | 호출 가능한 외부 시스템 도구 | 티켓, 저장소, 내부 시스템을 읽어야 함 |
| Hook | 이벤트 기반 검사 또는 차단 | 비밀 스캔, 포맷 검사, 위험 명령 확인 |
| Plugin | 팀 설치 패키지 | Skills, MCP, Hooks, 템플릿, 문서를 함께 배포 |
| Automation | 예약 또는 이벤트 기반 작업 | 보고서, 모니터링, 반복 검토 |

처음부터 Plugin을 설계하지 마세요. 먼저 작업을 한 번 실행하고, 어떤 단계가 반복되는지, 어떤 검사를 자동화해야 하는지, 어떤 외부 권한이 정말 필요한지 보세요.

상세 분기 논리는 [확장 방식 고르기](/skills/choosing-an-extension-method/)를 참고하세요.

## 제품 입구와 무관

이 메커니즘들은 단일 UI에 **묶이지 않습니다**. CLI, 데스크톱 App, IDE의 Skill/MCP 지원 수준은 다를 수 있으니 [기능 대조](/guide/reference/feature-comparison/)와 공식 설명을 기준으로 하세요.
