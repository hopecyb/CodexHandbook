Skill은 프롬프트 템플릿이 하나 더 생긴 것만이 아닙니다.

Codex가 일하는 방식에 영향을 주고, 때로는 스크립트나 추가 자원도 함께 옵니다.

그래서 출처를 믿을 수 없거나, 내용을 검토하지 않았거나, 버전이 어긋나면 위험이 MCP보다 크게 낮지 않습니다. 이 페이지는 팀이 Skill을 **선정·설치·업그레이드·감사**하는 방법을 설명합니다.

## 내용

- 어떤 Skill은 설치하면 안 되는지
- 버전 고정과 변경 검토
- Plugin 배포와의 관계

## 일반 사용자도 알아야 하는 이유

다음을 한다면:

- 남이 공유한 Skill 설치
- 프로젝트에서 팀 Skill 참조
- 기존 Skill 업그레이드
- 동료에게 Skill 추천

이미 위험 전파 고리에 참여하고 있는 것입니다.

Skill 보안은 「누군가 통일 관리」에만 맡길 수 없습니다. 사용자 각자도 기본 판단력이 필요합니다.

기초: [Skill 개요](/skills/overview/) · [첫 Skill 만들기](/skills/create-your-first-skill/)

## 위협 모델(단순화)

| 위험 | 표현 |
|---|---|
| 악성 Skill | 비밀 유출 유도, 파괴적 shell 실행 |
| 과도한 권한 | 건드리면 안 되는 경로 읽기/쓰기 |
| 공급망 | 변조된 서드파티 Skill 저장소 의존 |
| 낡은 Skill | 새 CLI와 호환되지 않아 동작 이상 |

## 설치 전 먼저 확인할 것

Skill을 만나면 먼저 세 가지를 물으세요.

1. 어디서 왔는가?
2. Codex가 무엇을 더 하게 되는가?
3. `SKILL.md`와 첨부 스크립트를 이해할 수 있는가?

이 세 가지 중 둘에 답하지 못하면 정식 프로젝트에 바로 넣기 부적합합니다.

## 설치 원칙

1. **출처**: 공식 마켓, 회사 자체 Git을 우선. 익명 gist는 신중히
2. **읽기**: 설치 전 `SKILL.md`와 첨부 스크립트를 열어 이상한 권한을 요청하는지 확인
3. **격리**: 고객 프로젝트와 개인 실험 Skill은 디렉터리를 분리
4. **최소 사용**: 하나의 Skill로 해결되면 열 개를 쌓지 말 것

## 흔한 오해

### 1. Skill은 글 설명일 뿐 실제 위험이 없다

워크플로, 도구 선택, 스크립트 실행 방식에 영향을 주므로 위험은 「문체만 바뀌는」 수준이 아닙니다.

### 2. 남들이 자주 쓰는 Skill이면 바로 프로덕션에 넣어도 된다

남이 쓸 수 있다고 해서 당신의 저장소, 권한 경계, 팀 규칙에 맞다는 뜻은 아닙니다.

### 3. Skill 업그레이드는 문서 한 장 업그레이드와 비슷하다

팀에게 Skill 업그레이드는 자동화 동작을 업그레이드하는 일입니다. 의존성 업그레이드만큼 진지하게 다루세요.

## 버전과 업그레이드

| 실천 | 설명 |
|---|---|
| 버전 Pin | 팀 문서에 Skill 이름 + commit/tag 기록 |
| 변경 검토 | Skill 업데이트는 PR로, 의존성 업그레이드처럼 |
| changelog | 팀 Skill 세트의 release note 유지 |
| 롤백 | 이전 버전 사본 보관. 문제 시 빠르게 전환 |

Plugin은 Skill을 묶어 통일 배포할 수 있습니다. [Plugins 개요](/skills/plugins/plugins-overview/)

## 팀 습관

Skill이 장기적으로 여러 사람에게 재사용된다면 「누가 DM으로 경로를 보낸」 상태에 두지 마세요.  
더 적합한 방법은 다음과 같습니다.

- 고정 출처
- 버전 기록
- 업그레이드 설명
- 롤백 경로

## `$skill` 호출과의 관계

사용자가 `$name`으로 명시 호출하면 의도가 분명합니다. **모델이 Skill을 자동 선택**할 때는 `AGENTS.md`에서 사용 가능한 목록과 장면을 제한하세요.

## 팀 거버넌스 체크리스트

- [ ] 설치 허용 Skill 출처 화이트리스트
- [ ] 신규 직원 onboarding은 「기본 패키지」만 설치
- [ ] 분기마다 여전히 필요한 Skill 재검토
- [ ] [허용·거부 규칙](/guide/customization/rules/allow-and-deny-patterns/)과 일치

## 흔한 실수

- 채팅 링크로 「원클릭 만능 Skill」 설치
- 프로덕션 저장소 AGENTS.md가 개인 경로 Skill을 참조
- 업그레이드 후 스모크 작업을 돌리지 않음
- `SKILL.md`를 읽지도 않고 동작을 바로 신뢰
