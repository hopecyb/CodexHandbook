**Skill**은 `SKILL.md`를 담은 디렉터리(스크립트와 참고 자료를 추가할 수 있음)로, 고정된 절차를 Codex가 **자동 또는 명시적으로 호출**할 수 있는 능력으로 패키징한 것입니다.

이미 반복되었고 앞으로도 계속 쓸 작업 방식을 담기에 적합합니다.

## 핵심 개념

### 슬래시 명령과의 차이

| | 슬래시 명령 | Skill |
|---|---|---|
| 트리거 | `/xxx`를 입력 | `$name`으로 호출하거나, 모델이 description으로 매칭 |
| 컨텍스트 | 보통 즉시 펼침 | **점진적 공개**: 평소에는 이름+설명만, 선택 시에만 전문 로드 |
| 적합한 경우 | 고정·고빈도·기억하기 쉬운 진입점 | 절차가 길고, 문서가 필요하며, 모델이 사용 시점을 판단하게 두고 싶을 때 |

### 점진적 공개

Codex는 시작 시 각 Skill의 **name, description, 경로**만 봅니다. 사용하기로 결정할 때만 전체 `SKILL.md`를 로드합니다. 따라서 본문에 자세한 체크리스트를 써도 컨텍스트를 가득 채우지 않습니다.

주의: Skill 목록에는 **초기 문자 예산**(컨텍스트의 일부 정도)이 있습니다. `description`에서는 핵심 트리거 장면을 **맨 앞**에 써서, 잘린 뒤 매칭이 실패하지 않게 하세요.

## Skill 디렉터리 구조

```text
my-skill/
├── SKILL.md          # 필수
├── scripts/          # 선택: 결정적 단계
└── references/       # 선택: 긴 참고 문서
```

`SKILL.md` 최소 예시:

```md
---
name: pr-review
description: 현재 브랜치의 main 대비 diff를 검토하고 위험과 테스트 공백을 표시합니다. 사용자가 review, PR 검토, 병합 전 검사를 요청할 때 사용합니다.
---

## 단계
1. main 대비 diff 가져오기
2. 파일별 분류: 논리 오류, 보안, 성능, 테스트
3. 등급별 목록 출력: 차단 / 제안 / nit
4. 자동 push나 병합은 하지 않음
```

## 저장 위치

| 유형 | 전형적 위치 | 설명 |
|---|---|---|
| 프로젝트 Skill | `.agents/skills/<name>/` | 저장소를 따르며 팀 공유 |
| 사용자 Skill | 사용자 skills 디렉터리(공식 문서 참고) | 개인, 프로젝트 간 |
| 공식 선별 | 설치 도구로 설치 | 경로는 설치 도구가 관리. 수동 디렉터리와 혼동하지 말 것 |

오래된 튜토리얼의 잘못된 경로나 가상의 `trigger:` 필드를 **그대로 베끼지 마세요**. [공식 Skills 문서](https://developers.openai.com/codex/skills)를 기준으로 하세요.

## 트리거 방식

1. **명시적**: 지원 환경에서 `$skill-name`으로 호출(이름은 frontmatter `name`과 일치)
2. **암시적**: 모델이 `description` 의미로 현재 작업에 맞는지 판단

좋은 `description` 작성 요점:

- 「언제 쓸지」와 「언제 쓰지 말지」를 명확히
- 사용자가 말할 법한 키워드 포함(review, 배포, changelog)
- 「코드 작성을 도와준다」처럼 막연한 표현 피하기

## 권장 워크플로

1. 어떤 절차가 이미 몇 번 반복되었음을 발견
2. `SKILL.md` 초안 작성, 우선 순수 텍스트 단계로
3. 작은 작업에서 `$name`과 암시적 매칭을 시험
4. 결정성이 필요할 때 `scripts/` 추가
5. `.agents/skills/`에 커밋하고 팀에 PR

실습: [첫 Skill 만들기](/ko/skills/create-your-first-skill/)

## 흔한 혼란

### 1. Skill과 프롬프트의 차이는?

- **프롬프트**: 이번 작업에서 임시로 하는 말
- **Skill**: 이후 비슷한 작업에도 재사용할 수 있는 절차 묶음

### 2. 처음부터 Skill 작성을 배워야 하나?

아닙니다. 먼저 일반 작업을 분명히 말하고, 어떤 절차가 여러 번 반복되면 그때 Skill로 정리하세요.

### 3. 슬래시 명령과 같은 건가?

완전히 같지는 않습니다. 슬래시 명령은 바로가기 입구에 가깝고, Skill은 완전한 설명과 절차가 있는 작업 패키지에 가깝습니다.

Skill은 시작에 필수인 요소가 아니라, 이미 반복되는 절차를 정리할 때 더 적합합니다.

## 보안 경계

- Skill 안의 스크립트와 MCP 호출은 현재 승인 정책을 상속합니다
- Skill에 비밀을 하드코딩하지 마세요. 환경 변수나 MCP 인증을 쓰세요
- 팀은 서드파티 Skill을 의존성 패키지처럼 검토해야 합니다

## 흔한 실수

- `description`이 너무 길거나 막연해 전혀 트리거되지 않거나 잘못 트리거됨
- 하나의 Skill에 관련 없는 열 가지 절차를 넣음
- 분명하게 서술할 수 있는 단계를 스크립트로 대체해 유지보수가 어려워짐
