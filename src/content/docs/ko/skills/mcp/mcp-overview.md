MCP는 Codex가 외부 도구와 데이터 소스에 연결하기 위한 표준 연결 방식입니다.

예를 들어 Codex가 Jira를 조회하고, 지식 기반을 읽고, 내부 API에 접근하고, 통제된 도구를 다루게 하려면 「어떻게 연결할지, 무엇을 호출할 수 있는지, 권한을 어떻게 관리할지」 메커니즘이 필요합니다. **MCP(Model Context Protocol)**가 그 일을 합니다.

## 내용

- MCP가 「Codex가 실제 시스템에 닿지 못하는」 문제를 해결함
- Skill·Plugin과의 역할 분담
- MCP를 반드시 보안 거버넌스에 넣어야 하는 이유

## 먼저 「무엇이 아닌지」 구분

MCP는 다음이 아닙니다.

- 계정·비밀번호를 Codex에 그대로 붙이는 것
- 모델이 「원하는 대로」 연결하게 두는 것
- 모든 서드파티 서비스를 기본 신뢰하는 것

외부 시스템 연결을 더 통제·감사 가능하게 만드는 정규화된 배선 방식입니다.

## 핵심 개념

```text
Codex  ←→  MCP 클라이언트  ←→  MCP 서버  ←→  외부 시스템
```

| 구성 요소 | 역할 |
|---|---|
| MCP 서버 | 도구 세트 노출(예: `search_issues`, `get_user`) |
| 설정 | Codex에 서버 시작/연결 방법 알림 |
| 도구 호출 | 모델이 작업 중 도구를 선택. 종종 승인 필요 |

MCP는 비즈니스 로직 자체를 **제공하지 않습니다**. 서버가 읽기/쓰기 규칙을 구현하고, Codex는 작업에서 어느 도구를 쓸지 담당합니다.

## MCP의 위치

Skill은 「조작 매뉴얼」에 가깝고, MCP는 「도구 인터페이스」를 다룹니다.

- Skill은 단계를 설명
- MCP는 어떤 외부 도구를 Codex 손에 넘김

둘은 자주 함께 나옵니다.  
Skill이 절차를 정하고, 절차의 어느 단계에서 MCP 도구를 호출합니다.

## Skill·Plugin과의 관계

| | MCP | Skill | Plugin |
|---|---|---|---|
| 본질 | 도구 프로토콜 | 워크플로 설명 | 배포 패키지 |
| 전형적 내용 | API 캡슐화 | 단계와 규범 | Skill + MCP + 앱 커넥터 |
| 누가 유지 | 당신 또는 서드파티 서버 | 당신 또는 팀 | 게시자 |

흔한 조합: **Skill이 절차를 정하고**, 절차의 어느 단계에서 **MCP 도구를 호출**해 티켓 목록을 가져옵니다.

## 언제 MCP를 고려할까

작업이 현재 저장소 파일만 읽고 쓰면 보통 MCP가 필요 없습니다.  
「저장소 밖」의 실제 시스템을 건드려야 하면 MCP, API, 또는 다른 통제된 통합을 고려하기 시작하세요.

## 적용 장면

| MCP에 적합 | MCP에 부적합 |
|---|---|
| Linear/Jira 티켓 조회 | 순수 저장소 내 코드 수정 |
| 문서/지식 기반 읽기 전용 조회 | 단순 `curl`로 충분하고 재사용 불필요 |
| 통제된 내부 도구 | 감사 없는 고권한 프로덕션 DB 쓰기 |

## 흔한 오해

### 1. MCP만 연결하면 Codex가 무엇이든 할 수 있다

할 수 있는 일은 MCP 서버가 노출한 도구와, 그 도구가 허용하는 일에만 달립니다.

### 2. MCP는 기술 접속 문제이지 보안 문제가 아니다

MCP가 실제 시스템에 연결되면 동시에 다음이 됩니다.

- 권한 문제
- 데이터 노출 문제
- 감사 문제
- 공급망 문제

### 3. MCP가 있으면 Skill이나 문서가 필요 없다

여전히 필요합니다. MCP는 「도구를 호출할 수 있는지」를 해결하고, 「어떤 절차로 호출할지, 언제 호출하지 말아야 할지」는 해결하지 않습니다.

## 보안 경계

- **최소 권한**: 읽기 전용, 프로젝트 한정, IP 한정
- **자격 증명**: OAuth 또는 단기 토큰. prompt·Git에 넣지 말 것
- **사람 승인**: 쓰기, 대량 삭제, 외부 메시지 발송은 재검토 설정
- **공급망**: 신뢰할 수 있는 서버만 연결. 서드파티 MCP 소스 검토

기업 장면은 로드맵 `11-team-enterprise/security/plugin-and-mcp-risk`를 참고하세요.

## 접속 순서

1. 공식 MCP 문서를 읽고 현재 클라이언트 설정 형식 확인
2. **읽기 전용** 공식 또는 커뮤니티 예시 서버부터
3. 테스트 프로젝트에서 단일 도구 호출 검증
4. 실제 시스템에 연결하고 운영 매뉴얼 작성

조작 단계: [MCP 서버 연결](/skills/mcp/connect-an-mcp-server/)

## 흔한 실수

- 「개발 편의」로 MCP 서버에 과도한 권한 부여
- MCP를 Skill 대체품으로 취급(절차 설명은 여전히 Skill 또는 AGENTS.md에)
- 설정 변경을 코드 검토에 넣지 않음
