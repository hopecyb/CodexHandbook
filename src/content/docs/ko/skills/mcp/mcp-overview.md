MCP는 “모델이 외부 기능을 사용하려 한다”는 요청을 구조화된 도구 호출로 바꿉니다. 타사 문서, 브라우저, Figma, 이슈 시스템, 내부 서비스를 연결할 때 적합합니다.

![일러스트: 도우미가 범용 허브에 연결되고, 표준 케이블이 데이터베이스, 캘린더, 티켓 보드, 클라우드 드라이브로 이어진다](/illustrations/mcp-overview.webp)

## 한 번의 호출 흐름

```text
작업 중인 Codex
  -> MCP 클라이언트(Codex host가 제공)
  -> MCP 서버(로컬 프로세스 또는 원격 서비스)
  -> 외부 시스템(문서, 디자인, 이슈, 내부 API)
  -> 구조화된 결과가 작업으로 반환됨
```

| 구성 요소 | 담당하는 일 | 담당하지 않는 일 |
|---|---|---|
| Codex host | 설정을 읽고 서버에 연결해 Agent에 도구 제공 | 서버의 업무 권한을 대신 정의하지 않음 |
| MCP 서버 | 도구, 인증, 인자, 구조화된 결과 정의 | 도구의 안전성을 자동으로 보장하지 않음 |
| Skill | 언제 어떤 순서로 도구를 사용할지 규정 | 네트워크 연결을 만들지 않음 |
| Plugin | Skills, 커넥터, MCP 등의 기능을 묶어 배포 | 또 다른 도구 프로토콜이 아님 |

## 현재 지원되는 서버 방식

### STDIO

Codex가 로컬 프로세스를 시작하고 표준 입력과 출력을 통해 통신합니다. 로컬 개발 도구나 현재 컴퓨터에서만 실행하는 서비스에 적합합니다.

주요 위험은 이 프로세스가 로컬 실행 환경을 상속한다는 점입니다. 명령, 의존성 출처, 전달되는 환경 변수를 모두 검토해야 합니다.

### Streamable HTTP

Codex가 원격 주소에 연결합니다. 현재 공식 문서는 Bearer token, OAuth, 신뢰할 수 있는 자사 서버에 대한 ChatGPT 세션 인증을 지원한다고 명시합니다.

주요 위험은 원격 서비스가 도구 인자를 받는다는 점입니다. TLS, 신원, 로그, 데이터 보관, 도구 권한을 반드시 확인해야 합니다.

## MCP, Skill, Plugin을 조합하는 방법

“매주 우선순위가 높은 이슈 확인”을 예로 들면 다음과 같습니다.

| 계층 | 내용 |
|---|---|
| MCP | `search_issues`, `get_issue` 등의 도구 제공 |
| Skill | 필터 조건, 근거 요구 사항, 보고 형식 규정 |
| Plugin | Skill, 커넥터, MCP 정의를 팀에 설치할 수 있도록 배포 |
| Scheduled task | 검증된 작업을 정해진 시간에 실행 |

이들은 서로 다른 역할이며 아래에서 위로 올라가는 업그레이드 단계가 아닙니다. 전체 관계는 [확장 기능 지도](/ko/skills/capability-map/)를 참고하세요.

## MCP를 연결할 가치가 있을 때

| 연결할 가치가 있음 | 지금은 불필요함 |
|---|---|
| 같은 외부 시스템을 반복 조회 | 일회성 공개 웹페이지 조회 |
| 구조화된 도구 인자와 결과가 필요 | 저장소 내부 파일 작업만으로 충분 |
| OAuth 또는 세밀한 도구 제어가 필요 | 쓰기 권한이 큰 인터페이스만 있고 테스트 환경은 없음 |
| 팀이 연결을 동일하게 재사용해야 함 | 서버 출처를 검토할 수 없음 |

## 보안 단계

1. **읽기 전용 시험**: 공개 문서나 테스트 테넌트에서 조회 도구만 활성화합니다.
2. **팀 검증**: 프로젝트, 역할, 도구 허용 목록을 제한하고 실패와 소요 시간을 기록합니다.
3. **제한된 쓰기**: 되돌릴 수 있는 좁은 범위의 쓰기 작업에 사람의 승인을 유지합니다.
4. **관리형 운영**: 권한 회수, 설정 검토, 로그의 민감 정보 제거, 환경별 격리를 가능하게 합니다.

token을 프롬프트, Git, 정적인 HTTP header에 쓰지 마세요. OAuth, `bearer_token_env_var` 또는 환경 변수 전달을 우선 사용하세요.

## 연결 전 체크리스트

- [ ] 서버 출처, 버전, 시작 명령을 검토할 수 있습니다.
- [ ] 도구 목록에서 읽기와 쓰기 작업을 구분했습니다.
- [ ] 테스트 테넌트나 최소 권한 계정을 사용합니다.
- [ ] 어떤 인자와 결과가 원격 로그에 남는지 확인했습니다.
- [ ] 쓰기 작업에 승인, 롤백, 감사 경로가 있습니다.
- [ ] 팀이 서버를 비활성화하고 권한을 회수하는 방법을 압니다.
