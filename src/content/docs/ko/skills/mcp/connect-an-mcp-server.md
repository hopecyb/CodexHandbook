이 페이지는 연결과 검증 절차에 초점을 둡니다. 프로토콜 세부와 서버 개발은 공식 MCP 문서를 참고하세요.

## 시작 전

- [ ] [MCP 개요](/skills/mcp/mcp-overview/)의 보안 경계를 이해함
- [ ] 읽기 전용 또는 샌드박스 환경의 테스트 계정이 있음
- [ ] 현재 Codex 클라이언트 버전이 MCP를 지원하는지 확인(공식 문서 기준)

## 권장 절차

### 1. 서버 유형 선택

| 유형 | 설명 | 위험 |
|---|---|---|
| 로컬 stdio 서버 | 본기에서 프로세스 시작 | 중간: 프로세스 권한=사용자 권한 |
| 원격 HTTP/SSE | 호스팅 서비스 | 중–고: TLS, 토큰 교체 필요 |

처음 연결할 때는 **공식 예시 또는 읽기 전용 로컬 서버**부터 하세요.

### 2. 설정 추가

설정 위치는 CLI/App마다 다르며, 흔히 사용자 또는 프로젝트급 `mcp` 설정 블록입니다. 구조 예시(**필드명은 공식 문서 기준**):

```json
{
  "mcpServers": {
    "example-readonly": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"],
      "env": {
        "API_TOKEN": "환경 변수에서 읽기. 저장소에 하드코딩하지 말 것"
      }
    }
  }
}
```

원칙:

- 비밀은 환경 변수 또는 비밀 관리자로 주입
- 설정 변경은 Git 검토를 거침(secrets 제외)

### 3. 클라이언트 재시작 또는 리로드

MCP 설정을 바꾼 뒤에는 보통 Codex 세션을 재시작해 서버 목록을 새로 고칩니다.

### 4. 도구가 보이는지 검증

작업에서 명확히 요청하세요.

```text
현재 사용 가능한 MCP 도구를 나열하세요(이름과 한 줄 설명만).
그다음 읽기 전용으로 테스트 도구 하나를 호출하고 결과를 보여 주세요.
쓰기 작업은 하지 마세요.
```

### 5. 작은 단계로 시험

실제이지만 위험이 낮은 작업을 고르세요. 예: 「MCP로 #123 티켓 제목을 조회하고, 상태는 바꾸지 마세요.」

## 인증 모드

| 모드 | 적합 |
|---|---|
| API Key / PAT | 개인 개발, 정기 교체 |
| OAuth | 사용자급 인가, SaaS에 적합 |
| 무인증 로컬 | 본기 mock만. 네트워크에 노출하지 말 것 |

실패 시 확인: 토큰 만료, 환경 변수 미전달, 회사 프록시 가로채기.

## 디버그 체크리스트

| 현상 | 가능한 원인 |
|---|---|
| 도구 목록이 비어 있음 | 설정 경로 오류, 프로세스 시작 실패 |
| 호출 타임아웃 | 네트워크, VPN, 서버 다운 |
| 권한 거부 | 토큰 scope 부족 |
| 모델이 도구를 전혀 호출하지 않음 | 작업 설명이 요구하지 않음; 또는 도구 description이 불분명 |

## 승인과 함께 쓰기

낯선 도구를 처음 호출할 때 클라이언트가 확인을 띄울 수 있습니다. 예상된 동작입니다. 팀 규범에서 「모든 MCP 쓰기 작업을 영구 허용」을 권장하지 마세요.
