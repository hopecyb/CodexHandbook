# 생성 템플릿

처음부터 만드는 작업에서 가장 흔히 생기는 문제는 둘입니다.

- 목표는 큰데 경계가 없음
- 정보가 아직 부족한데도 Codex에게 바로 생성을 재촉함

생성 템플릿은 산출물, 용도, 제약을 먼저 밝힌 뒤 시작하게 합니다.

## 템플릿

```text
목표: 【산출물 이름】을 만들어 【용도/사용자】에 쓴다.
배경: 【기존 약속, 디자인 스타일, 의존성 제한】
입력: 【명세, 스케치, 참고 @파일】
제약:
- 【경로 범위】만 수정/생성
- 【제외 항목】을 도입하지 말 것
- 【고위험 작업】은 제 승인 후에 실행
수락:
- 【관찰 가능한 결과 1】
- 【관찰 가능한 결과 2】
- 자체 점검 단계 제공
정보가 부족하면 먼저 가정을 나열하고 물어보세요. 추측하지 마세요.
```

## 언제 이 템플릿이 맞는가

- 페이지, 컴포넌트, 스크립트, 문서를 처음부터 만들 때
- 무엇을 낼지는 알지만 아직 손대지 않았을 때
- 생성 범위를 먼저 밝힌 뒤 시작하고 싶을 때

## 흔한 오해

### 1. 생성 작업은 “자유롭게 맡기면 된다”

처음부터 만들수록 다음을 더 말해야 합니다.

- 누구에게 쓰이는지
- 무엇에 쓰는지
- 어떤 스타일·기술 경로는 건드리면 안 되는지

### 2. 배경은 선택적 장식이다

생성 작업에서 배경은 산출물 방향에 직접 영향을 주는 경우가 많습니다.

### 3. 수락에 “괜찮아 보이면 됨”이면 충분하다

그렇게 쓰면 결국 끝났는지 판단하기 어렵습니다.

생성 작업에서 가장 위험한 경우는, “무엇을 만들지·누구에게 쓰일지”도 밝히지 않고 바로 시작하는 것입니다.
