# 검토 템플릿

검토류 작업이 가장 쉽게 이탈하는 지점은, 처음부터 “손쉽게 대신 고쳐 주는” 일로 바뀌는 것입니다.

문제를 먼저 찾은 뒤, 고칠지 말지를 정하는 편이 더 안전합니다.

## 템플릿

```text
현재 【main/대상 브랜치】 대비 diff를 검토하세요. 아직 코드를 바꾸지 마세요.
차원:
1. 【issue/명세】 범위를 넘었는지
2. 논리 오류, 경계, 오류 처리
3. 보안(비밀키, 주입, 권한)
4. 테스트·문서가 변경과 맞는지
등급별 목록으로 출력: 🔴 차단 / 🟡 제안 / 🟢 통과. 항목마다 파일과 행 번호 포함.
```

## 언제 이 템플릿이 맞는가

- PR 검토
- diff 검토
- 문서·설정 변경 한 라운드의 위험 검토

## 흔한 오해

### 1. 검토는 의견을 조금 달라고 하는 것이다

더 정확히는, 구조에 따라 문제를 찾게 하는 것입니다.

### 2. 분명한 버그가 없으면 통과다

검토는 다음도 봐야 합니다.

- 범위를 넘었는지
- 테스트·문서가 따라왔는지
- 보안·경계 문제가 있는지

검토 템플릿의 핵심은 고정 차원으로 위험을 드러내는 것이며, “좋은지 나쁜지”를 막연히 평가하는 것이 아닙니다.
