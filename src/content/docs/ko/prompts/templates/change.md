# 수정 템플릿

이 템플릿은 “기존 것을 조금 고치는” 작업에 맞습니다.

수정류 작업은 변경 경계를 먼저 분명히 하세요.

## 템플릿

```text
목표: 【기존 기능/파일】에서 【구체적 변경】을 완료한다.
배경: 【왜 고치는지, 영향 범위】
입력: @【관련 파일 경로】
제약:
- 제가 명시적으로 허용하지 않는 한 【API/스타일/동작】을 유지
- 최소 diff, 관련 없는 리팩터 금지
- 매 단계 후 【관련 테스트】만 실행
수락:
- 【동작 변화 설명】
- 관련 테스트 통과
- diff가 필요한 파일만 포함
```

## 언제 이 템플릿이 맞는가

- 기존 페이지·컴포넌트를 고칠 때
- 분명한 버그를 고칠 때
- 카피·인터랙션·설정을 미세 조정할 때
- “이 부분만 고치고, 손쉬운 리팩터는 하지 마”를 강조하고 싶을 때

## 흔한 오해

### 1. 수정은 생성보다 쉬우니 훨씬 적게 써도 된다

수정은 옛 코드, 옛 제약, 숨은 의존성에 걸리기 쉬워 경계가 더 필요합니다.

### 2. “최소 diff”는 몇 줄만 덜 고치는 것이다

“최소 diff”는 **목표와 직접 관련된 부분만** 고친다는 뜻입니다.

### 3. “기존 동작을 유지”만 말하면 충분하다

무엇이 “기존 동작”인지 한 문장 더 보완하는 편이 좋습니다.

## 이 템플릿이 막는 것

주로 다음을 막습니다.

- 너무 많이 고침
- 방향을 잘못 고침
- 권한 없는 계층까지 고침

수정류 프롬프트는 “무엇을 고칠지”뿐 아니라 “어디까지만 고칠 수 있는지”도 말해야 합니다.
