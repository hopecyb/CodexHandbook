# 자동화 템플릿

자동화류 작업의 흔한 오해는 “자동으로 돌릴 수 있는지”만 생각하고, 다음을 먼저 생각하지 않는 것입니다.

- 실패하면 어떻게 할지
- 누가 결과를 볼지
- 오류 시 안전하게 멈출 수 있는지

자동화 템플릿의 핵심은, 문제가 생겨도 통제 가능하게 만드는 것입니다.

## 템플릿

```text
목표: 【반복 작업】을 【스크립트/Skill/예약 작업】으로 자동화한다.
트리거: 【수동 / 예약 / CI】
입력: 【데이터 소스, 설정 파일】
제약:
- 실패 시 종료 코드와 로그 위치를 분명히 할 것
- 비밀키를 하드코딩하지 말 것. 환경 변수 사용
- dry-run 모드를 제공할 것
수락:
- 【예시 입력】에서 기대 결과를 출력
- 실행·장애 대응 방법을 문서에 설명할 것
```

## 언제 이 템플릿이 맞는가

- 규칙이 분명한 반복 작업
- 스크립트화·예약화가 필요한 프로세스
- dry-run, 로그, 종료 코드 같은 가드를 먼저 보완하고 싶을 때

## 흔한 오해

### 1. 자동화는 사람 판단을 없애는 것이다

실제로 더 잘 자리 잡는 자동화는 자동 점검, 자동 요약, 초안 자동 생성이기도 합니다.

### 2. 한 번 돌아가면 자동화할 수 있다

장기 실행 자동화로 만들려면 다음도 보완해야 합니다.

- 로그
- 종료 코드
- dry-run
- 장애 대응 설명

자동화 템플릿의 가치는, 장기적으로·안전하게 돌게 만드는 데 있습니다.
