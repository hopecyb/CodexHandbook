手册中的命令、权限、价格和产品功能会随版本变化。技术核对的目标，是让读者知道哪些结论有当前依据、适用于什么环境，以及哪些部分仍需自行确认。

## 核对目标

核对不只是检查文字是否通顺，还要确认关键事实与当前产品一致，操作步骤能够在声明的环境中完成，结论没有超出证据能够支持的范围。

## 证据优先级

1. 产品行为、参数和限制优先使用 OpenAI 官方文档。
2. 声称“已运行”的示例必须有实际执行结果和环境信息。
3. 社区文章可以帮助发现主题，但不能替代官方资料或实际运行。
4. 链接能够打开不等于内容足以支持结论，必须阅读原文。
5. 无法确认的信息应明确写出不确定性，不应靠推测补齐。

## 需要记录的范围

- 适用产品：App、CLI、IDE 或 Cloud
- 操作系统、客户端与重要依赖版本
- 实际执行过的步骤和检查方式
- 没有覆盖的平台、入口或边界条件
- 引用资料的具体页面，而不是只有网站首页

## 核对顺序

1. 先确认页面讨论的产品、入口和使用场景。
2. 对照当前官方文档检查易变事实。
3. 如果正文声称步骤可以运行，就在干净环境中从头执行。
4. 将未复现或不确定的部分缩小范围，并在正文中直接说明。
5. 最后检查站内链接、外部链接和读者需要的前置条件。

## 容易变化的信息

以下内容应在产品发布重大更新后优先复查：

- 命令、子命令和 flags
- 权限默认值与沙箱行为
- 套餐、模型名、价格、配额和地区可用性
- MCP、Hook 和其他集成接口
- 菜单位置、按钮名称和产品入口

## 无法确认时

不要把推测写成事实。可以删除过时的具体细节、改写为稳定的方法说明，或在 PR 与 issue 中记录待确认问题。涉及当前行为、价格和政策时，最终应回到官方资料。
