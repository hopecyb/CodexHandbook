“交互模式”指的是你在终端里和 Codex 一来一回地对话，它会解释、执行，也会在需要时等你确认。

这也是 CLI 的常见用法之一。

启动交互会话后：

1. 在项目目录中启动（或按文档指定工作目录）
2. 输入与 App 相同质量的提示词
3. 在提示时批准/拒绝工具调用
4. 用 `/` 类快捷命令（若有）管理会话——以当前 CLI 帮助为准

提示词方法仍适用：[提示词](/prompts/)

## 常见误会

### 1. 在终端里用，提示词是不是就可以随便一点？

不行。

虽然入口换成了终端，但任务描述质量还是一样重要。
目标、限制范围、完成标准，仍然越清楚越稳。

### 2. 为什么强调“在项目目录中启动”？

因为 CLI 需要知道自己是在哪个项目里工作。
目录不对，就容易出现：

- 看不到该看的文件
- 改到错误目录
- 读不到项目规则

### 3. 它在终端里问我要不要批准，是不是出错了？

很多时候这说明它正在按权限边界工作，不是在异常执行。

## 第一次使用时的简单场景

第一次可以先做这种小任务：

- 在项目根目录启动
- 只改一个文件
- 完成后让它说明改了什么

CLI 交互模式就是在终端里跑一条对话式任务流。目录要对，提示词也要清楚。
