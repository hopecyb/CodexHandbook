CLI 出问题时，报错看起来可能都像终端报错，但背后原因未必是同一类。

CLI 排障时，先判断问题属于“没装好 / 没登上 / 没权限 / 进错目录”哪一类。

| 症状 | 先试 |
|---|---|
| command not found | 检查安装与 PATH |
| 认证失败 | 重新登录；检查组织策略 |
| 权限拒绝 | 查看审批模式与沙箱设置 |
| 在错误目录改文件 | 确认当前工作目录 |

## 先分 4 类

- **命令都找不到**：通常是安装或 `PATH`
- **命令能跑，但进不去**：通常是认证
- **能进，但做不了事**：通常是权限或沙箱
- **做了不对的事**：通常是目录或上下文不对

## 常见误会

### 1. 所有 CLI 报错都要去研究同一个日志

先把问题分到大类，通常比一开始就深挖错误细节更快。

### 2. 权限拒绝就是程序坏了

很多时候不是坏了，而是审批、沙箱或策略在正常工作。

### 3. 命令执行了，就说明目录没问题

也不对。

CLI 很多问题不是命令不会跑，而是你在错误的仓库或错误的工作目录里跑。

## 排查顺序

1. 先确认命令是否存在
2. 再确认登录状态
3. 再看当前权限模式和沙箱限制
4. 最后确认当前工作目录是不是你以为的那个项目

CLI 排障时，先分清这是安装问题、登录问题、权限问题，还是目录问题，排查通常会顺一些。
