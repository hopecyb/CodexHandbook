---
title: 工具选择
description: 何时用终端、搜索、浏览器或其他工具。
---

“工具选择”说的是：这件事该用哪种方式做，既有效，也安全。

选工具时，按任务类型判断通常更清楚。

## 选工具时在看什么

选工具时，主要看这几件事：

- 哪个最贴近当前任务
- 哪个能用最小代价拿到结果
- 哪个风险最低、最好检查

同一个目标，用错工具不一定会完全失败，但经常会更慢、更绕、也更容易出意外。

| 需要 | 优先 |
|---|---|
| 改仓库内文件 | 文件工具 |
| 跑测试/构建 | 终端 |
| 查公开事实 | Web 搜索 |
| 看真实页面状态 | 浏览器（进阶） |

在提示词里写清允许与禁止的工具，减少擅自出网或乱装依赖。

## 拿不准时怎么选

如果一时拿不准，可以按这个顺序判断：

1. 这是在处理本地项目，还是在查外部事实
2. 我需要“执行动作”，还是只需要“看到结果”
3. 哪个工具能最小范围完成这一步

比如：

- 要看代码改动 -> 文件
- 要确认构建是否通过 -> 终端
- 要确认网页现在长什么样 -> 浏览器
- 要确认最新公开信息 -> Web 搜索

## 常见误会

### 1. 工具不是越强越好

越强的工具，通常也意味着：

- 影响范围更大
- 风险更高
- 更需要你理解它在做什么

### 2. 既然终端什么都能做，也不一定要优先走终端

如果只是要确认页面长什么样，浏览器通常比终端更直接。  
如果只是要查一个公开版本号，Web 搜索比让它到处执行命令更合适。

### 3. 不会选怎么办？

可以按这个规则判断：

- **读改项目内容** -> 文件
- **验证命令或构建** -> 终端
- **查公开事实** -> 搜索
- **看页面真实呈现** -> 浏览器

### 4. 一次任务通常不只会用一种工具

很多真实任务本来就会组合使用，比如：

- 先读文件，再跑构建
- 先搜索公开事实，再回到文档改写
- 先用浏览器看页面，再到代码里修

关键是每一步都尽量用更合适的工具，不用执着于“只能选一个”。

## 可直接使用的写法

可以直接在任务里补一句：

```text
优先用文件和终端完成，不要联网搜索；如果需要浏览器检查页面，请先说明原因。
```

先选最小、最贴任务的工具，不要一开始就动用影响范围最大的那种。
