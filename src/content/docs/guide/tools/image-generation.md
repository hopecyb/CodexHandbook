Codex 可在部分场景调用**图像生成**能力：插图、图标草稿、UI 概念图、示意图。生成结果应视为**待验收产物**，而非可直接上线的品牌资产。

它适合先给出视觉草稿，不适合直接当成最终成品。

## 本页内容

- 何时在 Codex 里生成图 vs 用专业工具
- 如何写图像 prompt 与约束
- 版权、品牌与文件管理

## 适用场景

| 适合 | 不适合 |
|---|---|
| 博客配图草稿、内部文档示意图 | 受严格品牌手册约束的对外物料 |
| 快速探索 UI 布局氛围 | 需像素级还原的设计交付 |
| 教程中的示例图标 | 含真人肖像且未授权的场景 |

与 [图像提示](/prompts/prompting-with-images/) 互补：那一页讲**输入**图像；本页讲**输出**图像。

## 图像生成适合做什么

图像生成更适合做这些事：

- 快速出方向
- 帮你看到一个视觉概念
- 给文章、文档、原型先配一个能用的草图

下面这些用途不适合直接交给生成结果：

- 假装这是正式品牌物料
- 假装这是精准设计稿
- 假装这是可直接对外发布的最终视觉

## 推荐工作流

1. 说明用途、尺寸比例、风格关键词（避免侵权风格名堆砌）
2. 要求输出格式（PNG/SVG 若支持）与保存路径
3. 生成后 [验证产物](/guide/quality/verify-artifacts/)：打开文件、检查分辨率与可读性
4. 对外发布前由设计或法务复核

## 常见误会

### 1. 只要画面好看，就说明这张图可以用了？

你还要看：

- 场景是不是符合用途
- 细节有没有怪异
- 文字有没有乱码
- 风格是不是和你的内容匹配

### 2. 我是不是只要一句“帮我生成一张图”就够了？

往往不够。  
至少要讲清几件事：

- 用途
- 画幅或尺寸比例
- 风格方向
- 是否要文字
- 文件格式

### 3. 图像生成是不是能替代设计师？

它更接近：

- 前期探索工具
- 内容配图工具
- 概念草图工具

而不是严格设计交付的替代品。

## 可以怎么写

可以按这个结构提：

1. 这张图拿来做什么
2. 需要横图、竖图还是方图
3. 希望什么气质和配色
4. 要不要出现文字
5. 输出后你准备怎么验

## 文件与仓库

- 大图放 `assets/` 或 CDN，评估 Git 体积
- 在 PR 中说明生成 prompt 与模型版本（内部审计）
- 见 [图像与截图](/guide/files-and-artifacts/images-and-screenshots/)

## 安全与合规

- 不要生成含敏感标识、虚假证件、他人肖像的误导内容
- 企业政策可能禁止某些题材；遵守 [可接受使用](https://openai.com/policies/) 与内部规定

## 常见错误

- 直接提交未压缩的 4K 图进仓库
- 用生成图冒充实拍或官方 logo
- 未在 prompt 中约束「无文字」导致乱码字幕

图像生成更适合先出方向和草稿；对外交付时，仍然要按正式产物标准验收。
