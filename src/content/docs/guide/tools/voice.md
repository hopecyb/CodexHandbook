部分 Codex 客户端支持**语音**：你说出任务，或听取回复摘要。适合双手占用、快速口述想法——**不**适合朗读密钥或替代书面验收记录。

## 这篇解决什么问题

- 语音适合哪些任务形态
- 与文字 prompt 如何配合
- 隐私与准确率注意

## 适用场景

| 适合 | 不适合 |
|---|---|
| 口述高层目标、头脑风暴 | 精确到变量名的代码指令 |
| 移动端简短跟进 | 宣读 API key、密码 |
|  accessibility 需求 | 需要可搜索、可 diff 的规范文档 |

口述后建议让 Codex **复述理解**或生成文字计划，你再确认——见 [请求计划](/prompts/ask-for-a-plan/)。

## 使用建议

1. 安静环境、简短句子，分段说清「目标 / 约束 / 完成标准」
2. 涉及文件路径、分支名时**改用打字**或让 Agent 复述拼写
3. 敏感项目关闭语音云端处理（若产品提供本地/禁用选项）
4. 重要决策保留文字记录在 issue 或 PR

## 隐私

- 语音可能经过云端转写；勿读客户 PII、凭证
- 公共场所注意旁人旁听
- 团队政策可能禁止录音类功能处理机密代码名

## 与多模态的关系

- **输入图像**：设计稿、截图 → [图像提示](/prompts/prompting-with-images/)
- **输入语音**：本页
- **输出**：仍以代码、文件、文字 diff 为主；语音摘要不能代替审查

## 常见错误

- 长篇口述无结构，Agent 漏约束
- 用语音接受大批量代码变更却不看 diff
- 在语音里描述未脱敏的生产事故细节
