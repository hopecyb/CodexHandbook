终端是让 Codex 执行动作最直接的方式之一，所以效率很高，也更需要你看懂风险。

## 为什么它既强大也危险

文件工具主要处理文本；终端会直接操作系统和运行环境。

一旦进入终端，常见动作就不只是读，而可能变成：

- 安装
- 构建
- 测试
- 删除
- 提交
- 推送

使用前先弄清楚它会改动哪里。

终端强大也危险。原则：

- 审批前读懂命令
- 禁止 `rm -rf`、强制推送、改 ssh 配置等，除非你完全理解且必要
- 把验证命令写进验收标准

产品入口：[集成终端](/guide/desktop-app/integrated-terminal/)

## 为什么终端风险更高

因为它不只是“给建议”，而是真的会执行动作。

比如它可能会：

- 安装依赖
- 删除文件
- 运行测试
- 改写配置
- 推送代码

看不懂一条命令时，先问清楚，再决定是否允许。

## 适合用终端的情况

下面这些事情，适合用终端：

- 跑测试
- 跑构建
- 查文件状态
- 执行项目已有脚本

如果只是想：

- 看页面长什么样
- 查最新公开资料
- 修改一两处已知文本

终端未必是第一选择。

## 常见误会

### 1. 不懂命令，也不是完全不能用终端

一开始不需要会写很多命令，但至少要能看懂：

- 这条命令大概想干什么
- 会不会改动文件或系统
- 是否真的和当前任务有关

### 2. 只要是测试命令，就一定安全？

也不能这么想。  
大多数测试命令风险较低，但仍然要看：

- 会不会写入很多文件
- 会不会联网
- 会不会调用你不清楚的脚本

### 3. 看不懂时怎么办？

可以直接追问，例如：

```text
这条命令会做什么？会修改哪些内容？如果不运行它，有什么影响？
```

## 可以直接套用的写法

可以直接补一句：

```text
运行命令前先说明用途、是否会写文件、是否会联网，以及失败后怎么恢复。
```

运行前先确认这条命令会改动哪里。
