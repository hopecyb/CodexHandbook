**Computer Use**（计算机使用）让 Agent 像人一样查看屏幕、移动指针、键入文字，不仅限于浏览器或终端。能力最强，**风险与审批要求也最高**。

Computer Use 直接作用在屏幕、鼠标、键盘这一层，和浏览器工具、终端不是同一类能力，因此也更需要谨慎启用。

## 本页内容

- Computer Use 与浏览器、终端的分工
- 哪些任务值得启用
- 个人与团队如何设防

## 能力边界

| 层级 | 典型能力 |
|---|---|
| 终端 | Shell、脚本、CLI 程序 |
| 浏览器 | 网页 DOM、有限交互 |
| Computer Use | 桌面应用、系统对话框、多窗口工作流 |

## 它和别的工具有什么区别

可以把它和其他工具这样区分：

- 整个桌面上做事
- 在多个窗口之间切换
- 点真实的按钮和系统弹窗

因此，它接触到的界面和信息范围通常也更大。

适合：

- 演示软件中无 API 的重复点击流程（需你监督）
- 跨应用复制数据（在合规前提下）
- 验证桌面 App 本身的行为

不适合：

- 日常写代码（用 IDE + 终端更高效）
- 无人值守生产操作
- 绕过安全软件或 DRM

## 常见误会

### 1. 能力更强，是否就该优先用？

只有在下面这些情况里，它的价值才会更明显：

- 任务真的涉及桌面 GUI
- 没有更轻、更安全的工具能完成

### 2. 只要我盯着看，就没什么风险？

人在旁边会更安全，但仍然可能发生：

- 误点确认框
- 打开不该打开的窗口
- 把屏幕上的敏感信息带入流程

### 3. 它是不是可以替代所有 GUI 自动化？

它更适合临时协助、验证流程、处理没有 API 的 GUI 步骤，不适合当成稳定、长期、无人值守的生产自动化方案。

## 风险模型

Computer Use 几乎等价于**把键盘鼠标交给 Agent**：

- 可打开邮件、聊天、文件管理器
- 可能误点确认对话框
- 屏幕可能包含通知里的敏感信息

必读：[权限与审批](/guide/foundations/permissions-and-approvals/)、[沙盒与网络](/guide/foundations/sandbox-and-network/)

## 怎么判断该不该用它

目标只是下面这些事情时，一般没必要先用 Computer Use：

- 改代码
- 跑测试
- 看网页
- 查资料

这些大多可以用更轻的工具完成。

如果任务属于下面这些情况，再考虑启用：

- 必须操作桌面应用
- 必须跨多个 GUI 窗口
- 必须处理浏览器和终端都够不到的界面

才值得认真考虑它。

## 推荐使用方式

1. **专用环境**：虚拟机或次要用户账号，屏幕上无隐私窗口
2. **任务最小化**：「在 Calculator 中验证公式」而非「帮我处理所有邮件」
3. **人在环**：保持可见，随时准备中断
4. **录屏/日志**：团队复盘用（注意录屏也含敏感信息）
5. **完成后检查**：文件系统、剪贴板、已打开应用

企业环境可能默认禁用；以托管策略为准。

## 与浏览器工具选择

```text
只需看网页？        → 浏览器工具
要操作 IDE 外应用？  → Computer Use（更谨慎）
只需改代码跑测试？  → 终端 + 文件工具
```

见 [工具选择](/guide/tools/tool-selection/)

## 可以直接套用的写法

可以直接这样写：

```text
只允许操作 Calculator 和本地测试应用，不要打开邮件、聊天软件、文件管理器或任何生产后台。
如果出现系统确认框，先停下来说明再继续。
```

## 常见错误

- 在主桌面跑不可信项目的 Computer Use
- 屏幕上有 2FA、银行、客户数据仍继续任务
- 把 GUI 自动化当完整测试策略

## 验收清单

- [ ] 仅在隔离环境启用
- [ ] prompt 写明允许操作的应用与禁止项
- [ ] 任务后检查无意外文件/网络连接
- [ ] 组织策略允许该能力
