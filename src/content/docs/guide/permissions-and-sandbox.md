# 权限与沙箱

Codex 不应在未获同意时执行高风险操作。**审批**是人机协作的关键闸门；**沙箱**限制 Agent 能触达的文件系统与部分系统能力。

## 本页内容

很多人第一次看到“权限”“审批”“沙箱”“网络访问”这几个词，会觉得它们差不多，反正都属于安全设置。

最容易出问题的，恰好就是这个混淆：你以为自己只是允许它继续执行，实际上可能同时放开了写文件、跑命令或访问外网的边界。

这页把这几个概念拆开，帮助你判断每次确认到底放开了什么。

## 先分清这几个概念

可以这样分：

- **审批**：要不要先问你一句
- **沙箱**：就算想做，也最多能碰到哪里
- **网络访问**：能不能把信息带出去，或从外面拉东西回来

它们会一起影响结果，但不是一回事。

## 你通常需要关心的

- 是否允许读写当前项目外的路径
- 是否允许联网
- 是否允许执行特定 shell 命令
- 团队是否下发了强制策略（托管配置）

## 沙箱与网络

**沙箱**降低误操作面。**网络访问**另算一层风险：可能外泄提示内容中的敏感信息，或拉取不可信数据。

刚开始用时，通常可以按这个思路处理：

1. 第一次练习关闭不必要的网络，或仅允许明确需要的访问
2. 不要把生产密钥放进练习项目
3. 看到「要出网 / 要写敏感路径」的请求，先停下来读懂再批

## 常见误会

### 弹窗出现，不代表一定危险

很多正常操作也会触发审批，比如：

- 安装依赖
- 写入项目外目录
- 打开浏览器或系统应用
- 访问外部网站或 API

真正要判断的是：**这一步是不是当前任务本来就需要的。** 不能只看弹窗有没有出现。

### 没弹窗，也不等于完全没风险

如果当前沙箱本来就允许某类操作，或者你之前已经放宽过规则，Codex 可能不再重复问。

所以不能只靠“有没有提示框”来判断风险，还要看当前环境本身怎么配置。

## 看到权限请求时，可以按这几步判断

每次看到权限相关请求时，可以先问自己三件事：

1. 这一步是不是完成当前任务必需的
2. 它要接触的数据或路径，是否超出了我本来预期
3. 就算执行错了，我是否知道怎么撤回或补救

如果这三条里有两条答不上来，先别批准，先让 Codex 说明为什么需要这一步。
