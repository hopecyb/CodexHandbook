**子 Agent（Subagent）** 是主 Agent 为一个明确子问题启动的独立工作单元。它有自己的上下文，完成后把结论和证据返回主线程；主 Agent 仍负责全局决策与最终验收。

![Codex 子 Agent 编排架构：主 Agent 分派有边界的子任务，子 Agent 返回证据，主 Agent 汇总并验证](/diagrams/subagent-orchestration-zh-cn.svg)

## 先理解三层关系

| 层 | 是否隔离 | 含义 |
|---|---|---|
| 对话上下文 | 是 | 每个子 Agent 聚焦自己的任务，不必携带主线程全部细节 |
| 沙箱与权限模式 | 继承 | 子 Agent 不会因为独立运行而获得更高权限 |
| 工作区文件 | 不一定 | 多个 Agent 可能看到同一工作区；并行写同一文件会冲突 |

最重要的一句是：**上下文隔离不等于文件隔离。** 要并行修改代码，应先按目录、组件或工作树划分所有权。

## 当前在哪里使用

当前 Codex 版本默认提供子 Agent 能力，并可在桌面 App、CLI 和 IDE 的相应界面查看活动。界面细节会变化，但稳定的使用方式是：明确要求 Codex 把独立子任务委托出去，并让主线程负责汇总。

CLI 中可以用 `/agent` 查看或切换线程；IDE 在支持的界面中显示后台 Agent；桌面 App 会呈现任务中的线程活动。是否能看到某个控件，以当前客户端和账号能力为准。

## 什么时候值得拆

当子任务满足下面三条中的两条，就值得考虑：

1. 可以独立描述，不需要频繁同步主线细节。
2. 有明确交付物，例如文件清单、测试结果或一页结论。
3. 与其他任务可以并行，或者单独深挖能显著减少主线程噪声。

### 适合并行的工作

- 分别只读梳理前端、后端和测试覆盖
- 并行调查多个互不依赖的失败测试
- 对两个技术方案分别收集证据
- 让专门角色做安全审查、性能分析或文档核对

### 更适合留在主线程的工作

- 需求尚未澄清，需要持续与用户对话
- 多个步骤必须严格串行
- 修改高度集中在同一个文件或同一段代码
- 子任务没有明确完成标准，只是“随便看看”

子 Agent 会增加 token 消耗和汇总成本。能用一个清晰线程完成的小任务，不必为了并行而并行。

## 主 Agent 的职责不会消失

主 Agent 应始终保留四件事：

- 全局目标、用户约束和最终决策
- 子任务边界与文件所有权
- 多个结论冲突时的取舍
- 合并后的测试、构建与风险说明

子 Agent 返回“完成”只是子任务信号，不是整个任务已经完成的证据。

## 写一份可验收的委托契约

下面是一份只读调查任务：

```text
请启动一个子 Agent，只读分析 packages/auth 的 session 刷新逻辑。

范围：packages/auth 与对应测试；不要修改文件。
问题：刷新失败后，旧 token 是否仍可能被复用？
交付：结论、关键文件与行号、可复现路径、建议测试。
验证：每条结论必须能从源码或现有测试核对。
返回：控制在 500 字以内，由主线程决定是否修改。
```

它写清了六件事：负责什么、查看哪里、回答什么、禁止什么、如何验证、由谁决策。

## 一个三路并行例子

假设登录功能出现偶发回归，可以让主 Agent 这样拆：

| 子任务 | 权限与范围 | 交付物 |
|---|---|---|
| A：代码路径 | 只读 `src/auth/` | 从入口到失败分支的调用链 |
| B：测试证据 | 只读测试与日志 | 可稳定复现的最小测试 |
| C：近期变更 | 只读相关 Git 历史 | 最可能引入回归的变更及依据 |

三路结果返回后，主 Agent 应先比较证据，再选择一个修复方向。不要让 A、B、C 同时修改 `src/auth/session.ts`。

## 需要并行写时如何隔离

优先按以下顺序降低冲突：

1. 把写任务拆到互不重叠的目录或组件。
2. 为并行实现分配独立工作树或分支。
3. 明确每个 Agent 可以修改的文件清单。
4. 由主 Agent 统一合并，并在合并后重新运行验证。

即使各子任务自己的测试都通过，合并后的组合仍可能失败，因此最终验证不能省略。

## 验收清单

- 返回内容是否回答了原始问题，而不是扩大范围
- 是否附有文件位置、日志或测试等可核对证据
- 是否遵守只读、目录或命令限制
- 多个结果是否互相矛盾，矛盾是否已被显式处理
- 合并后的完整测试和构建是否重新运行
- 是否说明未解决问题与剩余风险

## 与其他能力配合

- **Skill** 固化子任务方法与输出格式，例如代码审查清单。
- **MCP** 给子 Agent 提供受控的外部工具或数据。
- **Hook** 在子 Agent 开始、停止或调用工具时补充守护规则。
- **工作树** 隔离并行文件修改；它解决的是工作区冲突，不是上下文问题。
