执行中途常见的反应通常只有两种：

- 什么都不说，硬着头皮让它继续跑偏
- 一句“停，全部重来”

更常见的做法，是在执行途中持续**引导**，保留已经对的部分，只修正偏掉的地方。

## 引导在做什么

这里说的“引导”，是补充当前这一步该怎么走，例如：

- 哪部分是对的，保留
- 哪部分开始偏了，别继续
- 接下来优先做哪一步

## 什么是“引导”

引导是对当前执行状态做**局部调向**。

你通常会在这些时候需要它：

- 它理解对了目标，但步骤顺序不理想
- 已经做对一半，不想全部推翻
- 你刚补充了新信息，需要调整后续动作
- 你发现它即将进入不必要的重构或扩写

## 最常用的一条模板

中途引导可以非常短：

```text
停在当前步骤。保留 A 与 B；撤销对 C 的改动方向；下一步只做 D。不要开始 E。
```

这类指令有四个关键部件：

1. 停在哪里
2. 保留什么
3. 放弃什么
4. 下一步只做什么

## 常见误区

### 1. 发现偏了，是不是应该全部停掉重来

如果它已经有一半是对的，全部推倒通常意味着：

- 你要重新交代背景
- 已经对齐的部分也一起丢了
- 新一轮还可能再偏一次

### 2. 我只要说“不对”，它就应该知道哪里不对

通常不够。

更有效的是明确指出：

- 保留什么
- 放弃什么
- 现在优先什么

### 3. 引导和重新规划是不是一回事

- **引导**：路线基本对，只是局部修正
- **重新规划**：目标、前提或影响范围已经变了

## 为什么小步纠偏更有效

| 小步纠偏 | 推倒重来 |
|---|---|
| 保留已对齐的工作 | 前面做对的也一起丢掉 |
| 更省上下文 | 需要重新解释背景 |
| 更容易控制范围 | 容易再次漂移 |
| 更像真实协作 | 更像重复下单 |

## 什么时候先引导，什么时候回到规划

你可以这样判断：

- **只是顺序不对、范围大了、输出形式不对**：先引导
- **目标变了、前提变了、影响面变了**：回到规划

## 三种常见引导方式

### 1. 缩范围

当它开始做得太大时：

```text
先只处理登录页，不要扩展到注册和找回密码流程。
```

### 2. 调顺序

当它开始做的事本身没错，但先后不合适：

```text
先补验证和测试，再继续改实现。
```

### 3. 改输出形式

当你想先看分析而不是直接落地：

```text
先不要改文件。先给我一个对比表，说明当前方案和你建议方案的区别。
```

## 一个好引导应尽量包含什么

- 当前要停的位置
- 保留的部分
- 不要继续的方向
- 新的优先级
- 是否允许继续执行

下面这句就比较清楚：

```text
保留你对问题原因的判断，但先不要进入重构。下一步只补一个最小修复方案和验证步骤。
```

## 什么时候该回到“重新规划”

引导适合局部偏差，但以下情况更值得回到 [规划](/guide/agent-work/planning/)：

- 任务目标本身变了
- 新信息推翻了原先前提
- 影响范围明显扩大
- 你已经连续纠偏两三次，仍然在漂

如果问题已经不是局部偏差，就直接回到规划阶段。

## 常见错误

- 只说“不对”，不说哪不对
- 让它“自己决定怎么修”，却不给优先级
- 明明只想暂停一步，却用了会触发全面重做的话
- 已经变成新任务了，还试图靠一句补充说明强行续上

执行中发现偏差时，可以用短指令说明“保留什么、停止什么、下一步只做什么”。
