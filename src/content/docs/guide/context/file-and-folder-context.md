title: 文件与目录上下文
description: 指定相关文件并避免无关噪音。
---

别只说“帮我改一下”，还要告诉 Codex 该看哪些文件、别看哪些文件。

你可能已经知道问题在某个目录里，但如果范围没说清，Codex 就可能把无关文件也拉进来。

## 为什么范围很重要

范围一旦太大，常见问题就会一起出现：

- 它读了很多不相关文件
- 上下文被无关信息占掉
- 它把另一个相似文件也当成目标
- 改动范围超出你的预期

所以文件与目录上下文的作用就是给它画边界。

## 为什么要划清文件范围

可以把这件事想成带人进办公室找资料：

- 你如果直接说“去找一下”，对方可能把半层楼都翻一遍
- 你如果说“只看第三个柜子的蓝色文件夹”，效率会高很多

Codex 也是一样。你给的范围越清楚，它越不需要靠猜测补全。

## 一个简单例子

明确相关路径：

```text
请只阅读 src/components/Button.tsx 与其测试文件，不要扫描整个仓库。
```

这句话同时说明了：

- 要看哪里
- 不要看哪里
- 不要自己扩散范围

## 常见误会

### 1. 相关文件是不是说得越多越好？

太少会让它猜，太多会让重点被冲淡。
更合适的做法是：**只给完成当前任务真正需要的那部分。**

### 2. 我不知道相关文件在哪，怎么办？

可以先让它帮你缩小范围，但要明确目的，比如：

```text
先帮我找出和登录按钮样式相关的文件，再不要动手修改。
```

先定位，再执行，通常比一上来就“全仓库搜并顺手改”更稳。

### 3. 不指定范围也没关系，反正它会自己找？

它当然可以找，但代价通常是：

- 读得更多
- 变慢
- 更容易把相似文件也带进来
- 更可能改出你没预料到的地方

### 4. 目录和文件都要说吗

不一定，但能具体就尽量具体。

- 已经知道是哪个文件：直接点文件
- 只知道大概区域：先点目录
- 完全不确定：先让它只做定位和解释

## 提示词里最好补上的三件事

如果你担心它改多了，可以直接在提示里补这三件事：

1. 只看哪些文件或目录
2. 不要扫描哪里
3. 修改前先说明将影响哪些文件

IDE 中注意当前工作区根是否正确。

## 可直接使用的写法

可以直接用这种写法：

```text
先只看 `src/pages/home/` 和 `src/components/Hero.tsx`。
不要扫描 `backend/` 和 `scripts/`。
如果还需要别的文件，先告诉我为什么需要，再继续。
```

给 Codex 指文件范围，就是在减少猜测、噪音和误改。
