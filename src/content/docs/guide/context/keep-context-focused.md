很多任务越聊越乱，常见原因是上下文已经散掉了。

聚焦上下文，就是一次只处理一个清楚目标，不要让旧问题和新问题搅在一起。

## 为什么会越聊越乱

“多说一点更保险”通常并不成立，上下文不能一直往里堆。

对 Codex 来说，如果一个任务里同时塞进：

- 原来的问题
- 顺手的新问题
- 半路冒出的想法
- 前面已经讨论过但现在不重要的细节

最后常见的结果是重点变模糊。

## 为什么任务会越做越偏

常见原因有这些：

- 一个对话里塞了多个目标
- 前面说过的约束，后面自己也忘了
- 已经解决的问题还在反复占注意力
- 半路插进了一个新需求，但没重新收口

结果往往是你觉得自己在补充信息，Codex 看到的却是重点越来越散。

## 基本做法

- 一次任务一个目标
- 定期总结「已完成 / 未完成 / 仍有效约束」
- 长任务用阶段门
- 跨会话用 [交接与恢复](/guide/agent-work/handoff-and-resume/)

## 看到这些信号就该收口

如果出现下面这些情况，就该主动收口了：

- 你自己都要翻前面对话才知道现在做到哪
- 同一个任务里已经开始讨论第二个问题
- 你发现“顺手再做一个”越来越多
- 它开始引用前面不再重要的旧结论

## 这些做法分别解决什么问题

### 一次任务一个目标

不要在同一个任务里同时要求：

- 修 bug
- 改文案
- 顺手重构
- 再帮我查一个新问题

拆开之后，范围更清楚，也更容易检查。

### 定期总结「已完成 / 未完成 / 仍有效约束」

这相当于给任务做一次中途校准。任务一长，这一步能防止双方都忘记现在做到哪了。

### 长任务用阶段门

“阶段门”就是先做完一小段，确认没跑偏，再进入下一段。

比如先“只定位问题”，再“只提出方案”，最后“再执行修改”。

### 跨会话用交接

如果任务不可能一次做完，就用简短交接把关键状态留下来。

## 马上就能用的收口写法

中途收口时，可以直接这样写：

```text
我们先收口一下。
已完成：A。
未完成：B。
仍有效约束：只改前端，不改接口；不要安装新依赖。
下一步只做：C。
```

## 常见误区

### 1. 想着一次说完所有需求，结果主次不分

信息多不等于信息清楚。如果主任务和顺手任务没分开，Codex 更容易混。

### 2. 明明任务变了，还继续沿用旧对话

如果方向已经换了，继续硬聊有时不如新开线程更干净。

### 3. 不做阶段确认，一口气改太多

改得越多，后面越难判断到底是哪一步开始偏了。

上下文聚焦不是少说话，而是把还有效的信息留下，把已经不重要的内容及时收掉。上下文一乱，后面的执行就容易跑偏。
