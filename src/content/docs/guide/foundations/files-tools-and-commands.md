它和普通聊天机器人最大的区别，在于它会通过 **工具** 去做事。

文件是它改东西的地方，命令是它做动作的方式，工具是它动手的入口。

Codex 通过 **工具** 作用于真实世界：

- 读/写项目文件
- 在终端运行命令（需权限与沙箱策略允许）
- 搜索网页、打开浏览器等（视产品能力与策略）

## 这三个词先分开看

| 词 | 对应含义 |
|---|---|
| 文件 | 项目里的真实内容，比如代码、文档、配置 |
| 命令 | 在终端里执行的一步动作，比如构建、测试、搜索 |
| 工具 | Codex 用来读文件、改文件、跑命令、搜网页的能力入口 |

也可以从另一个角度看：

- **文件** 像材料
- **命令** 像动作
- **工具** 像它用来拿材料和做动作的器具

## 常见工作过程

你给出一个任务后，Codex 常见会做这些事：

1. 先读几个相关文件，了解项目结构
2. 必要时搜索文本、打开目录、查看配置
3. 如果需要验证结果，运行一个命令，比如测试或构建
4. 修改文件后，再把改动交给你检查

所以当你看到它“要读文件”或“要跑命令”，多半说明它正在做任务需要的正常步骤。

## 常见误会

### 1. 它能运行命令，是不是就什么都能做？

不一定。

能不能做，还取决于：

- 当前产品入口给了哪些工具
- 沙箱是否允许
- 这一步是否需要你审批
- 团队策略有没有额外限制

### 2. 它是不是应该少跑命令，直接改文件更快？

不一定。

有时跑一个检查命令，反而能更早发现问题。比如改完代码后跑测试，比你事后才发现坏了更稳。

### 3. 我不懂命令怎么办？

如果一时看不懂，可以直接追问：

```text
这条命令是做什么的？会改哪些内容？如果不运行它会怎样？
```

## 一个简单的判断法

看到 Codex 要读文件、改文件、跑命令时，可以先用这三问判断：

1. 这一步和我的目标有关吗？
2. 影响范围是不是我预期的目录或文件？
3. 如果做错了，我能不能轻松撤回？

只要这三问里有一项答不上来，就先让它解释。

## 使用原则

1. **最小必要范围**：指明目录与文件，避免「随便改整个仓库」
2. **危险命令需审批**：删除、推送、改系统配置等
3. **工具选择有方法**：见 [工具选择](/guide/tools/tool-selection/)

产品入口不同，工具面板与确认方式也不同，细节见各产品手册。

Codex 不只是会“说”，它会通过文件、命令和工具真的动手，所以范围和风险都要盯住。
