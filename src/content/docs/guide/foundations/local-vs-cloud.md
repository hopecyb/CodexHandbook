“本地”“云端”听起来像技术名词，简单说，本地是在你自己的电脑上做事，云端是在远程机器上做事。

如果只是想先把 Codex 用起来，通常先选 **本地** 更省事。

| | 本地任务 | Cloud 任务 |
|---|---|---|
| 运行位置 | 你的机器 / 本地环境 | 云端环境 |
| 适合 | 快速迭代、本机文件、需本机密钥的调试 | 连接远程仓库、长任务、标准化环境 |
| 注意 | 本机权限与误改风险 | 环境配置、密钥注入、网络策略 |

## 使用感受

两者大致是这样：

- **本地任务**：像你坐在自己电脑前，Codex 帮你一起改当前项目
- **Cloud 任务**：像把任务交给一台远程工作机，让它在那里继续跑

区别不只是“位置不同”，还包括：

- 能访问什么文件
- 能不能直接用你本机已有的软件和环境
- 任务能跑多久
- 团队是否需要统一环境

## 为什么很多初学者先从本地开始

因为本地更容易理解，也更容易检查。

- 你知道文件就在自己电脑上
- 你更容易打开项目、查看结果、手动修正
- 出错时撤回路径更清楚

对第一次上手的人来说，先把任务闭环跑通，比一开始就上云更重要。

## 常见误会

### 1. 云端不一定更高级，也不一定更适合正式工作

如果你的任务就是改本地项目、看本机文件、快速试几次，本地会更直接。

### 2. 本地是不是就比较“不专业”？

很多真实开发工作，本来就在本地完成。是否用云端，主要看任务类型，不用拿“高级感”当判断标准。

### 3. 我该怎么选

可以按这个判断：

- **改你电脑上的现有项目**：选本地
- **任务很长、想挂着跑、想接远程仓库环境**：再考虑云端

## 拿不准时怎么选

如果现在还分不清，可以按这个规则判断：能在本地完成，就别急着上云。

等你真的遇到这些需求，再切到 Cloud：

- 任务时间很长
- 需要统一环境
- 需要连接远程仓库或远端资源
- 不想占用本机

很多初学者会从 **本地 + 桌面 App** 开始。Cloud 细节见 [Web 与 Cloud 概述](/guide/web-and-cloud/)。在 App 内切换见 [本地与云端任务](/guide/desktop-app/local-and-cloud-tasks/)。

本地更适合先看懂流程、改小东西。云端更适合更长、更标准化、远程协作更多的任务。
