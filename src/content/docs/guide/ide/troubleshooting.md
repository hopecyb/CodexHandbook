IDE 排障和 CLI 排障有个区别：  
很多问题看起来像“插件不工作”，但实际常常是**工作区、登录状态或编辑器本身上下文**出了偏差。

IDE 出问题时，先分清是“扩展没起来”，还是“扩展起来了，但拿到的上下文不对”。

| 症状 | 先试 |
|---|---|
| 扩展无响应 | 更新扩展与编辑器；查看扩展主机日志 |
| 登录状态丢失 | 重新认证 |
| 上下文不对 | 确认打开的工作区根目录 |

## 先分 3 类

- **完全没反应**：多半是扩展加载问题
- **能打开但不能用**：多半是登录或认证问题
- **回答不对、改错地方**：多半是工作区或上下文问题

## 常见误会

### 1. 插件图标还在，就说明扩展没问题

图标在，只能说明它装着；不代表它当前会话真的正常。

### 2. 上下文不对就是模型理解差

不少时候不是理解差，而是你打开的根目录、文件选择范围或工作区本身就不对。

### 3. 重新装插件一定是第一步吗

不用一上来就这么做。

先确认：

- 编辑器版本
- 扩展版本
- 登录状态
- 当前工作区

很多问题到这一步就能定位出来。

## 排查顺序

1. 看扩展是不是有响应
2. 确认登录状态
3. 确认当前工作区根目录和打开文件
4. 还不行再看扩展日志

IDE 排障最常见的根因，多半是工作区、登录状态或上下文源头不对，不一定真是插件损坏。
