手册里的模块不少，第一次看时很容易看散。这页把主要能力放到一张图里，方便快速对上结构。

常见的卡点主要有两种：

- 东看一页、西看一页，最后还是不知道该先补哪块
- 一上来就扎进 MCP、自动化、扩展，结果基础部分反而没理顺

把大框架先理顺，后面再查具体主题会省力很多。

Codex 不只是一个聊天框，背后还有几层能力：

```text
目标与提示词
  → 上下文（项目 / 文件 / 对话）
    → 工具（文件、终端、搜索、浏览器…）
      → Agent 工作（计划、执行、引导、交接）
        → 质量验证与人工审批
      → 扩展与自动化（Skills / MCP / Hooks…，进阶）
            → 团队治理（后续里程碑）
```

## 整体结构

可以把 Codex 看成三层：

- 第一层：你怎么开口，让它知道你要做什么
- 第二层：它靠什么上下文和工具把事情做出来
- 第三层：你怎么把这套协作方式沉淀下来，后面还能重复用

刚开始用时，前两层更重要。把任务说明白、把结果跑顺，再去看高级扩展。

## 常见误会

### 能力越高级，不等于越该先学

Skills、MCP、Hooks、自动化当然都很强，但它们解决的更多是效率放大和规模化复用，不是刚上手时最容易卡住的那部分。

如果提示词、上下文、工具选择这些基础动作还没理顺，后面的扩展能力也容易用歪。

### 这张图也可以当阅读顺序参考

不必照着站点目录一页页读完。可以按这个顺序走：

1. 先理解 Codex 怎么工作
2. 再学怎么给任务、怎么给上下文、怎么验结果
3. 用顺之后，再考虑配置、扩展和自动化
