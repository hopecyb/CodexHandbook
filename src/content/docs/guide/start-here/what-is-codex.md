Codex 是 OpenAI 提供的 **AI 编程与工作 Agent**。你给它一个目标，它会结合项目文件、工具和你的批准去读内容、改内容、跑命令、生成结果，再把过程和改动交给你检查。

它更像一个会用工具的数字同事。你负责说明目标、边界和验收标准；它负责查资料、改文件、跑步骤，但最后怎么定还是你说了算。

官方产品文档以 [OpenAI Codex](https://developers.openai.com/codex) 为准；这份手册是社区开源指南，方便系统学习和实际上手，不替代官方文档。

## 它和普通 AI 聊天有什么区别

很多人刚看到 Codex，会把它理解成“更强一点的聊天 AI”。差别主要在执行能力。

| 你平时用的东西 | 可以这样理解 |
|---|---|
| 普通聊天机器人 | 给建议、解释概念、写一段文字 |
| Codex | 除了回答，还可能去**读文件、改文件、运行命令、生成产物** |

普通聊天工具主要停留在回答；Codex 在你允许的范围内会直接动手。

## 什么任务适合交给它

如果一个任务除了“聊一聊”，还需要读材料、改东西、跑步骤、产出结果，就很适合交给 Codex 一起做。

如果只是问一个概念、要一句灵感、聊一个泛泛建议，普通聊天型 AI 也能应付。

## 可以用在哪些事情上

即使你不是程序员，也可以从这些场景理解：

- **读和整理资料**：总结文档、会议记录、截图、表格
- **写和改内容**：润色文章、补目录、改说明文档
- **做小项目**：搭一个页面、改一个配置、补一个模板
- **查和修问题**：帮你定位哪里出错、下一步看什么
- **重复工作自动化**：把固定流程交给它先跑一遍

会写代码的人可以把它放进开发流程里；不会写代码，也可以把它当成能执行步骤的助手。

## 能做什么

- **理解**：总结仓库、文档、表格与截图中的信息
- **创建与修改**：写文稿、改代码、生成页面与配置
- **执行**：在你授权下运行终端命令、搜索与浏览
- **协作**：在 App、CLI、IDE、Cloud 等入口之间延续任务
- **扩展**：通过 Skills、Plugins、MCP、Hooks 等接入重复流程与外部系统（进阶章节后续补齐）

## 不能做什么（重要）

- 不能替代你对事实、安全与业务决策的最终责任
- 不能保证一次生成就完全正确；结果必须可检查
- 不能在未获授权时突破沙箱、网络或组织策略
- 不应被当作「无需验收的自动发布流水线」

## 使用时的基本判断

把 Codex 当助手用就行，责任别一起交出去。

可以让它先做、先查、先改，最后还是要自己确认：

- 它有没有改对地方
- 它有没有理解错你的目标
- 它给出的事实是否靠谱
- 它做的改动会不会带来副作用

## 常见流程

常见流程一般是这样：

1. 你说出一个目标
2. 它先回答或给出计划
3. 如果要改文件或跑命令，可能会请求你的批准
4. 做完以后，它会告诉你改了什么
5. 你再去检查结果是否符合预期

这条流程的完整示例见 [运行第一次任务](/guide/getting-started/run-your-first-task/)。

## 主要使用入口

| 入口 | 适合 |
|---|---|
| 桌面 App | 初学者默认；可视化项目、任务、差异审查 |
| CLI | 终端用户、脚本与自动化 |
| IDE 扩展 | 在编辑器内结合打开文件与选区工作 |
| Web / Cloud | 连接仓库、云端环境与长任务 |
| 移动与远程 | 监控、审批与轻量跟进 |

对照表见 [功能对照](/guide/reference/feature-comparison/)。概念关系见 [能力地图](/guide/start-here/)。

## 接着看

如果只想先抓三点，可以记这几句：

1. Codex 不只是聊天，它还会在授权后执行动作
2. 任务要讲清楚目标、边界和“怎样算做完”
3. 任何结果都要检查，不要直接盲信
