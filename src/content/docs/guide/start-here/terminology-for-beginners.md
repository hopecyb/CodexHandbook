更完整的词条见 [术语表](/guide/reference/glossary/)。这里先列最常见、也最容易影响阅读的那批词。

刚开始看 Codex 手册时，最容易卡住的往往是名词太密。每个词单看都认识，连在一起就容易发懵。

常见情况主要有两种：

- 看得懂每个字，但不知道它在实际操作里指什么
- 不知道哪些词现在必须懂，哪些可以以后再懂

不用把它当成术语考试。知道这些词大概在说什么，读正文时别总卡住就行。

## 最先要认识的几个词

如果当前目标只是跑通第一次任务，可以先理解这 6 个：

| 术语 | 为什么先懂 |
|---|---|
| **提示词** | 你怎么把任务说清楚 |
| **上下文** | Codex 当前能看到哪些信息 |
| **Agent** | 为什么它不只是回一段话 |
| **审批** | 为什么它有时会停下来问你 |
| **差异（diff）** | 你怎么检查它到底改了什么 |
| **任务** | 一次完整工作的基本单位 |

| 术语 | 简单解释 |
|---|---|
| **提示词（prompt）** | 你给 Codex 的目标、背景与要求 |
| **上下文（context）** | 模型当前能看到的项目、文件与对话信息 |
| **Agent** | 能围绕目标调用工具并迭代推进的执行方式 |
| **工具（tool）** | 读文件、跑命令、搜索等可调用能力 |
| **沙箱（sandbox）** | 限制文件系统与网络影响范围的执行环境 |
| **审批（approval）** | 某些操作需你明确同意后才继续 |
| **差异（diff）** | 变更前后的内容对比，供你审查 |
| **线程 / 会话** | 一段连续对话及其累积上下文 |
| **任务** | 一次有目标的工作单元（可能跨多步工具调用） |
| **Skill** | 可复用的专项工作说明与资源包（进阶） |
| **MCP** | 连接外部工具与数据源的协议（进阶） |
| **Cloud 任务** | 在云端环境中运行的任务，而非本机沙箱 |

## 换成更直白的说法

- **提示词**：你给它下任务时说的话
- **上下文**：它此刻手头拿到的材料
- **Agent**：不只是回你一段话，它会真的往前推进任务
- **审批**：有些事它不能自己做，必须你点头
- **diff**：改之前和改之后的对比
- **Skill**：把一套固定做法打包复用

## 怎么用

在别的页面碰到这些词时，不需要每次都停下来查定义：

- 大概知道它在说什么，就继续往下读
- 反复看见还是模糊，再回这里
- 已经影响到流程理解，再去读对应专题页

## 可以分组来看

如果不想一次记太多，可以这样分：

- 你说什么：提示词
- 它看什么：上下文
- 它怎么做：Agent、工具
- 它能不能做：审批、沙箱
- 你怎么检查：diff、任务结果

## 这些词可以晚点看

下面这些多半属于进阶内容，第一次不必急着弄透：

- Skill
- MCP
- Hook
- Plugin
- Cloud 环境细节

先完成 [第一次任务](/guide/getting-started/run-your-first-task/)，再回头看这些词，理解通常会更顺一些。

遇到生词时，回来查一下，再继续往下读就行。

第一次读手册时，把这些词当成提示就行。先知道它们大概指什么，比一开始就全背下来更实际。
