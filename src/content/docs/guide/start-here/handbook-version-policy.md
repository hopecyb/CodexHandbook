## 持续更新

本手册不会绑定单一 Codex 版本号长期冻结。产品会变，所以页面会用状态、核验日期与具体证据说明已检查范围；日期本身不是可靠性评分。

## 内容

- 为什么这本手册不能假设永远不变
- 页首状态和核验日期该怎么读
- 遇到和官方冲突时应该信谁

## 页面状态

| 状态 | 含义 |
|---|---|
| planned | 已规划，尚未编写 |
| draft | 编写中 |
| review | 内容完成，待复核 |
| verified | 已按标注依据核验 |
| outdated | 产品变化后需更新 |
| archived | 历史保留，不进主导航 |

## 页面状态怎么读

- `planned`：还没写
- `draft`：在写，但还不稳
- `review`：主体成型了，但还需要复核
- `verified`：已经按标注依据核验过
- `outdated`：以前可能对，但现在要警惕过时
- `archived`：保留参考，不当作当前主线内容

## 验证记录与内容更新

页首分别展示编辑状态、验证方式、核验日期与适用证据。`editorial` 是编辑审阅，`source-checked` 是来源核对，`run-tested` 是记录中环境的示例实跑；三者不能互相替代。历史说明单独保留，不自动升级为当前实跑。

[内容更新与纠错](/guide/updates/)说明具体改动和影响。中文正文页底部可以打开带当前页面信息的 GitHub 纠错草稿，提交前需自行核对和脱敏。

## 官方依据

产品行为以 OpenAI 文档为准：[https://developers.openai.com/codex](https://developers.openai.com/codex)。本仓库为社区指南，若与官方冲突，以官方为准并欢迎提 issue。

## 常见误会

### 1. 只要写进手册，就说明长期都不会变

尤其这些内容最容易变化：

- 安装方式
- 登录和账号流程
- 权限、模型、配置项
- Cloud 和产品入口行为

### 2. `review` 不等于不能看

`review` 表示主体内容已经有了，但还没到最强确认级别，不是不能参考。

### 3. 社区手册和官方文档冲突时，不能各信一半

可以这样分：

- 理解和路径说明看手册
- 具体最新行为和参数写法看官方

## 怎么判断一页是否可靠

如果担心某页已经过时，可以看这三件事：

1. 页首编辑状态是不是 `review`、`verified` 或 `outdated`
2. 最近核验日期离现在远不远
3. 讲的是概念，还是安装、配置、权限这类容易变化的东西

凡是涉及最新行为、参数和规则，最后都要以官方当前文档为准。
