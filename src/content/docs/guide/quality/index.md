很多人用 Codex 时，会把注意力都放在“它能不能做出来”，却忽略另一个问题：做出来之后，怎么确认这次真的可以收下？

这一组内容讲的就是这件事。做质量与验证，就是为了避免“看起来完成了，其实还没稳”。

- [审查差异](/guide/quality/review-diffs/)
- [运行测试](/guide/quality/run-tests/)
- [验证产物](/guide/quality/verify-artifacts/)
- [核验来源](/guide/quality/validate-sources/)
- [处理不确定性](/guide/quality/handle-uncertainty/)
- [完成定义](/guide/quality/definition-of-done/)

## 阅读顺序

第一次看时，可以按这个顺序读：

1. 看 [审查差异](/guide/quality/review-diffs/)，确认它到底改了什么
2. 看 [运行测试](/guide/quality/run-tests/)，确认有没有把东西改坏
3. 看 [验证产物](/guide/quality/verify-artifacts/)，确认结果是不是你真正想要的
4. 看 [完成定义](/guide/quality/definition-of-done/)，明确“怎样才算真的完成”

如果没有检查，“完成”很多时候只是暂时看起来像完成。
