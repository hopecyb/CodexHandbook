---
title: 完成定义
description: 团队与个人共用的完成清单思路。
---


“完成定义”的意思很直接：提前说明做到什么程度，才算这次真的完成。

如果没有这一步，常见情况就是：

- 你觉得还差一点
- Codex 觉得已经做完
- 双方都没有错，只是标准没对齐

## 为什么这一步重要

很多返工，问题都出在“完成”的标准一开始没说清楚。

例如：

- 是只要文案改了就行，还是还要页面预览正常？
- 是只要跑通构建，还是还要手工验证按钮可点击？
- 是只要功能能用，还是还要补充说明文档？

这些如果不提前说清楚，最后就很容易各说各话。

个人最小完成定义示例：

- [ ] 差异已审
- [ ] 验收标准逐条勾选
- [ ] 测试或手工验证完成
- [ ] 无密钥进入仓库
- [ ] 需要跟进的问题已记下

团队版将在后续治理里程碑扩展。

## 常见误会

### 1. 完成定义不一定很正式，也不一定很复杂

第一阶段，哪怕只写三条也有用：

- 改哪里
- 怎么验收
- 什么情况算没做完

### 2. 它和“目标”不是一回事

可以这样区分：

- **目标**：你想要什么结果
- **完成定义**：怎样证明这个结果已经达到

比如：

- 目标：修复首页按钮文案
- 完成定义：只改首页；按钮文案变成新版本；页面预览正常

### 3. 不需要每次都写很长

不用。

写清楚比写很长更重要。

## 一个简版模板

先用这版也可以：

```text
完成标准：
1. 只修改指定范围
2. 结果符合我给出的要求
3. 验证步骤完成，并告诉我如何检查
```

“完成定义”主要是把“做到什么程度才算做完”讲清楚，免得你和 Codex 的判断不一致。
