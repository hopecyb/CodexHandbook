部分 Codex 客户端支持**记忆（Memory）**：把你在多轮对话中确认的偏好或事实保留到后续会话。它与 `AGENTS.md`、项目配置互补，但**不能**替代版本化的团队规范。

## 内容

- 记忆存什么、不存什么
- 与 AGENTS.md、Memories 功能、项目指令的优先级
- 个人与团队如何管理记忆内容

## 记忆适合拿来做什么

可以把记忆理解成：**Codex 帮你记住那些总要重复说、但又不值得每次重讲的事情。**

比如：

- 你习惯中文解释
- 你喜欢先给结论再给细节
- 某个项目里“后端”默认指哪个目录

它更像“个人长期偏好和少量稳定事实”，不是项目说明书，也不是秘密保险箱。

## 记忆适合存什么

| 适合 | 不适合 |
|---|---|
| 个人编码偏好（注释语言、缩进习惯） | 生产密钥、token |
| 反复说明的项目别名（「后端指 `services/api`」） | 会变的 sprint 任务状态 |
| 你明确说「请记住」的非敏感事实 | 应写在 Git 里的团队规范 |

团队级规范应进 **`AGENTS.md` 或项目配置**，便于 review 与新人 onboarding。见 [作用域与优先级](/guide/customization/agents-md/scope-and-precedence/)。

## 常见误会

### 记忆不会“什么都帮你永久记住”

很多人会误以为只要说过一次，Codex 以后就会一直、完整、稳定地记住。

更准确的理解是：记忆是一个辅助层，用来减少重复说明，但不能替代文档和仓库里的正式信息。

### 记忆不适合承载团队共识

如果一条规则只有你账号里的记忆知道，那别人就看不到，也没法 review。

这类内容应该回到：

- `AGENTS.md`
- 项目文档
- 配置文件

### 记忆不是存敏感信息的地方

就算某个客户端支持记忆，也不应该把：

- token
- 客户数据
- 内部账号
- 未公开业务信息

交给它长期保存。

## 与相关机制对比

| 机制 | 谁可见 | 变更方式 |
|---|---|---|
| 单次 prompt | 当前任务 | 你打字 |
| 记忆 | 通常仅你的账号/工作区 | 对话中确认或设置页管理 |
| `AGENTS.md` | 全仓库协作者 | Git PR |
| 项目配置 | 按配置层级 | 文件 + 托管策略 |

## 推荐使用方式

1. **先写进仓库**：测试命令、目录结构、禁止 push——这些不应只存在记忆里
2. **记忆放个人偏好**：如「解释用中文」「diff 评论用英文」
3. **定期清理**：项目架构大变后删除过时记忆
4. **敏感项目**：关闭或限制记忆，避免跨项目泄漏上下文

## 怎么判断该不该存进记忆

如果你不确定一条信息该不该存进记忆，可以先问自己：

1. 这是不是我个人经常重复说的偏好
2. 这是不是短时间内相对稳定的事实
3. 这条信息就算别人看不见，也不会影响团队协作

三条都更接近“是”，才比较适合进记忆。

## 安全边界

- 不要让记忆成为**秘密通道**绕过 `AGENTS.md` 禁止项
- 不要在记忆中保存客户数据、凭证、未公开财务信息
- 企业环境可能禁用记忆功能——遵守托管策略

## 常见错误

- 把「本周要完成的 epic 列表」只放记忆，协作者看不见
- 记忆与 `AGENTS.md` 冲突时不更新任一侧
- 误以为记忆等于「模型永远记得整个仓库」

记忆最适合存“总要重复说的个人偏好和少量稳定事实”，不适合替代仓库文档、团队规则和敏感信息管理。
