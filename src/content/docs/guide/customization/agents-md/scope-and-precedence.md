多个 `AGENTS.md`、配置文件和当前对话同时存在时，需要明确**哪条规则生效**。

这里讲的是：当两条规则看起来不一样时，到底该听谁的。

## 优先级总览

```text
托管组织策略 >  nearer 目录的 AGENTS.md > 仓库根 AGENTS.md > 用户配置 > 当前对话
```

「nearer」指**离当前工作路径更近**的子目录文件。例如在 `packages/web/AGENTS.md` 下工作时，该文件与根目录文件合并，冲突时**子目录优先**。

## 怎么理解“近的优先”

可以把它看成：

- 根目录规则像“全仓默认法则”
- 子目录规则像“这个局部区域的特别说明”

所以越靠近当前工作位置的规则，通常越具体，也越该优先。

## 与对话提示的关系

| 来源 | 持久性 | 适合写什么 |
|---|---|---|
| AGENTS.md | 跨会话、可版本管理 | 团队共识、构建命令、禁区 |
| 任务提示词 | 仅本会话 | 本次目标、范围、截止时间 |
| @ 文件引用 | 本会话增强上下文 | 具体实现文件、设计稿 |

**不要**在对话里重复粘贴整份 `AGENTS.md`；若必须强调某条，用一句话引用：「遵守 AGENTS.md 中的测试要求，本次额外不要改 `legacy/` 目录。」

## Monorepo 模式

```text
repo/
├── AGENTS.md              # 全仓通用：包管理器、CI、安全
├── apps/
│   └── web/
│       └── AGENTS.md      # 前端：组件库、E2E 命令
└── packages/
    └── api/
        └── AGENTS.md      # 后端：数据库迁移约定
```

原则：

- **根文件**：全仓共享的 10–20 条硬规则
- **子包文件**：仅该包特有的命令与目录说明
- 避免三份文件 80% 重复——重复内容放根目录，子包只写增量

## 与个人偏好的边界

个人习惯（主题、默认模型、本机路径）放**用户配置**，不要写进团队仓库的 `AGENTS.md`，否则协作者被误伤。

## 常见误会

### 1. 当前对话里说的话肯定最新，所以优先级也最高

对话适合补“这次额外要求”，但不等于能随便覆盖团队或组织级硬规则。

### 2. 子目录 `AGENTS.md` 就是在复制一份根规则

也不该这样。

更合适的做法是：

- 根规则写共性
- 子目录只写增量和例外

### 3. 只记顺序，还不够

还不够。

更重要的是你知道：

- 哪类信息该放哪层
- 冲突时为什么会以某一层为准

## 冲突时怎么判断

当你发现两条规则看起来冲突时，可以按这个顺序看：

1. 哪条更靠近当前工作目录
2. 哪条是长期项目规则，哪条只是这次临时补充
3. 有没有组织或托管策略在更上层直接限制

规则冲突时，通常优先看更近、更硬、更明确的那层，不要默认“最新那句”一定赢。

## 常见错误

- 子目录 `AGENTS.md` 与根文件矛盾，却不说明以谁为准
- 把敏感密钥写进 `AGENTS.md` 并提交 Git——应使用密钥管理与环境变量
- 期望对话里的「临时放宽」覆盖团队托管策略（通常做不到）

## 验收清单

- [ ] 根 `AGENTS.md` 与子包文件分工清晰
- [ ] 冲突规则有明确「子目录优先」意识
- [ ] 任务提示只写增量，不复制整份项目手册
