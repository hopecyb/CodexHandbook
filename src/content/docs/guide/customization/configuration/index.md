第一次看到“配置”这一组时，很容易以为它只是在讲一堆参数名。

它主要在解决一件事：让 Codex 默认按什么方式工作，而不是每次临时再说一遍。

## 推荐顺序

1. [配置基础](/guide/customization/configuration/config-basics/)
2. [Profiles](/guide/customization/configuration/profiles/)

## 这组在解决什么问题

- 哪些偏好适合写进配置文件
- 什么时候该分多个 profile
- 为什么有些限制该交给规则或审批，而不是只靠配置备注

配置更适合放默认行为和稳定偏好，不适合拿来替代审批、规则和项目说明。
