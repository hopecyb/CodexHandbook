“威胁模型”说白了就是先把风险想在前面：

> **如果 Codex 真接进了我们的代码、命令和外部工具，最可能出什么事？**

**威胁模型**就是把这件事拆开看清楚。Codex 不只是“又一个聊天窗口”，它还能**读代码、跑命令、调外部工具**。本章先把主要风险面铺开，具体控制项再去看 [权限矩阵](/guide/reference/permission-matrix/) 与 [沙盒](/guide/foundations/sandbox-and-network/)。

## 内容

- 资产与信任边界
- 典型威胁与缓解方向
- 与规则、Hooks、CI 的分工

## 为什么不要把它当成“安全同学的事”

如果你是开发、平台、文档或项目负责人，这件事也和你直接相关。团队里真正容易出问题的，是这些具体场景：

- 把过高权限 token 交给自动化
- 让 Agent 在不可信输入上直接做高风险动作
- 不知道哪些数据能看、哪些不能带出
- 引入扩展时只看功能，不看权限和来源

威胁模型的价值，是让团队在出事前先把边界想明白。

## 资产与边界

| 资产 | 示例 |
|---|---|
| 源代码与 IP | 私有仓库、未发布设计 |
| 凭据 | API key、`.env`、云 IAM |
| 用户数据 | PII、客户工单内容 |
| 基础设施 | CI、生产部署管道 |

**信任边界：** 模型与扩展默认在**不可完全信任**一侧；人审与策略在边界上 enforcement。

## 两个核心问题

做任何团队级接入前，可以先问：

1. 我们最怕丢的是什么？
2. 我们最怕 Codex 误做什么？

第一个问题帮你识别“重要资产”，第二个问题帮你识别“危险动作”。很多控制策略，都是围绕这两个问题展开的。

## 一个场景

可以看这个场景：

- Codex 能读你的私有仓库
- 能访问一个带权限的工单系统
- 能执行 shell 命令
- 还能把结果发回评论区

这时候更值得关注的是这些事：

- 会不会看到不该看的内容
- 会不会做了不该做的动作
- 会不会把本来只该留在内部的信息带出去

把问题放到这个层面，威胁模型就更接近上线前的风险排查表。

## 威胁概览

| 威胁 | 描述 | 缓解方向 |
|---|---|---|
| Prompt 注入 | 恶意 issue/网页诱导越权操作 | 输入消毒、只读 CI、[注入专题](/guide/team-enterprise/security/prompt-injection/) |
| 过度权限 | token、沙盒过宽 | 最小权限、分支保护 |
| 数据外泄 | 命令/MCP 外传仓库内容 | 网络策略、DLP、审计 Hook |
| 恶意扩展 | 未审查 Plugin/MCP | [扩展风险](/guide/team-enterprise/security/plugin-and-mcp-risk/) |
| 供应链 | 依赖与脚本投毒 | 与现有 SCA、code review 结合 |
| 误操作 | Agent 删库、错 push | 命令 deny、无 push CI |

## 优先纳入威胁模型的情况

如果某项能力同时满足下面两点，就该优先进入威胁模型：

- 它能接触重要资产
- 它能执行真实动作

比如：读取私有仓库、访问生产 API、调用带写权限的 MCP、自动推送代码。

## 第一次落地时不要贪大求全

很多团队一听到安全治理，就想一次把所有文档、流程、策略全补齐，最后什么都没落地。

第一次接入 Codex 的团队，通常先把最直接的几件事做起来就够了：

1. 先列出最重要的 3 类资产
2. 再列出最不希望 Agent 做错的 3 类动作
3. 给这 6 件事各自配一个最直接的控制手段

例如：

- 怕泄露生产库数据，就先限制生产凭据与导出路径
- 怕误推送主分支，就先加分支保护和审批
- 怕被网页或 issue 带偏，就先收紧外部输入与只读 review 流程

这当然不算完整，但通常比写一份没人照着执行的大文档更有用。

## 推荐分层控制

```text
L1 身份与租户（SSO、组）
L2 组织托管配置与模型策略
L3 仓库 rules + AGENTS.md
L4 沙盒 / 审批 / Hooks
L5 人工 review 与分支保护
```

## 常见错误

- 只做培训不写技术控制
- 假设「模型足够聪明」不会犯错
- 生产密钥出现在 Agent 可写路径
- 把所有风险都压成一句“人工 review 就行”

## 最小版本

先把这三件事立住：

- 高风险动作需要审批
- 高敏感数据默认不给
- 自动化流程默认只读

这三件事先稳住，很多团队级风险就已经能压下去。后面的细化治理再慢慢补也不迟。
