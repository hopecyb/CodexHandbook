第一次看到斜杠命令，很多人会以为这是一堆要硬记的黑话。把它看成一组可以主动点名使用的快捷入口，会顺一些。

它们一般用于快速进入某种固定模式或内置流程。斜杠命令（`/command`）和 [Skill](/skills/overview/) 的 `$name` 调用相关，但不是一回事。具体列表**随产品与版本变化**，使用前请以客户端内 `/` 补全与官方文档为准。

## 概念区分

| 入口 | 谁发起 | 典型用途 |
|---|---|---|
| `/review` 等斜杠命令 | 你输入 `/` | 内置或配置的固定流程 |
| `$skill-name` | 你或模型 | 项目或用户 Skill |
| 自然语言 | 你 | 通用任务 |

## 直接区分三者

- `/命令`：你在聊天里主动点一个快捷入口
- `$skill`：你或模型点名使用某个 Skill
- 自然语言：你直接说需求，让模型自己判断怎么做

如果你只是想更快进入一个已知流程，试 `/命令` 会更直接。

## 它是什么

- 不是终端指令
- 不是神秘黑话
- 可以把它当成聊天界面里的“快捷按钮入口”

它比较适合用在这些场景：

- 你已经知道自己想进入哪种流程
- 你不想每次都重新把同样的意图说一遍

## 常见误会

### 1. 斜杠命令就是终端命令

它是聊天界面里的快捷入口，不是让你在 shell 里执行的 `codex ...` 命令。

### 2. 斜杠命令列表是固定不变的

不同产品、版本和环境里可用命令都可能不同，直接看当前环境里的 **补全列表** 更靠谱。

### 3. 用了斜杠命令，就不受审批和沙盒影响

如果它背后会触发写文件、跑命令、联网等动作，照样会受当前策略约束。

### 4. 不会斜杠命令，是不是就用不好 Codex

自然语言本身就能完成大多数任务。斜杠命令更多是在你已经熟一点之后，用来提速和走固定入口。

## 常见类别（示意）

以下名称在不同版本可能增减，**仅作学习分类**：

### 会话与模式

- 切换计划模式、压缩上下文、查看帮助
- 与 [规划](/guide/agent-work/planning/) 配合

### 审查与质量

- 对当前 diff 或 PR 做审查
- 结合 [审查 diff](/guide/quality/review-diffs/)

### 工作区与 Git

- 查看状态、生成提交说明（仍需你确认是否提交）
- 遵守 [人工审批模式](/cases/workflows/human-approval-patterns/)

### 扩展

- 安装或列出 Skill（若环境提供 `skill-installer` 等）

## 使用时注意

1. **先 `/` 看一眼** 当前环境支持什么，不要背过时列表
2. 团队固定流程优先做成 **Skill + 文档**，减少「只有老手知道命令名」
3. 斜杠命令触发的写操作，仍受沙盒与审批约束

## 直接试的方法

可以直接这样试：

1. 输入 `/`
2. 看看当前环境有什么
3. 选一个你能看懂名字和用途的先试

## 第一次可以这样试

第一次尝试时，可以按这个顺序：

1. 先输入 `/` 看当前环境提供什么
2. 选一个你看得懂用途的命令试一次
3. 观察它更像“切模式”还是“跑流程”
4. 如果是团队长期要复用的流程，再考虑沉淀成 Skill

这样更容易看出两者的分工：斜杠命令偏快捷入口，Skill 偏长期复用流程。

## 与 CLI 命令的区别

| | 聊天内 `/` | 终端 `codex …` |
|---|---|---|
| 上下文 | 当前会话与 @ 文件 | `--cwd` 指定目录 |
| 适合 | 交互探索 | 脚本、CI |

斜杠命令可以看成聊天里的快捷入口，先看当前环境实际提供什么，比死记命令名有用。

CLI 子命令见 [CLI 交互模式](/guide/cli/interactive-mode/) 与 [非交互模式](/guide/cli/non-interactive-mode/)。完整参数表见 [CLI 命令参考](/guide/reference/commands/)。
