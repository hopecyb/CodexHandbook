表格任务是容易 silently 做错的典型：分隔符、编码、表头、公式与日期格式任一出错，下游全崩。

## 本页内容

- 如何让 Codex 安全读写 CSV / Excel
- 数据分析类任务的 prompt 结构
- 如何验收数字与行数

## 格式选择

| 格式 | 优点 | 注意 |
|---|---|---|
| CSV | 文本可 diff、通用 | 编码（UTF-8 BOM）、分隔符、引号转义 |
| TSV | 少逗号冲突 | 同 CSV |
| XLSX | 多表、公式 | 二进制，diff 困难；用库读写 |
| Google Sheets | 协作 | 常经 MCP 或导出 CSV |

小数据、要进 Git：**优先 CSV/TSV**。复杂报表：**源数据 CSV + 生成 XLSX 脚本**。

先看这三点：

- 要可 diff、可追踪、可复现：优先 CSV / TSV
- 要交付给习惯 Excel 的人：再导出 XLSX
- 不要把“最终查看格式”和“最适合自动处理的源格式”混成一件事

## 读取与分析

推荐 prompt 结构：

```text
文件：data/sales_2025.csv
编码：UTF-8
任务：按 region 汇总 revenue，输出 summary.csv
约束：不修改原文件；空值按 0 处理；保留两位小数
验收：打印前 5 行 + 总行数
```

## 为什么表格任务特别容易悄悄做错

但真正容易出问题的地方通常是这些：

- 日期到底被当成文本还是日期
- 空值到底算 0、跳过，还是报错
- 哪一列才是唯一标识
- 小数和金额要不要四舍五入
- 原文件能不能改

如果这些不说清楚，Codex 可能也会“看起来完成了”，但结果并不可靠。

## 写入与清洗

- 明确**列名、顺序、类型**（日期用 ISO 8601）
- 大表分批处理，避免一次性加载爆内存
- 去重、合并键写进任务说明，不要让 Agent 猜「主键」

## 常见误会

### 1. 只要最后能打开文件，就说明处理对了

不对。

表格类任务里，“能打开”和“数据没被做坏”是两回事。

### 2. Excel 里看着没问题，就一定没问题

有些错误只在后续系统消费时才暴露，比如：

- 编码不对
- 列顺序变了
- 数值类型变了
- 公式被写死成结果

### 3. 让 Agent 自己判断空值、日期、主键就行

通常不建议。

这几类规则越明确，结果越稳。

## 交代表格任务时，把这些说清

可以尽量把需求说成这 5 件事：

1. 输入文件是什么
2. 输出文件要叫什么
3. 哪些列要保留、汇总或清洗
4. 空值、日期、重复值怎么处理
5. 怎么验证结果

这比只说“帮我整理一下这个 Excel”稳定得多。

若用 Python：`pandas` 读写；若用 Node：`csv-parse` / `xlsx` 等——在 `AGENTS.md` 约定项目标准库。

## 与验证

- 行数、合计是否与源数据交叉校验
- 打开 Excel 看日期是否被当成数字
- [验证产物](/guide/quality/verify-artifacts/)：抽样对比

表格任务里，更重要的是把列、类型、规则和验收说清楚。

## 常见错误

- Excel 打开 CSV 中文乱码（缺 BOM 或错编码）
- 浮点合计误差未四舍五入说明
- 在 Excel 里改公式却不保存为可复现脚本

## 验收清单

- [ ] 列名与类型符合下游消费方约定
- [ ] 合计/抽样与人工或 SQL 核对一致
- [ ] 原文件未被意外覆盖（或变更在 diff 中可见）
