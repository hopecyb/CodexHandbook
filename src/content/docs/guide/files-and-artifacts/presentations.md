演示文稿（PPT、Keynote、Google Slides、Marp/Reveal 等）强调**叙事结构**与**视觉一致性**。Agent 擅长出大纲和初稿，母版与品牌规范仍需人把关。

用 Codex 做演示稿，最有价值的是先把结构、页序和讲述逻辑搭出来，最后成稿还是要你自己收口。

## 本页内容

- 用 Codex 做幻灯片时的推荐工作流
- 不同格式（`.pptx`、Markdown 幻灯片）的取舍
- 如何避免「每页风格割裂」

## 先定交付格式

| 格式 | 适合 |
|---|---|
| Marp / Slidev / reveal.md | 开发者、版本管理友好 |
| `.pptx` | 商务汇报、与客户共享 |
| Google Slides | 实时协作（常经导出或 MCP） |
| PDF 导出 | 只读分发 |

在任务开头写死格式，避免 Agent 混用多种工具链。

按最终交付对象来选：

- 要给客户、老板或同事直接打开改：通常是 `.pptx`
- 要和代码一起版本管理：通常是 Markdown 幻灯片
- 只要发阅读版：通常最终导出 PDF

## 推荐工作流

```text
1. 大纲：受众、时长、3～5 个核心信息
2. 每页标题 + 3 bullet，备注讲稿要点
3. 选定工具生成初稿
4. 人工调整母版、图表、数据出处
5. 导出 PDF 彩排计时
```

与 [探索—计划—执行—验证](/cases/workflows/explore-plan-execute-verify/) 一致：大纲阶段先验收再填细节。

## 为什么演示稿最好先控结构

不先控结构的话，Codex 很容易直接铺很多页面，但内容也容易：

- 顺序乱
- 页数失控
- 每页像独立海报，不像同一份汇报

通常按这 3 层推进会稳一些：

1. 先定“这份演示到底要讲清什么”
2. 再定“每一页各自负责哪一句核心信息”
3. 最后才让 Agent 帮你填文案、图表说明和讲稿备注

## 常见误会

### 1. PPT 做得花，就等于表达更强？

很多时候，真正影响理解的是：

- 标题是否一句话就说清重点
- 页与页之间有没有推进关系
- 数据有没有来源

### 2. Agent 既然能生成整份初稿，就可以不用人工把关？

也不行。  
下面这些部分最好一定人工过一遍：

- 公司品牌和母版
- 关键结论
- 数字和图表
- 对外发送版本

### 3. 一页内容越满，越显得信息充分？

通常反而更难讲。  
如果一页里塞了太多 bullet、图和结论，观众很难一下抓到重点。

## 常用制作顺序

如果现在就要让 Codex 帮你做一份演示稿，可以按这个顺序给要求：

1. 先说受众是谁
2. 再说演讲时长
3. 再说你希望对方带走的 3 个点
4. 先让它给大纲
5. 大纲确认后，再让它展开每一页
6. 最后再补讲稿备注、视觉要求和导出格式

按这个顺序来，一般更容易收住：先控结构，再控文案，最后再控样式。

## Prompt 要点

- **受众**：技术同事 vs 管理层，决定术语深度
- **页数上限**：防止 80 页废话
- **品牌**：主色、 logo 路径、禁止 clipart（若公司有规范）
- **数据图**：注明数据来源文件，要求可更新而非截图瞎编

也可以直接把需求说成这种口吻：

> “先帮我做 10 页以内的大纲，受众是非技术管理层，每页只保留一个核心结论，最后补讲稿备注。”

这种要求通常比“做个高大上的 PPT”更容易产出能继续打磨的版本。

图像需求见 [图像与截图](/guide/files-and-artifacts/images-and-screenshots/)；纯生成图见 [图像生成](/guide/tools/image-generation/)。

## 验收

- 投影分辨率下字号可读
- 动画适度（过多动画难维护）
- 数字与 [验证来源](/guide/quality/validate-sources/) 一致
- 演讲备注是否足够（若需要）

## 哪些最适合交给 Codex，哪些最好你自己拍板

| 更适合交给 Codex | 最好人工把关 |
|---|---|
| 大纲拆页 | 最终结论措辞 |
| 页标题初稿 | 品牌一致性 |
| 讲稿备注初稿 | 敏感数据 |
| 图表说明文案 | 对外发布版本 |

这样分工通常更省时间，最后也更容易把质量卡住。

## 常见错误

- 没有大纲直接「做一份季度汇报 PPT」
- `.pptx` 二进制反复手改却不保留 Markdown 源
- 图表数据与仓库 CSV 不一致
- 一次让 Agent 同时决定结构、设计、结论和数据口径

## 验收清单

- [ ] 大纲经人工确认后再生成全文
- [ ] 在目标播放环境打开无字体错乱
- [ ] 关键数据可追溯到源文件
