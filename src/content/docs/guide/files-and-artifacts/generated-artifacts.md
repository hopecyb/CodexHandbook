Agent 完成任务时可能新建报告、脚本、静态站点、测试数据等**生成物**。它们不一定经过你熟悉的代码审查路径，所以需要单独的验收习惯。

文件是 Codex 新生成的，不代表它已经能直接拿去用。

## 本页内容

- 生成物与「改现有代码」的验收差异
- 检查清单
- 何时拒绝、要求重做

## 生成物类型

| 类型 | 验收重点 |
|---|---|
| 脚本 `.sh` `.py` | 可执行、无害、幂等 |
| 报告 `.md` `.html` | 事实准确、链接有效 |
| 构建输出 `dist/` | 是否应 gitignore |
| 测试夹具 | 无真实 PII |
| 配置模板 | 无默认弱密码 |

## 这里说的“生成物”是什么

这里的“生成物”就是：

- 它帮你新写出来的文件
- 它帮你导出来的报告
- 它帮你构建出来的页面、目录或包

这些东西和“只改了几行现有代码”不一样，因为它们更容易被你忽略掉实际内容。

## 验收流程

```text
1. 打开产物（不要只看 Agent 文字总结）
2. 对照任务中的「完成定义」
3. 运行相关测试或预览命令
4. 检查路径、权限、体积
5. 决定：接受 / 局部修改 / 废弃重做
```

方法：[验证产物](/guide/quality/verify-artifacts/)、[完成定义](/guide/quality/definition-of-done/)

## 常见误会

### 1. 它说“完成了”，也还是要看实际产物

总结只能告诉你“它认为自己做了什么”，不能代替你打开文件确认“实际产物长什么样”。

### 2. 新文件不一定比改旧文件更安全

新文件同样可能有：

- 错误内容
- 多余依赖
- 泄露信息
- 不该提交进仓库的大文件

### 3. 只要能跑出来，也不一定值得提交

有些生成物只适合本地临时使用，不适合进 Git。

## 与 Git 的关系

- 明确哪些生成物**应提交**、哪些应 `.gitignore`
- 避免一次 PR 混入 megabytes 构建缓存
- 大产物用 CI artifact 或外部存储

## 常用验收顺序

如果刚拿到一批生成物，可以按这个顺序看：

1. 先确认生成了什么文件
2. 打开最关键的那个产物
3. 看它是不是落在允许目录里
4. 看它应不应该提交到仓库
5. 再决定接受、修改还是重做

## 不可信生成物

对不可信仓库或外部数据驱动的任务：

- 先读脚本再执行
- 警惕 `curl | bash`、混淆 payload
- 在沙盒或容器中预览

生成物不能只看“已经生成”。至少要打开看过、验证过，也知道它该不该提交。

## 常见错误

- 只看 Agent 的 bullet summary 不打开文件
- 把一次性调试输出提交进 main
- HTML 报告含追踪像素或外联未审核脚本

## 验收清单

- [ ] 每个新文件路径在允许范围内
- [ ] 打开并扫读主要内容
- [ ] 自动化检查（lint/test/link check）已跑
- [ ] 无 secrets、无多余生成目录
