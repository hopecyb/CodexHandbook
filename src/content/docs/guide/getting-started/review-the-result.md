title: 检查结果
description: 阅读变更、验证产物并决定接受或修改。
---

做完任务以后，很多新手会跳过这一步。

想把 Codex 用得更稳，得看你会不会**检查结果**。

不要只看它说“完成了”，还要看它到底改了什么，结果是不是你要的。

## 检查清单

1. **看差异**：是否只改了允许的文件？
2. **打开产物**：内容是否符合验收标准？
3. **追问修正**：如果只差一点，就继续补精确反馈
4. **决定**：接受 / 手动改 / [撤销](/guide/getting-started/undo-and-recover/)

更多方法：[审查差异](/guide/quality/review-diffs/)。

## 常见漏看点

### 1. 只看总结，不看实际改动

Codex 可能会把总结写得很顺，但真正重要的是：

- 改没改错文件
- 有没有顺手改了你没授权的地方
- 结果是否真的满足验收条件

### 2. 看到“差不多”就直接接受

“差不多”很容易给后面留下小坑。  
如果只是差一点，补一句精确反馈会更好，不要自己默默将就。

### 3. 发现不对，却不知道怎么说

你可以直接用这种句式继续：

```text
结果接近了，但还有两个问题：1）…… 2）…… 请只修这两点，其他地方不要动。
```

## 检查顺序

第一次练习时，可以按这个顺序检查：

1. **看范围**：它改了哪些文件
2. **看结果**：页面、文档、代码输出是否符合要求
3. **看副作用**：有没有引入多余改动或新错误

验收时，主要就是确认这次结果能不能放心收下。
