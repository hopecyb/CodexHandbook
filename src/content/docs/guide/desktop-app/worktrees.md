工作树（worktree）让同一 Git 仓库拥有多个独立检出目录。每个目录有自己的文件和分支状态，但共享仓库的 Git 元数据，适合让多个编码聊天并行推进而不互相覆盖文件。

## 使用前提

- 项目必须位于 Git 仓库中；
- 任务边界应能独立描述和验收；
- 并行任务不应修改同一组核心文件。

如果只是第一次练习 Codex，先用 Local 模式串行完成任务；当等待时间或文件冲突真的成为问题时，再使用工作树。

## 在 App 中创建

1. 在新聊天的输入区下方选择 **Worktree**；
2. 选择起始分支，可选主分支、功能分支或带未暂存改动的当前分支；
3. 提交提示词，应用创建 Git worktree；
4. 在独立聊天中检查、测试和审查；
5. 准备回到本地检出时使用 **Handoff**。

默认创建的工作树处于 detached HEAD。这不妨碍 Codex 工作，但在你准备保留或共享提交前，要明确目标分支和合并方式。

## 两路并行示例

| 聊天 | 工作树任务 | 文件所有权 | 验收 |
|---|---|---|---|
| A | 修复登录错误 | `src/auth/**` | 认证测试通过 |
| B | 补充认证文档 | `docs/auth/**` | 链接检查通过 |

不要让 A 和 B 同时改共享锁文件或同一配置文件。若确实需要，先约定由一个聊天修改，另一个只提供分析结论。

## 交付前检查

```bash
git status --short
git diff --check
git diff --stat
```

接着运行任务对应的测试。只有在明确知道每个改动来自哪个聊天、目标分支是什么、验证是否通过后，才进行 Handoff、提交或合并。

## 与定时任务和 Remote 的关系

- Git 仓库中的定时任务可使用专用后台工作树，避免与当前工作冲突；
- Remote 可从移动端控制连接计算机上的工作树聊天，仓库和命令仍留在那台计算机或其远程开发环境中；
- 非 Git 项目没有工作树隔离，定时任务会直接使用项目目录。
