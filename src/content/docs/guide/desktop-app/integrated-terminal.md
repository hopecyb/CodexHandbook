ChatGPT 桌面应用中的每个聊天都带有一个终端，其作用域是当前项目或工作树。它不只是“看日志”的地方，也是你核对 Codex 结论的证据窗口。

可从应用右上角的终端图标打开，或同时按下 `Ctrl` 与反引号键。ChatGPT 可以读取当前终端输出，因此你也可以让它分析失败的构建或正在运行的开发服务器。

## 最小验证流程

在一个 JavaScript 项目中，可以按顺序运行：

```bash
git status --short
pnpm test
pnpm run lint
```

不同项目的命令不同，应先查看 `README.md`、`package.json` 或项目规则。把已确认的命令写进提示词：

```text
修改后请运行 pnpm test 和 pnpm run lint。
逐项报告退出状态；任何一项失败都不要声称任务已完成。
```

验收时至少记录：执行了什么、退出是否成功、失败的第一条有效错误、哪些检查没有运行。

## 长进程怎么处理

开发服务器会持续运行，这不等于命令卡死。让它启动后，检查：

- 输出中是否出现本地地址；
- 浏览器能否打开页面；
- 终端是否随后出现运行时错误。

需要停止时再发送中断信号。不要因为暂时没有新输出就重复启动多个服务器。

## 可复用 Action

若经常运行相同命令，可在本地环境中定义 Action。它会作为桌面应用里的快捷操作，并在集成终端中执行。适合封装 `test`、`lint`、`build` 等低风险验证，不适合隐藏生产发布或数据库清理操作。

## 安全边界

- 不把生产密钥粘贴到聊天或终端历史中；
- 看不懂的命令先要求解释目标、影响范围和回滚方式；
- 不在生产环境盲目重跑删除、迁移、发布命令；
- 终端可执行不代表命令已获业务授权。

官方文档给出的常见命令包括 `git status`、`git pull --rebase`、测试和 lint；本项目应以自身文档为最终命令来源。
