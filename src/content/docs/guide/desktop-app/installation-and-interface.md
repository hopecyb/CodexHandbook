本章适合第一次打开 ChatGPT 桌面应用的读者。目标不是记住所有按钮，而是完成一个**可审查、可验证的小任务**。

安装与登录步骤见[安装桌面 App](/guide/getting-started/install-desktop-app/)。当前官方提供 macOS、Windows 与 Linux 版本；登录后可以新建聊天、创建项目，或打开本地文件夹。

## 先认识三个对象

| 对象 | 用来做什么 | 新手先做什么 |
|---|---|---|
| 项目或文件夹 | 给聊天提供文件与工作目录 | 打开一个练习仓库，不要先用生产目录 |
| 聊天 | 保存目标、上下文、进度与结果 | 一个明确目标使用一个聊天 |
| Codex | 阅读、修改并验证项目内容 | 先做低风险、容易核对的小改动 |

应用会持续更新界面，但这三个对象比某个按钮的位置更稳定。

## 完成第一次真实任务

准备一个已有 Git 仓库，先确认没有需要保留但尚未记录的改动，再在应用中打开该文件夹并新建 Codex 聊天。

输入：

```text
请先阅读 README.md，只修改其中的“本地运行”一节：
1. 修正已经失效的启动命令；
2. 保留其他章节原样；
3. 修改后展示 diff，并运行文档中能执行的验证命令；
4. 如果无法验证，明确说明原因，不要声称完成。
```

完成后不要只读聊天摘要，还要检查：

1. 审查窗格里是否只出现预期文件；
2. 删除内容是否合理；
3. 终端输出是否真的支持“验证通过”的结论；
4. `git diff` 是否与任务范围一致。

## Chat、Work 与 Codex 怎么选

- 只问知识或讨论想法：使用 Chat。
- 处理跨文件、跨工具的通用工作：使用 Work。
- 需要理解、修改、测试仓库：使用 Codex。

若只是临时问一个不需要长期上下文的问题，可使用 Quick chat；需要连续追踪的工作应留在普通聊天或项目中。

## 失败时先查什么

- **看不到文件**：确认打开的是正确文件夹，任务权限没有被拒绝。
- **无法运行命令**：确认依赖已安装，再查看终端中的第一条真实错误。
- **改动混入旧内容**：先用 `git status` 区分任务前已有改动与本次改动。
- **应用界面与本文不同**：按“项目/文件夹、聊天、审查、终端”的逻辑对象定位，不依赖截图中的固定位置。
