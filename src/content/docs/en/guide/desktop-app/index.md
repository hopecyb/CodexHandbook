The desktop app is the default starting point for beginners: it gives you visible projects, tasks, diffs, and approvals.

It is also an approachable entry point if you are not familiar with the command line or IDE extensions.

It does more than let you chat. It brings projects, changes, approvals, and verification into one visible interface.

## What this chapter covers

- The first actions to learn in the desktop app
- Which features help beginners now and which can wait
- Where to look when reviewing changes, handling approvals, or troubleshooting

## Recognize these three things first

You do not have to learn every feature at once. Start by finding:

1. Where to enter a task
2. Where to inspect changes
3. Where to approve or reject an action

Once you can do those three things, you can complete a basic task cycle.

## Common misunderstandings

### 1. Is the desktop app just a graphical shell for the CLI?

It makes several key parts of the workflow visible:

- The current task
- Plans and tool calls
- File changes
- Approval actions
- Result review

### 2. Must I understand every button before starting?

At first, just find:

- Where to enter the task
- Where to view the diff
- Where to approve or reject

That is enough to begin.

### 3. If the desktop app suits beginners, is it unsuitable for real work?

Many real tasks can also be completed in the desktop app, especially when visible review and transparency matter to you.

## A good learning order

On your first use of the desktop app:

1. Install it and get familiar with the interface.
2. Select the right project.
3. Start a small task.
4. Inspect the changes.
5. Learn to approve and reject requests.
6. Then learn advanced features such as parallel agents, worktrees, and cloud tasks.

This is usually easier than trying to learn every feature immediately.
