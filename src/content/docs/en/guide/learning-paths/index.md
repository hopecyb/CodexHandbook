Learning paths **organize reading order only**; they do not duplicate long articles from the product handbook or capability guides.

At first, this chapter may look like another layer of navigation. Its purpose is to answer which kind of user you most resemble right now and what to read next.

It does not add new product knowledge. It helps you avoid unnecessary detours.

![Illustration: four paths from the same book—beginner, creator, developer, and team—meet at the summit](/illustrations/learning-paths.webp)

## What this chapter does

- Helps beginners, creators, developers, and team leads choose a path
- Shows how reading order differs by role
- Separates what is useful now from what can wait

## Hands-on creator path

The [creator path](/en/guide/learning-paths/creator/) has four consecutive milestones: materials and fact table → sourced article → editable eight-slide deck → reusable task brief. The article and slide deck each have separate downloadable materials, and every step has completion criteria. The full path has not yet been validated by independent readers.

## Hands-on developer path

The [developer path](/en/guide/learning-paths/developer/) reuses the shopping-cart bug exercise. It moves through reading the code → fixing and testing → reviewing the diff → preparing a handoff. It provides three fillable templates and an author reference. The reference tests have been rerun; independent reader completion remains unverified.

## Common misconceptions

### 1. Learning paths duplicate the handbook

The main articles explain the material. Learning paths tell you which articles to read now.

### 2. I must choose a fixed identity first

Ask one question instead:

**What is the main problem I want to solve right now?**

### 3. I must follow a path from beginning to end without skipping

A path is a suggested order, not a mandatory process. You can return to other chapters when a specific question arises.

## Choosing when you are unsure

If you are unsure which path to take, use the current task:

- Have not completed a full task yet: follow the [beginner path](/en/guide/learning-paths/beginner/)
- Mainly writing content, making visuals, or preparing presentations: see the [creator path](/en/guide/learning-paths/creator/)
- Mainly changing code, fixing bugs, or taking on a project: see the [developer path](/en/guide/learning-paths/developer/)
- Mainly planning team adoption and risk controls: see the [team path](/en/guide/learning-paths/team/)

Learning paths help you decide what to read next based on your most important current problem.
