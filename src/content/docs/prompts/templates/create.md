# 创建模板

从零创建的任务，最容易出现两个问题：

- 目标很大，但没有边界
- 信息还不够，却已经急着让 Codex 开始生成

创建类模板先把产物、用途和约束说清楚，再开始做。

## 模板

```text
目标：创建【产物名称】，用于【用途/用户】。
背景：【已有约定、设计风格、依赖限制】
输入：【规格、草图、参考 @文件】
约束：
- 只修改/创建【路径范围】
- 不要引入【排除项】
- 需要我批准后再执行【高风险操作】
验收：
- 【可观察结果 1】
- 【可观察结果 2】
- 提供自测步骤
若信息不足请先列出假设并问我，不要猜测。
```

## 什么时候适合用这个模板

- 从零做一个页面、组件、脚本或文档
- 你已经知道要产出什么，但还没动手
- 你希望把创建范围先说清楚，再开始做

## 常见误区

### 1. 创建任务就等于“让它自由发挥”

从零创建更需要说明：

- 给谁用
- 用来干什么
- 哪些风格或技术路线不能碰

### 2. 背景只是可选装饰

对于创建类任务，背景常常直接影响产物方向。

### 3. 验收写“看起来不错”还不够

这样最后会很难判断到底算不算完成。

创建类任务里，最容易出问题的情况，是还没说清“要做什么、给谁用”就直接开做。
