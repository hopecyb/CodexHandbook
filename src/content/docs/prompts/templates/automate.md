# 自动化模板

自动化类任务常见的误区，是只想着“能不能自动跑”，却没先想：

- 失败时怎么办
- 谁来看到结果
- 出错时能不能安全停下

自动化模板有个重点：任务出问题时也要可控。

## 模板

```text
目标：把【重复任务】自动化为【脚本/Skill/定时任务】。
触发：【手动 / 定时 / CI】
输入：【数据源、配置文件】
约束：
- 失败时明确退出码与日志位置
- 不硬编码密钥；用环境变量
- 提供 dry-run 模式
验收：
- 在【示例输入】上输出预期结果
- 文档说明如何运行与排障
```

## 什么时候适合用这个模板

- 规则清楚的重复任务
- 需要脚本化或定时化的流程
- 想先补上 dry-run、日志、退出码这些护栏

## 常见误区

### 1. 自动化就是省掉人工判断

很多更容易落地的自动化，实际上只是自动检查、自动汇总、自动开草稿。

### 2. 任务能跑通一次，就能自动化

要把任务做成可长期运行的自动化，还得补：

- 日志
- 退出码
- dry-run
- 排障说明

自动化模板的价值，就是让它能长期、安全地运行。
