# 审查模板

审查类任务最容易跑偏的地方，是一开始就变成“顺手帮你改了”。

先把问题找出来，再决定要不要改，会稳一些。

## 模板

```text
请审查当前相对【main/目标分支】的 diff，先不要改代码。
维度：
1. 是否超出【issue/规格】范围
2. 逻辑错误、边界、错误处理
3. 安全（密钥、注入、权限）
4. 测试与文档是否匹配变更
输出分级清单：🔴 阻断 / 🟡 建议 / 🟢 通过，每条附文件与行号。
```

## 什么时候适合用这个模板

- 审 PR
- 审 diff
- 审一轮文档或配置改动的风险

## 常见误区

### 1. 审查就是让它给点意见

更准确地说，是让它按结构找问题。

### 2. 没有明显 bug，就等于通过

审查还应该看：

- 是否超范围
- 测试和文档是否跟上
- 有没有安全和边界问题

审查模板的重点，就是按固定维度把风险翻出来，不是泛泛评价“好不好”。
