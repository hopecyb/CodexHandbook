# 修改模板

这个模板适合“在现有东西上改一点”的任务。

修改类任务先把改动边界说清楚。

## 模板

```text
目标：在【现有功能/文件】上完成【具体改动】。
背景：【为什么改、影响范围】
输入：@【相关文件路径】
约束：
- 保持【API/样式/行为】不变，除非我明确允许
- 最小 diff，不做无关重构
- 每步后只跑【相关测试】
验收：
- 【行为变化描述】
- 相关测试通过
- diff 仅涉及必要文件
```

## 什么时候适合用这个模板

- 改现有页面或组件
- 修某个明确 bug
- 微调文案、交互或配置
- 想强调“只改这一块，不要顺手重构”

## 常见误区

### 1. 修改任务比创建任务简单，所以可以少写很多

修改任务很容易踩到旧代码、旧约束和隐藏依赖，所以更需要边界。

### 2. “最小 diff”就是少改几行字

“最小 diff”意味着**只改和目标直接相关的部分**。

### 3. 只要说“保持现有行为不变”还不够

最好再补一句：到底什么算“现有行为”。

## 这个模板在防什么

这个模板主要防这些问题：

- 改多了
- 改偏了
- 改到了你没授权的层

修改类提示词除了“改什么”，还要说清“只允许改到哪里”。
