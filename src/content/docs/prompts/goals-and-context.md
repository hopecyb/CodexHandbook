title: 提供目标与背景
description: 让 Codex 知道要完成什么以及为何重要。
---

很多提示词看起来信息不少，但下面两件事反而没讲清楚：

- 你到底要什么结果
- 为什么这件事要这样做

目标负责说明“要做成什么”，背景负责说明“为什么要这么做”。

**目标** 写最终产物，不写模糊愿望。  
「让网站更好」→「把首页主按钮文案改成……并保持现有样式类名」。

**背景** 补充读者不知道但 Agent 需要的现状：技术栈、受众、截止原因、已知坑。

## 为什么“目标”和“背景”不能混着说

如果只有背景，没有目标，Codex 可能会理解成一段情况说明，不知道你到底要它产出什么。  
如果只有目标，没有背景，它又容易用一种“技术上能做、但不一定适合你场景”的方式去做。

## 常见误解

### 1. 目标就是“我想改善一下”

这更像愿望，不像目标。

一个更清楚的目标一般会说明：

- 改哪个东西
- 改成什么状态
- 需要保持什么不变

### 2. 背景不是越多越好

背景里真正有价值的部分，是那些**你知道、但 Codex 不知道**，而且会影响决策的信息。

### 3. 技术上下文才算背景

不只是技术上下文。

下面这些也可能是重要背景：

- 读者是谁
- 截止原因
- 已知坑
- 团队约束

## 一个够用的写法

如果先写一个能用版本，可以这样写：

```text
目标：把什么改成什么样
背景：为什么要改、给谁看、目前卡在哪
```

例如：

```text
目标：把 docs 首页首屏文案改得更适合初学者理解，并保持现有结构
背景：当前文案默认读者懂很多术语，第一次访问时理解门槛偏高
```

## 怎么检查自己写得够不够清楚

检查目标时，可以看两件事：

- 结果是不是能看出来
- 范围是不是能感知到

检查背景时，再看一件事：

- 这些信息会不会真的影响它怎么做

目标决定交付什么，背景补充为什么要这样做。
