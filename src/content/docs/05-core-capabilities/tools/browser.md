**浏览器工具**让 Agent 在受控环境中访问真实网页：读取 DOM、截图、有时可交互点击。适合前端验收、文档链接检查、对照设计稿——不适合替代你的安全审计或登录生产后台乱点。

## 这篇解决什么问题

- 浏览器工具能做什么、不能做什么
- 与 Web 搜索、Computer Use 的区别
- 如何安全地授权与约束

## 能力概览

| 适合 | 不适合 |
|---|---|
| 打开本地 dev server 页面看布局 | 批量爬取受 ToS 限制的网站 |
| 验证公开文档链接 404 | 在未授权系统上自动登录 |
| 对照静态页面与实现 | 替代完整 E2E 测试框架 |
| 读取页面可见文本辅助调试 | 处理需复杂人机验证的站点 |

选型背景：[工具选择](/05-core-capabilities/tools/tool-selection/)

## 与其他工具对比

| 工具 | 输入 | 输出 |
|---|---|---|
| Web 搜索 | 查询词 | 摘要与链接 |
| 浏览器 | URL / 本地地址 | 页面结构、截图、交互结果 |
| Computer Use | 整屏 GUI | 任意应用操作（更重、更敏感） |

## 推荐工作流

1. **本地前端**：先 `npm run dev`，再给 `http://localhost:PORT/path`
2. **明确任务**：「检查登录表单在 375px 宽度下是否溢出」，而非「看看网页」
3. **写清边界**：禁止访问外网、禁止提交表单到生产
4. **验收**：对照 [验证产物](/05-core-capabilities/quality/verify-artifacts/) 与截图

## 安全边界

- 默认假设浏览器可访问**你机器或环境能访问的一切**——包括内网 admin
- 任务中声明：`仅访问 localhost` 或允许域名白名单
- 勿在已登录个人账号的浏览器配置里跑不可信仓库任务
- Cloud 环境浏览器策略由 [Cloud 环境](/04-product-guides/web-and-cloud/cloud-environments/) 与网络策略决定

审批概念：[权限与审批](/01-foundations/permissions-and-approvals/)

## 常见错误

- 给生产 URL 且未限制只读
- 把浏览器截图当「测试通过」却不跑自动化测试
- 与 Web 搜索混用：搜索不能代替真实渲染检查

## 验收清单

- [ ] 访问范围在 prompt 中写死
- [ ] 关键视觉问题有截图或文字说明
- [ ] 与单元/E2E 测试结论一致或已知差异已记录
