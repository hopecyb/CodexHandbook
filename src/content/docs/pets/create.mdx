制作 Codex Pet 的目标不是单独得到一张好看的图片，而是得到一个 Codex 能识别、能播放、能切换状态的资源包。你可以把它理解成“元数据 + 动画图集 + 授权说明”的组合。

![插画：从手绘草图、网格对齐、动作图集到打包成宠物文件夹的制作流程](/illustrations/pets-create.webp)

最小结构通常是：

```text
<pet-id>/
  pet.json
  spritesheet.webp
```

## spritesheet 是什么

![插画：一张图集按行列排列多个动作，截取单帧后连成胶片并在屏幕上播放](/illustrations/pets-spritesheet.webp)

Spritesheet 是把多帧动画合并到一张大图里的做法。客户端不需要加载几十张小图，而是按行列坐标从大图中裁切每一帧，再连续播放。

图集规格与版本字段必须一起核对。本站旧示意图采用 8 列 × 9 行、每帧 192 × 208 px（整图 1536 × 1872 px）；它不能用作所有客户端的通用规格。制作前应获取目标客户端或制作工具对应版本的格式说明，确认行列数、动作映射和版本字段，再生成素材。

扩展图集不能仅修改图片高度而沿用旧元数据。缺少可追溯的格式说明时，先停止制作并查明契约，不凭示意图推断兼容。

## 准备素材

素材最好满足这些条件：

- 角色轮廓清楚，背景可干净抠出。
- 各动作的角色比例、视角和基线一致。
- 透明背景没有彩边、残影和多余像素。
- 角色不会贴边，避免播放时被裁切。
- 动作能对应工作、等待、完成、失败、移动或闲置等状态。

如果素材来自二创、游戏、动漫、品牌或他人作品，要先确认来源和授权。不要把未经授权的素材写成可商用资源。

## `pet.json` 负责什么

下面只演示身份与素材路径字段，不是已经验证可安装的完整包；实际格式可能还需要版本字段：

```json
{
  "id": "my-pet",
  "displayName": "My Pet",
  "description": "A focused companion for Codex sessions.",
  "spritesheetPath": "spritesheet.webp"
}
```

建议保持：

- `id` 使用小写字母、数字和短横线。
- 文件夹名和 `id` 一致。
- `spritesheetPath` 使用相对路径。
- `description` 写清楚这个宠物是什么，不写空泛描述。
- 在随包 README 或 LICENSE 中保留作者、版本、来源和许可；不要假定客户端接受任意扩展字段。

`pet.json` 的作用不是保存动画本身，而是告诉客户端“这个包是谁、素材在哪里、应该怎么解释”。当素材路径、文件名或目录结构不一致时，客户端通常就无法加载。

## 本地检查

发布或分享前，至少检查：

- `pet.json` 是合法 JSON。
- `spritesheetPath` 指向存在的文件。
- spritesheet 尺寸和帧网格符合当前契约。
- 每行动画不会明显跳帧、漂移或裁切。
- 透明背景干净。
- 包里没有临时文件、源图或不该公开的素材。

## 授权和来源

宠物素材常常来自二创、截图、AI 生成图、公开图库或他人作品。制作时要分清：

- 你能否个人使用。
- 你能否公开分享。
- 你能否允许他人二次分发。
- 你是否需要署名或保留来源链接。

保留原始工程文件和来源记录，会让后续修边、改动作、换尺寸和补授权说明更容易。
