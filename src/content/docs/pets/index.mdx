Codex 宠物是 ChatGPT/Codex 界面里的动态陪伴元素。它不是模型能力，也不会改变 Agent 的权限、任务或输出。当前公开入口以产品内创建、上传或选择为准，不需要手工构造 `~/.codex/pets` 目录。

![插画：一只像素风小宠物趴在 Codex 代码窗口边，开心地陪伴](/illustrations/pets-hero.webp)

这个栏目解释当前公开入口、文件限制和素材安全。本站不提供宠物资源列表，也不把外部资源站作为官方来源。

## 当前公开入口

![插画：打开的资源包里飘出三样东西——元数据卡片、多帧动画图集和授权卷轴](/illustrations/pets-anatomy.webp)

| 表面 | 入口 | 说明 |
|---|---|---|
| 桌面 App | Settings → Pets → Create pet | 在产品内创建和管理，界面随版本变化 |
| ChatGPT Web | Settings → Personalization → Pet → Upload pet | 上传单个符合规格的透明 sprite sheet 文件 |
| CLI | `/pets` 或 `/pet` | 需要 iTerm2 3.6+、Kitty graphics 或 Sixel；tmux/Zellij 中不可用 |

Web 上传文件当前要求 **1536 × 1872 px、透明背景、PNG 或 WebP、最大 20 MiB**。Web Pet 只出现在支持的 ChatGPT Work chats 中；桌面自定义 Pet 保存在本机，不会自动同步到 Web。IDE 扩展不提供 Pet picker 或浮动 Pet。这些是带日期的产品事实，使用前仍应以界面提示为准。

## 为什么需要了解它

了解 Pets 的结构可以帮你判断三件事：

- 启用时：选对产品入口，不运行来历不明的安装脚本。
- 排错时：检查账号开放、客户端版本、终端兼容和文件限制。
- 制作时：处理透明背景、画布尺寸和素材授权。

## 阅读路径

1. [启用或上传 Codex Pet](./install/)：按桌面、Web、CLI 三条路径操作。
2. [制作 Codex Pet](./create/)：准备当前 Web 上传所需的单图，并保留来源与授权。

旧教程中的 `pet.json + spritesheet.webp` 私有目录格式没有出现在当前公开契约中。它可能属于历史版本、内部实现或社区工具；除非目标版本提供可核验说明，不要把它当成通用安装方式。
