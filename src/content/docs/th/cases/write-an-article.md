เป้าหมายของแบบฝึกนี้คือบทความสั้นภาษาจีนที่ข้อเท็จจริงสำคัญทุกข้อย้อนกลับไปยังแหล่งข้อมูลได้ คุณจะจัดการคำอธิบายที่ขัดกัน แยกสิ่งที่แหล่งข้อมูลรองรับ ข้ออนุมานของผู้เขียน และคำถามที่รอยืนยัน แล้วแก้ร่างตัวอย่างที่จงใจใส่ข้อผิดพลาดชัดเจน

ระดับ: เริ่มต้น ใช้เวลาประมาณ 45—60 นาทีตามการประเมินของบรรณาธิการ และยังไม่ได้จับเวลาผู้อ่านจริง ข้อกำหนดเบื้องต้น: ส่งไฟล์ในเครื่องให้ Codex และอ่านต้นฉบับ Markdown ได้ การตรวจโครงสร้างแบบเลือกทำต้องใช้ Python 3.10+

[ดาวน์โหลดชุดฝึกฉบับเต็ม v1.0.0 (ZIP)](/downloads/source-backed-article/source-backed-article-1.0.0.zip)

สื่อทั้งหมดเป็นงานต้นฉบับของเว็บไซต์ ผลิตภัณฑ์ “拾页” และตัวละครผู้ให้สัมภาษณ์ “小林” เป็นเรื่องสมมติ ไม่ได้กล่าวถึงผลิตภัณฑ์จริงหรือคำรับรองจากผู้ใช้จริง

## ดูสิ่งที่จะได้เมื่อทำเสร็จ

บทความอ้างอิงฉบับสุดท้ายใช้แกนเรื่อง “ตรวจสรุปหนึ่งชุดก่อน แล้วค่อยตัดสินใจว่าจะขยายการใช้งานหรือไม่” ครอบคลุมขอบเขตอินพุต การทดลองวงจำกัด การตรวจสรุป และประเด็นที่ยังไม่ตัดสินใจ

| ผลงาน | ใช้ทำอะไร |
|---|---|
| `outline.md` | อธิบายปัญหาของผู้อ่านและลำดับบทความ |
| `article.md` | บทความภาษาจีนพร้อมหมายเลขข้อเท็จจริง |
| `claim-map.csv` | ข้อเท็จจริง/คำแนะนำสำคัญเจ็ดข้อ, source ID, ตำแหน่งหัวข้อ และประเภทหลักฐาน |
| `unresolved.md` | เก็บคำถามที่ตอบจากเอกสารไม่ได้ |
| `revision.diff` | ความต่างของข้อความจริงระหว่างร่างตัวอย่างกับฉบับสุดท้าย |

[ดูบทความอ้างอิง](/downloads/source-backed-article/solution/article.md) · [ดูตารางเชื่อมข้อเท็จจริง](/downloads/source-backed-article/solution/claim-map.csv)

## ดาวน์โหลดและเตรียมพร้อม

แตกไฟล์แล้วเปิดโฟลเดอร์ `source-backed-article` อ่าน `brief.md` และ `sources/index.csv` ใบอนุญาตคือ CC0 1.0 จึงแก้ไขและแจกจ่ายต่อได้ คุณอาจทำฉบับของตนเองก่อนโดยยังไม่ดู solution

เอกสารสามชุดคือ P คำอธิบายผลิตภัณฑ์, I บทสัมภาษณ์สังเคราะห์ และ C สรุปเวอร์ชัน แต่ละชุดมีหมายเลขหัวข้อที่คงที่ เช่น P1, I2, C3 การอ้างอิงควรชี้ถึงหัวข้อที่เจาะจง ไม่ใช่เขียนเพียงว่า “จากเอกสาร”

## 1. จัดระเบียบข้อเท็จจริงและข้อขัดแย้งก่อน

```text
อ่าน brief.md, sources/index.csv และเอกสารสามชุดที่ระบุไว้
แสดงข้อเท็จจริงที่รองรับโดยตรง ข้อมูลที่ขาด และข้อความที่ขัดกันก่อน โดยแต่ละข้อมี source ID และหัวข้อ
ห้ามค้นอินเทอร์เน็ตเพื่อเติมข้อมูลผลิตภัณฑ์สมมติ และห้ามเปลี่ยนบทสัมภาษณ์สังเคราะห์เป็นคำรับรองจากผู้ใช้จริง
อย่าแก้ข้อขัดแย้งอัตโนมัติตามวันที่เอกสาร ให้ส่งตารางข้อเท็จจริงก่อนแล้วจึงเขียนบทความ
```

แบบฝึกนี้จงใจเก็บข้อขัดแย้งหนึ่งรายการ: P3 ระบุว่าการอัปโหลดข้อมูลวินิจฉัยปิดเป็นค่าเริ่มต้น แต่ C2 ระบุว่าการติดตั้งใหม่เปิดเป็นค่าเริ่มต้น และ C3 ยืนยันว่าไม่มีคำชี้แจงแก้ไขจากผู้ดูแล วิธีที่ถูกต้องคือระบุว่ายังไม่ยืนยัน ไม่ใช่เลือกเอกสารที่ใหม่กว่าแล้วอ้างว่าปัญหาได้รับการแก้แล้ว

## 2. เขียนต่อเนื่องภายในขอบเขตที่ชัดเจนแล้ว

`prompts/02-outline-and-write.md` ในชุดฝึกกำหนดกลุ่มเป้าหมายและโครงสี่ส่วนไว้แล้ว: ทำอะไรได้ ทดลองอย่างไร ต้องตรวจอะไร และเรื่องใดยังไม่คลี่คลาย เมื่อยืนยันโครงนี้แล้ว ให้ทำต่อเนื่องได้โดยไม่ต้องหยุดทุกย่อหน้า

เขียนผลงานทั้งหมดลง `my-output/` และคงเอกสารอินพุตไว้ กำกับข้อเท็จจริงสำคัญด้วยหมายเลข เช่น `[F1]` แล้วบันทึกในตารางเชื่อมว่า:

```text
claim_id,article_section,claim,source_id,locator,evidence_type,confidence_note
```

ประเภทหลักฐานมีเพียง “原文支持” (ข้อความต้นฉบับรองรับ), “作者推断” (ข้ออนุมานของผู้เขียน) และ “未确认” (ยังไม่ยืนยัน) การแนะนำให้ทดลองกับไฟล์จำนวนน้อยเป็นวิจารณญาณของผู้เขียน ห้ามเขียนเป็นคำรับรองของผลิตภัณฑ์หรือขั้นตอนบังคับ

## 3. แก้ข้อเท็จจริงก่อน แล้วค่อยปรับน้ำเสียง

`solution/draft.md` เป็นกรณีผิดที่ผู้เขียนออกแบบ ไม่ใช่เอาต์พุตจริงจากโมเดล โดยจงใจใส่ความสามารถ PDF/รูปภาพที่เอกสารไม่รองรับ การทำงาน offline อย่างสมบูรณ์ การรับประกันผลลัพธ์ และคำรับรองจากผู้ใช้จริง

| ปัญหาในร่าง | วิธีแก้ | เหตุผล |
|---|---|---|
| “รองรับ PDF และรูปภาพทุกชนิด” | เปลี่ยนเป็น Markdown และ plain text | P1 กำหนดขอบเขตอินพุตชัดเจน |
| “offline ทั้งหมด และปิดการวินิจฉัยเป็นค่าเริ่มต้น” | วางข้อความที่ขัดกันคู่กัน แล้วระบุคำถามรอยืนยัน | P3/C2 อธิบายตรงข้ามกัน และยังขาดฟิลด์การอัปโหลด |
| “小林 พิสูจน์ความแม่นยำและการประหยัดเวลา” | คงสถานะสังเคราะห์และไม่ใส่ตัวเลขผลลัพธ์ | I3 ไม่มีการจับเวลาหรือชุดประเมินคงที่ |
| “เครื่องมือสารพัดประโยชน์ เพิ่มประสิทธิภาพได้ง่าย” | เปลี่ยนเป็นอินพุต การทำงาน และการตรวจที่เจาะจง | ลดคำเกินจริงโดยไม่เพิ่มข้อเท็จจริงใหม่ |

[ดู diff การแก้ไข](/downloads/source-backed-article/solution/revision.diff) และ [คำอธิบายการแก้ไข](/downloads/source-backed-article/solution/revision-notes.md) การเกลาแต่น้ำเสียงโดยยังคงความสามารถที่ผิดไว้ ไม่ถือว่าตรวจแก้เสร็จ

## 4. ตรวจโครงสร้าง แล้วอ่านแหล่งข้อมูลทีละประโยค

หากสภาพแวดล้อมมี Python 3.10+ ให้รันในไดเรกทอรีแบบฝึก:

```sh
python3 validation/check.py --output my-output
```

สคริปต์นี้ตรวจ hash ของแหล่งข้อมูลสามชุด หมายเลขในเนื้อหา หัวข้อแหล่งข้อมูล และไฟล์รายการที่ยังไม่ตัดสินใจ งานอ้างอิงในชุดผ่านการตรวจ และเมื่อเพิ่ม F99 ที่ไม่มีอยู่ลงในสำเนาชั่วคราว สคริปต์จะปฏิเสธ

**โครงสร้างผ่านไม่ได้แปลว่าข้อเท็จจริงถูกต้อง** เปิดต้นฉบับของ claim ทุกข้อ แล้วพิจารณาว่ารองรับประโยคปัจจุบันหรือไม่ และทำเงื่อนไขอย่าง “จำกัดเฉพาะ” หรือ “ยังไม่ยืนยัน” หายไปหรือไม่ การเขียนข้อความสังเคราะห์เป็นคำรับรองจริงยังคงผิด แม้มีหมายเลขอ้างอิง

หากรันสคริปต์ไม่ได้ ให้เปิดไฟล์ต้นฉบับทั้งสามตามตารางข้อเท็จจริงทีละรายการ แล้วตรวจหมายเลขและถ้อยคำ อย่าอ้างว่าการตรวจที่ไม่ได้รันผ่านแล้ว

## วิธีกู้คืนเมื่อเกิดปัญหา

- หาไฟล์ไม่พบ: ตรวจไดเรกทอรีที่แตกไฟล์และดัชนีแหล่งข้อมูลก่อน ห้ามแต่งเนื้อหาเอกสาร
- ไม่มีหมายเลขอ้างอิง: เติม mapping ที่ถูกต้องหรือลบข้อเท็จจริงที่ไม่มีแหล่งข้อมูล แต่อย่าลบความไม่แน่นอนที่สมเหตุสมผล
- แหล่งข้อมูลขัดกัน: แสดงทั้งสองข้อความและระบุว่าต้องให้ใครเติมหลักฐานใด ห้ามตัดสินตามวันที่ เสียงข้างมาก หรือน้ำเสียง
- บทความเหมือนโฆษณาเกินไป: ลบคำรับรองผลลัพธ์ที่ไม่มีหลักฐานก่อน แล้วเปลี่ยนเป็นการกระทำและข้อจำกัดที่เจาะจง

## เงื่อนไขเสร็จสมบูรณ์

ระบุตำแหน่งข้อเท็จจริงสำคัญได้ คำแนะนำของผู้เขียนแยกชัด ข้อขัดแย้งและข้อมูลที่ขาดยังมองเห็น และสถานะสังเคราะห์ไม่ถูกลบ งานส่งมอบอยู่ในเครื่องและไม่เผยแพร่อัตโนมัติ

จากนั้นใช้ฉบับสุดท้ายนี้[สร้างงานนำเสนอแปดหน้าที่แก้ไขได้](/th/cases/create-a-slide-deck/) แบบฝึกสไลด์มีอินพุต PPTX, PDF ภาพตัวอย่างแปดหน้า และบันทึกการยืนยันแยกต่างหาก หากเรียนต่อเนื่อง ให้ใช้บทความที่คุณทำและตรวจเองก่อน
