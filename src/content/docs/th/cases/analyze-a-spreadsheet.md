แบบฝึกนี้ให้ส่งมอบรายงานยอดขายประจำสัปดาห์ พร้อมสรุปตามภูมิภาค อันดับสินค้า และบัญชีรายการทำความสะอาดทีละแถว อินพุตเป็นข้อมูลสังเคราะห์ที่เว็บไซต์จัดทำเอง จึงไม่ต้องใช้ข้อมูลลูกค้าจริง

ระดับ: เริ่มต้น ใช้เวลาประมาณ 30–45 นาทีตามการประเมินของบรรณาธิการ และยังไม่ได้จับเวลาผู้อ่านจริง ข้อกำหนดเบื้องต้น: สามารถส่งไฟล์ในเครื่องให้ Codex ได้ การอ่านเฉพาะผลอ้างอิงไม่ต้องเขียนโปรแกรม แต่การรันตัวตรวจต้องใช้ Python 3.10+

[ดาวน์โหลดชุดฝึกฉบับเต็ม v1.0.0 (ZIP)](/downloads/sales-weekly-report/sales-weekly-report-1.0.0.zip) · [ดาวน์โหลดเฉพาะ CSV ยอดขาย](/downloads/sales-weekly-report/sales.csv)

## ดูผลลัพธ์ที่ต้องส่งมอบก่อน

| ตัวชี้วัด | ค่าอ้างอิง | จุดที่ต้องตรวจ |
|---|---:|---|
| ยอดขายสุทธิงวดปัจจุบัน | 4,644.75 หยวน | ต้องรวมยอดคืนเงิน |
| ยอดสุทธิงวดปัจจุบันของจีนตะวันออก | 1,281.25 หยวน | 1,401.75 − 120.50 |
| ยอดเงินที่ไม่มีวันที่ | 199.99 หยวน | แยกไว้ต่างหาก ห้ามเดาว่าอยู่สัปดาห์ใด |

งวดปัจจุบันคือ 2026-09-07—09-13 และงวดก่อนคือ 2026-08-31—09-06 การเปลี่ยนแปลงระหว่างสองสัปดาห์ปฏิทินเต็มเท่ากับ 87.04% นี่เป็นเพียงผลจากตัวอย่างสังเคราะห์ ไม่ใช่คำอธิบายสาเหตุทางธุรกิจจริง

[ดูรายงานประจำสัปดาห์อ้างอิง](/downloads/sales-weekly-report/summary.md) ลองทำเองก่อน แล้วค่อยเปิดคำตอบอ้างอิงเพื่อเปรียบเทียบ

## ดาวน์โหลดสื่อ

ชุดเต็มมีสรุปโจทย์ พจนานุกรมข้อมูล พรอมป์สามช่วง CSV 46 แถว รายงานอ้างอิง CSV สรุป/บัญชีสามไฟล์ implementation อ้างอิง สคริปต์ตรวจสอบอิสระ และบันทึกการยืนยันผล ทั้งหมดเผยแพร่ภายใต้ CC0 1.0 จึงแก้ไขและแจกจ่ายต่อได้

หลังแตกไฟล์ ให้เปิดโฟลเดอร์ `sales-weekly-report` อย่าดาวน์โหลดเฉพาะ CSV แล้วคาดว่าไฟล์อ้างอิงอื่นจะปรากฏเอง

## 1. ยืนยันไฟล์และหลักเกณฑ์ก่อน

มอบงานต่อไปนี้ให้ Codex วิธีส่งไฟล์อาจต่างกันตามไคลเอนต์ ก่อนทำต่อให้ยืนยันว่าระบบอ่านไฟล์ได้จริง

```text
อ่าน brief.md, starter/data-dictionary.md และ starter/sales.csv
ยืนยันว่าไฟล์มีอยู่ แล้วแสดงฟิลด์ ช่วงวันที่ จำนวนรายการ และหมายเลขแถวที่ต้องจัดการเป็นพิเศษ
ห้ามแก้ตารางต้นฉบับและห้ามดู solution แยกรายการซ้ำทุกช่อง วันที่หาย ค่าติดลบ และศูนย์จริงออกจากกัน
กำหนดขอบเขตสองสัปดาห์ตามพจนานุกรม หากมีข้อขัดแย้งให้แสดงรายการ หากไม่มีให้ทำต่อได้
```

ตารางต้นฉบับ 46 แถวมีรายการคืนเงินสองรายการ รายการซ้ำทุกช่องหนึ่งรายการ และรายการไม่มีวันที่หนึ่งรายการ สำหรับรายการซ้ำทุกช่องให้เก็บเฉพาะรายการแรก หาก ID เดียวกันแต่เนื้อหาต่างกัน ให้หยุดและตรวจสอบ วันที่หายห้ามแต่งเติม และยอดศูนย์เป็นข้อมูลที่ใช้ได้ หลังประมวลผลควรมี 44 แถวที่นำมาคำนวณ

## 2. สร้างรายงานและบัญชีการคำนวณ

ใช้ `prompts/02-report.md` ในชุดฝึกต่อ และกำหนดให้เขียนผลงานลง `my-output/`:

| ไฟล์ | ต้องมีอะไร |
|---|---|
| `summary.md` | ยอดรวม การเปลี่ยนแปลงรายสัปดาห์ ภูมิภาค Top 3 งวดปัจจุบัน คุณภาพข้อมูล และฐานการคำนวณ |
| `region-summary.csv` | ยอดสุทธิแต่ละภูมิภาคของสองสัปดาห์ ผลต่าง และการเปลี่ยนแปลง โดยผลรวมต้องตรวจเทียบกับผลบวกของภูมิภาคได้ |
| `top-products.csv` | เรียงตามยอดสุทธิสินค้างวดปัจจุบันจากมากไปน้อย โดยรวมยอดคืนเงิน |
| `row-ledger.csv` | หมายเลขแถวของแต่ละรายการต้นฉบับ การตัดสินใจว่าจะรวมไหม สัปดาห์ และยอดเงิน |

อินพุต solution และ validation ต้องไม่เปลี่ยน ชื่อฟิลด์และลำดับตารางต้องทำตามพจนานุกรมข้อมูล เพื่อให้ตัวตรวจอิสระเทียบได้ทีละรายการ งวดก่อนของจีนตะวันตกเฉียงใต้เป็นศูนย์ ให้ใส่ N/A ในช่องการเปลี่ยนแปลง ห้ามถือว่าเป็น 0% หรือเติบโตไม่สิ้นสุด

## 3. ตรวจซ้ำอย่างอิสระ อย่าถามเพียงว่า “ถูกไหม”

รันคำสั่งต่อไปนี้ในไดเรกทอรีชุดฝึกที่แตกไฟล์แล้ว:

```sh
python3 validation/check.py --output my-output
```

เมื่อผลงานครบทั้งสี่ไฟล์และตรงตามหลักเกณฑ์ ระบบจะแสดง `result: PASS` หาก hash ของอินพุตเปลี่ยน ลืมรวมยอดคืนเงิน จัดกลุ่มผิด หรือบัญชีรายการไม่ตรง ระบบจะแจ้งข้อผิดพลาด เมื่อการตรวจล้มเหลว ให้แก้เฉพาะผลงานของคุณ อย่าแก้ตัวตรวจเพื่อให้ยอมรับผล

หากรัน Python ไม่ได้ อย่างน้อยให้ตรวจด้วยตนเองดังนี้:

1. ยอดบวกเจ็ดรายการของจีนตะวันออกในงวดปัจจุบันรวม 1,401.75 หยวน บวกยอดคืนเงินแถว 44 จำนวน -120.50 เท่ากับ 1,281.25
2. ผลรวมสามภูมิภาคในงวดปัจจุบัน: 1,281.25 + 2,101.75 + 1,261.75 = 4,644.75
3. แถว 47 O046 ไม่มีวันที่ ยอด 199.99 หยวนจึงไม่รวมในสรุปสองสัปดาห์ ส่วนแถว 46 O001 เป็นรายการซ้ำ

ตัวตรวจอัตโนมัติไม่สามารถตรวจข้อสรุปภาษาธรรมชาติทั้งหมดได้ คุณยังต้องอ่านรายงานและลบคำอธิบายสาเหตุการเติบโตหรือข้อวินิจฉัยทางธุรกิจที่ไม่มีแหล่งอ้างอิง

## 4. แบบฝึกแก้ทิศทาง: ลืมยอดคืนเงิน

**กรณีผิดที่ออกแบบไว้:** หากกรองค่าติดลบทั้งหมดระหว่างสรุป ยอดงวดปัจจุบันจะเป็น 4,765.25 หยวน ซึ่งสูงเกินจริง 120.50 หยวน การตรวจอ้างอิงเคยแก้ผลชั่วคราวจริงเพื่อยืนยันว่าตัวตรวจจะปฏิเสธยอดที่ผิด นี่ไม่ใช่บทสนทนาโมเดลที่สร้างขึ้น

```text
ตรวจรายการที่ใช้ได้ซึ่งมี net_sales ต่ำกว่าศูนย์ และอธิบายว่าควรรวมหรือไม่
คงเครื่องหมายเดิมของยอดคืนเงิน คำนวณสรุปภูมิภาคและสินค้าใหม่ทั้งสองงวด แล้วแสดงผลต่างก่อนและหลังแก้
ห้ามทำให้การตรวจผ่านด้วยการแก้ CSV ต้นฉบับหรือตัวตรวจ
```

## 5. กู้คืนเมื่อพบปัญหา

| อาการ | ตรวจอะไรก่อน | ขั้นถัดไป |
|---|---|---|
| หาไฟล์ไม่พบ | ไดเรกทอรีปัจจุบันมี starter/sales.csv หรือไม่ | เปิดไดเรกทอรีที่แตกไฟล์แล้วอ้างอิงไฟล์ อย่าให้ Agent สร้างข้อมูลที่หายขึ้นใหม่ |
| อักษรจีนแสดงเพี้ยนหรือมีเพียงคอลัมน์เดียว | encoding เป็น UTF-8 และตัวคั่นเป็น comma หรือไม่ | นำเข้า CSV ต้นฉบับใหม่ อย่าแก้ยอดเงินด้วยมือ |
| ตัวเลขต่างกัน 120.50 | ลืมยอดคืนเงิน R043 หรือไม่ | คงค่าติดลบตามพจนานุกรม แล้วคำนวณสองงวดใหม่ |
| การเปลี่ยนแปลงแสดงข้อผิดพลาดหารด้วยศูนย์ | งวดก่อนของจีนตะวันตกเฉียงใต้เป็นศูนย์จริงหรือไม่ | เขียน N/A และอธิบายว่าฐานเป็นศูนย์ |
| ตัวตรวจแจ้งว่าไฟล์หาย | สร้างผลงานครบทั้งสี่ไฟล์หรือไม่ | เติมให้ครบตามพจนานุกรมแล้วรันใหม่ ไฟล์หายไม่ได้แปลว่ายอดเงินผิด |

## เงื่อนไขเสร็จสมบูรณ์และขั้นถัดไป

- hash ของตารางต้นฉบับไม่เปลี่ยน และผลงานครบทั้งสี่ไฟล์
- ตรวจซ้ำยอดรวม ยอดจีนตะวันออก และยอดที่ไม่มีวันที่อย่างอิสระแล้ว
- รายงานยังระบุความผิดปกติ ฐานศูนย์ และหลักเกณฑ์การคำนวณ โดยไม่แต่งสาเหตุ
- ระบุชัดเจนว่าการตรวจใดรันจริง และส่วนใดยังต้องอ่านตรวจด้วยคน

เก็บพรอมป์และบันทึกการแก้ทิศทางไว้ ก่อนเปลี่ยนชุดข้อมูลครั้งหน้าให้ยืนยันฟิลด์และหลักเกณฑ์อีกครั้ง ตัวตรวจแบบตายตัวของแบบฝึกนี้ใช้กับข้อมูลบริษัททั่วไปไม่ได้
