ก่อนตรวจเป็นรอบ ให้ยืนยันก่อนว่าสคริปต์พบปัญหาได้จริงและอธิบายได้ว่าตรวจอะไร แบบฝึกนี้เริ่มจากลิงก์เสียสองจุดที่จงใจออกแบบไว้ แก้ปลายทางครั้งละหนึ่งจุด แล้วสังเกตผลตรวจที่เปลี่ยนไป

[ดาวน์โหลดชุดฝึกฉบับเต็ม](/downloads/docs-link-audit/docs-link-audit-1.0.0.zip) · [README](/downloads/docs-link-audit/README.md) · [บันทึกกู้คืนจริง](/downloads/docs-link-audit/validation/recovery.json)

## รันตัวอย่างที่มีปัญหาก่อน

ต้องใช้ Python 3.10+ โดยไม่มี dependency ภายนอก API key หรือการเข้าถึงเครือข่าย รันในไดเรกทอรีที่แตกไฟล์แล้ว:

```sh
python3 scripts/check_links.py fixtures/site
```

คาดว่า exit code เป็น 1 และรายงานมีไฟล์ หมายเลขบรรทัด URL และสาเหตุ: `/missing/` ในบรรทัด 4 ของ index.html ไม่มีหน้าตรงกัน และ `#old-anchor` ในบรรทัด 5 ไม่มีอยู่ในหน้าปลายทาง ลิงก์ภายนอกอีกหนึ่งรายการจะอยู่ใน `unchecked` และไม่ถูกนับว่าผ่านโดยไม่แจ้ง

## แก้ทีละปัญหา

คัดลอก `fixtures/site` ไปยัง `work/` ของคุณและเก็บอินพุตต้นฉบับไว้ แก้ `/missing/` เป็น `/guide/` ก่อน แล้วรัน:

```sh
python3 scripts/check_links.py work
```

ตอนนี้ยังออกด้วยสถานะ 1 แต่เหลือเพียงปัญหา anchor จากนั้นแก้ `#old-anchor` เป็น `#install` แล้วรันใหม่ ผลต้องออกด้วยสถานะ 0 เทียบกับ `solution/site` และ [เอกสารอ้างอิงสำหรับตรวจด้วยคน](/downloads/docs-link-audit/solution/review.md) เพื่อยืนยันว่าไม่ได้ถือโอกาสแก้เนื้อหาอื่น

การตรวจด้วยผู้เขียนจริงได้ความล้มเหลว 2, 1 และ 0 ตามลำดับ โดย hash ของตัวอย่างต้นฉบับไม่เปลี่ยน [JSON ก่อนแก้](/downloads/docs-link-audit/validation/stage-0.json) · [JSON หลังแก้](/downloads/docs-link-audit/validation/stage-2.json)

## ทำความเข้าใจผลลัพธ์และขอบเขต

| ผลลัพธ์ | ความหมาย | ขั้นถัดไป |
|---|---|---|
| ออก 0 | การอ้างอิงในเครื่องผ่าน | อ่าน unchecked ห้ามใช้ผลนี้อ้างว่าลิงก์ภายนอกเข้าถึงได้ |
| ออก 1 | พบหน้าหาย anchor หาย หรือพาธออกนอกขอบเขต | ยืนยันเจตนาของแต่ละลิงก์แล้วค่อยแก้ |
| ออก 2 | ตรวจไม่สำเร็จ | ตรวจไดเรกทอรี ผล build ข้อผิดพลาดการอ่าน หรือ tag base ที่ไม่รองรับ |

สคริปต์อ่าน HTML หลัง build รองรับไดเรกทอรี `index.html`, relative path, root path และ HTML anchor แต่ไม่ parse dynamic JavaScript route, CSS URL, srcset หรือ rewrite เฉพาะเฟรมเวิร์ก เมื่อพบ `base href` จะหยุดเพื่อหลีกเลี่ยงการตีความ relative path ผิด URL ภายนอกและ protocol อื่นจะแสดงชัดว่าไม่ได้ตรวจ

รันการตรวจเจ็ดรายการในชุดฝึก:

```sh
python3 validation/test_links.py
```

เมื่อตรวจโปรเจกต์จริง ให้ build ตามคำอธิบายของโปรเจกต์ก่อน แล้วส่งไดเรกทอรีเอาต์พุตให้สคริปต์ เว็บไซต์นี้มีตัวตรวจการอ้างอิงภายในเฉพาะของตนเอง ชุดสอนนี้ใช้แทนการตรวจทั้งหมดของเฟรมเวิร์กไม่ได้

## เชื่อมเข้ากับกระบวนการตามรอบ

มอบ “build โปรเจกต์ → ตรวจลิงก์ → เก็บ exit code และ JSON” ให้ scheduler ที่มีอยู่ พร้อมตรึง working directory และสภาพแวดล้อม dependency หาก build ล้มเหลวให้หยุดและไม่อ่านเอาต์พุตเก่า หลีกเลี่ยงการเขียนบันทึกเดียวกันพร้อมกัน

รันด้วยมือหนึ่งครั้งก่อน จากนั้น trigger ด้วยมือในสภาพแวดล้อม scheduler เป้าหมาย แล้วจึงกำหนดรอบ เปรียบเทียบผลครั้งนี้กับครั้งก่อน: หากไม่เปลี่ยนให้เงียบไว้ หากมีความล้มเหลวใหม่ การตรวจผิดปกติ หรือการกู้คืน ให้เตรียมสรุปการเปลี่ยนแปลง การส่งจริงยังต้องอยู่ในขอบเขตสิทธิ์

ชุดนี้ไม่ได้สร้าง scheduled task ส่งการแจ้งเตือน แก้เว็บไซต์จริง หรือรัน CI ขั้นตอนกำหนดเวลาในที่นี้เป็นคู่มือเชื่อมต่อ ไม่ใช่หลักฐานว่า scheduler รันจริง ขั้นถัดไปดูได้ที่[คู่มืองานตามกำหนดเวลา](/th/skills/automations/scheduled-tasks/)

## วิธีจัดการลิงก์ภายนอก

ควรกำหนดขอบเขตและความถี่ที่อนุญาตสำหรับตรวจลิงก์ภายนอกแยกต่างหาก 404 ข้อจำกัดการยืนยันตัวตน timeout และข้อผิดพลาดชั่วคราวของบริการมีความหมายต่างกัน การเข้าถึงล้มเหลวครั้งเดียวใช้เป็นเหตุลบลิงก์โดยตรงไม่ได้ ชุดนี้ไม่ได้ตรวจลิงก์ภายนอกจริง และไม่ได้เขียน response จำลองเป็นเหตุขัดข้องเครือข่ายจริง
