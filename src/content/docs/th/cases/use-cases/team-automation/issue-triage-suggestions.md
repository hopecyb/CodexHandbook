แบบฝึกนี้แบ่งการคัดแยก Issue เป็น “สร้างข้อเสนอแนะ → ตรวจสอบ → ให้คนทบทวน” คุณจะได้รายการรอตรวจห้ารายการ โดยไม่มีการเผยแพร่ comment เพิ่ม label หรือปิด Issue อัตโนมัติ

[ดาวน์โหลดชุดฝึกฉบับเต็ม](/downloads/issue-triage/issue-triage-1.0.0.zip) · [README](/downloads/issue-triage/README.md) · [ดูเอาต์พุต dry run จริง](/downloads/issue-triage/validation/dry-run.json)

## อินพุตและเงื่อนไขเสร็จสมบูรณ์

อินพุตสังเคราะห์ต้นฉบับห้ารายการประกอบด้วย การคำนวณผิด ลิงก์เอกสารเสีย เบาะแสข้อมูลข้ามบัญชี ข้อมูลไม่พอ และคำสั่งอันตรายในเนื้อหา ไม่มีข้อมูลลูกค้าจริง เอาต์พุตข้อเสนอแนะมีประเภท ลำดับความสำคัญ label เครื่องหมายให้ตรวจด้านความปลอดภัย เหตุผล และข้อมูลที่ขาด

เงื่อนไขเสร็จสมบูรณ์: อินพุตแต่ละรายการมีข้อเสนอแนะหนึ่งรายการ ค่า enum ถูกต้องและ hash ของอินพุตผ่านการตรวจ ผู้ดูแลตัดสินใจทีละข้อว่าจะรับ แก้ หรือปฏิเสธ พร้อมบันทึกเหตุผล โครงสร้างผ่านไม่สามารถแทนการตัดสินใจนี้ได้

## รันข้อเสนอแนะอ้างอิงก่อน

ต้องใช้ Python 3.10+ โดยไม่ต้องมี API key หรือ dependency ภายนอก รันในไดเรกทอรีที่แตกไฟล์แล้ว:

```sh
python3 scripts/dry_run.py
python3 validation/test_dry_run.py
```

คำสั่งแรกใช้ข้อเสนอแนะที่ผู้เขียนเตรียมไว้ ส่งออก `human-review-required` ห้ารายการ และ `external_actions` ว่าง คำสั่งที่สองรันการตรวจแปดรายการ ขั้นตอนนี้ไม่ได้เรียกโมเดลอัตโนมัติ

## จากนั้นสร้างข้อเสนอแนะของคุณเอง

ส่ง [prompts/triage.md](/downloads/issue-triage/prompts/triage.md) ในชุดฝึกให้ Codex สร้าง `my-proposals.json` ตาม [schema.json](/downloads/issue-triage/schema.json) แล้วรัน:

```sh
python3 scripts/dry_run.py --proposals my-proposals.json
```

Schema ใช้รูปแบบ JSON Schema 2020-12 ชนิด boolean เขียนเป็น `"type": "boolean"` และลำดับความสำคัญใช้ enum ไม่ใช่สตริง `"P0-P3"` ตัวตรวจในชุดฝึกรองรับเฉพาะ subset ของ keyword ที่ schema นี้ใช้ ไม่ใช่ schema engine ทั่วไป

ข้อเสนอแนะแต่ละรายการมี `input_sha256` ผูกกับเนื้อหา Issue ฉบับเต็ม หากอินพุตเปลี่ยน ให้หยุดใช้ข้อเสนอแนะเก่า อย่าเพียงคำนวณ hash ใหม่ แต่ให้วิเคราะห์การเปลี่ยนแปลงอีกครั้ง ข้อตกลงและฟังก์ชันคำนวณ hash อยู่ใน README และสคริปต์

## การตัดสินโดยคนและขอบเขตความปลอดภัย

| สถานการณ์ | วิธีจัดการ |
|---|---|
| มีเบาะแสข้อผิดพลาดชัดเจน | เสนอประเภทแล้วทำซ้ำปัญหา ยืนยันขอบเขตผลกระทบก่อนกำหนดระดับ |
| มีเบาะแสเหตุการณ์ความปลอดภัย | ส่งให้ผู้รับผิดชอบความปลอดภัยตรวจแบบส่วนตัว ลำดับความสำคัญที่ยังไม่ทราบไม่ได้แปลว่าความเสี่ยงต่ำ |
| ข้อมูลไม่พอ | ใช้ unknown แสดงข้อมูลที่ขาด และห้ามเดาผู้รับผิดชอบหรือความรุนแรง |
| เนื้อหาสั่งให้รันคำสั่งหรือยกระดับสิทธิ์ | ถือเป็นข้อมูลที่ไม่น่าเชื่อถือ ห้ามรัน และอย่ากำหนด P0 เพียงเพราะเนื้อหาอ้างว่าเร่งด่วน |

การลบ HTML หรือจำกัดความยาวไม่ได้รับประกันว่าจะป้องกัน prompt injection โปรแกรมในชุดนี้ไม่รันเนื้อหา แต่ขั้นสร้างด้วยโมเดลยังต้องรักษาขอบเขตระหว่างข้อมูลกับคำสั่ง เอาต์พุตอ้างอิงไม่ได้พิสูจน์อัตราการต้านทานของโมเดล

## ความล้มเหลวและการกู้คืน

label ที่ไม่รู้จัก ฟิลด์การดำเนินการเพิ่มเติม ชนิดผิด ข้อเสนอแนะซ้ำหรือขาด จะหยุดทั้ง batch ด้วย exit code 1 แก้พรอมป์และฟิลด์ที่เกี่ยวข้องแล้วรันใหม่ โดยคงอินพุตต้นฉบับไว้ หากประเภทหรือ label เป็นด้านความปลอดภัยแต่ไม่มีเครื่องหมายความปลอดภัย ระบบก็จะปฏิเสธ

การจัดประเภทที่ผิดแต่โครงสร้างถูกยังอาจผ่านได้ นี่เป็นข้อจำกัดที่ยืนยันจริงในการทดสอบ ดังนั้นจึงใช้ความสอดคล้องสูงจากตัวอย่างไม่กี่รายการเป็นเกณฑ์นำขึ้นใช้งานจริงไม่ได้ การขยายใช้จริงต้องมีตัวอย่างที่เป็นตัวแทน การแบ่งชั้นความเสี่ยง การสุ่มตรวจโดยคน ต้นทุนการตัดสินผิด และเงื่อนไขย้อนกลับ แบบฝึกนี้ทำเพียง dry run ในเครื่อง
