คลังกรณีศึกษาตอบคำถามว่า “**เมื่อมีเป้าหมายจริงแบบนี้ การใช้ Codex ให้ครบกระบวนการเป็นอย่างไร**” และเสริมคำอธิบายผลิตภัณฑ์แต่ละบท

## กรณีศึกษาเทียบกับบทเรียน

| | บทเรียนเริ่มต้น | คลังกรณีศึกษา |
|---|---|---|
| เป้าหมาย | เรียนรู้ปุ่ม/แนวคิดหนึ่งอย่าง | ส่งมอบผลลัพธ์จริงประเภทหนึ่ง |
| โครงสร้าง | ตามความสามารถผลิตภัณฑ์ | ตามประเภทงาน |
| การจัดการความล้มเหลว | มักละไว้ | ต้องมี |

## วิธีใช้

1. เลือกกรณีที่ใกล้เป้าหมายที่สุด (หรือใช้เพียง “checklist เตรียมพร้อม”)
2. เทียบกับ [สำรวจ—วางแผน—ลงมือ—ยืนยันผล](/th/cases/workflows/explore-plan-execute-verify/)
3. เมื่อเสร็จแล้ว ใช้ [เทมเพลตกรณีศึกษา](/th/cases/use-cases/case-study-template/) ทบทวนและตัดสินใจว่าจะจัดเป็น Skill หรือไม่

## กรณี starter ที่มีอยู่

| ด้านงาน | กรณีศึกษา | คำอธิบาย |
|---|---|---|
| การพัฒนาซอฟต์แวร์ | [แก้ bug พร้อมการยืนยันผล](/th/cases/use-cases/software-development/fix-a-bug-with-verification/) | วงจรที่นักพัฒนาพบบ่อยที่สุด |
| การสร้างเนื้อหา | [ปรับโครงสร้างเว็บไซต์เอกสารพร้อมการตรวจ](/th/cases/use-cases/content-creation/refactor-docs-with-review/) | เอกสารหลายไฟล์และการยอมรับด้วย build |
| การวิจัยและการเรียนรู้ | [ตารางเปรียบเทียบความสามารถคู่แข่ง](/th/cases/use-cases/research-and-learning/competitive-feature-matrix/) | ผลงานวิจัยพร้อมแหล่งข้อมูล |
| ระบบอัตโนมัติของทีม | [ตรวจลิงก์เอกสารตามกำหนดเวลา](/th/cases/use-cases/team-automation/scheduled-link-check/) · [ข้อเสนอแนะคัดแยก Issue](/th/cases/use-cases/team-automation/issue-triage-suggestions/) | ระบบอัตโนมัติขนาดเล็กสำหรับ CI และ ticket |

ดูพรอมป์ที่คัดลอกได้ใน repository ที่ [`examples/prompts/`](https://github.com/hopecyb/CodexHandbook/tree/main/examples/prompts) กรณีด้านอื่นจะเพิ่มเข้าคลังนี้ต่อไป

## แนวทางการมีส่วนร่วม

- ขั้นตอนที่ทำซ้ำได้ (repository, branch, คำสั่ง)
- ระบุไคลเอนต์ที่ใช้ได้และวันที่ยืนยัน
- ไม่เขียนเรื่องเล่า “สำเร็จในครั้งเดียว” ที่ตรวจสอบไม่ได้
