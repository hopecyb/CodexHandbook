ย่อบทความให้เป็นงานนำเสนอแปดหน้า โดยส่งมอบ PPTX ที่แก้ข้อความได้ ภาพตัวอย่าง และบันทึกประกอบการบรรยาย คุณจะคงข้อจำกัดและความขัดแย้งของแหล่งข้อมูลไว้ ไม่เติมตัวเลขหรือกราฟเพียงเพื่อให้ครบหน้า

ระดับ: เริ่มต้น ใช้เวลาประมาณ 60—90 นาทีตามการประเมินของบรรณาธิการ และยังไม่ได้จับเวลาผู้อ่านจริง ข้อกำหนดเบื้องต้น: อ่านไฟล์ในเครื่องได้ และในขั้นสร้างต้องมีเครื่องมือหรือซอฟต์แวร์นำเสนอที่สร้าง PPTX ได้ ชุดเต็มมีบทความอินพุต จึงใช้ฝึกแยกต่างหากหรือทำต่อจาก[กรณีบทความ](/th/cases/write-an-article/)ก็ได้

## 1. อ่านอินพุตและกำหนดแกนเรื่อง

หลังแตกไฟล์ ให้เปิด `article-to-slides/` แล้วอ่าน `brief.md`, `input/article.md`, `input/claim-map.csv` และ `input/unresolved.md` ก่อน อย่าเริ่มจากการลอกงานอ้างอิง

```text
อ่าน brief.md รวมถึงบทความ ตารางข้อเท็จจริง และรายการที่ยังไม่ตัดสินใจใน input/
ออกแบบงานนำเสนอแปดหน้าสำหรับนักเขียนรายบุคคลที่ทดลองใช้เครื่องมือจัดระเบียบบันทึกเป็นครั้งแรก โดยตั้งเป้าประมาณห้านาที
เขียนข้อสรุปหนึ่งประโยค ประเด็นสำคัญ และหมายเลขแหล่งข้อมูลของแต่ละหน้า ลงใน my-output/outline.md
คงสถานะสมมติ ข้อจำกัดของรูปแบบที่รองรับ และข้อขัดแย้งเรื่องการตั้งค่าการวินิจฉัย
ห้ามแต่งข้อมูลความแม่นยำ ราคา หรือเวลาที่ประหยัดได้ และแยกคำแนะนำของผู้เขียนออกจากข้อเท็จจริงของผลิตภัณฑ์
```

เงื่อนไขเสร็จสมบูรณ์: บทบาทครบทั้งแปดหน้า แต่ละหน้ามีประเด็นเดียว และข้อเท็จจริงแต่ละรายการระบุตำแหน่งกลับไปยังหัวข้อในแหล่งข้อมูลได้ ห้านาทีเป็นเพียงเป้าหมาย ไม่ใช่การซ้อมบรรยายที่ทำเสร็จแล้ว พรอมป์ฉบับเต็มอยู่ที่ `prompts/01-outline.md` ในชุดฝึก

## 2. ตรวจเลย์เอาต์ด้วยสไลด์ตัวอย่างสองหน้า

ทำหน้าชื่อเรื่องและหน้าข้อจำกัดซึ่งเป็นหน้าที่หกก่อน หน้าแรกใช้ตรวจหัวเรื่องขนาดใหญ่ ส่วนหน้าที่หกใช้ตรวจเนื้อหาที่หนาแน่นที่สุด รูปแบบอ้างอิงใช้สีน้ำเงินเข้ม สีขาวนวล และข้อความจริง โดยไม่จำเป็นต้องเพิ่มของตกแต่ง

```text
ใช้โครงสไลด์แปดหน้าที่ตกลงแล้ว ทำตัวอย่างหน้า 1 และหน้า 6 ก่อน
ใช้อัตราส่วน 16:9 เนื้อหาเป็นกล่องข้อความจริง และเลือกฟอนต์ภาษาจีนที่มีในสภาพแวดล้อมปัจจุบัน
ในหน้า 6 ให้คงทั้ง P3 “ปิดเป็นค่าเริ่มต้น” และ C2 “เปิดเป็นค่าเริ่มต้นในการติดตั้งใหม่” พร้อมระบุว่ายังไม่ยืนยัน
render แล้วตรวจภาษาจีน การตัดบรรทัด ระยะขอบ และความอ่านง่ายของแหล่งข้อมูล เมื่อเลย์เอาต์ผ่าน ให้ทำอีกหกหน้าที่เหลือต่อเนื่อง
เขียน PPTX ภาพตัวอย่างทั้งแปดหน้า คำอธิบายรายหน้า และบันทึกการยืนยันลง my-output/
```

งานอ้างอิงใช้ Arial Unicode MS หากระบบของคุณไม่มีฟอนต์นี้ ให้เลือกฟอนต์ภาษาจีนที่ใช้งานได้อย่างถูกต้องและตรวจเลย์เอาต์ใหม่ หากเครื่องมือสร้าง PPTX ไม่ได้ คุณส่งโครงสไลด์ก่อนพร้อมระบุความสามารถที่ขาดได้ แต่มีเพียงโครงสไลด์ยังไม่ถือว่าทำแบบฝึกนี้เสร็จ

## 3. ตรวจความแก้ไขได้ เลย์เอาต์แปดหน้า และแหล่งข้อมูล

เปิด PPTX ที่สร้างในซอฟต์แวร์นำเสนอ บันทึกเป็นสำเนาทดสอบ เลือกข้อความสำคัญแล้วแก้ บันทึกและเปิดใหม่ จากนั้น export ภาพตัวอย่างทีละหน้า ตรวจข้อความจีน การตัดบรรทัด การบังกัน จำนวนหน้า และบันทึกประกอบ ห้ามใช้ภาพเต็มหน้าสไลด์แปดภาพแทนงานที่แก้ไขได้

งานอ้างอิงผ่านการ import และ export ด้วย LibreOffice แบบ headless ในสำเนา PPTX ชั่วคราว มีการแก้ชื่อเรื่องที่เป็นข้อความจริงจาก “一份” เป็น “两份” และอ่านข้อความที่เปลี่ยนได้หลัง export ใหม่ การตรวจนี้ไม่เท่ากับการคลิกแก้ผ่าน GUI และไม่ได้พิสูจน์ว่าซอฟต์แวร์ทุกตัวจะแสดงผลเหมือนกัน

![สไลด์อ้างอิงหน้าที่หก: วางค่าเริ่มต้นที่ขัดกันจากแหล่งข้อมูลสองชุดไว้คู่กัน และระบุชัดว่ายังไม่ยืนยันข้อสรุป](/downloads/article-to-slides/previews/slide-06.png)

หน้าที่หกเป็นจุดตรวจข้อเท็จจริงสำคัญ ห้ามลบข้อขัดแย้งด้านใดด้านหนึ่งหรือเปลี่ยนเป็น “ปิดเป็นค่าเริ่มต้น” เพื่อให้ข้อสรุปเรียบง่ายขึ้น คอลัมน์ซ้ายของหน้าที่ห้าเป็นกรณีผิดที่ผู้เขียนออกแบบ ต้องแยกจากถ้อยคำที่ถูกต้องในคอลัมน์ขวา แหล่งข้อมูลโดยละเอียดอยู่ในบันทึกของ PPTX และ `solution/slide-notes.md`

## 4. ตรวจไฟล์อ้างอิงและบันทึกการยืนยันของคุณ

รันคำสั่งต่อไปนี้ในไดเรกทอรีชุดฝึกฉบับเต็ม เพื่อตรวจว่าไฟล์อ้างอิงที่ดาวน์โหลดมาครบถ้วน (Python 3.10+ และใช้เฉพาะ standard library):

```sh
python3 validation/check.py
```

คำสั่งนี้ตรวจ hash ของไฟล์อ้างอิงในชุด จำนวนแปดหน้า ข้อความจริง บันทึกประกอบ และภาพตัวอย่าง ไม่ได้ตรวจงานใหม่ที่คุณสร้างใน `my-output/` งานใหม่ต้องตรวจในซอฟต์แวร์นำเสนอตามหัวข้อก่อนหน้า พร้อมบันทึกเวอร์ชันซอฟต์แวร์ ฟอนต์ ผลตรวจ และข้อจำกัดที่เหลือ

หากรันสคริปต์ไม่ได้ ยังเปิด PPTX/PDF ตรวจทีละหน้าได้ แต่อย่าอ้างว่าตรวจ hash หรือโครงสร้างแล้ว [บันทึกการยืนยัน](/downloads/article-to-slides/validation/record.md) ของงานอ้างอิงระบุขอบเขตที่รันจริง

## วิธีกู้คืนเมื่อเกิดปัญหา

| อาการ | ขั้นถัดไป | หลักฐานว่ากู้คืนสำเร็จ |
|---|---|---|
| ตัวอักษรจีนกลายเป็นสี่เหลี่ยม | ตรวจว่าโปรเซส render อ่านฟอนต์จีนได้หรือไม่ และเปลี่ยนฟอนต์ในสำเนาหากจำเป็น | render ทั้งแปดหน้าใหม่และอ่านภาษาจีนได้ |
| ข้อความล้นหลังเปลี่ยนฟอนต์ | ลดข้อความต่อหน้า ปรับกล่องข้อความและพื้นที่ว่าง โดยคงข้อจำกัดสำคัญ | ภาพตัวอย่างทุกหน้าไม่มีการตัดหรือซ้อนทับ |
| เลือกข้อความแยกไม่ได้ | กลับไปสร้างด้วยวัตถุข้อความจริง อย่าวาง PNG เต็มหน้า | เลือก แก้ บันทึก และเปิดข้อความใหม่ในซอฟต์แวร์ได้ |
| ข้อขัดแย้งของแหล่งข้อมูลถูก “เกลา” จนหาย | ตรวจ P3, C2 และ C3 แล้วคืนข้อความทั้งสองด้านพร้อมป้ายว่ายังไม่ยืนยัน | หน้าที่หกตรงกับตารางข้อเท็จจริง |
| เปิดไฟล์ไม่ได้หรือจำนวนหน้าผิด | export ใหม่แล้ว import ในซอฟต์แวร์นำเสนอ และเก็บไฟล์ที่ล้มเหลวไว้เพื่อวินิจฉัย | มีครบแปดหน้าและซอฟต์แวร์เปิดได้ตามปกติ |

ปัญหาแรกเกิดขึ้นจริงระหว่างงานนี้: ตอนแรก LibreOffice อ่านฟอนต์จีนของระบบไม่ได้ หลังระบุไดเรกทอรีฟอนต์ให้โปรเซส render ตัวอักษรจีนกลับมา และทั้งแปดหน้าผ่านการตรวจใหม่ หน้าที่ตัวอักษรหายไม่ได้ถูกใช้เป็นภาพตัวอย่างสุดท้าย

## เงื่อนไขเสร็จสมบูรณ์และขั้นถัดไป

- PPTX แปดหน้าเปิดได้ในสภาพแวดล้อมซอฟต์แวร์ที่คุณบันทึกไว้ และแก้ข้อความสำคัญได้
- มีภาพตัวอย่างครบแปดหน้า พร้อมตรวจภาษาจีน การตัดบรรทัด และขอบเขตทีละหน้า
- แหล่งข้อมูล สถานะสังเคราะห์ คำแนะนำของผู้เขียน และข้อขัดแย้งที่ยังไม่คลี่คลายยังมองเห็นชัด
- บันทึกการยืนยันแยกชัดว่าตรวจอะไรแล้วและไม่ได้ตรวจอะไร และผลงานยังอยู่ในเครื่อง
