เมื่อเพิ่งรู้จัก Skill คำถามที่พบบ่อยคือ งานนี้คุ้มค่าที่จะทำเป็น Skill โดยเฉพาะหรือไม่

หากทำทุกอย่างเป็น Skill ระบบจะหนักขึ้นเรื่อย ๆ แต่หากไม่บันทึกสิ่งที่ควรบันทึก ก็ต้องอธิบายเรื่องเดิมด้วยตนเองซ้ำ ๆ หน้านี้ช่วยตัดสินว่าเมื่อใดควรทำให้ workflow เป็นมาตรฐาน

![ภาพประกอบ: สายพานส่งการ์ดงานไปยังทางแยก งานที่เกิดซ้ำ ชัดเจน และมีหลายขั้นเข้าสู่กล่องเครื่องมือเรืองแสง ส่วนงานครั้งเดียวที่คลุมเครือเข้าสู่ฟองสนทนาทั่วไป](/illustrations/skills-when.webp)

## เหมาะจะบรรจุเป็น Skill

- ทำ workflow เดิมด้วยตนเองเป็นครั้งที่สาม
- ต้องใช้รายการตรวจสอบละเอียด แต่ไม่อยากให้กินบริบททุกครั้ง
- ต้องการให้โมเดลตัดสินจาก `description` โดยอัตโนมัติว่าเมื่อใดควรเปิดใช้
- ทีมต้องแชร์และกำหนดเวอร์ชัน workflow

## เงื่อนไขที่เหมาะจะทำเป็น Skill

หากงานหนึ่งตรงกับทั้งสองข้อต่อไปนี้ ก็ควรพิจารณาทำเป็น Skill:

- คุณจะทำงานนี้อีกในอนาคต
- คุณต้องการให้ครั้งต่อไปทำด้วยวิธีที่สอดคล้องกัน

Skill จำนวนมากมักอยู่ในสถานการณ์ต่อไปนี้:

- ตรวจ diff
- สร้าง changelog
- ตรวจก่อน release
- workflow เผยแพร่เอกสาร

งานเหล่านี้ไม่ซับซ้อน แต่เหมาะกับการนำกลับมาใช้

## ไม่ค่อยเหมาะ

- งานครั้งเดียวที่ไม่เคยเกิดซ้ำ
- คำสั่งตายตัวที่สั้นมากและคุณจำได้ (พิจารณาคำสั่ง slash)
- ต้องใช้สถานะระบบภายนอกแบบเรียลไทม์ที่เปลี่ยนเร็วมาก (พิจารณา MCP)

## ความเข้าใจผิดที่พบบ่อย

### 1. งานสำคัญทุกงานควรทำเป็น Skill

ความสำคัญไม่ได้แปลว่าเหมาะกับการนำกลับมาใช้  
หากเป็นงานพิเศษครั้งเดียว การทำเป็น Skill อาจเพิ่มภาระดูแลเท่านั้น

### 2. Skill ยิ่งมากยิ่งดี

Skill ที่มีขอบเขตคลุมเครือจำนวนมากทำให้โมเดลเลือกใช้ผิดและทีมดูแลยากขึ้น

### 3. หากเชื่อมระบบภายนอกได้ ก็ควรเริ่มจาก Skill

การเชื่อมระบบภายนอกมักเป็นเรื่องของ MCP มากกว่า Skill รับผิดชอบ “workflow” ส่วนวิธีเชื่อมต่อระบบภายนอกยังต้องพึ่ง MCP

## วิธีทดลอง

หากยังไม่แน่ใจว่า workflow หนึ่งคุ้มค่าที่จะบันทึกหรือไม่ ให้ลองดังนี้สองสามครั้ง:

1. ทำด้วยตนเองสองถึงสามครั้ง
2. สังเกตว่าทุกครั้งกำลังทำซ้ำลำดับตรวจสอบชุดเดิมหรือไม่
3. หากคำตอบคือ “ใช่” จึงค่อยรวบเป็น Skill

Skill ที่ได้จะมั่นคงกว่า เพราะเกิดจากงานซ้ำจริง ไม่ใช่ออกแบบขึ้นลอย ๆ

## เปรียบเทียบกับวิธีขยายอื่น

| วิธี | เหมาะกับ |
|---|---|
| Skill | workflow ที่นำกลับมาใช้ได้และการเปิดเผยแบบค่อยเป็นค่อยไป |
| MCP | เชื่อม API และแหล่งข้อมูลภายนอก |
| Hooks | ทำงานอัตโนมัติ ณ จุดเหตุการณ์ที่กำหนด |
| `AGENTS.md` | ข้อตกลงถาวรระดับโปรเจกต์ |

Skill เหมาะกับการบันทึก workflow ที่ “เกิดซ้ำ ต้องสอดคล้องกัน และไม่อยากอธิบายใหม่ทุกครั้ง”
