กลไกส่วนขยายสับสนได้ง่าย เพราะมักปรากฏใน workflow เดียวกัน แต่ไม่ได้แก้ปัญหาประเภทเดียวกัน

หน้านี้เริ่มจากแผนผังระบบ: พรอมป์และ `AGENTS.md` ให้งานกับกฎ, Skill ให้ workflow ที่นำกลับมาใช้ได้, MCP ให้เครื่องมือภายนอก, Hook เฝ้าระวังจุดต่าง ๆ ในวงจรชีวิต, Plugin รวมและแจกจ่ายความสามารถ และ Scheduled task ทริกเกอร์ตามเวลา กลไกเหล่านี้ใช้ร่วมกันได้ และไม่มี “ลำดับการยกระดับ” ตายตัว

## สถาปัตยกรรมระบบ

![สถาปัตยกรรมระบบงานที่นำกลับมาใช้ได้ของ Codex](/illustrations/arch-work-system.webp)

เมื่ออ่านภาพ ให้จับสามประเด็น:

- **อินพุตงาน** กำหนดว่าครั้งนี้ต้องทำอะไร ส่วนกฎโปรเจกต์กำหนดสิ่งที่ต้องปฏิบัติทุกครั้ง
- **ความสามารถในการลงมือ** ขยายขอบเขตได้ แต่ไม่ได้พิสูจน์โดยอัตโนมัติว่าผลลัพธ์ถูกต้อง MCP, Agent ย่อย และสคริปต์ล้วนต้องอยู่ภายใต้สิทธิ์และเกณฑ์การยอมรับ
- **การแจกจ่ายและการทริกเกอร์** ไม่ใช่ตัว workflow Plugin รวมความสามารถเข้าด้วยกัน ส่วน Scheduled task เริ่มการรันหนึ่งครั้งตามเวลาที่กำหนด

## หน้าที่แปดประเภท

| หน้าที่ | กลไก | เหมาะที่สุดสำหรับ | ไม่รับผิดชอบ |
|---|---|---|---|
| งานปัจจุบัน | พรอมป์ | ครั้งนี้ต้องทำอะไร ขอบเขตและเกณฑ์การยอมรับ | กฎโปรเจกต์ระยะยาว |
| กฎถาวร | `AGENTS.md` | คำสั่งของรีโพซิทอรี ข้อตกลง และขอบเขตไดเรกทอรี | ขั้นตอนทั้งหมดของงานประเภทหนึ่ง |
| workflow ที่นำกลับมาใช้ได้ | Skill | ขั้นตอนที่เสถียร เอกสารอ้างอิง เทมเพลต และสคริปต์ช่วย | ได้สิทธิ์ระบบภายนอกขึ้นมาเอง |
| เครื่องมือภายนอก | MCP / Connector | ให้ Codex เรียกข้อมูลและการกระทำนอกรีโพซิทอรี | ตัดสินว่าเป้าหมายธุรกิจถูกต้องหรือไม่ |
| การเฝ้าระวังวงจรชีวิต | Hook | บันทึก ตรวจ เพิ่มบริบท หรือบล็อกก่อนและหลัง session หรือการเรียกเครื่องมือ | แทนการทดสอบและการตรวจโดยมนุษย์ |
| การรวมและแจกจ่าย | Plugin | แพ็ก Skills, connectors, MCP, Hooks และเทมเพลตงาน | ทำให้ทุกความสามารถน่าเชื่อถือโดยอัตโนมัติ |
| การทริกเกอร์ตามเวลา | Scheduled task | รันงานที่ผ่านการตรวจแล้วตามเวลาหรือเป็นคาบ | แทนพรอมป์และเงื่อนไขจบที่ชัดเจน |
| การแบ่งงานขนาน | Agent ย่อย | แยกงานสำรวจ ทดสอบ หรือตรวจทานที่เป็นอิสระต่อกัน | ขจัด write conflict และต้นทุนประสานงานโดยอัตโนมัติ |

## งานหนึ่งใช้ความสามารถเหล่านี้ร่วมกันอย่างไร

สมมติว่าทีมตรวจความเสี่ยงของ dependency ทุกสัปดาห์:

1. `AGENTS.md` ระบุ package manager ที่อนุญาต คำสั่งทดสอบ และไดเรกทอรีที่ห้ามแก้
2. Skill `dependency-audit` กำหนดขั้นตอนรวบรวม dependency ตรวจประกาศ จัดระดับ และตรวจสอบ
3. GitHub หรือ MCP ของแหล่งแพ็กเกจให้ข้อมูลภายนอก โดยให้สิทธิ์อ่านอย่างเดียวก่อน
4. Hook สามารถป้องกันผลลัพธ์ที่มี secret จริง หรือบันทึกการเรียกเครื่องมือภายนอก
5. Plugin แจก Skill, การตั้งค่า MCP และ Hook ให้ทีมพร้อมกัน
6. Scheduled task ทริกเกอร์สัปดาห์ละครั้ง โดยสร้างเฉพาะรายงานหรือ draft issue และให้มนุษย์ตรวจก่อนเผยแพร่

การขาดชั้นใดชั้นหนึ่งไม่ได้หมายความว่าแนวทาง “ไม่ขั้นสูง” หากตรวจ dependency ในเครื่องเพียงครั้งเดียว พรอมป์ที่ชัดเจนกับคำสั่งเทอร์มินัลเดิมอาจเพียงพอแล้ว

## ความต้องการที่พบบ่อยและกลไกที่ตรงกัน

| ความต้องการ | ตัวเลือกที่แนะนำ |
|---|---|
| ทำให้สไตล์โค้ดและคำสั่งทดสอบเป็นมาตรฐาน | AGENTS.md |
| ทำ workflow “ตรวจ PR” ให้เป็นมาตรฐาน | Skill |
| อ่าน ticket จาก Jira/Linear | MCP |
| ให้ทั้งทีมติดตั้ง integration ชุดเดียวกัน | Plugin |
| สแกน secret ก่อน commit ทุกครั้ง | Hooks |
| สร้าง draft รายงานประจำสัปดาห์อัตโนมัติทุกวันจันทร์ | Automations (+ เผยแพร่โดยมนุษย์) |

## จากความสำเร็จครั้งเดียวสู่ทรัพยากรของทีม

ใช้ลำดับต่อไปนี้ตัดสินว่าควรบันทึกต่อหรือไม่:

| ระยะ | รูปแบบ | เหมาะกับสถานการณ์ใด |
|---|---|---|
| พรอมป์ครั้งเดียว | คำอธิบายงานในบทสนทนาปัจจุบัน | ทำครั้งเดียว หรือยังสำรวจปัญหาอยู่ |
| เทมเพลต | โครงตายตัว “เป้าหมาย บริบท ข้อจำกัด เกณฑ์การยอมรับ” | งานประเภทเดียวกันจะเกิดซ้ำ แต่ขั้นตอนยังปรับอยู่ |
| Skill | `SKILL.md` พร้อมเทมเพลต เอกสารอ้างอิง หรือสคริปต์ | workflow เสถียรและเกณฑ์ความสำเร็จชัดเจน |
| Plugin | แพ็กรวม Skills, connectors, MCP, Hooks และเทมเพลต | ต้องติดตั้ง อัปเดต และกำกับดูแลแบบเดียวกัน |
| Scheduled task | งานที่บันทึกไว้ กฎเวลา และบันทึกการรัน | ผ่านการตรวจด้วยตนเองแล้วและคุ้มค่าที่จะรันเป็นคาบ |

MCP, Hook และ Agent ย่อยไม่ใช่ขั้นที่จำเป็นบนบันไดการบันทึกนี้ เพิ่มเฉพาะเมื่องานต้องใช้เครื่องมือภายนอก การเฝ้าระวังวงจรชีวิต หรือการแบ่งงานขนานจริง ๆ

ดูตรรกะการเลือกโดยละเอียดที่ [วิธีเลือกส่วนขยาย](/th/skills/choosing-an-extension-method/)

## ขอบเขตผลิตภัณฑ์ปัจจุบัน

- Codex Skills นิยามด้วยไดเรกทอรีที่มี `SKILL.md` และอาจแนบสคริปต์ เอกสารอ้างอิง และ asset ได้ Codex โหลดคำอธิบายฉบับเต็มเมื่อต้องการ
- Desktop App, Codex CLI และ IDE extension แชร์การตั้งค่า MCP บน Codex host เดียวกัน
- ปัจจุบัน Plugins ใช้ได้ในจุดเข้าของ ChatGPT ที่รองรับ ประสบการณ์ Codex บนเดสก์ท็อป และ Codex CLI ส่วน IDE extension ไม่รองรับการเรียกดูและใช้ Plugin
- Scheduled task สร้างและจัดการจาก ChatGPT Web หรือ Desktop App ส่วน CLI และ IDE ช่วยทดสอบพรอมป์ Skill หรือสคริปต์ล่วงหน้าได้ แต่ไม่มีอินเทอร์เฟซจัดการ Scheduled task
- Agent ย่อยเหมาะกับงานสำรวจแบบอ่านอย่างเดียว การทดสอบ และการตรวจทานที่เป็นอิสระ การเขียนไฟล์ชุดเดียวกันพร้อมกันเพิ่มต้นทุนความขัดแย้ง

จุดเข้าของผลิตภัณฑ์ยังอาจเปลี่ยนแปลง ก่อนตั้งค่าจริง โปรดตรวจ [ตารางเปรียบเทียบฟีเจอร์](/th/guide/reference/feature-comparison/) และหลักฐานทางการด้านล่างต่อไป
