## คำถามและวัสดุคงที่

แพ็กเกจนี้ใช้เครื่องมือสมมติ “拾页” จาก [แบบฝึกหัดบทความ](/th/cases/write-an-article/) เพื่อวิจัยรูปแบบอินพุต การตั้งค่าเริ่มต้นของข้อมูลวินิจฉัย และฟิลด์อัปโหลด ข้อมูลสังเคราะห์ต้นฉบับสามชุดรวมอยู่ในแพ็กเกจ ส่วนคำอธิบายจากผู้ดูแลชุดที่สี่ในรายการตั้งใจให้ขาดหาย อย่าค้นหน้าเว็บจริงหรือแต่งคำตอบให้ผลิตภัณฑ์สมมตินี้

| สถานะหลักฐาน | ตัวอย่างในแพ็กเกจ | วิธีส่งมอบ |
|---|---|---|
| supported: ข้อมูลรองรับ | P1 ระบุเพียง Markdown และ plain text | ระบุขอบเขตและตำแหน่งที่รองรับ โดยไม่อ้างว่าทดสอบผลิตภัณฑ์จริงแล้ว |
| conflict: ขัดแย้ง | P3 ระบุว่าปิดเป็นค่าเริ่มต้น ส่วน C2 ระบุว่าเปิด | แสดงทั้งสองด้าน พร้อมคงช่องว่างด้านเวอร์ชันและเงื่อนไข |
| unknown: ไม่ทราบ | ไม่ได้ระบุฟิลด์อัปโหลดข้อมูลวินิจฉัย | ระบุสิ่งที่ขาด โดยไม่เดาเนื้อหาที่อัปโหลด |
| unavailable: แหล่งข้อมูลใช้ไม่ได้ | ไม่มีไฟล์ในเครื่องที่ตรงกับ M | คงแหล่งข้อมูลที่ล้มเหลวและผลกระทบไว้ โดยไม่แสร้งว่าอ่านแล้ว |

## ติดตั้งและเรียกใช้

วางไดเรกทอรีทั้งหมดใน `.agents/skills/evidence-research/` ของโปรเจกต์ฝึก ยืนยันว่าจุดเข้าคือ `SKILL.md` และอย่าเขียนทับ Skill กำหนดเองชื่อเดียวกัน เมื่อยืนยันตาม [ใช้ Skill](/th/skills/use-a-skill/) ว่าเลือกในไคลเอนต์ได้แล้ว ให้เรียก:

```text
$evidence-research ใช้ข้อมูลใน sources/catalog.json ของแพ็กเกจนี้
เพื่อตัดสินว่าสามารถยืนยันขอบเขตอินพุต การตั้งค่าเริ่มต้นของข้อมูลวินิจฉัย และฟิลด์อัปโหลดของ 拾页 1.2 ได้หรือไม่
ส่งออก my-output/report.md และ evidence.csv โดยระบุข้อมูลขัดแย้งและแหล่งข้อมูลที่เปิดไม่ได้อย่างชัดเจน
คงอัตลักษณ์สังเคราะห์ไว้ และอย่าค้นหน้าเว็บจริงของผลิตภัณฑ์สมมติ
```

กรณีทริกเกอร์ทั้งบวกและลบอยู่ใน `fixtures/trigger-cases.json` ของแพ็กเกจ การเปรียบเทียบแหล่งข้อมูลและตรวจหลักฐานเหมาะสม ส่วนบทกวีสร้างสรรค์และการนับไฟล์อย่างง่ายไม่ต้องใช้ workflow วิจัย นี่เป็นสิ่งที่คาดจากการออกแบบและยังไม่ได้วัดการทริกเกอร์อัตโนมัติ

## ตรวจแหล่งข้อมูลและรายงาน

การตรวจแบบไม่บังคับต้องใช้ Python 3.10+ และไม่มี dependency ภายนอก รันในไดเรกทอรีที่แตกไฟล์แล้ว:

```sh
# แสดงสถานะจริงของแต่ละแหล่งข้อมูล
python3 scripts/check_evidence.py --inspect-only
# ตรวจรายงานอ้างอิง
python3 scripts/check_evidence.py
# ตรวจรายงานที่สร้างตามข้อตกลงในแพ็กเกจ
python3 scripts/check_evidence.py --output my-output
# รันการทดสอบย้อนหลังในสำเนาชั่วคราว
python3 validation/test_checks.py
```

ผลอ้างอิงปกติคือ P/I/C เป็น `available`, M เป็น `missing` และโครงสร้างหลักฐานสี่รายการผ่าน exit code 0 หมายถึงการตรวจเสร็จและตรงตามโครงสร้าง ไม่ได้หมายความว่าแหล่งข้อมูลทั้งหมดใช้ได้ โดยเฉพาะเมื่อใช้โหมดตรวจแหล่งข้อมูลอย่างเดียว ต้องอ่าน status ทีละรายการ

ตัวตรวจจะระบุไฟล์ที่แฮชเนื้อหาเปลี่ยน ขาดหาย อ่านไม่ได้ หรือไม่มีแฮชที่คาดไว้ แหล่งข้อมูลที่ใช้ไม่ได้ห้ามนำมาเป็นหลักฐานว่าอ่านแล้ว และห้ามหายไปจากรายงานโดยไม่มีคำอธิบาย สคริปต์จัดการเฉพาะไฟล์ในเครื่อง ไม่ได้ทดสอบสถานะ HTTP หรือการเข้าถึงหน้าเว็บ

## วิธีฟื้นตัวหลังล้มเหลว

- **ไฟล์ขาดหาย**: ตรวจ path หากไม่ได้ให้ข้อมูลมาจริง ให้คงสถานะ unavailable และส่งข้อสรุปส่วนอื่นที่มีหลักฐาน
- **เนื้อหาเปลี่ยน**: เปรียบเทียบเวอร์ชันและ diff แล้วตรวจการอ้างอิงใหม่ อย่าเพียงอัปเดตแฮชให้การตรวจผ่าน
- **หลักฐานขัดแย้ง**: ตรวจเวอร์ชัน เงื่อนไขติดตั้ง และกลุ่มที่ใช้ หากแก้ไม่ได้ให้คงเป็นเรื่องค้าง อย่าเลือกคำตอบจากวันที่เพียงอย่างเดียว
- **ขาดข้อเท็จจริง**: ระบุฟิลด์หรือคำอธิบายที่ต้องขอจากผู้ดูแล อย่าเขียนคำแนะนำเป็นข้อเท็จจริงที่ยืนยันแล้ว

ตัวอย่างนี้ไม่บังคับให้แก้คำถามที่ไม่มีคำตอบในอินพุตคงที่ งานวิจัยจริงที่ได้รับอนุญาตให้หาแหล่งทดแทนต้องบันทึกเหตุผลที่แทนที่และผลการเข้าถึงจริง

## เงื่อนไขว่าเสร็จและข้อจำกัด

รายงานควรครอบคลุมคำถามวิจัย แหล่งที่อ่าน แหล่งที่ล้มเหลว หลักฐานรายข้อ และขั้นถัดไปในการหาหลักฐาน ผู้เขียนตรวจรายงานอ้างอิงเทียบกับข้อมูลคงที่แล้ว แต่ไม่มีผู้อ่านอิสระหรือผู้ตรวจคนที่สองยืนยัน

การทดสอบสคริปต์แปดรายการยังตรวจจุดบอดหนึ่งอย่าง: ข้อความเท็จว่า “รองรับทุก format และแม่นยำสมบูรณ์” ยังผ่านการตรวจโครงสร้างได้เมื่อคงการอ้างอิงที่ถูกต้อง ดังนั้นสคริปต์พิสูจน์ไม่ได้ว่าเนื้อหามีแหล่งรองรับ และตัดสินไม่ได้ว่าข้อความสองส่วนขัดแย้งกันจริงหรือไม่ ก่อนส่งมอบยังต้องอ่านต้นฉบับทีละรายการ
