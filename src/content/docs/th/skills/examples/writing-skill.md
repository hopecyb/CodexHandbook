Skill นี้เปลี่ยนข้อมูลที่ให้มาเป็นบทความที่ย้อนตรวจได้ พร้อมคงข้อกำหนดด้านสไตล์ หลักฐานข้อเท็จจริง และเรื่องที่ยังไม่ยืนยัน เหมาะกับงานเขียนจากแหล่งข้อมูลและการตรวจข้อเท็จจริง ส่วนการแก้ typo หนึ่งจุดไม่ต้องใช้ workflow เต็ม

[ดาวน์โหลด source-backed-writer v1.0.0 ฉบับเต็ม](/downloads/skills/source-backed-writer/source-backed-writer-1.0.0.zip) · [ดู SKILL.md](/downloads/skills/source-backed-writer/SKILL.md) · [คำแนะนำการติดตั้ง](/downloads/skills/source-backed-writer/README.md)

## มีอะไรในแพ็กเกจ

| วัสดุ | การใช้งาน |
|---|---|
| ข้อมูลสังเคราะห์สามชุดและดัชนีแฮช | ฝึกด้วยอินพุตคงที่ โดยไม่ถือผลิตภัณฑ์สมมติเป็นข้อมูลเลือกซื้อจริง |
| ตัวอย่างสไตล์และตัวอย่างที่ออกแบบให้ไม่ดี | ดูวิธีแทนคำรับรองผลลัพธ์ที่ไร้หลักฐานด้วยการกระทำที่เจาะจง |
| โครงร่าง draft แรก draft สุดท้าย และ revision diff | เห็นการเปลี่ยนข้อเท็จจริง โครงสร้าง และถ้อยคำแยกกัน |
| การแมปข้อเท็จจริงเจ็ดรายการและรายการเรื่องค้าง | แยกสิ่งที่ต้นฉบับรองรับ การอนุมานของผู้เขียน และสิ่งที่ยังไม่ยืนยัน |
| กรณีทริกเกอร์ทั้งบวกและลบ สคริปต์ และบันทึกตรวจสอบ | ระบุขอบเขตการใช้งานและข้อจำกัดของการตรวจ |

วัสดุใช้เครื่องมือสมมติ “拾页” จาก [แบบฝึกหัดบทความจากแหล่งข้อมูล](/th/cases/write-an-article/) คุณสามารถทำแบบฝึกหัดบทความให้เสร็จก่อน แล้วใช้ Skill บันทึกวิธีเขียนชุดนี้

## ติดตั้งและเรียกใช้ครั้งแรก

วางไดเรกทอรีทั้งหมดไว้ที่ `.agents/skills/source-backed-writer/` ของโปรเจกต์ฝึก โดยให้ `SKILL.md` อยู่ชั้นแรก หากมี Skill ชื่อเดียวกัน ให้เปรียบเทียบก่อนและอย่าเขียนทับ ดูกลไกการค้นพบที่ [ใช้ Skill](/th/skills/use-a-skill/) เมื่อยืนยันในไคลเอนต์ว่าเลือกใช้ได้แล้ว ให้เรียกอย่างชัดเจน:

```text
$source-backed-writer อ่านข้อมูลสามชุดใน sources/ ของแพ็กเกจสอนนี้
แล้วเขียนบทแนะนำสำหรับนักเขียนรายบุคคลตาม references/style.md โดยส่งออกไปที่ my-output/
ส่งมอบ article.md, claim-map.csv และ unresolved.md
คงอัตลักษณ์สังเคราะห์ไว้และห้ามเผยแพร่
```

การอ่านและเขียนไม่ต้องใช้ Python การตรวจโครงสร้างแบบไม่บังคับใช้เพียง standard library ของ Python 3.10+ รันจากไดเรกทอรี Skill ที่แตกไฟล์แล้ว:

```sh
# ตรวจ draft อ้างอิงที่มากับแพ็กเกจ
python3 scripts/check_article.py
# ตรวจ draft ของคุณตามรูปแบบแพ็กเกจนี้
python3 scripts/check_article.py --output my-output
# ทำซ้ำการตรวจแปดรายการในสำเนาชั่วคราว
python3 validation/test_checks.py
```

หน้านี้รันสคริปต์จริง แต่ไม่ได้ตรวจการค้นพบอัตโนมัติหรือการเรียกโมเดลในไคลเอนต์ใดโดยเฉพาะ งานจริงที่ใช้รูปแบบผลลัพธ์ของตนเองควรตรวจตามข้อตกลงของตน ไม่จำเป็นต้องเปลี่ยนเป็นรูปแบบของแพ็กเกจสอน

## จัดการข้อมูลขัดแย้งและข้อมูลขาดหายอย่างไร

คำอธิบายผลิตภัณฑ์ P3 ระบุว่าการอัปโหลดข้อมูลวินิจฉัยปิดไว้เป็นค่าเริ่มต้น แต่สรุปเวอร์ชัน C2 ระบุว่าการติดตั้งใหม่เปิดไว้เป็นค่าเริ่มต้น draft สุดท้ายระบุข้อมูลขัดแย้งทั้งสองด้าน โดยไม่ถือว่าฉบับที่วันที่ใหม่กว่าถูกต้อง ฟิลด์ที่อัปโหลดไม่ได้ระบุไว้ จึงคงอยู่ใน [รายการเรื่องค้าง](/downloads/skills/source-backed-writer/solution/unresolved.md)

บทสัมภาษณ์สังเคราะห์ไม่มีข้อมูลเวลาและชุดตัวอย่างประเมินคงที่ จึงเขียนว่า “มีประสิทธิภาพเป็นสองเท่า” หรือคำนวณความแม่นยำไม่ได้ วิธีแก้คือเอาตัวเลขไร้หลักฐานออก ใส่เงื่อนไขกำกับกลับคืน และอัปเดตตารางข้อเท็จจริง ไม่ใช่ค้นหาคำตอบที่ดูน่าเชื่อถือให้ผลิตภัณฑ์สมมติ

## เกณฑ์การยอมรับและข้อจำกัดของการตรวจ

หลังเขียนเสร็จ ให้ตรวจทีละข้อ:

- ข้อเท็จจริงหลักมีตำแหน่งให้ย้อนตรวจได้ และแยกข้อเท็จจริง คำแนะนำ กับสิ่งที่ไม่ทราบ
- อัตลักษณ์สังเคราะห์ ข้อจำกัดอินพุต และความขัดแย้งที่ยังไม่คลี่คลายยังอยู่ในเนื้อหา
- การแก้สไตล์ไม่ลบเงื่อนไขจำเป็นหรือเปลี่ยนโครงสร้างที่ผู้ใช้ขอ
- หลังรูปแบบอ้างอิงผ่าน ให้เทียบแต่ละประโยคกับต้นฉบับ ไม่ใช่ตรวจเพียงว่ามี ID

สคริปต์ตรวจพบการเปลี่ยนแฮชต้นฉบับและโครงสร้างอ้างอิงผิด แต่ตัดสินไม่ได้ว่าแหล่งข้อมูลรองรับข้อกล่าวอ้างในเชิงความหมายหรือไม่ แพ็กเกจตั้งใจทดสอบคำรับรองความสามารถที่เป็นเท็จหนึ่งรายการ ซึ่งยังผ่านการตรวจโครงสร้างได้เมื่อมี ID ถูกต้อง นี่พิสูจน์ว่ายังต้องตรวจข้อเท็จจริงด้วยมนุษย์
