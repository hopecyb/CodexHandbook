ก่อนตรวจทาน ให้ระบุชัดว่ากำลังเปรียบเทียบอะไร Skill นี้ป้องกันไม่ให้ตีความ “การเปลี่ยนแปลงปัจจุบันที่ยังไม่ commit” เป็น “commit เทียบกับ main” และไม่พลาดข้อผิดพลาดใน staging area เพียงเพราะ working tree ดูปกติ

[ดาวน์โหลด scoped-review v1.0.0 ฉบับเต็ม](/downloads/skills/scoped-review/scoped-review-1.0.0.zip) · [ดู SKILL.md](/downloads/skills/scoped-review/SKILL.md) · [คำแนะนำการติดตั้งและใช้งาน](/downloads/skills/scoped-review/README.md)

## ทำอะไรได้บ้าง

| คำขอของผู้ใช้ | ขอบเขตที่รวบรวม | สิ่งที่ไม่รวม |
|---|---|---|
| ตรวจเฉพาะ staged | HEAD → index | เนื้อหา unstaged |
| ตรวจเฉพาะ unstaged | index → working tree | patch ที่ staged แล้ว |
| ตรวจการเปลี่ยนแปลงปัจจุบันที่ยังไม่ commit | เก็บ patch สองชุดข้างต้นแยกกัน และระบุไฟล์ใหม่ | ยังต้องอ่านเนื้อหาไฟล์ใหม่แยกต่างหาก |
| ตรวจ commit เทียบกับ branch ที่ระบุ | merge-base เดียว → HEAD | เนื้อหาในเครื่องที่ยังไม่ commit |

Skill จะไม่เดา main เป็นค่าเริ่มต้น หากไม่มี baseline จะรายงานข้อผิดพลาด ไม่เปลี่ยนขอบเขตเงียบ ๆ ตัวรวบรวมให้เพียงหลักฐาน ส่วนการตัดสินข้อบกพร่องยังต้องพิจารณาโค้ดและการทดสอบที่เกี่ยวข้อง

## ติดตั้งและเรียกใช้ครั้งแรก

ต้องใช้ Python 3.10+, Git และรีโพซิทอรีฝึกในเครื่องที่มี commit แล้วหนึ่งรายการ วาง `scoped-review/` ที่แตกไฟล์แล้วใน `.agents/skills/` ของโปรเจกต์เป้าหมาย และยืนยันว่าจุดเข้าคือ `.agents/skills/scoped-review/SKILL.md` หากมี Skill ชื่อเดียวกัน ให้เปรียบเทียบก่อนและอย่าเขียนทับ

การค้นพบและจุดเข้าที่ใช้ได้ของ Skills ในเครื่องให้ยึด [คำอธิบายทางการ](https://learn.chatgpt.com/docs/build-skills) หลังติดตั้ง ให้ยืนยันว่าเลือกใช้ได้ แล้วเรียกอย่างชัดเจน:

```text
$scoped-review ตรวจการเปลี่ยนแปลงโค้ดปัจจุบันที่ยังไม่ commit ในรีโพซิทอรีฝึกนี้
ห้ามแก้ไฟล์ ให้ระบุ findings ก่อน แล้วอธิบายความครอบคลุมของ staged, unstaged และไฟล์ใหม่
```

นี่เป็นแพ็กเกจสอนและจะไม่ติดตั้งลงการตั้งค่าส่วนตัวโดยอัตโนมัติ หากยังไม่ติดตั้ง คุณสามารถรันสคริปต์ในแพ็กเกจโดยตรงเพื่อดูขอบเขตที่รวบรวมได้

## ทำซ้ำสถานการณ์ที่พลาดตรวจได้ง่าย

อินพุตสังเคราะห์อยู่ใน `fixtures/scenario.json`:

1. สูตรส่วนลด baseline ถูกต้อง
2. stage สูตรที่ผิด: `amount * (1 - percent)`
3. working tree กลับมาเป็นสูตรถูกต้อง: `amount * (1 - percent / 100)` แต่ยังไม่ได้ stage ใหม่

ในตอนนี้ หากดูเพียง `git diff HEAD` อาจไม่เห็นการเปลี่ยนแปลง แต่การ commit staging area ยังทำให้เกิดข้อผิดพลาด สำหรับ `amount=40, percent=10` เวอร์ชัน staged ได้ -360 ทั้งที่ควรเป็น 36

การตรวจที่ถูกต้องควรระบุแยกกันว่า เวอร์ชัน staged มีข้อผิดพลาด และ patch unstaged กำลังแก้ไข [ตัวอย่างอ้างอิงของผู้เขียน](/downloads/skills/scoped-review/fixtures/expected-review.md) ฉบับเต็มยังอธิบายว่าทำไมโหมด branch จึงไม่ควรรวมปัญหาในเครื่องนี้ แต่เอกสารดังกล่าวไม่ใช่ผลลัพธ์จากโมเดลจริง

## รันการตรวจในแพ็กเกจ

รันในไดเรกทอรี Skill ที่แตกไฟล์แล้ว:

```sh
python3 validation/test_scopes.py
```

การทดสอบเจ็ดรายการใช้รีโพซิทอรี Git ชั่วคราวตรวจขอบเขต การทดสอบย้อนหลังของกรณีพลาดตรวจ การปฏิเสธ baseline ที่ไม่ถูกต้อง รายการไฟล์ใหม่ และการไม่แก้รีโพซิทอรีที่ตรวจ เมื่อเสร็จปกติ exit code คือ 0 การทดสอบไม่เขียนไปยังโปรเจกต์จริงของคุณ

ใช้ตัวรวบรวมจริง:

```sh
python3 scripts/collect_diff.py --repo /path/to/your/repo --mode working-tree
```

แทน path ด้วยรีโพซิทอรีที่ได้รับอนุญาตให้ตรวจ โหมด branch ต้องระบุ `--base` เพิ่ม ผลลัพธ์ JSON อาจมีโค้ดส่วนตัวและจะไม่ถูกอัปโหลดอัตโนมัติ ดูคำสั่งทั้งหมดที่ [คำอธิบายขอบเขต](/downloads/skills/scoped-review/references/scopes.md)

## เมื่อใดไม่ควรทริกเกอร์

การขัดเกลาบทความและสร้างฟีเจอร์ใหม่ไม่ใช่งานของ Skill นี้ คำขอคลุมเครือว่า “review หน่อย” ควรใช้บริบทกำหนดขอบเขต และถามเมื่อยังไม่ชัด [กรณีทริกเกอร์](/downloads/skills/scoped-review/fixtures/trigger-cases.json) ในแพ็กเกจบันทึกคำขอที่คาดไว้เจ็ดแบบ แต่ยังไม่ได้วัดการ route อัตโนมัติจริง

## เงื่อนไขว่าเสร็จและข้อจำกัด

- รายงานระบุ snapshot, baseline และขอบเขตไฟล์ที่ตรวจจริง
- findings มีตำแหน่ง เงื่อนไขทริกเกอร์ ผลกระทบ และหลักฐาน โดยไม่ถือความชอบด้านสไตล์เป็นข้อบล็อก
- ตรวจเนื้อหาไฟล์ untracked ที่เกี่ยวข้องแล้ว หรือระบุชัดว่ายังไม่ได้ตรวจ ห้ามอ้างว่าครอบคลุม binary, ignored file และ submodule
- ระบุว่ารันการตรวจใดและไม่ได้รันอะไร การไม่พบข้อบกพร่องไม่ได้รับประกันว่าไม่มีข้อบกพร่อง
- การตรวจจบที่รายงาน โดยไม่แก้ commit หรือ push อัตโนมัติ

จากนั้นใช้เทมเพลตตรวจทานและส่งต่องานใน [เส้นทางนักพัฒนา](/th/guide/learning-paths/developer/) เพื่อเก็บผลลัพธ์ โครงสั้น `pr-review` เดิมยังใช้ทำความเข้าใจโครงสร้างได้ แพ็กเกจนี้ใช้ชื่ออื่นเพื่อไม่เขียนทับเวอร์ชันส่วนตัวที่มีอยู่
