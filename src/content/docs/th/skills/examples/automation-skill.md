## ติดตั้งและทดลองด้วยตนเอง

วางไดเรกทอรีทั้งหมดใน `.agents/skills/quiet-link-monitor/` ของโปรเจกต์ฝึก โดยไม่เขียนทับ Skill ชื่อเดียวกัน เมื่อยืนยันตาม [ใช้ Skill](/th/skills/use-a-skill/) ว่าเลือกได้แล้ว ให้เรียก:

```text
$quiet-link-monitor ทดลองความล้มเหลว การตรวจซ้ำ และการกู้คืนด้วยตัวอย่างในแพ็กเกจ
ทำงานในสำเนาชั่วคราว เก็บสถานะแยก และสุดท้ายรายงานการเปลี่ยนเหตุการณ์โดยไม่ส่งการแจ้งเตือน
```

คุณสามารถรันสคริปต์แยกก่อนโดยไม่ต้องใช้โมเดลหรือบัญชี ต้องใช้ standard library ของ Python 3.10+:

```sh
python3 validation/test_monitor.py
```

เมื่อทำด้วยตนเอง ให้คัดลอก `fixtures/broken` เป็น `work-site` ของคุณ แล้วรันต่อเนื่องในไดเรกทอรี Skill:

```sh
python3 scripts/run_once.py --site work-site --state run-state.json
python3 scripts/run_once.py --site work-site --state run-state.json
```

ครั้งแรกออกด้วย 1 และบันทึกเหตุการณ์ความล้มเหลว ครั้งที่สองยังออกด้วย 1 แต่ `new_event` เป็น null ให้แก้ไดเรกทอรีเดิมตาม `fixtures/fixed` แล้วรันอีกครั้ง จะได้ exit 0 และ `recovered` อย่าเปลี่ยนเป็น path เว็บไซต์อื่นเพื่อจำลองการกู้คืน เพราะสถานะจะปฏิเสธการเปลี่ยนขอบเขต

[สรุป CLI สามครั้งจริง](/downloads/skills/quiet-link-monitor/validation/manual-run.json)

## บันทึกอะไร และหยุดเมื่อใด

ไฟล์สถานะต้องอยู่นอกไดเรกทอรีที่ตรวจ โดยเก็บผลแต่ละรอบ จำนวนความล้มเหลวต่อเนื่อง และเหตุการณ์ถาวร สคริปต์จะเขียนไฟล์นี้และ lock file ที่อยู่ข้างกัน จึงไม่ใช่การทำงานแบบอ่านอย่างเดียวโดยสมบูรณ์ เนื้อหาเว็บไซต์จะไม่ถูกแก้

| สถานการณ์ | พฤติกรรม |
|---|---|
| สุขภาพดีครั้งแรก | สร้าง baseline โดยไม่มีเหตุการณ์ใหม่ |
| ล้มเหลวครั้งแรกหรือพบการเปลี่ยนแปลงของปัญหา | บันทึกเหตุการณ์การเปลี่ยนแปลง |
| ได้ผลเดิมอีกครั้ง | ไม่สร้างเหตุการณ์ใหม่ |
| แก้ความล้มเหลวแล้ว | บันทึกเหตุการณ์กู้คืน |
| การตรวจทำงานผิดพลาดต่อเนื่องสามครั้ง | บันทึกเหตุการณ์หยุดและเข้าสู่สถานะพัก |
| สถานะเสียหาย lock conflict หรือเว็บไซต์ไม่ตรง | หยุดทันทีโดยไม่เขียนทับสถานะเดิม |

การพบลิงก์เสียเป็นผลตรวจที่ใช้ได้และไม่นับเป็นข้อผิดพลาดขณะทำงาน เมื่อพักแล้ว การเรียกทั่วไปจะไม่ตรวจต่อ หลังตรวจสาเหตุและแก้แล้ว ให้กู้คืนอย่างชัดเจน:

```sh
python3 scripts/run_once.py --site work-site --state run-state.json --resume
```

อย่าลบ lock หรือสถานะอัตโนมัติเพื่อหลบความล้มเหลว กระบวนการ crash อาจทิ้ง lock ไว้ จึงต้องยืนยันก่อนว่าไม่มี process ที่ยังทำงานอยู่ [คำอธิบายสถานะและการกู้คืน](/downloads/skills/quiet-link-monitor/references/operations.md) ระบุ exit code การเก็บรักษา และขอบเขต concurrency

## ตัวเลือกการแจ้งเตือนไม่ได้หมายความว่าส่งแล้ว

สคริปต์บันทึกเฉพาะเหตุการณ์ในเครื่อง โดย `delivery` ทั้งหมดเป็น `not-sent` ไม่สร้าง schedule และไม่ส่งข้อความ เหตุการณ์มี id ที่เสถียรสำหรับบันทึกนั้น ผลลัพธ์ซ้ำจะไม่สร้างเหตุการณ์สถานะเดียวกันอีก

เมื่อต่อเข้ากับตัวส่งที่ได้รับอนุญาต ให้อ่านเหตุการณ์ถาวรที่ยังไม่ส่ง ทำ deduplicate ตาม id และเก็บการยืนยันการส่ง หากอ่านเฉพาะ `new_event` ล่าสุดจากเทอร์มินัล อาจพลาดรายงานเมื่อ process หยุดกลางคัน แพ็กเกจนี้ไม่มีตัวส่งและไม่รับประกัน exactly-once delivery ข้ามระบบ

## จากการรันด้วยตนเองสู่การรันเป็นคาบ

ยืนยันว่าบิลด์สำเร็จก่อน แล้วจึงตรวจผลลัพธ์ล่าสุด หากบิลด์ล้มเหลวให้หยุดและอย่าตรวจไดเรกทอรีเก่า ในแต่ละรอบ scheduler ต้องใช้เว็บไซต์และไฟล์สถานะเดียวกัน เพื่อหลีกเลี่ยงการเขียนทับพร้อมกัน ให้ทริกเกอร์ด้วยตนเองในสภาพแวดล้อมเป้าหมายก่อน ตรวจ log และพฤติกรรมหยุด แล้วจึงกำหนดคาบ ช่องทาง ผู้รับ และขอบเขตการแจ้งเตือนจริงต้องมาจากสิทธิ์ที่มีอยู่

ยังไม่ได้ทดสอบการกำหนดเวลาจริงและการส่งข้อความ ลิงก์ภายนอกยังอยู่ในสถานะ `unchecked` จึงห้ามเขียนว่าสถานะในเครื่องที่ดีหมายถึง “ลิงก์ทั้งเว็บไซต์ปกติ”

## ขอบเขตการใช้งานและเกณฑ์การยอมรับ

เหมาะกับการ audit ลิงก์เอกสารซ้ำ ส่วนรายงานยอดขายทั่วไป งานเขียนสร้างสรรค์ และการติดตั้งงาน production อัตโนมัติไม่อยู่ในความสามารถของแพ็กเกจนี้ กรณีทริกเกอร์เป็นสิ่งที่คาดจากการออกแบบ และยังไม่ได้วัดการ route โมเดล

เมื่อทำแบบฝึกหัดเสร็จ คุณควรแสดงบันทึกความล้มเหลวครั้งแรก ความเงียบเมื่อซ้ำ และการกู้คืนหลังแก้ รวมถึงหลักฐานการพักและกู้คืนอย่างชัดเจนได้ การทดสอบแปดรายการในแพ็กเกจตรวจพฤติกรรมสถานะในเครื่องเหล่านี้แล้ว แต่ไม่ได้พิสูจน์การตัดสินของโมเดล การเข้าถึงเครือข่าย หรือความน่าเชื่อถือใน production จริง
