ChatGPT และ Codex ใช้ไดเรกทอรี Plugin สาธารณะเดียวกัน Plugin รวมความสามารถที่เกี่ยวข้องเป็น workflow ที่ค้นพบและติดตั้งได้ ไม่ได้สร้างโปรโตคอลเรียกเครื่องมือชนิดใหม่

![ภาพประกอบ: แพ็กเกจส่วนขยายผูกริบบิ้นเคลื่อนตามรางไปติดตั้งในเครื่องหลายเครื่อง เครื่องหนึ่งกำลังแกะแพ็ก อีกเครื่องถอนการติดตั้งอย่างเรียบร้อย](/illustrations/plugins-overview.webp)

## Plugin มีอะไรได้บ้าง

| ส่วน | หน้าที่ | ผู้ติดตั้งควรตรวจ |
|---|---|---|
| Skills | ขั้นตอน เอกสารอ้างอิง และสคริปต์ที่นำกลับมาใช้ได้ | คำสั่งเหมาะกับงานปัจจุบันหรือไม่ สคริปต์เชื่อถือได้หรือไม่ |
| Connectors | เชื่อมเครื่องมืออย่าง GitHub, Slack และ Google Drive | OAuth scope, การอ่านเขียน และขอบเขตข้อมูลภายนอก |
| MCP servers | นิยามเครื่องมือ ยืนยันตัวตน และส่งข้อมูลแบบมีโครงสร้าง | แหล่งเซิร์ฟเวอร์ รายการเครื่องมือ log และสิทธิ์ |
| Browser extensions | ให้ความสามารถเบราว์เซอร์สำหรับ workflow เฉพาะ | ขอบเขตการเข้าถึงเบราว์เซอร์และความจำเป็น |
| Hooks | รันคำสั่งหรือเครื่องมือ MCP ณ จุดวงจรชีวิต | ตรวจและเชื่อถือนิยามที่แน่นอนก่อนเปิดใช้ |
| Scheduled task templates | เป็นจุดเริ่มที่นำกลับมาใช้ได้บนพื้นผิวที่รองรับงานตามเวลา | ความถี่ สิทธิ์ เงื่อนไขจบ และการตรวจโดยมนุษย์ |

## ต่างจาก Skill และ MCP อย่างไร

| กลไก | คำถามหลัก | ตัวอย่างในชุดตรวจ PR |
|---|---|---|
| Skill | ควรทำงานตามขั้นตอนใด | อ่าน diff ตรวจหลักฐาน และจัดอันดับความเสี่ยง |
| MCP / Connector | เรียกเครื่องมือภายนอกใดได้ | อ่าน GitHub PR และคอมเมนต์ |
| Hook | ตรวจ ณ จุดวงจรชีวิตใด | รัน secret scan หลังเขียนไฟล์ |
| Plugin | ติดตั้งและแจกจ่ายความสามารถเหล่านี้ร่วมกันอย่างไร | “แพ็กเกจตรวจ PR” ของทีม |

Plugin คือชั้นแจกจ่าย ไม่ใช่ขั้นสุดท้ายของสายการทำงาน ดูแผนผังความสัมพันธ์ที่ [แผนที่ความสามารถส่วนขยาย](/th/skills/capability-map/)

## ติดตั้งและตรวจครั้งแรก

### ChatGPT Web / Desktop App

1. เปิดแท็บ Plugins
2. ดูผู้เผยแพร่ คำอธิบาย และความสามารถที่มี
3. ติดตั้ง หากขอเชื่อมบริการภายนอก ให้ตรวจขอบเขตการอนุญาตแยกต่างหาก
4. ทำการตรวจความเสี่ยงต่ำใน Chat, Work หรืองาน Codex ใหม่

### Codex CLI

1. พิมพ์ `/plugins` เพื่อเปิด Plugin browser
2. ติดตั้งจาก marketplace ที่ตั้งค่าไว้
3. **เปิด session ใหม่** แล้วจึงตรวจ Skill หรือเครื่องมือที่ติดตั้งมาด้วย

IDE extension ปัจจุบันไม่รองรับ Plugin อย่าเขียนคู่มือแก้ปัญหาเรื่อง “หาจุดเข้าใช้ใน IDE ไม่พบ” วิธีที่ถูกต้องคือใช้ ChatGPT Desktop App หรือ Codex CLI จัดการ Plugin

## พรอมป์ตรวจความเสี่ยงต่ำ

```text
ตรวจเฉพาะ <plugin-name> ที่เพิ่งติดตั้ง และห้ามเขียนข้อมูล:
1. ระบุ Skills และเครื่องมือที่เกี่ยวข้องกับ Plugin นี้ในงานปัจจุบัน;
2. อธิบายว่าแต่ละเครื่องมือเป็น read-only หรืออาจสร้างผลข้างเคียงภายนอก;
3. เรียกขั้นต่ำหนึ่งครั้งด้วยข้อมูลทดสอบหรือ query แบบ read-only;
4. รายงานว่าใช้ส่วนประกอบใดจริง และระบุการอนุญาตที่ยังต้องให้มนุษย์ยืนยัน
```

หาก Plugin ต้องเชื่อมต่อภายนอก การตรวจครั้งแรกห้ามส่งข้อความ เปลี่ยนสถานะ ลบข้อมูล หรือเขียนไฟล์จำนวนมาก

## กระบวนการนำมาใช้ในทีม

1. **สำรวจส่วนประกอบ**: ระบุ Skills, connectors, MCP, browser extensions, Hooks และ templates
2. **ตรวจแหล่งที่มา**: ยืนยัน marketplace, รีโพซิทอรี, ผู้เผยแพร่ และนโยบายอัปเดต
3. **ให้สิทธิ์น้อยที่สุด**: ทดลองด้วยบัญชีทดสอบและ scope read-only
4. **แยก pilot**: ใช้ในโปรเจกต์ non-production หรือทีมเล็กก่อน
5. **ตรวจ Hook**: ใช้ `/hooks` ตรวจ hash และพฤติกรรมของ Hook ที่มากับ Plugin
6. **บันทึกทางออก**: เขียนขั้นตอนปิด ถอนติดตั้ง ย้อนกลับ และถอน OAuth

## ขอบเขตที่ห้ามละเลย

- ติดตั้งสำเร็จไม่ได้หมายความว่าส่วนประกอบปลอดภัยหรือเหมาะกับข้อมูลปัจจุบัน
- Plugin อาจขอให้เชื่อมบริการภายนอก การอนุญาตเป็นขั้นความเสี่ยงสูงแยกต่างหาก
- Plugin Hook จะรันร่วมกับ Hook ที่ตรงกันจากแหล่งอื่น และไม่เขียนทับ Hook เก่าโดยอัตโนมัติ
- ผู้ดูแล Workspace ควบคุมได้ว่า Plugin และเครื่องมือใดใช้ได้ ไดเรกทอรีที่บุคคลเห็นไม่เท่ากับขอบเขตที่องค์กรอนุญาต
- Mobile เหมาะกับการใช้ Plugin ที่บัญชีมีอยู่ ไม่ควรตั้งสมมติฐานว่ามีอินเทอร์เฟซจัดการครบ

## เมื่อใดไม่ต้องทำ Plugin

- มีเพียง `SKILL.md` ง่าย ๆ หนึ่งไฟล์ โดยไม่มีปัญหาการรวมและแจกจ่าย
- สคริปต์ส่วนตัวครั้งเดียวที่ยังทดลองอย่างรวดเร็ว
- นโยบายสิทธิ์และการอัปเกรดยังไม่เสถียร
- ผู้ใช้เป้าหมายทำงานเฉพาะใน IDE extension

การทำ Skill หรือ workflow MCP เดี่ยวให้เสถียรก่อน แล้วจึงพิจารณารวมแจกจ่าย มักตรวจได้ง่ายกว่า

## รายการตรวจรับ

- [ ] พื้นผิวเป้าหมายรองรับ Plugin
- [ ] ย้อนตรวจผู้เผยแพร่และแหล่งที่มาได้
- [ ] ตรวจการเชื่อมต่อภายนอกและ OAuth scope แล้ว
- [ ] ตรวจและเชื่อถือ Plugin Hook แล้ว
- [ ] งาน read-only ขั้นต่ำสำเร็จ
- [ ] session ใหม่ค้นพบ Skill หรือเครื่องมือที่คาดไว้
- [ ] ทีมมีคำอธิบายการปิด ย้อนกลับ และถอนสิทธิ์
