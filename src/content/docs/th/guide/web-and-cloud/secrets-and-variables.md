ตัวแปรสภาพแวดล้อมและ Secrets ใน Cloud มีวงจรชีวิตต่างกัน ความต่างนี้กำหนดว่าสนับสนุนงานใดได้อย่างปลอดภัย ไม่ใช่เพียงว่า “UI จะปิดบังค่าไว้หรือไม่”

| ประเภท | ช่วงที่มองเห็น | เนื้อหาที่เหมาะสม |
|---|---|---|
| ตัวแปรสภาพแวดล้อม | ตลอด setup + Agent | การกำหนดค่าที่ไม่อ่อนไหว เช่น โหมดการรันและ base URL ของ API สาธารณะ |
| Secret | เฉพาะ setup script | token ของ private package และข้อมูลประจำตัวสำหรับติดตั้ง dependency |

Secret ถูกเข้ารหัสเพิ่มเติมเมื่อจัดเก็บ ถอดรหัสเฉพาะตอนรันงาน และนำออกก่อนขั้น Agent เริ่ม จึงไม่ใช่ช่องทางข้อมูลประจำตัวทั่วไปสำหรับให้ Agent เรียก production API ระหว่างรัน

## ตัวอย่างที่ถูกต้อง: ติดตั้ง private package

สร้าง Secret ชื่อ `NPM_TOKEN` ในการตั้งค่าสภาพแวดล้อม แล้วให้ setup script ใช้สร้างการกำหนดค่าการยืนยันตัวตนชั่วคราวและติดตั้ง dependency:

```bash
set -euo pipefail
printf '//registry.npmjs.org/:_authToken=%s\n' "$NPM_TOKEN" > ~/.npmrc
pnpm install --frozen-lockfile
rm -f ~/.npmrc
```

ขั้น Agent ไม่ต้องใช้ token อีก และใช้เฉพาะ dependency ที่ติดตั้งแล้ว ห้าม `echo` Secret ใน log ของ setup

## ตัวอย่างที่ไม่ถูกต้อง

```text
กำหนด production API_KEY เป็นตัวแปรสภาพแวดล้อมทั่วไป
แล้วให้ Agent ใช้ curl เรียก endpoint ภายนอกเพื่อตรวจคำสั่งซื้อจริง
```

วิธีนี้ทำให้ค่าที่อ่อนไหวคงอยู่ตลอดขั้น Agent และเสี่ยงต่อการส่งออกหรือดำเนินการผิดเมื่อเปิดเครือข่าย ควรใช้ test fixture, mock, ข้อมูลประจำตัวทดสอบชั่วคราวที่มีสิทธิ์น้อยที่สุด หรือจำกัดการเตรียมงานที่ต้องยืนยันตัวตนไว้ใน setup

## การตรวจการกำหนดค่า

1. ระบุค่าที่ setup และ Agent ต้องใช้จริงแยกกัน
2. ค่าที่อ่อนไหวและใช้เฉพาะติดตั้งให้ใช้ Secret
3. การตั้งค่าที่ Agent ต้องใช้และไม่อ่อนไหวให้ใช้ตัวแปรสภาพแวดล้อม
4. อย่าเขียนค่าลงในพรอมต์, issue, PR, repository หรือ `AGENTS.md`
5. รัน secret scanner และตรวจ log ของ setup
6. หมุนเวียนและลบข้อมูลประจำตัวที่เลิกใช้เป็นประจำ

setup รันในเซสชัน Bash แยกต่างหาก `export` ทั่วไปจึงไม่ส่งต่อไปยังขั้น Agent โดยอัตโนมัติ ค่าที่ไม่อ่อนไหวและต้องคงอยู่ตลอดแชตควรกำหนดเป็นตัวแปรสภาพแวดล้อมโดยตรง ไม่ใช่อาศัยสถานะ shell ชั่วคราว

## ความสัมพันธ์กับ CI

GitHub Actions Secrets กับ Codex Cloud Secrets เป็นระบบจัดเก็บคนละระบบ และไม่ซิงค์อัตโนมัติ คุณใช้ **ชื่อ** ตัวแปรเดียวกันเพื่อให้อธิบายในเอกสารง่ายขึ้นได้ แต่อย่าคัดลอก production token เดียวกันที่มีสิทธิ์เกินความจำเป็นของงาน

## การดำเนินการหลังรั่วไหล

เพิกถอนหรือหมุนเวียนข้อมูลประจำตัวทันที แล้วล้างเนื้อหาที่เปิดเผยออกจาก log, แชต, issue และประวัติ Git การลบเฉพาะไฟล์ปัจจุบันไม่สามารถเรียกคืน Secret ที่แพร่กระจายไปแล้ว
