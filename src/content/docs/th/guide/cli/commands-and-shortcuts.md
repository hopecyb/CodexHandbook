ประสิทธิภาพในเทอร์มินัลมาจากสามส่วน: **วิธีเริ่มต้น** **การทำงานลัดภายในเซสชัน** และ **การใช้ร่วมกับสคริปต์/เอดิเตอร์** หน้านี้อธิบายวิธีใช้และแนวทางปฏิบัติ ส่วนตารางพารามิเตอร์ดูที่ [ข้อมูลอ้างอิงคำสั่ง CLI](/th/guide/reference/commands/) และ [แป้นพิมพ์ลัด](/th/guide/reference/keyboard-shortcuts/)

## เนื้อหาในหน้านี้

- เมื่อใดควรใช้ `codex` หรือ `codex exec`
- การทำงานประเภทใดพบบ่อยในเซสชันแบบโต้ตอบ
- ทำให้การทำงานซ้ำเป็น alias หรือสคริปต์ได้อย่างไร

## แยกให้ออกก่อน

เมื่อเห็น CLI ครั้งแรก ผู้เริ่มต้นจำนวนมากมักคิดว่า “คำสั่งและทางลัด” คือการท่องไวยากรณ์และพารามิเตอร์

ในทางปฏิบัติ ควรแยกสามเรื่องนี้ก่อน:

- ตอนนี้คุณต้องการ **คุยไปทำไป**
- หรือต้องการให้ **ทำงานหนึ่งงานจบในครั้งเดียว**
- หรือเพียงต้องการย่อการกระทำที่ทำซ้ำบ่อย

เมื่อแยกได้ การเลือกคำสั่งจะชัดขึ้นมาก

## ภาพรวมจุดเข้าคำสั่ง

| สิ่งที่ต้องการทำ | จุดเข้า | รายละเอียด |
|---|---|---|
| คุยไปแก้โค้ดไป | TUI แบบโต้ตอบ `codex` | [โหมดโต้ตอบ](/th/guide/cli/interactive-mode/) |
| งานครั้งเดียวใน CI / pipeline | `codex exec` | [โหมดไม่โต้ตอบ](/th/guide/cli/non-interactive-mode/) |
| เปลี่ยนพฤติกรรมเริ่มต้น | ไฟล์ตั้งค่า | [การตั้งค่า CLI](/th/guide/cli/configuration/) |

:::note
ปัจจุบัน `codex` และ `codex exec` เป็นจุดเข้า Stable ทั้งคู่ แต่ให้ยึดพารามิเตอร์จาก `codex --help` และ `codex exec --help`
:::

## ความเข้าใจผิดที่พบบ่อย

### `codex` กับ `codex exec` ไม่ใช่โหมดระดับต่ำกับระดับสูง

หลายคนเข้าใจว่า:

- แบบหนึ่งเป็นโหมดง่าย
- อีกแบบเป็นโหมดมืออาชีพ

การแบ่งที่ใช้งานได้จริงกว่าคือ:

- `codex` เหมาะเมื่อคุณอยู่ดูและกำกับระหว่างทาง
- `codex exec` เหมาะเมื่ออธิบายงานไว้ชัดล่วงหน้าและให้ทำตามกระบวนการครั้งเดียว

### ทางลัดยิ่งมากไม่ได้ยิ่งดี

เมื่อเริ่มต้น ไม่ต้องจำแป้นลัดและคำสั่ง `/` ทั้งหมด

ให้รู้ก่อนว่า:

- เริ่มเซสชันอย่างไร
- ตรวจว่าปัจจุบันรองรับคำสั่ง `/` ใดบ้างอย่างไร
- ออก เปิดใหม่ และเปลี่ยนไดเรกทอรีอย่างไร

เท่านี้ก็เพียงพอสำหรับเริ่มใช้งาน

## “ทางลัด” ในเซสชันแบบโต้ตอบ

แต่ละเวอร์ชันมีปุ่มและคำสั่ง `/` ต่างกัน แต่ประเภทหลักคงที่:

### การป้อนข้อมูลและประวัติ

- ป้อนหลายบรรทัด: ใช้ชุดปุ่มขึ้นบรรทัดใหม่ตามคำอธิบายผลิตภัณฑ์ (มักเป็น `Shift+Enter` หรือโหมดเอดิเตอร์)
- ย้อนดูงานก่อนหน้า: ใช้ประวัติเทอร์มินัลหรือประวัติในเซสชัน (ถ้ามี)

### คำสั่ง Slash

พิมพ์ `/` ที่ prompt เพื่อเรียกกระบวนการในตัว เช่น review หรือบีบอัดบริบท **อย่าท่องรายการตายตัว**—ให้ดูการเติมคำ `/` ในสภาพแวดล้อมปัจจุบัน หมวดหมู่สำหรับเรียนรู้ดูที่ [คู่มือย่อคำสั่ง Slash](/th/guide/reference/slash-commands/)

### การอนุมัติ

เมื่อ Agent ขอรัน shell หรือเขียนไฟล์ UI แบบโต้ตอบจะให้อนุมัติ/ปฏิเสธ/อนุญาตเสมอ (ถ้ามี) ก่อนใช้งานแบบไร้ผู้ดูแล ต้องอ่าน [การอนุมัติและ Sandbox](/th/guide/cli/approvals-and-sandbox/)

## ทางลัดระดับ Shell (แนะนำ)

เขียนฟังก์ชันสำหรับ “เข้าโปรเจกต์ + เริ่ม Codex” เพื่อลดความผิดพลาดด้านไดเรกทอรี:

```bash
# ตัวอย่าง ~/.zshrc (ปรับตามต้องการ)
cx() {
  cd "$1" || return 1
  codex
}
```

การ review แบบไม่โต้ตอบอาจห่อเป็นสคริปต์ และเก็บ prompt ไว้ใน `prompts/review.md` เพื่อจัดการเวอร์ชันได้ง่าย

## ฝึกตามลำดับนี้

เมื่อเริ่มใช้ CLI ให้ทำความคุ้นเคยตามลำดับนี้:

1. เริ่ม `codex` ในไดเรกทอรีที่ถูกต้อง
2. ตัดสินใจว่าเมื่อใดควรใช้ `codex exec`
3. ค่อยรวมการกระทำที่ใช้บ่อยเป็น alias ฟังก์ชัน หรือสคริปต์

วิธีนี้ช่วยไม่ให้ตกอยู่ในสถานการณ์ที่ยังใช้เครื่องมือไม่คล่อง แต่เพิ่มชั้นห่อให้มันแล้ว

## การแบ่งงานกับ IDE / App

| | CLI | ส่วนขยาย IDE |
|---|---|---|
| บริบท | ระบุไดเรกทอรีด้วย `--cd` / `-C` และให้เครื่องมืออ่านดิสก์ | เปิดไฟล์และเลือกโค้ด |
| เหมาะกับ | สคริปต์ SSH ระยะไกล และเทอร์มินัลล้วน | แก้ไปดู diff ไป |
| ทางลัด | ปุ่มเทอร์มินัล + `/` | command palette ของเอดิเตอร์ |

IDE: [เวิร์กโฟลว์งานในเครื่อง](/th/guide/ide/local-task-workflow/)

## ข้อผิดพลาดที่พบบ่อย

- เริ่มในไดเรกทอรีผิดจนแก้โปรเจกต์ข้างเคียง
- นำ `/review` ภายในแอปไปใช้เป็นคำสั่งย่อยใน shell ภายนอก
- วาง “prompt สารพัดประโยชน์” จากบุคคลที่สามซึ่งยังไม่ได้ตรวจลงในเซสชันแบบโต้ตอบ

ไม่ต้องรีบท่องทุกคำสั่งและแป้นลัด แยกก่อนว่า “ตอนนี้ต้องการคุยไปทำไป หรือให้รันจบในครั้งเดียว” การเลือกคำสั่งจะง่ายขึ้นมาก
