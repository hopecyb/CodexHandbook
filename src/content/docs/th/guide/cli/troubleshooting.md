เมื่อ CLI มีปัญหา ข้อผิดพลาดอาจดูเหมือนปัญหาเทอร์มินัลเหมือนกัน แต่สาเหตุเบื้องหลังอาจคนละประเภท

เมื่อตรวจสอบ CLI ให้แยกก่อนว่าเป็น “ติดตั้งไม่สมบูรณ์ / เข้าสู่ระบบไม่ได้ / ไม่มีสิทธิ์ / เข้าไดเรกทอรีผิด”

| อาการ | ลองก่อน |
|---|---|
| command not found | ตรวจการติดตั้งและ PATH |
| ยืนยันตัวตนล้มเหลว | เข้าสู่ระบบใหม่ ตรวจนโยบายองค์กร |
| ปฏิเสธสิทธิ์ | ตรวจโหมดอนุมัติและการตั้งค่า sandbox |
| แก้ไฟล์ในไดเรกทอรีผิด | ยืนยันไดเรกทอรีทำงานปัจจุบัน |

## แบ่งเป็น 4 ประเภทก่อน

- **ค้นหาคำสั่งไม่พบเลย**: มักเป็นการติดตั้งหรือ `PATH`
- **รันคำสั่งได้แต่เข้าใช้งานไม่ได้**: มักเป็นการยืนยันตัวตน
- **เข้าใช้งานได้แต่ทำอะไรไม่ได้**: มักเป็นสิทธิ์หรือ sandbox
- **ทำสิ่งที่ไม่ถูกต้อง**: มักเป็นไดเรกทอรีหรือบริบทผิด

## ความเข้าใจผิดที่พบบ่อย

### 1. ข้อผิดพลาด CLI ทุกแบบต้องค้นใน log เดียวกัน

การจัดปัญหาเข้าหมวดใหญ่ก่อนมักเร็วกว่าเจาะรายละเอียดข้อผิดพลาดทันที

### 2. การปฏิเสธสิทธิ์แปลว่าโปรแกรมเสีย

หลายครั้งโปรแกรมไม่ได้เสีย แต่การอนุมัติ sandbox หรือนโยบายกำลังทำงานตามปกติ

### 3. คำสั่งรันได้แปลว่าไดเรกทอรีไม่มีปัญหา

ไม่ถูกต้อง

ปัญหา CLI จำนวนมากไม่ใช่คำสั่งรันไม่ได้ แต่คุณรันอยู่ใน repository หรือไดเรกทอรีทำงานผิด

## ลำดับการตรวจสอบ

1. ยืนยันก่อนว่ามีคำสั่งอยู่
2. ยืนยันสถานะเข้าสู่ระบบ
3. ตรวจโหมดสิทธิ์และข้อจำกัด sandbox ปัจจุบัน
4. สุดท้าย ยืนยันว่าไดเรกทอรีทำงานปัจจุบันคือโปรเจกต์ที่คิดไว้

เมื่อตรวจปัญหา CLI ให้แยกก่อนว่าเป็นปัญหาติดตั้ง เข้าสู่ระบบ สิทธิ์ หรือไดเรกทอรี การตรวจสอบจะเป็นลำดับมากขึ้น
