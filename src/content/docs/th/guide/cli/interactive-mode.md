“โหมดโต้ตอบ” คือการสนทนาไปกลับกับ Codex ในเทอร์มินัล Codex จะอธิบาย ลงมือทำ และรอให้คุณยืนยันเมื่อจำเป็น

นี่เป็นหนึ่งในวิธีใช้ CLI ที่พบบ่อย

หลังเริ่มเซสชันแบบโต้ตอบ:

1. เริ่มในไดเรกทอรีโปรเจกต์ (หรือระบุไดเรกทอรีทำงานตามเอกสาร)
2. ป้อน prompt คุณภาพเดียวกับที่ใช้ใน App
3. อนุมัติ/ปฏิเสธการเรียกเครื่องมือเมื่อมีข้อความถาม
4. ใช้คำสั่งลัดประเภท `/` (ถ้ามี) จัดการเซสชัน—ให้ยึดความช่วยเหลือของ CLI ปัจจุบัน

แนวทางเขียน prompt ยังใช้ได้: [Prompt](/th/prompts/)

## งานที่เหมาะกับโหมดโต้ตอบ

โหมดโต้ตอบเหมาะที่สุดกับงานที่ต้อง “ทำไปตัดสินใจไป”:

| สถานะงาน | เหตุใดจึงเหมาะกับการโต้ตอบ |
|---|---|
| ความต้องการยังไม่ชัดทั้งหมด | ชี้แจงเพิ่มระหว่างทางได้ |
| ต้องดู diff ก่อนตัดสินใจขั้นถัดไป | อนุมัติทีละขั้นหรือลดขอบเขตได้ |
| ทดลองกระบวนการหนึ่งในโปรเจกต์เป็นครั้งแรก | สังเกตได้ง่ายขึ้นว่าอ่านและแก้อะไร |
| เกี่ยวข้องกับสิทธิ์ เครื่องมือภายนอก หรืออาจเขียนไฟล์ | คนตรวจควบคุมจุดสำคัญได้ |

หากงานนิ่งพอจนไม่ต้องยืนยันไปมาแล้ว ค่อยพิจารณา [โหมดไม่โต้ตอบ](/th/guide/cli/non-interactive-mode/) หรือระบบอัตโนมัติ

## ความเข้าใจผิดที่พบบ่อย

### 1. ใช้ในเทอร์มินัลแล้วเขียน prompt แบบคร่าว ๆ ได้หรือไม่

ไม่ได้

แม้เปลี่ยนจุดเข้ามาเป็นเทอร์มินัล คุณภาพคำอธิบายงานยังสำคัญเท่าเดิม
ยิ่งเป้าหมาย ขอบเขตจำกัด และเกณฑ์เสร็จชัด ผลยิ่งมั่นคง

### 2. เหตุใดจึงเน้นว่า “เริ่มในไดเรกทอรีโปรเจกต์”

เพราะ CLI ต้องรู้ว่ากำลังทำงานในโปรเจกต์ใด
ถ้าไดเรกทอรีผิด อาจเกิดปัญหา:

- มองไม่เห็นไฟล์ที่ควรเห็น
- แก้ไขผิดไดเรกทอรี
- อ่านกฎโปรเจกต์ไม่พบ

### 3. เมื่อถามในเทอร์มินัลว่าจะอนุมัติหรือไม่ แปลว่าเกิดข้อผิดพลาดหรือไม่

หลายครั้งหมายความว่ากำลังทำงานตามขอบเขตสิทธิ์ ไม่ใช่ทำงานผิดปกติ

## สถานการณ์ง่าย ๆ สำหรับครั้งแรก

ครั้งแรกให้ลองงานเล็กแบบนี้:

- เริ่มที่รากโปรเจกต์
- แก้เพียงหนึ่งไฟล์
- เมื่อเสร็จ ให้ Codex อธิบายว่าแก้อะไร

โหมดโต้ตอบของ CLI คือกระบวนการงานแบบสนทนาที่รันในเทอร์มินัล ไดเรกทอรีต้องถูก และ prompt ต้องชัด
