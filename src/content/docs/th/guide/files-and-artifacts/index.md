ผลลัพธ์หลักของ Codex มักเป็น **การเปลี่ยนแปลงไฟล์ใน repository** หรือ **artifact ที่สร้างใหม่** เช่น เอกสาร รูปภาพ และ config หัวข้อนี้อธิบายแนวปฏิบัติตามประเภทไฟล์ เพื่อป้องกันกรณี “สร้างแล้วแต่ใช้ไม่ได้”

แม้จะเรียกว่า “ไฟล์” เหมือนกัน แต่ไฟล์แต่ละประเภทต้องใช้วิธีมอบหมายและตรวจรับต่างกัน

“แก้โค้ด” “จัดการตาราง” “สร้างภาพหน้าจอ” และ “ส่งออก PPT” ล้วนดูเหมือนงานไฟล์ แต่จุดที่ผิดพลาดง่ายไม่เหมือนกัน

## บทนี้อธิบายอะไร

บทนี้เน้นสามเรื่อง:

- มอบหมายงานให้ชัดเจนอย่างไร
- จุดใดที่ระบบอาจทำผิดโดยไม่สังเกต
- ตรวจรับผลลัพธ์อย่างไร

จึงเป็นคู่มือการทำงานแยกตามประเภทไฟล์ ไม่ใช่เพียงรายการฟีเจอร์

## หลักการร่วม

1. **พาธชัดเจน**: ระบุ output path และชื่อใน prompt
2. **รูปแบบตรงกัน**: นามสกุล encoding เช่น UTF-8 และ line ending สอดคล้องกับโปรเจกต์
3. **คำนึงถึงขนาด**: อย่าใส่ binary ขนาดใหญ่ใน Git หรือใช้ LFS/CDN
4. **ตรวจรับโดยมนุษย์**: สร้างแล้ว ≠ เสร็จ ให้เทียบกับ [definition of done](/th/guide/quality/definition-of-done/)
5. **ข้อมูลอ่อนไหว**: ดู [บริบทอ่อนไหว](/th/guide/context/sensitive-context/)

## ความเข้าใจผิดที่พบบ่อย

### 1. สร้างไฟล์ได้ไม่ได้แปลว่างานเสร็จ

ปัญหาของงานไฟล์จำนวนมากไม่ใช่ “สร้างหรือยัง” แต่คือ:

- รูปแบบถูกหรือไม่
- เนื้อหาถูกต้องหรือไม่
- พาธถูกหรือไม่
- ระบบ downstream ใช้ต่อได้หรือไม่

### 2. ไฟล์ทุกประเภทมอบหมายคล้ายกันหรือไม่

ไม่เหมือนกัน เช่น:

- ไฟล์โค้ดเน้นขอบเขต logic และการทดสอบ
- ตารางเน้นคอลัมน์ type และกฎสรุป
- รูปภาพเน้นเนื้อหาภาพและขนาด
- เอกสารเน้นโครงสร้าง น้ำเสียง และข้อเท็จจริง

### 3. เปิดไฟล์ได้ก็ถือว่าไม่มีปัญหาหรือไม่

ไม่ใช่  
“เปิดได้” เป็นเพียงขั้นพื้นฐาน ไม่ได้แปลว่าพร้อม commit เผยแพร่ หรือส่งมอบ

## ลำดับการอ่านที่แนะนำ

เมื่อใช้ Codex จัดการไฟล์ครั้งแรก:

1. เลือกประเภทไฟล์ที่ใกล้กับงานปัจจุบันที่สุด
2. ดูจุดผิดพลาดที่พบบ่อยของไฟล์ประเภทนั้น
3. ดูวิธีตรวจรับที่เกี่ยวข้อง

วิธีนี้ช่วยไม่ให้ข้อมูลทั้งบทท่วมตั้งแต่เริ่ม

## ความสัมพันธ์กับเครื่องมือ

- อ่านและเขียนไฟล์: เครื่องมือไฟล์ + เทอร์มินัล
- ดูรูป: [การเขียน prompt ด้วยรูปภาพ](/th/prompts/prompting-with-images/)
- ดูหน้าเว็บ: [เครื่องมือเบราว์เซอร์](/th/guide/tools/browser/)
- สร้างรูป: [การสร้างรูปภาพ](/th/guide/tools/image-generation/)

ในงานไฟล์ ผลลัพธ์อาจถูกสร้างแล้ว แต่รูปแบบ กฎ หรือเนื้อหาอาจคลาดเคลื่อนไปโดยไม่สังเกต
