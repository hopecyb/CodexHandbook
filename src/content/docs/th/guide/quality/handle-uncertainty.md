เมื่อข้อมูลไม่พอ ให้ยืนยันก่อนแล้วจึงทำต่อ

หนึ่งในปัญหาที่ยุ่งยากที่สุดเมื่อใช้ Codex คือการเติมข้อมูลที่ขาดด้วยคำตอบซึ่งดูสมเหตุสมผล หากสมมติฐานผิด ขั้นตอนต่อมาจะเบี่ยงเบนไปด้วย

## “ไม่แน่นอน” หมายถึงอะไร

ความไม่แน่นอนในที่นี้หมายถึง:

- ยังไม่มีหลักฐานพอให้ยืนยัน
- ข้อมูลที่เกี่ยวข้องไม่อยู่ในบริบทปัจจุบัน
- หากเดาต่อ ความเสี่ยงจะสูงขึ้น

วิธีที่เหมาะกว่าคือระบุล่วงหน้าว่า “เมื่อใดต้องหยุดและขอยืนยันก่อน”

ใส่ในพรอมต์เป็นประจำว่า:

```text
หากข้อมูลไม่พอ ให้ถามก่อน; ห้ามแต่งพาธไฟล์ API หรือกฎธุรกิจ
```

เมื่อพบการแต่งขึ้น: หยุด แก้ข้อเท็จจริง และเปิดเธรดใหม่เมื่อจำเป็น

## วิธีตัดสิน

หากข้อสรุปตรงกับข้อใดข้อหนึ่งต่อไปนี้ ไม่ควรเดาแล้วทำต่อ:

- หาไม่มีหลักฐานในไฟล์ปัจจุบัน
- คุณไม่ได้ให้กฎธุรกิจข้อนี้อย่างชัดเจน
- ต้องใช้ข้อเท็จจริงภายนอกแต่ยังไม่ได้ตรวจแหล่งข้อมูล
- หากเดาผิดจะกระทบการทำงานหลายขั้นถัดไป

## ความเข้าใจผิดที่พบบ่อย

### 1. คำตอบครบถ้วนไม่ได้แปลว่า Codex รู้จริง

เนื้อหาที่ครบอาจเป็นเพียงการเติมได้ลื่นไหล ไม่ได้แปลว่าสิ่งนั้นมีอยู่จริงในโปรเจกต์ของคุณ

### 2. เมื่อข้อมูลไม่ครบ สิ่งสำคัญไม่ใช่เติมช่องว่างทั้งหมด

ให้ข้อมูลครบที่สุดย่อมดีกว่า แต่การทำงานจริงมักมีข้อมูลไม่ครบ

สิ่งสำคัญกว่าคือสองเรื่อง:

- เมื่อข้อมูลขาด Codex ต้องหยุดและขอยืนยันก่อน
- อนุญาตให้ Codex ถาม แทนการบังคับให้เดาจนครบ

### 3. การที่ Codex ถามไม่ได้ทำให้งานช้าลงเสมอ

แม้ดูเหมือนเพิ่มขั้นหนึ่ง แต่มักลดงานแก้ซ้ำได้

ปัญหาหลายอย่างขยายจากการ “เดาแล้วทำก่อน”

### 4. เมื่อพบว่า Codex เดา ให้หยุดก่อนทำต่อ

หยุดความผิดพลาดก่อนแล้วจึงทำต่อ ตามลำดับนี้:

1. ระบุชัดว่าข้อใดผิด
2. เติมข้อมูลจริง
3. หากจำเป็น ให้เริ่มใหม่จากข้อเท็จจริงที่แก้แล้ว

## รูปประโยคที่เติมได้ทันที

หากต้องการลดการเดา เขียนได้ว่า:

```text
หากยืนยันจากไฟล์ที่มีอยู่หรือข้อมูลที่ฉันให้ไม่ได้ ให้ถามก่อนและอย่าเติมเอง
```

## เพิ่มอีกหนึ่งข้อ

เติมประโยคนี้ได้ด้วย:

```text
หากตีความได้หลายแบบ ให้ระบุจุดที่คุณไม่แน่ใจก่อน แล้วจึงทำต่อ
```

สิ่งที่ยุ่งยากกว่าคือการนำการคาดเดาไปใช้ต่อเหมือนเป็นข้อเท็จจริง
