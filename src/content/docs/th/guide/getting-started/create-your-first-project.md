เมื่อสร้างโปรเจกต์ฝึกครั้งแรก หลายคนอยากใช้โปรเจกต์จริงที่มีอยู่ทันที แม้ดูสะดวก แต่ความเสี่ยงก็สูงกว่า

## วิธีที่แนะนำ

1. สร้างโฟลเดอร์ใหม่ เช่น `codex-practice/`
2. ใส่ไฟล์ข้อความ 1–2 ไฟล์ที่ไม่มีข้อมูลละเอียดอ่อน เช่น `hello.md`
3. เปิดหรือเพิ่มโฟลเดอร์นี้เป็นโปรเจกต์ใน Codex
4. **อย่า** ใช้รีโพซิทอรีที่มีคีย์โปรดักชัน ข้อมูลลูกค้า หรือประวัติที่ทิ้งไม่ได้

## ทำไมควรสร้างโปรเจกต์ฝึกก่อน

เป้าหมายของงานแรกคือเรียนรู้เวิร์กโฟลว์ ไม่ใช่ส่งมอบงานธุรกิจ การแยกพื้นที่ฝึกจะลดต้นทุนเมื่อแก้ผิดได้มาก

สิ่งสำคัญกว่าในการฝึกครั้งแรกคือทำความคุ้นเคยกับขั้นตอนเหล่านี้:

- Codex เข้าใจงานอย่างไร
- Codex ขอสิทธิ์เมื่อใด
- คุณตรวจผลลัพธ์อย่างไร
- หากทำผิดจะย้อนกลับอย่างไร

หากเริ่มฝึกในโปรเจกต์จริง ขั้นตอนที่ควรเรียนรู้แบบความเสี่ยงต่ำเหล่านี้จะมีต้นทุนจริงทันที

## ความเข้าใจผิดที่พบบ่อย

### 1. โปรเจกต์ฝึกยิ่งเหมือนโปรดักชันจริงยิ่งดี

ครั้งแรกควรให้ความสำคัญกับความปลอดภัย ความสามารถในการทิ้ง และความง่ายในการตรวจ ไม่จำเป็นต้อง “เหมือนจริงทุกอย่าง”

### 2. ถ้าระวังให้ดี ใช้รีโพซิทอรีจริงก็ไม่เป็นไร

ปัญหาที่พบบ่อยกว่าในการใช้ครั้งแรกคือ:

- บอกขอบเขตงานไม่ชัด
- มองข้ามความต่างบางส่วน
- อนุมัติสิ่งที่ตัวเองอ่านไม่เข้าใจ

### 3. โปรเจกต์ฝึกง่ายเกินไปจนไม่ได้เรียนรู้อะไร

ยิ่งงานแรกเล็ก คุณยิ่งโฟกัสที่เวิร์กโฟลว์ได้ แทนที่จะเสียสมาธิกับความซับซ้อนของธุรกิจ

## เลือกโปรเจกต์ฝึกอย่างไร

หากจะสร้างโปรเจกต์ฝึกตอนนี้ อย่างน้อยต้องตรงตาม 4 ข้อนี้:

1. ทิ้งได้
2. ไม่มีข้อมูลละเอียดอ่อน
3. มีไฟล์น้อยและโครงสร้างเรียบง่าย
4. มองการเปลี่ยนแปลงแล้วเข้าใจได้ทันที

โปรเจกต์ฝึกครั้งแรกไม่ต้องเหมือนโปรดักชัน ขอเพียงปลอดภัย เรียบง่าย และย้อนกลับได้ง่ายเมื่อทำผิด
