หลังทำงานเสร็จ ผู้เริ่มต้นจำนวนมากข้ามขั้นตอนนี้

หากต้องการใช้ Codex อย่างมั่นคง คุณต้องรู้จัก **ตรวจผลลัพธ์**

อย่าดูเพียงข้อความว่า “เสร็จแล้ว” ให้ดูด้วยว่า Codex แก้อะไร และผลลัพธ์ตรงตามที่ต้องการหรือไม่

## เช็กลิสต์ตรวจผล

1. **ดู diff**: แก้เฉพาะไฟล์ที่อนุญาตหรือไม่
2. **เปิดอาร์ติแฟกต์**: เนื้อหาตรงตามเกณฑ์ยอมรับหรือไม่
3. **ขอให้แก้ต่อ**: หากขาดอีกเล็กน้อย ให้ส่งข้อเสนอแนะที่เจาะจง
4. **ตัดสินใจ**: ยอมรับ / แก้เอง / [เลิกทำ](/th/guide/getting-started/undo-and-recover/)

ดูวิธีเพิ่มเติมที่ [ตรวจ diff](/th/guide/quality/review-diffs/)

## จุดที่มักมองข้าม

### 1. อ่านเฉพาะสรุป ไม่ดูการเปลี่ยนแปลงจริง

Codex อาจสรุปได้ลื่นไหล แต่สิ่งสำคัญจริงคือ:

- แก้ผิดไฟล์หรือไม่
- แก้จุดที่คุณไม่ได้อนุญาตเพิ่มหรือไม่
- ผลลัพธ์ผ่านเกณฑ์ยอมรับจริงหรือไม่

### 2. เห็นว่า “เกือบได้” แล้วกดยอมรับทันที

“เกือบได้” มักทิ้งปัญหาเล็กไว้ภายหลัง  
หากขาดอีกนิด ให้ส่งข้อเสนอแนะที่แม่นยำเพิ่มหนึ่งประโยค แทนการยอมรับเงียบ ๆ

### 3. เห็นว่าผิด แต่ไม่รู้จะบอกอย่างไร

ใช้รูปประโยคนี้ต่อได้เลย:

```text
ผลลัพธ์ใกล้เคียงแล้ว แต่ยังมีสองปัญหา: 1) … 2) … โปรดแก้เฉพาะสองจุดนี้ และอย่าเปลี่ยนส่วนอื่น
```

## ลำดับการตรวจ

เมื่อฝึกครั้งแรก ให้ตรวจตามลำดับนี้:

1. **ดูขอบเขต**: Codex แก้ไฟล์ใดบ้าง
2. **ดูผลลัพธ์**: หน้า เอกสาร หรือเอาต์พุตโค้ดตรงตามข้อกำหนดหรือไม่
3. **ดูผลข้างเคียง**: มีการเปลี่ยนแปลงเกินจำเป็นหรือข้อผิดพลาดใหม่หรือไม่

ขั้นยอมรับงานคือการยืนยันว่าคุณรับผลลัพธ์ครั้งนี้ได้อย่างมั่นใจ
