ตัวอย่างต่อไปนี้ใช้ **เดสก์ท็อป App** เป็นค่าเริ่มต้น แต่ CLI และ IDE ใช้พรอมต์เดียวกันได้

หลายคนใช้ Codex ครั้งแรกก็สั่งให้ “ทำเว็บไซต์ทั้งเว็บ” หรือ “รีแฟกเตอร์ทั้งโปรเจกต์” ทันที วิธีนี้ทำให้หลุดการควบคุมได้ง่าย

งานแรกควรเล็กเพื่อให้มั่นคงกว่า การทำเวิร์กโฟลว์ทั้งชุดให้ครบสำคัญกว่าการเริ่มด้วยงานใหญ่

## ทำไมงานแรกต้องเล็กขนาดนี้

งานแรกควรมีสามคุณสมบัติ:

- ขอบเขตการเปลี่ยนแปลงเล็ก
- ตรวจผลได้ทันที
- ย้อนกลับง่ายแม้ทำผิด

ตัวอย่างนี้จึงเป็นแบบฝึกขนาดเล็กมาก

## ตัวอย่างงาน

บอก Codex ในโปรเจกต์ฝึกว่า:

```text
เป้าหมาย: เพิ่มหัวข้อ “แบบฝึกวันนี้” ท้ายไฟล์ hello.md พร้อมรายการหัวข้อย่อยสามบรรทัด
ข้อจำกัด: แก้เฉพาะ hello.md; ห้ามลบเนื้อหาเดิม; ห้ามส่งคำขอเครือข่าย
เกณฑ์ยอมรับ: ท้ายไฟล์มีหัวข้อนี้และมีรายการสามข้อพอดี
หากข้อมูลไม่พอ ให้ถามฉันก่อน อย่าเดา
```

## หน้าที่ของแต่ละส่วนในพรอมต์

พรอมต์นี้แยกประเด็นสำคัญให้ชัดเจน:

- **เป้าหมาย**: บอกว่าต้องทำอะไร
- **ข้อจำกัด**: บอกว่าห้ามแก้ส่วนใดตามใจ
- **เกณฑ์ยอมรับ**: บอกว่า “อย่างไรจึงถือว่าเสร็จ”
- **หากข้อมูลไม่พอ ให้ถามฉันก่อน**: ป้องกันไม่ให้ตัดสินใจเดาเอง

นี่ไม่ใช่เทมเพลตตายตัว เพียงเขียนส่วนที่มักอธิบายไม่ชัดให้ครบ

## ความเข้าใจผิดที่พบบ่อย

### 1. งานแรกยิ่งใหญ่ ยิ่งได้เรียนรู้ของจริงมาก

ครั้งแรกควรทำวงจรให้ครบหนึ่งรอบมากกว่าขยายงานให้ใหญ่ในครั้งเดียว

### 2. เมื่อเขียน prompt แล้ว ที่เหลือปล่อยให้ Codex ทำเองได้

ในงานแรก ให้จับตาสามเรื่อง:

- เกินขอบเขตหรือไม่
- Codex กำลังแก้ไฟล์ที่คุณระบุหรือไม่
- ผลลัพธ์สุดท้ายผ่านเกณฑ์ยอมรับหรือไม่

### 3. ถ้างานแรกผิด แปลว่าฉันใช้ไม่เป็น

งานแรกมีขั้นตอนเหล่านี้อยู่แล้ว:

- หาให้เจอว่าผิดตรงไหน
- ระบุปัญหาได้
- รู้วิธีให้ Codex ย้อนกลับ

## ข้อควรระวังระหว่างทำงาน

1. ให้ Codex เสนอแผนสั้น ๆ หรือขอแผนเอง
2. เมื่อต้องอนุมัติการเขียนไฟล์ ให้ตรวจว่าพาธถูกต้อง
3. เมื่อเสร็จแล้ว ไปที่ [ตรวจผลลัพธ์](/th/guide/getting-started/review-the-result/)

## ลำดับการทำงาน

ทำตาม 5 ขั้นตอนนี้:

1. เลือกโปรเจกต์ฝึกที่ปลอดภัย
2. มอบหมายงานเล็กที่แก้เพียงไฟล์เดียว
3. ก่อนอนุมัติ ดูให้ชัดว่าจะเปลี่ยนที่ใด
4. เมื่อเสร็จแล้ว ตรวจขอบเขตและผลลัพธ์
5. หากไม่พอใจ ให้เลิกทำหรือแก้ทิศทางอย่างเจาะจงต่อ

เมื่อทำครบ 5 ขั้นตอน คุณจะคุ้นเคยกับจังหวะการทำงานร่วมกันมากขึ้น

## หลังเสร็จต้องตรวจอะไร

เน้นสามเรื่องนี้:

1. Codex แก้เฉพาะ `hello.md` หรือไม่
2. ท้ายไฟล์มีหัวข้อนั้นเพิ่มจริงหรือไม่
3. มีรายการสามข้อพอดีหรือไม่

หากถูกทั้งสามข้อ งานเล็กครั้งนี้ถือว่าราบรื่น

## หาก Codex ทำผิด

การทำผิดครั้งแรกเป็นเรื่องปกติ คุณสั่งต่อได้ทันทีว่า:

```text
คุณแก้เกินขอบเขต โปรดย้อนการเปลี่ยนแปลงในไฟล์อื่นทั้งหมด และคงไว้เฉพาะการแก้ hello.md
```

หรือ:

```text
ยังไม่ต้องแก้ต่อ บอกฉันว่าคุณเพิ่งเปลี่ยนอะไรบ้าง
```

หลักการของพรอมต์: [พื้นฐานพรอมต์](/th/prompts/basics/)
