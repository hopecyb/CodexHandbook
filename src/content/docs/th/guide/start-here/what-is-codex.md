Codex คือ **AI Agent สำหรับการเขียนโปรแกรมและการทำงาน** จาก OpenAI คุณให้เป้าหมาย แล้วมันจะใช้ไฟล์โปรเจกต์ เครื่องมือ และการอนุมัติของคุณเพื่ออ่าน แก้ไข รันคำสั่ง และสร้างผลลัพธ์ จากนั้นส่งขั้นตอนและการเปลี่ยนแปลงให้คุณตรวจ

มันคล้ายเพื่อนร่วมงานดิจิทัลที่ใช้เครื่องมือเป็น คุณระบุเป้าหมาย ขอบเขต และเกณฑ์ยอมรับ ส่วนมันค้นข้อมูล แก้ไฟล์ และรันขั้นตอน แต่การตัดสินใจสุดท้ายยังเป็นของคุณ

ให้ยึด [OpenAI Codex](https://developers.openai.com/codex) เป็นเอกสารผลิตภัณฑ์ทางการ คู่มือนี้เป็นคู่มือโอเพนซอร์สของชุมชนสำหรับเรียนรู้อย่างเป็นระบบและลงมือใช้จริง ไม่ได้แทนเอกสารทางการ

## ต่างจากแชต AI ทั่วไปอย่างไร

เมื่อเห็น Codex ครั้งแรก หลายคนคิดว่าเป็น “แชต AI ที่เก่งขึ้น” ความต่างหลักอยู่ที่ความสามารถในการลงมือทำ

| สิ่งที่คุณใช้ตามปกติ | เข้าใจได้ดังนี้ |
|---|---|
| Chatbot ทั่วไป | ให้คำแนะนำ อธิบายแนวคิด เขียนข้อความ |
| Codex | นอกจากตอบแล้ว ยังอาจ **อ่านไฟล์ แก้ไฟล์ รันคำสั่ง และสร้าง Artifact** |

เครื่องมือแชตทั่วไปเน้นการตอบ ส่วน Codex ลงมือทำโดยตรงภายในขอบเขตที่คุณอนุญาต

## งานแบบใดเหมาะกับ Codex

หากงานไม่ได้มีแค่ “คุยกัน” แต่ต้องอ่านข้อมูล แก้สิ่งต่าง ๆ รันขั้นตอน หรือสร้างผลลัพธ์ ก็เหมาะที่จะทำร่วมกับ Codex

ถ้าต้องการเพียงถามแนวคิด หาแรงบันดาลใจหนึ่งประโยค หรือขอคำแนะนำทั่วไป แชต AI ทั่วไปก็รองรับได้

## ใช้กับเรื่องใดได้บ้าง

แม้ไม่ใช่โปรแกรมเมอร์ ก็เข้าใจจากสถานการณ์เหล่านี้ได้:

- **อ่านและจัดข้อมูล**: สรุปเอกสาร บันทึกการประชุม ภาพหน้าจอ ตาราง
- **เขียนและแก้เนื้อหา**: ขัดเกลาบทความ เพิ่มสารบัญ แก้เอกสารคำอธิบาย
- **ทำโปรเจกต์เล็ก**: สร้างหน้า แก้การตั้งค่า เพิ่มเทมเพลต
- **ค้นและแก้ปัญหา**: ช่วยหาว่าผิดตรงไหนและควรดูอะไรต่อ
- **ทำงานซ้ำเป็นอัตโนมัติ**: ให้ลองรันกระบวนการคงที่หนึ่งรอบ

ผู้เขียนโค้ดนำไปใช้ในกระบวนการพัฒนาได้ ส่วนผู้ที่ไม่เขียนโค้ดก็ใช้เป็นผู้ช่วยที่ลงมือทำตามขั้นตอนได้

## ทำอะไรได้

- **ทำความเข้าใจ**: สรุปข้อมูลใน Repository เอกสาร ตาราง และภาพหน้าจอ
- **สร้างและแก้ไข**: เขียนต้นฉบับ แก้โค้ด สร้างหน้าและการตั้งค่า
- **ดำเนินการ**: รันคำสั่งเทอร์มินัล ค้นหา และเรียกดูภายใต้การอนุญาตของคุณ
- **ทำงานร่วมกัน**: ทำงานต่อเนื่องข้าม App, CLI, IDE และ Cloud
- **ขยายความสามารถ**: เชื่อมกระบวนการซ้ำและระบบภายนอกผ่าน Skills, Plugins, MCP และ Hooks (บทขั้นสูงจะเพิ่มภายหลัง)

## ทำอะไรไม่ได้ (สำคัญ)

- แทนความรับผิดชอบสุดท้ายของคุณต่อข้อเท็จจริง ความปลอดภัย และการตัดสินใจทางธุรกิจไม่ได้
- รับประกันไม่ได้ว่าผลครั้งแรกถูกต้องทั้งหมด ต้องตรวจผลได้
- ข้าม Sandbox เครือข่าย หรือนโยบายองค์กรโดยไม่ได้รับอนุญาตไม่ได้
- ไม่ควรใช้เป็น “Pipeline เผยแพร่อัตโนมัติที่ไม่ต้องตรวจรับ”

## หลักตัดสินใจพื้นฐานเมื่อใช้งาน

ใช้ Codex เป็นผู้ช่วย แต่อย่าส่งมอบความรับผิดชอบไปด้วย

ให้ช่วยทำ ค้น และแก้ก่อนก็ได้ แต่สุดท้ายต้องยืนยันเองว่า:

- แก้ถูกจุดหรือไม่
- เข้าใจเป้าหมายผิดหรือไม่
- ข้อเท็จจริงที่ให้มาน่าเชื่อถือหรือไม่
- การเปลี่ยนแปลงมีผลข้างเคียงหรือไม่

## ขั้นตอนทั่วไป

ขั้นตอนทั่วไปมักเป็นดังนี้:

1. คุณระบุเป้าหมาย
2. มันตอบหรือเสนอแผนก่อน
3. หากต้องแก้ไฟล์หรือรันคำสั่ง อาจขออนุมัติจากคุณ
4. เมื่อเสร็จ จะบอกว่าเปลี่ยนอะไรไป
5. คุณตรวจว่าผลตรงตามที่คาดหรือไม่

ดูตัวอย่างครบวงจรที่ [รันงานแรก](/th/guide/getting-started/run-your-first-task/)

## ช่องทางใช้งานหลัก

| ช่องทาง | เหมาะกับ |
|---|---|
| Desktop App | ค่าเริ่มต้นสำหรับผู้เริ่มต้น มองเห็นโปรเจกต์ งาน และการตรวจ diff |
| CLI | ผู้ใช้เทอร์มินัล สคริปต์ และระบบอัตโนมัติ |
| ส่วนขยาย IDE | ทำงานในเอดิเตอร์โดยใช้ไฟล์เปิดและส่วนที่เลือกเป็นบริบท |
| Web / Cloud | เชื่อม Repository สภาพแวดล้อม Cloud และงานระยะยาว |
| มือถือและระยะไกล | เฝ้าดู อนุมัติ และติดตามแบบเบา |

## อ่านต่อ

หากต้องการจำเพียงสามข้อ ให้จำดังนี้:

1. Codex ไม่ได้มีไว้แชตเท่านั้น แต่ลงมือทำหลังได้รับอนุญาต
2. งานต้องระบุเป้าหมาย ขอบเขต และ “แบบไหนจึงถือว่าเสร็จ” ให้ชัด
3. ต้องตรวจทุกผลลัพธ์ อย่าเชื่อโดยไม่ตรวจ
