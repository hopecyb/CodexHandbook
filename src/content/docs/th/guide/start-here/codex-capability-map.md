คู่มือนี้มีหลายโมดูล จึงอ่านกระจัดกระจายได้ง่ายในครั้งแรก หน้านี้รวมความสามารถหลักไว้ในภาพเดียวเพื่อให้เห็นโครงสร้างอย่างรวดเร็ว

จุดที่มักติดมีสองแบบ:

- อ่านหลายหน้าไปมา แต่ยังไม่รู้ว่าควรเสริมส่วนใดก่อน
- เริ่มจาก MCP ระบบอัตโนมัติ หรือส่วนขยายทันที ทั้งที่พื้นฐานยังไม่ชัด

จัดกรอบใหญ่ให้ชัดก่อน แล้วการค้นหัวข้อเฉพาะภายหลังจะง่ายขึ้นมาก

Codex ไม่ใช่แค่ช่องแชต แต่มีความสามารถหลายชั้นอยู่เบื้องหลัง:

```text
เป้าหมายและพรอมต์
  → บริบท (โปรเจกต์ / ไฟล์ / บทสนทนา)
    → เครื่องมือ (ไฟล์ เทอร์มินัล ค้นหา เบราว์เซอร์…)
      → การทำงานของ Agent (วางแผน ลงมือ กำกับ ส่งต่องาน)
        → การตรวจสอบคุณภาพและการอนุมัติโดยมนุษย์
      → ส่วนขยายและระบบอัตโนมัติ (Skills / MCP / Hooks… ขั้นสูง)
            → การกำกับดูแลของทีม (Milestone ถัดไป)
```

## โครงสร้างโดยรวม

มอง Codex เป็นสามชั้นได้:

- ชั้นแรก: คุณสื่อสารอย่างไรให้รู้ว่าต้องทำอะไร
- ชั้นสอง: ใช้บริบทและเครื่องมือใดทำงานให้สำเร็จ
- ชั้นสาม: ทำให้วิธีร่วมงานนี้บันทึกและนำกลับมาใช้ซ้ำได้อย่างไร

ช่วงเริ่มต้น สองชั้นแรกสำคัญกว่า อธิบายงานให้ชัด ทำผลลัพธ์ให้ครบวงจร แล้วค่อยเรียนส่วนขยายขั้นสูง

## ความเข้าใจผิดที่พบบ่อย

### ความสามารถยิ่งสูง ไม่ได้แปลว่าควรเรียนก่อน

Skills, MCP, Hooks และระบบอัตโนมัติมีประสิทธิภาพมาก แต่เน้นขยายประสิทธิภาพและนำกลับมาใช้ในวงกว้าง ไม่ใช่จุดที่ผู้เริ่มต้นมักติดที่สุด

หากพื้นฐานอย่างพรอมต์ บริบท และการเลือกเครื่องมือยังไม่ชัด ก็ใช้ความสามารถส่วนขยายผิดทางได้ง่าย

### ใช้แผนภาพนี้เป็นลำดับอ่านได้ด้วย

ไม่จำเป็นต้องอ่านทุกหน้าตามสารบัญเว็บไซต์ ให้เดินตามลำดับนี้:

1. เข้าใจก่อนว่า Codex ทำงานอย่างไร
2. เรียนรู้การมอบหมายงาน ให้บริบท และตรวจผล
3. เมื่อใช้คล่องแล้วค่อยพิจารณาการตั้งค่า ส่วนขยาย และระบบอัตโนมัติ
