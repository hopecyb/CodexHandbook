คู่มือนี้เขียนขึ้นสำหรับผู้ที่เพิ่งเริ่มใช้ Codex อย่างจริงจัง

ไม่ได้สมมติว่าคุณเข้าใจสิ่งเหล่านี้แล้ว:

- เทอร์มินัล
- Git
- Agent
- วิศวกรรมพรอมต์
- สภาพแวดล้อม Cloud

หากรู้อยู่แล้วจะอ่านได้เร็วขึ้น แต่ถ้ายังไม่คุ้น เนื้อหาก็พยายามเขียนให้ตามได้ง่าย

## ผู้อ่านสี่กลุ่ม

| ผู้อ่าน | วิธีใช้คู่มือนี้ |
|---|---|
| ผู้เริ่มต้นด้าน AI | เริ่มจาก “คืออะไร” ไปสู่งานแรกที่ปลอดภัย พร้อมคำอธิบายศัพท์ |
| ผู้สร้างสรรค์ | งานวิจัย การเขียน งานนำเสนอ และ Prototype อ่านภาพรวมก่อนแล้วค่อยเข้าหัวข้อความสามารถ |
| นักพัฒนา | ทำความเข้าใจโค้ด นำไปใช้ ทดสอบ ตรวจทาน และทำระบบอัตโนมัติ |
| ทีม | คำแนะนำร่วม สิทธิ์ คุณภาพ และการกำกับดูแล (เนื้อหาเชิงลึกอยู่ใน Milestone ถัดไป) |

## ไม่ต้องแบ่งคนสี่กลุ่มนี้อย่างตายตัว

ในความเป็นจริง หลายคนอยู่สองหรือสามกลุ่มพร้อมกัน เช่น:

- เขียนโค้ดได้นิดหน่อย แต่เพิ่งเริ่มใช้ Agent จริงจัง
- เดิมเป็นผู้สร้างเนื้อหา แล้วเริ่มให้ Codex ช่วยแก้เว็บไซต์
- หัวหน้าทีมที่ทดลองใช้ในฐานะบุคคลก่อน

ดังนั้นสี่กลุ่มนี้ใกล้เคียงกับ **สถานการณ์ใช้งาน** สี่แบบ ไม่ใช่ตัวตนที่แยกขาดจากกัน

## กลุ่มเป้าหมายหลัก

เนื้อหาหลักเขียนให้ **ผู้อ่านที่ไม่คุ้นกับเทอร์มินัลและ Agent** เนื้อหาสำหรับนักพัฒนาและทีมไม่ได้ตื้นลง แต่จะค่อย ๆ ขยายตามเส้นทางการเรียนรู้

## ความเข้าใจผิดที่พบบ่อย

### 1. คู่มือนี้ไม่ได้มีไว้สำหรับโปรแกรมเมอร์เท่านั้น

หากงานของคุณมีเรื่องต่อไปนี้ คู่มือนี้ก็เหมาะ:

- เขียนและจัดเนื้อหา
- วิจัยและเปรียบเทียบข้อมูล
- ดูแลเอกสาร
- แก้ Prototype และหน้าเว็บ
- จัดกระบวนการทีม

### 2. แม้มีพื้นฐานอยู่แล้ว ก็อ่านหน้าแรก ๆ ได้

หน้า “ก่อนเริ่ม” “แนวคิดพื้นฐาน” และ “งานแรก” ไม่ได้มีไว้ปูพื้นเฉพาะผู้ไม่มีพื้นฐาน แต่ช่วยปรับความเข้าใจได้เร็วว่า:

- Codex ทำงานอย่างไร
- ควรมอบหมายงานอย่างไร
- ควรหลีกเลี่ยงความเสี่ยงใดล่วงหน้า

### 3. ไม่ต้องอ่านตั้งแต่ต้นจนจบ

หลายคนอ่านดังนี้:

1. อ่านหน้าเริ่มต้น
2. ทำงานเล็กงานแรกให้สำเร็จ
3. ข้ามไปอ่านตามบทบาทของตน

## ไม่ควรใช้คู่มือนี้เป็นอะไร

- Changelog ทางการฉบับเต็มของผลิตภัณฑ์ใดผลิตภัณฑ์หนึ่ง
- Repository สคริปต์ที่นำขึ้น Production ได้โดยไม่ตรวจสอบ
- สิ่งทดแทนนโยบายความปลอดภัยและการปฏิบัติตามข้อกำหนดภายในองค์กร

## เหมาะกับใคร

คู่มือนี้ควรค่าแก่การอ่านหากคุณต้องการ:

- เริ่มใช้ Codex อย่างปลอดภัย
- พอใช้เป็นแล้ว แต่มอบหมายงานได้ไม่สม่ำเสมอ
- เปลี่ยนวิธีใช้ส่วนบุคคลเป็นกระบวนการที่ทีมใช้ซ้ำได้
- ไม่ได้มาจากสายพัฒนา แต่ต้องการเชื่อม AI เข้ากับงานประจำจริง
