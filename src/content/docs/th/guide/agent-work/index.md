การทำงานของ Agent มุ่งพางานไปสู่ **สถานะที่เสร็จและตรวจสอบได้** บทนี้อธิบายว่าเมื่อใดควรวางแผนก่อน เมื่อใดควรแยกงานย่อย เมื่อใดควรปรับทิศทางระหว่างทาง และเมื่อใดควรส่งต่องานหรือกลับมาทำต่อ

บทนี้ว่าด้วยวิธีทำงานร่วมกัน ไม่ใช่ฟีเจอร์ใดฟีเจอร์หนึ่ง

ความยากของหลายงานไม่ได้อยู่ที่การบอกความต้องการ แต่อยู่ที่การพางานไปจนถึงจุดที่ “เสร็จจริงและตรวจได้”

## บทนี้กล่าวถึงอะไร

- เมื่องานซับซ้อน จะสรุปให้เป็นแผนก่อนอย่างไร
- เมื่อพบว่าทิศทางเริ่มคลาดระหว่างทำงาน จะปรับทีละน้อยอย่างไร
- ปัญหาย่อยแบบใดควรมอบหมายให้ Agent ย่อย
- เมื่องานระยะยาวหยุดชะงัก จะส่งต่องานและกลับมาทำต่ออย่างไร

## กรอบที่ใช้บ่อย

โดยทั่วไป การทำงานของ Agent แบ่งเป็นสี่การกระทำต่อเนื่อง:

```text
ทำความเข้าใจก่อน → วางแผน → ปรับทิศทางระหว่างลงมือ → ส่งต่องาน/ปิดงาน
```

หากขาดขั้นใดขั้นหนึ่ง ผลที่พบบ่อยคือ:

- ขาดความเข้าใจ: แก้ผิดทิศ
- ขาดแผน: ทำไปครึ่งทางจึงพบว่าขอบเขตควบคุมไม่ได้
- ขาดการปรับทิศ: ยิ่งแก้ยิ่งคลาด
- ขาดการส่งต่องาน: เมื่องานยาวขาดช่วง ไม่มีใครรู้ว่าทำถึงไหนแล้ว

## ความเข้าใจผิดที่พบบ่อย

### 1. การทำงานของ Agent คือการเขียน prompt ให้ยาวขึ้น

ยังไม่พอ

Prompt เป็นเพียงจุดเริ่มต้น ปัจจัยที่กำหนดคุณภาพงานจริงยังรวมถึง:

- มีแผนหรือไม่
- มีการปรับทิศทางระหว่างทางหรือไม่
- แยกส่วนที่ซับซ้อนออกมาหรือไม่
- ทิ้งสถานะที่รับช่วงต่อได้ไว้หรือไม่

### 2. เปลี่ยนทิศระหว่างทางแปลว่างานก่อนหน้าสูญเปล่า

หลายครั้ง การลงมือไปพร้อมกับค่อย ๆ จำกัดขอบเขตเป็นเรื่องปกติ ไม่จำเป็นต้องทำเหมือนว่าสามารถระบุทุกอย่างให้ถูกตั้งแต่ครั้งแรก

### 3. ยิ่งแยก Agent ย่อยมากยิ่งมีประสิทธิภาพ

ไม่เสมอไป

หากขอบเขตไม่ชัด ยิ่งมีงานย่อยมาก เธรดหลักยิ่งสับสน

## เริ่มจากเวิร์กโฟลว์ขั้นต่ำนี้

หากต้องการทำงานให้เสร็จด้วยวิธีพื้นฐานที่สุด ให้ทำตาม 4 ขั้นตอนนี้:

1. อธิบายงานให้ชัด
2. ถ้างานซับซ้อน ให้ขอแผนก่อน
3. ปรับทิศทางทีละน้อยตามผลลัพธ์ระหว่างดำเนินการ
4. ก่อนจบ ขอผลลัพธ์ที่ตรวจสอบได้

เมื่อใช้ 4 ขั้นตอนนี้ได้คล่องแล้ว การเรียนรู้เรื่อง Agent ย่อยและการส่งต่องานจะเป็นธรรมชาติมากขึ้น

การทำงานของ Agent ให้ความสำคัญกับการพางานไปในทิศที่ถูกอย่างต่อเนื่องตลอดการวางแผน ลงมือ ปรับทิศ และปิดงาน

## ข้อผิดพลาดที่พบบ่อย

- ใช้ Agent เหมือนช่องค้นหา โดยให้เพียงเป้าหมายคลุมเครือหนึ่งประโยค
- คิดว่า “เปลี่ยนคำสั่งกลางทาง” เท่ากับต้องรื้อทำใหม่ทั้งหมด
- เป็นงานยาวแต่ไม่มีสิ่งส่งมอบสำหรับรับช่วงต่อ
- แยกงานย่อยโดยไม่กำหนดขอบเขต จนเธรดหลักยิ่งสับสน
