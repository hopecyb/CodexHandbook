ใน IDE นอกจาก Codex จะอ่าน prompt แล้ว ยังได้รับ **สถานะเอดิเตอร์** โดยอัตโนมัติด้วย นี่คือข้อได้เปรียบหลักของ IDE เมื่อเทียบกับ CLI การเข้าใจว่าบริบทมาจากไหนช่วยลดปัญหา “เปิดไฟล์อยู่แท้ ๆ แต่ Codex กลับไม่เห็น”

Codex ใน IDE ไม่ได้ดูเพียงสิ่งที่คุณพูด แต่ยังอ้างอิงเนื้อหาที่คุณกำลังดูในเอดิเตอร์ด้วย

## เนื้อหาในหน้านี้

- IDE แนบบริบทใดโดยอัตโนมัติ
- บริบทจากไฟล์แบบ @ ส่วนที่เลือก และ AGENTS.md ทำงานร่วมกันอย่างไร
- วิธีลดสัญญาณรบกวนและเพิ่มความแม่นยำ

## เวิร์กโฟลว์ที่แนะนำ

1. **เปิดรีโพซิทอรีจากรากเวิร์กสเปซ** อย่าเปิดเพียงโฟลเดอร์ย่อย (ข้อยกเว้นสำหรับ monorepo ดูเอกสารทีม)
2. เมื่อแก้ตรรกะเฉพาะจุด ให้ **เลือกโค้ดที่เกี่ยวข้องก่อน** แล้วจึงอธิบายงาน → [ส่วนที่เลือกและไฟล์ที่เปิดอยู่](/th/guide/ide/selected-code-and-open-files/)
3. งานข้ามโมดูลให้ใช้ `@` ระบุไฟล์สำคัญ อย่าคิดว่า “Codex จะค้นเจอเอง”
4. ในเซสชันยาว ให้ [บีบอัดบริบท](/th/guide/context/compaction/) เป็นระยะ หรือเปิดเธรดใหม่

## ความต่างจาก CLI

| | ส่วนขยาย IDE | CLI |
|---|---|---|
| การรับรู้ไฟล์ | สูง (เปิดแล้วเป็นบริบททันที) | ต้องใช้ `--cd` / `-C` และเครื่องมืออ่านดิสก์ |
| ส่วนที่เลือก | รองรับโดยตรง | ต้องวางข้อความหรือระบุพาธ |
| เหมาะกับ | การแก้ระดับบรรทัด อธิบายโค้ด | สคริปต์ CI และสภาพแวดล้อมที่ไม่มี GUI |

## คำถามที่พบบ่อย

### 1. เปิดไฟล์อยู่แล้ว ทำไม Codex ยังไม่แก้ตามที่ต้องการ

เพราะ “เปิดไฟล์แล้ว” ไม่ได้แปลว่า “เน้นจุดสำคัญชัดพอ” เสมอไป

หากขอบเขตงานยังคลุมเครือ Codex อาจไปดูเนื้อหาอื่นที่เกี่ยวข้อง หรือไม่จับส่วนที่คุณสนใจที่สุด

### 2. เปิดไฟล์ยิ่งมากยิ่งดีหรือไม่

การเปิดไฟล์ที่ไม่เกี่ยวข้องมากเกินไปทำให้บริบทมีสัญญาณรบกวนและเจือจางจุดสำคัญ

### 3. IDE มีบริบทอัตโนมัติแล้ว แปลว่าไม่ต้องอธิบายให้ชัดอีกหรือไม่

บริบทอัตโนมัติช่วยได้ แต่แทนคำอธิบายงานไม่ได้ คุณยังต้องระบุเป้าหมาย ข้อจำกัด และเกณฑ์เสร็จด้วยตัวเอง

บริบท IDE ช่วยคุณ แต่จะไม่เดาแทน ยิ่งขอบเขตไฟล์แม่น ผลลัพธ์มักยิ่งมั่นคง

## ข้อมูลละเอียดอ่อน

อย่าเปิด `.env` ที่มีคีย์ค้างไว้ด้านหน้าเอดิเตอร์ ดู [บริบทละเอียดอ่อน](/th/guide/context/sensitive-context/)

ลบหรือปกปิดข้อมูลละเอียดอ่อนใน log และข้อมูลลูกค้าก่อนวาง IDE จะไม่ตัดสินเรื่องการปฏิบัติตามข้อกำหนดแทนคุณโดยอัตโนมัติ

## ข้อผิดพลาดที่พบบ่อย

- คาดหวังว่าจะอ่าน `AGENTS.md` ได้ในโหมดไฟล์เดียวที่ไม่มีเวิร์กสเปซ
- เปิดไฟล์ใหญ่ที่ไม่เกี่ยวข้องหลายสิบไฟล์จนใช้หน้าต่างบริบท
- พูดเพียงว่า “ฟังก์ชันนี้” แต่ไม่ได้เลือกหรือระบุไฟล์ด้วย @

## เช็กลิสต์ยอมรับงาน

- [ ] รากเวิร์กสเปซถูกต้อง
- [ ] เปิดหรือระบุด้วย @ ไฟล์ที่เกี่ยวข้องกับงาน 1–3 ไฟล์แล้ว
- [ ] คำสั่งทดสอบใน `AGENTS.md` ตรงกับเทอร์มินัล IDE
