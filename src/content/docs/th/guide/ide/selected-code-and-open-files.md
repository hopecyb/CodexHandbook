ส่วนขยาย IDE เหมาะกับการแก้ไขแบบ **ขอบเขตเล็ก ความแม่นยำสูง**: คุณเลือกโค้ดส่วนหนึ่ง อธิบายเจตนา แล้ว Codex แก้ภายในบริบทใกล้เคียง หน้านี้อธิบายวิธีใช้ส่วนที่เลือกกับไฟล์ที่เปิดอยู่เพื่อลดขอบเขตและป้องกันการแก้ผิดจุด

หน้าที่ของส่วนที่เลือกเรียบง่าย: บอก Codex ให้โฟกัสตรงนี้และอย่าขยายขอบเขตเอง

## เนื้อหาในหน้านี้

- เลือกอย่างไรระหว่างส่วนที่เลือก ทั้งไฟล์ และพาธแบบ @
- จัดบริบทอย่างไรเมื่อรีแฟกเตอร์หลายไฟล์
- ลดปัญหา “แก้ไฟล์ที่ไม่เกี่ยวข้องจำนวนมาก”

## สามวิธีกำหนดขอบเขต

| วิธี | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|
| **ส่วนที่เลือก** | ฟังก์ชันเดียว คอมโพเนนต์เดียว หรือใกล้ error stack | เลือก `parseUser()` แล้วขอให้จัดการค่าว่าง |
| **ไฟล์ที่เปิดอยู่** | ต้องเข้าใจความเชื่อมโยงหลายจุดในไฟล์ | เปิด `auth.ts` + `auth.test.ts` |
| **พาธแบบ @** | ข้ามไดเรกทอรีหรือไฟล์ที่ยังไม่เปิด | ให้ `@src/api/client.ts` จัด type ให้ตรงกับแบ็กเอนด์ |

แนวคิดเชิงลึก: [บริบทไฟล์และไดเรกทอรี](/th/guide/context/file-and-folder-context/)

## วิธีขั้นต่ำที่ใช้ได้จริง

1. เลือก **ส่วนที่เกี่ยวข้องน้อยที่สุด** โดยทั่วไป 10–80 บรรทัด แล้วระบุเป้าหมายกับ [นิยามของคำว่าเสร็จ](/th/prompts/define-done/) ใน prompt
2. หากเกี่ยวข้องกับ caller ให้เปิดหรือระบุด้วย @ ไฟล์ต้นทางอีก 1–2 ไฟล์
3. สั่งว่า “แก้เฉพาะไฟล์ที่เกี่ยวกับ X; แสดงรายชื่อไฟล์ที่จะเปลี่ยนก่อนลงมือ”
4. ยอมรับทีละส่วนใน diff ของ IDE อย่ายอมรับทั้งหมด

## งานหลายไฟล์

```text
เปิด: ไฟล์ implementation + ไฟล์ทดสอบ + นิยาม type
ส่วนที่เลือก: ไม่บังคับ—เริ่มจากฟังก์ชันทางเข้า
Prompt: ระบุขอบเขตโมดูลและไดเรกทอรีที่ห้ามแก้
```

งานรีแฟกเตอร์ใหญ่เหมาะกับ [worktree ในเดสก์ท็อป App](/th/guide/desktop-app/worktrees/) หรือ [โหมดวางแผน](/th/guide/agent-work/planning/) มากกว่า ส่วน IDE เหมาะกับการเก็บงานและ commit ทีละน้อย

## คำถามที่พบบ่อย

### 1. ต้องเลือกโค้ดทุกครั้งหรือไม่

ไม่จำเป็น แต่หากคุณรู้อยู่แล้วว่าจุดสำคัญอยู่ในส่วนสั้น ๆ การเลือกมักมั่นคงกว่าการพูดเพียง “ช่วยแก้ฟังก์ชันนี้”

### 2. เลือกมากขึ้นไม่ได้แปลว่าปลอดภัยขึ้นเสมอ

เลือกใหญ่เกินไปเท่ากับผ่อนขอบเขตอีกครั้ง แต่เลือกเล็กเกินไปอาจขาดบริบทที่จำเป็น เกณฑ์ที่ใช้ได้จริงกว่าคือ “พอดีกับงาน”

### 3. ไฟล์ที่เปิดอยู่ต่างจากพาธ `@` อย่างไร

แยกง่าย ๆ ดังนี้:

- **ไฟล์ที่เปิดอยู่**: ให้ Codex เห็นว่าคุณกำลังดูอะไร
- **พาธแบบ @**: ระบุชัดว่าต้องรวมไฟล์ใดเข้ามาด้วย

สาระของการใช้ส่วนที่เลือกและไฟล์ที่เปิดอยู่คือพยายามไม่ดึงขอบเขตที่ไม่เกี่ยวข้องเข้ามา

## ใช้ร่วมกับการตรวจทาน

ก่อนยอมรับ ให้เทียบกับ [ตรวจ diff](/th/guide/quality/review-diffs/):

- เปลี่ยนเฉพาะไฟล์ที่ตกลงกันหรือไม่
- มีการลบโดยไม่ตั้งใจนอกส่วนที่เลือกหรือไม่
- การทดสอบครอบคลุม branch ใหม่หรือไม่

ด้านผลิตภัณฑ์: [ตรวจการเปลี่ยนแปลงใน IDE](/th/guide/ide/reviewing-changes/)

## ข้อผิดพลาดที่พบบ่อย

| ข้อผิดพลาด | ผลลัพธ์ |
|---|---|
| เลือกทั้งไฟล์หลายพันบรรทัด | เปลืองบริบทและขยายพื้นที่แก้ไขมากเกินไป |
| ไม่เลือกอะไรแล้วพูดเพียง “ปรับให้ดีขึ้น” | โมเดลขยายขอบเขตเอง |
| ยอมรับคำแนะนำทั้งหมดโดยไม่อ่าน diff | เกิด style drift หรือช่องโหว่ความปลอดภัย |
