IDE เก็บการทำงานวนซ้ำอย่างรวดเร็วไว้ในเครื่องได้ และเชื่อมต่อ Codex web เพื่อมอบหมายงานที่ใช้เวลานานกว่าให้ Cloud ได้เช่นกัน จุดเริ่มยังอยู่ในเอดิเตอร์ แต่สภาพแวดล้อมการทำงาน สถานะรีโพซิทอรี และขอบเขตเครือข่ายเปลี่ยนเป็นบนคลาวด์แล้ว

## ควรมอบหมายเมื่อใด

| ทำต่อในเครื่อง | มอบหมายให้ Cloud |
|---|---|
| ต้องแก้ไปมารวดเร็วกับส่วนที่เลือกอยู่ | งานมีหลายขั้นตอนและใช้เวลานาน |
| พึ่งพาสถานะในเครื่องที่ยังไม่ได้ commit | อินพุตอยู่ในรีโพซิทอรีระยะไกลหรืออัปโหลดได้แล้ว |
| ต้องใช้เครื่องมือเฉพาะในเครื่อง | สภาพแวดล้อมคลาวด์สร้าง dependency และกระบวนการตรวจสอบซ้ำได้ |
| คุณต้องควบคุมโปรเซสแบบเรียลไทม์ | คุณต้องการทำงานอื่นในเครื่องต่อ |

คลาวด์จะไม่มีไฟล์ที่ยังไม่ได้ commit ข้อมูลประจำตัว หรือโปรเซสที่กำลังทำงานบนเครื่องของคุณโดยอัตโนมัติ ก่อนมอบหมายต้องระบุให้ชัดว่างานเริ่มจากรีโพซิทอรี branch และ commit ใด

## เช็กลิสต์ก่อนมอบหมาย

- [ ] ลงชื่อเข้าใช้ด้วยบัญชี ChatGPT แล้ว; Codex Cloud ไม่รับการลงชื่อเข้าใช้ด้วย API key
- [ ] เชื่อมต่อ GitHub แล้ว หรือกำลังใช้การผสาน GitLab Beta ที่รองรับในปัจจุบัน
- [ ] สภาพแวดล้อมคลาวด์เรียกสคริปต์ติดตั้งและตรวจสอบได้
- [ ] ตั้งค่าตัวแปรและ secrets ที่จำเป็นในสภาพแวดล้อมแล้ว โดยไม่เขียนลงในพรอมต์
- [ ] จัดการการเปลี่ยนแปลงในเครื่องที่ยังไม่ได้ commit แล้ว หรือระบุชัดว่าไม่รวมในงาน
- [ ] เขียนเป้าหมาย พาธที่อนุญาต พื้นที่ห้ามแก้ และคำสั่งยอมรับงานไว้อย่างชัดเจน

## ตัวอย่างครบวงจร

```text
เป้าหมาย: แก้ปัญหาที่โมดูล retry ยังรอเพิ่มอีกหนึ่งครั้งหลังถึงขีดจำกัดแล้ว
จุดเริ่ม: รีโพซิทอรี acme/retry-service, branch fix/retry-limit
ขอบเขต: แก้เฉพาะ src/retry.ts และการทดสอบที่เกี่ยวข้อง
ข้อจำกัด: ห้ามอัปเกรด dependency, ห้ามแก้ public API, ห้าม push ไป main
เกณฑ์ยอมรับ: เรียก pnpm test -- retry และ pnpm typecheck; แสดง diff กับผลคำสั่ง
```

เวิร์กโฟลว์ที่แนะนำ:

1. แนบไฟล์หรือส่วนที่เกี่ยวข้องใน IDE แล้วตรวจขอบเขตปัญหาก่อน
2. เลือก Cloud เพื่อทำงานระยะยาวต่อ
3. ดูแผน ความคืบหน้า และผลการตรวจสอบใน Cloud
4. กลับไปที่ IDE หรือ Web เพื่อตรวจผลลัพธ์ที่พร้อม review
5. ดึง branch หรือรับการเปลี่ยนแปลงผ่าน PR
6. ทดสอบซ้ำในสภาพแวดล้อมภายในเครื่องที่เชื่อถือได้ และให้คนตรวจทานก่อน merge

คำว่า “เสร็จ” บนคลาวด์หมายถึงการทำงานระยะไกลสิ้นสุด ไม่ได้แปลว่าโค้ดพร้อม merge ความต่างของ dependency ระยะไกล ระบบปฏิบัติการ หรือข้อมูลประจำตัวจากเครื่อง/CI ยังอาจทำให้เกิดปัญหาเฉพาะสภาพแวดล้อมได้

## ความขัดแย้งและความปลอดภัย

- หลังมอบหมาย อย่าให้ในเครื่องกับบนคลาวด์แก้ไฟล์เดียวกันพร้อมกัน
- อย่าวางคีย์โปรดักชันในพรอมต์ ให้ใช้ environment secrets
- อย่าถือว่าการเข้าถึงเครือข่ายเป็นความสามารถเริ่มต้นของ Cloud ให้กำหนดตาม allowlist ของสภาพแวดล้อม
- push, เปิด PR และ merge เป็นคนละการดำเนินการ การ merge ต้องยังมีด่านตรวจจากคนหรือ CI
