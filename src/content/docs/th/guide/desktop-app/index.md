Desktop App เป็นจุดเริ่มต้นหลักสำหรับผู้เริ่มต้น เพราะแสดงโปรเจกต์ งาน diff และการอนุมัติให้เห็นชัด

สำหรับผู้ที่ยังไม่คุ้นกับ command line หรือปลั๊กอิน IDE นี่ก็เป็นทางเริ่มต้นที่ง่ายกว่า

แอปไม่ได้มีไว้เพียง “แชต” แต่รวมโปรเจกต์ การเปลี่ยนแปลง การอนุมัติ และการตรวจสอบไว้ในอินเทอร์เฟซเดียว

![ภาพประกอบ: คอนโซลเดสก์ท็อปแสดงการ์ดงานและวงแหวนความคืบหน้าหลายรายการ โดยการ์ดหนึ่งเปิดเป็น diff แบบเทียบสองฝั่งพร้อมสวิตช์อนุมัติ](/illustrations/desktop-app.webp)

## เนื้อหาในบทนี้

- การทำงานใดใน Desktop App ที่ควรเรียนก่อน
- ฟีเจอร์ใดเหมาะสำหรับผู้เริ่มต้น และฟีเจอร์ใดเรียนภายหลังได้
- เมื่อมีการเปลี่ยนแปลง คำขออนุมัติ หรือปัญหา ควรดูตรงไหน

## เริ่มจากรู้จักสามอย่างนี้

ไม่ต้องเรียนทุกฟีเจอร์พร้อมกัน  
ให้เริ่มจากการทำงานหลักสามประเภท:

1. ป้อนงานที่ไหน
2. ดูการเปลี่ยนแปลงที่ไหน
3. อนุมัติหรือปฏิเสธการทำงานที่ไหน

เมื่อทำครบสามขั้นตอนนี้ได้ คุณก็จบวงจรงานพื้นฐานหนึ่งรอบแล้ว

## ความเข้าใจผิดที่พบบ่อย

### 1. Desktop App เป็นเพียงหน้ากราฟิกของ CLI หรือไม่

แอปจะแสดงขั้นตอนสำคัญของการทำงานร่วมกัน:

- งานปัจจุบัน
- แผนและการเรียกใช้เครื่องมือ
- การเปลี่ยนแปลงไฟล์
- การอนุมัติ
- การตรวจทานผลลัพธ์

### 2. ต้องเข้าใจทุกปุ่มก่อนเริ่มหรือไม่

ช่วงแรกเพียงรู้จัก:

- ตำแหน่งป้อนงาน
- ตำแหน่งดู diff
- ตำแหน่งอนุมัติหรือปฏิเสธ

ก็เพียงพอแล้ว

### 3. Desktop App เหมาะกับมือใหม่ แปลว่าไม่เหมาะกับงานจริงหรือไม่

งานจริงจำนวนมากก็ทำใน Desktop App ได้ โดยเฉพาะเมื่อคุณให้ความสำคัญกับการตรวจทานแบบเห็นภาพและความโปร่งใสของกระบวนการ

## ลำดับเริ่มต้น

เมื่อใช้ Desktop App ครั้งแรก ให้ทำตามลำดับนี้:

1. ติดตั้งและทำความรู้จักอินเทอร์เฟซ
2. เลือกโปรเจกต์ให้ถูก
3. เปิดงานขนาดเล็ก
4. ดูการเปลี่ยนแปลง
5. ฝึกอนุมัติและปฏิเสธ
6. จากนั้นค่อยเรียน Agent แบบขนาน, worktree และงาน Cloud

วิธีนี้มักง่ายกว่าการศึกษาทุกฟีเจอร์ตั้งแต่เริ่ม
