หน่วยพื้นฐานของงานแบบขนานคือแชตที่มีบริบท ข้อความ ผลลัพธ์ และเป้าหมายของตนเอง งานที่เหมาะกับการทำขนานไม่ใช่เพียงงานที่ “มีหลายขั้นตอน” แต่ต้อง **เป็นอิสระต่อกัน มีขอบเขตไฟล์ชัดเจน และตรวจรับแยกกันได้**

![แผนภาพการจัดงานที่ thread หลักมอบงานอิสระให้ Agent ย่อยหลายตัว แล้วรวบรวมหลักฐานและความขัดแย้ง](/illustrations/flow-subagents.webp)

## ตรวจว่าทำขนานได้หรือไม่

| ทำขนานได้ | ควรทำตามลำดับ |
|---|---|
| งานวิจัยแบบอ่านอย่างเดียวสองงาน | งานหลังต้องอาศัยข้อสรุปจากงานแรก |
| ไดเรกทอรีโค้ดและเอกสารไม่ทับกัน | แก้ไฟล์หลักเดียวกันพร้อมกัน |
| ทำ prototype แยกกันสองแนวทาง | requirement ยังเปลี่ยนบ่อย |
| แต่ละงานมีการทดสอบอิสระ | ต้องรวมกันก่อนจึงรู้ว่าถูกหรือผิด |

คำแนะนำทางการคืออย่าให้สองแชตเขียน data source เดียวกัน และให้ใช้ Git worktree ต่างกันเมื่อเขียนโค้ดขนาน

## จากง่ายไปยาก

### 1. เริ่มจากงานอ่านอย่างเดียวแบบขนาน

```text
งาน: วิเคราะห์เฉพาะความล้มเหลวล่าสุดของโมดูล authentication ห้ามแก้ไฟล์
ขอบเขต: src/auth/** และการทดสอบที่เกี่ยวข้อง
สิ่งส่งมอบ: สมมติฐานสาเหตุหลัก พาธหลักฐาน จุดที่ยังไม่แน่ใจ และคำสั่งตรวจสอบที่แนะนำ
```

งานอ่านอย่างเดียวไม่ทำให้เกิด merge conflict จึงเหมาะกับการฝึกครั้งแรก

### 2. จากนั้นค่อยทำงานเขียนแบบขนาน

ระบุเป้าหมาย เจ้าของไฟล์ พื้นที่ห้ามแตะ และเกณฑ์ตรวจรับสำหรับแต่ละแชต:

```text
เป้าหมาย: เพิ่มเอกสารรหัสข้อผิดพลาดของ authentication
เจ้าของไฟล์: เฉพาะ docs/auth/**
ห้าม: แก้ src/**, lockfile และ shared config
ตรวจรับ: รัน pnpm check:links และรายงานผล
```

แชตที่เขียนโค้ดควรอยู่ใน [worktree](/th/guide/desktop-app/worktrees/) แยกกัน ส่วน shared config ให้แชตหลักหรือเจ้าของเพียงรายเดียวแก้

### 3. รวบรวมผลในตอนท้าย

อย่านำผลลัพธ์มาต่อกันทันที แชตหลักต้องตรวจว่า:

1. แต่ละงานส่งมอบตามขอบเขตหรือไม่
2. หลักฐานและการทดสอบทำซ้ำได้หรือไม่
3. ข้อสรุปต่าง ๆ ขัดแย้งกันหรือไม่
4. หลังรวมแล้วต้องรัน integration test เพิ่มหรือไม่

## งานยาวและโหมด Goal

ป้อน `/goal` ใน Desktop App, CLI หรือ IDE เพื่อเริ่มโหมด Goal เป้าหมายควรระบุผลลัพธ์ ข้อจำกัด และเกณฑ์ตรวจสอบ แต่ละแชตมีเป้าหมายแยกกัน การทำงานขนานไม่ได้ขยาย sandbox หรือสิทธิ์ และยังหยุดเมื่อพบการทำงานที่ต้องตัดสินใจ

ดูการจัดงานระดับเครื่องมืออย่างละเอียดที่ [Agent ย่อย](/th/guide/agent-work/subagents/)
