สรุปในแชตคือคำอธิบายงานของ Codex ส่วน Git diff คือการเปลี่ยนแปลงจริงในไฟล์ แผงตรวจทานของ Desktop App แสดง diff เพิ่มความคิดเห็นรายบรรทัด และเลือกได้ว่าจะ stage, discard, commit หรือ push ส่วนใด

โปรเจกต์ต้องอยู่ใน Git repository จึงจะใช้แผงตรวจทานแบบเต็มและ `/review` ได้

## การตรวจทานสองชั้น

ตรวจขอบเขตการเปลี่ยนแปลงด้วยตนเองก่อน แล้วเรียก reviewer อิสระเพื่อตรวจปัญหาในการทำงาน:

1. เปิดแผงตรวจทาน แล้วดูจำนวนไฟล์และพาธก่อน
2. เลือก **Last turn** เพื่อยืนยันว่ารอบนี้เปลี่ยนอะไรจริง
3. สลับระหว่าง **Unstaged**, **Staged**, **Commit** หรือ **Branch** เพื่อยืนยันขอบเขตการตรวจ
4. เรียก `/review` ในช่องป้อนข้อความ
5. เลือกเปรียบเทียบกับ branch ฐาน ตรวจการเปลี่ยนแปลงที่ยังไม่ commit ระบุ commit หรือกำหนดเกณฑ์เอง
6. อ่านข้อค้นพบตามลำดับความสำคัญ แล้วค่อยตัดสินใจว่าจะแก้หรือไม่

โดยค่าเริ่มต้น reviewer ของ `/review` เป็นแบบอ่านอย่างเดียวและจะไม่แก้ working tree หากขอให้ Codex แก้ข้อค้นพบภายหลัง ก็ยังอยู่ภายใต้กฎ sandbox และการอนุมัติเดิม

## เกณฑ์ตรวจทานที่ใช้ซ้ำได้

```text
โปรดตรวจการเปลี่ยนแปลงที่ยังไม่ commit โดยเน้น:
- มีส่วนใดเกินขอบเขตงานหรือไม่
- มี regression, edge case หรือปัญหาความปลอดภัยหรือไม่
- การทดสอบครอบคลุมเส้นทางที่ล้มเหลวหรือไม่
- เอกสารตรงกับ implementation หรือไม่

ให้ระบุปัญหาก่อน เรียงตามความรุนแรง แต่ละข้อให้ไฟล์ ตำแหน่ง หลักฐาน และแนวทางแก้ขั้นต่ำ
หากไม่พบปัญหา ให้ระบุอย่างชัดเจนและบอกความเสี่ยงจากการทดสอบที่ยังไม่ครอบคลุม
```

## ลดความกำกวมด้วยความคิดเห็นรายบรรทัด

เลื่อนเมาส์เหนือบรรทัดที่น่าสงสัย เลือก **+** ที่ปรากฏ แล้วเขียนข้อเสนอแนะให้ชัดเจน เมื่อใส่ความคิดเห็นครบแล้ว ให้ส่งคำสั่งที่ตรงไปตรงมา:

```text
จัดการความคิดเห็นรายบรรทัดที่ฉันทิ้งไว้ รักษาขอบเขตการแก้ไขให้เล็กที่สุด
เมื่อเสร็จแล้วให้รันการทดสอบที่เกี่ยวข้องอีกครั้งและแสดง diff ใหม่
```

ความคิดเห็นที่มีประโยชน์ควรระบุความเสี่ยงหรือเกณฑ์ยอมรับ เช่น “กรณี array ว่าง ตรงนี้จะคืนค่าอะไร” ส่วนคำว่า “ตรงนี้ผิด” เพียงอย่างเดียวมักไม่พอ

## การ stage และ discard

แผงตรวจทานสามารถ stage, unstage หรือ discard ได้ทั้ง diff ทั้งชุด รายไฟล์ หรือราย hunk การ discard จะลบการเปลี่ยนแปลง ก่อนทำต้องยืนยันว่าไม่ใช่งานของผู้ใช้ที่มีอยู่ก่อนเริ่มงานนี้

ลำดับตรวจรับที่แนะนำคือ ขอบเขต → พฤติกรรม → การทดสอบ → ความปลอดภัย → การดูแลรักษา อ่านเพิ่มที่ [ตรวจทาน diff](/th/guide/quality/review-diffs/)
