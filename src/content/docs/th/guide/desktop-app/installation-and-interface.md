บทนี้เหมาะสำหรับผู้ที่เปิด ChatGPT Desktop App เป็นครั้งแรก เป้าหมายไม่ใช่จำทุกปุ่ม แต่คือทำงานขนาดเล็กที่ **ตรวจทานและตรวจสอบได้** ให้เสร็จ

ดูขั้นตอนติดตั้งและลงชื่อเข้าใช้ที่ [ติดตั้ง Desktop App](/th/guide/getting-started/install-desktop-app/) ปัจจุบันมีเวอร์ชัน macOS, Windows และ Linux อย่างเป็นทางการ หลังลงชื่อเข้าใช้ คุณสามารถเริ่มแชตใหม่ สร้างโปรเจกต์ หรือเปิดโฟลเดอร์ในเครื่อง

## รู้จักสามองค์ประกอบก่อน

| องค์ประกอบ | ใช้ทำอะไร | ผู้เริ่มต้นควรทำอะไร |
|---|---|---|
| โปรเจกต์หรือโฟลเดอร์ | ให้ไฟล์และ working directory แก่แชต | เปิด repository สำหรับฝึก อย่าเริ่มจากไดเรกทอรี production |
| แชต | เก็บเป้าหมาย บริบท ความคืบหน้า และผลลัพธ์ | ใช้หนึ่งแชตต่อหนึ่งเป้าหมายที่ชัดเจน |
| Codex | อ่าน แก้ไข และตรวจสอบเนื้อหาในโปรเจกต์ | เริ่มจากการเปลี่ยนแปลงความเสี่ยงต่ำที่ตรวจได้ง่าย |

อินเทอร์เฟซของแอปจะอัปเดตต่อเนื่อง แต่องค์ประกอบทั้งสามนี้เสถียรกว่าตำแหน่งของปุ่มใดปุ่มหนึ่ง

## ทำงานจริงครั้งแรก

เตรียม Git repository ที่มีอยู่ ตรวจให้แน่ใจก่อนว่าไม่มีการเปลี่ยนแปลงที่ยังไม่ได้บันทึกแต่ต้องเก็บไว้ จากนั้นเปิดโฟลเดอร์นั้นในแอปและเริ่มแชต Codex ใหม่

ป้อนข้อความ:

```text
โปรดอ่าน README.md ก่อน และแก้เฉพาะหัวข้อ “การรันในเครื่อง”:
1. แก้คำสั่งเริ่มต้นที่ใช้ไม่ได้แล้ว
2. คงหัวข้ออื่นไว้ตามเดิม
3. หลังแก้ให้แสดง diff และรันคำสั่งตรวจสอบที่ทำได้ตามเอกสาร
4. หากตรวจสอบไม่ได้ ให้ระบุเหตุผลชัดเจนและอย่าอ้างว่างานเสร็จ
```

เมื่อเสร็จแล้ว อย่าอ่านเพียงสรุปในแชต แต่ให้ตรวจ:

1. แผงตรวจทานแสดงเฉพาะไฟล์ที่คาดไว้หรือไม่
2. เนื้อหาที่ลบสมเหตุสมผลหรือไม่
3. output ของเทอร์มินัลรองรับข้อสรุปว่า “ตรวจสอบผ่าน” จริงหรือไม่
4. `git diff` ตรงกับขอบเขตงานหรือไม่

## เลือก Chat, Work หรือ Codex อย่างไร

- ถามความรู้หรือหารือแนวคิดเท่านั้น: ใช้ Chat
- ทำงานทั่วไปที่ข้ามหลายไฟล์และเครื่องมือ: ใช้ Work
- ต้องเข้าใจ แก้ไข และทดสอบ repository: ใช้ Codex

หากเป็นคำถามชั่วคราวที่ไม่ต้องเก็บบริบทระยะยาว ใช้ Quick chat ได้ ส่วนงานที่ต้องติดตามต่อเนื่องควรอยู่ในแชตปกติหรือโปรเจกต์

## เมื่อเกิดปัญหาให้ตรวจอะไร

- **มองไม่เห็นไฟล์**: ยืนยันว่าเปิดโฟลเดอร์ถูกต้องและไม่ได้ปฏิเสธสิทธิ์ของงาน
- **รันคำสั่งไม่ได้**: ยืนยันว่าติดตั้ง dependency แล้ว จากนั้นดูข้อผิดพลาดจริงรายการแรกในเทอร์มินัล
- **มีการเปลี่ยนแปลงเก่าปะปน**: ใช้ `git status` แยกการเปลี่ยนแปลงเดิมก่อนเริ่มงานออกจากการเปลี่ยนแปลงรอบนี้
- **อินเทอร์เฟซไม่เหมือนบทความ**: หาองค์ประกอบเชิงตรรกะ เช่น “โปรเจกต์/โฟลเดอร์ แชต การตรวจทาน เทอร์มินัล” อย่ายึดตำแหน่งคงที่ในภาพ
