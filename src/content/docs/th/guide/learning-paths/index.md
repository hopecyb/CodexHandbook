เส้นทางเรียนรู้ **ทำหน้าที่จัดลำดับเท่านั้น** ไม่ได้คัดลอกเนื้อหายาวจากคู่มือผลิตภัณฑ์หรือหัวข้อความสามารถ

เมื่อเห็นบท “เส้นทางเรียนรู้” ครั้งแรก คุณอาจรู้สึกว่าเป็นสารบัญเพิ่มอีกชั้น หน้าที่หลักคือช่วยตอบว่า ตอนนี้คุณใกล้เคียงผู้ใช้ประเภทใด และควรอ่านตามลำดับใด

บทนี้ไม่ได้เพิ่มความรู้ใหม่ แต่ช่วยลดทางอ้อมในการเรียน

![ภาพประกอบ: ถนนสี่สายเริ่มจากหนังสือเล่มเดียว—ผู้เริ่มต้น ครีเอเตอร์ นักพัฒนา และทีม—แล้วมาบรรจบกันบนยอดเขา](/illustrations/learning-paths.webp)

## บทนี้ทำอะไร

- หากฉันเป็นผู้เริ่มต้น ครีเอเตอร์ นักพัฒนา หรือผู้นำการนำไปใช้ในทีม ควรเลือกเส้นทางใด
- ลำดับการอ่านของแต่ละบทบาทต่างกันอย่างไร
- เนื้อหาใดควรอ่านตอนนี้ และเนื้อหาใดเก็บไว้ภายหลังได้

## เส้นทางปฏิบัติสำหรับครีเอเตอร์

[เส้นทางครีเอเตอร์](/th/guide/learning-paths/creator/) มีสี่ milestone ต่อเนื่อง: ข้อมูลและตารางข้อเท็จจริง → บทความที่มีแหล่งอ้างอิง → งานนำเสนอแปดสไลด์ที่แก้ไขได้ → คำอธิบายงานที่ใช้ซ้ำได้ บทความและงานนำเสนอมีสื่อดาวน์โหลดแยกกัน ทุกขั้นมีเงื่อนไขว่าเสร็จ แต่ทั้งเส้นทางยังไม่ได้ทดสอบให้ผู้อ่านอิสระทำจนจบ

## เส้นทางปฏิบัติสำหรับนักพัฒนา

[เส้นทางนักพัฒนา](/th/guide/learning-paths/developer/) ใช้แบบฝึก Bug ตะกร้าสินค้าซ้ำ โดยเรียงเป็นการอ่านโค้ด → แก้และทดสอบ → ตรวจ diff → ส่งต่อ พร้อมเทมเพลตให้กรอกสามชุดและเอกสารอ้างอิงของผู้เขียน การทดสอบอ้างอิงเรียกใหม่แล้ว แต่ยังรอการยืนยันจากผู้อ่านอิสระที่ทำจนจบ

## เส้นทางทีม: ทดลองสองสัปดาห์และตัดสินใจขยายผล

- [ทีม](/th/guide/learning-paths/team/): กฎบัตร → ตรวจด้วยมือ → สุ่มตรวจ → ฝึกย้อนกลับ → ตัดสินใจขยาย ทำต่อ หรือหยุด พร้อมเทมเพลตหกชุด

## เส้นทางผู้ปฏิบัติขั้นสูง

หากคุณทำงานเล็กได้แล้ว ขั้นถัดไปไม่ใช่ท่องคำสั่งเพิ่ม แต่คือเรียนรู้การรวมความสามารถหลายอย่างเป็นเวิร์กโฟลว์ที่มั่นคง:

| ขั้น | หัวข้อ | อ่านก่อน |
|---|---|---|
| 1 | ช่องทางด่วน | [คำสั่ง slash และทางลัด](/th/guide/reference/slash-commands/) |
| 2 | บริบทถาวร | [AGENTS.md](/th/guide/customization/agents-md/) และ [หน่วยความจำกับบริบทถาวร](/th/guide/customization/memories-and-persistent-context/) |
| 3 | กระบวนการใช้ซ้ำ | [ภาพรวม Skills](/th/skills/overview/) และ [โครงสร้าง Skill](/th/skills/skill-anatomy/) |
| 4 | งานย่อยอิสระ | [Agent ย่อย](/th/guide/agent-work/subagents/) และ [การทำงานร่วมกันของหลาย Agent](/th/cases/workflows/multi-agent-coordination/) |
| 5 | ระบบภายนอก | [ภาพรวม MCP](/th/skills/mcp/mcp-overview/) |
| 6 | Guardrail อัตโนมัติ | [ภาพรวม Hooks](/th/skills/hooks/hooks-overview/) |
| 7 | แจกจ่ายให้ทีม | [ภาพรวม Plugins](/th/skills/plugins/plugins-overview/) |
| 8 | ย้อนกลับและตรวจทาน | [เลิกทำและกู้คืน](/th/guide/getting-started/undo-and-recover/) และ [ตรวจ Diff](/th/guide/quality/review-diffs/) |

เส้นทางนี้เหมาะกับการยกระดับจาก “ให้ Codex ช่วยเป็นครั้งคราว” เป็น “ระบบเล็กที่ทีมทำซ้ำได้”: คำสั่งโปรเจกต์กำหนดกฎระยะยาว Skill กำหนดวิธีทำงาน MCP ให้เครื่องมือภายนอก Agent ย่อยแบ่งงานย่อยที่มีขอบเขตชัด Hook ปกป้องจุดสำคัญ และ Plugin แจกความสามารถชุดนี้ให้คนอื่น

## ความเข้าใจผิดที่พบบ่อย

### 1. เส้นทางเรียนรู้กับเนื้อหาหลักของคู่มือซ้ำกันสองชุด

เนื้อหาหลักมีหน้าที่อธิบาย ส่วนเส้นทางเรียนรู้บอกว่าตอนนี้ควรอ่านหน้าใด

### 2. ฉันต้องระบุก่อนว่าตนเองเป็นบทบาทใดแบบตายตัว

ตัดสินเพียงเรื่องเดียวก่อน:  
**ตอนนี้ปัญหาหลักที่คุณอยากแก้ที่สุดคืออะไร**

### 3. ต้องเรียนเส้นทางหนึ่งตั้งแต่ต้นจนจบ ห้ามข้าม

เส้นทางคือลำดับแนะนำ ไม่ใช่กระบวนการบังคับ เมื่อใช้งานจริง คุณย้อนหรือข้ามไปบทอื่นตามปัญหาที่เจาะจงได้

## หากเลือกไม่ถูก

หากไม่แน่ใจว่าจะเลือกเส้นทางใด ให้ใช้เกณฑ์นี้:

- ยังไม่เคยทำงานครบวงจรครั้งแรก: เลือก [เส้นทางผู้เริ่มต้น](/th/guide/learning-paths/beginner/)
- ต้องการเขียนเนื้อหา ทำสื่อภาพ หรืองานนำเสนอเป็นหลัก: ดู [เส้นทางครีเอเตอร์](/th/guide/learning-paths/creator/)
- ต้องการแก้โค้ด แก้ bug หรือทำโปรเจกต์เป็นหลัก: ดู [เส้นทางนักพัฒนา](/th/guide/learning-paths/developer/)
- กำลังวางแผนนำไปใช้ในทีมและควบคุมความเสี่ยง: ดู [เส้นทางทีม](/th/guide/learning-paths/team/)

เส้นทางเรียนรู้ใช้ “ปัญหาที่สำคัญที่สุดในตอนนี้” เป็นตัวตัดสินว่าควรอ่านอะไรต่อ
