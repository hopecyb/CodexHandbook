ใช้ข้อมูลหนึ่งชุดเขียนบทความ แล้วเปลี่ยนเป็นงานนำเสนอที่แก้ไขได้ ก่อนบันทึกคำอธิบายงานไว้ใช้ซ้ำครั้งหน้า ทุกขั้นจะมีไฟล์เหลือไว้ให้คุณตัดสินได้ว่าทำเสร็จหรือยัง

คุณต้องเปิดโฟลเดอร์ในเครื่องด้วย Codex ได้ การสร้างงานนำเสนอยังต้องมีเครื่องมือที่สร้าง PPTX และซอฟต์แวร์ที่เปิดไฟล์นั้นได้ ดูสภาพแวดล้อมเฉพาะในกรณีศึกษา โดยไม่ได้กำหนดให้ทุกไคลเอนต์มีเครื่องมือเหมือนกัน หากยังไม่คุ้นกับไฟล์ ให้ทำ [ทำงานกับไฟล์](/th/guide/learning-paths/beginner/02-work-with-files/) ก่อน

## เส้นทางและสื่อ

| ขั้น | อินพุตก่อนเริ่ม | ผลลัพธ์ขั้นนี้ | เมื่อเสร็จไปที่ใด |
|---|---|---|---|
| 1. จัดหลักฐาน | ข้อมูลสังเคราะห์สามชุดและดัชนีแหล่งข้อมูล | ตารางข้อเท็จจริง รายการความขัดแย้งและสิ่งที่ขาด | เขียนบทความ |
| 2. เขียนและแก้ไข | ตารางข้อเท็จจริง กลุ่มผู้อ่าน และโครงเรื่อง | บทความ แผนผังข้อกล่าวอ้าง และคำอธิบายการแก้ไข | สร้างงานนำเสนอ |
| 3. สร้างงานนำเสนอ | บทความ แผนผังข้อกล่าวอ้าง และเป้าหมายการนำเสนอ | PPTX แปดสไลด์ ตัวอย่างแปดสไลด์ บันทึกย่อ และบันทึกการตรวจ | เก็บคำอธิบายสำหรับใช้ซ้ำ |
| 4. เก็บคำอธิบายสำหรับใช้ซ้ำ | ผลลัพธ์และประสบการณ์จริงจากสามขั้นแรก | เทมเพลตงาน เช็กลิสต์ยอมรับ และบันทึกการย้ายหนึ่งครั้ง | ลองกับข้อมูลใหม่อีกครั้ง |

[ดาวน์โหลดชุดฝึกบทความ](/downloads/source-backed-article/source-backed-article-1.0.0.zip) · [ดาวน์โหลดชุดฝึกงานนำเสนอ](/downloads/article-to-slides/article-to-slides-1.0.0.zip)

ทั้งสองชุดใช้แยกกันได้ หากเรียนต่อเนื่อง ขั้นที่ 3 ควรใช้บทความที่คุณทำเอง ส่วน `input/` ในชุดงานนำเสนอเป็นอินพุตอ้างอิงสำหรับผู้ที่ยังทำบทความไม่เสร็จหรือต้องการเทียบ ผลิตภัณฑ์ บุคคล และบทสัมภาษณ์ทั้งหมดเป็นข้อมูลสังเคราะห์เพื่อการสอน

## 1. จัดหลักฐานและเก็บความขัดแย้งไว้

ก่อนเริ่ม: แตกชุดบทความ แล้วอ่าน `brief.md`, `sources/index.csv` และข้อมูลสามชุดที่ระบุ ทำตาม [ขั้นแรกของกรณีศึกษาบทความ](/th/cases/write-an-article/#1-จัดระเบียบข้อเท็จจริงและข้อขัดแย้งก่อน) เพื่อจัดข้อมูล โดยยังไม่รีบเขียนเป็นบทความ

ใส่เอาต์พุตใน `my-output/` ของชุดบทความ และเก็บแหล่งข้อมูลต้นฉบับไว้ ตารางข้อเท็จจริงต้องบันทึก ID ของข้อมูล หัวข้อย่อย ข้อความที่รองรับ และประเภทหลักฐาน นอกจากนี้ให้เขียน `unresolved.md` ระบุคำถามที่ข้อมูลยังตอบไม่ได้

เงื่อนไขว่าเสร็จ: พบความขัดแย้งระหว่าง P3 กับ C2 เรื่องค่าเริ่มต้นการวินิจฉัย และไม่ได้เลือกฝ่ายใดเป็นคำตอบสุดท้ายเอง บทสัมภาษณ์สังเคราะห์ยังระบุว่าเป็นข้อมูลสังเคราะห์ และไม่ได้สร้างตัวเลขความแม่นยำหรือเวลาที่ประหยัดซึ่งแหล่งข้อมูลไม่ได้ให้ไว้

หากเปิดแหล่งข้อมูลไม่ได้หรือหมายเลขไม่ตรง ให้กู้ไฟล์และดัชนีก่อน ห้ามเดาเนื้อหาจากชื่อไฟล์ เมื่อผ่านแล้วจึงไปขั้นถัดไป

## 2. เขียนบทความ แล้วแก้โดยเทียบกับแหล่งข้อมูล

ก่อนเริ่ม: มีรายการข้อเท็จจริงและเรื่องที่ยังไม่ตัดสินจากขั้นก่อน ทำ [กรณีศึกษาบทความ](/th/cases/write-an-article/) ต่อ กำหนดกลุ่มผู้อ่านให้ชัดแล้วสร้างโครงเรื่อง เขียนร่างต่อเนื่องภายในขอบเขตที่กำหนด จากนั้นตรวจข้อเท็จจริงและแก้สำนวน

ส่งมอบ `article.md`, `claim-map.csv`, `unresolved.md` และคำอธิบายการแก้ไขหนึ่งชุด ระบุการแก้ข้อเท็จจริงอย่างน้อยหนึ่งรายการและการแก้สำนวนอย่างน้อยหนึ่งรายการ ชุดอ้างอิงมีร่างที่ออกแบบไว้และ diff ของข้อความจริงอยู่แล้ว ห้ามถือว่าตัวอย่างผิดที่ออกแบบไว้นั้นเป็นความล้มเหลวจริงของโมเดล

เงื่อนไขว่าเสร็จ: ระบุตำแหน่งข้อเท็จจริงสำคัญได้ แยกคำแนะนำของผู้เขียนออกจากสิ่งที่ข้อมูลรองรับ และเก็บความขัดแย้งเรื่องการวินิจฉัยไว้ หากเรียก Python ได้ ให้ตรวจโครงสร้างตามกรณีศึกษา แม้ผ่านก็ยังต้องตัดสินทีละประโยคว่าแหล่งข้อมูลรองรับข้อสรุปหรือไม่

เก็บไฟล์ชุดนี้เป็นอินพุตขั้นถัดไป บทความของคุณต่างจากฉบับอ้างอิงได้ แต่ห้ามทำข้อจำกัดสำคัญหาย

## 3. เปลี่ยนบทความเป็นงานนำเสนอแปดสไลด์

ก่อนเริ่ม: มีบทความและตารางข้อเท็จจริงที่เสร็จแล้ว ทำตาม [กรณีศึกษางานนำเสนอ](/th/cases/create-a-slide-deck/) เพื่อกำหนดกลุ่มผู้ฟัง เป้าหมายประมาณห้านาที และเนื้อหาหลักแปดสไลด์ ยืนยันเลย์เอาต์ด้วยสไลด์ธีมและสไลด์ข้อจำกัดก่อน แล้วจึงทำสไลด์ที่เหลือ

คัดลอกบทความกับตารางข้อเท็จจริงไปยังไดเรกทอรีอินพุตของงานนำเสนอ และระบุว่าเป็นเวอร์ชันของคุณเอง อย่าอ้างบทความของตนเองพร้อมกับถือว่าข้อสรุปทั้งหมดจากฉบับอ้างอิงยังใช้ได้โดยอัตโนมัติ

ส่งมอบ PPTX แปดสไลด์ ตัวอย่างแปดสไลด์ คำอธิบายรายสไลด์ และบันทึกการตรวจ เงื่อนไขว่าเสร็จ: เปิดได้ในสภาพแวดล้อมซอฟต์แวร์นำเสนอที่บันทึกไว้ ข้อความสำคัญแก้ไขได้ ตรวจภาษาจีนและขอบสไลด์ทุกหน้า และความขัดแย้งของแหล่งข้อมูลยังเห็นได้ชัดแม้ย่อเนื้อหาแล้ว

หากไม่มีเครื่องมือ PPTX ให้เก็บโครงเรื่องและบันทึกความสามารถที่ยังขาด ขั้นนี้ยังไม่เสร็จและค่อยทำต่อในสภาพแวดล้อมที่มีเครื่องมือ เมื่อผ่านแล้วจึงเข้าสู่ขั้นใช้ซ้ำ

## 4. เก็บคำอธิบายงานที่ใช้ซ้ำได้ในครั้งหน้า

ก่อนเริ่ม: ทำและตรวจบทความกับงานนำเสนอเรียบร้อยแล้ว สร้าง `workflow.md` แล้วเขียนวิธีที่ใช้จริงตามเทมเพลตต่อไปนี้ อย่าเก็บเพียงพรอมต์ “ทำต่อ” จากรอบสุดท้าย

```md
# จากข้อมูลสู่งานนำเสนอ

## งานครั้งนี้
- กลุ่มผู้รับและวัตถุประสงค์:
- ไดเรกทอรีอินพุต ดัชนีแหล่งข้อมูล และไฟล์ต้นฉบับที่ห้ามแก้:
- ไดเรกทอรีเอาต์พุตและรูปแบบไฟล์ที่ต้องการ:

## ลำดับ
1. ระบุข้อเท็จจริง การอนุมาน ความขัดแย้ง และสิ่งที่ขาดก่อน แล้วจึงเขียนเนื้อหาหลัก
2. เมื่อกำหนดผู้รับและโครงสร้างชัดแล้ว ให้เขียนร่างต่อเนื่องและแก้โดยเทียบแหล่งข้อมูล
3. ย่อบทความเป็นแปดสไลด์ แล้วตรวจสไลด์ธีมกับสไลด์ข้อจำกัดก่อน
4. ตรวจข้อความแบบ native ฟอนต์ภาษาจีน ตัวอย่างทุกสไลด์ และบันทึกย่อ

## การยอมรับ
- ระบุตำแหน่งข้อเท็จจริงสำคัญในต้นฉบับได้ และเรื่องที่ยังไม่ตัดสินยังมองเห็น
- แยกคำแนะนำของผู้เขียนออกจากข้อเท็จจริงผลิตภัณฑ์ และไม่นำข้อมูลสังเคราะห์มาอ้างเป็นคำยืนยันจริง
- เปิดและแก้ PPTX ได้; ตรวจทีละสไลด์ พร้อมบันทึกซอฟต์แวร์และสภาพแวดล้อมฟอนต์
- ระบุชัดว่าตรวจอะไรจริงและไม่ได้ตรวจอะไร โดยหยุดสิ่งส่งมอบไว้ในเครื่อง

## ประสบการณ์ครั้งนี้
- ปัญหาที่พบจริง แก้อะไร และยืนยันการกู้คืนอย่างไร:
- ขั้นตอนที่เก็บไว้ใช้ครั้งหน้าได้:
- ข้อเท็จจริงและสภาพแวดล้อมที่ต้องยืนยันใหม่ครั้งหน้า:
```

จากนั้นทำการย้ายขนาดเล็กหนึ่งครั้ง: เปลี่ยนกลุ่มผู้รับจาก “นักเขียนรายบุคคลที่ทดลองใช้ครั้งแรก” เป็น “เพื่อนร่วมงานที่เตรียมตรวจสื่อ” ใช้แหล่งข้อมูลชุดเดิม และสร้างเฉพาะโครงเรื่องใหม่ บันทึก `reuse-check.md` ว่าชื่อเรื่อง จุดเน้น และลำดับเปลี่ยนอย่างไรเมื่อเปลี่ยนผู้รับ และขอบเขตข้อเท็จจริงใดยังคงเดิม แบบฝึกนี้ตรวจว่าเทมเพลตปรับเข้ากับงานใหม่ได้หรือไม่ ไม่ได้อ้างว่าทำการวิจัยข้อเท็จจริงใหม่เสร็จแล้ว

เงื่อนไขว่าเสร็จ: ผู้รับ `workflow.md` หาอินพุตกับเอาต์พุตได้และรู้ว่าเมื่อใดถือว่าเสร็จ บันทึกการย้ายมีความต่างที่เจาะจง และไม่ได้เขียนต่อเป็นบทความสำหรับกลุ่มเดิม หากลำดับนิ่งแล้ว อ่าน [ตกผลึกเวิร์กโฟลว์เป็น Skill](/th/cases/workflows/turn-a-workflow-into-a-skill/) ต่อ [ตัวอย่าง Skill สำหรับการเขียน](/th/skills/examples/writing-skill/) มีชุดดาวน์โหลดครบ ซึ่งใช้ตัวอย่างสไตล์ ตารางข้อเท็จจริง และวิธีจัดการความขัดแย้งซ้ำได้ แต่การตรวจโครงสร้างแทนการตรวจข้อเท็จจริงโดยคนไม่ได้

## ทางเลือก: เริ่มด้วยงานที่มีตัวเลขชัดเจน

ผู้อ่านที่เน้นงานวิเคราะห์สำนักงานเริ่มจาก [รายงานยอดขายประจำสัปดาห์](/th/cases/analyze-a-spreadsheet/) ได้ งานนี้มี CSV รายการคืนเงินและแถวซ้ำ สรุปอ้างอิง และสคริปต์ตรวจอิสระ เมื่อเสร็จแล้วให้เพิ่ม “ตัวเลขสำคัญต้องคำนวณอิสระ และเกณฑ์ความผิดปกติต้องเขียนให้ชัด” ลงในเช็กลิสต์ยอมรับของคุณ โดยไม่ต้องฝืนรวมเข้ากับบทความผลิตภัณฑ์สมมติ

เมื่อทำทั้งเส้นทางเสร็จ คุณควรมีข้อมูลแหล่งที่มา บทความกับตารางข้อเท็จจริง งานนำเสนอที่แก้ไขได้ บันทึกการตรวจ และคำอธิบายใช้ซ้ำ การอ่านลิงก์จนหมดหรือดาวน์โหลดคำตอบอ้างอิงอย่างเดียวไม่ถือว่าทำแบบฝึกเสร็จ
