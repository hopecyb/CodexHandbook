บริบทคือ “ข้อมูลที่โมเดลนำไปใช้ได้อย่างมีประสิทธิภาพในขณะนี้” หากจัดการบริบทไม่ดี ต่อให้พรอมต์ดีเพียงใดก็จะถูกกลบด้วยข้อมูลรบกวน

ในการใช้งานจริง หมายถึงสิ่งที่ Codex เห็นอยู่จริง อ้างอิงได้ และใช้ตัดสินใจ สิ่งที่คุณรู้แต่ไม่ได้ส่งให้ Codex ไม่นับเป็นบริบทของงานนี้

## ทำไมบทนี้จึงสำคัญมาก

ปัญหาประเภท “ทำไมเข้าใจผิดอีกแล้ว” มักไม่ได้เกิดจากพรอมต์สั้นเกินไป แต่เกิดจากการจัดการบริบทที่ไม่ดี

กรณีที่พบบ่อย ได้แก่:

- ให้ข้อมูลที่ไม่เกี่ยวข้องมากเกินไป
- ไม่ได้ส่งไฟล์สำคัญให้
- บทสนทนาเก่าทำให้งานใหม่ออกนอกทิศทาง
- ไม่ได้ระบุว่าเมื่อข้อมูลขัดแย้งกัน อะไรสำคัญกว่า

## ควรอ่านบทนี้อย่างไร

หากอ่านบทนี้อย่างเป็นระบบเป็นครั้งแรก แนะนำให้เรียงตามนี้:

1. ทำความเข้าใจก่อนว่าบริบทประกอบด้วยอะไรบ้าง
2. จากนั้นดูว่าบริบทระดับโปรเจกต์ ไฟล์ และการสนทนาแยกกันอย่างไร
3. สุดท้ายจึงอ่านเรื่องลำดับความสำคัญ การย่อบริบท การรักษาบริบทให้ตรงประเด็น และข้อมูลละเอียดอ่อน
