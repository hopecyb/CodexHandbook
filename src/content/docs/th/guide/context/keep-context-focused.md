งานจำนวนมากยิ่งคุยยิ่งสับสน เพราะบริบทกระจัดกระจายไปแล้ว

การรักษาบริบทให้ตรงประเด็นคือจัดการเป้าหมายที่ชัดเจนทีละเรื่อง ไม่ปล่อยให้ปัญหาเก่ากับปัญหาใหม่ปะปนกัน

## ทำไมยิ่งคุยยิ่งสับสน

แนวคิดว่า “บอกเพิ่มอีกหน่อยย่อมปลอดภัยกว่า” มักไม่จริง เพราะไม่สามารถเติมข้อมูลเข้าไปในบริบทได้ตลอด

สำหรับ Codex หากงานเดียวมีสิ่งเหล่านี้พร้อมกัน:

- ปัญหาเดิม
- ปัญหาใหม่ที่แทรกเข้ามา
- ความคิดที่เกิดขึ้นกลางทาง
- รายละเอียดที่เคยคุยแล้วแต่ตอนนี้ไม่สำคัญ

ผลที่พบบ่อยคือประเด็นสำคัญไม่ชัดเจน

## ทำไมงานจึงค่อย ๆ ออกนอกทิศทาง

สาเหตุที่พบบ่อย ได้แก่:

- ใส่หลายเป้าหมายไว้ในบทสนทนาเดียว
- ลืมข้อจำกัดที่ตัวเองระบุไว้ก่อนหน้า
- ปัญหาที่แก้แล้วกลับมาดึงความสนใจซ้ำ ๆ
- เพิ่มความต้องการใหม่กลางทางโดยไม่สรุปขอบเขตใหม่

ผลลัพธ์มักเป็นว่า คุณคิดว่ากำลังเติมข้อมูล แต่สิ่งที่ Codex เห็นคือประเด็นสำคัญกระจัดกระจายมากขึ้น

## วิธีพื้นฐาน

- หนึ่งงานต่อหนึ่งเป้าหมาย
- สรุป “เสร็จแล้ว / ยังไม่เสร็จ / ข้อจำกัดที่ยังมีผล” เป็นระยะ
- ใช้ stage gate กับงานยาว
- เมื่อต้องทำข้ามเซสชัน ให้ใช้ [การส่งต่องานและกลับมาทำต่อ](/th/guide/agent-work/handoff-and-resume/)

## เมื่อเห็นสัญญาณเหล่านี้ ให้สรุปขอบเขตใหม่

หากเกิดกรณีต่อไปนี้ ควรสรุปขอบเขตใหม่เชิงรุก:

- คุณต้องย้อนอ่านบทสนทนาก่อนหน้าจึงจะรู้ว่าทำถึงไหน
- เริ่มคุยปัญหาที่สองในงานเดียวกันแล้ว
- พบว่างานประเภท “ทำอีกอย่างไปด้วย” เพิ่มขึ้นเรื่อย ๆ
- Codex เริ่มอ้างข้อสรุปเก่าที่ไม่สำคัญแล้ว

## แต่ละวิธีแก้ปัญหาอะไร

### หนึ่งงานต่อหนึ่งเป้าหมาย

อย่าขอทั้งหมดนี้ในงานเดียว:

- แก้ bug
- แก้ข้อความ
- refactor ไปด้วย
- ช่วยตรวจปัญหาใหม่อีกเรื่อง

เมื่อแยกงาน ขอบเขตจะชัดและตรวจสอบง่ายขึ้น

### สรุป “เสร็จแล้ว / ยังไม่เสร็จ / ข้อจำกัดที่ยังมีผล” เป็นระยะ

นี่คือการปรับงานให้ตรงกันระหว่างทาง เมื่องานยาว ขั้นตอนนี้ช่วยป้องกันไม่ให้ทั้งสองฝ่ายลืมว่าทำถึงไหนแล้ว

### ใช้ stage gate กับงานยาว

“Stage gate” คือทำส่วนย่อยให้เสร็จก่อน ยืนยันว่าไม่ออกนอกทิศทาง แล้วจึงเข้าสู่ส่วนถัดไป

ตัวอย่างเช่น เริ่มจาก “ค้นหาปัญหาเท่านั้น” ต่อด้วย “เสนอแนวทางเท่านั้น” และสุดท้ายจึง “ลงมือแก้”

### ใช้การส่งต่องานเมื่อทำข้ามเซสชัน

หากทำงานให้เสร็จในครั้งเดียวไม่ได้ ให้บันทึกสถานะสำคัญไว้ในข้อความส่งต่องานสั้น ๆ

## รูปแบบสรุปขอบเขตที่ใช้ได้ทันที

ระหว่างงานสามารถเขียนได้โดยตรงดังนี้:

```text
ขอสรุปให้ตรงกันก่อน
เสร็จแล้ว: A
ยังไม่เสร็จ: B
ข้อจำกัดที่ยังมีผล: แก้เฉพาะ frontend ห้ามแก้ API และห้ามติดตั้ง dependency ใหม่
ขั้นถัดไปทำเฉพาะ: C
```

## ข้อผิดพลาดที่พบบ่อย

### 1. พยายามบอก requirement ทั้งหมดในครั้งเดียวจนแยกเรื่องหลักกับเรื่องรองไม่ออก

ข้อมูลมากไม่ได้แปลว่าข้อมูลชัดเจน หากไม่แยกงานหลักออกจากงานที่ทำพ่วง Codex จะสับสนได้ง่ายขึ้น

### 2. งานเปลี่ยนแล้วแต่ยังใช้บทสนทนาเก่าต่อ

หากทิศทางเปลี่ยนแล้ว บางครั้งการเปิดเธรดใหม่สะอาดกว่าการฝืนคุยต่อ

### 3. ไม่ยืนยันแต่ละช่วงและแก้หลายอย่างในครั้งเดียว

ยิ่งแก้มาก ภายหลังยิ่งหาว่างานเริ่มออกนอกทิศทางที่ขั้นตอนไหนได้ยาก

การรักษาบริบทให้ตรงประเด็นไม่ได้หมายถึงพูดให้น้อย แต่หมายถึงเก็บข้อมูลที่ยังมีผลและตัดเนื้อหาที่ไม่สำคัญแล้วออกให้ทันเวลา เมื่อบริบทสับสน การดำเนินงานถัดไปก็ออกนอกทิศทางได้ง่าย
