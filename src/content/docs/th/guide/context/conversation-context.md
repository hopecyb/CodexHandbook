“บริบทการสนทนา” หมายถึง สิ่งที่คุณกับ Codex พูดไว้ก่อนหน้านี้ในงานเดียวกันจะยังส่งผลต่อส่วนถัดไป ทั้งเป็นประโยชน์และสร้างความเสี่ยงได้

## ทำไมจึงมีประโยชน์

ข้อมูลเหล่านี้จะสะสมในเธรดเดียวกัน:

- เป้าหมายและข้อจำกัดของคุณ
- ข้อสรุปที่ได้จากการหารือ
- ขั้นตอนที่ดำเนินการแล้ว
- ข้อมูลสำคัญจากผลลัพธ์ของเครื่องมือ

ตัวอย่างเช่น หากก่อนหน้านี้คุณระบุแล้วว่า “แก้เฉพาะหน้าแรก ห้ามแตะระบบหลังบ้าน” โดยทั่วไปก็ไม่ต้องย้ำในทุกประโยคถัดไป

## ทำไมจึงสร้างปัญหาได้เช่นกัน

ปัญหาที่พบบ่อยคือ **ข้อมูลเก่าไม่ได้หมดผลโดยอัตโนมัติเสมอไป**

กรณีที่พบบ่อย ได้แก่:

- คุณลืมแก้ข้อจำกัดที่ระบุไว้ก่อนหน้า
- ทิศทางงานเปลี่ยนแล้ว แต่ยังคุยต่อโดยอิงบริบทเก่า
- ข้อสรุปชั่วคราวก่อนหน้านี้ใช้ไม่ได้แล้ว แต่ยังส่งผลต่อการตัดสินใจภายหลัง

ดังนั้น ประเด็นสำคัญไม่ใช่การยืดบทสนทนา แต่คือยิ่งบทสนทนายาวก็ยิ่งต้องสรุปขอบเขตให้ชัดเจน

## เมื่อใดควรย้ำข้อจำกัดสำคัญ

แม้จะพูดไว้ก่อนหน้าแล้ว แต่ควรย้ำอีกครั้งในจุดสำคัญ เช่น:

- ก่อนเริ่มแก้ไฟล์จริง
- หลังทิศทางงานเปลี่ยน
- หลังบทสนทนายาวมากแล้ว
- เมื่อพบว่า Codex เริ่มละเลยขอบเขตบางข้อ

ข้อมูลต่อไปนี้ควรย้ำมากที่สุด:

- แก้ได้เฉพาะไฟล์ใด
- ห้ามทำอะไร
- เกณฑ์ว่าเสร็จคืออะไร
- ข้อจำกัดใดยังมีผล

## ความเข้าใจผิดที่พบบ่อย

### 1. ยิ่งเธรดยาวยิ่งสะดวกหรือไม่

ไม่เสมอไป

หากหัวข้อยังเหมือนเดิม เธรดยาวก็สะดวก  
แต่หากทิศทางงานเปลี่ยนแล้ว การใช้เธรดเก่าต่ออาจทำให้งานใหม่ออกนอกทิศทางได้ง่ายขึ้น

### 2. ฉันบอกไปแล้ว ทำไม Codex ยังทำผิด

เพราะข้อมูลก่อนหน้าอาจถูกเนื้อหาที่ตามมาจำนวนมากเจือจาง หรือไม่สอดคล้องกับงานปัจจุบันมากพอ

ในกรณีนี้ อย่าพูดเพียงว่า “คุณรู้อยู่แล้วไม่ใช่หรือ” วิธีที่ได้ผลกว่าคือย้ำข้อจำกัดที่ยังสำคัญอีกครั้ง

### 3. เมื่อใดควรเปิดเธรดใหม่

ใช้เกณฑ์ต่อไปนี้:

- เป้าหมายเปลี่ยนแล้ว
- ปัญหาเดิมจบแล้ว
- คุณเองก็รู้สึกว่าบทสนทนาเริ่มสับสน

เมื่อเป็นเช่นนี้ การเปิดเธรดใหม่มักสะอาดกว่าการฝืนคุยต่อ

## วิธีจัดการเมื่อเปลี่ยนหัวข้อ

เมื่อเปลี่ยนหัวข้อ:

1. เปิดเธรดใหม่
2. วางเฉพาะสรุปข้อจำกัดที่ยังมีผล
3. อย่าย้ายภูมิหลังที่ล้าสมัยแล้วไปด้วย

หากยังทำต่อในเธรดเดิม ให้ส่ง “ข้อความปรับความเข้าใจให้ตรงกัน” สั้น ๆ ก่อน เช่น:

```text
ต่อจากนี้ให้คุยเฉพาะการปรับหน้าแรก เนื้อหาเกี่ยวกับ API ฝั่งระบบหลังบ้านก่อนหน้านี้ไม่ต้องนำมาต่อ ในรอบนี้ยังคงแก้เฉพาะข้อความและสไตล์ ห้ามแก้โครงสร้างข้อมูล
```

เธรดเดียวกันช่วยสานต่อความจำ แต่ก็พาภาระเก่าติดมาด้วย เมื่อหัวข้อเปลี่ยน ควรสรุปขอบเขตใหม่อย่างชัดเจน
