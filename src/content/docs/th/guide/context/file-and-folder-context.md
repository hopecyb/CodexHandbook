อย่าบอกเพียงว่า “ช่วยแก้ให้หน่อย” ควรระบุด้วยว่า Codex ต้องดูไฟล์ใดและห้ามดูไฟล์ใด

คุณอาจรู้อยู่แล้วว่าปัญหาอยู่ในไดเรกทอรีใด แต่หากไม่กำหนดขอบเขตให้ชัด Codex อาจดึงไฟล์ที่ไม่เกี่ยวข้องเข้ามาด้วย

## ทำไมขอบเขตจึงสำคัญ

เมื่อขอบเขตกว้างเกินไป ปัญหาเหล่านี้มักเกิดขึ้นพร้อมกัน:

- Codex อ่านไฟล์ที่ไม่เกี่ยวข้องจำนวนมาก
- ข้อมูลที่ไม่เกี่ยวข้องใช้พื้นที่บริบท
- Codex เข้าใจผิดว่าไฟล์อื่นที่คล้ายกันก็เป็นเป้าหมาย
- ขอบเขตการเปลี่ยนแปลงเกินกว่าที่คุณคาดไว้

ดังนั้น บริบทของไฟล์และไดเรกทอรีจึงมีไว้ขีดเส้นขอบเขตให้ Codex

## ทำไมต้องกำหนดขอบเขตไฟล์ให้ชัด

ลองนึกภาพว่าคุณพาใครสักคนเข้าไปหาเอกสารในสำนักงาน:

- หากบอกเพียงว่า “ช่วยไปหาให้หน่อย” เขาอาจรื้อค้นทั้งครึ่งชั้น
- หากบอกว่า “ดูเฉพาะแฟ้มสีน้ำเงินในตู้ที่สาม” จะทำงานได้เร็วขึ้นมาก

Codex ก็เช่นกัน ยิ่งขอบเขตชัด Codex ก็ยิ่งไม่ต้องเดาเพื่อเติมข้อมูลที่ขาด

## ตัวอย่างง่าย ๆ

ระบุเส้นทางที่เกี่ยวข้องให้ชัด:

```text
โปรดอ่านเฉพาะ src/components/Button.tsx และไฟล์ทดสอบของไฟล์นี้ ห้ามสแกนทั้ง repository
```

ประโยคนี้ระบุพร้อมกันว่า:

- ต้องดูที่ใด
- ห้ามดูที่ใด
- ห้ามขยายขอบเขตเอง

## ความเข้าใจผิดที่พบบ่อย

### 1. ยิ่งระบุไฟล์ที่เกี่ยวข้องมากยิ่งดีหรือไม่

น้อยเกินไปทำให้ Codex ต้องเดา มากเกินไปทำให้ประเด็นสำคัญเจือจาง
วิธีที่เหมาะกว่าคือ **ให้เฉพาะส่วนที่จำเป็นจริงต่อการทำงานปัจจุบัน**

### 2. หากไม่รู้ว่าไฟล์ที่เกี่ยวข้องอยู่ที่ใด ควรทำอย่างไร

ให้ Codex ช่วยจำกัดขอบเขตก่อนได้ แต่ต้องระบุเป้าหมายให้ชัด เช่น:

```text
ก่อนอื่นช่วยหาไฟล์ที่เกี่ยวข้องกับสไตล์ของปุ่มเข้าสู่ระบบ โดยยังไม่ต้องแก้ไข
```

การค้นหาตำแหน่งก่อนแล้วค่อยลงมือ มักปลอดภัยกว่าการสั่งให้ “ค้นทั้ง repository แล้วแก้ไปด้วย”

### 3. ไม่ระบุขอบเขตก็ได้ เพราะ Codex หาเองได้ใช่หรือไม่

Codex หาเองได้ แต่ต้นทุนโดยทั่วไปคือ:

- อ่านมากขึ้น
- ช้าลง
- ดึงไฟล์ที่คล้ายกันเข้ามาได้ง่ายขึ้น
- มีโอกาสแก้ส่วนที่คุณคาดไม่ถึงมากขึ้น

### 4. ต้องระบุทั้งไดเรกทอรีและไฟล์หรือไม่

ไม่จำเป็นเสมอไป แต่หากระบุให้เจาะจงได้ก็ควรทำ

- หากรู้ว่าเป็นไฟล์ใด: ระบุไฟล์โดยตรง
- หากรู้เพียงบริเวณโดยรวม: ระบุไดเรกทอรีก่อน
- หากไม่แน่ใจเลย: ให้ Codex ทำเฉพาะการค้นหาและอธิบายก่อน

## สามสิ่งที่ควรเพิ่มในพรอมต์

หากกังวลว่า Codex จะแก้มากเกินไป ให้เพิ่มสามข้อนี้ในพรอมต์โดยตรง:

1. ดูได้เฉพาะไฟล์หรือไดเรกทอรีใด
2. ห้ามสแกนที่ใด
3. ก่อนแก้ ให้ระบุว่าจะกระทบไฟล์ใดบ้าง

ใน IDE ให้ตรวจว่ารากของ workspace ปัจจุบันถูกต้อง

## รูปแบบที่นำไปใช้ได้ทันที

ใช้รูปแบบนี้ได้โดยตรง:

```text
ก่อนอื่นให้ดูเฉพาะ `src/pages/home/` และ `src/components/Hero.tsx`
ห้ามสแกน `backend/` และ `scripts/`
หากยังต้องใช้ไฟล์อื่น ให้บอกเหตุผลก่อนแล้วจึงดำเนินการต่อ
```

การระบุขอบเขตไฟล์ให้ Codex ช่วยลดการคาดเดา ข้อมูลรบกวน และการแก้ผิดจุด
