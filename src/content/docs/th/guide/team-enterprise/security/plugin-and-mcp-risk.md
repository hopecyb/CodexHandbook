**Plugin** และ **เซิร์ฟเวอร์ MCP** เชื่อม Codex กับระบบภายนอก เช่น ระบบ ticket ฐานข้อมูล และ API ภายใน ยิ่งมีความสามารถมาก พื้นที่เสี่ยงด้านข้อมูลรั่วไหลและการใช้สิทธิ์เกินขอบเขตใน [โมเดลภัยคุกคาม](/th/guide/team-enterprise/security/threat-model/) ก็ยิ่งกว้าง ควรอ่านบทนี้คู่กับ [ภาพรวม MCP](/th/skills/mcp/mcp-overview/) และ [ภาพรวม Plugins](/th/skills/plugins/plugins-overview/)

เมื่อพบคำเหล่านี้ครั้งแรก ไม่ต้องรีบจำคำนิยาม ให้ยึดหลักเดียวก่อนว่า เมื่อ Codex เชื่อมต่อระบบภายนอก ความสามารถและความเสี่ยงจะเพิ่มขึ้นพร้อมกัน

ไม่ว่าจะเรียก Plugin หรือ MCP คำถามหลักคล้ายกัน:

- อ่านอะไรได้
- แก้ไขอะไรได้
- ใครเป็นผู้อนุมัติ
- ติดตามอย่างไรเมื่อเกิดปัญหา

## เนื้อหา

- การจำแนกความเสี่ยงของส่วนขยาย
- รายการที่อนุมัติและการตรึงเวอร์ชัน
- การแยกส่วนเมื่อดีบักหรือเกิดเหตุ

## การจำแนกความเสี่ยง

| ประเภท | ตัวอย่าง | การควบคุม |
|---|---|---|
| อ่านข้อมูล | MCP อ่านฐานข้อมูลลูกค้า | บัญชีอ่านอย่างเดียวและสิทธิ์ระดับแถว |
| เขียนข้อมูล | ปิด ticket หรือแก้การกำหนดค่าอัตโนมัติ | อนุมัติโดยมนุษย์และยืนยันการเขียนซ้ำ |
| เครือข่าย | เชื่อมต่อภายนอกได้โดยพลการ | allowlist ขาออก |
| ข้อมูลประจำตัว | OAuth token ถูกเขียนลงดิสก์ | จัดการ secret และใช้ token อายุสั้น |
| Supply chain | อัปเดตเซิร์ฟเวอร์บุคคลที่สามด้วยโค้ดอันตราย | ตรึงเวอร์ชันและล็อก hash |

## ขั้นตอนอนุมัติของทีม (แนะนำ)

```text
ยื่นคำขอ (วัตถุประสงค์, ระดับข้อมูล, สิทธิ์) → Review ด้านความปลอดภัย/สถาปัตยกรรม
    → เพิ่มใน repository หรือไดเรกทอรีภายในของ “รายการที่อนุมัติ”
    → ตรึงหมายเลขเวอร์ชัน + ระบุผู้รับผิดชอบ
    → ทบทวนทุกไตรมาสหรือเมื่ออัปเกรด major version
```

MCP สำหรับการทดลองส่วนบุคคล **ไม่ควร** ใช้ token เดียวกับ repository production

## แนวปฏิบัติขั้นต่ำ

1. **ปฏิเสธโดยค่าเริ่มต้น** สำหรับ remote MCP ที่ไม่อยู่ในรายการ
2. **Local MCP** ยังอาจอ่านได้ทั้งดิสก์—ให้ใช้ผู้ใช้ OS หรือ container เฉพาะ
3. **Log**: บันทึกชื่อ tool และสรุปพารามิเตอร์โดยลบข้อมูลอ่อนไหว ดู [การตรวจสอบด้วย Hook](/th/skills/hooks/hooks-examples/)
4. **การแบ่งหน้าที่ของ Skill และ MCP**: Skill อธิบายขั้นตอน ส่วน MCP เชื่อมต่อภายนอก—ให้รวมสิทธิ์ของทั้งสองแล้วใช้นโยบายที่เข้มงวดที่สุด

## ข้อผิดพลาดที่พบบ่อย

- คิดว่า “Marketplace ทางการ” เท่ากับ “ผ่านการตรวจความปลอดภัยแล้ว”
- สภาพแวดล้อมพัฒนาและ production ใช้แอป MCP OAuth เดียวกัน
- เปิด `DEBUG=*` ระหว่างดีบักจน token ปรากฏใน log ของ CI

## ความเข้าใจผิดที่พบบ่อย

### 1. ยังแยก Plugin กับ MCP ไม่ชัด เป็นปัญหาหรือไม่

ในระยะแรกไม่ใช่ปัญหาใหญ่

จุดร่วมคือ:  
ทั้งสองทำให้ Codex เข้าถึงระบบภายนอก จึงต้องพิจารณาสิทธิ์และความเสี่ยงเหมือนกัน

### 2. เหตุใดจึงเน้น “อ่านอย่างเดียวก่อน”

เพราะการอ่านอย่างเดียวมักทำให้:

- ทดลองใช้ได้ง่ายกว่า
- เห็นคุณค่าได้ง่ายกว่า
- ความเสียหายเมื่อผิดพลาดต่ำกว่า

### 3. ติดตั้งส่วนขยายแล้วใช้งานได้อย่างมั่นใจทันทีหรือไม่

แม้ฟังก์ชันจะดูสะดวก ก็ยังต้องถามว่า:

- เข้าถึงข้อมูลใดได้
- เขียนข้อมูลกลับเข้าระบบหรือไม่
- จัดการข้อมูลประจำตัวอย่างไร

สำหรับส่วนขยายภายนอก ให้ตรวจสิทธิ์และขอบเขตก่อนประเมินความสามารถ
