ไคลเอนต์ Codex บางตัวรองรับ **เสียง**: คุณพูดงานหรือฟังสรุปคำตอบได้ เหมาะเมื่อมือไม่ว่างหรืออยากพูดแนวคิดอย่างรวดเร็ว แต่ **ไม่** เหมาะกับการอ่าน Key และแทนบันทึกตรวจรับแบบลายลักษณ์อักษรไม่ได้

เสียงเหมาะกับการบอกทิศทาง เติมภูมิหลัง หรือติดตามเร็ว ๆ ส่วนรายละเอียดที่ต้องแม่น ค้นหาได้ และตรวจย้อนหลังได้ ควรกลับมาใช้ข้อความ

## เนื้อหาในหน้านี้

- งานรูปแบบใดเหมาะกับเสียง
- ใช้ร่วมกับพรอมต์ข้อความอย่างไร
- ข้อควรระวังเรื่องความเป็นส่วนตัวและความแม่นยำ

## กรณีใช้งาน

| เหมาะ | ไม่เหมาะ |
|---|---|
| พูดเป้าหมายระดับสูงและระดมความคิด | คำสั่งโค้ดที่ต้องตรงชื่อตัวแปร |
| ติดตามสั้น ๆ บนมือถือ | อ่าน API key หรือรหัสผ่าน |
| ความต้องการด้าน Accessibility | เอกสารข้อกำหนดที่ต้องค้นหาและ diff ได้ |

หลังพูด ควรให้ Codex **ทวนความเข้าใจ** หรือสร้างแผนข้อความให้คุณยืนยัน ดู [ขอแผน](/th/prompts/ask-for-a-plan/)

## เสียงเหมาะกับอะไร

ข้อดีหลัก:

- รวดเร็ว
- ไม่ต้องใช้มือ
- เหมาะกับการถ่ายทอดความคิดออกมาก่อน

ปัญหาที่พบบ่อย:

- คำตกหล่น
- ฟังผิด
- ไม่เหมาะกับเส้นทาง ชื่อตัวแปร และพารามิเตอร์บรรทัดคำสั่งที่ต้องแม่น

วิธีทั่วไปคือพูดทิศทางก่อน แล้วเติมเป็นข้อความเพื่อยืนยัน

## คำแนะนำการใช้

1. ใช้สภาพแวดล้อมเงียบ ประโยคสั้น และแบ่ง “เป้าหมาย / ข้อจำกัด / เกณฑ์เสร็จ” ให้ชัด
2. เมื่อมีเส้นทางไฟล์หรือชื่อ Branch ให้ **พิมพ์** หรือให้ Agent ทวนการสะกด
3. ปิดการประมวลผลเสียงบน Cloud สำหรับโปรเจกต์อ่อนไหว หากผลิตภัณฑ์มีตัวเลือก Local/ปิดใช้
4. เก็บการตัดสินใจสำคัญเป็นข้อความใน issue หรือ PR

## ความเข้าใจผิดที่พบบ่อย

### 1. เสียงแทนการพิมพ์ได้ทั้งหมดหรือไม่

ไม่ได้ เรื่องต่อไปนี้ควรพิมพ์:

- เส้นทางไฟล์
- ชื่อ Branch
- คำสั่ง
- พารามิเตอร์
- เกณฑ์ยอมรับ

### 2. ยิ่งพูดยาวและละเอียด ไม่ได้แปลว่าจะผิดพลาดน้อยลง

การพูดยาวโดยไม่มีโครงสร้างกลับทำให้ประเด็นสำคัญกระจาย

### 3. คำตอบเสียงแทนการตรวจผลได้หรือไม่

ไม่ได้ สรุปเสียงช่วยให้เข้าใจภาพรวมเร็ว แต่เมื่อตรวจการเปลี่ยนแปลง ไฟล์ diff และผลทดสอบ ยังต้องกลับมาที่ข้อความและ Artifact จริง

## ลำดับการพูดที่ใช้บ่อย

เมื่อต้องการมอบงานด้วยเสียง ให้พูดตามลำดับนี้:

1. ต้องการทำอะไร
2. ห้ามทำอะไร
3. เสร็จแล้วตรวจอย่างไร

จากนั้นให้จัดเป็นข้อความเพื่อให้คุณยืนยัน

## ความเป็นส่วนตัว

- เสียงอาจถอดข้อความบน Cloud อย่าอ่าน PII ของลูกค้าหรือข้อมูลรับรอง
- ระวังคนอื่นได้ยินในที่สาธารณะ
- นโยบายทีมอาจห้ามฟีเจอร์บันทึกเสียงประมวลชื่อรหัสลับ

## ความสัมพันธ์กับ Multimodal

- **อินพุตภาพ**: แบบออกแบบ ภาพหน้าจอ → [พรอมต์ด้วยภาพ](/th/prompts/prompting-with-images/)
- **อินพุตเสียง**: หน้านี้
- **เอาต์พุต**: ยังเน้นโค้ด ไฟล์ และ diff แบบข้อความ สรุปเสียงแทนการตรวจทานไม่ได้

## ข้อผิดพลาดที่พบบ่อย

- พูดยาวโดยไม่มีโครงสร้างจน Agent ทำข้อจำกัดตกหล่น
- ยอมรับการเปลี่ยนโค้ดจำนวนมากผ่านเสียงโดยไม่ดู diff
- อธิบายเหตุ Production ที่ยังไม่ลบข้อมูลอ่อนไหวผ่านเสียง

เสียงเหมาะกับการเริ่มและติดตาม ไม่เหมาะแทนคำสั่งแม่นยำ การจัดการข้อมูลอ่อนไหว และการตรวจรับขั้นสุดท้าย
