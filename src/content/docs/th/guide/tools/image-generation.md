ในบางสถานการณ์ Codex เรียกใช้ความสามารถ **สร้างภาพ** ได้ เช่น ภาพประกอบ ร่างไอคอน ภาพแนวคิด UI และแผนภาพ ควรมองผลลัพธ์เป็น **Artifact ที่รอตรวจรับ** ไม่ใช่ทรัพย์สินแบรนด์ที่นำขึ้นใช้งานได้ทันที

เหมาะกับการสร้างร่างภาพก่อน ไม่เหมาะกับการใช้เป็นชิ้นงานสุดท้ายโดยตรง

## เนื้อหาในหน้านี้

- เมื่อใดควรสร้างภาพใน Codex และเมื่อใดควรใช้เครื่องมือเฉพาะทาง
- วิธีเขียนพรอมต์ภาพและข้อจำกัด
- ลิขสิทธิ์ แบรนด์ และการจัดการไฟล์

## กรณีใช้งาน

| เหมาะ | ไม่เหมาะ |
|---|---|
| ร่างภาพประกอบบล็อกและแผนภาพเอกสารภายใน | สื่อภายนอกที่ต้องทำตามคู่มือแบรนด์อย่างเคร่งครัด |
| สำรวจบรรยากาศ Layout ของ UI อย่างรวดเร็ว | งานออกแบบที่ต้องเหมือนระดับพิกเซล |
| ไอคอนตัวอย่างในบทสอน | ภาพบุคคลจริงที่ไม่ได้รับอนุญาต |

ใช้คู่กับ [พรอมต์ด้วยภาพ](/th/prompts/prompting-with-images/): หน้านั้นอธิบายภาพ **อินพุต** ส่วนหน้านี้อธิบายภาพ **เอาต์พุต**

## การสร้างภาพเหมาะกับอะไร

เหมาะกับ:

- หาแนวทางอย่างรวดเร็ว
- ช่วยให้เห็นแนวคิดด้านภาพ
- สร้างภาพร่างที่ใช้งานได้ก่อนสำหรับบทความ เอกสาร หรือ Prototype

ไม่ควรใช้ผลสร้างโดยตรงเพื่อ:

- อ้างว่าเป็นสื่อแบรนด์ทางการ
- อ้างว่าเป็นแบบออกแบบแม่นยำ
- อ้างว่าเป็นภาพสุดท้ายที่เผยแพร่ภายนอกได้ทันที

## เวิร์กโฟลว์ที่แนะนำ

1. ระบุวัตถุประสงค์ อัตราส่วนภาพ และคำหลักด้านสไตล์ โดยหลีกเลี่ยงการเรียงชื่อสไตล์ที่อาจละเมิดสิทธิ์
2. ระบุรูปแบบเอาต์พุต (PNG/SVG หากรองรับ) และเส้นทางบันทึก
3. หลังสร้าง ให้ [ตรวจสอบ Artifact](/th/guide/quality/verify-artifacts/): เปิดไฟล์ ตรวจความละเอียดและความอ่านง่าย
4. ก่อนเผยแพร่ภายนอก ให้ฝ่ายออกแบบหรือกฎหมายตรวจทาน

## ความเข้าใจผิดที่พบบ่อย

### 1. ภาพสวยแล้วแปลว่าใช้ได้หรือไม่

ยังต้องตรวจว่า:

- ฉากตรงกับวัตถุประสงค์หรือไม่
- รายละเอียดผิดธรรมชาติหรือไม่
- ข้อความเพี้ยนหรือไม่
- สไตล์เข้ากับเนื้อหาหรือไม่

### 2. พูดเพียง “ช่วยสร้างภาพ” พอหรือไม่

มักไม่พอ อย่างน้อยควรระบุ:

- วัตถุประสงค์
- แนวภาพหรืออัตราส่วน
- ทิศทางสไตล์
- ต้องมีข้อความหรือไม่
- รูปแบบไฟล์

### 3. การสร้างภาพแทนนักออกแบบได้หรือไม่

ใกล้เคียงกับ:

- เครื่องมือสำรวจช่วงต้น
- เครื่องมือภาพประกอบเนื้อหา
- เครื่องมือร่างแนวคิด

ไม่ใช่สิ่งทดแทนงานออกแบบส่งมอบที่มีข้อกำหนดเข้มงวด

## วิธีเขียนคำขอ

ใช้โครงสร้างนี้ได้:

1. ภาพนี้ใช้ทำอะไร
2. ต้องเป็นแนวนอน แนวตั้ง หรือสี่เหลี่ยม
3. ต้องการอารมณ์และสีแบบใด
4. ต้องมีข้อความหรือไม่
5. จะตรวจผลอย่างไร

## ไฟล์และ Repository

- เก็บภาพขนาดใหญ่ใน `assets/` หรือ CDN และประเมินขนาด Git
- ระบุพรอมต์ที่ใช้สร้างและเวอร์ชันโมเดลใน PR เพื่อการตรวจสอบภายใน
- ดู [ภาพและภาพหน้าจอ](/th/guide/files-and-artifacts/images-and-screenshots/)

## ความปลอดภัยและการปฏิบัติตามข้อกำหนด

- อย่าสร้างเนื้อหาชวนเข้าใจผิดที่มีเครื่องหมายอ่อนไหว เอกสารปลอม หรือภาพบุคคลอื่น
- นโยบายองค์กรอาจห้ามบางหัวข้อ ให้ปฏิบัติตาม [นโยบายการใช้งานที่ยอมรับได้](https://openai.com/policies/) และข้อกำหนดภายใน

## ข้อผิดพลาดที่พบบ่อย

- Commit ภาพ 4K ที่ไม่บีบอัดเข้า Repository โดยตรง
- ใช้ภาพสร้างแทนภาพถ่ายจริงหรือ Logo ทางการ
- ไม่ระบุ “ไม่มีข้อความ” ในพรอมต์จนเกิดตัวอักษรเพี้ยน

การสร้างภาพเหมาะกับการหาแนวทางและร่างก่อน สำหรับงานส่งมอบภายนอกยังต้องตรวจรับตามมาตรฐาน Artifact ทางการ
