**Computer Use** ช่วยให้ Agent ดูหน้าจอ เลื่อนตัวชี้ และพิมพ์ข้อความได้เหมือนมนุษย์ ไม่ได้จำกัดอยู่แค่เบราว์เซอร์หรือเทอร์มินัล เป็นความสามารถที่ทรงพลังที่สุด และมี **ความเสี่ยงกับข้อกำหนดการอนุมัติสูงที่สุด** เช่นกัน

Computer Use ทำงานตรงระดับหน้าจอ เมาส์ และแป้นพิมพ์ จึงเป็นคนละประเภทกับเครื่องมือเบราว์เซอร์และเทอร์มินัล และต้องเปิดใช้อย่างระมัดระวังกว่า

## เนื้อหาในหน้านี้

- การแบ่งหน้าที่ระหว่าง Computer Use เบราว์เซอร์ และเทอร์มินัล
- งานแบบใดคุ้มค่าที่จะเปิดใช้
- วิธีป้องกันสำหรับบุคคลและทีม

## ขอบเขตความสามารถ

| ระดับ | ความสามารถทั่วไป |
|---|---|
| เทอร์มินัล | Shell, สคริปต์, โปรแกรม CLI |
| เบราว์เซอร์ | DOM ของเว็บและการโต้ตอบจำกัด |
| Computer Use | แอป Desktop กล่องโต้ตอบระบบ และเวิร์กโฟลว์หลายหน้าต่าง |

## ต่างจากเครื่องมืออื่นอย่างไร

แยกได้ดังนี้:

- ทำงานทั่วทั้ง Desktop
- สลับระหว่างหลายหน้าต่าง
- กดปุ่มจริงและกล่องโต้ตอบระบบ

ดังนั้นขอบเขตอินเทอร์เฟซและข้อมูลที่สัมผัสได้มักกว้างกว่า

เหมาะกับ:

- สาธิตขั้นตอนคลิกซ้ำในซอฟต์แวร์ที่ไม่มี API (โดยคุณกำกับดูแล)
- คัดลอกข้อมูลข้ามแอป (ภายใต้ข้อกำหนด)
- ตรวจพฤติกรรมของ Desktop App

ไม่เหมาะกับ:

- เขียนโค้ดประจำวัน (IDE + เทอร์มินัลมีประสิทธิภาพกว่า)
- ควบคุม Production แบบไม่มีผู้ดูแล
- ข้ามซอฟต์แวร์ความปลอดภัยหรือ DRM

## ความเข้าใจผิดที่พบบ่อย

### 1. ความสามารถสูงกว่า แปลว่าควรใช้ก่อนหรือไม่

มีคุณค่าชัดเจนเมื่อ:

- งานเกี่ยวข้องกับ Desktop GUI จริง
- ไม่มีเครื่องมือที่เบาและปลอดภัยกว่าทำได้

### 2. ถ้าเฝ้าดูอยู่ตลอด จะไม่มีความเสี่ยงหรือไม่

การมีคนเฝ้าปลอดภัยกว่า แต่ยังอาจเกิด:

- กดกล่องยืนยันผิด
- เปิดหน้าต่างที่ไม่ควรเปิด
- นำข้อมูลอ่อนไหวบนหน้าจอเข้าสู่กระบวนการ

### 3. ใช้แทนระบบอัตโนมัติ GUI ทั้งหมดได้หรือไม่

เหมาะกับการช่วยชั่วคราว ตรวจขั้นตอน และจัดการ GUI ที่ไม่มี API มากกว่า ไม่เหมาะเป็นระบบอัตโนมัติ Production ที่เสถียร ระยะยาว และไม่มีผู้ดูแล

## โมเดลความเสี่ยง

Computer Use แทบเท่ากับ **มอบแป้นพิมพ์และเมาส์ให้ Agent**:

- เปิดอีเมล แชต และตัวจัดการไฟล์ได้
- อาจกดกล่องยืนยันผิด
- หน้าจออาจมีข้อมูลอ่อนไหวใน Notification

ต้องอ่าน: [สิทธิ์และการอนุมัติ](/th/guide/foundations/permissions-and-approvals/) และ [Sandbox กับเครือข่าย](/th/guide/foundations/sandbox-and-network/)

## ตัดสินใจว่าควรใช้หรือไม่

หากเป้าหมายเป็นเพียงเรื่องต่อไปนี้ โดยทั่วไปไม่ต้องใช้ Computer Use ก่อน:

- แก้โค้ด
- รันการทดสอบ
- ดูเว็บ
- ค้นข้อมูล

ส่วนใหญ่ทำได้ด้วยเครื่องมือที่เบากว่า

ค่อยพิจารณาเปิดใช้เมื่อ:

- ต้องควบคุมแอป Desktop
- ต้องทำงานข้ามหลายหน้าต่าง GUI
- ต้องจัดการอินเทอร์เฟซที่เบราว์เซอร์และเทอร์มินัลเข้าไม่ถึง

## วิธีใช้ที่แนะนำ

1. **สภาพแวดล้อมเฉพาะ**: Virtual Machine หรือบัญชีผู้ใช้รอง โดยไม่มีหน้าต่างส่วนตัวบนจอ
2. **ลดขนาดงาน**: “ตรวจสูตรใน Calculator” แทน “จัดการอีเมลทั้งหมดให้หน่อย”
3. **มีคนในวงจร**: เปิดให้มองเห็นและพร้อมหยุดได้ตลอด
4. **บันทึกหน้าจอ/Log**: ใช้ทบทวนในทีม โดยจำไว้ว่าบันทึกอาจมีข้อมูลอ่อนไหว
5. **ตรวจหลังเสร็จ**: ระบบไฟล์ Clipboard และแอปที่เปิดอยู่

สภาพแวดล้อมองค์กรอาจปิดโดยค่าเริ่มต้น ให้ยึดนโยบายที่บริหารจากส่วนกลาง

## เลือกระหว่าง Computer Use กับเบราว์เซอร์

```text
ต้องดูเว็บเท่านั้น?          → เครื่องมือเบราว์เซอร์
ต้องควบคุมแอปนอก IDE?      → Computer Use (ระวังมากกว่า)
ต้องแก้โค้ดและรันทดสอบเท่านั้น? → เทอร์มินัล + เครื่องมือไฟล์
```

ดู [การเลือกเครื่องมือ](/th/guide/tools/tool-selection/)

## ข้อความที่นำไปใช้ได้ทันที

```text
อนุญาตให้ควบคุมเฉพาะ Calculator และแอปทดสอบในเครื่อง ห้ามเปิดอีเมล โปรแกรมแชต ตัวจัดการไฟล์ หรือระบบหลังบ้าน Production ใด ๆ
หากมีกล่องยืนยันของระบบ ให้หยุดและอธิบายก่อนดำเนินต่อ
```

## ข้อผิดพลาดที่พบบ่อย

- รัน Computer Use ของโปรเจกต์ที่ไม่น่าเชื่อถือบน Desktop หลัก
- ทำงานต่อทั้งที่บนจอมี 2FA ข้อมูลธนาคาร หรือข้อมูลลูกค้า
- ถือว่าระบบอัตโนมัติ GUI เป็นกลยุทธ์ทดสอบที่ครบถ้วน
