“การเลือกเครื่องมือ” คือการตัดสินว่างานนี้ควรทำด้วยวิธีใดจึงมีประสิทธิภาพและปลอดภัย

การตัดสินตามประเภทงานมักชัดเจนที่สุด

## พิจารณาอะไรเมื่อเลือกเครื่องมือ

- เครื่องมือใดใกล้กับงานปัจจุบันที่สุด
- เครื่องมือใดให้ผลด้วยต้นทุนน้อยที่สุด
- เครื่องมือใดเสี่ยงต่ำและตรวจง่ายที่สุด

การใช้เครื่องมือผิดอาจไม่ทำให้งานล้มเหลวทั้งหมด แต่มักช้าลง อ้อมขึ้น และเกิดเหตุไม่คาดคิดง่ายขึ้น

| ความต้องการ | ใช้ก่อน |
|---|---|
| แก้ไฟล์ใน Repository | เครื่องมือไฟล์ |
| รันการทดสอบ/Build | เทอร์มินัล |
| ตรวจข้อเท็จจริงสาธารณะ | Web Search |
| ดูสถานะหน้าจริง | เบราว์เซอร์ (ขั้นสูง) |

ระบุเครื่องมือที่อนุญาตและห้ามใช้ในพรอมต์ เพื่อลดการเชื่อมต่อภายนอกหรือติดตั้ง Dependency โดยพลการ

## ถ้ายังเลือกไม่ได้

พิจารณาตามลำดับนี้:

1. กำลังจัดการโปรเจกต์ในเครื่อง หรือตรวจข้อเท็จจริงภายนอก
2. ต้อง “ลงมือทำ” หรือเพียง “ดูผล”
3. เครื่องมือใดทำขั้นนี้ได้ในขอบเขตเล็กที่สุด

ตัวอย่าง:

- ดูการเปลี่ยนแปลงโค้ด -> ไฟล์
- ยืนยันว่า Build ผ่าน -> เทอร์มินัล
- ยืนยันว่าหน้าเว็บตอนนี้เป็นอย่างไร -> เบราว์เซอร์
- ยืนยันข้อมูลสาธารณะล่าสุด -> Web Search

## ความเข้าใจผิดที่พบบ่อย

### 1. เครื่องมือไม่ได้ยิ่งทรงพลังยิ่งดี

เครื่องมือที่ทรงพลังกว่ามักหมายถึง:

- ขอบเขตผลกระทบกว้างกว่า
- ความเสี่ยงสูงกว่า
- ต้องเข้าใจสิ่งที่กำลังทำมากกว่า

### 2. แม้เทอร์มินัลทำได้ทุกอย่าง ก็ไม่จำเป็นต้องใช้ก่อน

ถ้าต้องการเพียงดูหน้าจริง เบราว์เซอร์มักตรงกว่าเทอร์มินัล หากต้องการเพียงตรวจเลขเวอร์ชันสาธารณะ Web Search เหมาะกว่าการรันคำสั่งไปทั่ว

### 3. ถ้าเลือกไม่เป็นควรทำอย่างไร

ใช้กฎนี้:

- **อ่านและแก้เนื้อหาโปรเจกต์** -> ไฟล์
- **ตรวจคำสั่งหรือ Build** -> เทอร์มินัล
- **ตรวจข้อเท็จจริงสาธารณะ** -> Search
- **ดูการแสดงผลจริงของหน้า** -> เบราว์เซอร์

### 4. งานหนึ่งมักใช้มากกว่าหนึ่งเครื่องมือ

งานจริงจำนวนมากต้องใช้ร่วมกัน เช่น:

- อ่านไฟล์ก่อน แล้วรัน Build
- ค้นข้อเท็จจริงสาธารณะก่อน แล้วกลับมาแก้เอกสาร
- ใช้เบราว์เซอร์ดูหน้าก่อน แล้วแก้ในโค้ด

ประเด็นคือใช้เครื่องมือที่เหมาะในแต่ละขั้น ไม่ต้องยึดว่า “เลือกได้เพียงหนึ่ง”

## ข้อความที่ใช้ได้ทันที

```text
ใช้ไฟล์และเทอร์มินัลก่อน ห้ามค้นอินเทอร์เน็ต หากต้องใช้เบราว์เซอร์ตรวจหน้า ให้อธิบายเหตุผลก่อน
```

เลือกเครื่องมือที่เล็กที่สุดและตรงงานที่สุดก่อน อย่าเริ่มจากเครื่องมือที่มีขอบเขตผลกระทบกว้างที่สุด
