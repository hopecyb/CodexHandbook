Web Search เหมาะกับการเติมข้อเท็จจริง ไม่เหมาะกับการตัดสินข้อสรุปสุดท้ายแทนคุณ

เหมาะกับการค้นเอกสารสาธารณะ รหัสข้อผิดพลาด และ Release Notes ไม่เหมาะกับการถือผลค้นเป็นข้อสรุปทางกฎหมาย การแพทย์ หรือการเงิน

ขอให้แนบแหล่งที่มาและเปิดตรวจด้วยตนเอง ใช้ร่วมกับ [ตรวจสอบแหล่งข้อมูล](/th/guide/quality/validate-sources/)

## Search เหมาะกับอะไร

Search ช่วยหา:

- ควรดูที่ไหน
- ข้อมูลใดควรตรวจเพิ่ม
- มีแหล่งที่น่าเชื่อถือกว่าหรือไม่

หน้าที่คือหาเอกสารก่อน แล้วจึงกลับไปตรวจต้นฉบับ

## ความเข้าใจผิดที่พบบ่อย

### 1. ค้นเจอแล้วแปลว่าคำตอบน่าเชื่อถือหรือไม่

ไม่ใช่ ค้นเจอไม่ได้แปลว่าน่าเชื่อถือ และสรุปที่ลื่นไหลก็ไม่ได้แปลว่าถูกต้อง

### 2. ควรใช้ Search เมื่อใด

สถานการณ์ทั่วไป:

- ค้นเอกสารทางการ
- ค้นข้อความข้อผิดพลาด
- ค้นการเปลี่ยนแปลงเวอร์ชัน
- ตรวจข้อเท็จจริงบนเว็บสาธารณะ

### 3. อ้างสรุปในผลค้นโดยตรงได้หรือไม่

อย่าเพิ่งอ้างโดยตรง ให้ทำดังนี้:

1. ดูว่าผลค้นมีแหล่งใดบ้าง
2. เปิดหน้าต้นฉบับ
3. สรุปด้วยคำของตนเอง

### 4. เมื่อใดไม่ควรพึ่ง Search อย่างเดียว

เมื่อเป็น:

- การตัดสินทางกฎหมาย การแพทย์ หรือการเงินที่มีความเสี่ยงสูง
- ต้องยืนยันพฤติกรรมจริงของหน้าเว็บ
- ต้องตรวจไฟล์ในโปรเจกต์ ไม่ใช่ข้อมูลสาธารณะ

ต้องใช้เครื่องมืออื่นหรือการตรวจโดยมนุษย์ร่วมด้วย

## ลำดับการค้น

1. ค้นคำหลักที่ใกล้ปัญหาที่สุด
2. ให้ความสำคัญกับเอกสารทางการหรือแหล่งปฐมภูมิ
3. เปิดต้นฉบับเพื่อยืนยันรายละเอียด
4. แล้วค่อยตัดสินใจว่าจะใส่ข้อสรุปในผลลัพธ์หรือไม่

## ข้อความที่ใช้ได้ทันที

```text
ค้นก่อนและใช้แหล่งทางการเป็นหลัก เมื่อสรุปให้แนบลิงก์แหล่งที่มาที่คลิกได้ อย่าให้เฉพาะสรุปจากหน้าผลค้น
```

Search ให้เบาะแสและแหล่งที่มา แต่สุดท้ายยังต้องกลับไปตรวจต้นฉบับ
