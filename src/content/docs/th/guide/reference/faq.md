หากมีคำถามย่อย ๆ อยู่หลายเรื่อง ลองเปิด FAQ ก่อน ที่นี่ไม่ได้อธิบายเนื้อหาทั้งระบบอย่างละเอียด แต่เน้นช่วยให้คุณค้นพบอย่างรวดเร็วว่าควรอ่านอะไรต่อ

## ควรอ่านเมื่อใด

เมื่อพบสถานการณ์ต่อไปนี้ ลองเปิด FAQ ก่อนได้:

- มีหลายหน้าจนไม่รู้ว่าควรอ่านหน้าใดต่อ
- ติดขัดกับปัญหาบางอย่าง แต่ยังไม่จำเป็นต้องอ่านทั้งบท
- ต้องการคำแนะนำเบื้องต้นเพื่อกำหนดทิศทางก่อน

**ถาม: เพิ่งเริ่มต้นควรใช้ไคลเอนต์ใด**  
ตอบ: App เดสก์ท็อป ดู [เลือกไคลเอนต์](/th/guide/choose-your-client/)

**ถาม: ข้ามการตรวจสอบแล้วรับการเปลี่ยนแปลงทั้งหมดได้ไหม**  
ตอบ: ไม่ควร ดู [การตรวจสอบและการทบทวนโดยมนุษย์](/th/guide/foundations/verification-and-human-review/)

**ถาม: พรอมต์มีเทมเพลตมาตรฐานไหม**  
ตอบ: มีกรอบให้ใช้ แต่ไม่มีสูตรวิเศษ ดู [โครงสร้างของงานที่ดี](/th/prompts/task-anatomy/)

**ถาม: หากคู่มือขัดแย้งกับเอกสารทางการควรทำอย่างไร**  
ตอบ: ให้ยึดเอกสารทางการเป็นหลัก: [https://developers.openai.com/codex](https://developers.openai.com/codex) และยินดีรับ issue

**ถาม: AGENTS.md, Skill และ MCP ต่างกันอย่างไร**  
ตอบ: ดู [แผนที่ความสามารถส่วนขยาย](/th/skills/capability-map/) และ [วิธีเลือกแนวทางขยายความสามารถ](/th/skills/choosing-an-extension-method/)

**ถาม: มีเวิร์กโฟลว์มาตรฐานที่แนะนำไหม**  
ตอบ: โดยค่าเริ่มต้นให้ใช้ [สำรวจ—วางแผน—ลงมือทำ—ตรวจสอบ](/th/cases/workflows/explore-plan-execute-verify/)

**ถาม: จะเชื่อม Cloud กับ GitHub และเปิด PR ได้อย่างไร**  
ตอบ: ดู [เชื่อมต่อ GitHub](/th/guide/web-and-cloud/connect-github/) และ [สร้าง Pull Request](/th/guide/web-and-cloud/create-pull-requests/)

**ถาม: นำ CLI ไปใช้ใน CI ได้ไหม**  
ตอบ: ได้ เริ่มจาก [โหมดไม่โต้ตอบ](/th/guide/cli/non-interactive-mode/) และออกแบบขั้นตอนการอนุมัติกับสิทธิ์ให้เหมาะสม

**ถาม: มีคำสั่งแบบสแลชอะไรบ้าง**  
ตอบ: ให้ยึดรายการเติมข้อความอัตโนมัติที่แสดงเมื่อพิมพ์ `/` ในไคลเอนต์เป็นหลัก ส่วนคำอธิบายเพื่อการเรียนรู้ดู [คู่มืออ้างอิงด่วนสำหรับคำสั่งแบบสแลช](/th/guide/reference/slash-commands/)

**ถาม: แล้วเส้นทางฉบับเต็มสำหรับครีเอเตอร์ นักพัฒนา และทีมล่ะ**  
ตอบ: มีเส้นทางเริ่มต้นแล้ว สำหรับกรณีศึกษาเชิงลึกดู [กรณีศึกษาตามสถานการณ์](/th/cases/use-cases/) ส่วนการกำกับดูแลทีมอยู่ในแผนงาน M6 `11-team-enterprise`

## ความเข้าใจผิดที่พบบ่อย

### 1. FAQ จะอ่านหรือไม่อ่านก็ได้ใช่ไหม

สำหรับผู้เริ่มต้น FAQ มักเป็นจุดเริ่มต้นที่ค่อนข้างรวดเร็ว

### 2. คำตอบใน FAQ เพียงพอให้นำไปปฏิบัติได้ทันทีหรือไม่

FAQ มีหน้าที่หลักสองอย่าง:

- ช่วยชี้ทิศทางเบื้องต้น
- พาคุณไปยังหน้าที่อธิบายได้ครบถ้วนกว่า

### 3. หากไม่มีคำถามของฉันที่นี่ แปลว่าคู่มือไม่ได้กล่าวถึงใช่ไหม

บางครั้งเนื้อหาของคำถามนั้นอาจกระจายอยู่ใน:

- หน้าหัวข้อเฉพาะที่เกี่ยวข้อง
- หน้าเส้นทางการเรียนรู้
- หน้ากรณีศึกษาจากการใช้งานจริง

## วิธีใช้

หากติดขัดแต่ไม่แน่ใจว่าควรไปหน้าใด ให้ใช้ FAQ ดังนี้:

1. เปิด FAQ ก่อน
2. ค้นหาคำถามที่ใกล้เคียงที่สุด
3. ตามลิงก์ไปยังหัวข้อเฉพาะที่เกี่ยวข้อง

โดยทั่วไป วิธีนี้จะสะดวกกว่าการไล่เปิดไปมาในแถบด้านข้าง
