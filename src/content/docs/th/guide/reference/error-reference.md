เมื่อเห็นข้อผิดพลาด หลายคนมักจ้องข้อความภาษาอังกฤษบรรทัดนั้นซ้ำ ๆ แล้วพยายามเดาคำตอบจากสัญชาตญาณ แต่โดยทั่วไป การจำแนกประเภทของปัญหาก่อนจะได้ผลมากกว่า

เมื่อพบข้อผิดพลาด ให้พิจารณาก่อนว่าปัญหานั้นใกล้เคียงกับ **การยืนยันตัวตน สิทธิ์ สภาพแวดล้อม เครือข่าย หรือตรรกะของงาน** มากที่สุด หน้านี้สรุปความหมายโดยทั่วไปของข้อความที่พบบ่อยและขั้นตอนถัดไป ไม่ใช่พจนานุกรมข้อผิดพลาดฉบับสมบูรณ์ ส่วนพฤติกรรมล่าสุดให้ยึดเอกสารอย่างเป็นทางการและผลลัพธ์จากไคลเอนต์เป็นหลัก

## เมื่อพบข้อผิดพลาด ควรอ่านอย่างไรก่อน

เมื่อเพิ่งพบข้อผิดพลาด ให้เริ่มจากสามขั้นตอนต่อไปนี้:

1. ดูว่าคำสำคัญอยู่ในประเภทใด: การยืนยันตัวตน สิทธิ์ สภาพแวดล้อม เครือข่าย หรือบริบท
2. ดูว่าเกิดขึ้นในขั้นตอนใด: เริ่มต้น ติดตั้ง ดำเนินการ push หรือสร้างผลลัพธ์
3. จากนั้นจึงไปยังหน้าหัวข้อเฉพาะเพื่อแก้ปัญหา

โดยทั่วไป วิธีนี้เร็วกว่าการเดาสาเหตุโดยตรง

ดัชนีรวม: [การแก้ปัญหา](/th/guide/reference/troubleshooting/)

## การยืนยันตัวตนและบัญชี

| ข้อความแจ้งหรืออาการ | สาเหตุที่เป็นไปได้ | ขั้นตอนถัดไป |
|---|---|---|
| Authentication failed / 401 | token หมดอายุ หรือยังไม่ได้ลงชื่อเข้าใช้ | [การลงชื่อเข้าใช้และการยืนยันตัวตน](/th/guide/getting-started/sign-in-and-authentication/) |
| Organization policy | องค์กรปิดใช้ฟังก์ชันหรือโมเดล | ติดต่อผู้ดูแลระบบ และตรวจสอบแพ็กเกจใน [บัญชีและการเข้าถึง](/th/guide/getting-started/account-plans-and-access/) |
| Rate limit / 429 | ส่งคำขอถี่เกินไปหรือถึงโควตา | ลองใหม่ภายหลัง และตรวจสอบการใช้งานตามแพ็กเกจ |

## ความเข้าใจผิดที่พบบ่อย

### 1. ข้อความข้อผิดพลาดที่ยาวไม่ได้หมายความว่าปัญหาซับซ้อนกว่าเสมอไป

ข้อความข้อผิดพลาดยาว ๆ จำนวนมากเพียงรวบรวมบริบทไว้หลายชั้น ส่วนที่มีประโยชน์จริงมักเป็นคำสำคัญเพียงช่วงสั้น ๆ

### 2. รหัสออกที่ไม่ใช่ศูนย์ไม่ได้หมายความว่าโมเดลทำงานนั้นไม่ได้เสมอไป

สาเหตุอาจเป็นเพียง:

- ยังไม่ได้ให้สิทธิ์
- เครือข่ายเชื่อมต่อไม่ได้
- รูปแบบผลลัพธ์ไม่ตรงตามข้อกำหนด
- ตัวงานเองเข้าเงื่อนไขที่ทำให้ล้มเหลว

### 3. 401 / 403 / 429 ไม่ใช่ปัญหาเดียวกัน

ทั้งสามกรณีแตกต่างกันอย่างมาก:

- `401` โดยทั่วไปหมายถึง “ยืนยันตัวตนไม่สำเร็จ”
- `403` โดยทั่วไปหมายถึง “ระบบรู้ว่าคุณเป็นใคร แต่ไม่อนุญาตให้ทำ”
- `429` โดยทั่วไปหมายถึง “คุณส่งคำขอเร็วเกินไป โปรดลองอีกครั้งภายหลัง”

### 4. บรรทัดสุดท้ายไม่ได้สำคัญที่สุดเสมอไป

บางครั้งบรรทัดสุดท้ายเป็นเพียง “สรุปว่าล้มเหลวในท้ายที่สุด” แต่ข้อมูลที่มีประโยชน์จริงอาจอยู่ก่อนหน้านั้นหลายบรรทัด เช่น:

- ขั้นตอนใดเป็นตัวกระตุ้น
- ไฟล์ คำสั่ง หรือเครื่องมือใดล้มเหลว
- มีข้อความที่บอกสาเหตุดั้งเดิมหรือไม่

## CLI และคำสั่ง

| ข้อความแจ้งหรืออาการ | สาเหตุที่เป็นไปได้ | ขั้นตอนถัดไป |
|---|---|---|
| command not found: codex | ยังไม่ได้ติดตั้ง หรือมีปัญหากับ PATH | [ติดตั้ง CLI](/th/guide/getting-started/install-cli/) |
| Config parse error | ไวยากรณ์ TOML/YAML | [การกำหนดค่า CLI](/th/guide/cli/configuration/) |
| Permission denied (write) | แซนด์บ็อกซ์หรือการอนุมัติปฏิเสธการดำเนินการ | [การอนุมัติและแซนด์บ็อกซ์](/th/guide/cli/approvals-and-sandbox/) |
| รหัสออกที่ไม่ใช่ศูนย์ (exec) | งานล้มเหลวหรือไม่ตรงตามเงื่อนไขเสร็จสมบูรณ์ | ตรวจสอบล็อก stderr และจำกัดขอบเขตพรอมต์ให้แคบลง |

## จำแนกประเภทก่อน

หากไม่รู้ว่าควรเริ่มจากจุดใด ให้แบ่งข้อผิดพลาดออกเป็น 5 ประเภท:

| ประเภท | สิ่งที่ควรตรวจสอบก่อน |
|---|---|
| การยืนยันตัวตน | บัญชี token และสถานะการลงชื่อเข้าใช้ |
| สิทธิ์ | การอนุมัติ แซนด์บ็อกซ์ และสิทธิ์ของรีโพซิทอรี |
| สภาพแวดล้อม | การติดตั้ง PATH การกำหนดค่า และ dependency |
| เครือข่าย | การเชื่อมต่อออก พร็อกซี และการเข้าถึงบริการระยะไกล |
| ตรรกะของงาน | พรอมต์ ไฟล์อินพุต และข้อกำหนดของผลลัพธ์ |

เมื่อจำแนกได้ถึงขั้นนี้ ทิศทางการแก้ปัญหาก็มักไม่ออกนอกทาง

## วิธีใช้

ให้ใช้หน้านี้เป็นตารางคัดแยกข้อผิดพลาด ไม่จำเป็นต้องมองว่าเป็นพจนานุกรมฉบับสมบูรณ์:

- มองหาคำสำคัญ
- หาให้พบว่าอยู่ในประเภทใด
- ไปยังหน้าแก้ปัญหาที่เจาะจงยิ่งขึ้น

หากยังไม่เข้าใจ ให้เปลี่ยนข้อความข้อผิดพลาดเป็นคำถามที่ตรงไปตรงมายิ่งขึ้น:

- ลงชื่อเข้าใช้ไม่สำเร็จใช่ไหม
- ไม่มีสิทธิ์ใช่ไหม
- คำสั่งนี้ยังไม่ได้ติดตั้งอย่างถูกต้องใช่ไหม
- เครือข่ายเข้าถึงปลายทางไม่ได้ใช่ไหม
- ข้อกำหนดที่ให้ Codex ยังไม่ชัดเจนใช่ไหม

หากยังตัดสินใจไม่ได้ว่าควรอ่านอะไรต่อ ให้ใช้หน้านี้จำแนกปัญหาเป็นหมวดหมู่ใหญ่ก่อน

## สิทธิ์และแซนด์บ็อกซ์

| ข้อความแจ้งหรืออาการ | สาเหตุที่เป็นไปได้ | ขั้นตอนถัดไป |
|---|---|---|
| User rejected tool call | คุณหรือนโยบายปฏิเสธการดำเนินการ | ตรวจสอบว่าควรอนุมัติหรือไม่ หรือแก้ไขงาน |
| Sandbox violation | พาธที่เขียนหรือคำสั่งอยู่นอกขอบเขต | [แซนด์บ็อกซ์และเครือข่าย](/th/guide/foundations/sandbox-and-network/) |
| Network access denied | ไม่อนุญาตให้เชื่อมต่อออก | Cloud: [การเข้าถึงอินเทอร์เน็ต](/th/guide/web-and-cloud/internet-access/) |

## Cloud และ GitHub

| ข้อความแจ้งหรืออาการ | สาเหตุที่เป็นไปได้ | ขั้นตอนถัดไป |
|---|---|---|
| Repository access denied | ขอบเขต OAuth ไม่เพียงพอ | [เชื่อมต่อ GitHub](/th/guide/web-and-cloud/connect-github/) |
| Clone failed | ชื่อรีโพซิทอรี สิทธิ์ หรือเครือข่าย | [การแก้ปัญหา Cloud](/th/guide/web-and-cloud/troubleshooting/) |
| Secret not found | ชื่อหรือขอบเขตไม่ถูกต้อง | [Secrets และตัวแปร](/th/guide/web-and-cloud/secrets-and-variables/) |
| Push rejected | การป้องกันสาขา | [สร้าง PR](/th/guide/web-and-cloud/create-pull-requests/) |

## MCP และส่วนขยาย

| ข้อความแจ้งหรืออาการ | สาเหตุที่เป็นไปได้ | ขั้นตอนถัดไป |
|---|---|---|
| MCP server failed to start | พาธคำสั่งหรือ dependency ขาดหาย | [เชื่อมต่อ MCP](/th/skills/mcp/connect-an-mcp-server/) |
| Tool timeout | API ภายนอกทำงานช้าหรือหยุดให้บริการ | ลองใหม่ และตรวจสอบล็อก MCP |
| Unknown tool | การกำหนดค่าไม่ตรงกับเวอร์ชันของเซิร์ฟเวอร์ | เริ่มเซสชันใหม่ และอัปเดตการกำหนดค่า |

## บริบทและโมเดล

| ข้อความแจ้งหรืออาการ | สาเหตุที่เป็นไปได้ | ขั้นตอนถัดไป |
|---|---|---|
| Context length exceeded | บทสนทนาหรือไฟล์ที่อ้างด้วย @ มีขนาดใหญ่เกินไป | [การบีบอัด](/th/guide/context/compaction/) · ลดขอบเขต |
| Model not available | ภูมิภาคหรือแพ็กเกจไม่รองรับ | [โมเดลและการให้เหตุผล](/th/guide/foundations/models-and-reasoning/) |

## วิธีใช้หน้านี้

1. **คัดลอกประโยคสำคัญ** ไปค้นหาในไคลเอนต์หรือคู่มือนี้
2. ไปยังหน้าหัวข้อเฉพาะตามตาราง แล้วทำตามรายการตรวจ
3. หากยังแก้ไม่ได้ ให้เก็บล็อกฉบับเต็มไว้แล้วดู [แหล่งข้อมูลอย่างเป็นทางการ](/th/guide/reference/official-resources/)

## ข้อมูลที่ควรแนบเมื่อรายงานปัญหา

- ประเภทและเวอร์ชันของไคลเอนต์ (App / CLI / IDE / Cloud)
- ระบบปฏิบัติการ
- ข้อความข้อผิดพลาดฉบับเต็มที่ปกปิดข้อมูลละเอียดอ่อนแล้ว
- ใช้โหมดไม่โต้ตอบหรือไม่ และใช้ CI หรือไม่

## ลำดับการแก้ปัญหา

1. จับภาพหน้าจอหรือคัดลอกข้อความข้อผิดพลาดทั้งหมดก่อน อย่าเก็บเพียงประโยคสุดท้าย
2. จำแนกประเภทก่อน โดยยังไม่ต้องรีบเดารายละเอียดทางเทคนิค
3. ทบทวนว่าเพิ่งเปลี่ยนแปลงอะไรไป
4. เปลี่ยนตัวแปรเพียงหนึ่งรายการ แล้วลองใหม่หนึ่งครั้ง
5. หากยังไม่ได้ผล ให้นำข้อมูลทั้งหมดไปสอบถามผู้อื่นหรือตรวจสอบเอกสารอย่างเป็นทางการ

วิธีนี้ช่วยไม่ให้การเปลี่ยนแปลงหลายอย่างปะปนกัน และช่วยให้ผู้อื่นระบุตำแหน่งปัญหาได้ง่ายขึ้น
