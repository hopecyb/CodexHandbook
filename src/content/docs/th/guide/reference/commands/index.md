หน้าข้อมูลอ้างอิงคำสั่งมีไว้ช่วยตัดสินใจว่าจะเริ่มใช้งานจากช่องทางใด คุณไม่จำเป็นต้องท่องพารามิเตอร์ทั้งหมดตั้งแต่แรก:

> **ตอนนี้ควรใช้โหมดโต้ตอบ หรือใช้คำสั่งแบบครั้งเดียว?**

หน้านี้รวบรวมช่องทางการเรียกใช้งานระดับ Stable ของ **Codex CLI** ในปัจจุบัน เพื่อให้ค้นหาและเปรียบเทียบได้สะดวก ก่อนเรียกใช้ คุณยังควรรัน `codex --help` และ `--help` ของคำสั่งย่อยแต่ละคำสั่งเสมอ ส่วนระดับความพร้อมและพารามิเตอร์ทั้งหมดให้ยึด [Developer commands](https://learn.chatgpt.com/docs/developer-commands) เป็นหลัก

## ควรใช้เมื่อใด

หน้าข้อมูลอ้างอิงคำสั่งมักใช้ตอบคำถามต่อไปนี้:

- ตอนนี้ควรเข้าโหมดโต้ตอบโดยตรง หรือรันคำสั่งแบบครั้งเดียว
- งานนี้เหมาะกับการทำงานแบบสนทนา หรือการเรียกใช้ผ่านสคริปต์
- รู้ว่าต้องใช้ CLI แต่ไม่แน่ใจว่าควรดูช่องทางการเรียกใช้งานแบบใด

## เลือกช่องทางการเรียกใช้งาน

- ดูผลลัพธ์ สนทนา และแก้ไขไปพร้อมกัน: ใช้ `codex`
- มอบหมายงานครั้งเดียว แล้วรับผลลัพธ์เมื่อทำเสร็จ: ดู `codex exec`

สำหรับผู้ที่เพิ่งเริ่มใช้ CLI เพียงแยกสองกรณีนี้ได้ก็ช่วยเลือกช่องทางการเรียกใช้งานส่วนใหญ่ได้แล้ว

## ภาพรวมคำสั่งระดับ Stable

| ช่องทางการเรียกใช้งาน | วัตถุประสงค์ | รายละเอียด |
|---|---|---|
| `codex` | เซสชัน TUI แบบโต้ตอบ | [โหมดโต้ตอบ](/th/guide/cli/interactive-mode/) |
| `codex exec` / `codex e` | งานแบบครั้งเดียวหรือแบบไปป์ไลน์ที่ไม่โต้ตอบ | [โหมดไม่โต้ตอบ](/th/guide/cli/non-interactive-mode/) |
| `codex doctor` | สร้างรายงานวินิจฉัยการติดตั้ง การกำหนดค่า การยืนยันตัวตน รันไทม์ Git และเทอร์มินัล | [การแก้ปัญหา CLI](/th/guide/cli/troubleshooting/) |
| `codex login` / `codex logout` | จัดการการยืนยันตัวตน | [การลงชื่อเข้าใช้และการยืนยันตัวตน](/th/guide/getting-started/sign-in-and-authentication/) |
| `codex resume` / `codex fork` | ทำต่อหรือแยกแขนงจากเซสชันที่บันทึกไว้ | [การส่งต่องานและกลับมาทำต่อ](/th/guide/agent-work/handoff-and-resume/) |
| `codex mcp` | จัดการเซิร์ฟเวอร์ MCP | [เชื่อมต่อ MCP](/th/skills/mcp/connect-an-mcp-server/) |
| `codex plugin` | ติดตั้ง แสดงรายการ และนำ Plugin ออก | [Plugins](/th/skills/plugins/) |

:::caution[ระดับความพร้อมแตกต่างกัน]
ข้อมูลอ้างอิงอย่างเป็นทางการยังมีคำสั่งระดับ Experimental, Beta และ Deprecated หน้านี้ไม่ได้นำคำสั่งเหล่านั้นมาปะปนกับคู่มืออ้างอิงด่วนพื้นฐาน หากจำเป็นต้องใช้ ให้ตรวจสอบระดับความพร้อมและความเสี่ยงในตารางอย่างเป็นทางการก่อน
:::

## ความเข้าใจผิดที่พบบ่อย

### 1. ไม่จำเป็นต้องจำคำสั่งทั้งหมดในหน้าข้อมูลอ้างอิง

วิธีที่ใช้ได้จริงกว่าคือ รู้ก่อนว่า “ช่องทางการเรียกใช้งานประเภทใดเหมาะกับงานปัจจุบัน” แล้วค่อยตรวจสอบรายละเอียดที่เหลือจาก `--help` เมื่อต้องใช้

### 2. `codex exec` ไม่ใช่เพียงเวอร์ชันขั้นสูงของ `codex`

คำสั่งนี้เหมาะกับการทำงานแบบไม่ต้องเฝ้าดู สคริปต์ และ CI มากกว่า ไม่ใช่ช่องทางโต้ตอบที่ “ทรงพลังกว่า” เท่านั้น

### 3. เห็นพารามิเตอร์ไม่ได้หมายความว่าต้องปรับทันที

พารามิเตอร์จำนวนมากขึ้นอยู่กับเวอร์ชัน สภาพแวดล้อม และนโยบายความปลอดภัยปัจจุบัน ควรเข้าใจวัตถุประสงค์ก่อน แล้วจึงตัดสินใจว่าจำเป็นต้องเปลี่ยนหรือไม่

### 4. หน้าข้อมูลอ้างอิงคำสั่งไม่ใช่บทเรียนการใช้งาน

หน้านี้เป็น:

- แผนที่ช่องทางการเรียกใช้งาน
- ดัชนีพารามิเตอร์
- จุดเชื่อมต่อที่บอกว่า “ควรไปอ่านรายละเอียดหน้าใดก่อน”

## โหมดโต้ตอบ (แนวคิด)

```bash
# เริ่มเซสชันแบบโต้ตอบที่รากของรีโพซิทอรี (ตัวอย่าง)
codex

# การดำเนินการทั่วไปภายในเซสชัน (ให้ยึด TUI เป็นหลัก)
# - ป้อนคำอธิบายงาน
# - คำสั่งแบบสแลช / → ดูหน้า slash-commands
# - อนุมัติคำขอเรียกใช้ shell / เขียนไฟล์
```

คำสั่งแบบสแลช: [คู่มืออ้างอิงด่วนสำหรับคำสั่งแบบสแลช](/th/guide/reference/slash-commands/)

## วิธีเลือกช่องทางการเรียกใช้งาน

เมื่อเพิ่งเริ่มใช้ CLI ให้พิจารณาตามลำดับนี้:

1. รัน `codex --help` ก่อน
2. จากนั้นตัดสินใจว่าจะเข้าโหมดโต้ตอบหรือดู `exec`
3. เมื่อต้องใช้คำสั่งย่อยใดจริง ๆ จึงค่อยดู `--help` ของคำสั่งนั้น

ลำดับนี้ช่วยไม่ให้คุณต้องจมอยู่ในตารางพารามิเตอร์ทั้งหมดตั้งแต่เริ่มต้น

## เริ่มต้นอย่างรวดเร็ว

หากต้องการเริ่มใช้งานทันที ให้ทำดังนี้:

1. รัน `codex --help` ก่อน
2. หากต้องการสนทนาและทำงานไปพร้อมกัน ให้เข้า `codex` โดยตรง
3. หากต้องการใช้กับ CI หรือสคริปต์ จึงค่อยศึกษา `codex exec`

วิธีนี้ง่ายกว่าการเริ่มต้นด้วยรายละเอียดของพารามิเตอร์ทั้งหมด

## exec แบบไม่โต้ตอบ (แนวคิด)

```bash
# ระบุไดเรกทอรีทำงานและพรอมต์สำหรับงานครั้งเดียว (ตัวอย่าง)
codex exec --cd /path/to/repo "คำอธิบายงานของคุณแบบครบถ้วน"

# พารามิเตอร์ที่ใช้บ่อยในปัจจุบัน
# --cd, -C       ไดเรกทอรีทำงาน
# --model        กำหนดโมเดล
# --sandbox      นโยบายแซนด์บ็อกซ์
# --ask-for-approval, -a  นโยบายการอนุมัติ
# ไปป์ stdin     อ่านพรอมต์จากไฟล์หรือคำสั่งต้นทาง
```

ความปลอดภัย: [รูปแบบการอนุมัติโดยมนุษย์](/th/cases/workflows/human-approval-patterns/)

## รหัสออกและระบบอัตโนมัติ

โดยทั่วไป โหมดไม่โต้ตอบจะใช้ **รหัสออก** เพื่อระบุว่าสำเร็จหรือล้มเหลวสำหรับ CI:

- `0`: งานเสร็จสมบูรณ์ตามที่กำหนด
- ไม่ใช่ `0`: ล้มเหลวหรือต้องให้มนุษย์เข้ามาดำเนินการ — ให้ตรวจสอบอาร์ติแฟกต์ของล็อก

หน้าคำสั่ง CLI มีไว้ช่วยแยกแยะช่องทางการเรียกใช้งานและค้นหาวัตถุประสงค์ คุณไม่จำเป็นต้องท่องพารามิเตอร์เพื่อเริ่มใช้งาน

อย่าละเลย stderr ใน CI และควรเก็บล็อกไว้เพื่อใช้กับแนวทาง [วินิจฉัยก่อนแก้ไข](/th/cases/workflows/diagnose-before-fixing/)
