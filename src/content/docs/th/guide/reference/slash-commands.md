เมื่อเห็นคำสั่ง Slash ครั้งแรก หลายคนอาจคิดว่าเป็นศัพท์เฉพาะจำนวนมากที่ต้องท่องจำ ลองมองว่าเป็นชุดทางลัดที่คุณเลือกเรียกใช้ได้โดยตรง จะเข้าใจได้ง่ายกว่า

โดยทั่วไป คำสั่งเหล่านี้ใช้เพื่อเข้าสู่โหมดที่กำหนดไว้หรือขั้นตอนในตัวอย่างรวดเร็ว คำสั่ง Slash (`/command`) เกี่ยวข้องกับการเรียก [Skill](/th/skills/overview/) ด้วย `$name` แต่ไม่ใช่สิ่งเดียวกัน รายการที่ใช้ได้ **เปลี่ยนไปตามผลิตภัณฑ์และสิทธิ์การเข้าถึง** และชุดคำสั่งใน App เดสก์ท็อป, CLI, IDE และ ChatGPT Web ก็แตกต่างกัน ก่อนใช้ ให้ยึดรายการเติมคำอัตโนมัติเมื่อพิมพ์ `/` ใน composer ปัจจุบันและเอกสารทางการเป็นหลัก

## แยกแนวคิด

| ช่องทางเข้า | ผู้เริ่ม | การใช้งานทั่วไป |
|---|---|---|
| คำสั่ง Slash เช่น `/review` | คุณพิมพ์ `/` | ขั้นตอนตายตัวที่มีอยู่ในระบบหรือกำหนดค่าไว้ |
| `$skill-name` | คุณหรือโมเดล | Skill ของโปรเจกต์หรือผู้ใช้ |
| ภาษาธรรมชาติ | คุณ | งานทั่วไป |

## แยกทั้งสามแบบโดยตรง

- `/command`: คุณเลือกทางลัดในแชตด้วยตัวเอง
- `$skill`: คุณหรือโมเดลระบุให้ใช้ Skill ใด Skill หนึ่ง
- ภาษาธรรมชาติ: คุณบอกความต้องการโดยตรง แล้วให้โมเดลตัดสินใจเองว่าจะทำอย่างไร

หากเพียงต้องการเข้าสู่ขั้นตอนที่รู้จักอยู่แล้วให้เร็วขึ้น การลอง `/command` จะตรงกว่ามาก

## คืออะไร

- ไม่ใช่คำสั่งเทอร์มินัล
- ไม่ใช่ศัพท์ลึกลับ
- มองได้ว่าเป็น “ทางเข้าปุ่มลัด” ในหน้าจอแชต

เหมาะกับสถานการณ์เหล่านี้:

- คุณรู้อยู่แล้วว่าต้องการเข้าสู่ขั้นตอนใด
- คุณไม่ต้องการอธิบายเจตนาเดิมซ้ำทุกครั้ง

## ความเข้าใจผิดที่พบบ่อย

### 1. คำสั่ง Slash คือคำสั่งเทอร์มินัล

คำสั่งนี้เป็นทางลัดในหน้าจอแชต ไม่ใช่คำสั่ง `codex ...` ที่ให้รันใน shell

### 2. รายการคำสั่ง Slash ไม่เคยเปลี่ยน

คำสั่งที่ใช้ได้อาจต่างกันตามผลิตภัณฑ์ เวอร์ชัน และสภาพแวดล้อม การดู **รายการเติมคำอัตโนมัติ** ในสภาพแวดล้อมปัจจุบันโดยตรงจึงเชื่อถือได้กว่า

### 3. เมื่อใช้คำสั่ง Slash แล้ว จะไม่อยู่ภายใต้การอนุมัติและ sandbox

หากขั้นตอนเบื้องหลังเขียนไฟล์ รันคำสั่ง หรือเชื่อมต่อเครือข่าย ก็ยังอยู่ภายใต้นโยบายปัจจุบันเช่นเดิม

### 4. ถ้าใช้คำสั่ง Slash ไม่เป็น จะใช้ Codex ได้ไม่ดีหรือไม่

ภาษาธรรมชาติเพียงอย่างเดียวก็ทำงานส่วนใหญ่ได้ คำสั่ง Slash มีไว้ช่วยเพิ่มความเร็วและเข้าถึงขั้นตอนตายตัวเมื่อคุณคุ้นเคยขึ้นแล้วเป็นหลัก

## ทางลัดที่พบบ่อยในปัจจุบัน

### App เดสก์ท็อป / IDE

- `/plan`: สลับเป็นโหมดวางแผนหลายขั้นตอน
- `/review`: Review การเปลี่ยนแปลงที่ยังไม่ commit หรือเปรียบเทียบกับ branch ฐาน
- `/status`: ดู chat ID, ปริมาณการใช้บริบท และ rate limits
- `/mcp`: ดูสถานะการเชื่อมต่อ MCP
- `/init`: สร้างโครงเริ่มต้น `AGENTS.md` สำหรับโปรเจกต์ปัจจุบัน

### การควบคุมเซสชันเฉพาะ CLI

- `/permissions`: ปรับวิธีจัดการสิทธิ์ของเซสชันปัจจุบัน
- `/agent`: ตรวจสอบหรือสลับเธรด Agent
- `/model`: เลือกโมเดลปัจจุบัน
- `/status`: ตรวจสอบการตั้งค่าของเซสชันปัจจุบัน

ChatGPT Web มีเมนูคำสั่งใน composer ของตัวเอง จึงไม่ควรสมมติว่าคำสั่งของ App เดสก์ท็อปหรือ CLI จะมีชื่อเดียวกันและใช้งานได้บน Web

## ข้อควรระวังเมื่อใช้

1. **พิมพ์ `/` เพื่อตรวจดูก่อน** ว่าสภาพแวดล้อมปัจจุบันรองรับอะไร อย่าท่องรายการที่อาจล้าสมัย
2. ขั้นตอนตายตัวของทีมควรจัดทำเป็น **Skill + เอกสาร** ก่อน เพื่อลดกรณีที่ “มีเพียงผู้ใช้เก่าเท่านั้นที่รู้ชื่อคำสั่ง”
3. การเขียนข้อมูลที่เรียกผ่านคำสั่ง Slash ยังอยู่ภายใต้ข้อจำกัดของ sandbox และการอนุมัติ

## วิธีลองใช้งานโดยตรง

ลองทำตามนี้ได้ทันที:

1. พิมพ์ `/`
2. ดูว่าสภาพแวดล้อมปัจจุบันมีอะไรให้ใช้
3. เลือกรายการที่คุณเข้าใจชื่อและวัตถุประสงค์มาลองก่อนหนึ่งรายการ

## ครั้งแรกให้ลองตามลำดับนี้

ในการลองครั้งแรก ทำตามลำดับต่อไปนี้ได้:

1. พิมพ์ `/` ก่อนเพื่อดูว่าสภาพแวดล้อมปัจจุบันมีอะไรให้ใช้
2. เลือกคำสั่งที่เข้าใจวัตถุประสงค์มาลองหนึ่งครั้ง
3. สังเกตว่าคำสั่งนั้นเหมือน “สลับโหมด” หรือ “รันขั้นตอน” มากกว่ากัน
4. หากเป็นขั้นตอนที่ทีมต้องใช้ซ้ำในระยะยาว ค่อยพิจารณาจัดทำเป็น Skill

วิธีนี้ช่วยให้เห็นการแบ่งหน้าที่ได้ชัดขึ้น: คำสั่ง Slash เน้นเป็นทางลัด ส่วน Skill เน้นขั้นตอนที่นำกลับมาใช้ซ้ำในระยะยาว

## ความแตกต่างจากคำสั่ง CLI

| | `/` ในแชต | `codex …` ในเทอร์มินัล |
|---|---|---|
| บริบท | เซสชันปัจจุบันและไฟล์แนบ | ไดเรกทอรีที่ระบุด้วย `--cd` / `-C` |
| เหมาะสำหรับ | การสำรวจแบบโต้ตอบ | สคริปต์, CI |

มองคำสั่ง Slash เป็นทางลัดในแชตได้ การดูว่าสภาพแวดล้อมปัจจุบันมีอะไรให้ใช้จริงย่อมมีประโยชน์กว่าการท่องชื่อคำสั่ง
