ทุกครั้งที่เริ่มรัน Codex จะสร้างลำดับคำสั่งขึ้นมา ประเด็นสำคัญไม่ใช่การคาดเดาตารางจัดลำดับที่รวม “นโยบายองค์กร การตั้งค่า และพรอมต์” ไว้ด้วยกัน แต่คือการทำความเข้าใจลำดับการค้นหาของ `AGENTS.md` ให้ถูกต้องเสียก่อน

## ลำดับการค้นหาอย่างเป็นทางการ

1. **ระดับส่วนกลาง**: ใน Codex home (ค่าเริ่มต้นคือ `~/.codex`) ระบบจะค้นหา `AGENTS.override.md` ก่อน และจะอ่าน `AGENTS.md` ก็ต่อเมื่อไม่พบไฟล์แรก ในระดับนี้จะใช้เฉพาะไฟล์แรกที่ไม่ว่างเปล่าเท่านั้น
2. **ระดับโปรเจกต์**: ไล่จากรากโปรเจกต์ (โดยทั่วไปคือราก Git) ลงมาจนถึงไดเรกทอรีทำงานปัจจุบัน โดยแต่ละไดเรกทอรีจะตรวจ `AGENTS.override.md`, `AGENTS.md` และชื่อไฟล์ fallback ที่กำหนดไว้ตามลำดับ แต่ละระดับจะเลือกไม่เกินหนึ่งไฟล์
3. **การผสาน**: นำเนื้อหามาต่อกันตั้งแต่รากจนถึงไดเรกทอรีปัจจุบัน ไฟล์ที่อยู่ใกล้ไดเรกทอรีปัจจุบันกว่าจะปรากฏภายหลัง จึงแทนที่คำแนะนำก่อนหน้าได้

Codex จะข้ามไฟล์ว่าง และหยุดเพิ่มเนื้อหาเมื่อเนื้อหาที่ผสานมีขนาดถึง `project_doc_max_bytes` โดยขีดจำกัดเริ่มต้นคือ 32 KiB

## ตัวอย่าง Monorepo

```text
repo/
├── AGENTS.md
├── apps/
│   └── web/
│       └── AGENTS.md
└── services/
    └── payments/
        ├── AGENTS.md
        └── AGENTS.override.md
```

เมื่อเริ่มจาก `services/payments` ระบบจะโหลด `AGENTS.md` ที่รากก่อน หากมี `AGENTS.override.md` อยู่ในไดเรกทอรีนี้ ระบบจะไม่อ่าน `AGENTS.md` ที่อยู่ในไดเรกทอรีเดียวกัน

ไฟล์ที่รากควรระบุกฎทั้ง repository เช่น package manager การทดสอบทั่วไป และขอบเขตต้องห้ามด้านความปลอดภัย ส่วนไฟล์ที่ซ้อนอยู่ควรระบุเฉพาะกฎเพิ่มเติมของบริการนั้น อย่าคัดลอกเนื้อหาที่เหมือนกันถึง 80%

## พรอมต์ของงานทำงานร่วมกันอย่างไร

`AGENTS.md` ใช้เก็บข้อตกลงระยะยาวของโปรเจกต์ที่จัดการเวอร์ชันได้ ส่วนพรอมต์ใช้ระบุเป้าหมาย ขอบเขต และเกณฑ์ยอมรับของงานครั้งนี้ ตัวอย่างเช่น:

```text
ปฏิบัติตาม AGENTS.md ที่มีผลใช้บังคับ งานนี้แก้ไขเฉพาะ services/payments/retry.ts และการทดสอบเท่านั้น
ห้ามหมุนเวียนคีย์ ให้รัน make test-payments และรายงานผลตามจริง
```

พรอมต์ไม่สามารถเปลี่ยนขอบเขตด้านระบบ องค์กร sandbox หรือสิทธิ์ ซึ่งไม่สามารถฝ่าฝืนได้ ให้กลายเป็นความสามารถที่ใช้งานได้ เมื่อเกิดข้อขัดแย้ง ให้ขอให้ Codex ระบุแหล่งที่มาและขอบเขตการมีผลของคำสั่งที่เกี่ยวข้อง พร้อมแยกข้อตกลงเริ่มต้นของโปรเจกต์ที่ปรับได้ออกจากข้อจำกัดในการดำเนินงานจริง หากขอบเขตชัดเจน ได้รับอนุญาตแล้ว และไม่มีความขัดแย้งกับคำสั่งระดับสูงกว่า ให้ดำเนินการต่อ หากขาดข้อมูลหรือสิทธิ์จริง ๆ จึงค่อยอธิบายสิ่งที่ขัดขวางอย่างเจาะจง ดูรายละเอียดทั้งหมดได้ที่ [ลำดับความสำคัญของบริบท](/th/guide/context/context-priority/)

## ตรวจสอบเนื้อหาที่โหลดจริง

เริ่มเซสชันใหม่จากไดเรกทอรีเป้าหมาย แล้วถามว่า:

```text
ก่อนเริ่มงาน ให้แสดงลำดับแหล่งที่มาของ AGENTS.md / AGENTS.override.md ที่โหลดในครั้งนี้
พร้อมสรุปข้อจำกัดใหม่ที่แต่ละไฟล์เพิ่มเข้ามาแยกกัน ห้ามแก้ไขไฟล์
```

ระบบจะอ่าน `AGENTS.md` เมื่อเริ่มรัน หลังแก้ไขแล้วควรเริ่มการรันหรือเซสชันใหม่เพื่อตรวจสอบ อย่าถือว่าเซสชันปัจจุบันได้รับการอัปเดตแบบ hot reload ไปแล้ว

## fallback และขีดจำกัดขนาด

หากมี `TEAM_GUIDE.md` อยู่แล้ว สามารถกำหนดค่าได้ดังนี้:

```toml
project_doc_fallback_filenames = ["TEAM_GUIDE.md", ".agents.md"]
project_doc_max_bytes = 65536
```

fallback จะมีผลก็ต่อเมื่อไม่มีไฟล์ที่มีลำดับความสำคัญสูงกว่าในไดเรกทอรีเดียวกัน ก่อนเพิ่มขีดจำกัด ให้ลบเนื้อหาซ้ำและบริบทเบื้องหลังที่ไม่เกี่ยวข้องก่อน เพื่อไม่ให้กฎสำคัญถูกเบียดออกจากบริบท
