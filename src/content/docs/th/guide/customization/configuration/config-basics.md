ไฟล์การตั้งค่าช่วยให้คุณ **กำหนดพฤติกรรม Codex ให้สอดคล้องกัน** ไม่ว่าจะใช้งานในเครื่องหรือในโปรเจกต์ โดยไม่ต้องตั้งค่าโมเดล ระดับการอนุมัติ หรือนโยบาย Sandbox ซ้ำในทุกเซสชัน

## เนื้อหาในหน้านี้

- ควรเก็บการตั้งค่าไว้ที่ใด และการตั้งค่าระดับโปรเจกต์กับระดับผู้ใช้ทำงานซ้อนกันอย่างไร
- รายการที่ปรับบ่อยที่สุด ได้แก่ โมเดล การอนุมัติ Sandbox และไดเรกทอรีทำงานเริ่มต้น
- ขอบเขตระหว่างการตั้งค่ากับ `AGENTS.md`: การตั้งค่าควบคุม “สวิตช์ความสามารถ” ส่วน AGENTS ควบคุม “วิธีเขียนโค้ดในโปรเจกต์”

## การตั้งค่าควบคุมอะไรกันแน่

การตั้งค่าใกล้เคียงกับ **นิสัยการทำงานเริ่มต้น** ของ Codex มากกว่า

ตัวอย่างเช่น:

- โดยปริยายจะใช้โมเดลใด
- โดยปริยายจะกำหนดขอบเขตความปลอดภัยเข้มงวดเพียงใด
- โดยปริยายจะทำงานในไดเรกทอรีใด

การตั้งค่าไม่ได้ควบคุมข้อกำหนดชั่วคราวของงานใดงานหนึ่ง แต่กำหนดว่าโดยทั่วไปควรเริ่มทำงานอย่างไร

## ระดับการตั้งค่า

| ระดับ | ตำแหน่งทั่วไป | เนื้อหา |
|---|---|---|
| ผู้ใช้ | การตั้งค่าภายใต้ `~/.codex/` (ให้ยึดชื่อไฟล์จริงตามเอกสารอย่างเป็นทางการ) | โมเดลเริ่มต้น พฤติกรรมการอนุมัติส่วนบุคคล |
| โปรเจกต์ | ส่วนย่อยการตั้งค่าภายใน repository หรือไฟล์โปรเจกต์ที่เกี่ยวข้องกับ `codex` | นโยบาย Sandbox/เครื่องมือที่ทีมใช้ร่วมกัน |
| จัดการจากส่วนกลาง | องค์กรเป็นผู้กำหนด | ข้อบังคับที่ผู้ใช้แต่ละคนไม่สามารถเขียนทับได้ |

สำหรับ **ข้อมูลที่เปลี่ยนแปลงง่าย** (พาธ ชื่อฟิลด์ และคีย์ TOML) ให้ยึด [เอกสาร OpenAI Codex](https://developers.openai.com/codex) เป็นหลัก หน้านี้อธิบายแนวคิดและวิธีตัดสินใจ

## ความเข้าใจผิดที่พบบ่อย

### การตั้งค่ามากไม่ได้แปลว่าเป็นมืออาชีพกว่า

เมื่อพบไฟล์การตั้งค่าครั้งแรก หลายคนมักอยากกำหนดทุกอย่างที่ตั้งค่าได้

แต่สำหรับผู้เริ่มต้น โดยทั่วไปตรึงเพียงไม่กี่รายการที่ใช้บ่อยก็เพียงพอ เช่น:

- โมเดลเริ่มต้น
- นโยบายการอนุมัติ/Sandbox เริ่มต้น
- ไดเรกทอรีทำงานเริ่มต้น

การทำให้รายการเหล่านี้เสถียรก่อน มักเหมาะกว่าการศึกษาทุกฟิลด์ให้ครบในครั้งเดียว

### การตั้งค่าไม่ใช่กฎของโปรเจกต์

หากข้อกำหนดหนึ่งเป็นสิ่งที่ “ผู้ร่วมงานทุกคนควรปฏิบัติตาม” โดยทั่วไปควรเขียนไว้ใน `AGENTS.md` หรือเอกสารโปรเจกต์ มากกว่าจะเก็บไว้เฉพาะในการตั้งค่าบนเครื่องของคุณ

ตัวอย่างเช่น:

- ต้องรันการตรวจสอบใดก่อน commit
- ห้ามแก้ไขไดเรกทอรีใดบ้าง
- งานประเภทใดห้าม push อัตโนมัติ

ข้อกำหนดเหล่านี้ไม่ควรพึ่งการตั้งค่าส่วนบุคคลเพียงอย่างเดียว

## เจตนาการตั้งค่าที่ปรับบ่อย

### โมเดลและการให้เหตุผล

- การพัฒนาทั่วไป: รักษาสมดุลระหว่างความเร็วกับคุณภาพ
- การปรับโครงสร้างที่ซับซ้อน: ใช้โมเดลที่ให้เหตุผลได้ดีกว่า (หากแพ็กเกจรองรับ)
- สคริปต์/CI: ตรึงโมเดลเพื่อให้ทำซ้ำได้

แนวคิดพื้นฐาน: [โมเดลและการให้เหตุผล](/th/guide/foundations/models-and-reasoning/)

### การอนุมัติและ Sandbox

| เจตนา | แนวทางการตั้งค่า |
|---|---|
| ผู้เริ่มต้น/repository ที่ไม่น่าเชื่อถือ | ใช้การอนุมัติที่เข้มงวดขึ้น และจำกัดขอบเขตการเข้าถึงเครือข่ายกับการเขียนดิสก์ |
| โปรเจกต์ส่วนตัวที่เชื่อถือได้ | ลดการขัดจังหวะได้ภายใต้เงื่อนไขที่ปลอดภัย |
| repository ขององค์กร | ปฏิบัติตามนโยบายที่จัดการจากส่วนกลาง และอย่าผ่อนคลายข้อจำกัดเอง |

แนวคิดพื้นฐาน: [สิทธิ์และการอนุมัติ](/th/guide/foundations/permissions-and-approvals/) และ [Sandbox และเครือข่าย](/th/guide/foundations/sandbox-and-network/)

### ความสอดคล้องระหว่าง CLI กับ App

บัญชีเดียวกันควรใช้ **เกณฑ์ความปลอดภัยพื้นฐานเดียวกัน** ทั้งใน CLI และ App เดสก์ท็อป เพื่อหลีกเลี่ยงพฤติกรรมสองมาตรฐานแบบ “CLI ให้สิทธิ์เต็ม แต่ App เข้มงวด”

## วิธีเริ่มต้นขั้นต่ำที่ใช้งานได้

1. อ่านหัวข้อ “Configuration” ในเอกสารอย่างเป็นทางการ และยืนยันพาธไฟล์ของเวอร์ชันปัจจุบัน
2. เปลี่ยนเพียงหนึ่งรายการ เช่น โหมด Sandbox เริ่มต้น แล้วสังเกตผลหนึ่งสัปดาห์ก่อนปรับอีกครั้ง
3. เขียนรายการที่ทีมใช้ร่วมกันไว้ในเอกสาร repository ส่วนความชอบส่วนบุคคลให้เก็บไว้ในเครื่อง
4. เขียนใน `AGENTS.md` ว่า “แนะนำให้ใช้ Codex กับโปรเจกต์นี้อย่างไร” แทนการคัดลอกการตั้งค่าทั้งชุด

## จะตัดสินใจได้อย่างไรว่าควรเก็บไว้ที่ใด

หากไม่แน่ใจว่ารายการหนึ่งควรอยู่ในการตั้งค่า `AGENTS.md` หรือพรอมต์ของงาน ให้พิจารณาคำถามต่อไปนี้:

1. นี่คือนิสัยเริ่มต้นที่ใช้กับงานส่วนใหญ่หรือไม่
2. นี่คือความชอบที่มีเพียงฉันเท่านั้นที่ให้ความสำคัญหรือไม่
3. นี่คือกฎที่ทั้งโปรเจกต์ควรปฏิบัติร่วมกันหรือไม่

โดยทั่วไป:

- นิสัยเริ่มต้น ให้ใส่ในการตั้งค่า
- ความชอบส่วนบุคคล ให้เก็บไว้ในระดับส่วนบุคคล
- ฉันทามติของทีม ให้เก็บไว้ใน repository

## ความเกี่ยวข้องกับหัวข้อ CLI

- การใช้งานแบบโต้ตอบ: [โหมดโต้ตอบของ CLI](/th/guide/cli/interactive-mode/)
- การใช้งานแบบไม่โต้ตอบและสคริปต์: [โหมดไม่โต้ตอบ](/th/guide/cli/non-interactive-mode/)
- รายละเอียดการตั้งค่าเพิ่มเติม: [การตั้งค่า CLI](/th/guide/cli/configuration/) · [เอกสารอ้างอิงรายการตั้งค่า](/th/guide/reference/configuration-reference/)

## ข้อผิดพลาดที่พบบ่อย

- ปิดการอนุมัติทั้งหมดเพื่อความสะดวก แต่เปิดโปรเจกต์ในไดเรกทอรีข้อมูล Production
- เขียนคีย์ API ลงในไฟล์การตั้งค่าแล้ว commit เข้า Git
- คีย์การตั้งค่าในเอกสารไม่ตรงกับเวอร์ชันที่ติดตั้ง (ไม่ได้ตรวจสอบซ้ำหลังอัปเกรด CLI)

## ขอบเขตความปลอดภัย

ไฟล์การตั้งค่าอาจมี **allowlist ของพาธ นโยบายเครือข่าย และรายการเซิร์ฟเวอร์ MCP** ก่อนเปลี่ยนแปลง ให้ลองคิดว่า “พรอมต์ที่เป็นอันตรายจะใช้ประโยชน์จากการตั้งค่านี้ได้หรือไม่” ในสภาพแวดล้อมองค์กร ผู้ดูแลระบบควรเป็นผู้กำหนดค่า และผู้ใช้แต่ละคนไม่ควรหลีกเลี่ยงนโยบายที่จัดการจากส่วนกลาง

การตั้งค่าเหมาะสำหรับค่าเริ่มต้นที่คุณเลือกซ้ำแทบทุกครั้ง ไม่จำเป็นต้องใส่กฎทั้งหมดลงในไฟล์การตั้งค่า
