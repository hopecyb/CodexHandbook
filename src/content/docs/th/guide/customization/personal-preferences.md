**ความชอบส่วนบุคคล** คือการตั้งค่าบนเครื่องของคุณที่มีผลข้ามโปรเจกต์ เช่น โมเดลเริ่มต้น ธีม รูปแบบการอนุมัติ และพาธคลัง Skill ส่วนตัว ความชอบส่วนบุคคลต่างจาก `AGENTS.md` ในรีโพซิทอรีตรงที่ **ไม่ควร** สมมติว่าเพื่อนร่วมทีมตั้งค่าเหมือนคุณ

## เนื้อหา

- อะไรควรอยู่ในชั้นส่วนบุคคล และอะไรควรอยู่ในชั้นโปรเจกต์
- วิธีใช้ร่วมกับ [Profile](/th/guide/customization/configuration/profiles/) เพื่อสลับตามสถานการณ์
- วิธีป้องกันไม่ให้การตั้งค่าส่วนบุคคลที่ผ่อนปรนรั่วไหลเข้ารีโพซิทอรีของทีม

ภาพรวมลำดับความสำคัญ: [การปรับแต่งเฉพาะบุคคล](/th/guide/customization/) · [ขอบเขตและลำดับความสำคัญ](/th/guide/customization/agents-md/scope-and-precedence/)

## ทำไมต้องแยกชั้นนี้

หลายคนเริ่มต้นด้วยการนำเรื่องเหล่านี้มาปะปนกัน:

- โดยส่วนตัวฉันชอบใช้งานอย่างไร
- รีโพซิทอรีนี้กำหนดให้ทำอย่างไร
- บริษัทหรือทีมบังคับให้ทำอย่างไร

หากไม่แยกสามประเภทนี้ออกจากกัน ปัญหาต่อไปนี้จะเกิดขึ้นได้ง่าย:

- เครื่องของคุณใช้งานได้คล่อง แต่เพื่อนร่วมทีมกลับทำซ้ำไม่ได้เลย
- คุณคิดว่ากฎมีผลแล้ว ทั้งที่จริงเป็นเพียงค่าเริ่มต้นบนเครื่องคุณที่ช่วยรองรับอยู่
- คุณนำการตั้งค่าที่ผ่อนปรนไปใช้ในโปรเจกต์ที่จริงจังกว่าโดยไม่ตั้งใจ

## เนื้อหาที่เหมาะกับความชอบส่วนบุคคล

| เนื้อหา | ตัวอย่าง |
|---|---|
| โมเดลเริ่มต้นและระดับการให้เหตุผล | ประสิทธิภาพเครื่องและแพ็กเกจส่วนบุคคล |
| ธีม UI ฟอนต์ และการแจ้งเตือน | [การตั้งค่า](/th/guide/desktop-app/settings/) ของ Desktop App |
| MCP ส่วนบุคคล (เครื่องมือส่วนตัว) | อ่านฐานข้อมูลในเครื่องอย่างเดียว (ให้สิทธิ์ด้วยความระมัดระวัง) |
| พาธคลัง Skill ส่วนบุคคล | ไม่ขัดแย้งกับ Plugin ของทีม |
| alias ของเทอร์มินัลและไดเรกทอรีเริ่มต้นของ `codex` | ดู [การกำหนดค่า CLI](/th/guide/cli/configuration/) |

## เนื้อหาของทีมที่ไม่ควรอยู่เฉพาะชั้นส่วนบุคคล

- รูปแบบโค้ด คำสั่งทดสอบ และโครงสร้างไดเรกทอรี → **`AGENTS.md` ของโปรเจกต์**
- นโยบาย Sandbox ที่บังคับใช้ → **การกำหนดค่าโปรเจกต์หรือการจัดการระดับองค์กร**
- ข้อกำหนดการปฏิบัติตามกฎของรีโพซิทอรีลูกค้า → **เอกสาร + CI** จะพึ่งหน่วยความจำส่วนบุคคลไม่ได้

## แนวปฏิบัติที่แนะนำ

1. **แยก Profile สำหรับงานและส่วนตัว**: ใช้ Profile ที่เข้มงวดกับโปรเจกต์ลูกค้า ส่วนโปรเจกต์ฝึกหัดอาจผ่อนปรนได้
2. **เมื่อเข้ารีโพซิทอรีใหม่ ให้อ่านกฎโปรเจกต์ก่อน** แล้วค่อยตัดสินใจว่าจำเป็นต้องแทนที่ค่าเริ่มต้นส่วนบุคคลชั่วคราวหรือไม่
3. **ทำความสะอาด** MCP และ Skill ส่วนบุคคลเป็นระยะ โดยนำแหล่งข้อมูลบุคคลที่สามซึ่งเลิกใช้งานแล้วออก
4. เมื่อเปลี่ยนเครื่องหรือติดตั้งใหม่ ให้ส่งออกรายการการกำหนดค่า (ไม่รวมค่าคีย์)

## ความเข้าใจผิดที่พบบ่อย

### 1. วิธีที่ฉันชอบใช้เป็นประจำไม่จำเป็นต้องเหมาะกับการตั้งเป็นค่าเริ่มต้นส่วนกลาง

หากพฤติกรรมเริ่มต้นของคุณค่อนข้างผ่อนปรน พฤติกรรมนั้นอาจไม่เหมาะเมื่อเข้าสู่โปรเจกต์ลูกค้าหรือโปรเจกต์ทีม

### 2. ความชอบส่วนบุคคลกับกฎโปรเจกต์แทบไม่ต่างกันใช่ไหม

ต่างกันมาก  
ความชอบส่วนบุคคลหมายถึง “ฉันเองคุ้นเคยกับการทำแบบนี้” ส่วนกฎโปรเจกต์หมายถึง “ทุกคนในรีโพซิทอรีนี้ควรพยายามทำแบบนี้”

### 3. แค่ตรวจบนเครื่องแล้วไม่พบปัญหา ยังไม่พอจะตัดสินว่าการตั้งค่านี้เหมาะสม

เกณฑ์ที่เหมาะกว่าคือ:

- ไม่ทำให้กฎในรีโพซิทอรีปะปนกับการตั้งค่าส่วนตัว
- ไม่พึ่งค่าเริ่มต้นที่มีเพียงคุณเท่านั้นที่รู้
- ไม่ก่อผลกระทบโดยไม่ตั้งใจเมื่อสลับไปโปรเจกต์ที่เข้มงวด

## ตัดสินอย่างไรว่าควรอยู่ในชั้นส่วนบุคคล

เมื่อไม่แน่ใจว่าการตั้งค่าหนึ่งควรอยู่ในชั้นส่วนบุคคลหรือไม่ ลองถามตัวเองว่า:

1. นี่เป็นพฤติกรรมที่มีเพียงฉันสนใจหรือไม่
2. มันจะกระทบการทำซ้ำผลลัพธ์ของผู้อื่นหรือไม่
3. มันเหมาะจะนำไปใช้กับทุกโปรเจกต์หรือไม่

หากคำตอบข้อ 2 บ่งชี้ว่าจะกระทบผู้อื่น หรือข้อ 3 บ่งชี้ว่าไม่เหมาะกับทุกโปรเจกต์ ก็อย่ารีบตั้งเป็นค่าเริ่มต้นส่วนกลาง

ความชอบส่วนบุคคลมีไว้เพื่อให้คุณใช้งานได้คล่องมือขึ้น ไม่ได้มีไว้รองรับกฎของทีม และไม่ควรนำการตั้งค่าที่ผ่อนปรนทั้งหมดไปใช้กับทุกโปรเจกต์

## ความสัมพันธ์กับฟีเจอร์หน่วยความจำ

หากผลิตภัณฑ์มี “หน่วยความจำ” หรือความชอบแบบถาวร ดู [หน่วยความจำและบริบทถาวร](/th/guide/customization/memories-and-persistent-context/) หน่วยความจำเหมาะสำหรับพฤติกรรมที่คงที่ แต่ **ข้อจำกัดเฉพาะโปรเจกต์ยังต้องยึดไฟล์ในรีโพซิทอรีเป็นหลัก**

## ข้อผิดพลาดที่พบบ่อย

- เขียน API key ของบริษัทแบบตายตัวไว้ในการกำหนดค่าส่วนบุคคล
- อนุมัติ shell โดยอัตโนมัติแบบส่วนกลาง แล้วนำไปใช้กับโค้ดลูกค้า
- เพื่อนร่วมทีม clone รีโพซิทอรีแล้วบ่นว่า “กฎไม่ทำงาน” ทั้งที่ไม่เคย commit กฎนั้นเลย

## รายการตรวจรับ

- [ ] ตั้งค่า Profile ที่เข้มงวดให้โปรเจกต์ลูกค้าอย่างน้อยหนึ่งโปรเจกต์
- [ ] ไม่มีคีย์ส่วนบุคคลอยู่ในรีโพซิทอรี
