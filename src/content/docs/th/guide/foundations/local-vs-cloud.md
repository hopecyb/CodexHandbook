คำว่า “ในเครื่อง” และ “Cloud” อาจฟังเป็นศัพท์เทคนิค กล่าวง่าย ๆ คือ งานในเครื่องทำบนคอมพิวเตอร์ของคุณ ส่วนงาน Cloud ทำบนเครื่องระยะไกล

หากเพียงต้องการเริ่มใช้ Codex โดยทั่วไปเลือก **ในเครื่อง** ก่อนจะง่ายกว่า

| | งานในเครื่อง | งาน Cloud |
|---|---|---|
| ตำแหน่งทำงาน | เครื่อง / local environment ของคุณ | สภาพแวดล้อม Cloud |
| เหมาะกับ | วนแก้เร็ว ไฟล์ในเครื่อง และการ debug ที่ต้องใช้ secret ในเครื่อง | เชื่อม repository ระยะไกล งานยาว และสภาพแวดล้อมมาตรฐาน |
| ข้อควรระวัง | สิทธิ์บนเครื่องและความเสี่ยงจากการแก้ผิด | การตั้งค่าสภาพแวดล้อม การใส่ secret และนโยบายเครือข่าย |

## ความรู้สึกในการใช้งาน

โดยคร่าว:

- **งานในเครื่อง**: คล้ายคุณนั่งหน้าเครื่องและให้ Codex ช่วยแก้โปรเจกต์ปัจจุบัน
- **งาน Cloud**: คล้ายมอบงานให้เครื่องทำงานระยะไกลทำต่อที่นั่น

ความต่างไม่ได้มีเพียง “ตำแหน่ง” แต่รวมถึง:

- เข้าถึงไฟล์ใดได้
- ใช้ซอฟต์แวร์และสภาพแวดล้อมบนเครื่องของคุณได้โดยตรงหรือไม่
- งานทำได้นานเพียงใด
- ทีมต้องใช้สภาพแวดล้อมเดียวกันหรือไม่

## ทำไมผู้เริ่มต้นจำนวนมากเริ่มในเครื่อง

เพราะเข้าใจและตรวจได้ง่ายกว่า

- คุณรู้ว่าไฟล์อยู่บนคอมพิวเตอร์
- เปิดโปรเจกต์ ดูผล และแก้ด้วยมือได้ง่ายกว่า
- เมื่อผิดพลาด เส้นทางย้อนกลับชัดกว่า

สำหรับผู้ใช้ครั้งแรก การทำวงจรงานให้ครบสำคัญกว่าการเริ่มจาก Cloud

## ความเข้าใจผิดที่พบบ่อย

### 1. Cloud ไม่ได้ล้ำกว่าหรือเหมาะกับงานจริงกว่าเสมอ

หากงานคือแก้โปรเจกต์ในเครื่อง ดูไฟล์บนเครื่อง และลองหลายรอบอย่างรวดเร็ว งานในเครื่องตรงกว่า

### 2. งานในเครื่อง “ไม่เป็นมืออาชีพ” หรือไม่

งานพัฒนาจริงจำนวนมากทำในเครื่อง การเลือก Cloud ขึ้นกับประเภทงาน ไม่ควรตัดสินจากความรู้สึกว่าดูล้ำกว่า

### 3. ควรเลือกอย่างไร

ใช้หลักนี้ในการเลือก:

- **แก้โปรเจกต์ที่มีอยู่บนคอมพิวเตอร์**: เลือกในเครื่อง
- **งานยาว ต้องปล่อยให้รัน หรือต้องเชื่อมสภาพแวดล้อม repository ระยะไกล**: ค่อยพิจารณา Cloud

## หากไม่แน่ใจควรเลือกอย่างไร

ใช้กฎนี้: หากทำในเครื่องได้ อย่าเพิ่งรีบขึ้น Cloud

เปลี่ยนเป็น Cloud เมื่อมี requirement จริงเหล่านี้:

- งานใช้เวลานานมาก
- ต้องใช้สภาพแวดล้อมมาตรฐานเดียวกัน
- ต้องเชื่อม repository หรือทรัพยากรระยะไกล
- ไม่ต้องการใช้ทรัพยากรบนเครื่อง

ผู้เริ่มต้นจำนวนมากเริ่มจาก **ในเครื่อง + Desktop App** ดูรายละเอียด Cloud ที่ [ภาพรวม Web และ Cloud](/th/guide/web-and-cloud/) และการสลับใน App ที่ [งานในเครื่องและ Cloud](/th/guide/desktop-app/local-and-cloud-tasks/)

งานในเครื่องเหมาะกับการเข้าใจกระบวนการและแก้สิ่งเล็กก่อน ส่วน Cloud เหมาะกับงานที่ยาวกว่า มีมาตรฐานมากกว่า และร่วมงานระยะไกลมากกว่า
