Codex ไม่ควรทำการทำงานความเสี่ยงสูงโดยไม่ได้รับความยินยอม **การอนุมัติ** คือประตูกั้นในการร่วมงานระหว่างมนุษย์กับระบบ

หาก Codex อ่านไฟล์ใดก็ได้ เชื่อมเครือข่ายได้ตามต้องการ และรันคำสั่งได้ทุกอย่าง ความเข้าใจงานผิดเพียงครั้งเดียวอาจมีต้นทุนสูง

![ภาพประกอบ: ประตูสี่บานที่มีสิทธิ์ต่างกัน ได้แก่ อ่านไฟล์ เขียนไฟล์ รันคำสั่ง และเชื่อมเครือข่าย โดยคนถือพวงกุญแจและตัดสินใจว่าจะมอบดอกใดให้ผู้ช่วย](/illustrations/permissions-approvals.webp)

## สิ่งที่ต้องใส่ใจ

- อนุญาตให้อ่านหรือเขียนพาธนอกโปรเจกต์ปัจจุบันหรือไม่
- อนุญาตเครือข่ายหรือไม่
- อนุญาตให้รัน shell command ใด
- ทีมกำหนดนโยบายบังคับผ่าน managed configuration หรือไม่

## การอนุมัติควบคุมอะไร

มองการอนุมัติเป็นกล่องยืนยันก่อนขั้นตอนอันตราย

ตัวอย่างที่ควรหยุดถามคุณ:

- ต้องเขียนไฟล์
- ต้องรันคำสั่งที่อาจเปลี่ยนระบบ
- ต้องเข้าถึงพาธนอกโปรเจกต์
- ต้องอ่านหรือส่งข้อมูลผ่านเครือข่าย

การเห็น popup หรือคำขอยืนยันไม่ได้แปลว่า Codex ผิดพลาด หลายครั้งเป็นการทำงานตามขอบเขตความปลอดภัย

## ความเข้าใจผิดที่พบบ่อย

### 1. ทำไมบางครั้งระบบทำทันที แต่บางครั้งถาม

เพราะการทำงานแต่ละอย่างมีความเสี่ยงต่างกัน

- อ่านไฟล์ทั่วไปหนึ่งไฟล์มีความเสี่ยงต่ำกว่า
- แก้หลายไฟล์ เชื่อมเครือข่าย หรือรันคำสั่งมีความเสี่ยงสูงกว่า

### 2. ควรกดอนุญาตตลอดหรือไม่

อย่างน้อยให้ตรวจสามข้อ:

1. ระบบต้องการทำอะไร
2. จะกระทบที่ใด
3. เป็นสิ่งที่คุณตั้งใจให้ทำหรือไม่

### 3. หากปฏิเสธ งานทั้งหมดจะใช้ไม่ได้หรือไม่

โดยทั่วไปไม่ คุณปฏิเสธแล้วขอให้ใช้วิธีที่ปลอดภัยกว่าต่อได้

## หลักการใช้งานแบบง่าย

- หากไม่เข้าใจ อย่าเพิ่งอนุมัติ
- ระวังเป็นพิเศษเมื่อเกินขอบเขตโปรเจกต์ปัจจุบัน
- ดูอีกครั้งเมื่อขอเครือข่าย รันคำสั่ง หรือแก้ไฟล์จำนวนมาก
- หากไม่แน่ใจ ให้ขอคำอธิบายก่อนว่า “ทำไมต้องใช้สิทธิ์นี้”
