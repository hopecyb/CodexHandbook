แต่ละผลิตภัณฑ์อาจใช้คำต่างกันเล็กน้อย คู่มือนี้ใช้ความหมายดังนี้:

- **โปรเจกต์ / workspace**: โฟลเดอร์หรือราก repository ที่ Codex ผูกอยู่
- **Thread / session**: บทสนทนาต่อเนื่องหนึ่งชุด ซึ่งสะสมบริบท
- **งาน**: การทำงานครั้งหนึ่งที่มีเป้าหมายชัดเจน และอาจเรียกเครื่องมือหลายขั้น

หลายคนปะปนคำเหล่านี้ จนเกิดคำถามอย่าง:

- ทำไมระบบยังจำสิ่งที่ฉันพูดก่อนหน้า
- ทำไมเปลี่ยนคำถามแล้ว แต่ระบบยังเดินตามทิศทางเดิม
- ทำไมอยู่ใน “โปรเจกต์เดียวกัน” แต่ยังแนะนำให้เปิด thread ใหม่

โปรเจกต์กำหนดว่าทำงานที่ไหน thread กำหนดว่าจะต่อจากบทสนทนาใด และงานกำหนดว่าครั้งนี้ต้องทำอะไร เมื่อแยกสามระดับนี้ได้ พฤติกรรมการใช้งานจะชัดขึ้นมาก

![ภาพประกอบแบบตัดขวาง: กล่องโปรเจกต์ขนาดใหญ่มีโฟลเดอร์งานหลายชุด และแต่ละงานมี thread สนทนาหลายเส้น](/illustrations/threads-tasks-projects.webp)

## แยกความสัมพันธ์สามระดับก่อน

- **โปรเจกต์ / workspace**: คุณพาระบบเข้า repository หรือโฟลเดอร์ใด
- **Thread / session**: แชตต่อเนื่องปัจจุบันระหว่างคุณกับระบบ
- **งาน**: เป้าหมายเฉพาะหนึ่งอย่างภายในแชตนั้น

หนึ่งโปรเจกต์มีหลาย thread ได้  
หนึ่ง thread อาจเคยทำมากกว่าหนึ่งงาน  
ปัญหามักเกิดตรงนี้: งานเปลี่ยน แต่ thread ยังแบกบริบทเก่า

## คำแนะนำในการใช้งาน

- เมื่อเปลี่ยนหัวข้อ ให้ **เปิด thread ใหม่** เพื่อไม่ให้บริบทเก่ารบกวน
- งานยาวควรระบุช่วงและ checkpoint ดู [Prompt สำหรับงานยาว](/th/prompts/long-running-tasks/)
- เมื่อต้องทำต่อข้าม session ให้ทำ handoff summary ดู [การส่งต่องานและกู้คืน](/th/guide/agent-work/handoff-and-resume/)

## ความเข้าใจผิดที่พบบ่อย

### 1. อยู่ใน repository เดียวกัน ควรใช้ thread เดียวตลอดหรือไม่

ไม่จำเป็น  
repository ไม่เปลี่ยน ไม่ได้แปลว่างานไม่เปลี่ยน  
เมื่อเปลี่ยนหัวข้อ บริบทเก่าใน thread อาจกลายเป็น noise

### 2. เปิด thread ใหม่เท่ากับเสียบริบททั้งหมดหรือไม่

ไม่ได้เป็นเรื่องเสียหายเสมอ  
หลายครั้งคุณต้องการ “ทิ้งบริบทที่ไม่เกี่ยวข้อง” และเก็บเฉพาะข้อมูลที่งานนี้ต้องใช้

### 3. งานกับ thread มีความหมายเดียวกันหรือไม่

เป็นคนละแนวคิด  
Thread คล้าย container ส่วนงานคือการทำงานเฉพาะหนึ่งครั้งภายใน container

โปรเจกต์กำหนดสถานที่ทำงาน thread กำหนดประวัติที่จำ และงานกำหนดสิ่งที่ต้องทำครั้งนี้
