บางงานเดินหน้าได้รวดเร็ว บางงานยิ่งคุยยิ่งออกนอกทาง ความต่างไม่ได้อยู่ที่โมเดลฉลาดขึ้นหรือแย่ลงทันที แต่อยู่ที่คุณแบ่งงานชัดหรือไม่

แบบสั้นที่สุดคือ เป้าหมายบอกว่า “สุดท้ายต้องการอะไร” บริบทบอกว่า “ทำจากข้อมูลใด” การทำงานบอกว่า “ทำอะไรได้บ้าง” และการตรวจรับบอกว่า “ระดับใดจึงถือว่าเสร็จ”

การทำงานกับ Codex ที่ค่อนข้างเสถียรมักมีสี่ส่วน:

1. **เป้าหมาย**: ต้องส่งมอบอะไร
2. **บริบท**: พื้นหลัง ไฟล์ และข้อจำกัดที่เกี่ยวข้อง
3. **การทำงาน**: ขั้นตอนที่อนุญาตให้ Codex ทำ เช่น อ่าน แก้ และรัน
4. **การตรวจรับ**: เสร็จเมื่อไร และตรวจอย่างไร

บทเรียนการเขียน prompt ขยายสี่ส่วนนี้เป็นกรอบที่เสถียร ดู [โครงสร้างของงานที่ดี](/th/prompts/task-anatomy/)

## แต่ละส่วนควบคุมอะไร

มองว่าเป็นการมอบงานให้ผู้ช่วยลงมือทำ:

- **เป้าหมาย**: ต้องส่งมอบอะไร
- **บริบท**: ต้องรู้ข้อเท็จจริงใดก่อนตัดสิน
- **การทำงาน**: อ่านไฟล์ แก้ไฟล์ รันคำสั่ง หรือค้นอินเทอร์เน็ตได้หรือไม่
- **การตรวจรับ**: เมื่อเสร็จ คุณใช้เกณฑ์ใดบอกว่า “ใช้ได้”

หากขาดส่วนใดก็เกิดปัญหาได้:

- ไม่มีเป้าหมาย: ระบบทำงานมาก แต่ไม่จำเป็นต้องตรงจุด
- ไม่มีบริบท: ระบบต้องเดา
- ไม่มีขอบเขตการทำงาน: ระบบอาจทำเกินหรือไม่กล้าทำ
- ไม่มีการตรวจรับ: คุณกับระบบเข้าใจคำว่า “เสร็จ” ต่างกัน

## ความเข้าใจผิดที่พบบ่อย

### 1. บอกเป้าหมายชัดอย่างเดียวยังไม่พอ

ยังไม่พอ

เช่น “ช่วยแก้หน้าแรก” เป็นเพียงทิศทาง ยังไม่พอให้ทำอย่างเสถียร ระบบต้องรู้ด้วยว่า:

- แก้ไฟล์ใด
- ต้องเก็บอะไรไว้
- ห้ามแตะอะไร
- ต้องการผลลัพธ์สุดท้ายแบบใด

### 2. ยิ่งให้บริบทมากยิ่งดี

บริบทน้อยเกินไปทำให้เดา บริบทมากเกินไปทำให้ประเด็นสำคัญถูกกลบ สิ่งสำคัญคือให้ **บริบทที่เกี่ยวข้อง** ไม่ใช่เทข้อมูลทั้งหมด

### 3. ไม่ต้องระบุการทำงาน ให้ระบบตัดสินเองได้หรือไม่

บางครั้งได้ แต่ไม่เสถียรสำหรับผู้เริ่มต้น

หากระบุชัดว่า:

- แก้ไฟล์ใดได้
- ห้ามติดตั้ง dependency
- ห้ามแก้ config
- เสนอแนวทางก่อนลงมือ

ผลลัพธ์จะเสถียรกว่ามาก

## หากไม่รู้จะเขียนอย่างไร ให้เรียงตามนี้

หากไม่รู้จะจัดโครงสร้างงานอย่างไร ให้เรียงตามสี่ประโยคนี้:

1. สุดท้ายฉันต้องการให้ทำอะไร
2. ต้องอาศัยพื้นหลังและข้อจำกัดใด
3. ทำอะไรได้และทำอะไรไม่ได้
4. ฉันจะใช้เกณฑ์ใดตรวจว่าเสร็จแล้ว

ชัดเจนกว่าประโยคเดียวว่า “ช่วยจัดการปัญหานี้”

## ตัวอย่างสั้น

> เป้าหมาย: จัดลำดับหัวข้อใน `notes.md` ให้ชัดเจน  
> บริบท: แก้เฉพาะไฟล์นี้ และคงลำดับย่อหน้าเดิม  
> การทำงาน: แก้ไฟล์ได้ แต่ห้ามติดตั้ง dependency  
> การตรวจรับ: เมื่อเปิดไฟล์ ลำดับหัวข้อต่อเนื่องจาก H1 ถึง H3 โดยไม่ข้ามระดับ

งานที่เสถียรควรระบุอย่างน้อยเป้าหมาย บริบท ขอบเขตการทำงาน และวิธีตรวจรับให้ชัด
