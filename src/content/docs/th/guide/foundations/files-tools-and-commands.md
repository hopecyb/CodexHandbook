ความต่างหลักจาก chatbot ทั่วไปคือ Codex ลงมือผ่าน **เครื่องมือ**

ไฟล์คือที่ที่ระบบแก้เนื้อหา คำสั่งคือวิธีทำการกระทำ และเครื่องมือคือจุดเข้าที่ระบบใช้ลงมือ

Codex ใช้ **เครื่องมือ** ทำงานกับโลกจริง:

- อ่านและเขียนไฟล์โปรเจกต์
- รันคำสั่งในเทอร์มินัล เมื่อสิทธิ์และนโยบาย sandbox อนุญาต
- ค้นเว็บ เปิดเบราว์เซอร์ และอื่น ๆ ตามความสามารถผลิตภัณฑ์และนโยบาย

## แยกสามคำนี้ก่อน

| คำ | ความหมาย |
|---|---|
| ไฟล์ | เนื้อหาจริงในโปรเจกต์ เช่น โค้ด เอกสาร และ config |
| คำสั่ง | การทำงานหนึ่งขั้นในเทอร์มินัล เช่น build, test หรือค้นหา |
| เครื่องมือ | ความสามารถที่ Codex ใช้อ่านและแก้ไฟล์ รันคำสั่ง หรือค้นเว็บ |

อีกมุมหนึ่ง:

- **ไฟล์** คล้ายวัสดุ
- **คำสั่ง** คล้ายการกระทำ
- **เครื่องมือ** คล้ายอุปกรณ์ที่ใช้หยิบวัสดุและทำการกระทำ

## กระบวนการทำงานทั่วไป

หลังคุณมอบงาน Codex มักทำสิ่งเหล่านี้:

1. อ่านไฟล์ที่เกี่ยวข้องเพื่อเข้าใจโครงสร้างโปรเจกต์
2. ค้นข้อความ เปิดไดเรกทอรี หรือดู config เมื่อจำเป็น
3. รันคำสั่ง เช่น test หรือ build เมื่อต้องตรวจผล
4. หลังแก้ไฟล์ ส่งการเปลี่ยนแปลงให้คุณตรวจ

ดังนั้นเมื่อเห็นระบบ “ขออ่านไฟล์” หรือ “ขอรันคำสั่ง” ส่วนใหญ่เป็นขั้นปกติที่งานต้องใช้

## ความเข้าใจผิดที่พบบ่อย

### 1. รันคำสั่งได้ แปลว่าทำอะไรก็ได้หรือไม่

ไม่จำเป็น

ยังขึ้นอยู่กับ:

- จุดเข้าผลิตภัณฑ์ปัจจุบันให้เครื่องมือใด
- sandbox อนุญาตหรือไม่
- ขั้นตอนนี้ต้องให้คุณอนุมัติหรือไม่
- นโยบายทีมมีข้อจำกัดเพิ่มหรือไม่

### 2. ควรรันคำสั่งให้น้อย แล้วแก้ไฟล์โดยตรงเพื่อให้เร็วขึ้นหรือไม่

ไม่จำเป็น

บางครั้งคำสั่งตรวจหนึ่งคำสั่งช่วยพบปัญหาเร็วกว่า เช่น รัน test หลังแก้โค้ดย่อมเสถียรกว่าพบความเสียหายภายหลัง

### 3. หากไม่เข้าใจคำสั่งควรทำอย่างไร

ถามได้โดยตรง:

```text
คำสั่งนี้ทำอะไร จะเปลี่ยนเนื้อหาใด และหากไม่รันจะเกิดอะไร
```

## วิธีตัดสินแบบง่าย

เมื่อ Codex ต้องการอ่านไฟล์ แก้ไฟล์ หรือรันคำสั่ง ให้ถามสามข้อ:

1. ขั้นตอนนี้เกี่ยวข้องกับเป้าหมายหรือไม่
2. ขอบเขตผลกระทบอยู่ในไดเรกทอรีหรือไฟล์ที่คาดหรือไม่
3. หากผิดพลาด ย้อนกลับได้ง่ายหรือไม่

หากตอบข้อใดไม่ได้ ให้ขอคำอธิบายก่อน

## หลักการใช้งาน

1. **ขอบเขตขั้นต่ำที่จำเป็น**: ระบุไดเรกทอรีและไฟล์ อย่าบอกว่า “แก้ทั้ง repository ได้ตามต้องการ”
2. **คำสั่งอันตรายต้องอนุมัติ**: เช่น ลบ push หรือแก้ system config
3. **เลือกเครื่องมืออย่างมีวิธี**: ดู [การเลือกเครื่องมือ](/th/guide/tools/tool-selection/)

แต่ละจุดเข้าผลิตภัณฑ์มีแผงเครื่องมือและวิธียืนยันต่างกัน ดูรายละเอียดในคู่มือผลิตภัณฑ์แต่ละรายการ

Codex ไม่ได้เพียง “พูด” แต่ลงมือจริงผ่านไฟล์ คำสั่ง และเครื่องมือ คุณจึงต้องเฝ้าดูทั้งขอบเขตและความเสี่ยง
