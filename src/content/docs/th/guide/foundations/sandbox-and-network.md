“Sandbox” กับ “เครือข่าย” เป็นคนละเรื่อง: sandbox จำกัดว่าสัมผัสอะไรได้ ส่วนเครือข่ายจำกัดว่าเชื่อมไปที่ใดได้

**Sandbox** จำกัด file system และความสามารถระบบบางส่วนที่ Agent เข้าถึง เพื่อลดพื้นที่ความผิดพลาด ส่วน **การเข้าถึงเครือข่าย** เป็นความเสี่ยงอีกชั้น เพราะอาจทำให้ข้อมูลอ่อนไหวใน prompt รั่ว หรือดึงข้อมูลที่ไม่น่าเชื่อถือมา

![ภาพประกอบ: Agent ทำงานใน sandbox กระจก ยกบัตรคำขอรออนุมัติ ขณะที่คนด้านนอกกดปุ่มยืนยัน และสายเครือข่ายถูกถอดพร้อมล็อก](/illustrations/sandbox-and-approval.webp)

## ทำไมข้อจำกัดสองอย่างนี้สำคัญ

หากไม่มีขอบเขตเหล่านี้ เมื่อ Codex เข้าใจงานผิด ผลกระทบอาจใหญ่ขึ้น เช่น:

- แก้ไดเรกทอรีที่คุณไม่ต้องการ
- อ่านไฟล์อ่อนไหวที่ไม่ควรอ่าน
- ส่งเนื้อหางานไปเว็บไซต์ภายนอก
- ดึงข้อมูลหรือสคริปต์จากแหล่งไม่ทราบที่มา

ข้อจำกัดจึงเป็น guardrail เริ่มต้น ไม่ได้มีไว้เพิ่มอุปสรรคโดยเจตนา

## คำแนะนำเริ่มต้น

1. ปิดเครือข่ายที่ไม่จำเป็นขณะฝึก หรืออนุญาตเฉพาะการเข้าถึงที่ระบุชัด
2. อย่าใส่ production secret ในโปรเจกต์ฝึก
3. เมื่อเห็นคำขอ “ออกเครือข่าย / เขียนพาธอ่อนไหว” ให้หยุดและอ่านให้เข้าใจก่อนอนุมัติ

## ความเข้าใจผิดที่พบบ่อย

### 1. Sandbox แปลว่าความสามารถไม่พอหรือไม่

Sandbox มีไว้ควบคุมความเสี่ยง ไม่ได้ตั้งใจลดความสามารถ

### 2. ยิ่งเข้าถึงเครือข่ายมากยิ่งดีหรือไม่

ยิ่งเปิดเครือข่ายมาก:

- แหล่งข้อมูลยิ่งซับซ้อน
- อาจพบเนื้อหาที่ไม่น่าเชื่อถือ
- เนื้อหาบางส่วนของงานอาจถูกส่งไปบริการภายนอก

ดังนั้นระหว่างฝึก หากไม่ต้องใช้เครือข่ายก็ควรปิดไว้ก่อน

### 3. ควรตัดสินคำขอสิทธิ์อย่างไร

ดูสามข้อ:

1. งานนี้ต้องออกเครือข่ายจริงหรือไม่
2. พาธหรือเว็บไซต์ที่เข้าถึงตรงกับที่คาดหรือไม่
3. หากปฏิเสธขั้นนี้ ยังใช้วิธีที่ปลอดภัยกว่าต่อได้หรือไม่

## มุมมองที่เข้าใจง่าย

มองเป็นประตูสองบาน:

- **ประตู sandbox**: กำหนดว่าเข้าถึงไฟล์และพื้นที่ระบบใดได้
- **ประตูเครือข่าย**: กำหนดว่ามองหรือเชื่อมออกไปภายนอกได้หรือไม่

ทั้งสองบานไม่ใช่เพียงการตั้งค่าทางเทคนิค แต่เป็นวิธีควบคุมความเสี่ยงของคุณ
