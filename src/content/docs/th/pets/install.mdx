เว็บไซต์นี้ยังไม่ได้ทดสอบความเข้ากันได้ระหว่างไคลเอนต์แต่ละรุ่นกับแพ็ก Pet โดยเฉพาะ โปรดบันทึกเวอร์ชันและแหล่งที่มาก่อน แล้วใช้[บันทึกความเข้ากันได้และการกู้คืน](/th/guide/reference/resource-compatibility/)เพื่อตรวจสอบผลลัพธ์จริง แผนภาพใช้เพื่ออธิบายโครงสร้างเท่านั้น ไม่ได้หมายความว่าข้อกำหนดด้านรูปแบบนี้ใช้ได้กับทุกเวอร์ชัน


แก่นของการติดตั้ง Codex Pet คือการนำแพ็กทรัพยากรที่ไคลเอนต์รู้จักไปไว้ในไดเรกทอรีที่กำหนด เมื่อไคลเอนต์เริ่มทำงานหรือรีเฟรชการตั้งค่า ไคลเอนต์จะอ่านไดเรกทอรีนี้ ค้นหาเมทาดาทา แล้วโหลดทรัพยากรแอนิเมชันที่เกี่ยวข้อง

![ภาพประกอบ: ใช้แว่นขยายตรวจสอบแพ็กทรัพยากรก่อน จากนั้นใส่ลงในไดเรกทอรีแบบลิ้นชัก เมื่อรีเฟรชแล้ว Pet จะปรากฏบนหน้าจอแล็ปท็อป](/illustrations/pets-install.webp)

โดยทั่วไป Pet หนึ่งตัวจะเป็นโฟลเดอร์ภายในเครื่องที่มีไฟล์อย่างน้อยสองไฟล์:

```text
~/.codex/pets/<pet-id>/
  pet.json
  spritesheet.webp
```

`pet.json` ระบุชื่อ Pet คำอธิบาย และพาธของ spritesheet ส่วน `spritesheet.webp` ใช้เก็บเฟรมแอนิเมชัน โดยทั่วไปไฟล์ทั้งสองจะอยู่ในไดเรกทอรี Pet เดียวกัน และ `spritesheetPath` ใน `pet.json` ต้องชี้ไปยังไฟล์ที่มีอยู่จริง

## กลไกเบื้องหลังขั้นตอนการติดตั้ง

1. รับแพ็ก Pet: ตรวจสอบว่าภายในมีอย่างน้อย `pet.json` และ spritesheet
2. วางไว้ในไดเรกทอรี Pets: ตำแหน่งที่พบบ่อยคือ `~/.codex/pets/<pet-id>/`
3. ให้ไคลเอนต์อ่านข้อมูลใหม่: รีสตาร์ต Codex หรือรีเฟรชในการตั้งค่า Pets
4. มองหาตัวเลือกสำหรับเลือก Pet ในไคลเอนต์ที่ใช้อยู่ ชื่อและตำแหน่งของเมนูอาจแตกต่างกันตามเวอร์ชัน หากไม่พบตัวเลือกนี้ ให้ตรวจสอบก่อนว่าเวอร์ชันนั้นรองรับหรือไม่

บน Windows โดยทั่วไปจะใช้ `.codex\pets\<pet-id>\` ภายใต้ไดเรกทอรีผู้ใช้ หากคุณกำหนดค่า `CODEX_HOME` ไว้ ให้ยึดโฟลเดอร์ Pets ที่ไคลเอนต์ปัจจุบันแสดงเป็นหลัก

## สาเหตุที่การติดตั้งล้มเหลวบ่อยครั้ง

หาก Pet ไม่ปรากฏหลังติดตั้ง ให้ตรวจสอบรายการต่อไปนี้ก่อน:

- ชื่อโฟลเดอร์ตรงกับ `id` ใน `pet.json` หรือไม่
- `spritesheetPath` เป็นพาธสัมพัทธ์หรือไม่ เช่น `spritesheet.webp`
- spritesheet อยู่ในไดเรกทอรีเดียวกันจริงหรือไม่
- ได้รีสตาร์ต Codex หรือรีเฟรชในการตั้งค่า Pets แล้วหรือไม่
- Windows, WSL หรือ `CODEX_HOME` ที่กำหนดเองชี้ไปยังไดเรกทอรีคนละแห่งหรือไม่

หากตรวจสอบพาธและไฟล์แล้วไม่พบปัญหา ยังต้องตรวจสอบเวอร์ชันของรูปแบบ การรองรับของไคลเอนต์ และข้อผิดพลาดที่เกิดขึ้นจริงระหว่างการโหลด

## สาระสำคัญของการอัปเดตและถอนการติดตั้ง

สำรองไดเรกทอรีเดิมก่อนอัปเดต หลังจากยืนยันว่าแพ็กใหม่ใช้งานได้ จึงค่อยเขียนทับ `pet.json` และ spritesheet

ก่อนปิดใช้งาน ให้สลับกลับไปใช้ Pet ที่มาพร้อมระบบหรือปิดการแสดงผลก่อน จากนั้นย้ายแพ็กที่กำหนดเองไปยังตำแหน่งสำรองซึ่งอยู่นอกไดเรกทอรีที่ Pets ใช้สแกน หลังจากรีเฟรชหรือรีสตาร์ตแล้ว ให้ยืนยันว่าแพ็กนั้นไม่ปรากฏอีก หากต้องการกู้คืน ให้นำแพ็กเดิมกลับไปไว้ที่เดิมและตรวจสอบอีกครั้ง ลบแพ็กสำรองได้ก็ต่อเมื่อยืนยันว่าไม่จำเป็นต้องใช้อีก ขั้นตอนนี้ยังไม่ได้ผ่านการทดสอบจริงกับเวอร์ชันไคลเอนต์ที่เว็บไซต์นี้บันทึกไว้

## ข้อควรระวังด้านความปลอดภัย

อย่ารันคำสั่ง remote shell จากแหล่งที่ไม่น่าเชื่อถือโดยตรง สคริปต์ติดตั้งอาจเขียนไฟล์ภายในเครื่อง หรือแม้กระทั่งเรียกใช้คำสั่งเพิ่มเติม วิธีที่ปลอดภัยกว่าคือดาวน์โหลดแพ็กก่อน ตรวจสอบ `pet.json` ยืนยันแหล่งที่มาและใบอนุญาตของทรัพยากร แล้วจึงคัดลอกไปยังไดเรกทอรี Pets ด้วยตนเอง

หากมองการติดตั้งว่าเป็น “การคัดลอกแพ็กทรัพยากรภายในเครื่อง” ขอบเขตความเสี่ยงจะชัดเจนขึ้น: ตรวจสอบไฟล์ทรัพยากรได้ ต้องตรวจทานพฤติกรรมของสคริปต์ และต้องเก็บข้อมูลแหล่งที่มากับสิทธิ์การใช้งานไว้
