ความเข้าใจผิดที่พบบ่อยในงานอัตโนมัติคือคิดเพียงว่า “รันอัตโนมัติได้หรือไม่” โดยยังไม่ได้คิดว่า:

- หากล้มเหลวจะทำอย่างไร
- ใครจะเห็นผลลัพธ์
- เมื่อเกิดข้อผิดพลาด จะหยุดอย่างปลอดภัยได้หรือไม่

เทมเพลตทำงานอัตโนมัติมีหัวใจสำคัญคือ งานต้องยังควบคุมได้แม้เกิดปัญหา

## เทมเพลต

```text
เป้าหมาย: ทำ【งานซ้ำ】ให้เป็น【สคริปต์/Skill/งานตามกำหนดเวลา】อัตโนมัติ
ทริกเกอร์: 【ด้วยตนเอง / ตามเวลา / CI】
อินพุต: 【แหล่งข้อมูล ไฟล์ตั้งค่า】
ข้อจำกัด:
- เมื่อล้มเหลว ให้มี exit code และตำแหน่ง log ที่ชัดเจน
- ห้าม hard-code secret ให้ใช้ environment variable
- มีโหมด dry-run
เกณฑ์การยอมรับ:
- ให้ผลลัพธ์ที่คาดหวังกับ【อินพุตตัวอย่าง】
- เอกสารอธิบายวิธีรันและแก้ปัญหา
```

## เมื่อใดควรใช้เทมเพลตนี้

- งานซ้ำที่มีกฎชัดเจน
- workflow ที่ต้องทำเป็นสคริปต์หรือกำหนดเวลา
- ต้องการเพิ่มราวกั้น เช่น dry-run, log และ exit code ก่อน

## ความเข้าใจผิดที่พบบ่อย

### 1. งานอัตโนมัติคือการตัดการตัดสินใจของมนุษย์ออก

งานอัตโนมัติที่นำไปใช้ได้ง่ายกว่าจำนวนมากเป็นเพียงการตรวจอัตโนมัติ สรุปอัตโนมัติ หรือเปิด draft อัตโนมัติ

### 2. งานรันผ่านหนึ่งครั้งก็ทำเป็นอัตโนมัติได้

หากต้องการให้ทำงานอัตโนมัติได้ในระยะยาว ยังต้องเพิ่ม:

- log
- exit code
- dry-run
- คำอธิบายการแก้ปัญหา

คุณค่าของเทมเพลตทำงานอัตโนมัติคือช่วยให้ทำงานได้อย่างปลอดภัยในระยะยาว
