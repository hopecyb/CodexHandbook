เมื่อผลลัพธ์ไม่ถูกต้อง สาเหตุที่พบบ่อยคือ:

- ไม่ได้เขียนเป้าหมายเป็นผลลัพธ์ที่ตรวจสอบได้
- ระบุข้อจำกัดไม่ชัด
- บริบทไม่ครบหรือล้าสมัย
- งานใหญ่เกินไป แต่ไม่ได้ขอแผนก่อน

หัวใจของการแก้ปัญหาพรอมป์คือหาว่าข้อมูลหายไปในชั้นใด

## เริ่มจากหาตำแหน่งปัญหา

เมื่อผลลัพธ์เบี่ยงเบน ไม่จำเป็นต้องเริ่มใหม่ทั้งหมดทันที การหาก่อนว่าปัญหาอยู่ในชั้นใดจะช่วยประหยัดงาน:

1. เป้าหมายไม่ชัดหรือไม่
2. ขอบเขตหลุดการควบคุมหรือไม่
3. บริบทไม่พอหรือไม่
4. งานใหญ่เกินไปหรือไม่
5. หรือเลือกแนวทางใช้เครื่องมือผิดตั้งแต่ต้น

## เมื่อผลลัพธ์ไม่ถูกต้อง ให้ถามตามลำดับ

1. เป้าหมายตรวจสอบได้หรือไม่
2. ระบุข้อจำกัดชัดหรือไม่ Agent เห็นข้อจำกัดนั้นหรือไม่
3. บริบทล้าสมัยหรือขัดแย้งกันหรือไม่ (การบีบอัด/thread เก่า)
4. ควรขอแผนก่อนหรือไม่
5. เลือกเครื่องมือผิดหรือไม่ (เช่น เชื่อมต่ออินเทอร์เน็ตทั้งที่ไม่ควร)

## แต่ละข้อกำลังตรวจอะไร

### 1. เป้าหมายตรวจสอบได้หรือไม่

หากเป้าหมายคลุมเครือ เช่น “ปรับให้ดีขึ้น” ผลลัพธ์ก็เบี่ยงเบนได้ง่าย

### 2. ระบุข้อจำกัดชัดหรือไม่

ปัญหา “ทำเกินไป” จำนวนมากไม่ได้เกิดจาก Agent ทำงานไม่เป็น แต่เกิดจากคุณไม่ได้บอกว่า “ทำได้ถึงตรงไหนเท่านั้น”

### 3. บริบทล้าสมัยหรือขัดแย้งกันหรือไม่

โดยเฉพาะใน thread ยาว มักเกิดเหตุการณ์ต่อไปนี้:

- ช่วงต้นระบุ A
- ช่วงหลังเพิ่ม B
- สิ่งที่ Agent ได้รับในตอนนี้คือสถานะที่ผสมกัน

### 4. ควรขอแผนก่อนหรือไม่

เมื่องานใหญ่ การลงมือทันทีมักเบี่ยงเบนง่ายกว่าการวางแผนก่อน

### 5. เลือกเครื่องมือผิดหรือไม่

ตัวอย่างเช่น คุณต้องการให้มุ่งที่โค้ดในเครื่อง แต่ Agent กลับค้นเว็บ หรือคุณต้องการงานวิจัยที่มีแหล่งอ้างอิง แต่ Agent ตอบจากความจำเพียงอย่างเดียว

## ความเข้าใจผิดที่พบบ่อย

### 1. ผลลัพธ์ผิดแสดงว่าพรอมป์ทั้งหมดใช้ไม่ได้

หลายครั้งเพียงเติมส่วนเล็ก ๆ ก็พอ:

- ระบุเกณฑ์การยอมรับให้ชัด
- ลดขอบเขต
- ให้เสนอแผนก่อน

### 2. การแก้ปัญหาคือเขียนพรอมป์ให้ยาวขึ้นเรื่อย ๆ

บางครั้งสิ่งที่ต้องทำคือตัดสิ่งรบกวนออก ให้เหลือเพียงขอบเขตที่สำคัญที่สุด

### 3. thread ยิ่งยาวยิ่งดี เพราะมีบริบทมากกว่า

เมื่อ thread ยาวเกินไป ข้อจำกัดเก่า ข้อมูลล้าสมัย และเศษข้อมูลหลังการบีบอัดอาจเริ่มรบกวน

## ลำดับแก้ไขที่เพียงพอ

หากต้องการดึงงานกลับสู่ทิศทางที่ถูกต้อง ให้ทำดังนี้:

1. เขียนเป้าหมายใหม่ให้ตรวจสอบได้
2. เติมว่า “แก้เฉพาะที่ใด และห้ามแก้ที่ใด”
3. หากงานใหญ่ ให้ขอแผนก่อน
4. หากยังสับสน ให้ลดเหลือการทำซ้ำปัญหาในไฟล์เดียวหรือปัญหาเดียว
5. หากยังไม่ดีขึ้น ให้เปิด thread ใหม่และอธิบายขอบเขตสำคัญอีกครั้ง

แก่นของการแก้ปัญหาพรอมป์คือหาว่าข้อมูลสำคัญชั้นใดไม่ได้รับการสื่อสารอย่างถูกต้อง ไม่ใช่ทำให้ข้อความซับซ้อนขึ้นเรื่อย ๆ

หากยังล้มเหลว ให้ลดเหลือการทำซ้ำในไฟล์เดียว หรือเปิด thread ใหม่แล้วระบุข้อจำกัดอีกครั้ง
