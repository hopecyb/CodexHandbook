`Automations` 主要讲的是重复任务怎么自动跑，不是讨论“让 Codex 更聪明”这件事。

这一组更关心的是：

- 什么任务值得自动跑
- 自动跑到哪一步就该停下来等人
- 失败、告警、回滚该怎么设计

## 判断重点

刚接触自动化时，不必一开始就把所有重复活都交给它。

可以按下面的顺序判断：

1. 先判断这件事是不是**重复、规则清楚、结果好验收**
2. 再判断它能不能只读、只提建议、只开草稿 PR
3. 再考虑完全无人值守

## 常见误区

### 1. 只要重复，就一定该自动化

如果任务虽然重复，但判断标准还很依赖人，太早自动化反而更容易出问题。

### 2. 自动化就应该省掉人工确认

很多自动化先做到这些就已经有价值：

- 自动检查
- 自动汇总
- 自动开 issue / 开草稿 PR

不要直接把结果推上主分支。

自动化更适合“重复、规则清楚、结果好检查”的任务。遇到依赖判断的事情，把人工复核留在流程里通常会更稳。
