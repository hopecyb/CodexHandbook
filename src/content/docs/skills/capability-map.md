扩展机制不少，也确实容易混淆。这页只讲它们之间的关系，不展开安装步骤。

## 对比表

| | 谁触发 | 持久性 | 连外部系统 | 团队分发 |
|---|---|---|---|---|
| AGENTS.md | 自动加载 | 高（Git） | 易 |
| 提示词 | 你 | 低 | 难 |
| 斜杠命令 | 你 | 中 | 视产品 |
| Skill | 你或模型匹配 | 高 | 易（目录/Git） |
| MCP | 模型调用工具 | 配置级 | 需治理 |
| Plugin | 安装后综合生效 | 高 | 官方/团队渠道 |
| Hooks | 系统事件 | 配置级 | 企业常见 |
| Automations | 时间/事件 | 配置级 | 需审批流 |

## 常见对应关系

| 需求 | 建议选择 |
|---|---|
| 统一代码风格和测试命令 | AGENTS.md |
| 把「审查 PR」流程标准化 | Skill |
| 读 Jira/Linear 工单 | MCP |
| 给全团队装一套集成 | Plugin |
| 每次提交前扫描密钥 | Hooks |
| 每周一自动生成周报草稿 | Automations（+ 人工发布） |

## 从一次任务到团队能力包

可以按下面这条线判断要不要继续沉淀：

| 阶段 | 形态 | 适合什么情况 |
|---|---|---|
| 一次性提示词 | 当前对话里的任务说明 | 只做一次，或者还在摸索问题 |
| 模板 | 固定“目标、上下文、约束、验收”骨架 | 同类任务会重复，但步骤还在调整 |
| Skill | `SKILL.md` 加模板、参考资料或脚本 | 流程稳定，成功标准清楚 |
| 子 Agent | 独立上下文里的专项角色 | 审查、测试、调试、资料检索等边界清楚的子任务 |
| MCP | 可调用的外部系统工具 | 需要读工单、查仓库、访问内部系统 |
| Hook | 事件触发的检查或拦截 | 密钥扫描、格式检查、危险命令提醒 |
| Plugin | 一组能力的团队安装包 | Skill、MCP、Hook、模板和说明要一起分发 |
| Automation | 定时或事件驱动任务 | 周报、监控、定期审查等无人值守流程 |

不要从 Plugin 开始设计。先把一次任务跑顺，再观察哪些步骤真的重复、哪些检查必须自动化、哪些外部权限值得接入。

详细分支逻辑见 [如何选择扩展方式](/skills/choosing-an-extension-method/)。

## 与产品入口无关

这些机制**不绑定**单一界面：CLI、桌面 App、IDE 对 Skill/MCP 的支持程度可能不同，以 [功能对照](/guide/reference/feature-comparison/) 与官方说明为准。
