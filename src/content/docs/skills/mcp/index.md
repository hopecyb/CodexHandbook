`MCP` 是一套标准接法：Codex 通过 MCP 连接外部工具和数据源。

如果 Skill 偏向“做事步骤”，那 MCP 处理的是“把外部工具接进来”。

## 本组内容

- 什么情况下才真的需要 MCP
- 怎样把外部系统接进来又不把权限开太大
- 连不上、调不通时先查哪几类问题

## 推荐顺序

1. [MCP 概述](/skills/mcp/mcp-overview/)：先分清 MCP 与 Skill、Plugin 的分工
2. [连接 MCP 服务器](/skills/mcp/connect-an-mcp-server/)：按配置思路接第一个服务器
3. [调试 MCP](/skills/mcp/debugging-mcp/)：连不上、工具不出现、权限不对时怎么排查

## 常见误解

### 1. 只要接了 MCP，Codex 就“无所不能”

它能做什么，完全取决于你接的那个 MCP 服务器暴露了哪些工具、这些工具本身给了多大权限。

### 2. MCP 只是技术接入问题

一旦它连到真实系统，马上就同时变成：

- 权限问题
- 数据暴露问题
- 审计问题

所以这里不只是“怎么接”，也包括“怎么避免接乱”。

只有当任务需要碰到仓库外的真实系统时，MCP 才值得上场。
