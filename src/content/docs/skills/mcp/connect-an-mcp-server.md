## 开始前

- [ ] 已理解 [MCP 概述](/skills/mcp/mcp-overview/) 中的安全边界
- [ ] 有只读或沙箱环境的测试账号
- [ ] 确认当前 Codex 客户端版本支持 MCP（以官方文档为准）

## 推荐流程

### 1. 选择服务器类型

| 类型 | 说明 | 风险 |
|---|---|---|
| 本地 stdio 服务器 | 本机启动进程 | 中：进程权限=你的用户权限 |
| 远程 HTTP/SSE | 托管服务 | 中高：需 TLS、令牌轮换 |

第一次接入时，建议从**官方示例或只读本地服务器**开始。

### 2. 添加配置

配置位置因 CLI/App 而异，常见为用户或项目级 `mcp` 配置块。结构示意（**字段名以官方文档为准**）：

```json
{
  "mcpServers": {
    "example-readonly": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"],
      "env": {
        "API_TOKEN": "从环境变量读取，不要写死在仓库"
      }
    }
  }
}
```

原则：

- 密钥用环境变量或密钥管理器注入
- 配置变更走 Git 审查（secrets 除外）

### 3. 重启或重载客户端

修改 MCP 配置后通常需重启 Codex 会话，使服务器列表刷新。

### 4. 验证工具可见

在任务中明确请求：

```text
列出当前可用的 MCP 工具（只需名称与一句话说明）。
然后用只读方式调用一个测试工具，展示结果。
不要执行写操作。
```

### 5. 小步试用

选一个真实但低风险任务，例如：「用 MCP 查编号 #123 的工单标题，不要改状态。」

## 鉴权模式

| 模式 | 适用 |
|---|---|
| API Key / PAT | 个人开发，定期轮换 |
| OAuth | 用户级授权，适合 SaaS |
| 无鉴权本地 | 仅本机 mock，勿暴露到网络 |

失败时检查：令牌过期、环境变量未传入、公司代理拦截。

## 调试清单

| 现象 | 可能原因 |
|---|---|
| 工具列表为空 | 配置路径错误、进程启动失败 |
| 调用超时 | 网络、VPN、服务器宕机 |
| 权限被拒 | 令牌 scope 不足 |
| 模型从不调用工具 | 任务描述未要求；或工具 description 不清晰 |

## 与审批的配合

首次调用陌生工具时，客户端可能弹出确认——这是预期行为。不要在团队规范中鼓励「永久允许所有 MCP 写操作」。
