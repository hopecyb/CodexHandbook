在 IDE 里，Codex 不仅读你的 prompt，还会自动获得**编辑器状态**——这是 IDE 相对 CLI 的核心优势。理解上下文从哪来，能避免「我明明打开了文件，它却没看见」的挫败感。

## 这篇解决什么问题

- IDE 自动附带哪些上下文
- 与 @ 文件、选区、AGENTS.md 如何叠加
- 如何减少噪音、提高命中率

## 上下文来源（概念分层）

| 来源 | 谁控制 | 典型内容 |
|---|---|---|
| 工作区根目录 | 你打开的文件夹 | 项目结构、`AGENTS.md`、配置文件 |
| 当前打开文件 | 编辑器标签页 | 正在编辑的源码 |
| 选区 | 你高亮的代码 | 函数、报错片段 |
| 显式 @ | 你在对话里 @ 的路径 | 跨目录文件、文档 |
| 项目规则 | 仓库内 `AGENTS.md` 等 | 编码规范、测试命令 |

优先级与冲突处理见 [上下文优先级](/05-core-capabilities/context/context-priority/)。

## 推荐工作流

1. **用工作区根打开仓库**，不要只打开子文件夹（monorepo 例外见团队文档）
2. 改局部逻辑时，**先选中相关代码**再描述任务 → [选区与打开文件](/04-product-guides/ide/selected-code-and-open-files/)
3. 跨模块任务用 `@` 点名关键文件，而不是假设「它自己会搜到」
4. 长会话定期 [压缩上下文](/05-core-capabilities/context/compaction/) 或开新线程

## 与 CLI 的差异

| | IDE 扩展 | CLI |
|---|---|---|
| 文件感知 | 强（打开即上下文） | 需 `--cwd` 与工具读盘 |
| 选区 | 原生支持 | 需粘贴或指定路径 |
| 适合 | 行级修改、解释代码 | 脚本、CI、无 GUI 环境 |

## 敏感信息

不要把含密钥的 `.env` 长期开在编辑器前台；见 [敏感上下文](/05-core-capabilities/context/sensitive-context/)。

日志、客户数据粘贴前脱敏；IDE 不会自动替你判断合规。

## 常见错误

- 在单文件模式（无工作区）下期望读取 `AGENTS.md`
- 打开十几个无关大文件，挤占上下文窗口
- 只口头说「这个函数」但未选中、未 @ 文件

## 验收清单

- [ ] 工作区根目录正确
- [ ] 任务相关的 1–3 个文件已打开或 @
- [ ] `AGENTS.md` 中的测试命令与 IDE 终端一致
