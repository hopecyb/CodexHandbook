チームの自動化では、勢いで対象を広げすぎがちです。ルールが明確な反復作業を自動化し、それ以外は引き続き人が判断すると考えるのが適切です。

## 本グループの事例

- [定期リンクチェック](/ja/cases/use-cases/team-automation/scheduled-link-check/)
- [Issue トリアージ提案](/ja/cases/use-cases/team-automation/issue-triage-suggestions/)

## 本グループの強調点

- 完全自動と提案のみの境界
- 失敗・異常時の通知と停止
- 「ドラフト PR の自動作成」が「メインブランチの自動変更」より通常は堅実な理由
