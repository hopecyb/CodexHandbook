## 1. 目標とコンテキスト

**目標：** 3〜5 競合の比較表（機能、価格シグナル、適合性）を作り、各結論に出典を付ける。

**成功基準：**

- Markdown 表 +「要確認」ラベル
- 価格やバージョン番号を捏造しない
- 外向けドキュメントに内部秘密を含めない

## 2. 準備

- 比較軸を事前定義（プロンプトまたは `@brief.md`）
- [ウェブ検索](/guide/tools/web-search/) を有効化（製品がサポートする場合）

## 3. ワークフロー

[出典付き調査](/cases/workflows/research-with-sources/) に従う：

```text
ベンダー A/B/C の「チーム協業」機能を比較：
各次元 1〜2 文 + 出典 URL；
ブログより公式ドキュメントを優先；
価格は検証不能なら「要確認」；
Markdown 表を出力。他のリポジトリファイルは変更しない。
```

**検証：** 人が URL を 3 件開く。[検証ポリシー](/guide/start-here/handbook-version-policy/) に照らし日付を確認。

## 4. 失敗と回復

- 矛盾する出典：両方提示。一つの物語に無理にまとめない
- コンテキスト過長：「まず A vs B、その後 C を追加」に分割

## 5. 定着（キャプチャ）

- 比較表テンプレートをチームテンプレートディレクトリまたはナレッジベースに保存
- 任意 Skill：`source-backed-research`
