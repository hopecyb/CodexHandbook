本事例は **コンテンツエンジニアリング** タスク：複数 Markdown、サイドバー設定、ビルド検証。スタックは本ハンドブックに合わせていますが、パターンは任意の静的サイトに適用できます。

## メタデータ

| 項目 | 値 |
|---|---|
| 領域 | コンテンツ制作 / ドキュメントエンジニアリング |
| 入口 | CLI または IDE |
| リスク | 中（リンクとナビゲーションが多い） |
| 所要 | 1〜3 時間（規模による） |

テンプレート参照：[事例テンプレート](/ja/cases/use-cases/case-study-template/)

## 背景

新章追加後、次が必要：

1. `astro.config` のサイドバー slug 更新
2. ページ内相対リンク修正
3. `npm run build` がエラーゼロ

人は slug を見落としがち——Agent の**チェックリスト実行 + ビルド検証**に向く。

## 準備

- [ ] クリーンな git ブランチ
- [ ] ローカル `npm run build` が動作
- [ ] 新ページパスとサイドバー配置先のリスト

## タスクプロンプト（例）

```text
目標：12-reference 配下に environment-variables.md を追加し、サイドバーとインデックスリンクに接続する。
制約：src/content/docs と astro.config.mjs のみ変更。依存はアップグレードしない。
受け入れ：npm run build 成功。死リンクなし。
手順：先に設定、次に md、最後に 12-reference/index.md を更新。
```

## 実行メモ

- **設定がコンテンツより先**：slug 欠落のビルドエラーを避ける
- 3〜5 ファイル単位でコミットしレビューしやすく
- [探索—計画—実行—検証](/ja/cases/workflows/explore-plan-execute-verify/) を使用

## チェック

- [ ] 各サイドバー slug に対応ファイルがある
- [ ] 内部リンクが相対パス規約に従う
- [ ] ビルドログに Starlight 警告なし（チームがゼロ警告を要求する場合）

## 失敗回復

| 問題 | 対応 |
|---|---|
| サイドバー slug エラー | slug 修正または astro ドキュメントに従い md 追加 |
| 死リンク | `grep` で対象パス。リンク修正またはページ追加 |
| ビルド OOM | 分割変更。ローカルで Node メモリ増 |

## 振り返り

- 3 回目の同種「新章 + サイドバー」は Skill 化を検討
- ROADMAP 項目をチェックしドキュメントと計画を整合
