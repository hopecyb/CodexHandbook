**出典付き調査**とは、主要な結論が公式ドキュメント、論文、リポジトリファイルなど特定の出典に追跡できること——根拠のない主張だけにしないことです。技術選定、競合比較、文献レビュー、ポリシー解釈に向きます。

## 扱う内容

- [ウェブ検索](/guide/tools/web-search/) と読み取り専用リポジトリ作業の使い分け
- 引用形式と不確実性ラベルの要求方法
- [出典を検証する](/guide/quality/validate-sources/) との組み合わせ

## 最小限のアプローチ

```text
「このリポジトリ文脈での Rust vs Go」を調査：
1. 先に評価軸を列挙（性能、エコシステム、チーム習熟度）
2. 各結論に出典 URL または @リポジトリ内パスを付ける
3. 検証不能は「要確認」とマーク
4. 推奨と未解決の質問で締める
コードは変更しない。
```

## 推奨ワークフロー

```text
質問と除外項を定義
    → 出典収集（検索 / ドキュメント読み / MCP）
    → 比較表 + 長所短所
    → 信頼度と矛盾する出典をラベル
    → 人の判断または仕様フェーズへ
```

長い調査はラウンド分割——[長時間タスク管理](/cases/workflows/long-running-task-management/)。

## よくあるミス

- URL 不要——出力を再確認できない
- 古いブログと公式を区別せず混在
- 調査結論を実装指示として仕様を飛ばす
- 機密データを未承認外部ツールにアップロード

## 安全境界

- 未公開の社内資料は制御されていない MCP 経由で出さない
- 変わりやすい事実（価格、バージョン、地域提供）は [検証日](/guide/start-here/handbook-version-policy/) が必要

## 受け入れチェックリスト

- [ ] 主要結論にクリック可能または追跡可能な出典が少なくとも1つ
- [ ] 矛盾情報を並列提示
- [ ] 「不確実」項目を事実のふりをせず列挙
- [ ] 機密データがプロンプトやログに出ない
