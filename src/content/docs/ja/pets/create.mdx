# Codex Pet を作成する

Codex Pet の作成は、単に見栄えのよい画像を作ることではありません。Codex が識別し、読み込み、再生し、状態を切り替えられるパッケージを作ることが目的です。「メタデータ + アニメーションアトラス + 出所とライセンス情報」の組み合わせとして考えると分かりやすいです。

<PetScienceFigure variant="spritesheet" locale="ja" />

最小構成は通常次のとおりです。

```text
<pet-id>/
  pet.json
  spritesheet.webp
```

## spritesheet とは

Spritesheet は、複数のアニメーションフレームを一枚の大きな画像にまとめる方式です。クライアントは多数の小さな画像を読み込む必要がなく、行と列の座標で各フレームを切り出し、順番に再生します。

多くの Codex Pet パッケージは、次の atlas 規約を使います。

- 8 列 x 9 行
- 1 フレームあたり 192 x 208 px
- 全体画像 1536 x 1872 px
- 72 フレーム
- WebP、または元ツールが明示的に対応する画像形式

これらは一般的な規約であり、永遠に固定されたルールではありません。作成前に、現在の Codex クライアント、生成ツール、または素材ソースが使う実際の契約を確認してください。

## 素材を準備する

良い素材には通常、次の条件があります。

- キャラクターの輪郭が明確で、背景をきれいに抜ける。
- 各アクションで比率、視点、基準線がそろっている。
- 透明背景に色フチ、残像、余分なピクセルがない。
- 再生時に切れないよう十分な余白がある。
- 作業、待機、完了、失敗、移動、アイドルなどの状態に対応できる。

素材が二次創作、ゲーム、アニメ、ブランド、他人の作品に由来する場合は、まず出所とライセンスを確認してください。許諾のない素材を商用可能なリソースとして説明しないでください。

## `pet.json` の役割

`pet.json` は少なくともペットの識別情報と spritesheet のパスを示します。最小例：

```json
{
  "id": "my-pet",
  "displayName": "My Pet",
  "description": "A focused companion for Codex sessions.",
  "spritesheetPath": "spritesheet.webp"
}
```

推奨事項：

- `id` は小文字、数字、ハイフンを使う。
- フォルダ名と `id` を一致させる。
- `spritesheetPath` は相対パスにする。
- `description` は中身が分かる説明にする。
- 追加メタデータに作者、バージョン、出所、ライセンスを残す。

`pet.json` はアニメーション自体を保存するものではありません。クライアントに「このパッケージは誰か、素材はどこにあるか、どう解釈すべきか」を伝えるものです。

## ローカル確認

公開または共有前に、少なくとも次を確認します。

- `pet.json` が有効な JSON である。
- `spritesheetPath` が存在するファイルを指している。
- spritesheet のサイズとフレームグリッドが現在の契約に合っている。
- 各行のアニメーションが大きく跳ねたり、ずれたり、切れたりしない。
- 透明背景がきれいである。
- パッケージに一時ファイル、元画像、公開すべきでない素材が入っていない。

## ライセンスと出所

ペット素材は、二次創作、スクリーンショット、AI 生成画像、公開素材、他人の作品などから来ることがあります。作成時は次を分けて考えてください。

- 個人利用できるか。
- 公開共有できるか。
- 他者による再配布を許可できるか。
- クレジット表記や出所リンクの保持が必要か。

元の作業ファイルと出所記録を残しておくと、後から修正、動作追加、サイズ変更、ライセンス説明の補足がしやすくなります。
