# Codex テーマスキン

Codex のスキンを変えるというと、見た目を少しよくするだけの話に聞こえます。実際には、Codex Dream Skin はデスクトップ向けの本格的なテーマ方式です。Codex のネイティブな操作は残し、公式インストールパッケージは変更せず、外部から背景・配色・雰囲気を実際の画面に注入します。

## Codex Dream Skin とは

Codex Dream Skin は、Codex デスクトップアプリをテーマ化するためのオープンソースプロジェクトです。16:9 の壁紙を Codex の背後に敷き、ライト/ダークモード、焦点位置、配色に合わせて自動調整します。サイドバー、提案カード、プロジェクト選択、入力欄は引き続きネイティブなインタラクティブ部品です。

![Codex Dream Skin が Codex ホーム画面に 16:9 背景を適用した例](/theme/codex-dream-skin/article/codex-dream-skin-home.jpg)

_実際の Codex デスクトップにテーマを適用したホーム画面。サイドバー、提案カード、入力欄はネイティブ部品のままです。_

以前の「バイナリを改造して着せ替える」方法とは大きく異なります。

| 方式 | 公式ファイル変更 | 署名破壊 | ネイティブ操作 | 画像自由度 |
| --- | --- | --- | --- | --- |
| CDP インジェクション（Dream Skin） | しない | しない | 使える | 高い |
| `app.asar` 変更 | する | する | 一部 | 中 |
| 公式ライト/ダーク切替 | しない | しない | 使える | なし |

`app.asar` を変更する方法では、Codex のリソースを展開し、CSS や画像を変えて再パックします。署名が無効になり、Codex の更新ごとにやり直しになりやすく、セキュリティソフトに止められることもあります。

CDP インジェクションは公式バイナリを変更しません。Codex の外側からデバッグポート経由でスタイルとスクリプトを注入し、`.app`、`app.asar`、コード署名には触れません。

できること：スキン変更、背景変更、複数テーマの保存、公式外観へのワンクリック復元。

しないこと：

- インストーラーが第三者 API Key や Base URL を黙って書き込むことはありません。テーマと中継設定は分離されています。
- 公式インストール先や署名は変更しません。
- CDP は `127.0.0.1` のみにバインドします。ただしテーマ実行中も、出所不明のローカルプログラムは避けるべきです。

プロジェクトは OpenAI 公式製品ではないと明記しています。復元してアンインストールすれば、Codex は公式外観に戻り、CDP 接続も切断されます。

## インストールと開始

インストール前に Codex を一度開き、デスクトップアプリが起動、ログイン、終了できることを確認します。これによりテーマツールが正しいローカル環境を見つけやすくなります。

### macOS

macOS では通常、プロジェクトの Releases から `.dmg` をダウンロードします。インストール後、`Codex Dream Skin.app` を Applications にドラッグし、メニューバーからテーマ管理、背景切替、公式外観への復元を行います。

アプリが「壊れている」または開けないと表示される場合、多くは Gatekeeper が未署名アプリをブロックしています。配布元を信頼できると確認した場合のみ、システム設定 > プライバシーとセキュリティで許可してください。

### Windows

Windows では通常 Releases からインストーラーをダウンロードするか、プロジェクト文書の PowerShell 手順に従います。インストール後はシステムトレイからテーマツールを開き、テーマや背景を管理します。

SmartScreen の青い警告が出る場合、インストーラーにコード署名証明書がないことがよくあります。配布元を信頼できる場合のみ続行してください。

### よくある問題

| 現象 | 原因 | 対処 |
| --- | --- | --- |
| macOS が「壊れている」と表示 | 未署名アプリを Gatekeeper がブロック | システム設定 -> プライバシーとセキュリティ -> このまま開く |
| Windows SmartScreen の青い警告 | コード署名証明書がない | 詳細情報 -> 実行 |
| インストール後に効かない | Codex を一度も起動していない | Codex を開いてログイン、終了してから Dream Skin をインストール |
| Codex 更新後にテーマが効かない | 内部パスが変わった可能性 | 最新インストーラーを上書きインストール |

上書きインストールしても、保存済みテーマや画像は削除されません。

## 背景画像とテーマ管理

インストール後、macOS のメニューバーまたは Windows のシステムトレイから「背景を変更」を選び、画像を指定します。

![Codex Dream Skin のテーマプレビューと切替](/theme/codex-dream-skin/article/codex-dream-skin-gallery.jpg)

_画像変更後はホーム、サイドバー、入力欄、タスクページを合わせて確認し、実作業でも読みやすい状態を保ちます。_

画像を選ぶと、エンジンは明るさ、主色、焦点位置、左右どちらの情報量が少ないかをローカルで分析し、その画像に合うテーマ変数を生成します。テーマは保存、命名、ワンクリック切替ができます。

Gothic Void Crusade は公開インストーラーのデフォルトテーマで、コミュニティ作者によるものです。任意の 16:9 の純粋な背景画像もインポートできます。

画像の目安：

- 推奨は `2560 x 1440` の 16:9 背景。ウィンドウ、サイドバー、文字、ロゴを含めない。
- 主役を Codex の入力欄、サイドバー、提案カード領域に重ねない。
- 明るすぎる、情報量が多すぎる、コントラストが強すぎる背景は避ける。
- 公開共有や商用利用の前に、画像、人物、商標、フォント、IP の権利を確認する。

構図条件を満たさない画像も使えますが、ネイティブ内容が主役を隠したり、文字が読みにくくなったりします。

## 仕組み

### CDP インジェクション

CDP（Chrome DevTools Protocol）は Chromium 系ブラウザーのリモートデバッグプロトコルです。Chrome DevTools がモバイルページをリモートデバッグするときにも使われ、ブラウザーがローカルデバッグポートを開き、外部ツールが CSS や JavaScript を注入できます。

Codex デスクトップは Electron ベースで、内部は同じく Chromium です。Dream Skin の流れは次のように簡略化できます。

![記事中の CDP インジェクション手順図](/theme/codex-dream-skin/article/cdp-injection-flow.png)

```text
テーマツールを起動
  -> ローカル CDP エンドポイント付きで Codex デスクトップを開く
  -> Codex の Chromium レンダラープロセスへ接続
  -> テーマ CSS と装飾 DOM を注入
  -> Codex は通常通り動き、見た目はテーマ層が担当
```

インジェクター停止時には PID、実行ファイルパス、起動時刻を照合し、別プロセスを誤って終了しないようにします。

注入された CSS はサイドバー、入力欄、提案カードのネイティブ操作を保ちます。壁紙はネイティブ部品の下に置かれ、半透明のグラデーションで文字の可読性を確保します。

### 自適応配色：ローカル計算、アップロードなし

画像変更後、Dream Skin は Canvas 上で画像をローカルに縮小し、主色、明るさ、焦点位置を抽出します。その後 HSL 色空間でアクセント色、サブ色、ハイライト色などの CSS 変数を計算します。

ダークモードでは暗めの主色から、ライトモードでは明るいニュートラルグレーから出発します。画像が変わるたび、配色全体が自動再計算されます。

ルート認識として、ホームではフル背景とグラデーションを維持し、タスクページでは低干渉の環境レイヤーに切り替えて、内容を優先します。

## 最後に

CDP インジェクションによるテーマ化は、公式バイナリを変更せず、アプリ外部からスタイルを注入する考え方です。この考え方は Codex だけでなく、CDP デバッグポートを持つ Electron アプリ全般に理論上応用できます。

個人化された開発環境への需要は確かにあります。よいテーマは「より格好いい」だけでなく、ネイティブ操作を保ち、復元可能で、検査でき、見た目の拡張とモデル設定を混ぜないものであるべきです。
