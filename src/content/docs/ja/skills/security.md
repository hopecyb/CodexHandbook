Skill は単なるプロンプトテンプレートではありません。

Codex の動き方を変え、スクリプトや追加リソースを含むことがあります。

信頼できないソース、未レビュー内容、バージョンのずれは MCP と同等のリスクになり得ます。本ページはチームが Skill を**選定・インストール・アップグレード・監査**する方法を説明します。

## 内容

- 入れてはいけない Skill
- バージョン固定と変更レビュー
- Plugin 配布との関係

## 一般利用者が知る理由

次をするなら、すでにリスク伝播チェーンにいます。

- 他人が共有した Skill をインストール
- プロジェクトでチーム Skill を参照
- 既存 Skill をアップグレード
- 同僚に Skill を推奨

Skill セキュリティは「誰かが一元管理」だけに頼れず、利用者にも基本判断が必要です。

基礎：[Skills 概要](/skills/overview/) · [最初の Skill を作成する](/skills/create-your-first-skill/)

## 脅威モデル（簡略）

| リスク | 現れ方 |
|---|---|
| 悪意ある Skill | 鍵漏洩の誘導、破壊的 shell 実行 |
| 過剰権限 | 触るべきでないパスの読み書き |
| サプライチェーン | 改ざんされた第三者 Skill リポジトリ |
| 古い Skill | 新 CLI と非互換、異常挙動 |

## インストール前の確認

任意の Skill で次を問う：

1. どこから来たか？
2. Codex に余分に何をさせるか？
3. `SKILL.md` と同梱スクリプトが理解できるか？

3 つのうち 2 つ答えられなければ、本番プロジェクトに入れない。

## インストール原則

1. **ソース**：公式マーケットプレイス、社内 Git を優先。匿名 gist は慎重に
2. **閲読**：インストール前に `SKILL.md` とスクリプトを開き、不自然な権限要求を確認
3. **分離**：顧客プロジェクトと個人実験 Skill をディレクトリ分け
4. **最小利用**：10 個積むより 1 個で解決

## よくある誤解

### 1. Skill は文字だけなので実リスクはない

ワークフロー、ツール選択、スクリプト実行に影響——「口調が変わる」だけではない。

### 2. 人気 Skill は本番でも安全

他人の文脈はあなたのリポジトリ、権限境界、チームルールと一致しない。

### 3. Skill のアップグレードはドキュメント更新と同じ

チームにとって Skill アップグレードは自動化行為のアップグレード——依存のアップグレードと同様に扱う。

## バージョンとアップグレード

| 実践 | 説明 |
|---|---|
| バージョン固定 | チーム文書に Skill 名 + commit/tag を記録 |
| 変更レビュー | Skill 更新は依存バンプ同様に PR |
| changelog | チーム Skill セットのリリースノートを維持 |
| ロールバック | 前版を保持。障害時に迅速切替 |

Plugin は Skill をバンドルして統一配布可能：[Plugins 概要](/skills/plugins/plugins-overview/)

## チームの習慣

Skill が長期に多人で使われるなら「誰かが DM でパスを送った」ままにしない。  
より適切：

- 固定ソース
- バージョン履歴
- アップグレード説明
- ロールバック経路

## `$skill` 呼び出しとの関係

明示的 `$name` は意図が明確。**モデル自動選択**時は `AGENTS.md` で利用可能 Skill とシーンを制限。

## チームガバナンスチェックリスト

- [ ] 許可 Skill ソースのホワイトリスト
- [ ] 新人オンボーディングは「基本パック」のみ
- [ ] 四半期ごとにまだ必要な Skill を再確認
- [ ] [許可と拒否パターン](/guide/customization/rules/allow-and-deny-patterns/) と整合

## よくあるミス

- チャットリンクから「万能 Skill」をインストール
- 本番 `AGENTS.md` が個人パス Skill を参照
- アップグレード後にスモークタスクを走らせない
- `SKILL.md` を読まず挙動を信頼
