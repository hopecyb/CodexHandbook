`MCP` は標準的な接続方式です。Codex は MCP 経由で外部ツールとデータソースに接続します。

Skill が「作業手順」寄りなら、MCP は「外部ツールを接続する」ことを扱います。

## 本グループの内容

- 本当に MCP が必要な状況
- 外部システムを接続しつつ権限を広げすぎない方法
- 接続できない、呼べないときに先に見る問題の種類

## 推奨順序

1. [MCP 概要](/skills/mcp/mcp-overview/)：MCP と Skill、Plugin の役割分担を先に区別
2. [MCP サーバー接続](/skills/mcp/connect-an-mcp-server/)：設定の考え方で最初のサーバーを接続
3. [MCP デバッグ](/skills/mcp/debugging-mcp/)：接続不可、ツール非表示、権限不一致時の切り分け

## よくある誤解

### 1. MCP を接続すれば Codex が「万能」になる

できることは、接続した MCP サーバーが公開するツールと、それらツールに与えた権限次第です。

### 2. MCP は技術接続の問題だけ

実システムに接続すると同時に次になります。

- 権限の問題
- データ露出の問題
- 監査の問題

したがって「どう接続するか」だけでなく「どう接続を乱さないか」も含みます。

リポジトリ外の実システムに触れる必要があるタスクでのみ、MCP が価値を持ちます。
