**Automations** は Codex を**スケジュール、リポジトリイベント、外部トリガー**で自動実行します。例：依存更新チェック、ドキュメント同期、定期ヘルススキャン。

## 本ページの内容

- いつ自動化に値し、いつ人をループに残すか
- トリガー、実行、通知、失敗の 4 設計点
- Cloud タスク、ローカル CLI スクリプトとの関係

## 手動タスクとの比較

| | 手動タスク | Automation |
|---|---|---|
| 開始 | あなたが起動 | スケジュール/イベント |
| 監督 | いつでも中断可能 | 通知とログが必要 |
| リスク | その場で判断 | 誤りが一括拡散しうる |
| 向く用途 | 探索、リファクタ | 反復、ルール明確 |

## 安全な自動化設計

### 1. トリガー条件を明確に

```text
良い：毎週月曜 09:00 に docs/ ディレクトリの死リンクをチェック
悪い：常時監視してコードを自動変更
```

### 2. 権限の最小化

- 読み取りスキャンは自動コミットより優先
- 自動 PR を開く場合は専用 bot アカウントとブランチ保護を使用

### 3. 終了条件

- 連続 N 回失敗で一時停止
- diff が行数閾値を超えたら人手へ
- `AGENTS.md` 禁止ディレクトリに触れたら中止

### 4. 通知

- Slack/メール/モバイル：完了、失敗、承認待ち
- 監査用にログを保持

### 5. 人手レビューポイント

| 完全自動でよい | 人手が必要 |
|---|---|
| ドラフト PR 生成 | main へのマージ |
| 陳腐化依存の一覧 | major バージョンのアップグレード |
| 公開ドキュメントの同期 | 対外公告の公開 |

## 典型パターン

### 定期メンテナンス

- 依存脆弱性レポート → issue を開き、lockfile は直接変更しない
- 翻訳ファイルとソース文案の diff リマインダー

### イベント駆動

- 新 PR オープン → review Skill を実行（コメント提案のみ、push しない）
- Issue ラベル `bug` → 再現手順ドラフトを生成

### 長時間タスク

複数段の Automation + [引き継ぎと再開](/guide/agent-work/handoff-and-resume/) に分割し、単回のコンテキスト枯渇を避ける。

## Cloud / CLI との関係

- **Cloud**：GitHub 深統合のリモート自動化に向く
- **CLI + cron/CI**：イントラネット、カスタムパイプライン向き
- 選定は [ローカルとクラウド](/guide/foundations/local-vs-cloud/) と [Web と Cloud](/guide/web-and-cloud/) を参照

## よくあるミス

- 自動化が直接 `git push` で main に送る
- 失敗アラートがなく、リポジトリが静かに劣化
- 探索的タスクをスケジュール化——クォータ浪費と検証困難

## 受け入れチェックリスト

- [ ] トリガー条件、権限、通知、終了条件を文書化
- [ ] fork またはテストリポジトリで 1 サイクル完走をリハーサル
- [ ] チームが bot アカウントと承認ルールを把握
