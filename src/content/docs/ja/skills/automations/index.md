`Automations` は主に繰り返しタスクの自動実行を扱い、「Codex をもっと賢くする」話ではありません。

このグループが重視するのは：

- どのタスクを自動実行する価値があるか
- 自動実行はどこで止めて人を待つか
- 失敗、アラート、ロールバックをどう設計するか

## 判断の要点

自動化に初めて触れるとき、すべての反復作業をすぐ任せる必要はありません。

次の順で判断できます。

1. まず**繰り返し、ルールが明確、結果が検証しやすい**か
2. 読み取り専用、提案のみ、ドラフト PR のみで足りるか
3. その後、完全無人実行を検討

## 本グループの入口

- [スケジュールとバックグラウンドタスク](/skills/automations/scheduled-tasks/)：自動化タスクとは何か、トリガー方式、終了条件、人手レビューポイント

## よくある誤解

### 1. 繰り返すなら必ず自動化すべき

反復でも判断基準が人に強く依存するなら、早すぎる自動化はかえって問題を起こしやすい。

### 2. 自動化は人手確認を省くべき

多くの自動化は、次だけでも価値があります。

- 自動チェック
- 自動集約
- 自動で issue / ドラフト PR を開く

結果を直接 main に push しない。

自動化は「繰り返し、ルールが明確、結果が検査しやすい」タスクに向きます。判断依存のことは、フローに人手レビューを残す方が安定しやすいです。
