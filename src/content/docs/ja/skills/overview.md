**Skill** は `SKILL.md` を含むディレクトリ（スクリプトや参考資料を追加可能）で、一連の固定フローを Codex が**自動または明示的に呼び出せる**能力としてパッケージ化したものです。

すでに繰り返し現れ、今後も使い続ける作業方法に向いています。

## コア概念

### スラッシュコマンドとの違い

| | スラッシュコマンド | Skill |
|---|---|---|
| トリガー | `/xxx` と入力 | `$name` で呼び出し、またはモデルが description に基づいてマッチ |
| コンテキスト | 一般に即座に展開 | **段階的開示**：普段は名前+説明のみ、選択時に全文を読む |
| 向いている用途 | 固定で高頻度、覚えている入口 | フローが長い、ドキュメントが必要、モデルに判断させたい場合 |

### 段階的開示

Codex 起動時には各 Skill の **name、description、パス** だけが見えます。使用を決めたときだけ完全な `SKILL.md` を読み込みます。そのため本文に詳細なチェックリストを書いても、コンテキストを占有しません。

注意：Skill リストには**初期文字数予算**（コンテキストの一部程度）があります。`description` では核心となるトリガーシーンを**先頭に**書き、切り詰められてマッチ失敗しないようにしてください。

## Skill ディレクトリ構造

```text
my-skill/
├── SKILL.md          # 必須
├── scripts/          # 任意：決定論的ステップ
└── references/       # 任意：長い参考ドキュメント
```

`SKILL.md` の最小例：

```md
---
name: pr-review
description: 現在のブランチと main の diff をレビューし、リスクとテスト不足を指摘する。ユーザーが review、PR レビュー、マージ前チェックを求めたときに使用する。
---

## ステップ
1. main との diff を取得
2. ファイルごとに分類：ロジックエラー、セキュリティ、パフォーマンス、テスト
3. 段階別リストを出力：ブロック / 提案 / nit
4. 自動で push やマージしない
```

## 配置場所

| 種類 | 典型的な場所 | 説明 |
|---|---|---|
| プロジェクト Skill | `.agents/skills/<name>/` | リポジトリに含まれ、チームで共有 |
| ユーザー Skill | ユーザー skills ディレクトリ（公式ドキュメント参照） | 個人でプロジェクト横断 |
| 公式厳選 | インストーラー経由でインストール | パスはインストーラーが管理、手書きディレクトリと混同しない |

**しないこと**：古いチュートリアルの誤ったパスや架空の `trigger:` フィールドをそのまま使うこと。 [公式 Skills ドキュメント](https://developers.openai.com/codex/skills) を正とする。

## トリガー方式

1. **明示的**：対応環境で `$skill-name` で呼び出し（名前は frontmatter の `name` と一致）
2. **暗黙的**：モデルが `description` の意味から現在のタスクに適用するか判断

`description` を書く要点：

- 「いつ使う」「いつ使わない」を明確に
- ユーザーが言いそうなキーワードを含める（review、リリース、changelog）
- 漠然とした「ユーザーのコードを手伝う」は避ける

## 推奨ワークフロー

1. あるフローを何度か手動で繰り返したことに気づく
2. `SKILL.md` を起草し、まずはテキストのみのステップ
3. 小さなタスクで `$name` と暗黙マッチを試す
4. 決定論が必要になったら `scripts/` を追加
5. `.agents/skills/` にコミットし、チームに PR

実践演習：[最初の Skill を作成する](/skills/create-your-first-skill/)

## よくある混乱

### 1. Skill とプロンプトの違いは？

- **プロンプト**：今回のタスクで一時的に言うこと
- **Skill**：今後も同様のタスクで再利用できる一連のフロー

### 2. 最初から Skill の書き方を覚える必要がある？

いいえ。まず普通のタスクを明確に伝え、あるフローが何度も繰り返されたら Skill 化を検討すればよい。

### 3. スラッシュコマンドと同じこと？

完全には同じではない。スラッシュコマンドはショートカット入口に近く、Skill は完全な説明とフローを持つワークパッケージに近い。

Skill は入門の必需品ではなく、すでに繰り返し現れるフローを整理するのに向いている。

## セキュリティ境界

- Skill 内のスクリプトと MCP 呼び出しは現在の承認ポリシーを継承
- Skill に秘密鍵をハードコードしない。環境変数または MCP 認証を使う
- チームはサードパーティ Skill を依存パッケージと同様にレビューする

## よくあるミス

- `description` が長すぎるか広すぎて、トリガーされないか誤トリガーされる
- 1 つの Skill に無関係な 10 種類のフローを詰め込む
- 明確に説明できるステップをスクリプトで置き換え、保守が難しくなる
