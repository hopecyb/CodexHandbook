# 作成テンプレート

ゼロから作るタスクでよくある問題は次の2つです。

- 目標は大きいが境界がない
- 情報がまだ足りないのに生成を急ぐ

作成系テンプレートは、成果物・用途・制約を先に言ってから始めます。

## テンプレート

```text
目標：【成果物名】を作成し、【用途／ユーザー】向けとする。
背景：【既存の約束、デザイン方針、依存の制限】
入力：【仕様、ラフ、参考 @ファイル】
制約：
- 【パス範囲】のみ変更／作成
- 【除外項目】は導入しない
- 【高リスク操作】は私の承認後に実行
受け入れ：
- 【観察可能な結果 1】
- 【観察可能な結果 2】
- 自己テスト手順を提供
情報不足なら仮定を列挙して質問し、推測しない。
```

## いつこのテンプレートが向くか

- ページ・コンポーネント・スクリプト・ドキュメントをゼロから作る
- 何を出すかは分かっているが、まだ手を付けていない
- 作成範囲を先に言ってから始めたい

## よくある誤解

### 1. 作成タスクは自由にやらせればよい

ゼロから作るほど次を書く必要があります。

- 誰向けか
- 何のためか
- 触ってはいけないスタイルや技術路線

### 2. 背景は飾り

作成タスクでは背景が成果物の方向を左右することが多いです。

### 3. 受け入れは「良さそう」で足りる

完了判断が難しくなります。

作成タスクで最も問題になりやすいのは、「何を作るか・誰向けか」を言わずに始めることです。
