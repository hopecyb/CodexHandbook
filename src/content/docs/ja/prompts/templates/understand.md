# 理解テンプレート

多くのタスクが止まるのは、最低限の共通理解がまだないからです。

理解テンプレートは「まず把握し、次を決める」タスク向けです。

## テンプレート

```text
目標：【テーマ／モジュール／コードベース領域】を理解し、後続の【実装／変更／レビュー】の準備をする。
背景：【プロジェクト種別、技術スタック、関連 issue】
入力：【@ファイルパス、ドキュメントリンク、スクリーンショット】
制約：読み取り専用の分析のみ。ファイルは一切変更しない。破壊的コマンドは実行しない。
出力：
1. 核心概念またはモジュール責務を 5〜8 条で説明
2. 【目標】に最も関連するファイル／ディレクトリ 3 つと理由
3. 要確認の質問 3 つ
受け入れ：出力を見て次のタスク範囲を決められる。
```

## いつこのテンプレートが向くか

- コードベースを新規引き継ぎ
- 見慣れないモジュールを読む
- 変更前に関連範囲を把握する

## よくある誤解

### 1. 理解タスクは「要約させる」だけ

次も示させます。

- どのファイルが最も関連するか
- まだ不明な点はどこか
- 次はどこから手を付けるか

### 2. 理解フェーズは詳細すぎても意味がない

まず主線を掴む方が、いきなり全部掘るより重要です。

理解テンプレートの価値は、次のタスク範囲を先に絞れることです。
