# レビューテンプレート

レビュータスクが外れやすいのは、いきなり「ついでに直す」モードになることです。

問題を先に洗い出し、直すかはあとで決める方が安定します。

## テンプレート

```text
【main／対象ブランチ】との diff をレビューして。先にコードは変更しないで。
観点：
1. 【issue／仕様】の範囲を超えていないか
2. ロジックエラー、境界、エラーハンドリング
3. セキュリティ（鍵、インジェクション、権限）
4. テストとドキュメントが変更に追随しているか
出力：🔴 ブロック / 🟡 提案 / 🟢 合格 の段階付きリスト。各項目にファイルと行番号。
```

## いつこのテンプレートが向くか

- PR のレビュー
- diff のレビュー
- ドキュメントや設定変更のリスク確認

## よくある誤解

### 1. レビューは意見をもらうこと

より正確には、構造に沿って問題を探すことです。

### 2. 明らかなバグがなければ合格

次も見ます。

- 範囲超過
- テスト・ドキュメントの追随
- セキュリティと境界

レビューテンプレートの要点は、固定の観点でリスクを洗い出すことで、「良い／悪い」の漠然とした評価ではありません。
