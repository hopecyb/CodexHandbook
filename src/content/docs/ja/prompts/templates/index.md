# プロンプトテンプレート

「テンプレート」と聞くと反応は二つに分かれがちです。

- 硬すぎて使いたくない
- そのままコピーして、何を変えるべきか分からない

テンプレートの主な役割は、重要な段落を抜かしにくくすることであり、あなたの代わりに唯一の正解を出すことではありません。

テンプレートページの目的はタスク構造を保つことで、唯一の正解を生成することではありません。

## テンプレートの使い方

次のように使えます。

1. タスクに最も近いテンプレート種別を選ぶ
2. `【】` のプレースホルダを自分の実タスクに置き換える
3. 関係ない段落を削除する
4. 今回固有の制約と受け入れを足す

テンプレートは足場であり、模範解答ではありません。

| テンプレート | 向く場面 |
|---|---|
| [理解](/prompts/templates/understand/) | コードベース・ドキュメント・資料を読み、まず認識を揃える |
| [作成](/prompts/templates/create/) | 機能・原稿・成果物をゼロから作る |
| [変更](/prompts/templates/change/) | 既存の上で反復的に改める |
| [診断](/prompts/templates/diagnose/) | 根因を特定し、先にコードは触らない |
| [レビュー](/prompts/templates/review/) | diff、PR、ドキュメント変更をレビュー |
| [調査](/prompts/templates/research/) | 出典付きの調査と比較 |
| [自動化](/prompts/templates/automate/) | 反復タスク、スクリプト、無人フロー |

## テンプレートからワークフローへ

一度だけでよいプロンプトもあります。何度も出てくるものは、安定した形に沈めるべきです。

| 繰り返すタスク | 最初の形 | 安定後の形 |
|---|---|---|
| PR 準備 | レビュー/変更テンプレート | 固定チェックリストを持つ Skill |
| API ドキュメント生成 | 作成/変更テンプレート | Skill + ドキュメントスクリプト |
| テストカバレッジ拡張 | 変更テンプレート | Skill + 合意済みテストコマンド |
| 性能調査 | 診断テンプレート | サブエージェントまたは専用 Skill |
| ファイル作成後の形式確認 | テンプレートだけでは不向き | Hook |
| 外部チケットを読んでから改修 | リサーチテンプレート | MCP + Skill |

テンプレートは人が始めるタスク向きです。Skill は繰り返す手順、Hook は固定点の自動チェック、MCP は外部システム接続に向きます。

## よくある誤解

### 1. テンプレートはそのままコピーするもの

プレースホルダを変えず、不要段落を削らないと、かえって空っぽのタスクになります。

### 2. テンプレートを使えば自然とプロっぽくなる

テンプレートは構造を保つだけで、次は代わりに決められません。

- 本当の目標は何か
- 制約はどこまでか
- 受け入れはどう書くか

### 3. テンプレートは多いほど良い

初心者には「足りるが膨らみすぎない」で十分です。

まず種別を選び、自分のタスクに直す。テンプレートそのものをタスクにしない。
