長時間タスクでよくある失敗は次のとおりです。

- 一度にやりすぎる
- 途中にチェックポイントがない
- スレッドが長くなり、前後の制約が矛盾する

長時間タスクの要点はプロンプトを長くすることではなく、チェックポイント付きの小さなフェーズに分けることです。

長時間タスクはフェーズに分け、各フェーズに受け入れを置きます。

```text
フェーズ 1：調査と案の列挙のみ（コードは変更しない）
フェーズ 2：最小限の変更を実装
フェーズ 3：テストを足して実行……
各フェーズの終わりに一旦止めて、私の確認を待って。
```

## なぜ長時間タスクは逸脱しやすいか

だいたい次の仕事が一度に混ざります。

- 問題の理解
- 設計
- 実装
- 検証の実行
- 引き継ぎメモ

これらを「一気に完了」にするとリスクが上がります。

## よくある誤解

### 1. 長時間タスクは短いタスクを詳しく書けばよい

長時間タスクには**段階管理**が必要で、背景を増やすだけでは足りません。

### 2. フェーズを列挙すれば十分

各フェーズに明確な出口があるとよいです。例：

- 案だけ、コードは触らない
- 最小実装だけ
- テストと検証だけ

### 3. 1 スレッドを最後まで続ける方がよい

長すぎると、引き継ぎ・要約・スレッドを開き直す方が明確になることがあります。

## 十分使える分割の考え方

長時間タスクは次の4段に分けられます。

1. 調査：理解する、手は動かさない
2. 計画：手順・リスク・検証を列挙
3. 実行：最小変更
4. 検証：チェック実行、結論、引き継ぎ準備

## より実用的な書き方

```text
フェーズ 1：調査と案の列挙のみ。コードは変更せず、確認を待つ
フェーズ 2：最小変更のみ。終わったら影響範囲を報告
フェーズ 3：検証を補い、関連チェックを実行
フェーズ 4：変更・リスク・今後の提案をまとめる
```

各段で止まって確認できるようにするのが適切です。
