# 権限とサンドボックス

Codex は同意なしに高リスク操作を実行すべきではありません。**承認** は人と機械の協業における重要なゲートです。**サンドボックス** は Agent が触れられるファイルシステムと一部のシステム能力を制限します。

## 本ページの内容

「権限」「承認」「サンドボックス」「ネットワークアクセス」は似た安全設定に見えがちです。

問題になりやすいのはこの混同です。続行を許したつもりが、実際にはファイル書き込み、コマンド実行、外部ネットワークまで広がっている、というケースです。

本ページではこれらを分け、各確認で何が開放されるかを判断できるようにします。

## まず概念を分ける

次のように分けられます。

- **承認**：先に聞くかどうか
- **サンドボックス**：やろうとしても、どこまで触れるか
- **ネットワークアクセス**：情報を外に出せるか、外から取れるか

結果には一緒に効きますが、同じものではありません。

## 通常気にすべきこと

- 現在のプロジェクト外のパスへの読み書きを許すか
- ネットワーク接続を許すか
- 特定の shell コマンドを許すか
- チームが強制ポリシーを配布しているか（マネージド設定）

## サンドボックスとネットワーク

**サンドボックス** は誤操作の面を小さくします。**ネットワークアクセス** は別レイヤーのリスクです。プロンプト内の機密情報が外部に漏れたり、信頼できないデータを取り込んだりする可能性があります。

初めて使うときは、次の考え方がおすすめです。

1. 初回練習では不要なネットワークを切る、または必要なものだけ許可
2. 本番鍵を練習プロジェクトに入れない
3. 「外部接続 / 機密パスへの書き込み」要求が出たら、内容を読んでから承認

## よくある誤解

### ダイアログが出た = 必ず危険

多くの正常操作でも承認が出ます。例えば：

- 依存関係のインストール
- プロジェクト外ディレクトリへの書き込み
- ブラウザやシステムアプリの起動
- 外部サイトや API へのアクセス

判断すべきは **この一歩が今のタスクに本当に必要か** です。ダイアログの有無だけでは判断できません。

### ダイアログが出ない = 完全に安全

サンドボックスがもともとその操作を許している、または以前にルールを緩めている場合、Codex は繰り返し聞かないことがあります。

リスク判断は「プロンプトがあったか」だけでなく、現在の環境設定も見る必要があります。

## 権限要求が出たときの判断手順

毎回、次の 3 つを自分に聞いてください。

1. この一歩は現在のタスクに必須か
2. 触れるデータやパスは、自分の想定を超えていないか
3. 失敗しても、取り消しや復旧の方法がわかるか

3 つのうち 2 つに答えられないなら、承認せず、なぜ必要か説明させてください。
