Cloud で問題が起きたとき、再実行を繰り返しても根本原因は通常解決しません。

Cloud の問題は**権限、環境差異、認証情報、ネットワーク**の 4 層に多くあります。本ページは症状から対応するトピックへ案内し、チャットで盲目的に再試行するのを避けます。

## 内容

- タスク失敗時に最初に調べる原因の種類
- ローカルトラブルシューティングとの役割分担
- いつローカルでの小さな検証に戻すべきか

## まず何を調べるか

「Cloud は赤、ローカルは緑」なら、実行条件を優先的に確認してください。

よくある原因：

- リモート環境とローカルが異なる
- Cloud はローカル未プッシュのものを見えない
- Secret が正しく設定されていない
- ネットワークまたは権限が制限されている

トラブルシューティングでは、条件が満たされているかを先に見て、タスク自体の問題はその後に見ます。

## クイックトリアージ

| 症状 | 優先参照 |
|---|---|
| リポジトリ接続不可 / 403 | [GitHub に接続](/guide/web-and-cloud/connect-github/) |
| 依存関係インストール失敗 | [インターネットアクセス](/guide/web-and-cloud/internet-access/) · [Cloud 環境](/guide/web-and-cloud/cloud-environments/) |
| プライベートパッケージ / API 401 | [Secrets と変数](/guide/web-and-cloud/secrets-and-variables/) |
| タスクがずっと待機中 | [委任とフォローアップ](/guide/web-and-cloud/delegate-and-follow-up/) · 承認待ちか |
| ローカルに commit があるが Cloud に見えない | push 済みか。Cloud は未プッシュのローカル内容を読まない |
| PR が開けない / プッシュできない | ブランチ保護 · [PR を作成](/guide/web-and-cloud/create-pull-requests/) |
| Cloud でテスト赤、ローカル緑 | バージョン/環境整合表は [Cloud 環境](/guide/web-and-cloud/cloud-environments/) |

## トラブルシューティング順序

次の順序で調べられます：

1. リポジトリとブランチは正しいか
2. 権限と承認は十分か
3. 環境と依存関係は揃っているか
4. Secret とネットワークは通るか
5. タスク説明に重要な制約の漏れはないか

これらを先に整理する方が、いきなり再実行するより効果的です。

## 接続と権限

**現象：** OAuth は成功したが、タスクが clone できない。

**確認：**

1. 承認スコープに対象組織/リポジトリが含まれているか
2. リポジトリが archived か、GitHub App 制限が有効か
3. 個人アカウントで org SSO が必要なリポジトリに接続していないか

**現象：** push が拒否される。

**確認：** ブランチ保護、required review、`main` への直接 push を試していないか

## よくある誤解

### 1. インストール段階のエラーは必ず依存関係の問題か

ネットワーク、認証、Secret、プライベート registry 権限の問題かもしれません。

### 2. ローカルで動くからコードに問題はなく、Cloud はたまの不調か

多くの場合、  
**ローカル環境に Cloud にない前提条件がある**ことを示します。

### 3. タスクが止まっているのはモデルが考えているからか

次の可能性もあります：

- 承認待ち
- ネットワーク待ち
- 環境起動待ち
- 範囲が大きすぎるタスク

## 環境と依存関係

**現象：** `command not found`（node、python など）。

**確認：** ベースイメージに必要なランタイムが含まれているか。`AGENTS.md` にバージョンとインストールコマンドが書かれているか。

**現象：** lockfile 競合またはインストールタイムアウト。

**確認：** 外部ネットワークポリシー。registry ミラー。依存関係に VPN が必要（Cloud は通常社内ネットワーク外）

## Secrets と変数

**現象：** ビルド時に環境変数が空。

**確認：**

- Secret 名がドキュメントと一致しているか（大文字小文字の区別がよくある）
- 正しいリポジトリ/環境スコープに設定されているか
- Secret 値をプロンプトに書いてマスキングされた誤りをしていないか

詳細：[Secrets と変数](/guide/web-and-cloud/secrets-and-variables/)

## タスクの停止とタイムアウト

| 原因 | 対処 |
|---|---|
| 人の承認待ち | App/スマホで承認または拒否 |
| タスクが大きすぎる | 複数の小さな委任に分割 |
| 環境起動が遅い | 初回のコールドスタートは正常。継続的に遅い場合は公式ステータスページを確認 |

フォローアップ方法：[委任とフォローアップ](/guide/web-and-cloud/delegate-and-follow-up/)

## 成果物品質

Cloud は完了したが結果が使えない：

1. タスク説明に検証条件の漏れがないか照合
2. ローカルで同一ブランチを checkout してテスト実行
3. [先に診断してから修正](/cases/workflows/diagnose-before-fixing/) でフォローアップを追加し、タスク全体をやり直さない

## いつローカルに戻すべきか

Cloud の条件を 2 ラウンド連続で調べており、タスク自体が前に進んでいないなら、先にローカルに戻れます：

- ローカルで最小再現
- 依存関係、コマンド、検証方法を明確に記載
- その後 Cloud に再委任

リモート環境で推測し続けるより時間を節約できます。
