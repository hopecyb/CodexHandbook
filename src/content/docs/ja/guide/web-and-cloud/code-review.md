Cloud は変更の作成を手伝いますが、マージの責任までは引き受けません。

Cloud タスク終了後、**人のレビュー**がマージ前の最後の関門です。本ページでは、リモート Agent の成果物をどうレビューし、GitHub PR、CI、Skill レビューと連携するかを説明します。

## 内容

- Cloud PR とローカル PR レビューの違い
- レビューチェックリストとよくあるリスク
- Codex でレビューを補助しつつ責任を放棄しない方法

## なぜ Cloud レビューはより注意が必要か

リモート Agent では次のような状況が起きやすいからです：

- 無関係なファイルまでついでに変更
- 環境差異による大量の lockfile や生成ファイルの変更
- テストが走ったように見えるが、重要ロジックをカバーしていない
- PR 説明は充実しているが、内容が事実か未確認

Cloud レビューは軽くなるのではなく、要点を押さえる必要があります。

## フロー上の位置づけ

```text
Cloud タスク完了 → ブランチをプッシュ → PR を開く
        ↓
CI 実行（テスト、lint、セキュリティスキャン）
        ↓
人が diff をレビュー + 任意で Agent 補助レビュー
        ↓
承認してマージ（ブランチ保護の制約下）
```

PR を開く：[Pull Request を作成](/guide/web-and-cloud/create-pull-requests/)

## 最低チェック基準

完全なレビューの前に、少なくとも次の 4 点を確認してください：

1. 変更範囲がずれていないか
2. 重要ロジックが本当に目標どおり変更されているか
3. テストまたは検証が実際に行われたか
4. 機密情報や危険な変更が混入していないか

この 4 項目を確認する前に、「タスク完了」を「マージ可能」とは言えません。

## 人によるレビューチェックリスト

[diff のレビュー](/guide/quality/review-diffs/) と一致し、Cloud シナリオでは追加で次に注意：

| チェック項目 | 理由 |
|---|---|
| 無関係なファイルを変更していないか | リモート Agent が「ついでに」リファクタリングする可能性 |
| lockfile / 生成ファイル | 環境差異による大規模変更 |
| 新規依存関係の出所 | サプライチェーンリスク |
| テストが新ロジックを本当にカバーしているか | Agent が空のテストを書く可能性 |
| 権限と認証の変更 | 権限昇格、token のハードコード |
| issue の範囲と一致しているか | scope creep を防ぐ |

## よくある誤解

### 1. CI が緑ならマージしてよいか

CI が示すのは「この自動チェックセットは失敗しなかった」だけです。要件の理解、範囲のずれ、許容できるリスクかは、人が判断する必要があります。

### 2. Agent が書いた PR 説明が充実しているから、少し見なくてよいか

それでもダメです。

PR 説明はコンテキストに素早く入る助けであり、事実の検証を代行しません。

### 3. Codex にもう一度レビューさせれば、レビュー完了か

補助レビューは有用ですが、最終責任は人にあります。

## Codex でレビューを補助する（人の代替にはしない）

許容されるやり方：

- ローカルまたは Cloud で新 PR に `$pr-review` Skill を実行（[Skill を作成](/skills/create-your-first-skill/) を参照）
- 「ブロッカー / 提案 / nit」の 3 分類で意見を出すよう要求
- **あなた**がブロッカー項目を一つずつ確認

許容されないやり方：

- diff を読まず、Agent の「問題なし」だけでマージ
- Agent に保護ブランチを自行 approve させる

[検証と人間による再確認](/guide/foundations/verification-and-human-review/) を参照

## 推奨順序

次の順序で見るとよいです：

1. PR タイトルと説明で目標を確認
2. 主要ロジックの diff
3. テスト、生成ファイル、設定ファイル
4. 自動コメントと補足提案

最初から大量の詳細に埋もれないようにできます。

## レビューコメントに基づく修正

PR に review コメントが付いたら：

1. 新しい Cloud またはローカルタスクを開く：「以下の review コメントのみ対応し、範囲を広げない」
2. コメントのリンクまたは番号を添付
3. 同一 PR に新 commit をプッシュ
4. 再度 CI + 差分を人が確認

GitHub 側：[GitHub 統合](/guide/integrations/github/)

## Automations との連携

- PR オープン時にレビュー Skill を自動実行（コメントのみ、merge しない）
- 詳細は [スケジュールとトリガータスク](/skills/automations/scheduled-tasks/)

## よくあるエラー

- Cloud 環境の「分離」を信頼してセキュリティレビューをスキップ
- 「CI が緑」だから巨大 diff をマージ
- review コメントにマスキングされていない本番ログを貼る
- 「問題を見つけられなかった」を「問題がない」と誤解

## 検証チェックリスト

- [ ] CI がすべて緑で、失敗の再試行履歴を理解している
- [ ] 少なくとも一人が主要ロジックの diff を読んだ
- [ ] issue/タスク説明の範囲と一致
- [ ] Secrets がリポジトリに入っていない
