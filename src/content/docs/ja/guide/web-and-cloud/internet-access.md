Cloud タスクは**外部ネットワーク**を必要とすることがよくあります：npm/PyPI パッケージの取得、API へのアクセス、サブモジュールのクローン。一方、インターネットアクセスは**データ漏洩**の高リスク面でもあり、Agent がリポジトリや Secrets の内容を外部サービスに持ち出す可能性があります。

## 内容

- Cloud 環境がデフォルトでインターネットにアクセスできるか
- いつ開放が必要か、露出を最小化する方法
- ローカルサンドボックス、Secrets ポリシーとの連携

## 基本境界

「ネットワークが必要」は「無制限にネットワークを開放すべき」ではありません。

多くの人は次の二択で考えがちです：

- 完全にネットワーク不可
- 便利のためすべて開放

より一般的なのは、タスクに必要なネットワーク能力だけを与え、余分な能力は与えないことです。

## 二層の「ネットワーク」

| 層 | 意味 |
|---|---|
| Cloud 環境の外部ネットワーク | リモートマシンがパブリックネットまたは社内 API にアクセスできるか |
| Agent ツールのネットワーク | セッション内の web search、curl など（クライアントごとにポリシーが異なる） |

本ページは **Cloud 環境** に焦点を当てます。一般的な概念は [サンドボックスとネットワーク](/guide/foundations/sandbox-and-network/) を参照。

## なぜローカルで動くからといって Cloud でも動くとは限らないか

ローカルでネットワークが使えるのは、次の理由かもしれません：

- PC で既にサービスにログイン済み
- ローカルに `.npmrc`、SSH key、プロキシ設定がある
- 会社 VPN 内にいる

Cloud はこれらの条件を自動的に引き継ぎません。「ローカルで `npm install` できる」から「Cloud でもできる」とは言えません。

## 外部ネットワークが典型的に必要なシナリオ

- 依存関係のインストール：`npm install`、`pip install`、`go mod download`
- プライベート registry の取得（[Secrets](/guide/web-and-cloud/secrets-and-variables/) が必要）
- サードパーティ API の呼び出し（決済、地図、LLM ゲートウェイなど）
- サブモジュールのクローンまたはビルドリソースのダウンロード

## 判断原則

今回のタスク完了に必須でないネットワーク操作は、先に開放しないでください。

例：

- 依存関係インストールのためのパッケージソースへのアクセスは、通常必須
- ついでに無関係なサイトへアクセスしたり、追加リソースをダウンロードするのは、通常不要

## 推奨戦略

### デフォルトは厳格化し、必要に応じて開放

1. [Cloud 環境](/guide/web-and-cloud/cloud-environments/) で現在のネットワークポリシーを確認
2. **必須ドメイン**をリスト化（パッケージマネージャー、社内 API）。「全ネット開放」を避ける
3. `AGENTS.md` に、アクセス許可 URL とプロンプトへのキー記載禁止を明記
4. テストタスクで検証：依存関係はインストールできるが、無関係サイトにはアクセスできない（製品が細粒度ポリシーをサポートする場合）

### Secrets との役割分担

| 内容 | 置き場所 |
|---|---|
| API key、token | Cloud Secrets、リポジトリに入れない |
| 許可する API ベース URL | ドキュメントまたは環境変数名（値ではない） |
| プロキシ / ミラー URL | チーム標準設定 |

## よくある誤解

### 1. ネットワークが使えるのは「少し便利」であって、セキュリティ問題ではない

ネットワークが使えると同時に、次も起きます：

- 依存関係ダウンロードの問題
- 認証情報使用の問題
- データ外部送信の問題

### 2. プロンプトに Secret を書かなければ絶対に安全

環境自体が Secret を読め、結果を外部サービスに送れるなら、リスクは残ります。

### 3. web search と Cloud の外部ネットワークは同じもの

一つはリモート環境レベルのネットワークアクセス能力、もう一つはセッションツールレベルのネットワーク能力です。混同してトラブルシューティングしないでください。

### データ漏洩対策

- 本番データベース接続文字列をタスク説明に入れない
- Agent が `.env`、キーファイルの内容を外部に送ろうとしていないかレビュー
- 信頼できないリポジトリで初めて Cloud を実行するとき、**外部ネットワーク禁止または読み取り専用サンドボックス**で試走

## ローカル開発との整合

ローカルで `curl` できても Cloud でできるとは限りません。よくある「Cloud 赤」の原因：

| 現象 | 考えられる原因 |
|---|---|
| 依存関係インストール失敗 | 外部ネットワーク禁止、または registry 認証が必要 |
| サブモジュールが取得できない | SSH key が Secrets に注入されていない |
| 社内 API タイムアウト | Cloud が会社 VPN 内にない |

解決方向：HTTPS + token に切り替え、到達可能なミラーを提供、またはドキュメントで Cloud は社内リソース非対応と明記。

## よくあるエラー

- 手間を省いて外部ネットワークを全面開放し、Secrets を含む本番リポジトリで無制限タスクを実行
- Cloud とノート PC が同じ `.npmrc` を共有していると想定（未プッシュまたは Secret 未設定）
- 「ネットワークが必要」と「web search ツールが必要」を混同
- インストール失敗まで Cloud にローカルのログイン状態がないと気づかない

## 検証チェックリスト

- [ ] このリポジトリの Cloud タスクに必須の送信先ドメイン/サービスをリスト化
- [ ] Secrets が設定済みで Git にコミットされていない
- [ ] テストブランチで完全なインストール + テストを一度通過
- [ ] チームがネットワーク付きプロンプトに置いてはいけないデータを把握している
