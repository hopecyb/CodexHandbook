# コンテキストとファイル

コンテキストとは、Codex がその瞬間に見え、参照し、それに基づいて動ける情報のことです。

頭の中では明確でも、相手に重要資料が見えていなければ方向がずれます。  
Codex も同じです。コンテキストを管理できないと、どんなに良いプロンプトでもノイズに埋もれます。

## コンテキストに含まれるもの

グループチャットに入ったばかりの同僚が頼る情報だと考えてください。

- 渡したタスク要件 = いまの問題
- 開いて見せたファイル = 背景資料
- リポジトリ内のルールドキュメント = チームの約束
- 会話履歴 = このタスクに対する記憶

これらを合わせたものが、いま依存しているコンテキストです。

## よくある問題の原因

「また誤解した」の多くは、モデルが弱いのではなくコンテキストの問題です。例えば：

- 情報が少なすぎて推測しかできない
- 情報が多すぎて要点が埋もれる
- このファイルを知っているはずだと思っていたが、明示していなかった
- 古い会話を長く続け、初期情報がもはや焦点ではない

本ページの要点は次の単純な基準です。

> **本当に関係ある情報だけを見せ、無関係な情報に場所を取らせない。**

## ファイルと成果物

「何をしてほしいか」だけでなく、「何を見せるか」もよく必要になります。

ここでの「もの」は次のようなものです。

- コードやドキュメント
- スクリーンショット
- PDF
- 表
- プレゼンテーション

ファイル種別ごとに、Codex の読み方、適した聞き方、検収の仕方が少しずつ違います。

## おすすめの読み順

一度に全部読む必要はありません。次の順がおすすめです。

1. まず [ファイルとディレクトリのコンテキスト](/guide/context/file-and-folder-context/) で「どのファイルを見せるか」を理解
2. 次に [焦点を保つ](/guide/context/keep-context-focused/) でタスクが散らばるのを防ぐ
3. 手元の資料タイプに応じて、対応するファイル章を読む

コンテキストは Codex が判断するときの手元の情報の束です。正しく渡せば、結果も正しくなりやすくなります。
