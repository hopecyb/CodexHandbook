**子 Agent（Subagent）** は、主 Agent が特定のサブ問題のために起動する**独立した作業単位**です。比較的隔離されたコンテキストを持ち、完了後に結果をメインスレッドへ集約します。

子 Agent は、明確な小さなタスクを、そのことだけに集中する助手に任せるイメージです。価値は「かっこいい」ことではなく、「クリーン・集中・並行しやすい」ことにあります。

## 中核概念

| 主 Agent | 子 Agent |
|---|---|
| 全体目標とユーザー対話を保持 | 単一サブタスクに集中 |
| コンテキストに完全な履歴 | コンテキストがクリーンで、深掘り向き |
| 結果の調整と統合 | 探索・検索・専門実装を実行 |

[並列 Agent](/guide/desktop-app/parallel-agents/) との違い：子 Agent は通常、**主 Agent が能動的に委任する**タスク単位であり、ユーザーが手動で複数ウィンドウを開くこととは異なります（製品実装は重なる場合があります。現行 UI を基準にしてください）。

## いつ分ける価値があるか

タスクが大きいから必ず分けるのではなく、次のようなときです。

- サブ問題自体が単独で深掘りが必要
- サブ問題と本線が同種の作業ではない
- 独立した結論を先に返してほしい

このとき子 Agent に分けると、メインスレッドが全体と細部を同時に抱えるより安定しやすいです。

## 向き・不向き

| 向いている | 向いていない |
|---|---|
| 大規模リポジトリで「認証モジュールが token をどう検証するか」を定向検索 | ユーザーと要件を何度も往復して詰める必要がある |
| 二つの技術案を並行調査 | サブタスクが同一ファイルの排他編集に強く依存 |
| 長時間の読み取り専用分析で主コンテキストを汚さない | 明確な成果物がない「なんとなく見る」 |

## よくある誤解

### 1. 子 Agent は多いほど良い？

分けすぎると新しいコストが出ます。

- 返ってきた結果を読む量が増える
- 子 Agent 同士の結論が食い違う
- 調整コストが利益を上回ることもある

### 2. 複雑なら必ず子 Agent？

必ずしもそうではありません。  
問題が強く結合していて、あなたとの確認が頻繁に必要なら、メインスレッドで直接進める方が省エネなこともあります。

### 3. 子 Agent に変更まで任せられる？

任せ方次第ですが、デフォルトでより安定なやり方は次です。

- 先に子 Agent に読み取り専用の分析・比較・特定だけ任せる
- メインスレッドが結論を見てから、変更に入るか決める

## 推奨ワークフロー

### 1. 主 Agent がサブタスク契約を書く

```text
サブタスク：packages/auth の session 更新ロジックを読み取り専用で分析。
成果物：1 ページ以内の要約 + 重要ファイルパス + リスク点。
禁止：ファイル変更、push しない。
```

ここで重要なのは形式より、次の四つを明確にすることです。

- 何だけを担当するか
- 成果物の形
- 許可しない動作
- 返ったあと誰が判断するか

### 2. 子 Agent が実行し、構造化結果を返す

期待フォーマット：

```text
## 結論
## 根拠（ファイル:行番号）
## 推奨する次の一手
## 未解決の問題
```

### 3. 主 Agent が統合と判断

メインスレッド（またはあなた）が採用するパスを決め、[探索—計画—実行—検証](/cases/workflows/explore-plan-execute-verify/) の実行段階へ進みます。

### 4. 検証

- 子 Agent の出力が独立して検証できるか（ファイルを開いて照合できるか）
- 権限外のリポジトリ変更をしていないか
- 複数子 Agent の結論が衝突したとき、明示されているか

## 判断の目安

サブタスクが次の三条件のうち二つを満たせば、分ける候補です。

1. 独立して説明できる
2. 明確な成果物がある
3. メインスレッドと細かいコンテキストを頻繁に共有する必要がない

## Skill・MCP との組み合わせ

- **Skill**：サブタスクの標準成果形式を定義（例：セキュリティレビュー checklist）
- **MCP**：子 Agent は外部チケットを読み取り専用で照会し、主 Agent が総合判断

## よくあるミス

- 子 Agent の範囲が大きく、第二の主 Agent になる
- 構造化返却を求めず、メインスレッドが長いログを読み直す
- 複数子 Agent が同じディレクトリを同時に変更する

子 Agent が最も向くのは「境界が明確・成果が明確・単独で完結できる」サブ問題です。メインタスク全体を複製する用途には向きません。
