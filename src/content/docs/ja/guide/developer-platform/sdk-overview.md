SDK（名称と言語は [公式ドキュメント](https://developers.openai.com/codex) を基準に）で、**自社サービス**からタスク作成、状態ポーリング、結果取得ができます。ターミナル TUI だけに頼る必要がありません。

初めて「SDK」を見ると、プログラムが Codex を呼ぶための開発ツールセットと考えてください。人がクリックする UI ではありません。「あなたのシステムが Codex を呼ぶ」向き。単発タスクなら先に SDK は不要なことが多いです。

## このページで扱うこと

- いつ SDK を使い、CLI `exec` を使わないか
- 認証とテナント分離
- Webhook、キューとの連携思路

プラットフォーム総覧：[開発者プラットフォーム](/guide/developer-platform/)

## SDK vs CLI

| | SDK | CLI `exec` |
|---|---|---|
| 統合位置 | バックエンドサービス、内部ツール | Shell、GitHub Actions |
| 状態管理 | あなたのコードが担当 | プロセス終了コード |
| 向く用途 | マルチテナント製品、カスタム UI | シンプルなパイプライン |

多くのチームは **CI は CLI、製品は SDK** です。

## よくある誤解

### 1. SDK と CLI の差は？

- **CLI**：人またはスクリプトがターミナルで呼ぶ
- **SDK**：コードで Codex 能力を自サービスに埋め込む

### 2. 先に SDK を学ぶべき？

通常は不要。Codex をまず使いたいなら、ローカル入口と CLI 対話モードが先です。

### 3. いつ SDK が価値を出す？

例：

- 自社製品から Codex タスクを起動したい
- タスク状態と結果を自分で管理したい
- カスタム UI、権限、フローを作りたい

SDK は「プログラムにシステムを接続」向き。Codex 初回入門の主入口ではありません。

## 核心概念（言語非依存）

1. **認証**：組織 API key または OAuth 委任——最小 scope に従う
2. **タスク／スレッド**：一回のユーザー要求に対応する追跡可能 ID
3. **ツール方針**：サーバー側でサンドボックスと承認を指定。クライアントと一致
4. **結果**：メッセージ履歴、ファイル diff、artifact URL（API による）
5. **エラー**：再試行可能（429）と不可（400）を区別

エラー索引：[エラーとメッセージリファレンス](/guide/reference/error-reference/)

## 最小統合チェックリスト

- [ ] staging で読み取り専用リポジトリを試走
- [ ] ログ脱敏。PII を含む完全 prompt を記録しない
- [ ] タイムアウトとキャンセル：ユーザーがページを離れたらタスク中止
- [ ] SDK とモデル ID を固定

## CI/CD との接続

SDK が Cloud やリモート runner を起動、または CI があなたのサービスにコールバックして PR 状態を更新。例パターンは [コードレビュー自動化](/guide/developer-platform/ci-cd/code-review-automation/) を参照。

## よくあるミス

- ユーザーブラウザの session cookie を API 秘密鍵として使う
- 同時実行制限なし。流量ピークでクォータ枯渇
- SDK 出力 PR を自動マージ
