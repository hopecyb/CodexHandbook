「ローカル」「クラウド」は技術用語に聞こえますが、簡単に言えばローカルは自分のコンピュータで作業し、クラウドはリモートのマシンで作業します。

まず Codex を使い始めるだけなら、通常は **ローカル** から選ぶほうが手軽です。

| | ローカルタスク | Cloud タスク |
|---|---|---|
| 実行場所 | あなたのマシン / ローカル環境 | クラウド環境 |
| 向いていること | 素早い反復、ローカルファイル、端末固有の鍵を使うデバッグ | リモートリポジトリ接続、長時間タスク、標準化された環境 |
| 注意点 | ローカル権限と誤変更のリスク | 環境設定、鍵の注入、ネットワークポリシー |

## 使い心地の違い

ざっくり次のような違いがあります。

- **ローカルタスク**：自分の PC の前に座り、Codex が現在のプロジェクトを一緒に直してくれる感じ
- **Cloud タスク**：リモートの作業マシンにタスクを渡し、そこで続けてもらう感じ

違いは「場所が違う」だけではありません。次も含まれます。

- どのファイルにアクセスできるか
- ローカルに既にあるソフトや環境をそのまま使えるか
- タスクをどれくらい長く走らせられるか
- チームで環境を統一する必要があるか

## なぜ多くの初心者はローカルから始めるか

ローカルのほうが理解しやすく、確認もしやすいからです。

- ファイルが自分の PC にあることがわかる
- プロジェクトを開き、結果を見て、手で直すのが容易
- 失敗したときの取り消し経路が明確

初めて使う人にとって、最初からクラウドに行くより、タスクの一連の流れを閉じてみるほうが重要です。

## よくある誤解

### 1. クラウドのほうが必ず上級で、本番向きとは限らない

ローカルのプロジェクトを直し、ローカルファイルを見て、何度か試すタスクなら、ローカルのほうが直接的です。

### 2. ローカルは「プロっぽくない」のでは？

多くの実際の開発作業はもともとローカルで行われます。クラウドを使うかはタスクの種類次第で、「格の高さ」で判断する必要はありません。

### 3. どう選べばいいか

次の基準で判断できます。

- **PC 上の既存プロジェクトを直す**：ローカルを選ぶ
- **タスクが長い、バックグラウンドで走らせたい、リモートリポジトリ環境につなぎたい**：クラウドを検討する

## 迷ったときの選び方

まだ区別がつかないなら、このルールで十分です。ローカルで済むなら、急いでクラウドに移らない。

次のニーズが本当に出てきたら Cloud に切り替えてください。

- タスク時間が非常に長い
- 環境を統一したい
- リモートリポジトリやリモートリソースに接続したい
- ローカルマシンを占有したくない

多くの初心者は **ローカル + デスクトップ App** から始めます。Cloud の詳細は [Web と Cloud の概要](/ja/guide/web-and-cloud/)。App 内での切り替えは [ローカルとクラウドのタスク](/ja/guide/desktop-app/local-and-cloud-tasks/) を参照してください。

ローカルは流れを理解し、小さな変更を試すのに向いています。クラウドはより長く、標準化され、リモート協業が多いタスクに向いています。
