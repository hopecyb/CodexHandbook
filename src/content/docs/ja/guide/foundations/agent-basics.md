**Agent** は目標を中心に継続して作業します。目標の理解 → ツールの選択 → 結果の観察 → 次の一手の調整、という流れを、完了するかあなたの介入が必要になるまで繰り返します。

普通の AI は質問に答える人に近く、Agent はタスクを受け取って一歩ずつ進める人に近いです。

## Agent と普通のチャットの違い

| | 普通のチャット | Agent |
|---|---|---|
| 出力 | 主に文章のアドバイス | ファイルの読み書き、コマンド実行、リポジトリの変更が可能 |
| 過程 | 一度の応答 | 複数ステップのツール呼び出し |
| リスク | 誤解を招くアドバイス | ファイルを壊したり危険なコマンドを実行したりする可能性 |
| あなたの役割 | 読む | 境界の設定、承認、受け入れ |

## 直感的なたとえ

次のように対比できます。

- **普通のチャット**：友だちに「この問題の解き方は？」と聞く
- **Agent**：同僚に一版作ってもらい、できあがったら一緒に確認する

Agent モードでは、次をより意識する必要があります。

- 何にアクセスできるか
- 先に計画を出すべきか
- 完了後にどう検収するか

## なぜこの区別が大切か

多くの誤用は、同じ誤解から生じます。

> ただ「言うだけ」だと思っている

ファイルの読み取り、変更、コマンド実行が始まると、チャット上のアドバイスではなく、実際の作業に参加していることになります。

初めて使うときは、あわせて次を読むことをおすすめします。

1. [権限と承認](/guide/foundations/permissions-and-approvals/)
2. [最初のタスクを実行する](/guide/getting-started/run-your-first-task/)
3. [結果を確認する](/guide/getting-started/review-the-result/)

## 関連概念

- Skill / Plugin / MCP：「何ができるか」「どこにつながるか」を拡張する——[拡張と自動化](/skills/) と [能力マップ](/guide/start-here/codex-capability-map/) を参照
- 人的承認：[権限と承認](/guide/foundations/permissions-and-approvals/) を参照

Agent の特徴は、目標を中心に複数のステップを連続して実行できることです。一段の返答だけではありません。
