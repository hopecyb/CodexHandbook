初めて `App / CLI / IDE / Cloud` という言葉を見ると、多くの人は「結局どれを入れればいいのか」で止まります。

最初に自分に最適な入口を選べなくても、先に進めなくなるわけではありません。まず使いやすいものから始め、あとから別のものを足せば十分です。

## シンプルな選び方

強いこだわりがなければ、次のように選べます。

- **初めて使う**：デスクトップ App
- **もともとターミナルを毎日使う**：CLI
- **主に VS Code / JetBrains でコードを書く**：IDE 拡張
- **GitHub のクラウドリポジトリ接続や長時間タスクが明確**：そのときに Cloud を検討

## 各入口とは何か

| 入口 | こう理解するとよい |
|---|---|
| デスクトップ App | グラフィカルなコンソール。タスク確認、差分確認、承認に向く |
| CLI | ターミナル内の Codex。コマンドライン派向け |
| IDE 拡張 | エディタに組み込まれたアシスタント。コードを見ながら直すのに向く |
| Cloud | リモートでタスクを走らせる方式。リポジトリ協業と長時間タスク向け |

| もしあなたが… | 選ぶもの |
|---|---|
| 初めて使い、差分とレビューをはっきり見たい | **デスクトップ App**（デフォルト推奨） |
| ターミナルに慣れており、スクリプトも書く | **CLI** |
| 主にエディタ内でコードを直す | **IDE 拡張** |
| GitHub クラウド環境 / 長時間タスクが必要 | **Cloud**（まず概要を読む） |

## よくある誤解

### 1. クライアント選びは技術的すぎるから後回しでいい

これは実務的なステップです。最初の体験がスムーズかどうかを左右します。

### 2. 一番プロっぽく見えるものを最初に使うべき

初回は「過程と結果がいちばん読みやすい入口」を選ぶ方がよく、最もハードなものを追う必要はありません。

## なぜ最初はデスクトップ App を勧めるか

初心者にとってデスクトップ App が扱いやすい理由は次のとおりです。

- 何をしたかが見えやすい
- いつ権限を求めているかが一目でわかる
- diff、タスク、プロジェクトの概念が直感的
- 問題が起きても止めて確認しやすい

ターミナルを明確に好むのでなければ、デスクトップ App の方が向いていることが多いです。

## あとから複数の入口を併用できる

四択でも、長期的な縛りでもありません。

多くの人は後から次のように使い分けます。

- 普段はデスクトップ App でタスク確認と変更レビュー
- バッチ処理が必要なときは CLI
- 主にコードを書くときは IDE 拡張

最初の選択は出発点にすぎません。

## 手間を抑えたいなら

1. まず [デスクトップ App](/guide/getting-started/install-desktop-app/) を入れる
2. [最初のタスク](/guide/getting-started/run-your-first-task/) を一度走らせる
3. 慣れてから CLI や IDE を検討する

完全な対照表は [機能対照](/guide/reference/feature-comparison/)。複数クライアントを入れても構いません。**練習プロジェクトは同じディレクトリに保つ**と、比較しやすくなります。
