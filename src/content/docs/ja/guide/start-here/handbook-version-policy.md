## 継続的な更新

このハンドブックは単一の Codex バージョンに長期間固定されません。製品は変化するため、各ページでは状態、検証日、具体的な証拠を使って何を確認したか示します。日付だけで信頼性を評価することはできません。

## 内容

- なぜこのハンドブックは永遠に変わらないと仮定できないか
- ページ冒頭の状態と検証日の読み方
- 公式と矛盾したとき、どちらを信じるべきか

## ページの状態

| 状態 | 意味 |
|---|---|
| planned | 計画済み、未執筆 |
| draft | 執筆中 |
| review | 内容完成、再確認待ち |
| verified | 記載根拠に基づき検証済み |
| outdated | 製品変更後、更新が必要 |
| archived | 歴史的保存、メインナビには含まない |

## ページ状態の読み方

- `planned`：まだ書かれていない
- `draft`：執筆中だが、まだ不安定
- `review`：本体はできたが、再確認が必要
- `verified`：記載根拠に基づき検証済み
- `outdated`：以前は正しかった可能性があるが、今は古い可能性に注意
- `archived`：参考として保持、現在のメインコンテンツではない

## 検証記録とコンテンツの更新

各ページの冒頭には、編集状態、検証方法、検証日、該当する証拠が別々に表示されます。`editorial` は編集上のレビュー、`source-checked` は出典の照合、`run-tested` は記録された環境での実例の実行を意味します。これらは互いに代替できません。過去の注記は別に残され、現在の実行テストの証拠へ自動的に格上げされることはありません。

[コンテンツの更新と訂正](/ja/guide/updates/)には、具体的な変更とその影響を記載しています。中国語本文のページ下部からは、現在のページ情報を含む GitHub 訂正用の下書きを開けます。送信前に内容を確認し、機密情報を取り除いてください。

## 公式根拠

製品の挙動は OpenAI ドキュメントが基準：[https://developers.openai.com/codex](https://developers.openai.com/codex)。このリポジトリはコミュニティガイドで、公式と矛盾する場合は公式を優先し、issue の提出を歓迎します。

## よくある誤解

### 1. ハンドブックに書いてあれば、長期間変わらない

特に次の内容は変わりやすいです。

- インストール方法
- ログインとアカウントフロー
- 権限、モデル、設定項目
- Cloud と製品入口の挙動

### 2. `review` は読んではいけないわけではない

`review` は本体コンテンツがあるが、十分な確認はまだ完了していないことを示し、参考にならないわけではありません。

### 3. コミュニティハンドブックと公式ドキュメントが矛盾したら、半分ずつ信じるわけではない

次のように分けられます。

- 理解とパスの説明はハンドブック
- 具体的な最新の挙動とパラメータの書き方は公式

## ページの信頼性の判断方法

ページが古いのではないか心配なら、次の 3 点を確認してください。

1. ページ冒頭の編集状態が `review`、`verified`、`outdated` のどれか
2. 最終検証日が現在から遠くないか
3. 概念の話か、インストール、設定、権限など変わりやすい話か

最新の挙動、パラメータ、ルールに関わることは、最終的に公式の現行ドキュメントが基準です。
