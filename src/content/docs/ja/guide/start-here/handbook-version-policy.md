## 継続的な更新

このハンドブックは単一の Codex バージョン番号に長期固定されません。製品は変わるため、ページには状態と検証日で現在の信頼度を示します。

## 内容

- なぜこのハンドブックは永遠に変わらないと仮定できないか
- 文末の状態と検証日の読み方
- 公式と矛盾したとき、どちらを信じるべきか

## ページの状態

| 状態 | 意味 |
|---|---|
| planned | 計画済み、未執筆 |
| draft | 執筆中 |
| review | 内容完成、再確認待ち |
| verified | 記載根拠に基づき検証済み |
| outdated | 製品変更後、更新が必要 |
| archived | 歴史的保存、メインナビには含まない |

## ページ状態の読み方

- `planned`：まだ書かれていない
- `draft`：執筆中だが、まだ不安定
- `review`：本体はできたが、再確認が必要
- `verified`：記載根拠に基づき検証済み
- `outdated`：以前は正しかった可能性があるが、今は古い可能性に注意
- `archived`：参考として保持、現在のメインコンテンツではない

## 文末の 3 行

MVP 段階では各ページ文末に **状態 / 対象製品 / 最終検証** を記載。変わりやすい内容（インストール、アカウント、権限、モデル）には公式リンクを付ける。

## 公式根拠

製品の挙動は OpenAI ドキュメントが基準：[https://developers.openai.com/codex](https://developers.openai.com/codex)。このリポジトリはコミュニティガイドで、公式と矛盾する場合は公式を優先し、issue の提出を歓迎します。

## よくある誤解

### 1. ハンドブックに書いてあれば、長期間変わらない

特に次の内容は変わりやすいです。

- インストール方法
- ログインとアカウントフロー
- 権限、モデル、設定項目
- Cloud と製品入口の挙動

### 2. `review` は読んではいけないわけではない

`review` は本体コンテンツがあるが、最強の確認レベルには達していないことを示し、参考にならないわけではありません。

### 3. コミュニティハンドブックと公式ドキュメントが矛盾したら、半分ずつ信じるわけではない

次のように分けられます。

- 理解とパスの説明はハンドブック
- 具体的な最新の挙動とパラメータの書き方は公式

## ページの信頼性の判断方法

ページが古いのではないか心配なら、次の 3 点を確認してください。

1. 文末の状態が `review`、`verified`、`outdated` か
2. 最終検証日が現在から遠くないか
3. 概念の話か、インストール、設定、権限など変わりやすい話か

最新の挙動、パラメータ、ルールに関わることは、最終的に公式の現行ドキュメントが基準です。
