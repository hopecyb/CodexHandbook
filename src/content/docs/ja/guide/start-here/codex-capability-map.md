ハンドブックのモジュールは多く、初見では散らかって見えがちです。このページでは主要な能力を 1 枚の図にまとめ、構造を素早く把握できるようにします。

よくあるつまずきは主に 2 つです。

- あちこち読んでも、結局どこから補えばよいかわからない
- いきなり MCP、自動化、拡張に入り、基礎が整理されていない

大枠を先に整理すると、具体的なトピックを後から調べるのが楽になります。

Codex はチャットボックスだけではありません。背後にはいくつかの能力層があります。

```text
目標とプロンプト
  → コンテキスト（プロジェクト / ファイル / 会話）
    → ツール（ファイル、ターミナル、検索、ブラウザ…）
      → Agent 作業（計画、実行、ガイド、引き継ぎ）
        → 品質検証と人的承認
      → 拡張と自動化（Skills / MCP / Hooks…、上級）
            → チームガバナンス（今後のマイルストーン）
```

## 全体構造

Codex を 3 層と見なせます。

- 第 1 層：どう伝えて、何をしてほしいかを知らせるか
- 第 2 層：どのコンテキストとツールで実現するか
- 第 3 層：この協業方式をどう蓄積し、後から再利用するか

使い始めでは、前 2 層がより重要です。タスクを明確にし、結果をスムーズに出してから、高度な拡張を見てください。

## よくある誤解

### 能力が高度だから、先に学ぶべきとは限らない

Skills、MCP、Hooks、自動化は確かに強力ですが、解決するのは主に効率の拡大とスケールでの再利用であり、初めて使うときに最もつまずきやすい部分ではありません。

プロンプト、コンテキスト、ツール選択といった基本動作が整理されていないと、後の拡張能力も使い方を誤りやすくなります。

### この図は読む順序の参考にもなる

サイトの目次を 1 ページずつ読む必要はありません。次の順序で進められます。

1. まず Codex の動き方を理解する
2. 次にタスクの伝え方、コンテキストの与え方、結果の検証方法を学ぶ
3. 慣れてから、設定、拡張、自動化を検討する
