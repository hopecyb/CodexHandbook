このハンドブックは、Codex を本格的に使い始める人向けに書かれています。

次のことを前提としません。

- ターミナル
- Git
- Agent
- プロンプトエンジニアリング
- クラウド環境

すでに慣れている人は読み進めやすいです。まだ不慣れでも、本文はできるだけ追いやすく書いています。

## 4 種類の読者

| 読者 | このハンドブックの使い方 |
|---|---|
| AI 初心者 | 「とは何か」から最初の安全なタスクまで。用語には説明付き |
| クリエイター | リサーチ、ライティング、プレゼン、プロトタイプ。概要を読んでから能力トピックへ |
| 開発者 | コード理解、実装、テスト、レビュー、自動化 |
| チーム | 共有の説明、権限、品質、ガバナンス（詳細は今後のマイルストーン） |

## 4 種類に厳密に分ける必要はない

多くの人は実際に 2〜3 種類にまたがります。例えば：

- 少しコードは書けるが、Agent を本格的に使い始めたばかり
- もともとコンテンツクリエイターだが、サイト修正も Codex に任せ始めた
- チームリーダーが個人として先に試用する

したがって、この 4 分類は排他的な身分ではなく、**利用シーン** に近いです。

## 主な対象読者

本文は主に **ターミナルと Agent に不慣れな読者** 向けです。開発者とチーム向けの内容も浅くはしませんが、学習パスに沿って段階的に展開します。

## よくある誤解

### 1. このハンドブックはプログラマーだけ向けではない

仕事に次のような内容があるなら、このハンドブックも向いています。

- ライティングとコンテンツ整理
- リサーチと情報比較
- ドキュメント保守
- プロトタイプとページ修正
- チームフローの整理

### 2. ある程度の基礎があっても、最初の数ページは読む価値がある

「始める前」「基礎概念」「最初のタスク」は、ゼロからの道筋だけでなく、次の点を素早く合わせるのにも役立ちます。

- Codex は実際にどう動くか
- タスクはどう伝えるべきか
- どのリスクを事前に避けるべきか

### 3. 最初から最後まで読む必要はない

多くの人は次のように読みます。

1. スタートページを読む
2. 最初の小さなタスクを通す
3. 自分の役割に応じて飛び読みする

## ハンドブックを何にしないか

- 単一製品の完全な公式 changelog
- 検証なしで本番に出せるスクリプトリポジトリ
- 組織内部のセキュリティとコンプライアンスポリシーの代替

## 向いている人

次のニーズがあるなら、このハンドブックは見る価値があります。

- Codex を安全に使い始めたい
- ある程度使えるが、タスクの伝え方が不安定
- 個人の使い方をチームで再利用できるフローに整理したい
- 開発出身ではないが、AI を日常業務に本当に接続したい
