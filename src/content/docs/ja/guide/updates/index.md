## ページの問題を見つけた場合

中国語の各記事の下部には「このページの問題を報告（GitHub 下書き）」というリンクがあります。ページの題名、サイト内のパス、記録済みの検証日を含む未送信の Issue 下書きを開きます。内容を確認してから自分で送信してください。GitHub アカウントが必要です。

該当箇所、期待と実際の違い、必要な環境、公開された根拠を記してください。共有するのは伏せた情報だけにし、API キー、アカウント、私的なディレクトリ、顧客データ、完全な生ログを貼らないでください。下書きはタスクの記録を自動収集せず、ページのクエリパラメータも含みません。

GitHub アカウントがない場合は、ページのパスと問題の説明をローカルに保存し、権限のある協力者に送信を依頼できます。対応期限は約束されず、メッセージが自動送信されることもありません。

## メンテナーの対応

問題を再現するか出典を確認したら、受け入れ、修正、まだ確認できない理由を記録します。製品の事実を変更した場合は関連証拠を更新し、無関係なページの検証日を一括更新しません。演習を変えたら元資料、ダウンロードパッケージ、本文をそろえます。以前の結論が無効になった場合は、単に「内容を改善した」とするのではなく、旧方法の影響と移行手順を説明してください。

このページを更新するときは具体的なページと検証記録をリンクし、未テストの範囲を残します。これはコミュニティのハンドブックの変更履歴であり、OpenAI の公式リリースノートではありません。
