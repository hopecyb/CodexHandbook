「脅威モデル」は先にリスクを考えることです：

> **Codex がコード、コマンド、外部ツールに本当に接続したら、最も起きやすいことは何か？**

**脅威モデル**はそれを分解して見える化します。Codex は「もう一つのチャット」ではなく、**コード読取、コマンド実行、外部ツール呼び出し**ができます。本章は主要リスク面を先に広げ、具体制御は [権限マトリクス](/guide/reference/permission-matrix/) と [サンドボックス](/guide/foundations/sandbox-and-network/) を参照。

## 内容

- 資産と信頼境界
- 典型脅威と緩和方向
- ルール、Hooks、CI との分担

## なぜ「セキュリティ担当だけの話」ではないか

開発、プラットフォーム、文書、プロジェクト責任者にも直結します。チームでよく壊れるのは：

- 過大権限 token を自動化に渡す
- 信頼できない入力で Agent に高リスク動作させる
- どのデータが見え、どれが持ち出されるか不明
- 拡張導入で機能だけ見て権限と出所を見ない

脅威モデルの価値は、事故前に境界を考え抜くことです。

## 資産と境界

| 資産 | 例 |
|---|---|
| ソースコードと IP | 私有リポジトリ、未公開設計 |
| 資格情報 | API key、`.env`、クラウド IAM |
| ユーザーデータ | PII、顧客チケット内容 |
| インフラ | CI、本番デプロイパイプライン |

**信頼境界：** モデルと拡張はデフォルトで**完全信頼できない側**。人の review と方針が境界で enforcement します。

## 二つの核心問い

チーム級接続前に：

1. 最も失いたくないものは何か？
2. Codex に最も誤ってほしくない動作は何か？

前者が「重要資産」、後者が「危険動作」。多くの制御はこの二問りに包まれます。

## 一つのシーン

- Codex が私有リポジトリを読める
- 権限付きチケットシステムにアクセスできる
- shell コマンドを実行できる
- 結果をコメント欄に返せる

注目すべきは：

- 見えてはいけないものを見るか
- やってはいけない動作をするか
- 内部に留めるべき情報を外に持ち出すか

このレベルで問うと、脅威モデルは本番前リスクチェック表に近づきます。

## 脅威概要

| 脅威 | 説明 | 緩和方向 |
|---|---|---|
| Prompt 注入 | 悪意 issue/ウェブが越権操作を誘導 | 入力消毒、読み取り専用 CI、[注入トピック](/guide/team-enterprise/security/prompt-injection/) |
| 過大権限 | token、サンドボックスが広すぎ | 最小権限、ブランチ保護 |
| データ漏洩 | コマンド/MCP でリポジトリ内容を外部送信 | ネットワーク方針、DLP、監査 Hook |
| 悪意拡張 | 未審査 Plugin/MCP | [拡張リスク](/guide/team-enterprise/security/plugin-and-mcp-risk/) |
| サプライチェーン | 依存とスクリプトへの混入 | 既存 SCA、code review と組み合わせ |
| 誤操作 | Agent が DB 削除、誤 push | コマンド deny、push なし CI |

## 脅威モデルに優先投入すべき能力

次を両方満たすなら優先：

- 重要資産に触れる
- 実動作を実行できる

例：私有リポジトリ読取、本番 API アクセス、書き込み権限 MCP、コード自動 push。

## 初回着地で全部やらない

一度に文書、プロセス、方針を全部揃えようとすると、何も着地しません。

初回チームは次で十分なことが多いです：

1. 最重要3類の資産を列挙
2. Agent に最も誤ってほしくない3類の動作を列挙
3. この6つにそれぞれ最も直接的な制御を一つ付ける

例：

- 本番 DB 漏洩が怖い → 本番資格情報とエクスポートパスを制限
- 誤 push が怖い → ブランチ保護と承認
- issue/ウェブに引っ張られるが怖い → 外部入力と読み取り専用 review を厳格化

完璧ではないが、誰も実行しない大文書より有用なことが多いです。

## 推奨層別制御

```text
L1 身份とテナント（SSO、グループ）
L2 組織マネージド設定とモデル方針
L3 リポジトリ rules + AGENTS.md
L4 サンドボックス / 承認 / Hooks
L5 人の review とブランチ保護
```

## よくあるミス

- 研修だけで技術制御なし
- 「モデルは賢いから大丈夫」
- 本番秘密鍵が Agent 書き込み可能パスに存在
- すべてのリスクを「人が review すれば」に圧縮

## 最小版

まずこの三つ：

- 高リスク動作は承認必須
- 高機密データはデフォルト非提供
- 自動化フローはデフォルト読み取り専用

これで多くのチーム級リスクはかなり抑えられます。細化ガバナンスは後からでも構いません。
