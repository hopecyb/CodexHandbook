チャットの要約は Codex による作業の説明であり、Git の差分がファイルに実際に起きた変更です。デスクトップ App のレビューパネルでは、差分の表示、行単位のコメント追加、stage、取り消し、commit、push する内容の決定ができます。

完全なレビューパネルと `/review` を使うには、プロジェクトが Git リポジトリ内にある必要があります。

## 二段階のレビュー

最初に自分で変更範囲を確認し、次に独立した reviewer で実装上の問題を探します。

1. レビューパネルを開き、最初にファイル数とパスを確認する。
2. **Last turn** を選択し、今回のターンで何が変更されたかを確認する。
3. **Unstaged**、**Staged**、**Commit**、**Branch** を切り替え、レビュー範囲を確認する。
4. 入力欄で `/review` を実行する。
5. 基準ブランチとの比較、未コミット変更、指定した commit、カスタム基準のいずれかを選ぶ。
6. 優先度順の指摘を読み、修正するかを判断する。

`/review` の reviewer はデフォルトで読み取り専用であり、worktree を変更しません。その後、Codex に指摘の修正を依頼する場合も、元のサンドボックスと承認ルールが適用されます。

## 再利用可能なレビュー基準

```text
現在の未コミット変更をレビューし、次を重点的に確認してください。
- タスク範囲を超えていないか
- 動作の回帰、境界条件、セキュリティ問題がないか
- テストが失敗経路をカバーしているか
- 文書と実装が一致しているか

最初に問題を列挙し、重大度順に並べてください。各項目にファイル、位置、証拠、最小限の修正案を含めてください。
問題がない場合は明示し、まだカバーされていないテストリスクを列挙してください。
```

## 行単位のコメントで曖昧さを減らす

疑わしい行にカーソルを合わせ、表示される **+** を選んで具体的なフィードバックを書きます。すべてのコメントを書いた後、次のような明確な指示を送ります。

```text
私が残した行単位のコメントを処理してください。変更範囲を最小限に保ち、完了後に関連テストを再実行して新しい diff を表示してください。
```

有用なコメントは、「空の配列の場合、ここは何を返すか」のようにリスクまたは検収条件を示します。「ここが違う」だけでは通常不十分です。

## stage と取り消し

レビューパネルでは、差分全体、ファイル単位、hunk 単位で stage、unstage、取り消しができます。取り消すと変更が失われます。操作前に、タスク開始前から存在したユーザーの変更ではないことを必ず確認してください。

検収順序は、範囲、動作、テスト、セキュリティ、保守性に固定することを推奨します。詳しくは[差分をレビューする](/ja/guide/quality/review-diffs/)を参照してください。
