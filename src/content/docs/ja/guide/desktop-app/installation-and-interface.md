この章は、ChatGPT デスクトップ App を初めて開く読者向けです。すべてのボタンを覚えることではなく、**レビュー可能で検証可能な小さなタスク**を完了することが目標です。

インストールとログインの手順は[デスクトップ App をインストールする](/ja/guide/getting-started/install-desktop-app/)を参照してください。現在の公式版は macOS、Windows、Linux で提供されています。ログイン後、新しいチャットやプロジェクトを作成するか、ローカルフォルダを開けます。

## 最初に三つの対象を理解する

| 対象 | 用途 | 初心者が最初にすること |
|---|---|---|
| プロジェクトまたはフォルダ | チャットへファイルと作業ディレクトリを提供する | 本番ディレクトリではなく練習用リポジトリを開く |
| チャット | 目標、コンテキスト、進捗、結果を保存する | 一つの明確な目標に一つのチャットを使う |
| Codex | プロジェクトの内容を読み、変更し、検証する | 低リスクで簡単に確認できる小さな変更から始める |

App の画面は今後も更新されますが、この三つの対象は特定のボタン位置より安定しています。

## 最初の実タスクを完了する

既存の Git リポジトリを準備し、記録されていない必要な変更がないことを先に確認します。次に App でそのフォルダを開き、新しい Codex チャットを作成します。

入力例：

```text
最初に README.md を読み、「ローカル実行」の節だけを変更してください。
1. 無効になっている起動コマンドを修正する。
2. そのほかの節は変更しない。
3. 変更後に diff を表示し、文書にある実行可能な検証コマンドを実行する。
4. 検証できない場合は理由を明示し、完了したと主張しない。
```

完了後はチャットの要約だけでなく、次も確認してください。

1. レビューパネルに想定したファイルだけが表示されているか。
2. 削除された内容が妥当か。
3. ターミナル出力が「検証に合格した」という結論を実際に裏付けているか。
4. `git diff` がタスク範囲と一致しているか。

## Chat、Work、Codex の選び方

- 知識について質問する、またはアイデアを議論するだけ：Chat を使う
- 複数のファイルやツールをまたぐ一般的な作業：Work を使う
- リポジトリを理解、変更、テストする：Codex を使う

長期的なコンテキストが不要な一時的な質問には Quick chat を使えます。継続して追跡する作業は、通常のチャットまたはプロジェクトに残してください。

## 失敗したときに最初に確認すること

- **ファイルが見えない**：正しいフォルダを開いており、タスクの権限が拒否されていないか確認する
- **コマンドを実行できない**：依存関係がインストール済みか確認し、ターミナルにある最初の実際のエラーを見る
- **変更に以前の内容が混ざる**：`git status` でタスク前の変更と今回の変更を区別する
- **App の画面が本文と違う**：「プロジェクト / フォルダ、チャット、レビュー、ターミナル」という論理的な対象から探し、スクリーンショットの固定位置に依存しない

次は[差分、コメント、レビュー](/ja/guide/desktop-app/diffs-comments-and-review/)と[統合ターミナル](/ja/guide/desktop-app/integrated-terminal/)を学んでください。
