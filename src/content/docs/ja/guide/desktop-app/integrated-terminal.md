ChatGPT デスクトップ App の各チャットには、現在のプロジェクトまたは worktree をスコープとするターミナルがあります。単にログを見る場所ではなく、Codex の結論を確認するための証拠ウィンドウでもあります。

App の右上にあるターミナルアイコンから開くか、`Ctrl` とバッククォートキーを同時に押します。ChatGPT は現在のターミナル出力を読み取れるため、失敗したビルドや実行中の開発サーバーを分析するよう依頼することもできます。

## 最小の検証フロー

JavaScript プロジェクトでは、次の順序で実行できます。

```bash
git status --short
pnpm test
pnpm run lint
```

コマンドはプロジェクトごとに異なるため、先に `README.md`、`package.json`、プロジェクトルールを確認してください。確認済みのコマンドをプロンプトに記述します。

```text
変更後に pnpm test と pnpm run lint を実行してください。
各コマンドの終了状態を報告し、どれか一つでも失敗した場合はタスクが完了したと主張しないでください。
```

検収時には少なくとも、実行した内容、正常終了したか、失敗した最初の有効なエラー、実行しなかったチェックを記録します。

## 長時間プロセスの扱い

開発サーバーは継続して実行されますが、それはコマンドが停止したことを意味しません。起動後に次を確認してください。

- 出力にローカルアドレスが表示されているか
- ブラウザでページを開けるか
- その後、ターミナルに実行時エラーが出ていないか

停止が必要になった時点で中断信号を送ります。新しい出力が一時的にないからといって、複数のサーバーを繰り返し起動しないでください。

## 再利用可能な Action

同じコマンドを頻繁に実行する場合は、ローカル環境に Action を定義できます。デスクトップ App のショートカット操作として表示され、統合ターミナルで実行されます。`test`、`lint`、`build` などの低リスクな検証をまとめるのに適していますが、本番リリースやデータベース削除を隠す用途には適しません。

## セキュリティ境界

- 本番の Secret をチャットやターミナル履歴へ貼り付けない
- 理解できないコマンドは、実行前に目的、影響範囲、ロールバック方法を説明させる
- 本番環境で削除、migration、リリースのコマンドを無条件に再実行しない
- ターミナルで実行できることは、そのコマンドが業務上承認済みであることを意味しない

公式文書で一般的なコマンドとして示されるものには、`git status`、`git pull --rebase`、テスト、lint があります。最終的なコマンドは各プロジェクトの文書を基準にしてください。
