互換性は、具体的なバージョンの組み合わせについて判断する必要があります。パッケージ構造が正しいこと、画像サイズが適切なこと、画面が開くことだけでは、アニメーションの状態や無効化後の復旧まで正常に動くとは証明できません。

## 現在ある証拠

2026-09-18 に、ローカルアプリの `Info.plist` を読み取り専用で確認しました。クライアント識別子は `com.openai.codex`、バージョンは `26.911.61220`、ビルドは `9647` でした。この確認ではペットやテーマを読み込まず、クライアントの設定も変更していません。**インストール、再生、切り替え、復旧のテストを完了したバージョンの組み合わせは、現時点ではありません。**

[ペットのインストール](/ja/pets/install/)、[ペットの作成](/ja/pets/create/)、[テーマ](/ja/theme/)の手順は、対象リソースとクライアントのバージョンを確かめて使ってください。第三者のプロジェクトによる主張は出典を明示し、当サイトの実測として扱わないでください。

## コピーして使える記録テンプレート

```text
記録の種類：ペット / テーマ
状態：未実施 / 実施中 / 合格 / 失敗 / 結果未確認
テスト日：
テスト担当者：
OS とアーキテクチャ：
クライアントのバージョンとビルド：
リソースまたはツールの名前とバージョン：
元の出典 URL と対応する tag/commit：
ダウンロードしたファイル名と SHA-256：
素材の作者とライセンス：
インストール前の状態とバックアップ先（公開前に伏せる）：
実際に行ったインストール手順：
読み込みと画面の証拠：
アニメーションまたは操作の確認：
無効化の手順と結果：
復旧の手順と結果：
再起動後の再確認：
失敗ログと未解決事項：
未テストの環境、状態、機能：
```

未実施の項目は空欄にするか「未実施」と記します。所要時間を 0 としたり、合格や推測したバージョンを書いたりしないでください。公開する記録には伏せたパスとテスト用の画面を使い、実際のタスク内容を含めないでください。

## ペットの確認

最初に JSON とリソースのパスを検証します。続いてクライアントで選択、読み込み、背景の透過、動作の切り替え、ウィンドウのサイズ変更を確認します。アトラスにバージョン欄がある場合は、行と列の仕様に一致しているか確かめてください。画像が開けるだけでは、クライアントが正しいフォーマットのバージョンとして解釈したことにはなりません。

無効化するときは、まず組み込みリソースに戻すかペットをオフにします。カスタムパッケージをスキャン対象ディレクトリの外にあるバックアップ先へ移し、再読み込みまたは再起動後に表示されないことを確認します。復旧するときは同じパッケージを戻し、読み込めるか確認します。スキャン対象内で名前を変えるだけでは不十分です。設定ディレクトリ全体を削除しないでください。

## テーマの確認

有効化の前後で同じ画面の見た目と操作を記録します。少なくともホーム、タスク、入力欄、検索、エラーメッセージ、アクセスできる承認画面を確認します。表示できない画面は未テストと記し、ボタンの確認だけを目的に実際の高リスク操作を行わないでください。

復旧後は通常のクライアントを開き直し、見た目と操作が正常で、テーマが自動再起動または再注入されないことを確認します。画面の復旧とデバッグ接続の終了は別々に確かめてください。どちらかを確認できなければ未解決として記録を残します。

## 再検証が必要なとき

クライアント、OS、テーマエンジン、ペットの形式、またはリソースパッケージが変わったら、同じ手順で再検証します。古い記録は残し、新しいバージョンの組み合わせを追加してください。検証日だけを書き換えてはいけません。失敗した場合は既知の正常な設定に戻してから、新たな変更点を個別に調べます。
