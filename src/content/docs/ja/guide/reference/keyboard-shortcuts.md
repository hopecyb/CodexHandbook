ショートカットは**クライアントとバージョン**で大きく異なります。本ページは**操作意図**で分類し、より速い方法があるか判断する助けにします。具体キー配列は製品内ヘルプまたは設定で確認してください。

ショートカットを一度に全部覚える必要はありません。操作リズムを最も妨げる数個を慣れさせれば十分有用です。

:::caution
下表は**示意**。完全バインディング表ではありません。更新後キーが変わる可能性があります。
:::

## 一般意図索引

| 意図 | デスクトップ App（示意） | CLI TUI（示意） | IDE 拡張（示意） |
|---|---|---|---|
| 新規タスク/セッション | `Cmd/Ctrl+N` またはサイドバー | 終了して再入 / 新スレッドコマンド | コマンドパレット「Codex」 |
| メッセージ送信 | `Enter` / `Cmd+Enter` | 製品説明に従う | パネル内送信 |
| 改行のみ（送信しない） | `Shift+Enter` | TUI 依存 | パネル依存 |
| コマンドパレット | `Cmd/Ctrl+K` 類 | `/` スラッシュコマンド | `Cmd/Ctrl+Shift+P` |
| 履歴検索 | サイドバー検索 | セッション内検索（あれば） | チャット履歴 |
| ツール呼び出し承認 | パネルボタン | `y` / 方向キー（TUI 依存） | 通知またはインラインボタン |
| 拒否 | パネルボタン | `n` | インライン拒否 |

**インストールしたバージョンの UI を基準にしてください。**

## 先に慣れるべき動作

ショートカットの価値は次の卡顿を減らすことです：

- 送信したいのにボタンを探す
- 改行したいのに誤送信
- 承認操作で慌てる
- 新タスクの入口が分からない

全套暗記より、次の4類を先に：

- 送信 / 改行
- 新規タスク
- コマンドパレット
- 承認 / 拒否

## スラッシュコマンド vs キーボード

- **スラッシュコマンド**：`/review`、`/help` 等——[スラッシュコマンド早見](/guide/reference/slash-commands/)
- **ショートカット**：文字入力なしで UI 動作を直接起動

組み合わせ可：先に `Cmd+K` で入力にフォーカスし、次に `/review`。

## CLI ターミナルユーザー

- **Ctrl+C** で暴走出力を中断（未保存状態の中断に注意）
- ターミナルマルチプレクサ（tmux）で分割：片方 Codex、片方 `git diff`
- 常用 `codex exec` を shell エイリアスに——[コマンドとショートカット](/guide/cli/commands-and-shortcuts/)

## よくある誤解

### 1. ショートカットを覚えてから使い始める必要はない

最も頻出する動作を数個慣れさせるコストは低いです。

### 2. 他人が熟練＝自分が遅い

ショートカットは慣れによる筋肉記憶。入門の壁ではありません。

### 3. 全クライアントでキーを無理に統一する必要はない

重要なのは：

- その動作にショートカットがあるか
- どこで確認・変更するか
- どの動作を優先的にバインドするか

## 最初に慣れる動作

1. 送信方法
2. 改行のみ（送信しない）
3. コマンドパレット
4. 承認または拒否
5. 新規タスク

この5つが順れば、残りは使いながら補えます。

## IDE ユーザー

- 「Codex で選択コードを説明」を手慣れのキーに
- エディタ原生 diff、定義ジャンプと組み合わせ、コピペを減らす

[IDE 設定](/guide/ide/settings/) · [選択コードとファイルを開く](/guide/ide/selected-code-and-open-files/)

## アクセシビリティとカスタマイズ

多くのクライアントは設定でキー変更可能。チームは**推奨バインディング**を文書化しても、全員一致は要求しない。

ショートカットは試験範囲ではありません。最も操作を妨げる数個を慣れさせれば通常十分です。
