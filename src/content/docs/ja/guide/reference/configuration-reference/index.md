「設定項目リファレンス」はキー、層、上書き関係で圧倒されがちです。先に一問：

> **どの挙動を設定で変え、設定で解決すべきでないか？**

設定ファイルは **モデル、サンドボックス、承認、MCP** などの挙動統一によく使われます。本ページは**概念索引**。具体ファイルパス、TOML/YAML キー名は [OpenAI Codex ドキュメント](https://developers.openai.com/codex) とインストールバージョンを基準にしてください。

## 一つの判断原則

設定には「**長期に挙動へ影響させたい**」ものを置き、次は向きません：

- 秘密値
- チームルール全文
- 一時的なタスク説明

三つに分けると分かりやすい：

- **長期挙動好み** → 一般に設定
- **具体タスク要求** → prompt / `AGENTS.md` / Skill
- **秘密値** → 環境変数または Secret

迷ったら：Codex の長期習慣を変えているか、今回タスクを指示しているか。

- 長期習慣 → 設定
- 現在タスク → prompt、`AGENTS.md`、タスク説明

## 設定の層

| 層 | 位置（概念） | 典型内容 |
|---|---|---|
| ユーザー級 | `~/.codex/` 等 | デフォルトモデル、個人承認習慣 |
| プロジェクト級 | リポジトリ内設定ファイル | チームサンドボックス、MCP リスト |
| 環境変数 | Shell / CI 注入 | 秘密鍵、一時スイッチ |
| マネージド | 組織配布 | 上書き不可の強制方針 |

## 各層が管理すること

- **ユーザー級**：自分のデフォルト習慣
- **プロジェクト級**：このリポジトリで共有したいデフォルト挙動
- **環境変数**：実行時に一時投入する値
- **マネージド方針**：組織が固定。ローカル変更不可

初見では「誰が必ず誰を上書きするか」を暗記する必要はありません。各層が何を管るかを先に知る：

- ユーザー級：「個人として普段こう使いたい」
- プロジェクト級：「このリポジトリでは皆こう使いたい」
- 環境変数：「今回実行だけ渡す値」
- マネージド方針：「組織がすでに決めた境界」

入門：[設定の基礎](/guide/customization/configuration/config-basics/) · ターミナル寄り：[CLI 設定](/guide/cli/configuration/)

## 設定ドメイン索引（概念）

### モデルと推論

| 意図 | 説明 |
|---|---|
| デフォルトモデル | 新セッションで使うモデル ID |
| 推論強度 / reasoning | 複雑タスク段階（サポート時） |
| 温度等サンプリング | 一般はデフォルト維持。スクリプト化時は固定 |

背景：[モデルと推論](/guide/foundations/models-and-reasoning/)

### サンドボックスとネットワーク

| 意図 | 説明 |
|---|---|
| ファイルシステム範囲 | 書き込み可能パス、プロジェクト外書き込み可否 |
| ネットワークアクセス | 禁止 / 制限 / 許可 |
| 外向きドメイン | 許可リスト（サポート時） |

背景：[サンドボックスとネットワーク](/guide/foundations/sandbox-and-network/)

### 承認方針

| 意図 | 説明 |
|---|---|
| shell 実行前 | 常に確認 / 信頼リスト / 自動（高リスク） |
| ファイル書き込み前 | 同上 |
| MCP ツール呼び出し | サーバーまたはツール粒度 |

背景：[権限と承認](/guide/foundations/permissions-and-approvals/) · マトリクス：[権限マトリクス](/guide/reference/permission-matrix/)

### ワークスペースと CLI

| 意図 | 説明 |
|---|---|
| デフォルト `cwd` | 起動ディレクトリ |
| 非対話デフォルト | exec の承認とサンドボックス |
| ログレベル | 障害時に上げる |

### MCP サーバー

| 意図 | 説明 |
|---|---|
| サーバーリスト | コマンド、URL、転送方式 |
| 環境変数注入 | MCP プロセスにバインド。Git へ入れない |

[MCP 接続](/skills/mcp/connect-an-mcp-server/)

### IDE / App 拡張

一部項目は拡張設定 UI にのみ存在し、CLI と同一ユーザー設定バックエンドを共有する場合あり——製品説明を基準に。

[IDE 設定](/guide/ide/settings/) · [デスクトップ App 設定](/guide/desktop-app/settings/)

## よくある誤解

### 1. 設定できるものすべてを設定ファイルに入れるべきではない

`AGENTS.md`、環境変数、Skill、現在タスク説明が適切な場合もあります。設定は万能容器ではありません。

### 2. すべての設定キーを最初から理解する必要はない

多くの人が最初に触る四類：

- モデル
- サンドボックス
- 承認
- MCP

入門段階の疑問の大半をカバーします。

### 3. プロジェクト級設定＝チーム文書の完全代替？

設定は「システム挙動のデフォルト」向き。「なぜそうするか、いつしないか」の説明代替ではありません。

### 4. 公式設定キーが多くても一度に全部学ぶ必要はない

最初に多い四類：

- デフォルトモデル
- サンドボックス範囲
- 承認方針
- MCP 接続

これらを理解すれば入門疑問の多くをカバーできます。

## 環境変数との関係

| 種類 | 置き場所 |
|---|---|
| API key、token | 環境変数または Secret マネージャ |
| 非秘密スイッチ | 環境変数または設定 |
| コーディング規範 | `AGENTS.md`。config ではない |

## 設定に入れるべきかの判断

1. 長期デフォルトとして効かせたいか？
2. 秘密情報か？
3. 個人好みか、プロジェクト共有ルールか？
4. システム挙動を調整しているか、今回タスクを指示しているか？

この四問で、設定、環境変数、`AGENTS.md`、Skill、現在 prompt への配置が大体判断できます。

## 挙動調整時の判断

1. 長期デフォルトか、今回タスクの一時要求か？
2. 秘密値か、普通の設定か？
3. 個人好みか、プロジェクト共有ルールか？

設定ファイル、環境変数、`AGENTS.md`、Skill、現在 prompt へ分かれます。

## よくあるシーン

| やりたいこと | 一般に置く場所 |
|---|---|
| モデルを長期固定 | ユーザー級またはプロジェクト級設定 |
| チーム要求：コード変更前にテスト | `AGENTS.md` |
| 今回タスクは `docs/` だけ | 現在 prompt |
| API key / token | 環境変数または Secret |
| ある MCP サービス接続 | プロジェクト設定 + 環境変数 |

設定キー一覧を見続けるより、こう見ると整理しやすいです。

Cloud Secrets：[Secrets と環境変数](/guide/web-and-cloud/secrets-and-variables/)

## 変更規律

1. 一度に一類だけ変更し、一週間観察
2. プロジェクト級変更は PR review
3. CLI 更新後に公式 migration 説明を diff
4. 秘密鍵を設定ファイルに書いて Git コミットしない

設定は長期デフォルト挙動向き。秘密値やタスク説明、チームルール全文の置き場ではありません。

## よくあるミス

- 文書のキー名が旧 CLI と不一致
- 個人本機でサンドボックス緩和し、顧客リポジトリで使用
- `AGENTS.md` 指示と矛盾（設定は許可、文書は禁止）
