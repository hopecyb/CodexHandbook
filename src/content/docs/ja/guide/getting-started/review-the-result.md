タスク完了後、このステップを飛ばす初心者が多いです。

Codex をより安定して使うには、**結果を確認する** 能力が必要です。

「完了しました」という言葉だけでなく、実際に何を変更したか、結果が求めているものかを見てください。

## 確認チェックリスト

1. **差分を見る**：許可したファイルだけを変更したか？
2. **成果物を開く**：内容は検証基準に合っているか？
3. **修正を追う**：少し足りないだけなら、精密なフィードバックを続ける
4. **決める**：承認 / 手動修正 / [取り消し](/ja/guide/getting-started/undo-and-recover/)

さらに詳しい方法：[差分のレビュー](/ja/guide/quality/review-diffs/)。

## よく見落とす点

### 1. 要約だけ見て、実際の変更を見ない

Codex は要約をうまく書くことがありますが、本当に重要なのは次です。

- 正しいファイルを変更したか
- 承可していない場所をついでに変更していないか
- 結果が本当に検証条件を満たしているか

### 2. 「だいたい合っている」からそのまま承認

「だいたい」は後で小さな問題を残しやすいです。  
少し足りないだけなら、黙って妥協するより精密なフィードバックを追加した方がよいです。

### 3. 間違っているのに、どう伝えればよいかわからない

次のような文で続けられます。

```text
結果は近いですが、2 点問題があります：1）…… 2）…… この 2 点だけ修正してください。他は変更しないでください。
```

## 確認順序

初回練習では、次の順序で確認できます。

1. **範囲を見る**：どのファイルを変更したか
2. **結果を見る**：ページ、ドキュメント、コード出力が要件に合っているか
3. **副作用を見る**：余分な変更や新しいエラーが入っていないか

検証時に確認するのは、今回の結果を安心して受け取れるかどうかです。
