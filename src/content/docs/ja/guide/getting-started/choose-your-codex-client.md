初めて `App / CLI / IDE / Cloud` という言葉を見たとき、よくある疑問は「結局どれを使うべきか」です。

初回選択は重く考えすぎなくて大丈夫です。使いやすい入口から始め、後から他を補えば十分です。

## すぐに選ぶ

今、強いこだわりがなければ、次のように選べます。

- **初めて使う**：デスクトップ App
- **普段からターミナルを使う**：CLI
- **主に VS Code / JetBrains でコードを書く**：IDE 拡張
- **GitHub クラウドリポジトリ接続や長期タスクが明確**：Cloud を確認

## 各入口とは

| 入口 | こう理解できる |
|---|---|
| デスクトップ App | グラフィカルなコンソール。タスク、差分、承認のクリックに向く |
| CLI | ターミナル内の Codex。コマンドラインユーザー向け |
| IDE 拡張 | エディタに埋め込まれたアシスタント。コードを見ながら変更する向き |
| Cloud | リモートでタスクを実行する方式。リポジトリ協業と長期タスク向け |

## 状況別の選択

| もしあなたが… | 選ぶ |
|---|---|
| 初めて使い、差分とレビューをはっきり見たい | **デスクトップ App** |
| ターミナルに慣れ、スクリプトを書く | **CLI** |
| 主にエディタ内でコードを変更する | **IDE 拡張** |
| GitHub クラウド環境 / 長期タスクを使う | **Cloud**（先に概要を読む） |

## デスクトップ App が初心者に向く理由

初心者にとって、デスクトップ App には明らかな利点があります。

- 何をしたか見やすい
- いつ権限を申請するかが一目瞭然
- diff、タスク、プロジェクトの概念が直感的
- 間違えたときも止めて確認しやすい

ターミナルへの明確なこだわりがなければ、デスクトップ App の方が楽なことが多いです。

## よくある誤解

### 1. 4 つの入口はまったく別製品

同じ能力セットを使い、違いは主に操作方式と適したシーンです。

### 2. 初回に正しく選ばないと、後で大変

初回選択は起点であり、生涯の決定ではありません。

### 3. 将来も 1 つの入口に固定する必要がある

多くの人は後から次のように組み合わせます。

- 普段はデスクトップ App でタスクと変更レビュー
- 一括操作が必要なときは CLI
- 主にコードを書くときは IDE 拡張

## 開始順序

1. まず [デスクトップ App](/guide/getting-started/install-desktop-app/) をインストール
2. [最初のタスク](/guide/getting-started/run-your-first-task/) を 1 回通す
3. 慣れたら CLI や IDE を検討

完全な対照：[機能対照](/guide/reference/feature-comparison/)。複数クライアントをインストールしてもよい。**練習プロジェクトは同じディレクトリを維持**し、体験を比較しやすくする。

初回は「どれがよりプロか」を急いで比較する必要はありません。プロセスと結果が最も見やすい入口を選べば十分です。
