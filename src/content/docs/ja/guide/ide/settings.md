IDE 拡張の設定は**個人の好み**と**プロジェクトルール**をつなぎます。どのモデルか、承認をどれだけ厳しくするか、開いているファイルを自動で含めるかなど。全体の [設定の基礎](/guide/customization/configuration/config-basics/) と整合し、本ページはエディター内のよく触る項目に焦点を当てます。

## 本ページの内容

- IDE 設定 vs ユーザー設定 vs `AGENTS.md` の役割分担
- 開発者がよく調整する項目
- チームでのデフォルト値の統一

## これらの設定が担うこと

IDE 設定は、**Codex がエディター内でどう協業するかのデフォルト習慣**に近いです。

次のような問題を扱います。

- デフォルトのモデル
- デフォルトの承認の厳しさ
- 現在のファイルや選択範囲を自動で含めるか

プロジェクトルールそのものは定義せず、エディターでの使い心地と安定性を決めます。

## 設定の階層（復習）

| 階層 | 例 | 優先度 |
|---|---|---|
| 組織の管理ポリシー | サンドボックス緩和の禁止 | 最高 |
| プロジェクト `AGENTS.md` / プロジェクト設定 | テストコマンド、ディレクトリ規約 | 高 |
| IDE 拡張設定 UI | デフォルトモデル、パネルレイアウト | 中 |
| 単発タスクのプロンプト | 「今回はネットワーク不要」 | タスク単位 |

[スコープと優先順位](/guide/customization/agents-md/scope-and-precedence/) を参照。

## よくある誤解

### IDE 設定はプロジェクト規約ではない

「エディターのデフォルト設定」＝「このプロジェクトのやり方」と混同しがちです。

より明確な分け方：

- エディター設定は個人の使い心地寄り
- `AGENTS.md` とプロジェクト設定はチーム合意寄り

関連はありますが、同じものではありません。

### コンテキストを自動で含めるほど多いとは限らない

現在のファイル、選択範囲、開いているタブを自動で含めるのは便利ですが、入れすぎるとタスクの焦点がぼやけます。

実用的な基準は「足りればよい」であり、「多く開くほど強い」ではありません。

## よく変える設定（概念）

### モデルと推論

応答速度と複雑タスクの品質に影響します。チームプロジェクトでは README に「推奨モデル段階」を書き、人ごとのデフォルト差で再現が難しくなるのを防げます。

### 承認とサンドボックス

[権限と承認](/guide/foundations/permissions-and-approvals/) に対応：

- 初心者：デフォルトまたはより厳しく
- 信頼済みリポジトリ：慎重に緩和し、本番 secrets ディレクトリと混在させない

CLI と IDE は**同じセキュリティ基準**を使うべきです。CLI は [CLI 設定](/guide/cli/configuration/) を参照。

### コンテキストの挙動

一部の拡張では次を設定できます。

- 現在のファイル / 選択範囲を自動で含めるか
- `AGENTS.md` を読むか
- コンテキストウィンドウ関連（バージョンによる）

自動コンテキストを増やしすぎるとノイズが増えます。[コンテキストを絞る](/guide/context/keep-context-focused/) を参照。

### ログインとアカウント

[ログインと認証](/guide/getting-started/sign-in-and-authentication/) と共通。アカウント変更後は拡張セッションを再起動してください。

## チームでの統一

1. **必ず揃える**項目はリポジトリに書く（`AGENTS.md` + 任意のプロジェクト設定）
2. **個人の習慣**は IDE 設定に留め、Git に書かない
3. 新メンバーのオンボーディング：[IDE インストール](/guide/ide/installation/) で拡張バージョンを確認

## 初回に見る設定

IDE 拡張を初めて設定するときは、次の 3 類だけ見れば十分です。

1. モデルと推論段階
2. 承認 / セキュリティ関連
3. 自動コンテキスト関連

この 3 類を整えれば、実運用の多くの問題はカバーできます。

## トラブルシューティング

| 現象 | 確認 |
|---|---|
| 設定が効かない | 組織ポリシーで上書きされていないか。ウィンドウ再読み込みが必要か |
| CLI と挙動が違う | [設定リファレンス](/guide/reference/configuration-reference/) と比較 |
| 拡張が応答しない | [IDE トラブルシューティング](/guide/ide/troubleshooting/) |

IDE 設定は「エディター内で Codex とどう協業するか」に近く、プロジェクトルールの書き方は別レイヤーです。混同しないでください。
