## 前提条件

通知は各項目の点検を通過し、facts.md と private-note.md は元のままで、records に自分の点検記録が保存されている。

## 復元を一度練習する

1. `work` フォルダー全体を新しい `backup-final` フォルダーへコピーし、3 つのファイルがそろっていることを確認する。
2. さらに新しい `recovery-drill` フォルダーへコピーする。この演習用コピーでだけ notice.md を「復元演習用の誤った版」に変更する。実際の work は変更しない。
3. 演習用ファイルを開いて実際に変更されていることを確認し、backup-final にある正しい notice.md を上書きコピーする。
4. recovery-drill の 3 つのファイルをバックアップと一つずつ比較し、内容が一致することを確認する。work が変わっていないことも確認する。

ファイルマネージャーとエディターだけで操作できる。対象のパスが演習用コピーであることを先に確かめる。同名のフォルダーが既にある場合は別の名前を選び、他の内容を上書きしない。復元結果を確認できなかった場合は、記録に「未確認」と残す。

## 引き継げる成果物を保存する

`templates/handoff.md` を records にコピーする。実際の内容に基づいて、クライアントのバージョン、最終ファイル、根拠、点検の証拠、未解決の申込方法、復元結果を記入する。今回使ったタスクの指示も保存し、次回は資料を差し替えられるようにする。

提出物には、完成した notice.md、元の facts.md、自分で作った review.md と handoff.md、再利用できるタスク指示を含める。これらは学習用ファイルであり、実際の公開を許可するものではない。

## 完了の判断基準

通知は事実に基づき、不明なことを作り上げていない。変更範囲は正しく、誤りのある例を見つけ、復元演習を実際に行って記録し、引き継ぎから第三者が根拠と未解決事項をたどれる。「3 つのタスクが成功した」と書くだけでは完了の証拠にならない。
