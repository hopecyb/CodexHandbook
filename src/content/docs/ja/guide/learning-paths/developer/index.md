主に Codex でコードを変更し、プロジェクトを理解し、問題を修正したい場合は、このパスから始められます。

## 向いている状況

- コードを読み、変更し、テストを実行する必要がある人
- Codex を実際の開発ワークフローに接続したい人
- 「タスクを書く、diff を見る、検証を実行する」フローを身につけたい人

## よくある誤解

### 1. 開発者パスはまずコードを書かせること

結果の品質により影響するのは、しばしば次の点です。

- 範囲を理解しているか
- 完了基準を定義しているか
- 最後に diff と検証結果を丁寧に見たか

### 2. コードを書けるので基礎概念は飛ばせる

完全に飛ばすのはおすすめしません。

Codex の動作は通常のエディタの自動補完とは異なります。権限、コンテキスト、ツール呼び出しといった概念は結果に直接影響します。

## 推奨読書順序

開発に Codex を使う準備ができている場合は、次の順序で読めます。

1. [クイックスタート](/guide/getting-started/)
2. [CLI](/guide/cli/) または [IDE](/guide/ide/)
3. [Agent ワーク](/guide/agent-work/)
4. [テストの実行](/guide/quality/run-tests/)
5. [差分のレビュー](/guide/quality/review-diffs/)

このパスは、変更を制御可能にし結果を検証可能にすることを重視し、「まず書かせる」ことだけを追求しません。

## 計画中のステップ（概要）

コードベースの理解 → 修正と実装 → テストとレビュー → 自動化ワークフロー → マルチ Agent 開発
