「ツール選択」とは、ある作業をどの方法で進めるか——効果的かつ安全に——を決めることです。

ツールを選ぶときは、タスクの種類で判断するのが通常はっきりします。

## ツール選択で見ること

ツールを選ぶとき、主に次の点を確認します。

- どれが現在のタスクに最も近いか
- どれが最小のコストで結果を得られるか
- どれがリスクが最も低く、確認しやすいか

同じ目標でも、ツールを間違えると必ず失敗するわけではありませんが、遅くなったり、遠回りになったり、予期しない問題が起きやすくなります。

| 必要なこと | 優先 |
|---|---|
| リポジトリ内のファイルを変更 | ファイルツール |
| テスト / ビルドを実行 | ターミナル |
| 公開されている事実を調べる | Web 検索 |
| 実際のページ状態を確認 | ブラウザ（上級） |

プロンプトに許可・禁止するツールを明記し、勝手に外部へ出たり、依存関係を乱に入れたりするのを防ぎましょう。

## 迷ったときの選び方

判断に迷ったら、次の順序で考えてみてください。

1. これはローカルプロジェクトの処理か、外部の事実を調べる作業か
2. 「動作を実行」する必要があるか、それとも「結果を見る」だけでよいか
3. どのツールが最小範囲でこのステップを完了できるか

たとえば：

- コードの変更を確認したい → ファイル
- ビルドが通るか確認したい → ターミナル
- ページが今どう見えるか確認したい → ブラウザ
- 最新の公開情報を確認したい → Web 検索

## よくある誤解

### 1. ツールは強いほど良いわけではない

強力なツールほど、通常は次のことも意味します。

- 影響範囲が広い
- リスクが高い
- 何をしているかを理解する必要がある

### 2. ターミナルで何でもできるからといって、必ずしもターミナル優先ではない

ページの見た目を確認したいだけなら、ブラウザのほうが通常は直接的です。  
公開されているバージョン番号を調べたいだけなら、あちこちでコマンドを実行させるより Web 検索のほうが適切です。

### 3. 選べないときはどうする？

次のルールで判断できます。

- **プロジェクト内容の読み書き** → ファイル
- **コマンドやビルドの検証** → ターミナル
- **公開事実の調査** → 検索
- **ページの実際の表示を確認** → ブラウザ

### 4. 1 つのタスクでツールは 1 つとは限らない

実際のタスクでは、次のように組み合わせて使うことがよくあります。

- まずファイルを読み、次にビルドを実行
- まず公開事実を検索し、その後ドキュメントを書き直す
- まずブラウザでページを確認し、その後コードを修正

重要なのは、各ステップでより適切なツールを使うことであり、「1 つだけ選ばなければならない」とこだわる必要はありません。

## そのまま使える書き方

タスクに次の一文を足せます。

```text
優先してファイルとターミナルで完了し、ネットワーク検索はしない。ブラウザでページを確認する必要がある場合は、先に理由を説明すること。
```

最初から影響範囲が最大のツールを使うのではなく、最小でタスクに最も近いツールを選びましょう。
