**ブラウザツール**は、Agent が制御された環境で実際の Web ページにアクセスできるようにします。DOM の読み取り、スクリーンショット、場合によっては簡単な操作も可能です。フロントエンドの検証、ドキュメントリンクの確認、デザイン稿との照合に向いています。セキュリティ監査の代替には向かず、本番管理画面を無造作に操作する用途にも向きません。

検索とは別カテゴリのツールです。検索は Web 上の情報を探すため、ブラウザツールは Web ページを実際に開くためのものです。

## 向いている問題

このツールは、次のような問題によく使われます。

- このページは今、実際にどう見えるのか
- このボタンを押すと何が起きるのか
- このレイアウトは実際の幅で崩れていないか

コードを読むだけ、または文字の説明だけでは足りない問題です。ページを実際に開く必要があります。

## 本ページの内容

- ブラウザツールでできること、できないこと
- Web 検索、Computer Use との違い
- 安全に承認と制約を設定する方法

## 能力の概要

| 向いている | 向いていない |
|---|---|
| ローカル dev server のページを開いてレイアウトを確認 | ToS で制限されたサイトの一括クロール |
| 公開ドキュメントリンクの 404 を確認 | 未承認システムへの自動ログイン |
| 静的ページと実装の照合 | 完全な E2E テストフレームワークの代替 |
| ページの可視テキストを読み取ってデバッグを補助 | 複雑な CAPTCHA が必要なサイトの処理 |

選定の背景：[ツール選択](/guide/tools/tool-selection/)

## 他ツールとの比較

| ツール | 入力 | 出力 |
|---|---|---|
| Web 検索 | クエリ | 要約とリンク |
| ブラウザ | URL / ローカルアドレス | ページ構造、スクリーンショット、操作結果 |
| Computer Use | 画面全体の GUI | 任意のアプリ操作（より重く、よりセンシティブ） |

## よくある誤解

### 1. ブラウザツールは自動テストの代替ではない

ページの確認、スクリーンショット、一部の操作のクリックは助けになりますが、完全なテスト体系の代替にはなりません。

### 2. ページが開けたからといって、問題がないわけではない

開けることは「ページが存在する」ことだけを意味します。レイアウト、文言、操作、リンクが正しいかは、引き続き確認が必要です。

### 3. どんな場面で使うべきか？

よくあるシナリオは次のとおりです。

- ローカルページにレイアウトの問題がないか確認
- リンクが 404 になっていないか確認
- ページとデザイン稿の大まかな一致を確認
- 「コードは正しそうだが、実際のページも正しいか」を確認

## 判断基準

次のような問いであれば、ブラウザツールは純テキスト分析より適していることが多いです。

- 「実際にレンダリングするとどう見えるか」
- 「ページ上で実際に何が見えているか」
- 「この操作のあと、ページのフィードバックは何か」

## 推奨ワークフロー

1. **ローカルフロントエンド**：まず `npm run dev` を実行し、`http://localhost:PORT/path` を渡す
2. **タスクを明確に**：「ログインフォームが 375px 幅で溢れていないか確認」——「Web ページを見て」ではなく
3. **境界を書く**：外部ネットワークへのアクセス禁止、本番へのフォーム送信禁止
4. **検証**：[成果物の検証](/guide/quality/verify-artifacts/) とスクリーンショットを照合

## そのまま使える書き方

次のように依頼できます。

```text
http://localhost:4321/guide/foundations/local-vs-cloud/ のみにアクセスし、ファーストビューのレイアウトと見出し画像の印象を確認してください。
外部ネットワークにはアクセスせず、フォームは一切送信しないこと。
問題があれば、スクリーンショットの根拠と修正提案を出してください。
```

## 安全境界

- デフォルトでは、ブラウザは**あなたのマシンまたは環境からアクセスできるすべて**——社内 admin を含む——に到達できると想定する
- タスクで `localhost のみ` または許可ドメインのホワイトリストを宣言する
- 個人アカウントでログイン済みのブラウザプロファイルで、信頼できないリポジトリのタスクを実行しない
- Cloud 環境のブラウザポリシーは [Cloud 環境](/guide/web-and-cloud/cloud-environments/) とネットワークポリシーで決まる

承認の概念：[権限と承認](/guide/foundations/permissions-and-approvals/)

## よくあるミス

- 本番 URL を渡し、読み取り専用の制限を設けない
- ブラウザのスクリーンショットを「テスト合格」とみなし、自動テストを実行しない
- Web 検索と混同する——検索は実際のレンダリング確認の代替にならない

## 検証チェックリスト

- [ ] アクセス範囲をプロンプトに固定した
- [ ] 重要な視覚的問題にスクリーンショットまたは文字説明がある
- [ ] ユニット / E2E テストの結論と一致しているか、既知の差異を記録した
