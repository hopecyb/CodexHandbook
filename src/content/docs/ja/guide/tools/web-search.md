Web 検索は事実を補うのに向いていますが、最終結論を代わりに下す用途には向きません。

向いているのは、公開ドキュメント、エラーコード、バージョン説明の調査です。向いていないのは、検索結果を最終的な法律・医療の結論として扱うことです。

出典の添付を求め、原文を自分で開いて確認してください。[出典の検証](/guide/quality/validate-sources/) と併用しましょう。

## 検索が向いていること

検索は主に次のものを見つけるのに役立ちます。

- どこを見ればよいか
- どの情報をさらに確認する価値があるか
- より権威ある出典があるか

役割は資料を先に見つけることであり、その後は原文に戻って確認します。

## よくある誤解

### 1. 結果が見つかったから、答えが信頼できる？

そうは見なせません。見つかったことと信頼できることは別です。要約がスムーズでも、正確とは限りません。

### 2. どんな場面で検索が向いている？

よくあるシナリオは次のとおりです。

- 公式ドキュメントの確認
- エラーメッセージの調査
- バージョン変更の確認
- 公開 Web ページ上の事実の確認

### 3. 検索結果の要約をそのまま引用してよい？

まずは引用しないでください。次の手順で扱えます。

1. 検索結果にどんな出典があるかを確認する
2. 原ページを開く
3. 自分の言葉で要約する

### 4. 検索だけに頼ってはいけないのはいつ？

次のような場合です。

- 高リスクな法律・医療・財務の判断
- 実際のページ動作を確認する必要がある
- 公開 Web ではなくプロジェクトのローカルファイルを確認する必要がある

このときは、他のツールや人手による検証も必要です。

## 検索の順序

次の順序で進められます。

1. まず問題に最も近いキーワードで検索する
2. 公式ドキュメントや一次情報を優先する
3. 原文を開いて詳細を確認する
4. そのうえで結論を結果に書き込むかどうかを決める

## そのまま使えるプロンプト

次の一文を足せます。

```text
まず検索し、公式出典を優先すること。結論を出すときはクリック可能な出典リンクを添付し、検索要約だけを渡さないこと。
```

検索は手がかりと出典を与えます。最後は必ず原文に戻って確認しましょう。
