Codex は一部のシナリオで**画像生成**能力を呼び出せます。イラスト、アイコンの草稿、UI コンセプト図、説明図などです。生成結果は**検証待ちの成果物**として扱い、そのまま公開できるブランド資産とは見なさないでください。

視覚的な草稿を先に出す用途に向き、最終成果物としてそのまま使う用途には向きません。

## 本ページの内容

- Codex 内で画像を生成するか、専門ツールを使うか
- 画像プロンプトと制約の書き方
- 著作権、ブランド、ファイル管理

## 適用シナリオ

| 向いている | 向いていない |
|---|---|
| ブログ記事用の挿絵草稿、内部ドキュメントの説明図 | 厳格なブランドガイドラインに縛られた対外資料 |
| UI レイアウトの雰囲気を素早く探索 | ピクセル単位の再現が必要なデザイン納品 |
| チュートリアル用のサンプルアイコン | 未承認の実在人物の肖像を含むシーン |

[画像プロンプト](/prompts/prompting-with-images/) と補完関係にあります。あちらは画像の**入力**、本ページは画像の**出力**を扱います。

## 画像生成が向いていること

画像生成は、次のような用途に向いています。

- 方向性を素早く出す
- 視覚コンセプトを確認する
- 記事、ドキュメント、プロトタイプに使える草稿を先に用意する

次の用途には、生成結果をそのまま使うのは向きません。

- 正式なブランド資料のふりをする
- 精密なデザイン稿のふりをする
- そのまま対外公開できる最終ビジュアルのふりをする

## 推奨ワークフロー

1. 用途、サイズ比率、スタイルのキーワードを説明する（侵害の恐れのあるスタイル名の羅列は避ける）
2. 出力形式（PNG / SVG がサポートされる場合）と保存パスを指定する
3. 生成後に [成果物の検証](/guide/quality/verify-artifacts/)：ファイルを開き、解像度と可読性を確認する
4. 対外公開前にデザインまたは法務でレビューする

## よくある誤解

### 1. 見た目が良ければ、その画像は使える？

次も確認してください。

- 用途に合っているか
- 不自然なディテールがないか
- 文字化けや乱れた文字がないか
- コンテンツのトーンとスタイルが合っているか

### 2. 「画像を 1 枚生成して」だけで十分？

多くの場合、不十分です。  
少なくとも次を伝える必要があります。

- 用途
- 横長、縦長、正方形のどれか
- スタイルの方向性
- 文字を入れるかどうか
- ファイル形式

### 3. 画像生成はデザイナーの代替になる？

次に近い位置づけです。

- 初期探索ツール
- コンテンツ用挿絵ツール
- コンセプト草稿ツール

厳密なデザイン納品の代替ではありません。

## どう書くか

次の構造で依頼できます。

1. この画像の用途
2. 横長、縦長、正方形のどれが必要か
3. 望む雰囲気と配色
4. 文字を入れるかどうか
5. 出力後にどう検証するか

## ファイルとリポジトリ

- 大きな画像は `assets/` または CDN に置き、Git のサイズを評価する
- PR で生成プロンプトとモデルバージョンを記載する（内部監査用）
- [画像とスクリーンショット](/guide/files-and-artifacts/images-and-screenshots/) を参照

## 安全とコンプライアンス

- 機密標識、偽造証明書、他人の肖像を含む誤解を招くコンテンツを生成しない
- 企業ポリシーで特定の題材が禁止されている場合がある。[Acceptable Use](https://openai.com/policies/) と社内規定に従う

## よくあるミス

- 未圧縮の 4K 画像をそのままリポジトリにコミット
- 生成画像を実写や公式ロゴのふりをする
- プロンプトで「文字なし」を指定せず、文字化けした字幕が出る

画像生成は方向性と草稿を先に出す用途に向いています。対外納品では、正式な成果物基準で検証が必要です。
