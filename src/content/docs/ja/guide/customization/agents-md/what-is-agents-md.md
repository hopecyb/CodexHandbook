`AGENTS.md` はリポジトリ（またはサブディレクトリ）に置く **Markdown プロジェクト指示**です。Codex がそのプロジェクトに入ると読み、コーディングスタイル、テスト要求、コミット規範、禁止事項を揃えます。

「このプロジェクトで Codex にどう協力してほしいか」の説明書と考えてください。

高度なアーキテクチャ文書でも、新人向け完全マニュアルでもなく、Codex 向けのプロジェクト協業ルールです。

## 一つの核心概念

**新入社員向けハンドブックの濃縮版**と見なしてください。「このリポジトリでどう働くか」だけを書き、会社の歴史は書かない。

| AGENTS.md に向く | 向かない |
|---|---|
| テスト、lint、ビルドの実行方法 | 完全 API 文書（正式文書へリンク） |
| ディレクトリ約束、命名スタイル | 数千行の過去設計決定 |
| 禁止事項（`main` を変えない、秘密鍵をコミットしない） | 毎回違う一時要求 |
| コミットメッセージ、PR チェックリスト | コードと無関係な個人好み |

## 最小実用例

リポジトリルートに `AGENTS.md` を作成：

```md
# プロジェクト指示

## ビルドとテスト
- インストール：`pnpm install`
- テスト：`pnpm test`（ロジック変更後は必須）
- 型チェック：`pnpm typecheck`

## コードスタイル
- TypeScript 厳格モードを使用
- 新コンポーネントは `src/components/`、ファイル名は PascalCase

## 禁止
- 依存変更以外で `pnpm-lock.yaml` を変更しない
- `.env` や API 秘密鍵をコミットしない
- 確認なしに `git push` を実行しない

## 完了の定義
- 関連テストが通る
- 新規 lint エラーなし
- PR 説明に検証手順を記載
```

保存後、新タスクでは**今回の差分**だけ書けばよい：「Safari でのログインページレイアウトを修正。AGENTS.md の受け入れ基準に従う。」

## よくある誤解

### 1. 毎回手動でルールを言い直す必要がある？

通常は不要。`AGENTS.md` の意味の一つは、**安定したプロジェクトルール**を入れ、新タスクごとの繰り返しを避けることです。

### 2. 書いたら Codex が100%従う？

`AGENTS.md` は重要ですが、次と一緒に働きます。

- 今回タスクの明示要求
- 製品の権限と承認
- サンドボックス、ネットワーク、チーム方針

正確には「整合を助ける」もので、万能の強制装置ではありません。

### 3. プログラマーでなくても関係ある？

基本概念は知る価値があります。コードを書かなくても Codex にプロジェクトを継続処理させるなら、`AGENTS.md` が繰り返し説明と逸脱を減らします。

## 置き場所

| 位置 | スコープ |
|---|---|
| リポジトリルート `AGENTS.md` | プロジェクト全体のデフォルト |
| サブディレクトリ `AGENTS.md` | そのディレクトリと子パス（monorepo で一般的） |
| ユーザーレベル説明 | 個人設定やグローバル好み。プロジェクト指示と混ぜない |

スコープと衝突処理は [スコープと優先順位](/ja/guide/customization/agents-md/scope-and-precedence/) を参照。

## Skill、スラッシュコマンドとの違い

| 仕組み | 本質 | 典型用途 |
|---|---|---|
| AGENTS.md | 永続・受動的なプロジェクトルール | スタイル、テスト、禁止事項 |
| Skill | 再利用可能なワークフローパック（`SKILL.md`） | リリースチェックリスト、専門レビュー手順 |
| スラッシュコマンド | あなたが能動的に起動するショートカット | `/review`、単発ワークフロー |

プロジェクトルールは `AGENTS.md`。**反復可能で共有可能な一連の手順**は [Skill](/ja/skills/overview/) が向きます。

## どこに書くかの判断

迷ったら：

- **長期に成立するルール** → `AGENTS.md`
- **今回タスクだけの特別要求** → 現在タスクの prompt
- **何度でも使える手順** → Skill を検討

例：

- 「このリポジトリは `pnpm test` で検証」→ `AGENTS.md`
- 「今回はログインページだけ。登録ページは触らない」→ 現在タスク
- 「毎回リリース前に同じチェック」→ Skill

## よくあるミス

- ファイルが長く、モデルが前半しか読まない——**ハード制約は先頭30行に**
- 「常に自動 push」など高リスク指示を書き、[権限と承認](/ja/guide/foundations/permissions-and-approvals/) と衝突
- チームが保守せず、文書と実スクリプトが不一致

## セキュリティ境界

`AGENTS.md` は**サンドボックスと承認の代替ではない**。「自由にコマンド実行可」と書いても製品は確認を要求する場合があり、チームマネージド方針がさらに厳しくすることもあります。

`AGENTS.md` は Codex に「このプロジェクトでは普段どう動くか」を伝えるもの。今回具体的に何をするかの代替ではありません。
