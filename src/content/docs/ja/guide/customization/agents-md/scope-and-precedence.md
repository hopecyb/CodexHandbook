複数の `AGENTS.md`、設定ファイル、現在の会話が同時にあるとき、**どのルールが効くか**を明確にする必要があります。

二つのルールが違って見えるとき、結局誰の言うことを聞くか、という話です。

## 優先順位の概要

```text
マネージド組織方針 > より近いディレクトリの AGENTS.md > リポジトリルート AGENTS.md > ユーザー設定 > 現在の会話
```

「nearer」は**現在の作業パスにより近い**サブディレクトリのファイルを指します。例：`packages/web/AGENTS.md` で作業するとき、そのファイルとルートはマージされ、衝突時は**サブディレクトリが優先**します。

## 「近いほど優先」の理解

- ルートルールは「全リポジトリのデフォルト法」
- サブディレクトリルールは「その局所の特別説明」

作業位置に近いルールほど具体的で、優先されるべきです。

## 会話 prompt との関係

| ソース | 永続性 | 向く内容 |
|---|---|---|
| AGENTS.md | セッション横断、バージョン管理可 | チーム合意、ビルドコマンド、禁止事項 |
| タスク prompt | 本会話のみ | 今回の目標、範囲、期限 |
| @ ファイル参照 | 本会話のコンテキスト強化 | 具体実装ファイル、デザイン |

会話で `AGENTS.md` 全文を繰り返し貼らない。強調が必要なら一文で参照：「AGENTS.md のテスト要求に従う。今回は追加で `legacy/` を変更しない。」

## Monorepo パターン

```text
repo/
├── AGENTS.md              # 全リポジトリ共通：パッケージマネージャ、CI、セキュリティ
├── apps/
│   └── web/
│       └── AGENTS.md      # フロント：コンポーネントライブラリ、E2E コマンド
└── packages/
    └── api/
        └── AGENTS.md      # バックエンド：DB マイグレーション約束
```

原則：

- **ルートファイル**：全リポジトリ共有の10〜20のハードルール
- **サブパッケージファイル**：そのパッケージ固有のコマンドとディレクトリ説明
- 三ファイルが80%重複しない——重複はルートへ、サブパッケージは差分だけ

## 個人好みとの境界

個人の習慣（テーマ、デフォルトモデル、本機パス）は**ユーザー設定**へ。チームリポジトリの `AGENTS.md` に書かない。協業者を誤って傷つけます。

## よくある誤解

### 1. 会話が最新なので優先度も最高

会話は「今回の追加要求」向き。チーム・組織のハードルールを安易に上書きするものではありません。

### 2. サブディレクトリ `AGENTS.md` はルートのコピー

そうすべきではありません。

- ルートに共通事項
- サブディレクトリに差分と例外

### 3. 順序だけ覚えれば足りる

足りません。どの情報をどの層に置くか、衝突時になぜその層が勝つかを知ることが重要です。

## 衝突時の判断

1. どちらが現在の作業ディレクトリに近いか
2. どちらが長期プロジェクトルールで、どちらが一時補足か
3. 上位の組織・マネージド方針で直接制限されているか

ルール衝突時は、通常「より近く、より硬く、より明確」な層を優先。「最新の一言」が必ず勝つとは限りません。

## よくあるミス

- サブディレクトリとルートが矛盾し、どちらが勝つか不明
- 機密鍵を `AGENTS.md` に書いて Git コミット——秘密管理と環境変数を使う
- 会話の「一時的な緩和」がチームマネージド方針を上書きできると期待（通常は不可能）

## 受け入れチェックリスト

- [ ] ルート `AGENTS.md` とサブパッケージファイルの分担が明確
- [ ] 衝突ルールで「サブディレクトリ優先」を意識できる
- [ ] タスク prompt は差分だけ。プロジェクトマニュアル全文をコピーしない
