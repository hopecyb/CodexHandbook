「対話モード」とは、ターミナルで Codex と会話を交わし、Codex が説明や実行を進め、必要に応じてユーザーの確認を待つ使い方です。

これも CLI の代表的な使い方のひとつです。

対話セッションを開始したら：

1. プロジェクトディレクトリで起動する（またはドキュメント指定の作業ディレクトリを使う）
2. App と同品質のプロンプトを入力する
3. 確認が表示されたらツール呼び出しを承認 / 拒否する
4. `/` 系ショートカット（ある場合）でセッション管理——現行 CLI のヘルプを正とする

プロンプトの考え方は引き続き有効：[プロンプト](/ja/prompts/)

## 対話モードに向くタスク

対話モードは、作業を進めながら判断する必要がある場合に適しています。

| タスクの状態 | 対話が役立つ理由 |
|---|---|
| 要件がまだ固まっていない | 途中で明確にできる |
| 次の手順を決める前に diff を見たい | 段階的に承認したり、範囲を絞ったりできる |
| プロジェクトで初めて手順を試す | 何を読み、何を変えたか確認しやすい |
| 権限、外部ツール、ファイル書き込みが関係する | 重要な地点で人が判断できる |

やり取りによる判断が不要なほどタスクが安定したら、[非対話モード](/ja/guide/cli/non-interactive-mode/)や自動化を検討します。

## よくある誤解

### 1. ターミナルならプロンプトは適当でいい？

いいえ。

入口がターミナルになっても、タスク記述の品質は同じくらい重要です。  
目標、範囲、完了基準は、はっきりしているほど安定します。

### 2. なぜ「プロジェクトディレクトリで起動」を強調するのか

CLI は、どのプロジェクトで働いているかを知る必要があるからです。  
ディレクトリが違うと、次のような問題が起きやすくなります。

- 見るべきファイルが見えない
- 誤ったディレクトリを変更する
- プロジェクトルールを読めない

### 3. ターミナルで承認を求められるのはエラー？

多くの場合、権限境界どおりに動いているサインであり、異常実行ではありません。

## 初回に試す簡単なシナリオ

初回は次のような小さなタスクから始めてください。

- プロジェクトルートで起動
- 1 ファイルだけ変更
- 完了後に何を変えたか説明させる

CLI 対話モードは、ターミナルで会話型タスクフローを走らせるものです。ディレクトリとプロンプトの両方が正しいことが重要です。
