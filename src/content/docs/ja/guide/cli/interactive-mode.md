「対話モード」とは、ターミナルで Codex と往復しながら説明・実行し、必要なら承認を待つ使い方です。

これも CLI の代表的な使い方のひとつです。

対話セッションを開始したら：

1. プロジェクトディレクトリで起動する（またはドキュメント指定の作業ディレクトリを使う）
2. App と同品質のプロンプトを入力する
3. プロンプト時にツール呼び出しを承認 / 拒否する
4. `/` 系ショートカット（ある場合）でセッション管理——現行 CLI のヘルプを正とする

プロンプトの考え方は引き続き有効：[プロンプト](/ja/prompts/)

## よくある誤解

### 1. ターミナルならプロンプトは適当でいい？

いいえ。

入口がターミナルになっても、タスク記述の品質は同じくらい重要です。  
目標、範囲、完了基準は、はっきりしているほど安定します。

### 2. なぜ「プロジェクトディレクトリで起動」を強調するのか

CLI は、どのプロジェクトで働いているかを知る必要があるからです。  
ディレクトリが違うと、次のような問題が起きやすくなります。

- 見るべきファイルが見えない
- 誤ったディレクトリを変更する
- プロジェクトルールを読めない

### 3. ターミナルで承認を求められるのはエラー？

多くの場合、権限境界どおりに動いているサインであり、異常実行ではありません。

## 初回に試す簡単なシナリオ

初回は次のような小さなタスクから始めてください。

- プロジェクトルートで起動
- 1 ファイルだけ変更
- 完了後に何を変えたか説明させる

CLI 対話モードは、ターミナルで会話型タスクフローを走らせるものです。ディレクトリとプロンプトの両方が正しいことが重要です。
