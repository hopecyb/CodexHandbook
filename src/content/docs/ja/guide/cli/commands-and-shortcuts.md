ターミナルでの効率は 3 つに分かれます：**起動方法**、**セッション内ショートカット**、**スクリプト / エディタとの連携**。本ページは使い方と習慣を扱います。引数表は [CLI コマンドリファレンス](/guide/reference/commands/) と [キーボードショートカット](/guide/reference/keyboard-shortcuts/)。

## 本ページの内容

- いつ `codex`、いつ `codex exec` を使うか
- 対話セッションでよくある操作の種類
- 繰り返し操作をエイリアスやスクリプトに固定する方法

## まず区別すること

CLI を初めて見ると、「コマンドとショートカット」は構文と引数の暗記だと思いがちです。

実務的には次の 3 つを先に分けます。

- **会話しながら進める** のか
- **一度に走らせたい** のか
- **よく繰り返す動作を短くしたい** のか

ここが分かると、コマンド選びはかなり明確になります。

## コマンド入口一覧

| やりたいこと | 入口 | 詳細 |
|---|---|---|
| 会話しながらコードを直す | `codex` 対話 TUI | [対話モード](/guide/cli/interactive-mode/) |
| CI / パイプの単発タスク | `codex exec`（または同等） | [非対話モード](/guide/cli/non-interactive-mode/) |
| デフォルト挙動を変える | 設定ファイル | [CLI 設定](/guide/cli/configuration/) |

:::note
サブコマンド名はバージョンで変わります。`codex --help` を正としてください。
:::

## よくある誤解

### `codex` と `codex exec` は上下関係ではない

よくある誤解は次のとおりです。

- ひとつが簡単モード
- もうひとつがプロモード

実務的な分け方は次です。

- `codex`：人がその場にいて、見ながら誘導する
- `codex exec`：タスクを先に言い切り、一度きりのフローで走らせる

### ショートカットは多いほどよいわけではない

最初はすべてのショートカットと `/` コマンドを覚える必要はありません。

まず押さえるのは次です。

- セッションの起動方法
- 現在の環境で使える `/` コマンドの確認方法
- 終了、再起動、ディレクトリ変更

これだけで十分です。

## 対話セッション内の「ショートカット」

バージョンごとにキーと `/` コマンドは違いますが、カテゴリは安定しています。

### 入力と履歴

- 複数行入力：製品説明どおりの改行キー（よくあるのは `Shift+Enter` やエディタモード）
- 前のタスクを見る：ターミナル履歴またはセッション履歴（ある場合）

### スラッシュコマンド

プロンプトで `/` を入力すると組み込みフロー（レビュー、コンテキスト圧縮など）が起動します。**一覧を暗記しない**——現在の環境の `/` 補完を正としてください。学習向け分類は [スラッシュコマンド早見表](/guide/reference/slash-commands/)。

### 承認関連

Agent が shell やファイル書き込みを求めると、対話 UI で承認 / 拒否 / 常に許可（提供される場合）が出ます。無人実行前に必ず [承認とサンドボックス](/guide/cli/approvals-and-sandbox/) を読んでください。

## Shell 層のショートカット（推奨）

「プロジェクトに入る + Codex を起動」を関数化し、ディレクトリミスを減らします。

```bash
# ~/.zshrc の例（必要に応じて変更）
cx() {
  cd "$1" || return 1
  codex
}
```

非対話レビューは `prompts/review.md` にプロンプトを置くスクリプトにまとめると版管理しやすいです。

## 慣れる順序

CLI を初めて使うなら、次の順がおすすめです。

1. 正しいディレクトリで `codex` を起動
2. いつ `codex exec` を使うか判断
3. 最後に高頻度操作を alias、関数、スクリプトにまとめる

こうすると、ツールに慣れる前にラッパーを重ねすぎることを避けられます。

## IDE / App との役割分担

| | CLI | IDE 拡張 |
|---|---|---|
| コンテキスト | `--cwd`、`@` ファイル（バージョンによる） | 開いているファイル、選択コード |
| 向くこと | スクリプト、SSH リモート、純ターミナル | 変更しながら diff を見る |
| ショートカット | ターミナルキー + `/` | エディタのコマンドパレット |

IDE：[ローカルタスクワークフロー](/guide/ide/local-task-workflow/)

## よくあるミス

- 誤ったディレクトリで起動し、隣のプロジェクトを変更
- アプリ内 `/review` をターミナル外の shell サブコマンドだと思い込む
- 対話セッションに未確認の第三者「万能プロンプト」を貼り付ける

すべてのコマンドとショートカットを急いで覚える必要はありません。まず「会話しながらか、一度に走らせるか」をはっきりさせれば、選びは単純になります。
