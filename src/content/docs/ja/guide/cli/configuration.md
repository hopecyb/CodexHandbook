CLI 設定は **デフォルトモデル、作業ディレクトリ、承認の厳しさ、MCP サーバー** などを決めます。[設定の基礎](/guide/customization/configuration/config-basics/) と概念は同じで、本ページはターミナルユーザーがよく触る項目に焦点を当てます。

## 本ページの内容

CLI 設定を初めて触る人は、「高度な設定パネル 1 つ」と考えがちです。そこから次の誤解が起きやすくなります。

- 設定しなくてもよいと思い、毎回同じことを手動で繰り返す
- 設定が多いほどプロっぽいと思い、個人嗜好、チームルール、一時実験を全部 1 か所に詰め、後で追いにくくする

ここでは、**長期固定すべき設定** と **一時的に変えるべき設定** を分けることが主題です。

## CLI 設定が管理すること

CLI 設定は「ターミナルでの Codex のデフォルトの働き方」と考えてください。

- モデル設定：デフォルトで誰に任せるか
- サンドボックスと承認：どこまでできるか、どこで承認が必要か
- 作業ディレクトリ：デフォルトでどのプロジェクトで動くか
- MCP と拡張：どの外部能力を借りるか

何も設定しなくても Codex は動きます。ただし、同じ選択を何度も繰り返すことになります。

## 設定の置き場所

| レイヤー | 用途 |
|---|---|
| ユーザー級 | 個人デフォルト。プロジェクト横断 |
| プロジェクト級 | チーム共有ポリシー（コミット前にレビュー） |
| 環境変数 | CI で鍵とスイッチを注入 |

**パスとファイル名** は CLI バージョンで変わるため、[公式ドキュメント](https://developers.openai.com/codex) を正としてください。よくあるのはユーザーディレクトリの `config.toml` または同等ファイルです。

## よくある誤解

### すべての設定をプロジェクトに書くべきではない

初心者は「好みのデフォルトモデル」「ローカルパス」「チーム全体の承認方針」を混ぜがちです。

より明確な分け方は次のとおりです。

- 個人の長期嗜好 → ユーザー級
- このリポジトリで全員が揃えるべきこと → プロジェクト級
- CI、スクリプト、単発実行だけの一時注入 → 環境変数

### 設定 = 権限がすぐ広がるわけではない

設定に方針を書いても、以後すべての操作が無条件に通るわけではありません。実際の挙動は製品入口、実行環境、マネージドポリシー、タスク内容にも左右されます。

設定はデフォルト傾向であり、永久特権ではありません。

## よく触る項目

### デフォルトモデルと推論強度

速度、コスト、複雑タスクの成功率に影響します。スクリプト化では **モデルを固定** してログ比較しやすくするのがおすすめです。

### サンドボックスとネットワーク

| 設定意図 | 説明 |
|---|---|
| 厳格 | 信頼できないリポジトリ向け |
| 標準 | 日常開発 |
| 緩和 | 個人の信頼環境のみ。会社方針に合致すること |

概念：[サンドボックスとネットワーク](/guide/foundations/sandbox-and-network/)

### 承認ポリシー

CLI は shell 実行、書き込み、ネットワーク接続の前に確認することがあります。チームは `AGENTS.md` に、どのコマンドが自動承認されうるかを書くべきです——製品の実挙動と一致しているときだけ有効です。

### MCP サーバー一覧

[Connect MCP サーバー](/skills/mcp/connect-an-mcp-server/) と設定を共有。変更後はセッションを再起動してください。

## 十分な設定順序

始めたばかりなら、全フィールドを一度に調べる必要はありません。次の順が楽です。

1. 最もよく使うモデルを固定
2. デフォルト作業ディレクトリが現在のプロジェクトか確認
3. 承認とサンドボックスを保守的か緩めるか決める
4. 最後に MCP、自動化、より高度な拡張を足す

この順にするのは、前半が日常利用、後半がリスク管理だからです。

## プロジェクトと CLI の整合

「App では動くが CI では失敗」を避けるには：

1. README に推奨 CLI 最低バージョンを明記
2. プロジェクト級設定には **チーム合意項目だけ** を置く
3. 秘密情報はリポジトリに入れない

## トラブルシューティング

| 現象 | 確認 |
|---|---|
| 設定が効かない | レイヤーを間違えていないか。再起動が必要か |
| MCP が読み込まれない | JSON/TOML 構文、パス |
| 承認が多すぎる | サンドボックスモードと allowlist |

詳細：[CLI トラブルシューティング](/guide/cli/troubleshooting/)

CLI 設定は「デフォルトの働き方」と考え、**ほぼ毎回同じ選択をするものだけ** 固定すれば十分です。高度な能力は後から足しても遅くありません。
