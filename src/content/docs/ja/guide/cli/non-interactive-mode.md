非対話モードでは、Codex が **TTY 会話なし** でタスクを完了できます。Agent をスクリプトや CI に接続する入口です。

要するに、非対話モードは往復チャットではなく、タスクを一度に渡して実行する方式です。  
コマンド型の呼び出しに近いと考えてください。

## 本ページの内容

- 非対話を使うタイミングと `codex` 対話セッションの違い
- 無人実行時のセキュリティと承認の追加要件
- [設定](/guide/cli/configuration/) との関係

## 向いている場面

| 向く | 向かない |
|---|---|
| CI で固定レビュープロンプトを実行 | 多回の要件確認が必要 |
| 夜間のドキュメントリンクチェック | 探索的リファクタリング |
| 事前定義テンプレートからのコード生成 | 曖昧なプロダクト判断 |

## 中核概念

非対話実行は通常、次のように動きます。

1. 引数または stdin から **完全なタスク説明** を受け取る
2. 指定された作業ディレクトリで実行する
3. 終了コードで成功 / 失敗を示す
4. ログまたは構造化結果を下流で消費できる形で出力する

**コマンド名と引数は公式 CLI ドキュメントを正とする**（よくあるのは `codex exec` または同等のサブコマンド）。CLI を上げたら `--help` で再確認してください。

## 最小限の例（示意）

```bash
# リポジトリルートで読み取り専用レビュー（示意。引数は公式を正とする）
codex exec --cwd . "main との diff からセキュリティリスクを列挙し、ファイルは変更しない"
```

実践のコツ：

- shell スクリプトでは先にクリーンな作業コピーへ `cd`
- タスク文字列は heredoc か版管理された `prompts/` ファイルへ
- 終了コードを捕捉し、失敗時は CI を赤にする

## セキュリティ設計

無人実行 = **あなたがその場で拒否できない**：

| 原則 | やり方 |
|---|---|
| 最小権限 | 読み取り専用トークン、制限付きサンドボックス |
| push 禁止 | CI は PR 作成または artifact アップロードのみ |
| 固定プロンプト | PR 説明から未消毒テキストを直接連結しない（注入リスク） |
| 監査 | ログと diff artifact を保持 |

[人間承認パターン](/cases/workflows/human-approval-patterns/) とロードマップ `08-developer-platform/non-interactive/` を参照。

## 対話モードとの比較

| | 対話モード | 非対話モード |
|---|---|---|
| 入口 | `codex` TUI | `exec` / パイプ |
| 人間の介在 | 強い | 弱い。事前設計が必要 |
| 学習向き | はい | いいえ |
| CI 向き | いいえ | はい |

対話の使い方：[CLI 対話モード](/guide/cli/interactive-mode/)

## よくある誤解

### 1. 非対話の方が効率的だから最初に学ぶべき？

おすすめしません。

初めての人にとって非対話は速すぎ、硬すぎ、途中での確認余地が少なすぎます。

### 2. 対話モードとの最大の違いは？

核心は次のとおりです。

- **対話モード**：途中で質問・修正・承認できる
- **非対話モード**：一度きりの実行。事前定義フロー向き

### 3. いつ触らない方がよい？

次の段階なら、まず触らない方がよいです。

- プロンプトの書き方にまだ不慣れ
- 結果の検収方法がまだわからない
- 承認、サンドボックス、権限の基本判断がまだない

非対話は自動化向きで、初回の試行錯誤向きではありません。対話に慣れてからスクリプト接続を検討してください。

## よくあるミス

- 対話セッションの長い履歴をそのまま 1 回の exec に詰め込む
- CI で本番資格情報と書き込み権限を使う
- CLI バージョンを固定せず、パイプラインの挙動が突然変わる
