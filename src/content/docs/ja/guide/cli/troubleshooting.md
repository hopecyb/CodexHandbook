CLI で問題が起きると、表示はどれもターミナルエラーに見えますが、原因の種類は同じとは限りません。

CLI のトラブルシューティングでは、まず「未インストール / 未ログイン / 権限なし / 誤ディレクトリ」のどれかを判断します。

| 症状 | まず試すこと |
|---|---|
| command not found | インストールと PATH を確認 |
| 認証失敗 | 再ログイン。組織ポリシーを確認 |
| 権限拒否 | 承認モードとサンドボックス設定を確認 |
| 誤ったディレクトリでファイル変更 | 現在の作業ディレクトリを確認 |

## まず 4 分類

- **コマンド自体が見つからない**：多くはインストールまたは `PATH`
- **コマンドは動くが入れない**：多くは認証
- **入れるが何もできない**：多くは権限またはサンドボックス
- **動いたが結果がおかしい**：多くはディレクトリまたはコンテキスト

## よくある誤解

### 1. すべての CLI エラーを同じログで調べる必要がある

まず大分類すると、最初からエラー詳細を掘るより速いことが多いです。

### 2. 権限拒否 = 壊れている

多くの場合、壊れているのではなく、承認、サンドボックス、ポリシーが正常に働いています。

### 3. コマンドが実行された = ディレクトリは問題ない

それも違います。

CLI の多くの問題は「コマンドが走らない」のではなく、「誤ったリポジトリや作業ディレクトリで走っている」ことです。

## 切り分け順序

1. コマンドが存在するか確認
2. ログイン状態を確認
3. 現在の権限モードとサンドボックス制限を確認
4. 最後に作業ディレクトリが想定どおりか確認

CLI トラブルシューティングでは、インストール、ログイン、権限、ディレクトリのどれかを先に分けると、だいたいスムーズに進みます。
