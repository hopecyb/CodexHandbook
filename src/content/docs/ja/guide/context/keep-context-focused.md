多くのタスクが会話の途中で散らかるのは、コンテキストがすでに拡散していることがよくある原因です。

コンテキストに焦点を保つとは、一度に明確な目標を一つだけ扱い、古い問題と新しい問題を混ぜないことです。

## なぜ会話が散らかるか

「多く言うほど安全」は通常成立しません。コンテキストは際限なく積み上げられません。

Codex にとって、一つのタスクに次が同時に入ると：

- 元の問題
- ついでに出た新しい問題
- 途中で浮かんだアイデア
- 以前議論したが今は重要でない細部

最後によくある結果は、要点がぼやけることです。

## なぜタスクがずれていくか

よくある原因は次のとおりです。

- 一つの会話に複数の目標を詰め込んだ
- 先に言った制約を、後で自分が忘れた
- すでに解決した問題がまだ注意を占めている
- 途中で新しい要件が入ったが、再び締めていない

あなたは情報を補っていると感じても、Codex が見ているのは要点がどんどん散らばる状態です。

## 基本のやり方

- 一度のタスクに目標は一つ
- 定期的に「完了 / 未完了 / まだ有効な制約」を要約する
- 長いタスクには段階ゲートを使う
- セッションをまたぐ場合は [引き継ぎと再開](/ja/guide/agent-work/handoff-and-resume/) を使う

## 締めるべきサイン

次のような状況が出たら、積極的に締めるべきです。

- 自分でも前の会話を遡って初めて進捗が分かる
- 同じタスクの中で第二の問題を議論し始めた
- 「ついでにもう一つ」が増えてきた
- もはや重要でない古い結論を引用し始めた

## 各やり方が解く問題

### 一度のタスクに目標は一つ

同じタスクで同時に依頼しないでください。

- bug 修正
- 文案変更
- ついでにリファクタ
- さらに別の新しい問題の調査

分けると、範囲が明確になり、確認もしやすくなります。

### 定期的に「完了 / 未完了 / まだ有効な制約」を要約する

これはタスクの途中校正に相当します。タスクが長いほど、この一手で双方が今どこまで進んだか忘れにくくなります。

### 長いタスクには段階ゲート

「段階ゲート」とは、小さな区切りを完了し、外れていないことを確認してから次に進むことです。

たとえば先に「問題の特定だけ」、次に「案の提示だけ」、最後に「変更の実行」。

### セッションをまたぐ場合は引き継ぎ

一度で終わらないタスクは、短い引き継ぎで重要な状態を残してください。

## すぐ使える締めの書き方

途中で締めるときは、次のように直接書けます。

```text
一度締めましょう。
完了：A。
未完了：B。
まだ有効な制約：フロントエンドだけ変更、API は変更しない。新しい依存は入れない。
次にやることは C だけ。
```

## よくある誤解

### 1. 一度にすべての要件を言おうとして、主従が分からなくなる

情報が多い ≠ 情報が明確。主タスクとついでタスクを分けないと、Codex は混ぜやすくなります。

### 2. タスクが変わったのに、古い会話を続ける

方向が変わったら、無理に続けるより新しいスレッドがすっきりすることもあります。

### 3. 段階確認をせず、一度に変更しすぎる

変更が多いほど、どの段階から外れたか後から判断しにくくなります。

コンテキストの焦点は、話を減らすことではなく、まだ有効な情報を残し、もはや重要でない内容を適時に片付けることです。コンテキストが散らばると、その後の実行も外れやすくなります。
