「会話コンテキスト」とは、Codex と同じタスクの中でこれまでに話した内容が、その後の応答に引き続き影響することを指します。助けになる面もありますが、リスクも伴います。

## なぜ有用か

同じスレッドには次の内容が蓄積されます。

- あなたの目標と制限
- 途中の議論で出た結論
- すでに実行したステップ
- ツール出力の重要な情報

たとえば、先に「ホームページだけ直して、バックエンドには触らない」と説明していれば、後のやり取りで毎回繰り返す必要は通常ありません。

## なぜ問題も起きるか

よくある問題は、**古い情報が自動的に失効しない** ことです。

よくある状況は次のとおりです。

- 先に言った制限を、あなた自身が後で変更し忘れた
- タスクの方向は変わったのに、古いコンテキストに沿って会話を続けている
- 途中の一時的な結論がもはや成立していないのに、まだ後続の判断に影響している

したがって重要なのは会話を長くすることではなく、会話が長くなるほど積極的に締めることです。

## いつ重要な制約を再述すべきか

先に言ったことでも、次のような節目では改めて伝える価値があります。

- 実際にファイルを変更し始める前
- タスクの方向が変わった後
- 会話がすでに長くなった後
- ある境界を無視し始めたと感じたとき

特に次の情報は再提起する価値が高いです。

- 変更してよいファイルだけ
- やらないこと
- 完了基準は何か
- まだ有効な制限はどれか

## よくある誤解

### 1. 同じスレッドが長いほど楽になる？

必ずしもそうではありません。

テーマが一貫していれば、長いスレッドは便利です。  
しかしタスクの方向が変わったのに古いスレッドを続けると、新しいタスクをずらしやすくなります。

### 2. 言ったはずなのに、なぜまた間違えるの？

先の情報は、その後の内容によって薄まっているか、現在のタスクに十分合っていない可能性があります。

このとき「知っているはずだ」と言うより、まだ重要な制約を改めて伝える方が効果的です。

### 3. いつ新しいスレッドを開くべきか

次の基準で判断できます。

- 目標が変わった
- 元の問題は終わった
- 自分でもこの会話が散らかってきたと感じる

この場合、無理に続けるより新しいスレッドを開く方がすっきりします。

## テーマが切り替わったときの対処

テーマが切り替わったときは次のようにします。

1. 新しいスレッドを開く
2. まだ有効な制約の要約だけ貼り付ける
3. すでに古くなった背景は持ち込まない

同じスレッドで続ける場合は、短い「再合わせの説明」を先に送ることもできます。例えば：

```text
これからはホームページのリデザインだけを議論します。先ほどのバックエンド API の内容は引き続きません。今回も文案とスタイルだけを変更し、データ構造は変えません。
```

同じスレッドは記憶の継続を助けますが、古い荷物も一緒に運びます。テーマが変わったら、積極的に締めるべきです。
