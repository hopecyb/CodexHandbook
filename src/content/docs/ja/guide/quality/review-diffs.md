「差分」とは、Codex が今回どこを変更したかを指します。

多くの人が初回検収で、実際の変更を見ずに書かれた要約だけを見ます。  
問題の発見は主に diff に依存します。「完了しました」という説明は参考程度にしてください。

## diff で何を見るか

diff は次の重要な質問に直接答えられます。

- 実際にどのファイルを変更したか
- 変更が許可した範囲内か
- ついでに削除したり壊したりしていないか
- デバッグ内容、キー、臨時コードが混入していないか

diff を読むときの重点：

1. 許可したパスだけを変更したか？
2. 予期しない削除はないか？
3. 命名とスタイルは一貫しているか？
4. キーやデバッグ残留はないか？

製品側のビュー：[差分、コメントとレビュー](/ja/guide/desktop-app/diffs-comments-and-review/)

## よくある誤解

### 1. コードの diff が読めなくても、基礎レビューはできる

最初の段階では、シニア開発者のように各行のロジックを読む必要はありません。  
まず次の 3 点を見るだけでも価値があります。

- どのファイルを変更したか
- 変更してはいけない場所を変更していないか
- 明らかに無関係な内容が追加されていないか

### 2. 1 ファイルだけの変更だから、必ず安全

ファイルが少なくても、変更が正しいとは限りません。  
ただし範囲が小さいほど、確認しやすく、取り消しもしやすいです。

### 3. 「小さな変更」でも見る必要がある

見落としやすいのは、しばしば「小さな変更に見える」箇所です。

## 確認順序

初めて diff を見るときは、次の順序で進められます。

1. いくつのファイルを変更したか見る
2. 許可したパスを超えていないか見る
3. 明らかな誤削除、臨時ログ、デバッグ残留がないか見る
4. スタイルと命名が調和しているか見る

実際に何を変更したかを先に把握し、その内容に基づいて今回の結果を受け入れるか決めてください。
