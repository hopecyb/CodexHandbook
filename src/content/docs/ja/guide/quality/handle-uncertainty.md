情報が足りないときは、先に確認してから続けてください。

Codex を使うとき、最も厄介な状況の一つは、欠けている情報をもっともらしい答えで補完することです。  
前提が間違えば、その後のステップも一緒にずれます。

## 「不確実」とは何か

ここでの「不確実性」は主に次を指します。

- 現時点で確認する十分な根拠がない
- 関連情報が現在のコンテキストにない
- この判断を推測で続けるとリスクが大きい

より適切なのは、「いつ先に止まって確認するか」を事前に明確にすることです。

プロンプトに固定で書きます。

```text
情報不足のときは先に質問する。ファイルパス、API、業務ルールを捏造しない。
```

推測を見つけたら：止める、事実を訂正する、必要なら新しいスレッドを開く。

## 判断方法

次のいずれかに当てはまる結論は、推測で進めるべきではありません。

- 現在のファイルに根拠が見つからない
- その業務ルールを明示していない
- 外部事実が必要だが、まだ出典を確認していない
- 一度間違えると、その後の複数ステップに影響する

## よくある誤解

### 1. 回答が完結している = 本当に知っている

内容が完結していることは、時には空白をうまく埋めただけで、その内容がプロジェクトに実在するとは限りません。

### 2. 情報が不完全なとき、重要なのは空白を埋めることではない

情報をできるだけ揃えるのは当然よいですが、実際の協業では情報不足はよくあります。

より重要なのは次の 2 点です。

- 情報が足りないとき、先に止まって確認する
- 無理に推測で終わらせず、質問できるようにする

### 3. 質問すると、必ず遅くなる

表面上は一手増えますが、通常は手戻りを減らします。

多くの問題は「先に推測して進める」ことから広がります。

### 4. 推測を見つけたら、先に止める

まず誤りを止めてから続けます。対処順序は次のとおりです。

1. どの点が間違っているかを明確に指摘する
2. 正しい情報を補う
3. 必要なら訂正後の事実に基づいてやり直してもらう

## そのまま足せる一文

推測を減らしたいなら、次のように直接書けます。

```text
既存ファイルや私が提供した情報から確認できない場合は、先に質問してください。勝手に補完しないでください。
```

## さらに足す一文

次も追加できます。

```text
複数の解釈が可能な場合は、不確かな点を先に列挙してから続けてください。
```

より厄介なのは、推測を事実としてそのまま先に進めることです。
