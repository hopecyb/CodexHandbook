Codex を使うとき、多くの人は「作れるかどうか」に注目しがちですが、もう一つの問いを見落としやすいです。作ったあと、今回の結果を本当に受け取れるかどうか。

この一連の内容は、その問いに答えるものです。品質と検証は、「見た目は完了したが、まだ安定していない」状態を避けるためのものです。

- [差分のレビュー](/guide/quality/review-diffs/)
- [テストの実行](/guide/quality/run-tests/)
- [成果物の検証](/guide/quality/verify-artifacts/)
- [出典の確認](/guide/quality/validate-sources/)
- [不確実性の扱い](/guide/quality/handle-uncertainty/)
- [完了の定義](/guide/quality/definition-of-done/)

## 読み順

初めて読むときは、次の順序がおすすめです。

1. [差分のレビュー](/guide/quality/review-diffs/) で、実際に何を変えたかを確認する
2. [テストの実行](/guide/quality/run-tests/) で、他を壊していないかを確認する
3. [成果物の検証](/guide/quality/verify-artifacts/) で、結果が本当に望んだものかを確認する
4. [完了の定義](/guide/quality/definition-of-done/) で、「どうなったら本当に完了か」を明確にする

確認がないと、「完了」は多くの場合、一時的に完了したように見えるだけです。
