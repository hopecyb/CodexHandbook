本ページでは、`src/content/docs/` に**ガイド型**のページ（純粋な事例や参照表だけではないページ）を追加・改稿する方法を説明します。

## 本ページの内容

よくあるつまずきは次のとおりです。

- ガイドページがどんな形であるべきかわからない
- 自分が書いているのが「チュートリアル」「規約」「目次の要約」のどれかわからない
- 初心者に本当に役立つ書き方がわからない

ここではそれらを分けて説明し、保守しやすく、読者にも伝わるガイドページを書けるようにします。

## ガイドページの役割

ここでいう「ガイドページ」は、資料を積み上げただけでは完成しません。「このテーマがあることは知っている」から「いつ使うか、まず何を読むか、何を避けるかがだいたいわかる」まで読者を連れていく必要があります。

したがって、単なる知識のリストでも、コマンド一覧だけでもなく、次にどこへ進めばよいかも示す必要があります。

## Frontmatter

```yaml
---
title: ページタイトル
description: 本文が解決する問題を一文で
---
```

新しいページでは、編集状態と検証方法を frontmatter に記録します。自由記述の検証フッターは付けません。

```yaml
editorialStatus: review
verification:
  kind: editorial
  checkedAt: "2026-09-18"
  summary: 内容の構成を確認済み。実際に行った確認内容と日付に置き換えてください。
```

出典の確認やサンプルの実行を示す場合は、[技術コンテンツの検証](/ja/guide/contributing/verify-technical-content/)に従い、必要なリンクと環境情報を追加します。日付は引用符で囲んだ `YYYY-MM-DD` 形式の文字列にしてください。

## 推奨構造

[外部資料統合テンプレート](https://github.com/hopecyb/CodexHandbook/blob/main/docs/planning/external-source-integration.md#6-推荐页面模板) から節を選び、よくある組み合わせは次のとおりです。

- ページが解決する問題
- 誰向けか
- 最小限で使えるやり方
- 推奨ワークフロー
- よくある間違い
- 安全境界
- 受け入れチェックリスト
- 参考ソース

製品操作ページは手順寄り、概念ページは表や図解寄りにするとよいです。

## よくある誤解

### すべてのページを百科事典にする必要はない

初めてガイドを書くとき、知っていることを全部入れてしまい、かえって要点がぼやけることがあります。

より一般的な書き方は次のとおりです。

- まずページが主に解決する問題を書く
- 次に読者が最も誤解しやすい点を書く
- 最後に十分使えるやり方や判断基準を一つ示す

一度にすべての細部を詰めるより、こうした方が新人には役立つことが多いです。

### 自分が書けることだけでなく、読者の読み方も考える

自分にはコンテキストが見えていても、初めて来た読者には見えていません。

だから次の橋渡し情報を意識的に足します。

- ページは誰向けか
- 読み終えたら何が解決するか
- まず手を付けたいだけなら、どこを押さえるか

### ガイドページは公式ドキュメントの代わりにならない

コミュニティハンドブックは理解・つなぎ・実践を助けられますが、変わりやすい事実は公式ドキュメントで検証する必要があります。

## 相互リンク

- サイト内リンクはルートパス：`/ja/cases/workflows/explore-plan-execute-verify/`
- 権威あるページへリンクし、大きな重複を避ける
- 新規ページは章の `index.md` と `astro.config.mjs` の sidebar に登録する

## トーン

- 日本語、実践者向け
- 不確実性を認める（「公式ドキュメントを正とする」）
- 「万能プロンプト」の語りを使わない

## 執筆の順序

次の順で書くとよいです。

1. まずページが解決する問題を書く
2. 次に読者が最も誤解したり飛ばしたりしやすい点を書く
3. 最小限のやり方、ワークフロー、判断基準を補う
4. 最後に相互リンクと参考ソースを足す

## 検証

PR 提出前に [技術コンテンツの検証](/ja/guide/contributing/verify-technical-content/) を読んでください。コマンド、価格、権限など変わりやすい情報は必ず再確認します。

良いガイドページは「資料を全部書いた」ことではなく、初めて来た読者がページの存在理由、最初に読むべき箇所、次の一歩を理解できることにあります。
