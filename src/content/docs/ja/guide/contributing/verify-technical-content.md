コマンド、権限、価格、製品機能はバージョンによって変わることがあります。技術情報の確認では、どの記述に現在の根拠があるか、どの環境に適用できるか、読者が別途確認すべき点は何かを明確にします。

## 確認の目的

文章を読みやすくするだけでは十分ではありません。重要な事実が現在の製品と一致し、記載された環境で手順を実行でき、結論が根拠の範囲を超えていないことを確かめます。

## 根拠の優先順位

1. 製品の動作、パラメーター、制限には OpenAI の公式ドキュメントを優先します。
2. 「実行済み」と記載する例には、実際の結果と環境情報が必要です。
3. コミュニティの記事は話題を見つける助けになりますが、公式情報や実際の実行の代わりにはなりません。
4. リンクが開くことだけでは記述の根拠になりません。内容を読んで確認します。
5. 確認できない情報は推測で補わず、不確実であることを明記します。

## 記録する対象範囲

- 対象製品：App、CLI、IDE、Cloud
- OS、クライアント、重要な依存関係のバージョン
- 実際に行った手順と結果の確認方法
- 対象外のプラットフォーム、入口、境界条件
- サイトのトップページではなく、具体的な参照ページ

## 確認の順序

1. ページが扱う製品、入口、利用場面を特定します。
2. 変化しやすい事実を現在の公式ドキュメントと照合します。
3. 実行可能とする手順は、クリーンな環境で最初から実行します。
4. 未実行または不確かな記述は対象を狭め、制限を本文に直接記載します。
5. 内部リンク、外部リンク、読者に必要な前提条件を確認します。

## 変わりやすい情報

製品の大きな更新後は、次を優先して再確認します。

- コマンド、サブコマンド、flags
- 権限の初期値とサンドボックスの動作
- プラン、モデル名、価格、割り当て、地域別の提供状況
- MCP、Hooks、その他の統合インターフェース
- メニュー位置、ボタン名、製品の入口

## 確認できない場合

推論を事実として書かないでください。古い具体情報を削除する、安定した方法を中心に書き直す、または PR や issue に未解決事項を記録します。現在の動作、価格、ポリシーは公式情報を基準にします。
