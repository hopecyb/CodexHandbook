プロンプト例はリポジトリルートの [`examples/prompts/`](https://github.com/hopecyb/CodexHandbook/tree/main/examples/prompts) に置き、ハンドブック本文からリンクします。設計仕様は [`docs/planning/examples-system.md`](https://github.com/hopecyb/CodexHandbook/blob/main/docs/planning/examples-system.md) を参照してください。

## 本ページの内容

よくあるつまずきは次のとおりです。

- どんなプロンプトが掲載に値するのかわからない
- 他の人がそのまま再利用できる形式がわからない

本ページでは、**他の人が実際に試せ、学べ、再現できる**例をどう提出するかを説明します。

## 掲載基準

ここで集めるのは「コンテキスト・境界・受け入れ基準付きの再現可能な例」であり、インスピレーション断片ではありません。

合格するプロンプト例は、少なくとも次の三つに答える必要があります。

- いつ使うか
- 具体的にどう言うか
- 使ったあと、うまくいったかどうう判断するか

前提も検証方法もわからない、ただ賢そうな一文だけなら、メモに近く、例とは言えません。

## ファイル命名

```text
examples/prompts/<category>/<slug>.md
```

`category` の例：`development`、`research`、`meta-workflows`、`team`。

## 必須メタデータ（YAML frontmatter）

```yaml
---
id: prompt.fix-bug-with-tests
title: バグ修正とテスト追加
content_type: prompt
audience: [beginner, developer]
difficulty: beginner
products: [app, cli, ide]
capabilities: [planning, file-editing, testing]
status: draft
last_verified: YYYY-MM-DD
---
```

## 本文に必須の節

1. **使用シーン**
2. **使用前の準備**（権限、ブランチ、コンテキストファイル）
3. **推奨版プロンプト**（全文コピー可能）
4. **受け入れ基準**（客観的に確認できるチェックリスト）
5. **よくある失敗の仕方**
6. **関連ハンドブックページ**（`src/content/docs/` へのリンク）

任意：極簡版、解説用の分解、差し替え可能な変数。

## よくある誤解

### 要点を散らさない

背景、理論、補足説明を長く書き、実際にコピーして使うプロンプトが途中に埋もれることがあります。

より安定した書き方は次のとおりです。

- まず推奨版プロンプトを完結させる
- 次に前提、変数、失敗パターンを補う
- 最後に説明的な内容を足す

### 一度自分が使っただけでは、完成した例にならない

自分の頭の中の暗黙の前提は、読者には見えません。

だから次の前提を書き出します。

- どの製品入口向けか
- どのファイル、スクリーンショット、コンテキストが必要か
- ファイル変更、コマンド実行、ネットワーク利用をデフォルトで許可するか

### 実際の機密情報を例に入れない

例に実トークン、アカウント、内部リンク、顧客情報が含まれるなら、公開リポジトリ向きではありません。

例が教えるべきなのは方法であり、本番環境の露出ではありません。

## 受け入れ基準の例

```markdown
## 受け入れ基準

- [ ] もともと失敗していたテストが通る
- [ ] 合意した範囲のテストスイートが通る
- [ ] diff はタスク関連ファイルのみ
- [ ] git push は実行していない
```

## 品質のしきい値

- 目標と完了の定義が明確
- 権限と安全境界の説明を含む
- 実際の秘密鍵と PII を含まない
- `verified` 状態には [独立検証](/ja/guide/contributing/verify-technical-content/) が必要

## 提出フロー

次の順が一般的に安定します。

1. この例が解決する実タスクの種類を決める
2. 他の人がそのままコピーできるプロンプトを書く
3. 最低限必要な前提条件と境界を示す
4. 「成功」の定義を明確に書く
5. 最後に機密情報の漏れと配置ディレクトリを確認する

## PR チェック

- [ ] 新規ファイルパスを `examples/README.md` の索引に追加した（索引を維持している場合）
- [ ] 少なくとも一つの事例ページまたはワークフローページからその例へリンクしている（任意だが推奨）

良いプロンプト例は、他の人がそのまま再現し、近い結果を得られるものです。
