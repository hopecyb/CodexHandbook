难度：入门。预计 30—45 分钟，为编辑预估，尚未经过读者计时。前置条件：能够向 Codex 提供本地文件。只阅读参考结果不要求编程；运行校验需要 Python 3.10+。

## 1. 先确认文件和口径

把下面任务交给 Codex。不同客户端提供文件的方式可能不同；先确保它实际读到了文件，再继续。

```text
读取 brief.md、starter/data-dictionary.md 和 starter/sales.csv。
确认文件存在，列出字段、日期范围、记录数及需特殊处理的行号。
不改原表、不看 solution。区分完全重复、缺日期、负数与真实零。
按字典说明两周口径，有冲突时列出冲突，无冲突即可继续。
```

原表 46 行包含两条退款、一条完全重复、一条缺日期。完全重复只保留第一条；同 ID 内容不同时应停止核对。缺日期不补造，零金额有效。处理完应纳入 44 行。

## 2. 生成周报与计算台账

继续使用包内 `prompts/02-report.md`，要求产物写入 `my-output/`：

| 文件 | 应包含什么 |
|---|---|
| `summary.md` | 总额、环比、地区、本期 Top 3、数据质量和计算依据 |
| `region-summary.csv` | 两周各地区净额、增减额、环比，总计可与地区相加核对 |
| `top-products.csv` | 按本期产品净额降序排列，计入退款 |
| `row-ledger.csv` | 每条原记录的行号、纳入决定、周次和金额 |

输入、solution 与 validation 保持不变。字段名和表格顺序遵循数据字典，能让独立校验逐项对照。西南上期为零，环比填 N/A；不能当成 0% 或无限增长。

## 3. 独立核对，不能只问“对不对”

在解压后的练习目录运行：

```sh
python3 validation/check.py --output my-output
```

四个产物齐全且与约定口径一致时输出 `result: PASS`；输入哈希改变、漏算退款、分组错误或台账不符都会报错。校验失败时只修复自己的产物，不改校验器来迎合结果。

无法运行 Python 时，至少手动核对：

1. 华东本期七条正数合计 1,401.75 元，再加第 44 行退款 -120.50，得 1,281.25。
2. 本期三个地区相加：1,281.25 + 2,101.75 + 1,261.75 = 4,644.75。
3. 第 47 行 O046 缺日期，199.99 元不进入两周汇总；第 46 行 O001 是重复行。

自动校验并不能审查所有自然语言结论。仍需阅读周报，删除没有来源的增长原因或业务判断。

## 4. 练习纠偏：遗漏退款

**设计反例**：假设汇总时过滤了所有负数，本期会得到 4,765.25 元，多出 120.50 元。参考验证实际修改过临时结果，确认校验器会拒绝错误金额；这不是伪造的模型对话。

```text
核对 net_sales 小于零的有效记录，解释它们是否应纳入。
保留退款原符号，重算两期地区和产品汇总；列出修正前后的差额。
不要通过修改原始 CSV 或校验器消除失败。
```

## 5. 遇到问题时恢复

| 现象 | 先检查 | 下一步 |
|---|---|---|
| 找不到文件 | 当前目录是否有 starter/sales.csv | 打开解压后的目录，再引用文件，不让 Agent 重建缺失数据 |
| 中文乱码或只有一列 | 编码是否 UTF-8，分隔符是否逗号 | 重新导入原 CSV，不手改金额 |
| 数字相差 120.50 | 是否漏掉 R043 退款 | 按字典保留负数，重算两期 |
| 环比显示除零错误 | 西南上期是否真实为零 | 写 N/A，并说明基数为零 |
| 校验器报缺文件 | 是否生成全部四个产物 | 按字典补全，再运行；缺文件不等于金额错误 |

## 完成条件与下一步

- 原表哈希不变，四个产物齐全。
- 总额、华东与缺日期金额完成独立复核。
- 周报保留异常、零基数和计算口径，未编造原因。
- 明确哪些检查实际运行、哪些仍需人工审阅。

保留自己的提示词与纠偏记录，下次替换数据前重新确认字段和口径。本练习的固定校验器不适用于任意企业数据。
