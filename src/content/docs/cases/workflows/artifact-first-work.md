**产物优先**是先把交付物的形态和位置说明白，再让 Codex 反推步骤。它适合 Markdown 文档、OpenAPI、迁移脚本、幻灯片大纲这类输出明确的任务，也可以和 [规格驱动](/cases/workflows/specification-driven-work/) 配合使用。

## 这页重点

- 如何描述产物结构而非过程细节
- 多文件产物的一致性检查
- 与 [文件与产物](/guide/files-and-artifacts/) 能力对齐

## 最小可用做法

```text
目标产物：
- docs/api/auth.md（含 3 个小节：概述、端点、错误码）
- 风格与 @docs/api/users.md 一致

先输出目录大纲与每节要点，不要写全文；
我确认后再生成，并自检内部链接是否有效。
```

## 推荐工作流

```text
定义产物清单（路径 + 格式 + 样例引用）
    → 大纲或骨架文件
    → 人工确认
    → 填充内容 + 交叉链接
    → 验证（lint、链接检查、预览）
```

可视化产物可要求截图或预览说明，见 [验证产物](/guide/quality/verify-artifacts/)。

## 常见错误

- 产物路径与仓库约定不一致（放错目录）
- 只生成单文件，忽略导航与 index 更新
- 未对照样例，风格割裂
- 二进制产物（pptx/docx）未说明如何人工打开验收

## 安全边界

- 生成物若含第三方版权内容，需人工合规检查
- 不要覆盖生产配置路径，先在分支或 `draft/` 下产出

## 验收清单

- [ ] 所有声明的文件存在且可打开
- [ ] 格式与引用样例一致
- [ ] 链接/目录/Frontmatter 有效
- [ ] 符合 [定义完成](/prompts/define-done/)
