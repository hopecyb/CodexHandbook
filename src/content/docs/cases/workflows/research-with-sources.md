**带引用的研究**工作流强调：结论必须能回到**来源**（官方文档、论文、仓库文件），而不是模型自信编造。适合技术选型、竞品对比、文献综述、政策解读。

## 这篇解决什么问题

- 何时用 [网页搜索](/guide/tools/web-search/) vs 只读仓库
- 如何要求引用格式与不确定性标注
- 与 [验证来源](/guide/quality/validate-sources/) 的衔接

## 最小可用做法

```text
研究「Rust 与 Go 在本仓库场景下的适用性」：
1. 先列出评估维度（性能、生态、团队熟悉度）
2. 每个结论附来源 URL 或 @仓库内文件路径
3. 无法核验的标为「待确认」
4. 最后给推荐与开放问题
不要改代码。
```

## 推荐工作流

```text
定义问题与排除项
    → 收集来源（搜索 / 读文档 / MCP）
    → 对比表 + 优劣势
    → 标注置信度与冲突来源
    → 人工拍板或进入规格阶段
```

长研究任务拆成多轮，见 [长任务管理](/cases/workflows/long-running-task-management/)。

## 常见错误

- 不要求 URL，产出无法复核
- 混用过时博客与官方文档不说明
- 把研究结论直接当实现指令，跳过规格
- 上传含机密数据的文件到未授权外部工具

## 安全边界

- 内部未公开资料不得通过不受控 MCP 外发
- 价格、版本、地区可用性等易变事实须标 [核验日期](/guide/start-here/handbook-version-policy/)

## 验收清单

- [ ] 关键结论有至少一个可点击或可追溯来源
- [ ] 冲突信息已并列呈现
- [ ] 「不确定」项已列出，未伪装成事实
- [ ] 敏感数据未出现在 prompt 或日志
