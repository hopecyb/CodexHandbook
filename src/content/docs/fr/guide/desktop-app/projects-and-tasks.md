« Projet » et « tâche » semblent simples, mais on peut facilement les confondre au début. Le projet est l'ensemble de fichiers ou le dépôt sur lequel vous travaillez ; la tâche est ce que vous demandez précisément à Codex.

Par exemple :

- Le dépôt de votre site de documentation → projet
- « Rendre les termes de la page d'accueil plus faciles à comprendre » → tâche

Cette distinction compte parce que deux niveaux coexistent toujours dans l'application de bureau :

- Le projet dans lequel vous travaillez
- Ce que vous demandez précisément à Codex maintenant

## Projet

- Ajoutez un dossier d'entraînement ou la racine d'un dépôt.
- Concentrez-vous sur un projet à la fois pour éviter de mêler les contextes.

Voyez le projet comme le **lieu de travail** de cette collaboration. Si vous choisissez le mauvais, de nombreux problèmes suivront.

## Tâche

- Commencez par une instruction complète.
- Suivez le plan et les appels d'outils.
- Approuvez ou refusez les demandes si nécessaire.

La tâche est la **demande précise** faite à Codex. Plus elle est claire, moins Codex doit deviner en cours de route.

Pour comparer les notions, voir [Conversations, tâches et projets](/fr/guide/foundations/threads-tasks-and-projects/).

## Idées reçues

### 1. Pourquoi choisir un projet avant de poser une question ?

Codex doit savoir sur quels fichiers ou quel dépôt il travaille.

Si le projet est mal choisi, des problèmes comme « Pourquoi ne voit-il pas mes fichiers ? » ou « Pourquoi a-t-il modifié autre chose ? » deviennent plus fréquents.

### 2. Peut-il y avoir plusieurs tâches dans un projet ?

Oui. Une méthode plus sûre consiste à :

- Rester dans le même projet.
- Travailler sur une tâche claire à la fois.
- Commencer la suivante après avoir terminé la précédente.

Cela évite davantage de mélanger les contextes.

### 3. Comment formuler une tâche au départ ?

Essayez d'inclure trois types d'informations :

- Le but
- Le périmètre et les contraintes
- Ce qui marque l'achèvement

### 4. Une grosse demande doit-elle être une seule tâche ?

Si le travail couvre beaucoup de choses, il vaut mieux :

- Garder le même projet.
- Diviser le travail en plusieurs tâches.
- Donner un seul objectif précis à chacune.

## Ordre habituel

Pour vos premiers pas dans l'application de bureau :

1. Vérifiez que le bon projet est sélectionné.
2. Assurez-vous que la tâche poursuit un objectif principal unique.
3. Précisez les limites du périmètre et les critères de fin.
4. Une fois lancée, surveillez surtout le plan, les appels d'outils et les modifications.
