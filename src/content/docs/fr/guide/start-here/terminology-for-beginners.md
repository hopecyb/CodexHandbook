Pour des définitions plus complètes, consultez le [glossaire](/fr/guide/reference/glossary/). Voici d'abord les termes les plus courants, ceux qui peuvent gêner la lecture.

Au début du manuel Codex, la densité des termes peut être le principal obstacle. Chaque mot semble familier, mais leur combinaison peut dérouter.

Deux situations fréquentes :

- Vous comprenez les mots sans savoir ce qu'ils désignent dans la pratique
- Vous ne savez pas quels termes comprendre tout de suite et lesquels peuvent attendre

Considérez cette page comme une aide à la lecture, pas comme un examen de vocabulaire. Une compréhension générale suffit pour avancer.

## Les premiers termes à connaître

Si votre but est de terminer une première tâche, commencez par ces six termes :

| Terme | Pourquoi le connaître maintenant ? |
|---|---|
| **Prompt** | Comment expliquer clairement une tâche |
| **Contexte** | Les informations auxquelles Codex a accès actuellement |
| **Agent** | Pourquoi il ne se contente pas de répondre par du texte |
| **Approbation** | Pourquoi il s'arrête parfois pour vous demander votre accord |
| **Diff** | Comment examiner ce qu'il a modifié |
| **Tâche** | L'unité de base d'un travail complet |

| Terme | Explication simple |
|---|---|
| **Prompt** | L'objectif, le contexte et les exigences que vous donnez à Codex |
| **Contexte** | Les informations du projet, des fichiers et de la conversation visibles par le modèle |
| **Agent** | Une manière de travailler qui utilise des outils et progresse vers un objectif |
| **Outil** | Une capacité utilisable pour lire des fichiers, exécuter des commandes ou chercher |
| **Bac à sable** | Un environnement d'exécution qui limite les effets sur les fichiers et le réseau |
| **Approbation** | Votre accord explicite avant certaines actions |
| **Diff** | La comparaison du contenu avant et après une modification, pour vérification |
| **Fil / session** | Une conversation continue et son contexte accumulé |
| **Tâche** | Une unité de travail avec un objectif, pouvant comprendre plusieurs appels d'outils |
| **Skill** | Des instructions et ressources réutilisables pour un travail spécialisé (avancé) |
| **MCP** | Un protocole de connexion à des outils et sources de données externes (avancé) |
| **Tâche cloud** | Une tâche exécutée dans un environnement cloud plutôt que dans un bac à sable local |

## En langage plus simple

- **Prompt :** ce que vous dites pour confier une tâche
- **Contexte :** les éléments dont Codex dispose à cet instant
- **Agent :** il fait réellement avancer la tâche au lieu de seulement répondre
- **Approbation :** certaines actions exigent votre accord
- **Diff :** une comparaison avant/après
- **Skill :** un ensemble d'étapes établies que l'on peut réutiliser

## Comment utiliser cette page

Lorsque vous croisez ces termes ailleurs, inutile de vous arrêter à chaque définition :

- Si vous saisissez l'idée générale, continuez
- Si un terme reste flou après plusieurs rencontres, revenez ici
- S'il vous empêche de comprendre un processus, lisez la page dédiée

## Regrouper les termes

Si vous ne voulez pas tout mémoriser, classez-les ainsi :

- Ce que vous dites : prompt
- Ce qu'il voit : contexte
- Comment il agit : agent, outils
- Ce qu'il peut faire : approbation, bac à sable
- Comment vous vérifiez : diff, résultat de la tâche

## Les termes qui peuvent attendre

Il s'agit surtout de sujets avancés qu'il n'est pas nécessaire de maîtriser pour une première tâche :

- Skill
- MCP
- Hook
- Plugin
- Détails des environnements cloud

Terminez votre [première tâche](/fr/guide/getting-started/run-your-first-task/) avant d'y revenir ; ils seront alors plus faciles à comprendre.

Revenez consulter cette page face à un terme inconnu, puis poursuivez votre lecture.

À la première lecture, prenez ces termes comme des repères. Comprendre leur sens général est plus utile que les apprendre tous par cœur.
