# 三组固定输入提示词对照

v1.0.0，CC0 教学设计。周报、文章、Bug 修复各有相同输入的 A/B 提示词；B 仅追加显式验收要求。此 v1.0.0 为冻结的输入与评分材料。2026-09-18 的 12 次运行另存于结果包 prompt-comparison-results；本包的空白模板仍保持未运行，不能冒充实际结果。

## 运行协议

1. 检查 validation/input-hashes.json，复制同一输入到两个全新工作目录。每组 A/B 提供相同工具、权限和时间上限，不提供 review-guide 参考答案。
2. 使用全新任务，固定实际模型、推理设置、客户端和任务说明；无法确认的设置记 null。A/B 不共享上一轮结果。不同轮次交替 A→B、B→A，预先约定次数与停止条件。
3. 分别使用 A.md、B.md，保留所有输出、工具错误和未完成情况。不得只选成功的一次；重试作为新记录。
4. 从 blank-run.json 复制一份记录，保存输入哈希、实际模型标签、环境、耗时和输出路径。未运行不能填零耗时或零分。
5. 使用同一 rubric.json 与该组 review-guide.md 打分，记录每个分数对应证据。若可能，隐藏变体标签后复核。人工返工时间单独记录，不和模型等待时间相加后冒称模型耗时。

每个维度单独呈现，不用一个综合分掩盖事实错误。少量样本仅说明这些任务和环境中的观察，不能推出普遍成功率，更不能证明提示词长度造成提升。

## 当前证据

本包只检查输入哈希、A/B前缀与空白模板；另一个结果包保存12次实际运行和主Agent非盲评分。原有设计示例仍是作者示例，不是模型输出。销售提示中的字典路径缺少 input/ 前缀，结果包记录了此缺陷；为保留本批实验文本，本版本未改A/B提示。

材料完整性检查需要 Python 3.10+：`python3 scripts/check_materials.py`。它不运行模型，也不测试提示词效果。
